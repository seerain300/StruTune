Understanding and analysis

- What the original PyTorch code does:
  - Inputs:
    - hidden_states: [B, I, D], where B=batch size, I=img_seq_len, D=hidden_dim
    - encoder_hidden_states: [B, T, D], where T=text_seq_len
    - process_weight: [D, D], a linear layer weight
  - It concatenates along the sequence dimension:
    - concatenated = cat([encoder_hidden_states, hidden_states], dim=1)
    - Shape becomes [B, T+I, D]
  - It applies a linear projection (no bias) to the concatenated tensor:
    - processed = concatenated @ process_weight.T
    - Shape becomes [B, T+I, D]
  - It splits back:
    - processed_encoder = processed[:, :T, :]
    - processed_hidden = processed[:, T:, :]
    - Returns two tensors: [B, T, D] and [B, I, D]

- Observations:
  - The weight matrix process_weight is square [D, D], and we never use bias.
  - The core computation is a batched matmul:
    - For each batch b, we compute two sequences:
      - A = encoder_hidden_states[b] ∈ R^(T×D), output yA ∈ R^(T×D)
      - B = hidden_states[b] ∈ R^(I×D), output yB ∈ R^(I×D)
    - Both yA and yB are A @ W and B @ W respectively, where W = process_weight ∈ R^(D×D).
  - The concatenation and split is just a view operation on the batched output; there is no extra compute there, only data movement.

- Optimization opportunities:
  - We can avoid the intermediate concatenation and perform two separate batched matmuls directly:
    - yA = encoder_hidden_states @ W.T (no bias)
    - yB = hidden_states @ W.T (no bias)
  - This reduces memory traffic:
    - The original path builds [B, T+I, D] then multiplies by [D, D], which increases the number of elements handled in the matmul and the bandwidth for reading/writing the concatenated tensor.
    - The two-matmul approach handles [B, T, D] and [B, I, D] separately, which is usually more efficient because we don’t materialize the larger concatenated tensor.
  - We can implement these two batched matmuls with Triton kernels. Each kernel will:
    - Handle one batch index b per program dimension.
    - Iterate over the output rows (either T or I) in tiles.
    - Accumulate across the D dimension using the weight matrix in tiles.
  - Triton suitability:
    - Triton is well-suited for custom, tiled matmul. PyTorch’s torch.matmul is highly optimized and might outperform a simple Triton matmul for some shapes, but here we must use Triton (strict requirement).
    - We will write two kernels: one for [T, D] × [D, D] → [T, D] per batch, and one for [I, D] × [D, D] → [I, D] per batch. Bias is None in the original code, so we don’t add any bias term.

- Design choices for Triton kernels:
  - Input layouts:
    - encoder_hidden_states: [B, T, D] with strides (sB_E, sT_E, sD_E). In the common case, contiguous gives strides (D*T, D, 1), but we’ll use the actual strides to be safe.
    - hidden_states: [B, I, D] with strides (sB_H, sI_H, sD_H).
    - process_weight: [D, D] with strides (sW0, sW1), typically contiguous (D, 1).
  - Output layouts:
    - processed_encoder: [B, T, D] with strides (sB_out, sT_out, sD_out). We’ll allocate contiguous output and write with correct strides.
    - processed_hidden: [B, I, D] with strides (sB_out2, sI_out, sD_out2).
  - Tiling:
    - We can tile over M (sequence length) and N (hidden_dim) dimensions. For typical D=64–1024, we’ll choose BLOCK_N as a power-of-two up to 128 or 256 and BLOCK_M around 64–128. BLOCK_K (accumulating over D) can be 32 or 64 depending on D. We can use simple heuristics based on runtime dims.
    - We will use num_warps 4 or 8; num_stages 2–4.
  - Grid:
    - For each batch element, we launch one Triton program per output sequence row (i.e., grid = (B, T) or (B, I)), and the kernel loops internally over M if needed. This keeps it simple and leverages Triton’s vectorization along K and N.
  - Masking:
    - We must use masks for loads/stores at the boundaries when M or N are not multiples of block sizes.

- Edge cases and correctness:
  - Dims vary across test cases. Our kernels should work for any T, I, D. We’ll use masks to handle non-multiple sizes.
  - We’ll assume contiguous weight; we’ll pass actual strides, so non-contiguous inputs still work if they’re regular. The original code uses .t() on a [D, D] tensor, which returns a view; we can pass that directly.
  - We must strictly avoid any torch.matmul or torch operations in the host forward. Only allocate tensors, compute strides/shape, and launch Triton kernels.

- Performance considerations:
  - Using two kernels (one for each output) avoids materializing the [B, T+I, D] intermediate. This can reduce memory bandwidth and potentially improve performance compared to concatenation + matmul.
  - Each kernel will do a batched GEMM. Triton kernels for GEMM are straightforward here, and we keep computation minimal (no bias, no activation).
  - We’ll choose BLOCK sizes based on runtime D and sequence length to keep good occupancy. Heuristics:
    - BLOCK_N = min(next power-of-two of D, 128) or min(128, D)
    - BLOCK_M = min(128, max(32, M))
    - BLOCK_K = min(64, D) if D <= 64, else 64
  - We’ll use num_warps 4 for smaller blocks, 8 for larger. These are reasonable defaults; Triton can auto-tune later, but we keep it simple.

- Limitations:
  - If B is large and M (T or I) is small, launching one program per (b, row) might underutilize the GPU. A 2D grid over (batch, sequence tiles) would be better, but it complicates the kernel. Given typical sizes, one-program-per-row is fine. We could tile M over grid, but for clarity and simplicity, we’ll do per-row loops inside the kernel.
  - Autograd: The original code uses @torch.no_grad(), so gradients aren’t required. Our Triton kernels won’t provide autograd; this is fine for the benchmark.

Plan

1. Implement two Triton kernels:
   - Kernel A: batched matmul for encoder: takes E (B, T, D), W (D, D), outputs Y_E (B, T, D)
   - Kernel B: batched matmul for image: takes H (B, I, D), W (D, D), outputs Y_H (B, I, D)
   Both kernels will:
   - Use strides for inputs/outputs to be generic.
   - Tile over N (hidden_dim) and K (hidden_dim) and loop over M (sequence length).
   - Use masks for bounds.
   - No bias.

2. Implement ModelNew:
   - In forward, extract B, T, I, D from inputs.
   - Allocate outputs: processed_encoder [B, T, D] and processed_hidden [B, I, D].
   - Ensure inputs are contiguous for best performance (they may already be).
   - Launch Kernel A with grid = (B, T), passing appropriate strides and parameters.
   - Launch Kernel B with grid = (B, I), passing appropriate strides and parameters.
   - Return the two outputs.

3. Keep the code minimal and compliant with the Triton-only requirement:
   - No torch.matmul, no torch operations in forward host code.
   - Only Triton kernels, tensor allocations, and metadata operations.

4. Add simple heuristics for BLOCK sizes in the kernels (based on D, T, I). This helps performance across varying shapes.

Now the Triton-optimized implementation with ModelNew:

```python
import torch
import triton
import triton.language as tl


@triton.jit
def _matmul_seq_to_dim_kernel(
    E_ptr,            # pointer to encoder_hidden_states: [B, T, D]
    W_ptr,            # pointer to process_weight: [D, D]
    Y_ptr,            # pointer to output: [B, T, D]
    B, T, D,
    sE_b, sE_t, sE_d,  # strides for E
    sY_b, sY_t, sY_d,  # strides for Y
    sW0, sW1,          # strides for W (we expect [D, D])
    BLOCK_M: tl.constexpr,
    BLOCK_N: tl.constexpr,
    BLOCK_K: tl.constexpr,
):
    # Each program handles one (batch, row) pair: output row t for batch b
    b = tl.program_id(0)
    t = tl.program_id(1)

    # Pointers to the b-th batch slice of E and Y
    E_row_ptr = E_ptr + b * sE_b + t * sE_t
    Y_row_ptr = Y_ptr + b * sY_b + t * sY_t

    # Initialize accumulator for output vector of length D
    acc = tl.zeros((BLOCK_N,), dtype=tl.float32)

    # Loop over K (hidden_dim) dimension in tiles
    for k0 in range(0, D, BLOCK_K):
        k_range = k0 + tl.arange(0, BLOCK_K)  # [BLOCK_K]
        # Load weight submatrix W_sub: shape [BLOCK_K, BLOCK_N]
        # W is [D, D], we iterate over k0 and accumulate across k
        # We need a matrix of pointers: for each k in BLOCK_K, load corresponding row across N.
        # Construct pointers for W_sub:
        W_sub_ptrs = W_ptr + k_range[:, None] * sW0 + tl.arange(0, BLOCK_N)[None, :] * sW1
        # Mask for valid k indices
        mask_k = k_range < D
        # Load E row vector for these D positions (vector length BLOCK_N)
        # E_row_ptr points to the start of row t for batch b; we load across D
        E_vec_ptrs = E_row_ptr + tl.arange(0, BLOCK_N) * sE_d
        mask_n = tl.arange(0, BLOCK_N) < D
        E_vec = tl.load(E_vec_ptrs, mask=mask_n, other=0.0).to(tl.float32)  # [BLOCK_N]
        # Load W_sub
        W_sub = tl.load(W_sub_ptrs, mask=mask_k[:, None] & mask_n[None, :], other=0.0).to(tl.float32)  # [BLOCK_K, BLOCK_N]
        # Accumulate: acc += sum_k (E_vec[k] * W_sub[k, :])
        # We can use a simple loop over BLOCK_K since it's small; or we can do tl.dot if we reshape appropriately.
        # Compute per-k contribution and accumulate
        # E_vec is [BLOCK_N], W_sub[:, j] is per-k vector across N; we'll do per-k inner product.
        for kk in range(BLOCK_K):
            k_valid = kk + k0 < D
            # vector from W_sub[:, kk] across N
            w_vec = W_sub[kk, :]  # [BLOCK_N]
            e_k = E_vec[kk] if k_valid else 0.0
            acc += e_k * w_vec

    # Store accumulated result to output row
    Y_out_ptrs = Y_row_ptr + tl.arange(0, BLOCK_N) * sY_d
    mask_n = tl.arange(0, BLOCK_N) < D
    # Cast back to original dtype of output tensor; here we assume float32; the original code uses float32.
    tl.store(Y_out_ptrs, acc, mask=mask_n)


@triton.jit
def _matmul_img_to_dim_kernel(
    H_ptr,            # pointer to hidden_states: [B, I, D]
    W_ptr,            # pointer to process_weight: [D, D]
    Y_ptr,            # pointer to output: [B, I, D]
    B, I, D,
    sH_b, sH_i, sH_d,  # strides for H
    sY_b, sY_i, sY_d,  # strides for Y
    sW0, sW1,          # strides for W
    BLOCK_M: tl.constexpr,
    BLOCK_N: tl.constexpr,
    BLOCK_K: tl.constexpr,
):
    # Each program handles one (batch, row) pair: output row i for batch b
    b = tl.program_id(0)
    i = tl.program_id(1)

    # Pointers to the b-th batch slice of H and Y
    H_row_ptr = H_ptr + b * sH_b + i * sH_i
    Y_row_ptr = Y_ptr + b * sY_b + i * sY_i

    acc = tl.zeros((BLOCK_N,), dtype=tl.float32)

    for k0 in range(0, D, BLOCK_K):
        k_range = k0 + tl.arange(0, BLOCK_K)
        mask_k = k_range < D

        # Load E row across D
        H_vec_ptrs = H_row_ptr + tl.arange(0, BLOCK_N) * sH_d
        mask_n = tl.arange(0, BLOCK_N) < D
        H_vec = tl.load(H_vec_ptrs, mask=mask_n, other=0.0).to(tl.float32)  # [BLOCK_N]

        # Load W submatrix [BLOCK_K, BLOCK_N]
        W_sub_ptrs = W_ptr + k_range[:, None] * sW0 + tl.arange(0, BLOCK_N)[None, :] * sW1
        W_sub = tl.load(W_sub_ptrs, mask=mask_k[:, None] & mask_n[None, :], other=0.0).to(tl.float32)

        for kk in range(BLOCK_K):
            k_valid = kk + k0 < D
            w_vec = W_sub[kk, :]
            h_k = H_vec[kk] if k_valid else 0.0
            acc += h_k * w_vec

    Y_out_ptrs = Y_row_ptr + tl.arange(0, BLOCK_N) * sY_d
    mask_n = tl.arange(0, BLOCK_N) < D
    tl.store(Y_out_ptrs, acc, mask=mask_n)


def _choose_blocks(D, M, N=None):
    # Choose tile sizes heuristically
    # BLOCK_N: up to 128 or cap at D
    if D <= 64:
        BLOCK_N = 64
    elif D <= 128:
        BLOCK_N = 128
    else:
        BLOCK_N = 128  # cap to 128 for good occupancy
    # BLOCK_K: up to 64
    if D <= 64:
        BLOCK_K = 32
    else:
        BLOCK_K = 64
    # BLOCK_M: rows tile; use 128 if M large, else 64
    BLOCK_M = 128 if M >= 128 else 64
    # num_warps: 4 for smaller, 8 for larger N
    num_warps = 8 if BLOCK_N >= 128 else 4
    # num_stages: 2-4, simple heuristic
    num_stages = 3
    return BLOCK_M, BLOCK_N, BLOCK_K, num_warps, num_stages


class ModelNew(torch.nn.Module):
    def forward(self, hidden_states: torch.Tensor, encoder_hidden_states: torch.Tensor, process_weight: torch.Tensor):
        """
        Triton-optimized version of the original run function:
        - Does not concatenate; computes two batched matmuls directly with Triton.
        - Returns (processed_encoder_hidden_states, processed_hidden_states) with shapes [B, T, D] and [B, I, D].
        """
        # Shapes
        B = hidden_states.shape[0]
        T = encoder_hidden_states.shape[1]
        I = hidden_states.shape[1]
        D = hidden_states.shape[2]
        assert encoder_hidden_states.shape[2] == D, "Hidden dims must match"
        assert process_weight.shape[0] == D and process_weight.shape[1] == D, "process_weight must be [D, D]"

        # Ensure inputs are contiguous for performance
        E = encoder_hidden_states.contiguous()
        H = hidden_states.contiguous()
        W = process_weight.contiguous()

        # Allocate outputs (float32; original uses float32). We can assume float32 for this benchmark.
        processed_encoder = torch.empty((B, T, D), device=E.device, dtype=torch.float32)
        processed_hidden = torch.empty((B, I, D), device=H.device, dtype=torch.float32)

        # Strides
        sE_b, sE_t, sE_d = E.stride()
        sH_b, sH_i, sH_d = H.stride()
        sY_b, sY_t, sY_d = processed_encoder.stride()
        sY2_b, sY2_i, sY2_d = processed_hidden.stride()
        sW0, sW1 = W.stride()

        # Choose blocks
        BLOCK_M_E, BLOCK_N, BLOCK_K, num_warps, num_stages = _choose_blocks(D, T)
        BLOCK_M_H, _, _, _, _ = _choose_blocks(D, I)  # same N/K

        # Launch kernels: one program per (batch, row)
        grid_encoder = (B, T)
        grid_image = (B, I)

        _matmul_seq_to_dim_kernel[grid_encoder](
            E, W, processed_encoder,
            B, T, D,
            sE_b, sE_t, sE_d,
            sY_b, sY_t, sY_d,
            sW0, sW1,
            BLOCK_M=BLOCK_M_E,
            BLOCK_N=BLOCK_N,
            BLOCK_K=BLOCK_K,
            num_warps=num_warps,
            num_stages=num_stages,
        )

        _matmul_img_to_dim_kernel[grid_image](
            H, W, processed_hidden,
            B, I, D,
            sH_b, sH_i, sH_d,
            sY2_b, sY2_i, sY2_d,
            sW0, sW1,
            BLOCK_M=BLOCK_M_H,
            BLOCK_N=BLOCK_N,
            BLOCK_K=BLOCK_K,
            num_warps=num_warps,
            num_stages=num_stages,
        )

        return processed_encoder, processed_hidden
```

Notes on the implementation

- The kernels perform batched GEMV-like operations per (batch, sequence-row) pair. We loop over the hidden_dim (K) in tiles and accumulate across it. For each K-tile, we:
  - Load a vector E_vec from the corresponding row of the input (either encoder or hidden).
  - Load a submatrix W_sub of process_weight for the current K-tile across all N (hidden_dim) columns.
  - Accumulate acc += sum_k E_vec[k] * W_sub[k, :].
- This avoids creating the [B, T+I, D] concatenated tensor and performing a single larger GEMM, which can reduce memory bandwidth and sometimes improve performance.
- We use masks for boundary handling, and we compute strides explicitly so non-contiguous inputs can still be supported (we convert to contiguous in forward for best performance).
- The Triton kernels are the only computational elements; there is no torch.matmul or any PyTorch tensor computation in the host forward. This satisfies the requirement to use Triton-only computation for the given operations.

Potential further improvements

- Tiling over M (sequence length) with a 2D grid can improve occupancy when T or I is large, but it complicates the kernel and indexing. The current one-program-per-row approach is simple and effective for many sizes.
- Using tl.dot with reshaped inputs could speed up the accumulation, but we chose a straightforward per-k loop to keep code clarity and compatibility.
- Autotuning BLOCK sizes with triton.autotune could yield additional performance, but we keep it simple here to ensure correctness across varied workloads.
