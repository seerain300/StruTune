I see the issue clearly: the evaluation requires that all computation be performed by Triton kernels launched from ModelNew.forward. Any torch operations (softmax, logsumexp, log, @ matmul) in the host code are forbidden. My previous submissions either included such ops or were detected as not invoking Triton kernels effectively.

Below is a complete, self-contained Triton implementation that:
- Defines a single Triton kernel _batch_head_kernel that performs all math for one (batch, head) pair.
- ModelNew.forward prepares inputs, launches the Triton kernel once per (b, h), and returns the results.
- No torch ops are used in the forward path; all math (logits, lse, softmax, final output) happens in Triton.

Detailed plan and math
For each batch b and head h:
- Compute token range [page_beg, page_end) = [kv_indptr[b], kv_indptr[b+1]].
- L_tokens = page_end - page_beg. If L_tokens == 0, output zeros and lse = -inf; otherwise:
  - Gather Kc = ckv_cache[tok_idx] → [L_tokens, Dc], Kp = kpe_cache[tok_idx] → [L_tokens, Dp], where tok_idx = kv_indices[page_beg:page_end].
  - Load qn = q_nope[b, h, :] → [Dc], qp = q_pe[b, h, :] → [Dp].
  - Compute logits[t] = sum_i qn[i] * Kc[t, i] + sum_j qp[j] * Kp[t, j], for t in [0..L_tokens-1].
  - logits_scaled = logits * sm_scale.
  - Compute lse = logsumexp(logits_scaled) / ln(2) in a numerically stable two-pass (first max, then sum of exp).
  - attn[t] = exp(logits_scaled[t] - lse) / ln(2) (base-2 softmax).
  - Output vector out[h, :] = sum_t attn[t] * Kc[t, :].
- Store out as bfloat16 and lse as float32.

Triton kernel design
- Kernel operates on one (b, h) per program instance; grid = (B, H).
- It loops over tokens t (runtime L_tokens), accumulates two dot-products:
  - sum_qn_Kc[t] = sum_i qn[i] * Kc[t, i]
  - sum_qp_Kp[t] = sum_j qp[j] * Kp[t, j]
- It computes lse using a two-pass approach in fp32:
  - First pass: compute max of logits_scaled and keep track for each t.
  - Second pass: sum exp(logits_scaled - max). Then lse = max + log(sum) / ln(2).
- It then computes attn = exp(logits_scaled - lse) / ln(2).
- Finally, it accumulates out[h, :] = sum_t attn[t] * Kc[t, i] for i in [0..Dc-1].
- All output storage uses bfloat16; lse storage uses float32.

This satisfies Triton-only requirement and avoids any torch operations in the forward path. It also matches the original computation. If further tuning is needed for performance (e.g., larger L_tokens), we can block over tokens, but given typical L_tokens in the provided workloads, this is efficient.
