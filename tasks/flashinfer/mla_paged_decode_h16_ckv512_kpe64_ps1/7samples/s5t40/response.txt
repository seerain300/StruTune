Deep analysis, root causes, and plan

1) What the original PyTorch code does
- Inputs:
  - q_nope: [batch_size, num_qo_heads, head_dim_ckv] (head_dim_ckv=512), dtype bfloat16.
  - q_pe: [batch_size, num_qo_heads, head_dim_kpe] (head_dim_kpe=64), dtype bfloat16.
  - ckv_cache: [num_pages, 1, head_dim_ckv], dtype bfloat16.
  - kpe_cache: [num_pages, 1, head_dim_kpe], dtype bfloat16.
  - kv_indptr: [len_indptr], dtype int32, typically len_indptr = batch_size + 1, storing cumulative token counts per batch.
  - kv_indices: [num_kv_indices], dtype int32, token indices within num_pages for this batch.
  - sm_scale: float32 scalar (default 1.0).
- For each batch b:
  - Compute L_tokens = kv_indptr[b+1] - kv_indptr[b].
  - Gather Kc_all = ckv_cache[tok_idx, 0] and Kp_all = kpe_cache[tok_idx, 0] for tok_idx = kv_indices[page_beg:page_end] (with L_tokens tokens).
  - For each head h in 0..num_qo_heads-1:
    - qn = q_nope[b, h] -> [head_dim_ckv], fp32
    - qp = q_pe[b, h] -> [head_dim_kpe], fp32
    - logits[h, :] = qn @ Kc_all.T + qp @ Kp_all.T -> [L_tokens]
    - scaled = logits * sm_scale
    - lse[h] = logsumexp(scaled) / ln(2)  (base-2)
    - attn = softmax(scaled, dim=-1)
    - output[b, h] = attn @ Kc_all  -> [head_dim_ckv], stored in bfloat16
  - Return output [batch, heads, head_dim_ckv] and lse [batch, heads] (as fp32, originally).

2) Why the previous Triton submissions failed
- KeyError: “Keyword argument sm_scale was specified but unrecognised”: This indicates that the Triton kernel signature did not include sm_scale, and the launcher passed it as a keyword. Even after adding sm_scale to kernels, one of the 47 evaluations still failed with this KeyError. This points to a dynamic path where a kernel is still being launched with sm_scale but was not declared in its signature. In Triton, all passed keyword arguments must be present in the kernel signature.
- Additional complexity: The evaluation harness appears to vary num_qo_heads and head_dim_ckv across workloads (e.g., some configs have head_dim_ckv different from 512). If we use tl.constexpr for head_dim and rely on static specialization, we must ensure specialization happens correctly per launch. Triton requires compile-time constants for tl.constexpr; we can pass them as arguments. But using per-launch specialization can inflate compilation overhead. A safer, general approach is to remove tl.constexpr for dims and instead use runtime loops over K (head_dim). This avoids requiring const specialization.

3) Correctness and robustness strategy
- Host code will:
  - Allocate per-batch contiguous buffers for Kc_tmp and Kp_tmp with shapes [L_tokens, head_dim_ckv] and [L_tokens, head_dim_kpe], respectively, in fp32.
  - Launch a Triton gather kernel to copy selected rows from ckv_cache and kpe_cache into these buffers using kv_indices.
  - For each head h in 0..num_qo_heads-1, launch a Triton kernel to compute logits (forward_attention_kernel): accumulate qn @ Kc_tmp.T + qp @ Kp_tmp.T. We compute this as a single vector using tiled loops over K (head_dim).
  - Launch a Triton softmax kernel over logits (after scaling by sm_scale), using subtract-max trick and reductions.
  - Launch a Triton matvec kernel to compute output[b, h] = attn @ Kc_tmp. This is a reduction over K, producing [head_dim_ckv].
  - Launch a Triton kernel to compute per-head lse = logsumexp(logits_scaled), and then reduce across heads with another Triton kernel, dividing by ln(2) in host code to produce base-2 lse as in original. Note: Triton doesn’t have a built-in logsumexp; we implement it explicitly.
  - Finally, cast output to bfloat16 and return.

- Triton kernels will:
  - forward_attention_kernel: for a given (b, h), loops K from 0 to head_dim_ckv in tiles, accumulates dot products with Kc_tmp and Kp_tmp into output vector of size L_tokens.
  - softmax_kernel: per (b, h), computes softmax over a 1D vector (scaled logits). We load vector with mask, compute max, exp, sum, divide.
  - matvec_kernel: for a given (b, h), loops over output_dim = head_dim_ckv in tiles and over K = 0..head_dim_ckv, computing out_tile = sum_j attn_j * Kc_tmp[j] and storing into output[b, h].
  - lse_per_head_kernel: for a given (b, h), computes logsumexp over a 1D logits vector using reduce operations (compute max, sum of exp, then log).
  - lse_reduce_kernel: per batch b, reduces num_qo_heads elements of lse to a single scalar and divides by ln(2), storing per-batch scalar.

4) Performance considerations
- Triton handles per-batch per-head computations on GPU, avoiding Python overhead. Using tiled loops over K (head_dim) keeps kernels general and robust without requiring tl.constexpr specialization.
- While Triton does not have a built-in matmul/logsumexp, the explicit reductions are efficient for moderate sizes (L_tokens up to a few thousand, K up to 512). This approach ensures correctness and avoids previous runtime errors by:
  - Ensuring all kernels accept sm_scale as a parameter.
  - Not modifying kernel launch tuples (no indexing or item assignment).
  - Handling dynamic num_qo_heads and head_dim via loops (no tl.constexpr required for dims).

@triton.jit
def matvec_kernel(
    attn_ptr,         # *f32, [L_tokens]
    Kc_ptr,           # *f32, [L_tokens, head_dim]
    out_ptr,          # *f32, [head_dim]

# Per-head lse: logsumexp(scaled_logits)
@triton.jit
def lse_per_head_kernel(
    logits_ptr,       # *f32, [L_tokens]
    out_ptr,          # *f32, scalar per head
    L_tokens: tl.constexpr,
    sm_scale: tl.float32,
):
    # Compute logsumexp over vector
    # We need a reduction. Triton doesn't provide vector reductions here, so we implement a simple per-lane scalar approach.
    # For robustness, we compute max and sum in separate passes.
    # However, Triton requires structured loops; we implement a simple reduction using loops over L_tokens.
    max_val = -float("inf")
    # Pass 1: max
    i = 0
    while i < L_tokens:
        x = tl.load(logits_ptr + i)
        max_val = tl.maximum(max_val, x)
        i += 1

    sum_exp = 0.0
    i = 0
    while i < L_tokens:
        x = tl.load(logits_ptr + i)
        sum_exp += tl.exp((x - max_val) * sm_scale)
        i += 1

    lse = max_val * sm_scale + tl.log(sum_exp)
    tl.store(out_ptr, lse)
