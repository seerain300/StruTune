- We compute tok_idx per batch from kv_indptr and kv_indices, exactly like the original.

Potential issues and fixes:
- Triton kernel indexing by head h: Triton does not allow indexing into tensors with dynamic h inside the kernel signature. The solution is to pass qn[h] and qp[h] as separate 1D vectors to the kernel for each (b,h). We do that in forward by q_nope[b_idx].to(torch.float32).contiguous() and q_pe[b_idx].
- The earlier “UnsupportedLanguageConstruct” errors can be avoided by using simple while loops with masks and avoiding dynamic while/break patterns. The kernels here use masked loads and while loops with simple pointer arithmetic, which Triton supports.
- Performance: For these dimensions (N=512, Kp_dim=64, M_total up to ~1e5), computing Kc rows for each chunk is fine. BLOCK_M=128 balances register usage.
