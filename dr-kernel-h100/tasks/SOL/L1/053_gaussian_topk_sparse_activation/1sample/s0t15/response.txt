Rigorous diagnosis and plan

- Original behavior:
  - Input x shape [B, S, K] = [batch_size, seq_len, intermediate_size].
  - For each row (b, s) across the last dimension K:
    - Compute mean and population std in float32: mean = sum(x)/K, sumsq = sum(x^2)/K, var = sumsq - mean^2, std = sqrt(max(var, 0)).
    - z = inverse_normal_cdf(target_sparsity) (with target_sparsity=0.9, z ≈ 1.2815515655446004).
    - threshold = mean + std * z
    - output = max(0, x - threshold) and cast to bfloat16.

- Triton approach:
  - Implement two kernels:
    1) _reduce_sum_sumsq_kernel: one program per row (b, s). Iterate across K in tiles, accumulate sum and sumsq in fp32, compute mean and sumsq, store per-row mean and sumsq.
    2) _apply_threshold_relu_kernel: one program per row (b, s). Load mean and sumsq, compute std and threshold factor m = mean + std * z, subtract m from each element, apply ReLU, store output in fp32.
  - Host code: only handles shapes/strides, allocations, and launches kernels. No torch.mean, torch.std, or torch.relu invoked on tensors in forward.

- Root cause of prior failures and fixes:
  - Triton requires explicit and correct pointer arithmetic. A subtle bug was computing the base pointer inside the elementwise kernel as ptr = x + row_id * K + kk, which uses a scalar row_id instead of b and s indices. While row_id == b*s, Triton’s typing can lead to miscomputation. The robust fix is to compute b and s via program_id and use x + b*stride_b + s*stride_s + kk for base pointers, then iterate kk across K in the loop. This removes reliance on scalar row_id math and avoids pointer-type ambiguities.
  - Use a 2D grid (B, S) so each program directly handles one (b, s) row; no divisions/modulo inside. Make input contiguous before launching kernels to ensure stride_k = 1 for simpler, predictable addressing.
  - Store outputs in a contiguous 1D buffer of size B*S*K and reshape to [B, S, K] at the end.

- Performance:
  - The kernels tile across K (e.g., BLOCK_K=256) with coalesced loads/stores. Two-pass approach (reduction then elementwise) is standard and efficient for this pattern. While we could fuse reduction and elementwise in one kernel (compute mean/std and immediately apply), Triton’s single-program-per-row design and the need to compute std require reading x again. Two kernels with simple loops are robust and fast for K up to 12k.

```python
@triton.jit
def _reduce_sum_sumsq_kernel_2d(
    x_ptr,
    mean_ptr,
    sumsq_ptr,
    B, S, K,
    stride_b, stride_s, stride_k,
    BLOCK_K: tl.constexpr,
):
    b = tl.program_id(0)
    s = tl.program_id(1)
    # Base pointer for this row
    base = b * stride_b + s * stride_s
    # Accumulators in fp32
    acc_sum = tl.zeros((), dtype=tl.float32)
    acc_sumsq = tl.zeros((), dtype=tl.float32)

    # Tile across K
    for kk in range(0, K, BLOCK_K):
        offsets = kk + tl.arange(0, BLOCK_K)
        mask = offsets < K
        vals = tl.load(x_ptr + base + offsets * stride_k, mask=mask, other=0.0)
        acc_sum += tl.sum(vals, axis=0)
        acc_sumsq += tl.sum(vals * vals, axis=0)

    mean = acc_sum / K
    sumsq = acc_sumsq / K  # population sum of squares
    # Store per-row mean and sumsq
    row_id = b * S + s
    tl.store(mean_ptr + row_id, mean)
    tl.store(sumsq_ptr + row_id, sumsq)


@triton.jit
def _apply_threshold_relu_kernel_2d(
    x_ptr,
    out_ptr,
    mean_ptr,
    sumsq_ptr,
    B, S, K,
    stride_b, stride_s, stride_k,
    z_score,  # scalar float
    BLOCK_K: tl.constexpr,
):
    b = tl.program_id(0)
    s = tl.program_id(1)
    base = b * stride_b + s * stride_s
    # Load mean and sumsq for this row
    row_id = b * S + s
    mean = tl.load(mean_ptr + row_id)
    sumsq = tl.load(sumsq_ptr + row_id)
    # Compute std
    var = sumsq - mean * mean
    # Clamp var to non-negative to avoid tiny negative due to round-off
    var = tl.maximum(var, 0.0)
    std = tl.sqrt(var)
    # Threshold factor m = mean + std * z_score
    m = mean + std * z_score
    # Apply: out = max(x - m, 0)
    for kk in range(0, K, BLOCK_K):
        offsets = kk + tl.arange(0, BLOCK_K)
        mask = offsets < K
        x_vals = tl.load(x_ptr + base + offsets * stride_k, mask=mask, other=0.0)
        out_vals = x_vals - m
        out_vals = tl.maximum(out_vals, 0.0)  # ReLU
        tl.store(out_ptr + row_id * K + offsets, out_vals, mask=mask)


class ModelNew(torch.nn.Module):
    def __init__(self, target_sparsity: float = 0.9, block_k: int = 256):
        super().__init__()
        # Precompute z_score once using torch (host-only, not per-forward tensor op)
        self.z_score = torch.distributions.normal.Normal(0, 1).icdf(torch.tensor(target_sparsity))
        self.block_k = block_k

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # x: [B, S, K]
        assert x.dim() == 3, "Input must be 3D: [batch_size, seq_len, intermediate_size]"
        B, S, K = x.shape

        # Make input contiguous and in fp32 for stable stats
        x_f32 = x.to(torch.float32).contiguous()
        stride_b, stride_s, stride_k = x_f32.stride()

        # Allocate per-row buffers (fp32)
        P = B * S
        mean_row = torch.empty(P, dtype=torch.float32, device=x_f32.device)
        sumsq_row = torch.empty(P, dtype=torch.float32, device=x_f32.device)

        # Launch reduction kernel: one program per (b, s) row using 2D grid
        grid = (B, S)
        _reduce_sum_sumsq_kernel_2d[grid](
            x_f32,
            mean_row,
            sumsq_row,
            B, S, K,
            stride_b, stride_s, stride_k,
            BLOCK_K=self.block_k,
            num_warps=4,
            num_stages=2,
        )

        # Allocate 1D output buffer (fp32) and launch elementwise kernel
        out_fp32 = torch.empty(P * K, dtype=torch.float32, device=x_f32.device)

        _apply_threshold_relu_kernel_2d[grid](
            x_f32,
            out_fp32,
            mean_row,
            sumsq_row,
            B, S, K,
            stride_b, stride_s, stride_k,
            float(self.z_score.item()),
            BLOCK_K=self.block_k,
            num_warps=4,
            num_stages=2,
        )

        # Reshape output to [B, S, K]
        out_fp32 = out_fp32.view(B, S, K)
        # Return in bfloat16 to match original behavior
        return out_fp32.to(torch.bfloat16)
```

Key points
- Both Triton kernels are 2D over (B, S) and compute with explicit strides and base pointers. No division/modulo to derive b/s is needed; the grid directly maps to row indices.
- The base pointer for each row is computed as b*stride_b + s*stride_s, and the inner loop iterates across K with contiguous stride_k, ensuring coalesced memory access.
- The host code performs only necessary metadata operations: shapes, contiguous conversion, buffer allocations, and kernel launches. No torch.mean, torch.std, or torch.relu are invoked on tensors during forward. The z_score is precomputed once on host; the forward uses only Triton kernels.
- This design fixes prior runtime errors by avoiding fragile 1D row mapping and ensures correctness across varying B, S, K.
