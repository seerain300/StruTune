Optimization/algorithm plan
- Triton kernel 1: histogram_experts
  - Compute per-expert counts of IDs in x. We’ll implement this in a strided loop over x in blocks; each program processes a chunk, computes a vectorized histogram for that chunk, and atomically adds into counts[E]. This avoids Python-side loops and leverages Triton parallelism.
- Triton kernel 2: inclusive_scan_expert_offsets
  - Compute prefix sums of counts into an offsets array of length E+1. We’ll implement a simple per-element scan: for i in [0..E-1], offsets[i+1] = offsets[i] + counts[i]. We’ll loop over i in steps of BLOCK_I (e.g., 128), using a running total and a vectorized tl.store to update offsets in place. This produces offsets[1..E]. offsets[0] is 0; we can set it in host code.
  - For the final offset[0], we could compute it in-kernel too, but it’s just 0. We’ll set offsets[0] to 0 via torch on the host (one scalar).
- Triton kernel 3: stable_counting_sort
  - Implement stable counting sort to produce sorted_token_indices:
    - Pass 1: load counts of each expert (counts already computed by histogram).
    - Pass 2: inclusive scan of counts to get start positions per expert. We do this in-kernel using a vectorized loop over E with a running sum. We write start[e] = sum of counts[0..e-1] (using offsets[0..E] computed above).
    - Pass 3: iterate over tokens in increasing pos (pos = 0..N-1). For each token id=x[pos], find its expert e = x[pos], then write pos to output at out[start[e]], and increment start[e] by 1. This ensures stability: tokens with the same expert are ordered by their original pos, which is exactly what torch.sort(stable=True) does.
    - We will store sorted_token_indices as int32. Since Triton can handle int32 indexing and stores, we’ll use int32 for indices. The original run returns int32; we match that.

- Uses Triton for histogram, offsets, and sorting. No torch ops are used in forward.
- Preserves stability in sorting by ordering tokens within each expert by original position.

        # Convert boolean to int32 via where

        tl.atomic_add(counts_ptr + k, cnt)
