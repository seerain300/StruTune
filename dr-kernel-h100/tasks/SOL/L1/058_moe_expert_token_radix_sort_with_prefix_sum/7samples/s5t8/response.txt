Implementation details
1) Triton stable argsort (bitonic):
   - Input: flat_ids (1D int32), output: out_idx (1D int32) = permutation indices of flat_ids sorted ascending with stable tie-break by original index.
   - We implement a bitonic network on N elements using Triton. Each program handles compare-exchange steps. We ensure stability by breaking ties using original indices: when keys are equal, we use original_index to order (i < j for i<j in original position).
   - This network is deterministic and avoids PyTorch on tensors. While intricate, using standard bitonic compare-exchange logic with proper index math and masked updates should work for moderate N up to 8192 (as in provided workloads). We’ll launch grid=(1,) so one program performs the whole sort.

2) Triton count per expert:
   - Each program loads a chunk of flat_ids and atomically increments counts in counts[num_experts]. We’ll run several programs to cover N efficiently (e.g., grid=4 or 8).

3) Triton exclusive prefix sum:
   - A single program loops over num_experts, computing exclusive prefix sum: offsets[0]=0, offsets[i+1]=offsets[i]+counts[i]. This produces offsets of length num_experts+1.

4) Host forward:
   - Reshape input to 1D int32 flat.
   - Launch stable_argsort_perm_kernel to produce out_idx (length N).
   - Launch count_expert_ids_kernel to produce counts (length num_experts).
   - Launch exclusive_prefix_sum_kernel to produce offsets (length num_experts+1).
   - Return out_idx (permutation indices) and offsets.

Limitations and assumptions
- We assume num_experts=256 as in the original run. The kernels are written for that. The counting kernel will work for general N, but the prefix sum kernel’s loop relies on num_experts known at compile time via tl.constexpr. We pass num_experts as tl.constexpr.
- The bitonic sort kernel uses a single program to sort N elements. For N up to 8192, this is fine. If N is much larger, we’d need a multi-program, segmented bitonic with merge. Given the provided workloads, single-program bitonic is acceptable for correctness.

@triton.jit
def count_expert_ids_kernel(flat_ptr, counts_ptr, N: tl.int32, num_experts: tl.int32, BLOCK: tl.constexpr):
    """
    Compute histogram of expert IDs in 'flat_ptr' (int32, length N) into 'counts_ptr' (int32, length num_experts).
    Each program processes BLOCK elements; uses masked loads and atomic adds.
    """
    pid = tl.program_id(0)
    start = pid * BLOCK
    offsets = start + tl.arange(0, BLOCK)
    mask = offsets < N

    # Load IDs; other=0 for masked lanes
    ids = tl.load(flat_ptr + offsets, mask=mask, other=0)

    # Atomic add counts per ID
    # We assume flat_ptr holds int32 IDs in range [0, num_experts-1]
    # For masked lanes, ids=0; atomic add to count 0.
    for i in range(0, BLOCK):
        idx = offsets[i]
        id_i = ids[i]
        # Only update if within bounds
        if mask[i]:
            tl.atomic_add(counts_ptr + id_i, 1)


@triton.jit
def exclusive_prefix_sum_kernel(counts_ptr, offsets_ptr, num_experts: tl.constexpr):
    """
    Exclusive prefix sum of 'counts_ptr' (int32, length num_experts) into 'offsets_ptr' (int32, length num_experts+1).
    offsets_ptr[0] = 0; offsets_ptr[i+1] = sum_{k=0..i} counts[k].
    Uses a single program with a loop over num_experts (tl.constexpr allows compile-time loop).
    """
    total = tl.int32(0)
    # Initialize first offset
    tl.store(offsets_ptr + 0, total)
    # Compute exclusive prefix sum
    for i in range(0, num_experts):
        c = tl.load(counts_ptr + i)
        total += c
        tl.store(offsets_ptr + i + 1, total)
