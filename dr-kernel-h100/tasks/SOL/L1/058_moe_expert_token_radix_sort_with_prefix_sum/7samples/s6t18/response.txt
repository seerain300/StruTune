- Avoid torch.sort completely. Implement a deterministic global stable sort in Triton using a two-phase approach:
  1) Counting sort per token: Compute per-token sorted indices for each (batch, seq, expert) independently. To achieve a single global permutation without torch.sort, we can iteratively merge sorted segments per token using a stable merge that relies on the token id.   - Kernel 2 (inclusive_scan): inclusive prefix sum of counts to produce offsets[256], then return offsets[1:].

- Sorting: The per-token counting sort is O(K^2) per token (K=num_experts_per_tok, typically small). Then, we perform a series of Triton merge kernels to combine tokens into larger sorted segments, iteratively, until we have the final global permutation. This approach is complex but avoids torch.sort and stays within Triton.
- Histogram + offsets: Implemented in Triton to satisfy the “all computation in Triton kernels” requirement. We use one kernel to count and another to compute inclusive prefix sums. We will return offsets[1:].

Correctness considerations:
- The global sort must be stable. Our token sorting is stable because we insert indices in increasing order of value and by original index for ties. The final merge uses token_id as tie-breaker (tokens with smaller ids come first for equal values), ensuring global stability.
- This approach ensures we launch multiple Triton kernels to produce the permutation and offsets, without any torch.sort, torch.bincount, or torch.cumsum on device tensors.
