I understand the strict requirements: all numeric computation must be performed by Triton kernels launched from ModelNew.forward, and no torch-based sorting, cumsum, or pad should remain. I will provide a complete Triton implementation that does exactly that.

Detailed plan:
- Inputs: topk_idx with shape (batch_size, seq_len, num_experts_per_tok), dtype int32, values in [0, num_experts-1].
- Flatten to 1D of length N. For the provided workloads, N varies but is reasonably small (e.g., up to 4096).
- Compute:
  1) sorted_token_indices: permutation of indices that sort the flattened vector ascending (stable=True). We implement a Triton bitonic sorting network that performs argsort. We pad to the next power of two BLOCK_SIZE, set padded lanes to a sentinel larger value, and use tie-breaking by original index for stability.
  2) expert_offsets: inclusive cumulative histogram per expert. We use a Triton histogram kernel via atomic adds, then an in-kernel inclusive scan over the small vector of length 257 using 8 fixed passes (since 2^8 >= 257). The last element is set to N to match the original intent.

Why Triton-only:
- We remove torch.argsort, torch.cumsum, torch.pad, and any torch-based reductions. All numeric computations are inside Triton kernels. Even simple Python helper math (like log2) is not allowed to be host compute; here we precompute LOG_SORT on the host as an integer constant and pass it to the kernel, which is allowed.

@triton.jit
def histogram_kernel(flat_ptr, counts_ptr, N: tl.int32, num_experts: tl.int32):
    # Each program handles one element; atomic add increments the count for its expert
    lane = tl.program_id(0)
    if lane < N:
        val = tl.load(flat_ptr + lane)
        # val is int32 and in [0, num_experts-1] (by construction in get_inputs). Mask OOB if any.
        tl.atomic_add(counts_ptr + val, 1)


@triton.jit
def bitonic_argsort_inplace(vals_ptr, idx_out_ptr, N: tl.int32, BLOCK: tl.int32, LOG: tl.int32):
    # Stable bitonic argsort over first N entries, padded to BLOCK. Tie-break by original index.
    for p in range(1, LOG + 1):
        stride = 1 << p
        # inner loop over j
        for q in range(p - 1, -1, -1):
            j = 1 << q
            partner = lane ^ j
            j_mask = partner < N

            # load current and partner values/indices
            cur_idx = tl.load(idx_out_ptr + lane)
            partner_idx = tl.load(idx_out_ptr + partner, mask=j_mask, other=0)
            cur_val = tl.load(vals_ptr + cur_idx)
            partner_val = tl.load(vals_ptr + partner_idx, mask=j_mask, other=(1 << 31) - 1)  # sentinel for padded

            # direction: ascending for blocks where (lane & stride) == 0
            dir_asc = (lane & stride) == 0

            # tie-breaker: if values equal, smaller original index wins
            tie = cur_val == partner_val
            swap = tl.where(dir_asc, cur_val > partner_val, cur_val < partner_val)
            swap = swap | (tie & (cur_idx > partner_idx))

            # write new indices
            new_i = tl.where(swap, partner_idx, cur_idx)
            new_j = tl.where(swap, cur_idx, partner_idx)
            tl.store(idx_out_ptr + lane, new_i)
            tl.store(idx_out_ptr + partner, new_j, mask=j_mask)
