Given the robust correctness and good speed, we can try incremental improvements while preserving semantics and the proven 2D atomic-add pattern.

Summary and plan
- Semantics: Preserve initial random values by cloning final_hidden_states. Triton must perform the atomic scatter-add for all tokens.
- Kernel structure: Keep the 2D grid over tokens and hidden column blocks with atomic_add. This is reliable and already fast.
- Host-side tuning: Adjust BLOCK_SIZE and num_warps to reduce the number of column tiles and improve throughput. Use masks for tail columns to avoid out-of-bounds.
- Keep num_stages=1 for lightweight execution.

Micro-tuning changes
- For hidden_size up to 1024, use BLOCK_SIZE=1024 with 8 warps (single column tile for many cases).
- For 1025–2048, use BLOCK_SIZE=2048 with 8 warps to reduce the number of column tiles further.
- For >2048, use BLOCK_SIZE=2048 with 8 warps (multiple column tiles). This reduces the grid’s second dimension and atomic operations per token.

These tweaks aim to maintain or slightly improve performance on typical shapes without changing semantics.

Final code (ModelNew)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_atomic_kernel(
    out_ptr, out_stride0, out_stride1,
    src_ptr, src_stride0, src_stride1,
    token_idx_ptr,  # int32 indices
    N_rows, H, N_tokens,
    BLOCK_SIZE: tl.constexpr,
):
    # 2D launch: program_id(0) = token index, program_id(1) = column block
    pid_token = tl.program_id(0)
    pid_col = tl.program_id(1)

    # Compute column offsets for this block
    col_offsets = pid_col * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = col_offsets < H

    # Load token index for this program
    tok = tl.load(token_idx_ptr + pid_token)

    # Compute pointers for this row and block
    out_ptrs = out_ptr + tok * out_stride0 + col_offsets * out_stride1
    src_ptrs = src_ptr + pid_token * src_stride0 + col_offsets * src_stride1

    # Load source values (masked for tail) and atomically add to destination
    src_vals = tl.load(src_ptrs, mask=mask, other=0.0)
    tl.atomic_add(out_ptrs, src_vals, mask=mask)


def triton_scatter_add(final_hidden_states: torch.Tensor,
                       expert_outputs: torch.Tensor,
                       token_indices: torch.Tensor):
    # Ensure device compatibility
    assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, \
        "All tensors must be on CUDA for Triton execution."

    # Preserve initial random values (clone)
    output = final_hidden_states.clone()

    # Make sure source and indices are contiguous
    expert_outputs = expert_outputs.contiguous()
    # Triton prefers int32 indices
    token_indices_i32 = token_indices.to(torch.int32)

    batch_seq_len = final_hidden_states.shape[0]
    hidden_size = final_hidden_states.shape[1]
    n_tokens = expert_outputs.shape[0]

    # Choose tiling based on hidden_size
    if hidden_size <= 1024:
        BLOCK_SIZE = 1024
        num_warps = 8
    elif hidden_size <= 2048:
        BLOCK_SIZE = 2048
        num_warps = 8
    else:
        BLOCK_SIZE = 2048
        num_warps = 8

    # 2D grid over tokens and hidden column blocks
    grid = (n_tokens, triton.cdiv(hidden_size, BLOCK_SIZE))

    # Launch Triton scatter-add kernel
    scatter_add_atomic_kernel[grid](
        output, output.stride(0), output.stride(1),
        expert_outputs, expert_outputs.stride(0), expert_outputs.stride(1),
        token_indices_i32,
        batch_seq_len, hidden_size, n_tokens,
        BLOCK_SIZE=BLOCK_SIZE,
        num_warps=num_warps,
        num_stages=1,
    )

    return output


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor,
                expert_outputs: torch.Tensor,
                token_indices: torch.Tensor):
        return triton_scatter_add(final_hidden_states, expert_outputs, token_indices)
```

Why this maintains correctness and can improve performance
- We clone final_hidden_states to preserve its initial random values exactly as in the original PyTorch behavior.
- The Triton kernel performs atomic additions for each token’s hidden slice using a 2D grid. Masks ensure no out-of-bounds accesses, and int32 indices ensure correct row addressing. This matches the semantics of output.index_add_(dim=0, index=token_indices, source=expert_outputs).
- The tiling heuristic uses larger column blocks for typical hidden sizes (≤2048), reducing the number of column tiles and kernel work per token, which can improve throughput. Using num_stages=1 keeps the kernel lightweight.
- No torch computation is used in the hot path beyond trivial setup; the heavy work is done by Triton, satisfying the requirement that the Triton implementation is the primary computation.

This approach has already shown strong speedups while maintaining correctness across evaluated workloads. If you profile further on your hardware, you can experiment with num_warps=4 for extremely large n_tokens to reduce per-launch pressure, but the above configuration provides a good balance for typical hidden sizes.
