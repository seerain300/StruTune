Optimization analysis
- Operation recap:
  - output = final_hidden_states.clone() to preserve initial random values.
  - For each token i, add expert_outputs[i] into output[token_indices[i]] along the hidden dimension. This is scatter-add across rows.
- Current Triton approach:
  - 2D grid: tokens × hidden column blocks, each program performs atomic_add for its tile. This is reliable and correct.
- Bottlenecks and opportunities:
  - Overhead from multiple column tiles can be reduced by increasing tile size when hidden_size is moderate.
  - Using an appropriate number of warps for tile size can improve throughput.
  - Keep num_stages low (1) since the kernel is memory/atomic light.

Plan
- Keep the exact semantics: output starts as clone of final_hidden_states; Triton kernel performs atomic scatter-add per token’s hidden slice.
- Adapt tile size and warps dynamically:
  - hidden_size ≤ 256: BLOCK_SIZE=512 (single column tile), num_warps=8.
  - 257 ≤ hidden_size ≤ 1024: BLOCK_SIZE=1024, num_warps=8. This reduces grid size and atomic operations for common hidden sizes.
  - hidden_size > 1024: BLOCK_SIZE=512, num_warps=8. Use two column tiles for very large hidden sizes.
- Ensure tensors are contiguous, indices are int32, and masks handle tail columns correctly.
- No torch in-place ops on the accumulation path; heavy work is done by Triton.

Final code (ModelNew)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_atomic_kernel(
    out_ptr, out_stride0, out_stride1,
    src_ptr, src_stride0, src_stride1,
    token_idx_ptr,  # int32
    N_rows, H, N_tokens,
    BLOCK_SIZE: tl.constexpr,
):
    # 2D launch: program_id(0) = token index, program_id(1) = column block
    pid_token = tl.program_id(0)
    pid_col = tl.program_id(1)

    # Compute column offsets for this block
    col_offsets = pid_col * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = col_offsets < H

    # Load token index for this program (row to scatter to)
    tok = tl.load(token_idx_ptr + pid_token)
    # Bounds check: tok must be in [0, N_rows). The provided inputs keep it valid,
    # but guarding is safe in general. If out-of-range, mask prevents writes.
    in_bounds = tok >= 0 and tok < N_rows

    # Compute pointers for this row and block of columns
    out_row_ptr = out_ptr + tok * out_stride0
    src_row_ptr = src_ptr + pid_token * src_stride0

    # Load source block and accumulate into output (masked)
    vals = tl.load(src_row_ptr + col_offsets * src_stride1, mask=mask, other=0.0)
    # Atomic add into output; masked to avoid OOB
    tl.atomic_add(out_row_ptr + col_offsets * out_stride1, vals, mask=mask & in_bounds)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor,
                expert_outputs: torch.Tensor,
                token_indices: torch.Tensor):
        """
        Triton-optimized scatter-add:
        output = final_hidden_states.clone()
        output.index_add_(dim=0, index=token_indices, source=expert_outputs)
        """
        # Clone to preserve original random values
        output = final_hidden_states.clone()

        # Shapes
        batch_seq_len = output.shape[0]
        hidden_size = output.shape[1]
        n_tokens = expert_outputs.shape[0]

        # Triton expects indices as int32 and contiguous
        token_indices_i32 = token_indices.to(torch.int32).contiguous()
        # Ensure source is contiguous
        expert_outputs = expert_outputs.contiguous()

        # Adaptive tiling based on hidden_size
        if hidden_size <= 256:
            BLOCK_SIZE = 512
            num_warps = 8
        elif hidden_size <= 1024:
            BLOCK_SIZE = 1024
            num_warps = 8
        else:
            BLOCK_SIZE = 512
            num_warps = 8

        # 2D grid over tokens and hidden column blocks
        grid = (n_tokens, triton.cdiv(hidden_size, BLOCK_SIZE))

        # Launch Triton scatter-add kernel
        scatter_add_atomic_kernel[grid](
            output, output.stride(0), output.stride(1),
            expert_outputs, expert_outputs.stride(0), expert_outputs.stride(1),
            token_indices_i32,
            batch_seq_len, hidden_size, n_tokens,
            BLOCK_SIZE=BLOCK_SIZE,
            num_warps=num_warps,
            num_stages=1,
        )

        return output
```

Why this maintains correctness and improves performance
- We still preserve the initial random values by cloning final_hidden_states, exactly matching the original PyTorch behavior.
- The Triton kernel performs atomic additions for each token’s hidden slice, using a 2D grid. Masks ensure no out-of-bounds accesses, and int32 indices ensure correct row addressing.
- Adaptive BLOCK_SIZE and num_warps reduce the number of column tiles for common hidden sizes (≤1024), cutting down kernel launches and atomic operations, which improves throughput. Using num_stages=1 keeps the kernel lightweight.
- No torch computation is used in the hot path beyond trivial setup; the heavy work is done by Triton, satisfying the requirement that the Triton implementation is the primary computation.

This should retain the 16/16 correctness and provide incremental speedups compared to the previous version. If profiling shows further opportunities, we could consider grouping tokens by row to reduce atomics per row, but given the lack of row ordering constraints in token_indices, a safe and effective improvement remains tuning tiling and warps as implemented.
