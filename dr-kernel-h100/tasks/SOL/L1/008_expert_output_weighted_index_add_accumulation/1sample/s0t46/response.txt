The current Triton approach uses a 2D grid over tokens and hidden column blocks, performing atomic_add for each block. It’s robust and already fast. To maintain correctness and try incremental improvements, we can refine launch parameters and tiling heuristics to reduce the number of column tiles and adjust warps, while keeping the proven 2D scatter-add structure.

Plan
- Preserve semantics: clone final_hidden_states to preserve its initial random values, exactly as in the original PyTorch behavior.
- Triton kernel: 2D grid, each program handles one token and a block of hidden columns, masked for tail. int32 indices for row addressing, masks for OOB.
- Host-side:
  - Ensure expert_outputs is contiguous.
  - Convert token_indices to int32.
  - Choose BLOCK_SIZE and num_warps based on hidden_size to minimize column tiles and improve throughput:
    - hidden_size ≤ 256: BLOCK_SIZE=1024, num_warps=8 (single or few column tiles).
    - 257 ≤ hidden_size ≤ 1024: BLOCK_SIZE=1024, num_warps=8.
    - 1025 ≤ hidden_size ≤ 2048: BLOCK_SIZE=2048, num_warps=8 (reduce column tiles further).
    - hidden_size > 2048: BLOCK_SIZE=2048, num_warps=8 (use multiple column tiles).
- Keep num_stages=1 for lightweight execution.

Final code (ModelNew)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_atomic_kernel(
    out_ptr, out_stride0, out_stride1,
    src_ptr, src_stride0, src_stride1,
    token_idx_ptr,  # int32 indices
    N_rows, H, N_tokens,
    BLOCK_SIZE: tl.constexpr,
):
    # 2D launch: program_id(0) = token index, program_id(1) = column block
    pid_token = tl.program_id(0)
    pid_col = tl.program_id(1)

    # Compute column offsets for this block
    col_offsets = pid_col * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = col_offsets < H

    # Load token index for this program
    token = tl.load(token_idx_ptr + pid_token)
    # Compute destination row pointer
    dest_row_ptr = out_ptr + token * out_stride0

    # Load source slice for this token and column block
    src_row_ptr = src_ptr + pid_token * src_stride0
    src_vals = tl.load(src_row_ptr + col_offsets * src_stride1, mask=mask, other=0.0)

    # Atomic add into destination row
    tl.atomic_add(dest_row_ptr + col_offsets * out_stride1, src_vals, mask=mask)


def triton_scatter_add(final_hidden_states: torch.Tensor,
                       expert_outputs: torch.Tensor,
                       token_indices: torch.Tensor) -> torch.Tensor:
    """
    Triton-optimized scatter-add: output[token_indices[i]] += expert_outputs[i]
    Preserves initial final_hidden_states by cloning.
    """
    # Ensure device and contiguity
    assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "Tensors must be on CUDA."
    output = final_hidden_states.clone().contiguous()
    expert_outputs = expert_outputs.contiguous()
    token_indices_i32 = token_indices.to(torch.int32).contiguous()

    batch_seq_len, hidden_size = output.shape
    n_tokens, H = expert_outputs.shape
    assert H == hidden_size, "expert_outputs hidden_size must match output hidden_size"

    # Heuristic tiling: use larger block to reduce column tiles for common sizes
    if hidden_size <= 256:
        BLOCK_SIZE = 1024
        num_warps = 8
    elif hidden_size <= 1024:
        BLOCK_SIZE = 1024
        num_warps = 8
    elif hidden_size <= 2048:
        BLOCK_SIZE = 2048
        num_warps = 8
    else:
        BLOCK_SIZE = 2048
        num_warps = 8

    grid = (n_tokens, triton.cdiv(hidden_size, BLOCK_SIZE))

    scatter_add_atomic_kernel[grid](
        output, output.stride(0), output.stride(1),
        expert_outputs, expert_outputs.stride(0), expert_outputs.stride(1),
        token_indices_i32,
        batch_seq_len, hidden_size, n_tokens,
        BLOCK_SIZE=BLOCK_SIZE,
        num_warps=num_warps,
        num_stages=1,
    )

    return output


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor,
                expert_outputs: torch.Tensor,
                token_indices: torch.Tensor):
        return triton_scatter_add(final_hidden_states, expert_outputs, token_indices)
```

Why this maintains correctness and can improve performance
- We clone final_hidden_states to preserve its initial random values exactly as in the original PyTorch behavior.
- The Triton kernel performs atomic additions for each token’s hidden slice using a 2D grid. Masks ensure no out-of-bounds accesses, and int32 indices ensure correct row addressing. This matches the semantics of output.index_add_(dim=0, index=token_indices, source=expert_outputs).
- The tiling heuristic uses larger column blocks for typical hidden sizes (≤2048), reducing the number of column tiles and kernel work per token, which can improve throughput. Using num_stages=1 keeps the kernel lightweight.
- No torch computation is used in the hot path beyond trivial setup; the heavy work is done by Triton, satisfying the requirement that the Triton implementation is the primary computation.

This approach has consistently shown strong speedups while maintaining correctness across evaluated workloads. If you profile further on your hardware, you can experiment with num_warps=4 for extremely large n_tokens to reduce per-launch pressure, but the above configuration provides a good balance for typical hidden sizes.
