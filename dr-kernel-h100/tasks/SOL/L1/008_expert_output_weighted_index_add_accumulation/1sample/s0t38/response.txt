The operation is a scatter-add along rows: output = final_hidden_states.clone(), then for each token i, output[token_indices[i]] += expert_outputs[i] across hidden_size columns. Our Triton kernel uses a 2D grid over tokens and hidden column blocks with atomic_add, which is robust.

To further optimize performance while preserving correctness, we can:
- Keep the exact semantics: preserve initial random values by cloning, and perform scatter-add via Triton.
- Adapt tile size and number of warps based on hidden_size to reduce grid size and improve throughput, while ensuring masks prevent out-of-bounds access.
- Maintain num_stages at 1 since the kernel is memory/atomic-light.

Implementation notes
- The Triton kernel will:
  - Use a 2D launch: program_id(0) indexes tokens; program_id(1) indexes hidden column blocks.
  - Compute col_offsets for the block, apply a mask for tail columns.
  - Load the token index (int32), compute destination row address, and atomic_add the source slice.
- Host code:
  - Clone final_hidden_states to preserve its initial values.
  - Convert token_indices to int32 and ensure expert_outputs is contiguous.
  - Choose BLOCK_SIZE and num_warps based on hidden_size:
    - hidden_size ≤ 256: BLOCK_SIZE=512, num_warps=8 (single column tile for many cases).
    - 257 ≤ hidden_size ≤ 1024: BLOCK_SIZE=1024, num_warps=8 (reduce column tiles).
    - hidden_size > 1024: BLOCK_SIZE=512, num_warps=8 (two column tiles).
  - Launch kernel with grid = (n_tokens, ceil_div(hidden_size, BLOCK_SIZE)).

This maintains correctness and should provide stable performance. Below is the complete ModelNew implementation.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_atomic_kernel(
    out_ptr, out_stride0, out_stride1,
    src_ptr, src_stride0, src_stride1,
    token_idx_ptr,  # int32 indices
    N_rows, H, N_tokens,
    BLOCK_SIZE: tl.constexpr,
):
    # 2D launch: each program handles one token and one column block
    pid_token = tl.program_id(0)  # token id
    pid_col = tl.program_id(1)    # column block id

    # Compute column offsets for this block
    col_offsets = pid_col * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    col_mask = col_offsets < H

    # Load token index (int32)
    tok = tl.load(token_idx_ptr + pid_token)  # scalar int32

    # Compute per-row and per-column strides
    # out_ptr points to row 0, col 0. Address of out[tok, col_offsets]:
    out_row_base = tok * out_stride0
    src_row_base = pid_token * src_stride0  # pid_token is token index into src rows

    # Form pointers for this tile
    out_ptrs = out_ptr + out_row_base + col_offsets * out_stride1
    src_ptrs = src_ptr + src_row_base + col_offsets * src_stride1

    # Atomic add: add this tile of expert_outputs to the corresponding positions in output
    # Use 'other=0' in load to ignore invalid lanes, but atomic_add only affects valid lanes via mask.
    # Triton supports atomic_add for fp16/bf16/fp32.
    tl.atomic_add(out_ptrs, tl.load(src_ptrs, mask=col_mask, other=0.0), mask=col_mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor,
                expert_outputs: torch.Tensor,
                token_indices: torch.Tensor) -> torch.Tensor:
        """
        Triton-optimized scatter-add:
        output = final_hidden_states.clone()
        output[token_indices[i]] += expert_outputs[i] for all i
        """
        # Preserve initial random values
        output = final_hidden_states.clone()

        # Shapes
        batch_seq_len = output.shape[0]
        hidden_size = output.shape[1]
        n_tokens = expert_outputs.shape[0]

        # Triton expects indices as int32 and contiguous
        token_indices_i32 = token_indices.to(torch.int32).contiguous()
        # Ensure source tensor is contiguous
        expert_outputs = expert_outputs.contiguous()

        # Adaptive tiling based on hidden_size
        if hidden_size <= 256:
            BLOCK_SIZE = 512
            num_warps = 8
        elif hidden_size <= 1024:
            BLOCK_SIZE = 1024
            num_warps = 8
        else:
            BLOCK_SIZE = 512
            num_warps = 8

        # 2D grid over tokens and hidden column blocks
        grid = (n_tokens, triton.cdiv(hidden_size, BLOCK_SIZE))

        # Launch Triton scatter-add kernel
        scatter_add_atomic_kernel[grid](
            output, output.stride(0), output.stride(1),
            expert_outputs, expert_outputs.stride(0), expert_outputs.stride(1),
            token_indices_i32,
            batch_seq_len, hidden_size, n_tokens,
            BLOCK_SIZE=BLOCK_SIZE,
            num_warps=num_warps,
            num_stages=1,
        )

        return output
```

Why this maintains correctness and improves performance
- We clone final_hidden_states to preserve its initial random values, exactly matching the original PyTorch behavior.
- The Triton kernel performs atomic additions for each token’s hidden slice, using a 2D grid. Masks ensure no out-of-bounds accesses. Indices are int32 for correct row addressing.
- Adaptive BLOCK_SIZE and num_warps reduce the number of column tiles for common hidden sizes (≤1024), cutting down kernel launches and atomic operations, which improves throughput. Using num_stages=1 keeps the kernel lightweight.
- No torch computation is used in the hot path beyond trivial setup; the heavy work is done by Triton, satisfying the requirement that the Triton implementation is the primary computation.

This should retain the 16/16 correctness and provide stable speedups. If further tuning is desired for specific hardware, you can experiment with BLOCK_SIZE=256 for very small hidden_size to reduce register pressure, or keep 1024 for larger sizes.
