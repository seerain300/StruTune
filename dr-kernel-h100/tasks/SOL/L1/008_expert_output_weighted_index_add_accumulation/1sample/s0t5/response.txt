- To avoid these pitfalls, I will:
  - Use torch.empty to allocate the output (fast and reliable). Then use Triton to zero-initialize it. This ensures we have a correct output buffer and the Triton kernel is actually exercised.
  - Use a robust Triton scatter kernel that:
    - Launches one program per token.
    - Iterates over hidden columns in fixed-size chunks (BLOCK_SIZE) using a simple while loop inside the kernel.
    - Performs atomic_add into out[token_index, col:col+BLOCK_SIZE] with correct masking for the tail.
  - Ensure dtype conversions are correct and tokens are int32 for Triton.

Design
- Forward:
  - Compute batch_seq_len = batch_size * seq_len.
  - Allocate out = torch.empty(batch_seq_len, hidden_size, dtype=torch.bfloat16, device=device). This is a fast allocation and will be zeroed via Triton.
  - Launch zero_init_kernel: 2D grid (rows, column blocks). For each (row, col_block), write zeros to out[row, col:col+BLOCK_SIZE] using masks. This covers all rows and columns.
  - Convert token_indices to int32 and ensure expert_outputs is contiguous.
  - Launch scatter_add_atomic_kernel: grid = (num_selected_tokens,), each program handles one token i:
    - Load token_index = token_indices[i].
    - Loop over columns in chunks of BLOCK_SIZE:
      - Compute cols = col + arange(0, BLOCK_SIZE).
      - mask = cols < hidden_size.
      - Load expert_vals = expert_outputs[i, cols] with mask.
      - atomic_add into out[token_index, cols] with mask.
- This guarantees:
  - Out starts at exactly zeros due to the Triton zero-init kernel.
  - Every token’s contribution is added via atomic_add, matching index_add semantics.
  - No torch operations perform the heavy lifting; only allocation and kernel launches occur.

Correctness checks
- The zero-init kernel writes zeros to every row across all columns. Using a 2D grid over (row, col-block) ensures full coverage even if hidden_size is not a multiple of BLOCK_SIZE.
- The scatter kernel performs atomic adds per token, so if multiple tokens map to the same row, the row accumulates correctly.
- Using torch.empty for out ensures we allocate exactly the required shape and dtype; the Triton zero-init then makes it correct. This avoids any stride-related surprises.

- Scatter kernel is O(num_selected_tokens * hidden_size) with one program per token. For the given workloads, this is reasonable. Atomic adds are performed only on the destination row, which is fine.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def zero_init_kernel(out_ptr, stride_row, stride_col, batch_seq_len, hidden_size, BLOCK_SIZE: tl.constexpr):
    # 2D grid: axis-0 over rows, axis-1 over column blocks
    row = tl.program_id(0)
    col_block = tl.program_id(1)
    cols = col_block * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = (row < batch_seq_len) & (cols < hidden_size)
    # Compute offsets: row*stride_row + cols*stride_col
    offsets = row * stride_row + cols * stride_col
    # Zero vector for this block
    zeros = tl.zeros([BLOCK_SIZE], dtype=tl.bfloat16)
    tl.store(out_ptr + offsets, zeros, mask=mask)


@triton.jit
def scatter_add_atomic_kernel(
    out_ptr, stride_row, stride_col,
    expert_ptr, expert_stride_row, expert_stride_col,
    token_indices_ptr,
    batch_seq_len, hidden_size, n_tokens, BLOCK_SIZE: tl.constexpr
):
    # One program per token
    i = tl.program_id(0)
    # Load token index (int32)
    token_index = tl.load(token_indices_ptr + i)
    # Ensure token_index is within bounds (get_inputs guarantees valid indices)
    # Loop over hidden columns in chunks
    # Note: Triton supports while-loops; use them here for robustness across hidden sizes.
    col = 0
    while col < hidden_size:
        cols = col + tl.arange(0, BLOCK_SIZE)
        mask = cols < hidden_size
        # Load expert vector for this token at cols
        expert_offsets = i * expert_stride_row + cols * expert_stride_col
        vals = tl.load(expert_ptr + expert_offsets, mask=mask, other=0.0)  # dtype follows ptr (bfloat16)
        # Compute out offsets for this row and columns
        out_offsets = token_index * stride_row + cols * stride_col
        # Atomic add into output
        tl.atomic_add(out_ptr + out_offsets, vals, mask=mask)
        col += BLOCK_SIZE
```
