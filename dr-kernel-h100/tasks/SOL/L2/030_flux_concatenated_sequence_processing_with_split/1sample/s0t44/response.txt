Design and plan

- Inputs:
  - hidden_states: [B, I, H]
  - encoder_hidden_states: [B, T, H]
  - process_weight: [H, H] (no bias), applied as right-multiply

- Steps:
  1) Concatenate along sequence dimension to get out_cat: [B, T+I, H].
     - Triton kernel: one program per batch. For each l in [0, T+I), if l < T: load from encoder; else: load from hidden. Store to out_cat. Masks for bounds.

  2) Batched GEMM in Triton:
     - A = out_cat, shape [M, K] where M = B*(T+I), K = H.
     - W = process_weight, shape [K, K] (we pass W as [K,K] and right-multiply by W^T).
     - Output C: [M, K]. Each Triton program computes a BLOCK_M x BLOCK_N tile, loops over K in BLOCK_K chunks, performs tl.dot, and accumulates in fp32. Important: We must map each flattened row m back to (batch b, seq l) to ensure A[m,:] selects the correct row of out_cat. This is done by b = m // (T+I), l = m % (T+I).
     - Use masks for M, N, and K bounds. Ensure W is contiguous and on the same device; cast to float32 for compute stability.

  3) Split C back into two streams:
     - Triton kernel: one program per batch. For each output row m in [0, M), map to (b, l) as above. If l < T: copy C[m, :] to processed_encoder[b, l, :]; else: to processed_hidden[b, l - T, :]. Masks ensure bounds for H.

- Device/dtype handling:
  - Ensure all tensors are on the same device. If hidden_states are on CUDA, all Triton kernels require CUDA. We’ll assume CUDA for evaluation. If device mismatch, we’ll move tensors appropriately (not typical for eval, but included defensively).
  - Perform compute in float32 (inputs converted to float32). Outputs will be float32. The original reference uses torch.float32 by default, so this should match. If you need original dtype, we can cast at the end, but default float32 is fine.

    stride_A_m, stride_A_k,

    stride_C_m, stride_C_n,

    pid_m = tl.program_id(axis=0)
    pid_n = tl.program_id(axis=1)

    m_offsets = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)

        a_ptrs = A_ptr + m_offsets[:, None] * stride_A_m + (k + k_offsets[None, :]) * stride_A_k  # [BM, BK]

        w = tl.load(w_ptrs, mask=(k + k_offsets[:, None] < K) & (n_offsets[None, :] < N), other=0.0)
        acc += tl.dot(a, w)

    # Write back
    c_ptrs = C_ptr + m_offsets[:, None] * stride_C_m + n_offsets[None, :] * stride_C_n
    tl.store(c_ptrs, acc, mask=(m_offsets[:, None] < M) & (n_offsets[None, :] < N))

Explanation and corrective measures

- Concatenation Triton kernel: One program per batch, loops over the concatenated sequence length and loads from either input tensor. Uses masks to avoid out-of-bounds. This avoids torch.cat and is robust for any T, I, H.
- Batched GEMM Triton kernel: A 2D-tiled matmul over (M, H). Each program computes a tile and reduces over K (H) in BLOCK_K chunks using tl.dot, accumulating in float32. It’s important to map the flattened row index m to (batch b, seq l) via b = m // (T+I), l = m % (T+I) to select the correct row in A = out_cat. Masks protect against boundary tiles.
- Split Triton kernel: One program per batch. For each l in [0, T+I), compute m = b*(T+I) + l, load C[m, :], and store to the appropriate output tensor. This avoids torch.split and keeps the computation in Triton, although Triton’s vectorized 2D loads are limited here; the per-l loop ensures correctness.
