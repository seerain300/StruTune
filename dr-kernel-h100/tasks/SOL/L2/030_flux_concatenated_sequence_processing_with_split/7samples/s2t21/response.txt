Key points and plan
- Original logic:
  - Concatenate encoder_hidden_states [B, T, H] and hidden_states [B, I, H] along sequence dim → concatenated [B, S, H], S = T + I.
  - Apply linear projection: processed = concatenated @ process_weight.T, where process_weight is [H, H] and process_weight.T is [H, H].
  - Split: processed_encoder = processed[:, :T, :], processed_hidden = processed[:, T:, :].

- Triton-only approach:
  1) concat_seqs_kernel: Given [B, T, H] and [B, I, H], create [B, S, H] by copying appropriate rows into first T and last I positions. This is a simple elementwise Triton copy with masks for bounds.
  2) matmul_seqs_kernel: For each batch b, compute C[b] = concatenated[b] @ process_weight.T. We implement a robust 2D tiled GEMM per batch with grid over tiles of M (rows S) and N (columns H), looping over K (H). We pass explicit strides to avoid indexing mistakes.
  3) split_seqs_kernel: Given C [B, S, H], write C[:, :T, :] to processed_encoder and C[:, T:, :] to processed_hidden. This is a simple copy kernel.

- Forward function:
  - Ensure inputs and process_weight are on CUDA and contiguous.
  - Allocate concatenated, processed_encoder, processed_hidden.
  - Launch concat_seqs_kernel to populate concatenated [B, S, H].
  - Launch matmul_seqs_kernel to compute C [B, S, H].
  - Launch split_seqs_kernel to produce outputs.
  - Return processed_encoder, processed_hidden.

This implementation keeps all heavy computation in Triton and avoids any torch operations in forward, while matching the original logic exactly. The kernels use explicit strides and masks to prevent out-of-bounds accesses and handle arbitrary shapes.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def concat_seqs_kernel(
    enc_ptr,              # *const T, [B, T, H]
    hidden_ptr,           # *const T, [B, I, H]
    out_ptr,              # *T, [B, S, H]
    B, T, I, H, S,
    enc_stride_b, enc_stride_t, enc_stride_h,
    hid_stride_b, hid_stride_i, hid_stride_h,
    out_stride_b, out_stride_s, out_stride_h,
    BLOCK_H: tl.constexpr,
):
    # Each program handles one output element [b, s, h]
    b = tl.program_id(0)
    s = tl.program_id(1)
    h = tl.program_id(2)

    # Bounds
    if (b >= 0 and b < B) and (s >= 0 and s < S) and (h >= 0 and h < H):
        # Copy from encoder for s < T
        if s < T:
            src_ptr = enc_ptr + b * enc_stride_b + s * enc_stride_t + h * enc_stride_h
            dst_ptr = out_ptr + b * out_stride_b + s * out_stride_s + h * out_stride_h
            val = tl.load(src_ptr)
            tl.store(dst_ptr, val)
        # Copy from hidden for s >= T
        else:
            src_i = s - T
            src_ptr = hidden_ptr + b * hid_stride_b + src_i * hid_stride_i + h * hid_stride_h
            dst_ptr = out_ptr + b * out_stride_b + s * out_stride_s + h * out_stride_h
            val = tl.load(src_ptr)
            tl.store(dst_ptr, val)


@triton.jit
def matmul_seqs_kernel(
    A_ptr,                # *const T, [B*S, H], actually per-batch A[b*S + m, :]
    Bt_ptr,               # *const T, [H, H]
    C_ptr,                # *T, [B*S, H]
    S, H,
    A_stride_m, A_stride_k,
    Bt_stride_k, Bt_stride_n,
    C_stride_m, C_stride_n,
    BLOCK_M: tl.constexpr,
    BLOCK_N: tl.constexpr,
    BLOCK_K: tl.constexpr,
):
    # 2D grid over tiles of M (rows) and N (cols)
    m_block = tl.program_id(0)
    n_block = tl.program_id(1)

    m_offsets = m_block * BLOCK_M + tl.arange(0, BLOCK_M)
    n_offsets = n_block * BLOCK_N + tl.arange(0, BLOCK_N)

    # Accumulator
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # Loop over K dimension
    for k_start in range(0, H, BLOCK_K):
        k_offsets = k_start + tl.arange(0, BLOCK_K)

        # Load A tile: shape (BLOCK_M, BLOCK_K)
        a_ptrs = A_ptr + m_offsets[:, None] * A_stride_m + k_offsets[None, :] * A_stride_k
        a_mask = (m_offsets[:, None] < S) & (k_offsets[None, :] < H)
        a = tl.load(a_ptrs, mask=a_mask, other=0.0)

        # Load Bt tile: shape (BLOCK_K, BLOCK_N)
        b_ptrs = Bt_ptr + k_offsets[:, None] * Bt_stride_k + n_offsets[None, :] * Bt_stride_n
        b_mask = (k_offsets[:, None] < H) & (n_offsets[None, :] < H)
        b = tl.load(b_ptrs, mask=b_mask, other=0.0)

        # Accumulate
        acc += tl.dot(a, b)

    # Store results into C
    c_ptrs = C_ptr + m_offsets[:, None] * C_stride_m + n_offsets[None, :] * C_stride_n
    c_mask = (m_offsets[:, None] < S) & (n_offsets[None, :] < H)
    tl.store(c_ptrs, acc, mask=c_mask)


@triton.jit
def split_seqs_kernel(
    C_ptr,                # *const T, [B, S, H]
    out_e_ptr,            # *T, [B, T, H]
    out_i_ptr,            # *T, [B, I, H]
    B, T, I, H, S,
    C_stride_b, C_stride_s, C_stride_h,
    out_e_stride_b, out_e_stride_t, out_e_stride_h,
    out_i_stride_b, out_i_stride_i, out_i_stride_h,
    BLOCK_H: tl.constexpr,
):
    # Each program handles one element [b, pos, h] where pos < T goes to encoder, else to hidden
    b = tl.program_id(0)
    pos = tl.program_id(1)
    h = tl.program_id(2)

    if (b >= 0 and b < B) and (pos >= 0 and pos < S) and (h >= 0 and h < H):
        src_ptr = C_ptr + b * C_stride_b + pos * C_stride_s + h * C_stride_h
        val = tl.load(src_ptr)
        if pos < T:
            dst_ptr = out_e_ptr + b * out_e_stride_b + pos * out_e_stride_t + h * out_e_stride_h
        else:
            dst_ptr = out_i_ptr + b * out_i_stride_b + (pos - T) * out_i_stride_i + h * out_i_stride_h
        tl.store(dst_ptr, val)


class ModelNew(torch.nn.Module):
    def forward(
        self,
        hidden_states: torch.Tensor,
        encoder_hidden_states: torch.Tensor,
        process_weight: torch.Tensor,
    ) -> tuple[torch.Tensor, torch.Tensor]:
        """
        Triton-optimized version of the original run:
        - Concatenates encoder_hidden_states and hidden_states along sequence dimension in Triton.
        - Applies linear projection via Triton matmul with process_weight.T.
        - Splits the result back into encoder and hidden parts in Triton.
        """
        assert hidden_states.is_cuda and encoder_hidden_states.is_cuda and process_weight.is_cuda, "Inputs must be on CUDA"
        hidden_states = hidden_states.contiguous()
        encoder_hidden_states = encoder_hidden_states.contiguous()
        process_weight = process_weight.contiguous()

        B = hidden_states.shape[0]
        T = encoder_hidden_states.shape[1]
        I = hidden_states.shape[1]
        S = T + I
        H = hidden_states.shape[2]

        # 1) Concatenate in Triton: [B, S, H]
        concatenated = torch.empty((B, S, H), device=hidden_states.device, dtype=hidden_states.dtype)
        grid_concat = (B, S, H)
        concat_seqs_kernel[grid_concat](
            encoder_hidden_states, hidden_states, concatenated,
            B, T, I, H, S,
            encoder_hidden_states.stride(0), encoder_hidden_states.stride(1), encoder_hidden_states.stride(2),
            hidden_states.stride(0), hidden_states.stride(1), hidden_states.stride(2),
            concatenated.stride(0), concatenated.stride(1), concatenated.stride(2),
            BLOCK_H=1,
            num_warps=1, num_stages=1,
        )

        # 2) Matmul via Triton: C[b] = concatenated[b] @ process_weight.T, for each batch b
        # Flatten batch rows into M = S
        C = torch.empty((B, S, H), device=hidden_states.device, dtype=hidden_states.dtype)
        # Note: We need per-batch kernels. Launch B programs, each handling its batch.
        for b in range(B):
            # A for this batch is concatenated[b] with shape [S, H]
            A = concatenated[b]  # [S, H]
            Bt = process_weight.t()  # [H, H]
            C_b = C[b]  # [S, H]
            grid_matmul = (triton.cdiv(S, 128), triton.cdiv(H, 128))
            matmul_seqs_kernel[grid_matmul](
                A, Bt, C_b,
                S, H,
                A.stride(0), A.stride(1),  # A[m, k]: stride_m = H, stride_k = 1 for contiguous [S, H]
                Bt.stride(0), Bt.stride(1),  # Bt[k, n]
                C_b.stride(0), C_b.stride(1),  # C[m, n]
                BLOCK_M=128, BLOCK_N=128, BLOCK_K=64,
                num_warps=4, num_stages=2,
            )

        # 3) Split in Triton: processed_encoder [B, T, H], processed_hidden [B, I, H]
        processed_encoder = torch.empty((B, T, H), device=hidden_states.device, dtype=hidden_states.dtype)
        processed_hidden = torch.empty((B, I, H), device=hidden_states.device, dtype=hidden_states.dtype)
        grid_split = (B, S, H)
        split_seqs_kernel[grid_split](
            C, processed_encoder, processed_hidden,
            B, T, I, H, S,
            C.stride(0), C.stride(1), C.stride(2),
            processed_encoder.stride(0), processed_encoder.stride(1), processed_encoder.stride(2),
            processed_hidden.stride(0), processed_hidden.stride(1), processed_hidden.stride(2),
            BLOCK_H=1,
            num_warps=1, num_stages=1,
        )

        return processed_encoder, processed_hidden
```

Explanation
- concat_seqs_kernel: Copies each element from either encoder or hidden into the concatenated tensor at the correct position. The grid is 3D over (B, S, H), which allows simple and safe indexing with masks. Although BLOCK_H=1 and num_warps=1 make it slower, correctness is prioritized. For performance, you can later switch to 2D tiling over H if needed.
- matmul_seqs_kernel: Implements a standard 2D-tiled GEMM per batch. The grid is over tiles of M (rows = S) and N (cols = H), looping over K (H) in chunks of BLOCK_K. Strides are explicitly passed for A, Bt, and C to avoid incorrect pointer arithmetic. This is the main Triton compute.
- split_seqs_kernel: Copies elements from C into processed_encoder and processed_hidden based on position. The grid is 3D over (B, S, H). Masks ensure we only write valid indices.

This design ensures all operations are in Triton, avoids torch.cat in forward, and should eliminate the runtime errors by keeping indexing straightforward and avoiding complex batched grids. If performance needs tuning after correctness is validated, you can:
- Increase BLOCK_N/BLOCK_M to 128 and use a 2D tiling across H to reduce launch overhead.
- Use more warps and stages for larger H.
- Fuse kernels where possible, but the current structure keeps semantics clear and robust.
