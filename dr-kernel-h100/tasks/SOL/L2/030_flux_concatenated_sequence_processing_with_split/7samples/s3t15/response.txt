Diagnosis and plan

- The original PyTorch logic is straightforward:
  - Concatenate [N, L_txt, K] and [N, L_img, K] along the sequence dimension to get [N, L_total, K], where L_total = L_txt + L_img.
  - Apply a linear projection: processed = concatenated @ process_weight.T, shape [N, L_total, K].
  - Split back into two streams: [:, :L_txt, :] and [:, L_txt:, :].

- The evaluation requires that all numeric computation be performed by Triton kernels invoked from ModelNew.forward. The earlier submissions failed with RUNTIME_ERROR, which strongly suggests issues in the Triton kernels rather than the host logic. The most likely causes:
  - Improper grid sizing or pointer arithmetic in the GEMM kernel.
  - Using tl.static_range or Python-side loops with non-constexpr bounds, which can cause compilation/runtime issues on variable sizes.
  - Accumulation dtype mismatches or storing to incorrect positions.

- To restore correctness robustly:
  - Implement the GEMM in Triton as a per-row, while-loop-based kernel. This avoids tl.static_range and reduces risk for variable K. Each program instance computes one output row (i.e., one (n, t) pair) times K, iterating over K in chunks of BLOCK_K.
  - Keep the concatenation in a simple Triton data-movement kernel that writes to out[n, t, k] by selecting from encoder or hidden based on t < L_txt. Use masks for tail K.
  - Launch both Triton kernels in forward, and perform minimal host-side operations: allocations, reshaping, and splitting. No torch.cat or torch.matmul for numeric work.

- Performance considerations:
  - This implementation prioritizes correctness. Once correctness is stable, we can introduce tiling (processing multiple rows per program or tiling columns) and autotune BLOCK_K/num_warps for better performance. However, given the evaluation repeatedly flagged runtime errors, we keep the kernels simple and robust for now.
  - We accumulate GEMM in float32 and cast back to the original dtype at the end.

Final code

```python
import torch
import triton
import triton.language as tl

# Triton kernel: concatenate [N, L_txt, K] and [N, L_img, K] into [N, L_txt+L_img, K]
@triton.jit
def _concat_sequences_kernel(
    out_ptr,  # *fp32, shape [N, L_total, K]
    encoder_ptr,  # *fp32, shape [N, L_txt, K]
    hidden_ptr,  # *fp32, shape [N, L_img, K]
    N: tl.constexpr, L_txt: tl.constexpr, L_img: tl.constexpr, K: tl.constexpr,
    out_stride_n, out_stride_t, out_stride_k,
    enc_stride_n, enc_stride_t, enc_stride_k,
    hid_stride_n, hid_stride_t, hid_stride_k,
    BLOCK_K: tl.constexpr,
):
    pid_n = tl.program_id(0)
    pid_t = tl.program_id(1)
    pid_k = tl.program_id(2)

    # compute k offsets
    k_offsets = pid_k * BLOCK_K + tl.arange(0, BLOCK_K)
    mask_k = k_offsets < K

    # source selection: if pid_t < L_txt -> encoder, else -> hidden
    # load values
    if pid_t < L_txt:
        # encoder[n, pid_t, k]
        enc_ptrs = encoder_ptr + pid_n * enc_stride_n + pid_t * enc_stride_t + k_offsets * enc_stride_k
        vals = tl.load(enc_ptrs, mask=mask_k, other=0.0)
    else:
        # hidden[n, pid_t - L_txt, k]
        src_t = pid_t - L_txt
        hid_ptrs = hidden_ptr + pid_n * hid_stride_n + src_t * hid_stride_t + k_offsets * hid_stride_k
        vals = tl.load(hid_ptrs, mask=mask_k, other=0.0)

    # store to out[n, pid_t, k]
    out_ptrs = out_ptr + pid_n * out_stride_n + pid_t * out_stride_t + k_offsets * out_stride_k
    tl.store(out_ptrs, vals, mask=mask_k)


# Triton kernel: per-row GEMM. Each program handles one row (n, t) and computes C[n, t, :] = A[n, t, :] @ B
# where A is [N_rows, K] contiguous rows of concatenated tensor, B is [K, K].
@triton.jit
def _matmul_row_kernel(
    C_ptr,  # *fp32, shape [N_rows, K]
    A_ptr,  # *fp32, shape [N_rows, K]
    B_ptr,  # *fp32, shape [K, K]
    N_rows: tl.constexpr, K: tl.constexpr,
    BLOCK_K: tl.constexpr,
):
    # one program per row
    row_id = tl.program_id(0)
    # guard (in case grid > N_rows)
    if row_id >= N_rows:
        return

    # accumulator
    acc = tl.zeros((K,), dtype=tl.float32)

    # loop over K in chunks
    for k0 in range(0, K, BLOCK_K):
        k_offsets = k0 + tl.arange(0, BLOCK_K)
        mask_k = k_offsets < K

        # load A row chunk: A[row_id, k_offsets]
        a_ptrs = A_ptr + row_id * K + k_offsets
        a = tl.load(a_ptrs, mask=mask_k, other=0.0)

        # load B chunk: B[k_offsets, :]
        b_ptrs = B_ptr + k_offsets[:, None] * K + tl.arange(0, K)[None, :]
        # mask for B: valid k_offsets in the first dim
        b = tl.load(b_ptrs, mask=mask_k[:, None], other=0.0)

        # outer product and accumulate
        acc += tl.sum(a[:, None] * b, axis=0)

    # store result
    c_ptrs = C_ptr + row_id * K + tl.arange(0, K)
    tl.store(c_ptrs, acc, mask=True)  # K is exact, so mask is not needed; but keeping for safety


class ModelNew(torch.nn.Module):
    def forward(
        self,
        hidden_states: torch.Tensor,
        encoder_hidden_states: torch.Tensor,
        process_weight: torch.Tensor,
    ) -> tuple[torch.Tensor, torch.Tensor]:
        # Shapes:
        # hidden_states: [N, L_img, K]
        # encoder_hidden_states: [N, L_txt, K]
        # process_weight: [K, K] (PyTorch Linear: in_features=K, out_features=K)
        # We will compute:
        # concatenated = cat([encoder_hidden_states, hidden_states], dim=1) -> [N, L_total, K]
        # processed = concatenated @ process_weight.T -> [N, L_total, K]
        # return processed_encoder = processed[:, :L_txt, :], processed_hidden = processed[:, L_txt:, :]

        # Ensure CUDA tensors and contiguous memory
        device = hidden_states.device
        assert hidden_states.is_cuda and encoder_hidden_states.is_cuda and process_weight.is_cuda, "Tensors must be on CUDA for Triton."
        N = hidden_states.shape[0]
        K = hidden_states.shape[2]
        L_img = hidden_states.shape[1]
        L_txt = encoder_hidden_states.shape[1]
        L_total = L_txt + L_img

        # Make inputs contiguous
        hidden = hidden_states.contiguous()
        encoder = encoder_hidden_states.contiguous()
        weight = process_weight.contiguous()

        # 1) Concatenate using Triton: out [N, L_total, K]
        out = torch.empty((N, L_total, K), device=device, dtype=torch.float32)

        # Compute strides (in elements)
        out_stride_n = out.stride(0)
        out_stride_t = out.stride(1)
        out_stride_k = out.stride(2)

        enc_stride_n = encoder.stride(0)
        enc_stride_t = encoder.stride(1)
        enc_stride_k = encoder.stride(2)

        hid_stride_n = hidden.stride(0)
        hid_stride_t = hidden.stride(1)
        hid_stride_k = hidden.stride(2)

        # Grid: (N, L_total, tiles along K). Choose BLOCK_K=128 for good balance.
        BLOCK_K = 128
        grid_concat = (N, L_total, triton.cdiv(K, BLOCK_K))
        _concat_sequences_kernel[grid_concat](
            out, encoder, hidden,
            N, L_txt, L_img, K,
            out_stride_n, out_stride_t, out_stride_k,
            enc_stride_n, enc_stride_t, enc_stride_k,
            hid_stride_n, hid_stride_t, hid_stride_k,
            BLOCK_K=BLOCK_K,
            num_warps=4, num_stages=2,
        )

        # 2) GEMM with Triton: A_rows = out reshaped to [N_rows, K], B = weight.T -> [K, K]
        A_rows = out.view(N * L_total, K).contiguous()  # [N_rows, K]
        B = weight.t().contiguous()  # [K, K]

        # Allocate output rows (fp32 accumulation)
        C_rows = torch.empty((N * L_total, K), device=device, dtype=torch.float32)

        # Launch per-row GEMM kernel. One program per row.
        grid_gemm = (N * L_total,)
        _matmul_row_kernel[grid_gemm](
            C_rows, A_rows, B,
            N * L_total, K,
            BLOCK_K=BLOCK_K,
            num_warps=4, num_stages=2,
        )

        # Cast result back to original dtype if needed
        if C_rows.dtype != hidden_states.dtype:
            C_rows = C_rows.to(hidden_states.dtype)

        # 3) Reshape back to [N, L_total, K] and split
        processed = C_rows.view(N, L_total, K)
        processed_encoder = processed[:, :L_txt, :]
        processed_hidden = processed[:, L_txt:, :]

        return processed_encoder, processed_hidden
```

What changed and why

- The GEMM is implemented as a per-row Triton kernel that iterates over K in chunks using a while-like for-loop. This avoids tl.static_range and potential compilation/runtime issues for variable K, which was the likely source of the previous RUNTIME_ERROR.
- The concatenation Triton kernel is simple and robust: it tiles along K and selects the source tensor based on t < L_txt. It uses masks for tail handling.
- Both Triton kernels are actually launched from ModelNew.forward. There is no torch.cat or torch.matmul for numeric computation, satisfying the “TRITON-ONLY” requirement.
- Accumulation is done in float32 for stability; the final result is cast back to the original dtype of hidden_states.

This version prioritizes correctness. Once correctness is confirmed across all workloads, we can explore more aggressive performance optimizations, such as processing multiple rows per program or introducing tiling over output columns and using tl.dot-based matmul templates with autotuning.
