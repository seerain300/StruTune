We’re consistently correct, but performance regressed to ~1.06x in the last run. Since the workload is bandwidth-bound and the per-row reduction requires the entire row, we cannot fuse the reduction with the elementwise pass. The main levers for performance are:
- Efficient per-row reduction: coalesced loads, float32 accumulation, rsqrt, and chunked traversal across the hidden dimension.
- Efficient elementwise application: minimize grid size and use sufficient parallelism (warps/stages) to keep the GPU busy without excessive launch overhead.

Observations and plan
- The reduction kernel is robust and previously performed well: one program per row, BLOCK_SIZE=1024, coalesced loads, float32 accumulation, rsqrt. We keep it unchanged.
- The elementwise kernel’s launch configuration can significantly affect occupancy and speed. A 2D grid with BLOCK_SIZE=4096 for H >= 4096 worked best in earlier runs, yielding ~1.37x. A grid of (B, 1) for H=4096 ensures each row is processed by one block with 16 warps, providing good parallelism. We revert to that pattern, and keep warps/stages tuned.

Final code
```python
import torch
import triton
import triton.language as tl


# Reduction kernel: per-row inv_rms = rsqrt(mean(x^2) + EPS)
@triton.jit
def _row_rms_inv_kernel(
    hidden_ptr,            # *const fp16/bf16/fp32, shape [B, H]
    inv_rms_ptr,           # *float32, shape [B]
    B: tl.int32,           # batch size
    H: tl.int32,           # hidden size
    EPS: tl.float32,       # epsilon
    BLOCK_SIZE: tl.constexpr,
):
    row = tl.program_id(0)
    if row >= B:
        return

    # Base pointer for this row (assuming contiguous [B, H] with stride(1) == 1)
    row_base = hidden_ptr + row * H

    sum_sq = 0.0
    col = 0
    while col < H:
        offs = col + tl.arange(0, BLOCK_SIZE)
        mask = offs < H
        x = tl.load(row_base + offs, mask=mask, other=0.0)
        x_f32 = x.to(tl.float32)
        sum_sq += tl.sum(x_f32 * x_f32, axis=0)
        col += BLOCK_SIZE

    mean = sum_sq / H
    inv_rms = tl.rsqrt(mean + EPS)
    tl.store(inv_rms_ptr + row, inv_rms)


# Elementwise apply: out[row, col] = hidden[row, col] * inv_rms[row] * weight[col]
@triton.jit
def _apply_two_scales_kernel(
    hidden_ptr,    # *const fp16/bf16/fp32, shape [B, H]
    inv_rms_ptr,   # *float32, shape [B]
    weight_ptr,    # *float32, shape [H]
    out_ptr,       # *float32, shape [B, H]
    B: tl.int32,
    H: tl.int32,
    BLOCK_SIZE: tl.constexpr,
):
    row = tl.program_id(0)
    col_block = tl.program_id(1)
    if row >= B:
        return

    # Column offsets for this block
    offs = col_block * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = offs < H

    # Load row base and compute scale: hidden * inv_rms[row] * weight[col]
    row_base = hidden_ptr + row * H
    hidden_vals = tl.load(row_base + offs, mask=mask, other=0.0).to(tl.float32)
    inv_rms_row = tl.load(inv_rms_ptr + row)
    weight_vals = tl.load(weight_ptr + offs, mask=mask, other=0.0)

    out_vals = hidden_vals * inv_rms_row * weight_vals
    tl.store(out_ptr + row * H + offs, out_vals, mask=mask)


def run_triton(hidden_states: torch.Tensor, weight: torch.Tensor) -> torch.Tensor:
    device = hidden_states.device
    B, H = hidden_states.shape
    # Ensure inputs are contiguous and in float32 for compute
    hidden_f32 = hidden_states.contiguous().to(torch.float32)
    weight_f32 = weight.contiguous().to(torch.float32)

    # 1) Compute inv_rms per row
    inv_rms = torch.empty((B,), dtype=torch.float32, device=device)
    _row_rms_inv_kernel[(B,)](
        hidden_f32, inv_rms, B, H, 1e-5,
        BLOCK_SIZE=1024, num_warps=8, num_stages=2
    )

    # 2) Elementwise apply: 2D grid over rows and column blocks
    if H >= 4096:
        BLOCK_SIZE_E = 4096
        num_warps_e = 16
    elif H >= 2048:
        BLOCK_SIZE_E = 2048
        num_warps_e = 8
    else:
        BLOCK_SIZE_E = 1024
        num_warps_e = 4

    out_f32 = torch.empty((B, H), dtype=torch.float32, device=device)
    grid_apply = (B, triton.cdiv(H, BLOCK_SIZE_E))
    _apply_two_scales_kernel[grid_apply](
        hidden_f32, inv_rms, weight_f32, out_f32,
        B, H,
        BLOCK_SIZE=BLOCK_SIZE_E,
        num_warps=num_warps_e, num_stages=2
    )

    # Cast back to original dtype
    return out_f32.to(hidden_states.dtype)


# Optional: original Model using Triton path
class Model(torch.nn.Module):
    def forward(self, hidden_states, weight):
        return run_triton(hidden_states, weight)


class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, weight):
        return run_triton(hidden_states, weight)
```

Why this should improve performance and maintain correctness
- The reduction kernel remains efficient: one program per row, coalesced loads, float32 accumulation, and rsqrt. It’s robust and previously achieved strong speedups for H=4096.
- The elementwise kernel uses a 2D grid with BLOCK_SIZE tuned to cover the row. For H >= 4096, BLOCK_SIZE=4096 with num_warps=16 and grid=(B, cdiv(H, 4096)) (often 1) provides good parallelism and previously yielded the best observed speedup (~1.37x). For other sizes, it uses 2048/1024 with appropriate warps and num_stages=2 for pipelining.
- We avoid incorrect pointer arithmetic by using row_base = hidden_ptr + row * H and simple offsets (inputs are contiguous), ensuring correct loads/stores.

This reverts to the configuration that previously performed best and should restore a clearer speedup while maintaining correctness across all workloads.
