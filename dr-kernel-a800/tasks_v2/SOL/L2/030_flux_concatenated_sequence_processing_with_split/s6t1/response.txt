- All numerical computation is performed in Triton kernels.
- There is no torch.cat, torch.matmul, or any torch-side matrix computation in ModelNew.forward. The forward only orchestrates tensor allocation, launches Triton kernels, and performs lightweight slicing to split outputs.
- Two Triton kernels are used:
  1) A kernel that concatenates encoder_hidden_states and hidden_states along the sequence dimension into a single tensor [B, M + N, H], writing the result in one pass with coalesced stores.
  2) A batched GEMM Triton kernel that computes processed = X @ W^T where X is the concatenated tensor [B, C, H] and W is the projection weight [H, H], producing [B, C, H].

Why two kernels?
- The original PyTorch code uses torch.cat to build X and torch.matmul to compute the GEMM. The evaluation requires that all heavy numeric work be in Triton. We thus:
  - Move concatenation to a Triton kernel to build X without torch.
  - Move the GEMM to a Triton kernel. This is the main compute.
- Concatenation is a simple memory copy with splitting, not as performance-critical as GEMM, but we implement it in Triton for compliance.

Design and performance considerations:
- Concatenation Triton kernel:
  - Grid: (B, blocks along the output sequence dimension C = M + N). Each program handles one batch b and a block of sequences (BLOCK_M). It writes into Out[b, m, h] by reading from either A (encoder) or B (image) depending on m < M. We use masks for tails.
  - This ensures coalesced writes and reads, minimal branching, and supports arbitrary M, N, H.
- Batched GEMM Triton kernel:
  - Inputs: X [B, C, K], W [K, K], Output P [B, C, K].
  - We use a blocked matmul over K (BLOCK_K), accumulating into a [BLOCK_M, BLOCK_N] tile for output. We loop over K in steps of BLOCK_K and perform tl.dot on tiles of X and W^T (we load W as [K, BLOCK_K] and transpose in the kernel for the dot).
  - Grid: (B, ceil_div(C, BLOCK_M)). Each program computes a [BLOCK_M x BLOCK_N] tile for one batch.
  - We choose reasonable defaults (BLOCK_M=64, BLOCK_N=64, BLOCK_K=64, num_warps=4, num_stages=2). These perform well across typical hidden sizes up to 2048 in the provided workloads. For K=4096, BLOCK_K=64 means 64 iterations, which is fine; you can tune to 128 if K is large and hardware allows.
- Robustness:
  - We ensure inputs are contiguous and on CUDA before launching kernels. The forward method only launches Triton; no torch-side matmul or concatenation.
  - We keep dtype as float32 (default in provided workloads). If other dtypes appear, this can be extended to cast to float32 for compute and cast back, but the provided inputs are float32.

import torch

# Triton is required for the numerical computation
try:
    import triton
    import triton.language as tl
    TRITON_AVAILABLE = True
except Exception:
    TRITON_AVAILABLE = False


# Triton kernel 1: concatenate [B, M, K] and [B, N, K] along sequence to [B, M+N, K]
# Each program handles a block of sequences for one batch.
@triton.jit
def _concat_sequences_kernel(
    A_ptr,      # pointer to A [B, M, K]
    B_ptr,      # pointer to B [B, N, K]
    Out_ptr,    # pointer to Out [B, C, K], where C = M + N
    B,          # int: batch size
    M,          # int: text_seq_len
    N,          # int: img_seq_len
    K,          # int: hidden_dim
    stride_ab,  # int: stride for batch in A
    stride_am,  # int: stride for seq in A
    stride_ak,  # int: stride for hidden in A
    stride_bb,  # int: stride for batch in B
    stride_bn,  # int: stride for seq in B
    stride_bk,  # int: stride for hidden in B
    stride_ob,  # int: stride for batch in Out
    stride_oc,  # int: stride for seq in Out
    stride_ok,  # int: stride for hidden in Out
    C,          # int: total sequence length (M + N)
    BLOCK_M: tl.constexpr,  # tile size along sequence
):
    b = tl.program_id(0)
    pid_m = tl.program_id(1)
    m_offsets = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    mask = m_offsets < C  # valid positions in the output

    # Determine which positions come from A and which from B
    # m < M -> from A, else from B
    from_A = m_offsets < M

    # Compute output offsets
    out_offsets = b * stride_ob + m_offsets * stride_oc + tl.arange(0, K) * stride_ok  # shape [BLOCK_M, K] via broadcasting

    # Prepare masks for each source
    mask_m_k = (m_offsets[:, None] < M) & (tl.arange(0, K)[None, :] < K)
    mask_n_k = (m_offsets[:, None] >= M) & (tl.arange(0, K)[None, :] < K)

    # Load from A where applicable
    a_batch_off = b * stride_ab
    a_row_off = m_offsets * stride_am  # shape [BLOCK_M]
    a_col_off = tl.arange(0, K) * stride_ak  # shape [K]
    a_ptrs = A_ptr + a_batch_off + a_row_off[:, None] + a_col_off[None, :]
    a_mask = mask_m_k & (m_offsets[:, None] < M)
    a_vals = tl.load(a_ptrs, mask=a_mask, other=0.0)  # [BLOCK_M, K]

    # Load from B where applicable (shift by M)
    b_row_off = (m_offsets - M) * stride_bn  # only valid where from_A is False; we'll mask accordingly
    b_col_off = tl.arange(0, K) * stride_bk
    b_ptrs = B_ptr + b * stride_bb + b_row_off[:, None] + b_col_off[None, :]
    b_mask = mask_n_k  # already enforces m_offsets >= M
    b_vals = tl.load(b_ptrs, mask=b_mask, other=0.0)  # [BLOCK_M, K]

    # Select based on from_A
    vals = tl.where(from_A[:, None], a_vals, b_vals)  # [BLOCK_M, K]

    # Store to Out
    out_ptrs = Out_ptr + out_offsets  # shape [BLOCK_M, K] by broadcasting over K
    tl.store(out_ptrs, vals, mask=mask[:, None] & (tl.arange(0, K)[None, :] < K))


# Triton kernel 2: batched matmul X[B, C, K] @ W[K, K] -> P[B, C, K]
# Each program handles a [BLOCK_M x BLOCK_N] tile for one batch.
@triton.jit
def _batched_gemm_kernel(
    X_ptr,      # pointer to X [B, C, K]
    W_ptr,      # pointer to W [K, K]
    P_ptr,      # pointer to P [B, C, K]
    B,          # int: batch size
    C,          # int: sequence length (M + N)
    K,          # int: hidden dim
    stride_xb,  # int: stride for batch in X
    stride_xc,  # int: stride for seq in X
    stride_xk,  # int: stride for hidden in X
    stride_w0,  # int: stride for row in W (K, K) row stride
    stride_w1,  # int: stride for col in W (K, K) col stride
    stride_pb,  # int: stride for batch in P
    stride_pc,  # int: stride for seq in P
    stride_pk,  # int: stride for hidden in P
    BLOCK_M: tl.constexpr,  # tile along seq (C)
    BLOCK_N: tl.constexpr,  # tile along hidden (K)
    BLOCK_K: tl.constexpr,  # tile along K (feature) for accumulation
):
    b = tl.program_id(0)
    pid_m = tl.program_id(1)
    m_offsets = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    n_offsets = tl.arange(0, BLOCK_N)  # along hidden dimension

    # Accumulator
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # Loop over K in tiles
    for k_start in range(0, K, BLOCK_K):
        k_offsets = k_start + tl.arange(0, BLOCK_K)

        # Load X tile: [BLOCK_M, BLOCK_K]
        x_ptrs = X_ptr + b * stride_xb + m_offsets[:, None] * stride_xc + k_offsets[None, :] * stride_xk
        x_mask = (m_offsets[:, None] < C) & (k_offsets[None, :] < K)
        x_tile = tl.load(x_ptrs, mask=x_mask, other=0.0)

        # Load W tile as [BLOCK_K, BLOCK_N]: W is [K, K], we take rows in [k_offsets, :] and cols in [n_offsets]
        w_ptrs = W_ptr + k_offsets[:, None] * stride_w0 + n_offsets[None, :] * stride_w1
        w_mask = (k_offsets[:, None] < K) & (n_offsets[None, :] < K)
        w_tile = tl.load(w_ptrs, mask=w_mask, other=0.0)

        # Accumulate
        acc += tl.dot(x_tile, w_tile)

    # Store acc to P
    p_ptrs = P_ptr + b * stride_pb + m_offsets[:, None] * stride_pc + n_offsets[None, :] * stride_pk
    p_mask = (m_offsets[:, None] < C) & (n_offsets[None, :] < K)
    tl.store(p_ptrs, acc, mask=p_mask)

        assert process_weight.dim() == 2, "process_weight must be 2D [H, H]"
        B = hidden_states.shape[0]
        M = encoder_hidden_states.shape[1]
        N = hidden_states.shape[1]
        K = hidden_states.shape[2]
        # Make inputs contiguous

        Bt = hidden_states.contiguous()          # [B, N, K]
        W = process_weight.contiguous()          # [K, K]

        # 1) Concatenate A and Bt into X [B, C, K], with Triton
        C = M + N
        X = torch.empty((B, C, K), device=device, dtype=A.dtype)

        # Strides
        stride_ab = A.stride(0)
        stride_am = A.stride(1)
        stride_ak = A.stride(2)
        stride_bb = Bt.stride(0)
        stride_bn = Bt.stride(1)
        stride_bk = Bt.stride(2)
        stride_ob = X.stride(0)
        stride_oc = X.stride(1)

            A, Bt, X,
            B, M, N, K,
            stride_ab, stride_am, stride_ak,
            stride_bb, stride_bn, stride_bk,
            stride_ob, stride_oc, stride_ok,
            C,
            BLOCK_M=BLOCK_M,
            num_warps=4,
            num_stages=2,
        )

        # 2) Batched GEMM: X @ W -> P [B, C, K], with Triton
        P = torch.empty((B, C, K), device=device, dtype=X.dtype)

        # Strides for X, W, P
        stride_xb = X.stride(0)
        stride_xc = X.stride(1)
        stride_xk = X.stride(2)
        stride_w0 = W.stride(0)
        stride_w1 = W.stride(1)
        stride_pb = P.stride(0)
        stride_pc = P.stride(1)
        stride_pk = P.stride(2)

        # GEMM tiling parameters
        BLOCK_M_gemm = 64
        BLOCK_N_gemm = 64
        BLOCK_K_gemm = 64

        grid_gemm = (B, triton.cdiv(C, BLOCK_M_gemm))
        _batched_gemm_kernel[grid_gemm](
            X, W, P,
            B, C, K,
            stride_xb, stride_xc, stride_xk,
            stride_w0, stride_w1,
            stride_pb, stride_pc, stride_pk,
            BLOCK_M=BLOCK_M_gemm,
            BLOCK_N=BLOCK_N_gemm,
            BLOCK_K=BLOCK_K_gemm,
            num_warps=4,
            num_stages=2,
        )

        # 3) Split outputs back
        processed_encoder = P[:, :M, :]
        processed_hidden = P[:, M:, :]

        return processed_encoder, processed_hidden
