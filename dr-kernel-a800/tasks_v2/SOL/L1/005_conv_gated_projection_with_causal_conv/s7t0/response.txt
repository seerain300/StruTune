Deep analysis, thinking, and optimization plan

1) Understanding the original PyTorch code
- Input x has shape (batch_size, seq_len, hidden_size). Let’s denote:
  B = batch_size, L = seq_len, H = hidden_size.
- Step 1: Triple linear projection
  - BCx = F.linear(x, in_proj_weight, in_proj_bias) with in_proj_weight shape (3H, H, L) yields BCx shape (B, 3H, L).
  - Then BCx = BCx.transpose(-1, -2) -> shape (B, 3H, L).
  - BCx.chunk(3, dim=1) splits channels into B, C, x_proj, each shape (B, H, L).
  - Note: The original code uses F.linear(x, in_proj_weight, ...) which typically maps (B, L, H) -> (B, L, 3H) when in_proj_weight is (3H, H, L). However, given x is (B, L, H), the proper linear is (B, L, H) @ (3H, H, L)^T -> (B, L, 3H). Then chunk along last dim after transposing might be intended to produce (B, H, L). To avoid confusion, we will implement the projection explicitly via in_proj_weight and chunk along feature dimension (dim=1) after transposing to (B, 3H, L), which matches the code’s intent.
- Step 2: Element-wise gating
  - Bx = B * x_proj with shapes (B, H, L).
- Step 3: Causal 1D convolution on Bx with kernel_size=4, groups=H
  - Bx is padded on the last dimension by conv_kernel_size - 1 (causal padding, no tail).
  - conv_out = F.conv1d(Bx_padded, conv_weight, conv_bias, groups=H), conv_weight shape (H, H, 4) -> output shape (B, H, L).
- Step 4: Output gating
  - y = C * conv_out with shapes (B, H, L).
- Step 5: Final output projection
  - y = y.transpose(-1, -2).contiguous() -> (B, L, H).
  - output = F.linear(y, out_proj_weight, out_proj_bias), out_proj_weight shape (H, L, H) yields output shape (B, L, H).

Given all tensors, the operation is:
- x: (B, L, H)
- in_proj_weight: (3H, H, L)  (note: non-standard weight layout but consistent with the code’s F.linear)
- in_proj_bias: (3H)
- conv_weight: (H, H, 4)
- conv_bias: (H)
- out_proj_weight: (H, L, H)
- out_proj_bias: (H)

2) Performance bottlenecks and opportunities
- The reference implementation uses:
  - F.linear (large GEMM-like): x has dims (B, L, H) but used as (B, L) rows; with in_proj_weight (3H, H, L), F.linear computes matmul-like on 3H channels, which is relatively large and dynamic.
  - conv1d with groups=H. This is not a common pattern and can be inefficient. It requires specialized kernels and careful tiling along the L dimension and H groups.

3) Triton strategy
Given the constraints (must use Triton for computation and not torch ops on tensors), we will implement:
- A Triton kernel for in-projection F.linear: Bx(H, L) x W(3H, H, L) + bias(3H) -> output(3H, L).
  - We can implement a matmul-like kernel for each (output_channel j in [0..3H), time t in [0..L)):
    - output[j, t] = sum_k in_proj_weight[j, k, t] * x[:, k] + bias[j].
    - Here x is (B, H, L) with broadcasting over batch, so it’s fine. We’ll pass x contiguous as (B, L, H) and read (k, t) as strides. For Triton kernel, we’ll treat x as (L, H) per batch (i.e., flatten over batch for simplicity), and broadcast b index.

- A Triton kernel for 1D causal convolution with groups=H and kernel_size=4:
  - Input Bx shape (B, H, L). Convolution along L dimension.
  - Weight shape (H, H, 4). groups=H implies each output channel c interacts only with its own input channel (groups semantics as separate independent convs across the same L, each with weight for that c).
  - Output shape (B, H, L).
  - Implement per (batch b, channel c, t) loop over k in [0..3], accumulate y[b, c, t] += Bx[b, c, t + k] * conv_weight[c, c, k] + conv_bias[c].
  - This can be tiled across T=L for performance; each program handles a block of T for a fixed (b, c). The dependency is only on contiguous T for each fixed c, which is good for memory coalescing along L.

- A Triton kernel for out-projection F.linear: y(B, L, H) x Wout(H, L, H) + bout(H) -> output(B, L, H).
  - Similar to in-projection but reversed dimensions.

- Gate multiplications (B*x_proj, y=C*conv_out) can be trivial Triton kernels with simple elementwise multiply. But to keep it lean and avoid overcomplication, we can also implement them in Triton as elementwise kernels. However, to keep the code concise, we can compute them in PyTorch (they are simple and small).

4) Practical considerations
- We must adhere to Triton-only computation. That means no torch.matmul, no torch.nn.functional.linear on tensors; only Triton kernels for the heavy ops and PyTorch for simple elementwise gating (or implement gating in Triton too).
- We will implement all heavy ops in Triton:
  - in_proj: Triton matmul-like kernel across (3H, L) with (H, L) input.
  - conv: Triton grouped causal 1D conv with kernel_size=4, groups=H.
  - out_proj: Triton matmul-like kernel across (H, L) with (L, H) input.
- We will ensure tensors are contiguous and handle strides correctly in Triton. We will pass pointer arrays and compute addresses with strides.

5) Correctness mapping
- We will compute:
  - BCx = in_proj_kernel(x, in_proj_weight, in_proj_bias) -> shape (3H, L).
  - Then split BCx into B, C, x_proj: chunk along dim=0. B=first H, C=second H, x_proj=third H.
  - Compute Bx = B * x_proj via Triton elementwise multiply kernel.
  - conv_out = conv1d_grouped_causal_kernel(Bx, conv_weight, conv_bias) -> shape (H, L).
  - y = C * conv_out via Triton elementwise multiply kernel.
  - y_transpose = y.transpose(-1, -2) -> (B, L, H) using PyTorch (simple metadata).
  - output = out_proj_kernel(y_transpose, out_proj_weight, out_proj_bias) -> shape (B, L, H).
- Finally return output.

6) Performance tuning notes
- The in-projection and out-projection kernels are matmul-like. Triton can be competitive for small to moderate sizes. Since our sequences are large (4096, 8192, etc.), using Triton for these ops can be viable. We will choose block sizes like BLOCK_M=64, BLOCK_N=64 for matmul kernels, and BLOCK_T=128 for convolution along T.
- The conv kernel loops over K=4, which is tiny. Each program handles one (b, c) pair and a block of T. This is efficient and simple. We’ll use strides to read along L.

7) Edge cases and robustness
- We will assume all tensors are on CUDA device. If not, we will fallback to PyTorch computation, but given the evaluation expects Triton usage, we will keep GPU checks and raise/assume CUDA is available.
- We will enforce contiguous input. If not contiguous, we’ll call .contiguous() on tensors before passing to Triton.
- We will use Triton dtype handling (float32). We’ll cast weights and biases to float32 for computation to be safe.

8) Summary of kernels to implement
- in_proj_kernel: computes (3H, L) output given (B, L, H) x (3H, H, L) and bias (3H).
- conv1d_grouped_causal_kernel: computes (H, L) given (B, H, L), weight (H, H, 4), bias (H), groups=H.
- out_proj_kernel: computes (B, L, H) given (B, L, H) x (H, L, H) and bias (H).
- gate_mul_kernel: elementwise multiply for gating (B*x_proj and y=C*conv_out).
- We will launch these from ModelNew.forward, which is the entry point.

Now the code with Triton kernels and ModelNew

Note: This implementation strictly uses Triton for all heavy computation (linear-like operations and convolution), and uses PyTorch for simple elementwise operations and tensor transposes. It is compliant with the requirement that Triton kernels must be launched from ModelNew.forward and do the main computation. If you want, we can further implement gating in Triton too, but the heavy ops are where performance matters.

```python
import torch
import torch.nn as nn
import triton
import triton.language as tl

# Kernel 1: In-projection linear: computes BCx[j, t] = sum_k in_proj_weight[j, k, t] * x[:, k, t] + bias[j]
# Shapes:
#   x: (B, L, H) contiguous
#   in_proj_weight: (3H, H, L) contiguous (note: non-standard layout; consistent with the original code)
#   in_proj_bias: (3H)
#   out_BCx: (3H, L) contiguous
@triton.jit
def in_proj_kernel(
    x_ptr,            # *float32, base pointer to x (B, L, H)
    w_ptr,            # *float32, base pointer to in_proj_weight (3H, H, L)
    b_ptr,            # *float32, base pointer to in_proj_bias (3H)
    out_ptr,          # *float32, base pointer to out_BCx (3H, L)
    B, L, H,          # int32
    stride_x_b, stride_x_l, stride_x_h,   # int32 strides for x
    stride_w_j, stride_w_k, stride_w_l,   # int32 strides for weight
    stride_out_j, stride_out_l,           # int32 strides for out
    J: tl.constexpr,                     # 3H, compile-time constant for output channels
    BLOCK_M: tl.constexpr,               # tile over J
    BLOCK_N: tl.constexpr,               # tile over L
):
    j_block = tl.program_id(0)
    l_block = tl.program_id(1)

    j_offsets = j_block * BLOCK_M + tl.arange(0, BLOCK_M)  # [BLOCK_M]
    l_offsets = l_block * BLOCK_N + tl.arange(0, BLOCK_N)  # [BLOCK_N]

    mask_j = j_offsets < J
    mask_l = l_offsets < L

    # Accumulator for each (j, l)
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # For each k in H, accumulate x[:, k, l] * w[j, k, l]
    # x is (B, L, H); we want to read x[b, l, k], but since Triton expects flattened pointers, we use strides.
    # We'll loop k from 0..H-1; for each k, we can sum over b dimension by iterating b. However, the original
    # F.linear(x, w) where x is (B, L, H) and w is (3H, H, L) implies x is (B, L) rows; our w[k, t] corresponds
    # to in_proj_weight[j, k, t] which is independent of batch. This is a bit confusing with standard linear,
    # but we'll follow the provided shapes and do: for each j,k,t, weight w[j,k,t] is scalar and x[:,k,t] is
    # the same across batch. Therefore, we can sum over B by multiplying each batch element into acc. In other
    # words, x[:, k, t] is just x[b, t, k] for all b. Our approach: for each k, we iterate b and accumulate.
    # This is expensive; better approach: recognize that F.linear with x (B, L, H) and w (3H, H, L) computes
    # per-(j,k) dot over t dimension: sum_t x[:, t, k] * w[j, k, t] + bias[j]. In our code, x is (B, L, H)
    # so x[:, t, k] is not a typical linear input. Given the original code runs F.linear(x, in_proj_weight),
    # we need to adhere to it. So we will implement the dot over t: for each k, sum over t x[:, t, k] * w[j,k,t].
    # But x is (B, L, H). The original code's F.linear with weight (3H, H, L) on input (B, L, H) is unusual.
    # To preserve behavior, we compute per k and t explicitly.
    # We'll do it as: for each k in [0..H-1], compute a vector (BLOCK_N,) of x[:, :, k] at each t, then
    # load w[j, k, t] and accumulate.

    # Loop over k dimension
    for k in range(0, H):
        # For each l in this block, compute x[:, l, k] * w[j, k, l] and sum over batch B. Since x is (B, L, H),
        # x[b, l, k] is what we need. We'll loop over b and accumulate.
        # Build addresses for x: x[b, l, k] = x_ptr + b*stride_x_b + l*stride_x_l + k*stride_x_h
        # We need x for all b; Triton cannot vectorize over b directly here, so we loop.
        # But that would be O(B * BLOCK_N). Instead, we note that F.linear with input (B, L, H) and weight (3H, H, L)
        # effectively computes for each (j,k), sum over t of x[:, t, k] * w[j, k, t]. That is, for each k, we
        # take the L-length vector x[:, :, k] across all batches (shape BxL) and weight slice w[j, k, :] (shape L),
        # then compute dot product per k. This is more efficient. We can construct x_vals for each (k,l) over b
        # by using a nested loop:
        # However, Triton does not support dynamic Python loops with runtime H well in this form. A better approach
        # is to consider that the original code's F.linear on (B, L, H) with (3H, H, L) is not the standard
        # (B, features) * (features, out_features). To keep correctness, we will compute per k and t using
        # PyTorch as a fallback; but the requirement is to use Triton. Therefore, we will implement the dot
        # per k and t by loading slices. Given the evaluation expects correctness, we will implement the exact
        # math as per original: for each j,k,t, w[j,k,t] multiplies x[b,t,k] summed over b, which in this
        # specific code is effectively elementwise across (B,L,H) but since x is (B,L,H), the linear with
        # weight (3H,H,L) means we compute per (j,k) a projection across t for each batch b. In other words,
        # the original F.linear(x, in_proj_weight) with x (B,L,H) and weight (3H,H,L) yields (B,L,3H).
        # The code then transposes to (B,3H,L) and chunks. To match, we will implement:
        # For each j in [0..3H-1], output[j, t] = sum over k of x[:, t, k] * in_proj_weight[j, k, t] + bias[j].
        # This is equivalent to computing dot of x[:, t, :] and in_proj_weight[j, :, t], then summing over k.
        # Let's implement this in Triton by looping over k and t:
        # We'll vectorize across t for this block, and loop over k.
        # Load x[:, t, k] as a vector across b. But we cannot vectorize across b directly; we will loop b.
        # This is acceptable for small sizes, and Triton can unroll when H is constexpr. Given evaluation sizes,
        # this approach is acceptable.

        # For each b in [0..B-1], accumulate: x[b, l, k] * w[j, k, l]
        # We'll compute a vector across l_offsets for a fixed k and j.
        # Load w[j, k, l] vector: address = w_ptr + j*stride_w_j + k*stride_w_k + l*stride_w_l
        w_vals = tl.load(w_ptr + j_offsets[:, None] * stride_w_j + k * stride_w_k + l_offsets[None, :] * stride_w_l,
                         mask=mask_j[:, None] & mask_l[None, :], other=0.0)

        # For each b, load x[b, l, k] vector: address = x_ptr + b*stride_x_b + l*stride_x_l + k*stride_x_h
        # We need to loop over b to gather values. Triton loops are fine if bounds are known at compile time.
        # We'll do that explicitly:
        # x_vals = tl.load(x_ptr + b*stride_x_b + l_offsets*stride_x_l + k*stride_x_h, mask=mask_l, other=0.0)
        # We must loop b:
        # Initialize per (j,l) accumulator for this k: acc += x_vals[:, None] * w_vals
        # We'll loop b:
        for b in range(0, B):
            x_vals = tl.load(x_ptr + b * stride_x_b + l_offsets * stride_x_l + k * stride_x_h,
                             mask=mask_l, other=0.0)
            # Broadcast x_vals over j dimension: (BLOCK_N,) -> (BLOCK_M, BLOCK_N)
            # Then add to acc
            acc += x_vals[None, :] * w_vals

    # After loop over k, add bias[j]
    bias_vals = tl.load(b_ptr + j_offsets, mask=mask_j, other=0.0)  # shape (BLOCK_M,)
    acc += bias_vals[:, None]

    # Store to out
    tl.store(out_ptr + j_offsets[:, None] * stride_out_j + l_offsets[None, :] * stride_out_l,
             acc, mask=mask_j[:, None] & mask_l[None, :])

# Kernel 2: Grouped causal 1D convolution with kernel_size=4 and groups=H.
# Input: Bx (B, H, L) contiguous
# Weight: conv_weight (H, H, 4) contiguous (out_channels=H, in_channels=H, kernel=4)
# Bias: conv_bias (H) contiguous
# Output: conv_out (B, H, L) contiguous
@triton.jit
def conv1d_grouped_causal_kernel(
    bx_ptr,            # *float32, base pointer to input Bx (B, H, L)
    w_ptr,             # *float32, base pointer to conv_weight (H, H, 4)
    b_bias_ptr,        # *float32, base pointer to conv_bias (H)
    out_ptr,           # *float32, base pointer to conv_out (B, H, L)
    B, L, H,           # int32
    stride_bx_b, stride_bx_c, stride_bx_l,    # int32 strides for input Bx
    stride_w_o, stride_w_i, stride_w_k,       # int32 strides for weight
    stride_out_b, stride_out_c, stride_out_l, # int32 strides for output
    K: tl.constexpr,                       # kernel size, here 4
    BLOCK_T: tl.constexpr,                 # tile size along L
):
    b = tl.program_id(0)  # one program per batch
    c = tl.program_id(1)  # one program per channel
    t_block = tl.program_id(2)  # tile along L
    t_offsets = t_block * BLOCK_T + tl.arange(0, BLOCK_T)
    mask_t = t_offsets < L

    acc = tl.zeros((BLOCK_T,), dtype=tl.float32)

    # Causal padding: we use input indices t + k (k in [0..K-1])
    # Loop over kernel taps
    for k in range(0, K):
        input_t = t_offsets + k  # potentially out of range for k==3; we guard by masking
        valid = input_t < L
        # Load Bx[b, c, input_t]
        # Address = bx_ptr + b*stride_bx_b + c*stride_bx_c + input_t*stride_bx_l
        bx_vals = tl.load(bx_ptr + b * stride_bx_b + c * stride_bx_c + input_t * stride_bx_l,
                          mask=mask_t & valid, other=0.0)
        # Load weight for (out_c=c, in_c=c, k=k): address = w_ptr + c*stride_w_o + c*stride_w_i + k*stride_w_k
        w_val = tl.load(w_ptr + c * stride_w_o + c * stride_w_i + k * stride_w_k)
        acc += bx_vals * w_val

    # Add bias
    bias_val = tl.load(b_bias_ptr + c)
    acc += bias_val

    # Store output conv_out[b, c, t]
    tl.store(out_ptr + b * stride_out_b + c * stride_out_c + t_offsets * stride_out_l,
             acc, mask=mask_t)

# Kernel 3: Out-projection linear: computes output[b, l, h] = sum_k out_proj_weight[h, l, k] * y[b, l, k] + bias[h]
# Shapes:
#   y: (B, L, H) contiguous
#   out_proj_weight: (H, L, H) contiguous
#   out_proj_bias: (H)
#   out: (B, L, H) contiguous
@triton.jit
def out_proj_kernel(
    y_ptr,             # *float32, base pointer to y (B, L, H)
    wout_ptr,          # *float32, base pointer to out_proj_weight (H, L, H)
    bout_ptr,          # *float32, base pointer to out_proj_bias (H)
    out_ptr,           # *float32, base pointer to out (B, L, H)
    B, L, H,           # int32
    stride_y_b, stride_y_l, stride_y_h,   # int32 strides for y
    stride_w_h, stride_w_l, stride_w_k,   # int32 strides for out_proj_weight
    stride_out_b, stride_out_l, stride_out_h, # int32 strides for output
    BLOCK_M: tl.constexpr,               # tile over H (channels)
    BLOCK_N: tl.constexpr,               # tile over L (time)
):
    h_block = tl.program_id(0)
    l_block = tl.program_id(1)

    h_offsets = h_block * BLOCK_M + tl.arange(0, BLOCK_M)  # [BLOCK_M]
    l_offsets = l_block * BLOCK_N + tl.arange(0, BLOCK_N)  # [BLOCK_N]

    mask_h = h_offsets < H
    mask_l = l_offsets < L

    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # We need to compute dot over k dimension for each (h,l):
    # For each h and l, output[h, l] = sum_k y[b, l, k] * out_proj_weight[h, l, k] + bias[h]
    # We'll iterate k from 0..H-1. y[b, l, k] is scalar; out_proj_weight[h, l, k] is scalar.
    for k in range(0, H):
        # Load y[:, l, k] vector across l
        y_vals = tl.load(y_ptr + 0 * stride_y_b + l_offsets * stride_y_l + k * stride_y_h,
                         mask=mask_l, other=0.0)  # here we fix b=0; Triton doesn't support vectorizing over B, so we use b=0
        # But we need y for all batches; since y is (B, L, H), we should iterate over b. Triton does not support
        # vectorizing over dynamic B well here. Instead, we implement per-k, per-(b,l) accumulation. We'll loop b.
        for b in range(0, B):
            y_vals_b = tl.load(y_ptr + b * stride_y_b + l_offsets * stride_y_l + k * stride_y_h,
                               mask=mask_l, other=0.0)
            wout_vals = tl.load(wout_ptr + h_offsets[:, None] * stride_w_h + l_offsets[None, :] * stride_w_l + k * stride_w_k,
                                mask=mask_h[:, None] & mask_l[None, :], other=0.0)
            acc += y_vals_b[None, :] * wout_vals

    # Add bias
    bias_vals = tl.load(bout_ptr + h_offsets, mask=mask_h, other=0.0)  # (BLOCK_M,)
    acc += bias_vals[:, None]

    # Store
    tl.store(out_ptr + 0 * stride_out_b + l_offsets[None, :] * stride_out_l + h_offsets[:, None] * stride_out_h,
             acc, mask=mask_h[:, None] & mask_l[None, :])  # Note: we used b=0 here, which is incorrect for storing
    # Correction: we must store for each batch. Since we computed acc per (h,l), we need to loop b again:
    # Re-compute acc per (h,l), then store per batch. To keep it simple, we recompute in a loop for b:
    # But Triton does not allow reassigning acc per b. Better approach: recompute per b and store separately.
    # Therefore, we'll launch a separate grid dimension for b. However, Triton requires static grid. To satisfy,
    # we can write a wrapper that loops over b; but here we provide a simplified version that assumes B=1.
    # Given the provided workloads have B>=1, but to avoid confusion, we will adjust the kernel to handle B by
    # passing B as a meta-parameter and looping inside the kernel. Triton allows loops over runtime B; we can
    # use it. The above code already loops over b for accumulation. We then store using b=0. To fix, we store
    # across all batches by indexing via pointers; Triton will treat out_ptr as (B,H,L). We need to pass B into
    # grid and create pointers per b. Triton kernels do not accept per-b pointers directly; instead, we call
    # the kernel with grid (B, ceil(H/BLOCK_M), ceil(L/BLOCK_N)) and make the pointer arithmetic include b.
    # Adjusting kernel signature and grid accordingly.

    # Revised version: add a grid dimension for b. Triton allows passing B as constexpr or runtime. We will
    # add b to kernel arguments and grid will include it.

# Revised out_proj_kernel with b in grid:
@triton.jit
def out_proj_kernel_b(
    y_ptr,             # *float32, base pointer to y (B, L, H)
    wout_ptr,          # *float32, base pointer to out_proj_weight (H, L, H)
    bout_ptr,          # *float32, base pointer to out_proj_bias (H)
    out_ptr,           # *float32, base pointer to out (B, L, H)
    B, L, H,           # int32
    stride_y_b, stride_y_l, stride_y_h,   # int32 strides for y
    stride_w_h, stride_w_l, stride_w_k,   # int32 strides for out_proj_weight
    stride_out_b, stride_out_l, stride_out_h, # int32 strides for output
    BLOCK_M: tl.constexpr,               # tile over H (channels)
    BLOCK_N: tl.constexpr,               # tile over L (time)
):
    h_block = tl.program_id(0)
    l_block = tl.program_id(1)
    b = tl.program_id(2)  # batch index

    h_offsets = h_block * BLOCK_M + tl.arange(0, BLOCK_M)  # [BLOCK_M]
    l_offsets = l_block * BLOCK_N + tl.arange(0, BLOCK_N)  # [BLOCK_N]

    mask_h = h_offsets < H
    mask_l = l_offsets < L

    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # We compute output[h, l] for this batch b:
    # For each k in [0..H-1], acc += y[b, l, k] * out_proj_weight[h, l, k]
    for k in range(0, H):
        y_vals = tl.load(y_ptr + b * stride_y_b + l_offsets * stride_y_l + k * stride_y_h,
                         mask=mask_l, other=0.0)
        wout_vals = tl.load(wout_ptr + h_offsets[:, None] * stride_w_h + l_offsets[None, :] * stride_w_l + k * stride_w_k,
                            mask=mask_h[:, None] & mask_l[None, :], other=0.0)
        acc += y_vals[None, :] * wout_vals

    # Add bias
    bias_vals = tl.load(bout_ptr + h_offsets, mask=mask_h, other=0.0)  # (BLOCK_M,)
    acc += bias_vals[:, None]

    # Store output[b, h, l]
    tl.store(out_ptr + b * stride_out_b + h_offsets[:, None] * stride_out_h + l_offsets[None, :] * stride_out_l,
             acc, mask=mask_h[:, None] & mask_l[None, :])

# Kernel 4: Elementwise gate multiply: out = a * b
@triton.jit
def gate_mul_kernel(
    a_ptr, b_ptr, out_ptr,
    B, L, H,
    stride_a_b, stride_a_l, stride_a_h,
    stride_b_b, stride_b_l, stride_b_h,
    stride_out_b, stride_out_l, stride_out_h,
    BLOCK_M: tl.constexpr,   # tile over H
    BLOCK_N: tl.constexpr,   # tile over L
):
    h_block = tl.program_id(0)
    l_block = tl.program_id(1)
    b = tl.program_id(2)  # batch index
    h_offsets = h_block * BLOCK_M + tl.arange(0, BLOCK_M)
    l_offsets = l_block * BLOCK_N + tl.arange(0, BLOCK_N)
    mask_h = h_offsets < H
    mask_l = l_offsets < L

    a_vals = tl.load(a_ptr + b * stride_a_b + l_offsets * stride_a_l + h_offsets * stride_a_h,
                     mask=mask_h[:, None] & mask_l[None, :], other=0.0)
    b_vals = tl.load(b_ptr + b * stride_b_b + l_offsets * stride_b_l + h_offsets * stride_b_h,
                     mask=mask_h[:, None] & mask_l[None, :], other=0.0)
    out_vals = a_vals * b_vals
    tl.store(out_ptr + b * stride_out_b + h_offsets[:, None] * stride_out_h + l_offsets[None, :] * stride_out_l,
             out_vals, mask=mask_h[:, None] & mask_l[None, :])

# Host-side function to run in-projection
def in_proj_triton(x, in_proj_weight, in_proj_bias):
    B, L, H = x.shape
    J = 3 * H
    # Ensure contiguous
    x_c = x.contiguous()
    w_c = in_proj_weight.contiguous()
    b_c = in_proj_bias.contiguous()
    out = torch.empty((J, L), dtype=torch.float32, device=x.device)
    stride_x_b, stride_x_l, stride_x_h = x_c.stride()
    stride_w_j, stride_w_k, stride_w_l = w_c.stride()
    stride_out_j, stride_out_l = out.stride()
    # Launch grid over J and L tiles
    BLOCK_M = 64
    BLOCK_N = 64
    grid = (triton.cdiv(J, BLOCK_M), triton.cdiv(L, BLOCK_N))
    in_proj_kernel[grid](
        x_c, w_c, b_c, out,
        B, L, H,
        stride_x_b, stride_x_l, stride_x_h,
        stride_w_j, stride_w_k, stride_w_l,
        stride_out_j, stride_out_l,
        J=J, BLOCK_M=BLOCK_M, BLOCK_N=BLOCK_N,
    )
    return out

# Host-side function to run grouped causal conv
def conv1d_grouped_causal_triton(Bx, conv_weight, conv_bias):
    B, H, L = Bx.shape
    # Ensure contiguous
    Bx_c = Bx.contiguous()
    w_c = conv_weight.contiguous()
    b_bias = conv_bias.contiguous()
    out = torch.empty((B, H, L), dtype=torch.float32, device=Bx.device)
    stride_bx_b, stride_bx_c, stride_bx_l = Bx_c.stride()
    stride_w_o, stride_w_i, stride_w_k = w_c.stride()
    stride_out_b, stride_out_c, stride_out_l = out.stride()
    K = 4
    BLOCK_T = 128
    grid = (B, H, triton.cdiv(L, BLOCK_T))
    conv1d_grouped_causal_kernel[grid](
        Bx_c, w_c, b_bias, out,
        B, L, H,
        stride_bx_b, stride_bx_c, stride_bx_l,
        stride_w_o, stride_w_i, stride_w_k,
        stride_out_b, stride_out_c, stride_out_l,
        K=K, BLOCK_T=BLOCK_T,
    )
    return out

# Host-side function to run out-projection
def out_proj_triton(y, out_proj_weight, out_proj_bias):
    B, L, H = y.shape

    y_c = y.contiguous()
    wout_c = out_proj_weight.contiguous()
    bout_c = out_proj_bias.contiguous()

    stride_w_h, stride_w_l, stride_w_k = wout_c.stride()
    stride_out_b, stride_out_l, stride_out_h = out.stride()
    BLOCK_M = 64
    BLOCK_N = 64

        stride_out_b, stride_out_l, stride_out_h,

    )
