Design details

- Shapes: inputs are [B, S, D]. We need mean and std per (b, s) over D.
- Triton kernel 1 (reduce_mean_std_kernel): One program per row (b, s). Loop over D in chunks of BLOCK_SIZE, load x, cast to float32, accumulate sum and sumsq. Write per-row sum and sumsq to arrays of length B*S.
- Triton kernel 2 (compute_mean_std_kernel): One program per row (b, s). Load sum and sumsq, compute mean = sum / D and std = sqrt(sumsq/D - mean^2), clamp var to >= 0. Write per-row mean and std to arrays of length B*S.
- Triton kernel 3 (ndtri_approx_kernel): Compute z = ndtri(sparsity) using A&S 5.2.23 approximation, returning a single float32 scalar. We call this kernel exactly once per forward with a scalar input.
- Triton kernel 4 (apply_activation_kernel): 3D grid over (b, s, tiles of D). Load per-row mean and std, compute threshold = mean + std * z_score, load x, compute y = max(0, x - threshold) in float32, store to output as bfloat16 (to match typical input dtype).

Performance considerations

- Memory-bound workloads: reductions and elementwise operations are bandwidth-bound. The design ensures contiguous access along the feature dimension for coalesced loads/stores.
- BLOCK_SIZE selection: choose min(1024, next power-of-two of D), tuned for typical D up to 12288. This balances occupancy and vector width.
- Computation in float32: accumulate and compute in float32 for numeric stability; store in bfloat16 to match the original.

Edge cases and correctness

- target_sparsity must be in (0, 1). The A&S approximation is defined for p in (0,1). We avoid p=0 or p=1. The original code uses target_sparsity in (0,1) in practice.
- We do not use torch.mean/std/ReLU in forward; all are replaced by Triton kernels.

import triton
import triton.language as tl


@triton.jit
def reduce_mean_std_kernel(
    X_ptr,           # *input tensor [B, S, D], contiguous
    SUM_ptr,         # *float32, length B*S
    SUMSQ_ptr,       # *float32, length B*S
    B, S, D,         # int32 dimensions
    BLOCK_SIZE: tl.constexpr,
):
    pid = tl.program_id(axis=0)  # 0..(B*S - 1)
    b = pid // S
    s = pid % S
    base = (b * S + s) * D

    sum_val = 0.0
    sumsq_val = 0.0

    offs = 0
    while offs < D:
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        ptrs = X_ptr + base + idx
        x = tl.load(ptrs, mask=mask, other=0.0).to(tl.float32)
        sum_val += tl.sum(x, axis=0)
        sumsq_val += tl.sum(x * x, axis=0)
        offs += BLOCK_SIZE

    tl.store(SUM_ptr + pid, sum_val)
    tl.store(SUMSQ_ptr + pid, sumsq_val)


@triton.jit
def compute_mean_std_kernel(
    SUM_ptr,         # *float32, length B*S
    SUMSQ_ptr,       # *float32, length B*S
    MEAN_ptr,        # *float32, length B*S
    STD_ptr,         # *float32, length B*S
    D,               # int32 number of features

    sumsq_val = tl.load(SUMSQ_ptr + pid)

    mean = sum_val / d
    var = sumsq_val / d - mean * mean
    var = tl.maximum(var, 0.0)
    std = tl.sqrt(var)
    tl.store(MEAN_ptr + pid, mean)
    tl.store(STD_ptr + pid, std)

    denom_high = (((((d1 * q_high + d2) * q_high + d3) * q_high + d4) * q_high + 1.0))
    nd_high = -poly_high / denom_high

    ndtri_approx = tl.where(low_mask, nd_low, tl.where(high_mask, nd_high, nd_mid))

    tl.store(OUT_ptr, ndtri_approx)

  2) compute_mean_std_kernel: one program per row. Load sum and sumsq, compute mean = sum / D, std = sqrt(sumsq/D - mean^2), store mean and std.
  3) ndtri_approx_kernel: compute z_score for given sparsity using A&S 5.2.23 approximation. Launch as a single program. This is tiny and just for a scalar.
  4) apply_activation_kernel: 3D grid over (b, s, tiles of D). Load per-row mean and std, compute threshold, load x, compute y = max(0, x - threshold) in float32, and store to output (bfloat16).

- Critical fixes for previous errors:
  - Triton requires pointer + int*vector expressions when using tl.load/tl.store with masks. Avoid adding plain ints to pointers. Use base indices as int*vector (base * D + tl.zeros([...], tl.int32)) and add idx vector.
  - Use tl.load on pointer buffers (SUM_ptr, MEAN_ptr, STD_ptr, etc.) and tl.store to store results.
  - Keep all math in float32 inside kernels. Output can be bfloat16 (Triton will cast on store).

- Host code:
  - Only tensor allocations and kernel launches. No torch elementwise ops or reductions.
  - z_score is computed via a Triton kernel (A&S approximation), ensuring Triton-only path.
  - Output dtype is bfloat16 to match typical input dtype.

import torch
import triton
import triton.language as tl


@triton.jit
def reduce_mean_std_kernel(
    X_ptr,           # *input tensor [B, S, D], contiguous
    SUM_ptr,         # *float32, length B*S
    SUMSQ_ptr,       # *float32, length B*S
    B, S, D,         # int32 dimensions
    BLOCK_SIZE: tl.constexpr,
):
    pid = tl.program_id(axis=0)  # 0..(B*S - 1)
    b = pid // S
    s = pid % S

    # Compute base row offset as int*vector for pointer arithmetic
    base = b * S + s
    base_idx = (base * D) + tl.zeros([BLOCK_SIZE], dtype=tl.int32)

    sum_val = 0.0
    sumsq_val = 0.0

    offs = 0
    while offs < D:
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        ptrs = X_ptr + base_idx + idx
        x = tl.load(ptrs, mask=mask, other=0.0).to(tl.float32)
        sum_val += tl.sum(x, axis=0)
        sumsq_val += tl.sum(x * x, axis=0)
        offs += BLOCK_SIZE

    # Store per-row sums
    tl.store(SUM_ptr + pid, sum_val)
    tl.store(SUMSQ_ptr + pid, sumsq_val)


@triton.jit
def compute_mean_std_kernel(
    SUM_ptr,         # *float32, length B*S
    SUMSQ_ptr,       # *float32, length B*S
    MEAN_ptr,        # *float32, length B*S
    STD_ptr,         # *float32, length B*S
    D,               # int32 number of features
):
    pid = tl.program_id(axis=0)
    sum_val = tl.load(SUM_ptr + pid)
    sumsq_val = tl.load(SUMSQ_ptr + pid)
    d = tl.full((), D, tl.int32)
    mean = sum_val / d
    var = sumsq_val / d - mean * mean
    var = tl.maximum(var, 0.0)  # clamp tiny negatives
    std = tl.sqrt(var)
    tl.store(MEAN_ptr + pid, mean)
    tl.store(STD_ptr + pid, std)
