- What is being optimized:

PyTorch’s index_add can be implemented using atomics or segmented reductions; when done with atomics it launches efficient CUDA kernels. The reference uses index_add, but the request is to replace it with Triton. So we need a Triton kernel that performs scatter-add along dim=0 of a 2D tensor.

- Why Triton can help:
  - Triton allows writing custom GPU kernels. We can implement a straightforward scatter-add kernel that:
    - reads expert_outputs[i]
    - adds it into output[token_indices[i]]
  - We’ll perform this in a 1D grid where each program handles a block of rows (indices i). For each i, load the hidden vector and do atomic_add into the target row in the output.
  - Using atomic_add is the simplest and robust approach. It guarantees correctness even if token_indices contain duplicates. A non-atomic approach would require per-row serialization or a two-phase reduction, which adds complexity and doesn’t make sense given the duplicates.

- Design choices for the Triton kernel:
  - Inputs:
    - output_ptr: pointer to the output tensor (final_hidden_states), shape (M, H), dtype bfloat16, device CUDA.
    - expert_outputs_ptr: pointer to expert_outputs, shape (N, H), dtype bfloat16, device CUDA.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_dim0_bf16(
    output_ptr,            # *ptr to (M, H) output
    expert_outputs_ptr,    # *ptr to (N, H) expert_outputs
    token_indices_ptr,     # *ptr to (N,) indices
    M, H, N,               # sizes: M rows, H hidden dim, N number of updates
    BLOCK_SIZE: tl.constexpr,
):
    # 1D grid: each program handles BLOCK_SIZE rows
    pid = tl.program_id(axis=0)
    offs = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = offs < N

    # Load token indices for these rows
    idx = tl.load(token_indices_ptr + offs, mask=mask, other=0)  # int32/int64

    # Base offsets for hidden dimension (columns)
    col = tl.arange(0, H)

    # Loop over hidden dimension to perform atomic adds
    # Note: we vectorize over H dimension using col; this keeps code simple
    # and ensures correctness for any H.
    for h in range(0, H):
        # Compute addresses and load expert_outputs row h across BLOCK_SIZE rows
        vals = tl.load(expert_outputs_ptr + offs * H + h, mask=mask, other=0).to(tl.bfloat16)

        # Compute destination address in output: idx * H + h
        dest_addr = idx * H + h  # broadcasting: idx is [BLOCK_SIZE], h is scalar
        # Atomic add into output
        # Cast vals to match destination dtype (bf16). Triton atomic_add expects same dtype.
        tl.atomic_add(output_ptr + dest_addr, vals, mask=mask)
```

- The Triton kernel uses atomic_add to handle duplicate indices and parallel updates.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_dim0_bf16(
    output_ptr,            # *ptr to (M, H) output tensor
    expert_outputs_ptr,    # *ptr to (N, H) expert_outputs tensor
    token_indices_ptr,     # *ptr to (N,) indices
    M, H, N,               # sizes: M rows, H hidden dim, N number of updates
    BLOCK_SIZE: tl.constexpr,
):
    # 1D grid: each program handles BLOCK_SIZE rows (updates)
    pid = tl.program_id(axis=0)
    offs = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = offs < N

    # Load token indices for these rows
    idx = tl.load(token_indices_ptr + offs, mask=mask, other=0)  # int32/int64

    # Loop over hidden dimension H; vectorize across rows handled by this program
    for h in range(0, H):
        # Load expert_outputs row h across BLOCK_SIZE rows
        vals = tl.load(expert_outputs_ptr + offs * H + h, mask=mask, other=0).to(tl.bfloat16)

        # Destination address: idx * H + h
        dest_addr = idx * H + h
        # Atomic add into output
        tl.atomic_add(output_ptr + dest_addr, vals, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        """
        Triton-optimized scatter-add along dim=0:
        output[token_indices[i]] += expert_outputs[i] for all i
        """
        # Ensure CUDA tensors
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, \
            "Triton kernels require CUDA tensors. Move inputs to CUDA device."
        assert final_hidden_states.dtype == torch.bfloat16, "final_hidden_states must be bfloat16"
        assert expert_outputs.dtype == torch.bfloat16, "expert_outputs must be bfloat16"
        assert token_indices.dtype in (torch.int32, torch.int64), "token_indices must be int32 or int64"

        # Compute sizes
        M = final_hidden_states.shape[0]
        H = final_hidden_states.shape[1]
        N = expert_outputs.shape[0]
        assert expert_outputs.shape[1] == H, "expert_outputs second dimension must equal hidden_size"
        assert token_indices.shape[0] == N, "token_indices length must equal number of expert outputs"

        # Clone to keep original buffer intact (matching reference semantics)
        output = final_hidden_states.clone()

        # Choose block size and num_warps
        BLOCK_SIZE = 1024
        grid = (triton.cdiv(N, BLOCK_SIZE),)

        # Launch Triton kernel
        scatter_add_dim0_bf16[grid](
            output, expert_outputs, token_indices,
            M, H, N,
            BLOCK_SIZE=BLOCK_SIZE,
            num_warps=4,
        )

        return output


def get_inputs(
    axes_and_scalars: dict[str, ...], device: torch.device

    """Returns the input arguments for the reference forward pass. Required method."""

        axes_and_scalars["batch_size"],
        axes_and_scalars["seq_len"],
        axes_and_scalars["hidden_size"],
    )
    num_experts_per_tok = axes_and_scalars["num_experts_per_tok"]

    batch_seq_len = batch_size * seq_len
    num_selected_tokens = batch_seq_len * num_experts_per_tok  # each token can have multiple experts

    # Initialize accumulation buffer with random values (not zeros) to detect no-op
    final_hidden_states = torch.randn(batch_seq_len, hidden_size, dtype=torch.bfloat16, device=device)

    expert_outputs = torch.randn(num_selected_tokens, hidden_size, dtype=torch.bfloat16, device=device)

    token_indices = torch.randint(
        0, batch_seq_len, (num_selected_tokens,), dtype=torch.long, device=device
    )

    return {
        "final_hidden_states": final_hidden_states,
        "expert_outputs": expert_outputs,
        "token_indices": token_indices,
    }
```

我的分析、计划和解决方案

1) 问题理解
- 原始 PyTorch 代码的行为：
  - get_inputs 生成：
    - final_hidden_states: 形状 (batch_size * seq_len, hidden_size), dtype bfloat16, 初始随机值。
    - expert_outputs: 形状 (num_selected_tokens, hidden_size), dtype bfloat16, 初始随机值, num_selected_tokens = batch_size * seq_len * num_experts_per_tok。
    - token_indices: 长度 num_selected_tokens, int64, 每个专家输出对应的 target token 行索引，在 [0, batch_size * seq_len) 范围内。
  - run 执行：
    - output = final_hidden_states.clone()
    - output.index_add_(dim=0, index=token_indices, source=expert_outputs)
  - 这是典型的 scatter-add 操作：对于每个 i，将 expert_outputs[i] 加到 output[token_indices[i]] 的行上。PyTorch index_add 内部使用原子操作处理重复索引。

2) 评审要求
- 必须使用 Triton 实现主要计算，并且要展示真正的优化：不仅仅是功能等价，还要提高性能。
- ModelNew.forward 不得包含任何 PyTorch 张量操作（除了可能的 host-side 元数据处理），所有计算必须由 Triton kernel 完成。
- get_inputs 必须保持原样，并被 ModelNew.forward 所使用的入口函数用到。

3) 优化策略
- 最初的 Triton kernel 使用了 1D grid 并对每个 hidden 维度进行循环 atomic_add，虽然正确但对大 hidden_size 来说效率较低，因为每个 H 都是独立的 loop iteration，增加控制开销且可能降低内存并行性。
