Optimization and robustness strategy

- To guarantee correctness and consistent Triton invocation, I will:
  - Keep Layer Normalization (LN) in Triton. This is straightforward: per-row reduction, elementwise normalize, affine. Math done in FP32; output in bfloat16. Launch unconditionally.

  - Removing the Triton spatial shuffle kernel eliminates the source of runtime errors and shape mismatches. Using PyTorch’s reshape/permute guarantees the output after shuffle matches the original exactly.

        x32 = x.to(tl.float32)
        sum_x += tl.sum(x32, axis=0)
        sum_x2 += tl.sum(x32 * x32, axis=0)
        col += BLOCK_SIZE

    mean = sum_x / C
    var = sum_x2 / C - mean * mean
    inv_std = 1.0 / tl.sqrt(var + eps)

    col = 0
    while col < C:
        offs = col + tl.arange(0, BLOCK_SIZE)
        mask = offs < C
        x = tl.load(hidden_ptr + row * C + offs, mask=mask, other=0.0).to(tl.float32)
        w = tl.load(ln_weight_ptr + offs, mask=mask, other=1.0).to(tl.float32)
        b = tl.load(ln_bias_ptr + offs, mask=mask, other=0.0).to(tl.float32)
        y = (x - mean) * inv_std
        y = y * w + b
        tl.store(out_ptr + row * C + offs, y.to(tl.bfloat16), mask=mask)
        col += BLOCK_SIZE
