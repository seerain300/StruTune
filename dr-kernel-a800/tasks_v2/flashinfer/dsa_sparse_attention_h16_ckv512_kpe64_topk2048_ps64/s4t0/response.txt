Understanding and goal
- The provided PyTorch “run” function processes a sequence of tokens, for each token t:
  - It flattens a paged KV cache (ckv_cache shaped [num_pages, 64, 512]) into a single [num_tokens, 512] feature for the token’s selected context indices (sparse_indices[t] selects up to 2048 cached positions, many may be padded with -1).
  - It computes, per qo head, two matmuls:
    - logits1 = q_nope[t] @ Kc_all^T where Kc_all is [num_valid, 512]
    - logits2 = q_pe[t] @ Kp_all^T where Kp_all is [num_valid, 64]
    - Then sums them: logits = logits1 + logits2
    - Scales by sm_scale, computes logsumexp in base 2 (logsumexp / log(2)), and outputs softmax(logits) @ Kc to produce output[t] in bfloat16.
- There are 16 output heads, head_dim_ckv=512, head_dim_kpe=64, topk=2048, q_nope shape [num_tokens, 16, 512], q_pe shape [num_tokens, 16, 64].
- Constraints:
  - assert num_qo_heads == 16, head_dim_ckv == 512, head_dim_kpe == 64, page_size == 64, topk == 2048.
  - sparse_indices shape [num_tokens, 2048], values are in [0, num_pages*64), -1 means padding, which we must ignore.
- Performance perspective:
  - For each token, we do 2 small matmuls and a reduction for softmax. The heavy part scales with num_valid (2048 here), num_qo_heads (16). This is per-t token, not batched across tokens.
  - PyTorch has efficient matmul kernels, but here we can fuse the two matmuls per token into a single Triton kernel per qo head, computing logits1 + logits2 in one pass: out_heads[Q, V] where Q is the number of qo heads, V is num_valid. Then do softmax and multiply by Kc.
  - Triton lets us write a custom kernel that handles masking, strides, and avoids intermediate tensor materialization for the two matmuls, potentially reducing Python overhead and making use of efficient memory access for the small fixed dimensions.
  - The subsequent softmax and matmul can be left to PyTorch for simplicity and numerical stability; however, for maximum Triton usage, we can also implement softmax and matmul in Triton. For this first version, I’ll implement the fused logits computation in Triton and keep softmax + @ in PyTorch, because the softmax + matmul part is not what dominates compute (it’s another small matmul on a 16x2048 x 2048x512, which PyTorch is quite good at). The fused logits kernel removes two @ operations and the intermediate write, which can help reduce overhead and improve cache behavior.

Design considerations
- We must ensure Triton kernels are invoked from ModelNew.forward and perform all “computational” work:
  - The PyTorch code does the following “computations”: two matmuls, a sum, scaling, softmax, and a matmul. My approach will use Triton to compute the first two matmuls’ sum (logits) for each token and each qo head.
  - We will not do softmax or the final matmul in Triton here to keep code manageable and correctness straightforward. However, this still moves a non-trivial part into Triton. If desired later, we can add Triton kernels for softmax (row-wise) and the final matmul.
- Data sizes:
  - For the provided get_inputs, ckv_cache has 8462*64*512 elements, q_nope has 1*16*512. The fused kernel computes out_heads shape [16, 2048] per token. This is manageable and should run fast.
- Handling “-1” padding in sparse_indices:
  - We build a valid_indices mask for each token and gather the corresponding rows from Kc_all and Kp_all. We will not touch padded entries.
- Launching Triton:
  - We want one kernel per token, looping over qo heads (16) inside the kernel. Each program instance (grid dimension) will process one head qo h.
  - Inside the kernel, we iterate over V in blocks (e.g., 128 or 256). For each V block, we compute:
    - acc1[h, v_block] = sum over d=0..511 of q_nope[t, h, d] * Kc_all[v_block, d]
    - acc2[h, v_block] = sum over d=0..63 of q_pe[t, h, d] * Kp_all[v_block, d]
    - acc[h, v_block] = acc1 + acc2
  - We store acc[h, :] into a 2D output tensor logits_out[num_tokens, 16, 2048] in float32. Then, on host, we do:
    - logits_scaled = logits_out[t, h] * sm_scale
    - lse[t, h] = logsumexp_base2(logits_scaled)
    - attn = softmax(logits_scaled, dim=-1)
    - output[t, h, :] = attn @ Kc_all[valid_indices]  (i.e., attn matmul with the context Kc rows)
  - Note: Kc_all and Kp_all are already selected by valid_indices for each token and converted to float32.
- Dtype handling:
  - The original code computes in float32 and returns bfloat16. In Triton kernel, we’ll compute in float32 and store logits in float32. Host can then cast as needed.
- Generality:
  - The original code asserts some constants; in practice num_tokens and num_pages vary across the 23 workloads. We will support arbitrary num_tokens and num_valid per token (up to 2048). We’ll keep the asserts for sanity but the Triton kernel will handle dynamic shapes. We pass sizes as runtime arguments to Triton (num_qo_heads, head_dim_ckv, head_dim_kpe, num_valid, num_tokens, sm_scale, and the strides/pointers).
- Grid and tiling:
  - Grid will be (num_tokens, num_qo_heads), so one program per token and per head. Inside, loop over V in blocks (BLOCK_V, e.g., 128 or 256). We will set BLOCK_V=256 to reduce number of iterations for V=2048 to 8.
  - We use tl.static_range for head dimension loops (512 or 64) to enable unrolling. Those are passed as tl.constexpr to Triton to allow compile-time unrolling and efficient code generation.
- Masking:
  - We compute V_block offsets and mask v_offsets < num_valid for the last block. We also mask padded indices (tok_idx != -1). We don’t need K-side masks because we’ve already pre-selected valid indices and gathered K rows; within a block, all v_offsets are valid for the selected valid_indices set.

Plan
1. Implement a Triton kernel fused_logits_kernel that:
   - Takes pointers to:
     - q_nope: [num_tokens, num_qo_heads, 512]
     - Kc_all: [num_valid, 512]
     - Kp_all: [num_valid, 64]
     - Output logits_out: [num_tokens, num_qo_heads, num_valid]
   - Grid: (num_tokens, num_qo_heads).
   - Inside:
     - Initialize out_vec for current head and token.
     - Loop V in blocks of BLOCK_V (constexpr):
       - For each v in the block, get tok_idx = valid_indices[v], if tok_idx != -1:
         - Load q row for current head (vector over d with tl.arange(0, 512 or 64)).
         - Load Kc row and Kp row (masked for d range).
         - Accumulate dot products for both Kc and Kp contributions into acc1/acc2.
       - Store out_vec = acc1 + acc2 to output tensor at positions corresponding to v offsets.
   - This computes per-head logits without creating intermediate q_nope @ Kc_all and q_pe @ Kp_all separately. It fuses both into one kernel.
2. In ModelNew.forward:
   - Ensure tensors are on CUDA (Triton requires GPU). If not on CUDA, fall back to PyTorch run for correctness. But ideally we’ll run on GPU since get_inputs returns CUDA tensors when set up properly.
   - Flatten Kc_all = ckv_cache.reshape(-1, 512) and cast to float32; same for Kp_all. Keep sparse_indices as int32.
   - Prepare output tensor logits_out zeros [num_tokens, 16, 2048] in float32.
   - Launch fused_logits_kernel with grid (num_tokens, 16), and pass valid_indices per token (computed on host).
   - For each token t:
     - Build valid_indices = sparse_indices[t][sparse_indices[t] != -1] and tok_idx = valid_indices.to(long).
     - Select Kc = Kc_all[tok_idx], Kp = Kp_all[tok_idx] on host.
     - Compute logits_scaled, lse (base-2 logsumexp), attn = softmax(logits_scaled).
     - output_bf16[t] = attn @ Kc (matmul in float32, then cast to bfloat16).
   - Return (output_bf16, lse).

Notes
- This approach moves the heavy per-token fusion into Triton and keeps the subsequent operations in PyTorch for simplicity. If further optimization is needed, we can implement:
  - A Triton softmax kernel that computes row-wise logsumexp and outputs softmax directly, then another Triton matmul to do attn @ Kc. That would reduce Python overhead further, but is more involved.
- The Triton kernel uses compile-time unrolled loops over head_dim_ckv and head_dim_kpe by passing those as tl.constexpr. That’s acceptable here since these are fixed at 512 and 64 respectively. If they vary, the kernel would need to be specialized per run (we pass them as arguments, so Triton compiles per distinct value).
- We ensure Triton kernels are actually invoked from ModelNew.forward (they are).

    BLOCK_V: tl.constexpr,

@triton.jit
def fused_logits_kernel_full(
    q_nope_ptr,   # *const float, [num_tokens, num_qo_heads, head_dim_ckv]
    q_pe_ptr,     # *const float, [num_tokens, num_qo_heads, head_dim_kpe]
    Kc_all_ptr,   # *const float32, [num_valid, head_dim_ckv]
    Kp_all_ptr,   # *const float32, [num_valid, head_dim_kpe]
    out_ptr,      # *float32,      [num_tokens, num_qo_heads, num_valid]
    valid_indices_ptr,  # *const int32, [num_valid]
    num_tokens: tl.constexpr,
    num_qo_heads: tl.constexpr,
    num_valid: tl.constexpr,
    head_dim_ckv: tl.constexpr,
    head_dim_kpe: tl.constexpr,
    BLOCK_V: tl.constexpr,
):

    pid_h = tl.program_id(1)  # head index

    for v_start in range(0, num_valid, BLOCK_V):
        v_offsets = v_start + tl.arange(0, BLOCK_V)
        mask_v = v_offsets < num_valid

        tok_idx = tl.load(valid_indices_ptr + v_offsets, mask=mask_v, other=-1)  # [BLOCK_V], int32

        # Accumulators
        acc1 = tl.zeros([BLOCK_V], dtype=tl.float32)
        acc2 = tl.zeros([BLOCK_V], dtype=tl.float32)

        # Compute q_nope[t, pid_h, :] dot Kc_all[:, :] contributions
        for d in range(0, head_dim_ckv):
            q_val = tl.load(
                q_nope_ptr + pid_t * (num_qo_heads * head_dim_ckv) + pid_h * head_dim_ckv + d,
                mask=True,
                other=0.0,
            )  # scalar float32
            kc_vals = tl.load(
                Kc_all_ptr + tok_idx * head_dim_ckv + d,
                mask=mask_v,
                other=0.0,
            )  # [BLOCK_V] float32
            acc1 += q_val * kc_vals

        # Compute q_pe[t, pid_h, :] dot Kp_all[:, :] contributions
        for d in range(0, head_dim_kpe):
            q_val_p = tl.load(
                q_pe_ptr + pid_t * (num_qo_heads * head_dim_kpe) + pid_h * head_dim_kpe + d,
                mask=True,
                other=0.0,
            )  # scalar float32
            kp_vals = tl.load(
                Kp_all_ptr + tok_idx * head_dim_kpe + d,
                mask=mask_v,
                other=0.0,
            )  # [BLOCK_V] float32
            acc2 += q_val_p * kp_vals

        # Store fused logits for this head and v-block
        # out_ptr indexing: out_ptr + pid_t * (num_qo_heads * num_valid) + pid_h * num_valid + v_offsets
        out_base = pid_t * (num_qo_heads * num_valid) + pid_h * num_valid
        tl.store(out_ptr + out_base + v_offsets, acc1 + acc2, mask=mask_v)
