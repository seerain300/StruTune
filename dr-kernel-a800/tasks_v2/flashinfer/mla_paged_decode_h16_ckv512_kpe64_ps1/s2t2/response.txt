What to optimize and how:
- Triton is great at small-GEMV (matrix-vector products) and reductions. We can implement:
  - A kernel to compute all tokens’ logits for a given batch element and loop over heads. We’ll use one Triton program per batch element and iterate H heads inside the kernel. This keeps the kernel simple and ensures we never use torch ops for matmul or softmax.
  - For each head h:
    - Load qn[h, :] and qp[h, :] as vectors.
    - Loop over tokens t:
      - Load Kc_row[t, :] and Kp_row[t, :]
      - Compute dot1 = sum(qn * Kc_row), dot2 = sum(qp * Kp_row)
      - Compute logits_scalar = (dot1 + dot2) * sm_scale and store it for this head into a per-head buffer logits_buf[H, D1].
      - After the loop, compute lse for head h from logits_buf[h, :] using max and sum-exp in Triton.
    - The original logic does out = attn @ Kc; we can compute this by re-reading Kc rows and using the softmax weights (or, equivalently, since attn multiplies Kc row-wise, we can recompute out as sum over tokens of normalized weights times Kc rows). But computing out directly per token in Triton is cumbersome because softmax requires reductions across tokens. To keep Triton-only and avoid torch operations, we implement a second kernel that:
      - For each head h, re-computes logits_scaled per token (reading q and K rows), computes softmax, and accumulates out[h, :] += softmax[t] * Kc_row[t, :].
- We will slice q and K per batch element on host and pass them to Triton kernels. Although we slice, the heavy computation (matmuls and softmax) is still performed by Triton. We avoid any torch matmul or softmax in the Triton path.

Why this approach:
- Avoids dynamic tl.arange with runtime sizes (which caused compilation failures before) by using tl.arange with tl.constexpr (D1, D2, H).
- Keeps everything in Triton kernels: two kernels total:

  2) compute_out_and_lse_kernel: for each batch element, re-computes per-token scaled logits, computes softmax, and accumulates out[h, :].
- Slicing on host is acceptable and avoids Triton limitations. It’s still a Triton-only solution because we do not use torch matmul/softmax; all softmax and reductions are done in Triton.

Performance considerations:
- L_tokens is small in provided workloads (e.g., 8–108). One program per batch element with inner loops over H (16) and D (512/64) is efficient and keeps the code simple and robust.
- We use fp32 math in Triton for stability; output is bfloat16 as in the original.

import math
import torch

import triton
import triton.language as tl


@triton.jit
def _compute_logits_lse_kernel(
    q_nope_rows_ptr,       # *f32, shape [H, D1], contiguous
    q_pe_rows_ptr,         # *f32, shape [H, D2], contiguous
    Kc_sub_ptr,            # *f32, shape [L_tokens, D1], contiguous
    Kp_sub_ptr,            # *f32, shape [L_tokens, D2], contiguous
    lse_out_ptr,           # *f32, shape [B, H], contiguous
    H: tl.int32,           # number of heads
    D1: tl.constexpr,      # head_dim_ckv (512)
    D2: tl.constexpr,      # head_dim_kpe (64)
    L_tokens: tl.int32,    # number of tokens in this batch element
    sm_scale: tl.float32,  # scaling factor
):
    # One Triton program per batch element. We loop over all heads inside.
    b = tl.program_id(axis=0)

    # Per-head buffers to accumulate logits for computing lse
    # Use a pointer to a 1D fp32 buffer of size H*D1, initialized on host. We will fill it here.
    # However, Triton does not allow direct pointer arithmetic to write into an output pointer without a base.
    # Instead, we allocate a temporary fp32 tensor on host, but here we keep it inside the kernel as a local array.
    # To store lse, we'll write to lse_out_ptr[b*H + h] after computing.
    for h in range(0, H):
        # Load q vectors for this head
        qn = tl.load(q_nope_rows_ptr + h * D1 + tl.arange(0, D1)).to(tl.float32)  # [D1]
        qp = tl.load(q_pe_rows_ptr + h * D2 + tl.arange(0, D2)).to(tl.float32)   # [D2]

        # Initialize per-column logits buffer
        logits_buf = tl.zeros((D1,), dtype=tl.float32)

        # Loop over tokens, accumulate per-column logits
        for t in range(0, L_tokens):
            Kc_row = tl.load(Kc_sub_ptr + t * D1 + tl.arange(0, D1)).to(tl.float32)  # [D1]
            Kp_row = tl.load(Kp_sub_ptr + t * D2 + tl.arange(0, D2)).to(tl.float32)  # [D2]

            dot1 = tl.zeros((), dtype=tl.float32)
            dot2 = tl.zeros((), dtype=tl.float32)
            for i in range(0, D1):
                dot1 += qn[i] * Kc_row[i]
            for j in range(0, D2):
                dot2 += qp[j] * Kp_row[j]

            logits_buf += (dot1 + dot2) * sm_scale

        # Compute lse for this head: max + log(sum(exp)) and divide by ln(2)
        max_val = tl.max(logits_buf)
        sum_exp = tl.zeros((), dtype=tl.float32)
        for i in range(0, D1):
            sum_exp += tl.exp(logits_buf[i] - max_val)
        lse_h = max_val + tl.log(sum_exp)
        lse_h = lse_h / math.log(2.0)
        tl.store(lse_out_ptr + b * H + h, lse_h)


@triton.jit
def _compute_out_from_logits_kernel(

    q_pe_rows_ptr,         # *f32, shape [H, D2]
    Kc_sub_ptr,            # *f32, shape [L_tokens, D1]
    Kp_sub_ptr,            # *f32, shape [L_tokens, D2]
    output_ptr,            # *bf16, shape [B, H, D1]
    lse_in_ptr,            # *f32, shape [B, H] (not used here, but can be passed if needed)
    H: tl.int32,
    D1: tl.constexpr,
    D2: tl.constexpr,
    L_tokens: tl.int32,
    sm_scale: tl.float32,
):

    # compute softmax, and accumulate output.
    b = tl.program_id(axis=0)

    for h in range(0, H):
        qn = tl.load(q_nope_rows_ptr + h * D1 + tl.arange(0, D1)).to(tl.float32)  # [D1]
        qp = tl.load(q_pe_rows_ptr + h * D2 + tl.arange(0, D2)).to(tl.float32)   # [D2]

        out_vec = tl.zeros((D1,), dtype=tl.float32)

        # First pass: compute per-token logits and max for softmax stability
        token_max = tl.full((), -float("inf"), dtype=tl.float32)
        for t in range(0, L_tokens):
            Kc_row = tl.load(Kc_sub_ptr + t * D1 + tl.arange(0, D1)).to(tl.float32)  # [D1]
            Kp_row = tl.load(Kp_sub_ptr + t * D2 + tl.arange(0, D2)).to(tl.float32)  # [D2]

            dot1 = tl.zeros((), dtype=tl.float32)
            dot2 = tl.zeros((), dtype=tl.float32)
            for i in range(0, D1):
                dot1 += qn[i] * Kc_row[i]
            for j in range(0, D2):
                dot2 += qp[j] * Kp_row[j]

            logits_t = (dot1 + dot2) * sm_scale
            token_max = tl.maximum(token_max, logits_t)

        # Second pass: compute sum of exp(logits - token_max)
        token_sum = tl.zeros((), dtype=tl.float32)
        for t in range(0, L_tokens):
            Kc_row = tl.load(Kc_sub_ptr + t * D1 + tl.arange(0, D1)).to(tl.float32)  # [D1]
            Kp_row = tl.load(Kp_sub_ptr + t * D2 + tl.arange(0, D2)).to(tl.float32)  # [D2]

            dot1 = tl.zeros((), dtype=tl.float32)
            dot2 = tl.zeros((), dtype=tl.float32)
            for i in range(0, D1):
                dot1 += qn[i] * Kc_row[i]
            for j in range(0, D2):
                dot2 += qp[j] * Kp_row[j]

            logits_t = (dot1 + dot2) * sm_scale
            attn_t = tl.exp(logits_t - token_max)  # softmax contribution
            # We need a scalar token_sum; we compute it via reduction; since this is small, loop is fine.
            # Then accumulate output
            out_vec += attn_t * Kc_row

        # Store output for this head
        tl.store(output_ptr + b * (H * D1) + h * D1 + tl.arange(0, D1),
                 out_vec.to(tl.bfloat16))

                D1=D1,

                D1=D1,
                D2=D2,
                L_tokens=L_tokens,
                sm_scale=sm_scale,
