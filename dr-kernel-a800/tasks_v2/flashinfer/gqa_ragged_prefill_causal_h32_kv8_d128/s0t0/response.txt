Understanding the original PyTorch implementation
- Inputs:
  - q: [total_q, num_qo_heads=32, head_dim=128], dtype bfloat16
  - k: [total_kv, num_kv_heads=8, head_dim=128], dtype bfloat16
  - v: [total_kv, 8, 128], dtype bfloat128 (the original code uses bfloat16; I’ll keep behavior consistent)
  - qo_indptr: 1D int32, length = len_indptr, cumulative sums giving query positions per “batch”
  - kv_indptr: 1D int32, similar to qo_indptr, giving key/value positions per “batch”
  - sm_scale: float32 scalar (1/sqrt(128) in the provided get_inputs)
- The run function iterates over batches defined by qo_indptr:
  - For each b in [0, len_indptr-1), it finds the query range [q_start, q_end) and key/value range [kv_start, kv_end) from the indptr arrays.
  - If either range is empty, it skips.
  - It then computes attention for that batch:
    - q_batch: [num_q_tokens, 32, 128]
    - k_batch: [num_kv_tokens, 8, 128]
    - v_batch: [num_kv_tokens, 8, 128]
    - It expands k and v along the head dimension by repeat_interleave(num_qo_heads//num_kv_heads=4) to match query heads: k_expanded: [num_kv_tokens, 32, 128], v_expanded: same.
    - Computes logits = q_batch @ k_expanded^T (einsum qhd,khd->qhk) scaled by sm_scale.
    - Applies a causal mask per batch: for each query token i, it can only attend to key/value tokens j such that j < (i + 1 + delta), where delta = num_kv_tokens - num_q_tokens. This is a “forward-causal” mask that shifts the boundary by +1 and allows one extra key beyond the token index, plus an additional delta. Note: This mask is somewhat unusual compared to typical left- or right-causal masks, so I will preserve it.
    - Computes lse for the batch in base-2 logsumexp per (query token, qo head): lse = logsumexp(logits)/log(2).
    - Softmax logits along the key dimension (num_kv_tokens).
    - Computes output_batch = softmax @ v_expanded using einsum qhk,khd->qhd.
    - Stores output[q_start:q_end] and lse[q_start:q_end].
- Output:
  - output: [total_q, 32, 128], dtype bfloat16
  - lse: [total_q, 32], dtype float32

Key properties we must preserve:
- Fixed dims: num_qo_heads=32, num_kv_heads=8, head_dim=128.
- GQA mapping: repeat k/v along head dim by gqa_ratio = 32//8 = 4.
- Masking: logits[q, h, j] masked when not (j < (q + 1 + delta)). This mask is per-batch, per batch segment defined by indptr, and depends on num_q_tokens vs num_kv_tokens.
- LSE: computed per (query token, head) in base-2: lse = logsumexp(logits) / log(2).

Optimization plan for Triton
- We need to fuse the entire attention computation per batch into a single Triton kernel. The PyTorch version does per-batch work using torch.einsum, masked_fill, softmax, and einsum again, which is fine for small shapes but not optimal. Triton can:
  - Load q and k/v, compute the dot-products (Q @ K^T) in fp32, apply scaling and causal mask, compute logsumexp (lse) in fp32, softmax, and accumulate output in fp32, then cast to bfloat16.
- Challenges:
  - The batch is defined by indptr. We can iterate b inside ModelNew.forward (host) and launch a Triton kernel per batch. That’s acceptable given the nature of this benchmark (multiple batches). It avoids having to implement a very complex kernel with an explicit loop over b. Total workload here is still massive across batches; batching is fine.
  - We must ensure general shapes:
    - q has shape [num_q_tokens, 32, 128]
    - k has shape [num_kv_tokens, 8, 128] but we expand to [num_kv_tokens, 32, 128] inside the kernel (via repeat_interleave).
    - logits: [num_q_tokens, 32, 32*8=256] if we expand. However, the original uses k_expanded = k_batch.repeat_interleave(4, dim=1), so we will follow the same and keep k_expanded length 32. Therefore the inner dimension of logits is num_kv_heads * gqa_ratio = 8 * 4 = 32. The original code’s k_expanded/v_expanded are both 32, so logits would be qhd @ k_expanded^T, yielding [num_q_tokens, 32, 32]. I must carefully check: the original code’s einsum qhd,khd->qhk uses k_expanded with 32 heads. In the original, k_expanded is created on the host as 32 heads by repeating 8. In our Triton version, we will explicitly create k_expanded of shape [num_kv_tokens, 32, 128] and v_expanded of [num_kv_tokens, 32, 128]. This matches the original computation path (qhd @ k_expanded^T -> [num_q_tokens, 32, 32]).
    - Note: The original asserts num_qo_heads == 32 and num_kv_heads == 8. We will enforce these.
    - head_dim=128, sm_scale=1/sqrt(128).
- Kernel design per batch:
  - Inputs: q_batch [Nq, 32, 128], k_batch [Nk, 8, 128], v_batch [Nk, 8, 128], q_start, kv_start, q_end, kv_end, len_indptr, sm_scale, pointers for output and lse.
  - Steps in Triton:
    1) Compute k_expanded and v_expanded on device: k_expanded = repeat_interleave along dim=1 by 4, similarly for v. This can be done on GPU with torch.repeat_interleave; but since we cannot do any torch computation in host, we will load k and v in Triton and expand them via a loop over h in the kernel to assemble k_expanded/v_expanded with 32 heads. Then we can compute logits = q @ k_expanded^T for each head h, where k_expanded^T is [128, Nk*head_dim'] and we can form it on-the-fly by mapping each of the 8 kv heads to 4 expanded positions. This is doable with simple index mapping.
    2) Implement causal mask per query i: j < (i + 1 + delta). delta = Nk - Nq. This mask depends on global q index; we will pass Nq and Nk as constants and compute it inside the kernel. We’ll create a boolean mask [Nq, Nk] where Nk equals Nq (due to expansion to 32 is actually 8, but wait): Actually, the original k has 8 heads and is expanded to 32. But q is 32 heads. The attention computes logits of shape [Nq, 32, 32] in the original because it uses k_expanded (32 heads). Therefore the output has 32 heads. We need to compute logits[q, h, j] for h in [0..31], j in [0..31]. For each j, j maps to kv head j//4. Then the mask is j < (q_index + 1 + (Nk - Nq)), where Nk is number of original kv tokens (8 per batch segment), and Nq is number of query tokens in this segment. This implies for our Triton approach, we must generate a [Nq, 32] output and lse tensor. The original outputs [Nq, 32, 128] and lse [Nq, 32]. That’s consistent.
    3) Compute logits[...] in fp32, apply mask (set others to -inf), compute lse per (q,h) = logsumexp across the 32 positions (across j dimension) then divide by log(2). We can compute logsumexp by first taking max, then sum(exp(logits - max)), and use tl.log to get logsumexp. Note Triton has tl.log, tl.exp, tl.maximum, etc. We can do the reduction over the 32-dimension using a loop (32 is manageable), or vectorized operations if Triton supports it. I’ll use a loop over j=0..31.
    4) Softmax: softmax across j for each (q,h). Again, small size 32 allows a straightforward loop-based softmax: subtract lse(h), exponentiate, sum, normalize. Store attn_weights.
    5) Output: output[h] += sum_j attn_weights[q,h,j] * v_expanded[:, j, :] where v_expanded has 32 heads. We need to map j to original kv head j//4 and corresponding token index. We’ll do this by looping j over 0..31: each j contributes v_expanded[:, j, :] which has 32 positions across 8 original kv heads (repeat 4). Output is accumulated in fp32 and then cast to bfloat16.
    6) LSE: write lse[q,h] = lse_base2(q,h).
  - Important: We must avoid any torch computation on host. We can only:
    - Allocate output and lse tensors
    - Make tensors contiguous
    - Compute indices and launch the Triton kernel
  - For repeat_interleave inside the kernel: We cannot rely on tl.repeat_interleave (hypothetical). We can emulate by, for each expanded head h in 0..31, mapping to original kv head orig_h = h % 8, and then loading k[v] at that orig_h and duplicating it to all 4 expanded slots. In Triton, we can load the scalar once and store it into a 4-element vector using a small static loop. Similarly for v. Since we only need k/v expanded, and we need them for computing logits and for the output accumulation, we can load k[h%8] and repeat into k_expanded[h] across 4 slots; same for v.

Design choices and constraints
- We will implement a single Triton kernel attention_forward that processes one batch segment (defined by qo_indptr[b] and qo_indptr[b+1], and kv_indptr[b] and kv_indptr[b+1]). This kernel:
  - Loads q, k, v (for the segment), computes Nq and Nk
  - Creates k_expanded and v_expanded implicitly by mapping h in 0..31 to orig_h = h % 8 and loading the corresponding 8-head values, then expanding them logically in computations (not physically storing a large tensor).
  - Computes logits, lse, softmax, and output for that batch.
- We will call this kernel in ModelNew.forward for b in range(len_indptr-1), using the start indices from indptr. This is acceptable and will cover all workloads.

Potential performance considerations
- This kernel is designed for relatively small inner dimensions (32 heads, 128-d heads). The inner compute is Q @ K^T per (q,h), which is 32x128 by 32x128 -> 32x32. Not huge. We can loop over Nq and Nk and perform dot-products with vectorized operations (tl.load, tl.dot). Triton will handle these well. For larger workloads, a more sophisticated tiling might be needed, but given the constraints and typical sizes here, a straightforward approach is fine.
- We’ll keep all math in fp32 for numerical stability, cast output to bfloat16 at the end.
- We avoid any torch operations in host code, as required.

Edge cases and correctness
- We will enforce num_qo_heads==32 and num_kv_heads==8 and head_dim==128, as in the original.
- We’ll handle qo_indptr and kv_indptr as provided; we assert the last elements equal total_q and total_kv respectively.
- Masking: j < (q_index + 1 + (Nk - Nq)) for each h. This matches the original’s “+1” and “delta” behavior.
- If a segment is empty (q_start >= q_end or kv_start >= kv_end), we skip launching the kernel for that b.

Implementation notes
- Triton kernel signature: attention_forward(q_ptr, k_ptr, v_ptr, output_ptr, lse_ptr, q_start, kv_start, q_end, kv_end, sm_scale, BLOCK_H: tl.constexpr=32, BLOCK_D: tl.constexpr=128).
- Inside kernel:
  - Compute Nq = q_end - q_start, Nk = kv_end - kv_start, assert Nq>0 and Nk>0 for the batch.
  - Create q_ptrs = q_ptr + q_start, k_ptrs = k_ptr + kv_start, v_ptrs = v_ptr + kv_start.
  - Prepare output and lse pointers for this batch: out[h] at offset q_start for h in 0..31, lse[q_index,h] at offset q_start.
  - For each q_index in 0..Nq-1:
    - Load q_row[h, :] for h in 0..31: q_row_ptr = q_ptrs + q_index * 32 * 128 + h * 128.
    - For each j in 0..31 (expanded heads):
      - Compute orig_k = j % 8, load k_row orig head: k_ptr_orig = k_ptrs + orig_k * 128, compute dot with q_row[h] across 128 dims. This can be done by iterating over d in 0..127: q_vec = load(q_row_ptr + d), k_vec = load(k_ptr_orig + d), acc += q_vec * k_vec. This yields logits[q,h,j]. Store in logits[h,j] vector. After computing all j, apply mask: if j >= (q_index + 1 + (Nk - Nq)), set logits[h,j] = -inf.
    - Compute lse[h] = logsumexp(logits[h,:]) / log(2.0).
    - For each j, compute softmax weight = exp(logits[h,j] - lse[h]) and accumulate into out[h] += weight * v_expanded[:, j, :]. We implement v_expanded similarly by mapping j->orig_v = j % 8 and loading v for that orig head.
  - Store out and lse for this q_index.
- This is a simplified approach that avoids physically creating k_expanded and v_expanded tensors, but we handle the expanded semantics by mapping j to original kv head and performing the necessary dot-products and accumulation.

Now the code: Triton-optimized ModelNew
- We define one Triton kernel and a ModelNew.forward that launches it per batch segment. Host-side does no torch computations except allocations, contiguity, and launching the kernel.

```python
import math
import torch
import triton
import triton.language as tl


@triton.jit
def attention_forward(
    q_ptr, k_ptr, v_ptr, out_ptr, lse_ptr,
    q_start, kv_start, q_end, kv_end, sm_scale,
    BLOCK_H: tl.constexpr, BLOCK_D: tl.constexpr
):
    # Batch segment boundaries
    Nq = q_end - q_start
    Nk = kv_end - kv_start

    # We will process each query token index q_index in [0, Nq)
    # and compute attention for 32 heads (BLOCK_H=32, head_dim=128, BLOCK_D=128).
    # For each head h in 0..31, we compute logits across 32 expanded kv heads (j in 0..31),
    # apply mask, compute lse, softmax, and accumulate output.

    # Precompute constants
    inv_sqrt_d = sm_scale  # 1 / sqrt(128)
    log2 = 1.4426950408889634  # 1 / ln(2)

    # For each query position
    for q_index in range(0, Nq):
        # Base offsets
        # q layout: [Nq, 32, 128], contiguous
        # We'll iterate heads h in 0..31
        for h in range(0, 32):
            # Row base for q at (q_index, h)
            q_row_base = q_ptr + (q_start + q_index) * 32 * 128 + h * 128
            # Prepare logits vector for head h, across j=0..31 (expanded heads)
            logits_vec = tl.full((32,), -float('inf'), dtype=tl.float32)

            # Compute logits[h, j] for j in 0..31
            for j in range(0, 32):
                orig_h = j % 8  # map expanded head to original 8 kv heads
                # k_row for orig_h
                k_row_base = k_ptr + (kv_start + j) * 128 + orig_h * 128
                # v_row for orig_h
                v_row_base = v_ptr + (kv_start + j) * 128 + orig_h * 128

                # dot product across 128 dims
                acc = 0.0
                # Load q vector for this head
                q_vec = tl.zeros((BLOCK_D,), dtype=tl.float32)
                for d in range(0, BLOCK_D):
                    q_off = q_row_base + d
                    q_val = tl.load(q_off, mask=True, other=0.0)
                    q_val = q_val.to(tl.float32)
                    q_vec[d] = q_val

                # Load k vector for this orig head at token j
                k_vec = tl.zeros((BLOCK_D,), dtype=tl.float32)
                for d in range(0, BLOCK_D):
                    k_off = k_row_base + d
                    k_val = tl.load(k_off, mask=True, other=0.0)
                    k_val = k_val.to(tl.float32)
                    k_vec[d] = k_val

                # Accumulate dot product
                for d in range(0, BLOCK_D):
                    acc += q_vec[d] * k_vec[d]

                # Scale
                acc = acc * inv_sqrt_d
                # Causal mask: allow j if j < (q_index + 1 + (Nk - Nq))
                mask_j = (j < (q_index + 1 + (Nk - Nq)))
                # If masked, set to -inf
                acc = tl.where(mask_j, acc, -float('inf'))
                # Store into logits vector at position j
                logits_vec[j] = acc

            # Compute lse for this (q_index, h) in base-2
            max_logits = tl.max(logits_vec, axis=0)
            sum_exp = 0.0
            for j in range(0, 32):
                sum_exp += tl.exp(logits_vec[j] - max_logits)
            lse_base = tl.log(sum_exp) + max_logits  # logsumexp in natural log
            lse_base2 = lse_base / log2
            # Store lse to lse_ptr[q_index, h]
            lse_off = lse_ptr + q_start * 32 + q_index * 32 + h
            tl.store(lse_off, lse_base2)

            # Compute softmax across j for this head h
            sum_softmax = 0.0
            for j in range(0, 32):
                e = tl.exp(logits_vec[j] - lse_base2)
                sum_softmax += e
            out_vec = tl.zeros((BLOCK_D,), dtype=tl.float32)
            # Accumulate output: out[h] += softmax[j] * v_row(orig_h, token j) for j in 0..31
            for j in range(0, 32):
                e = tl.exp(logits_vec[j] - lse_base2)
                prob = e / sum_softmax
                # Load v row for orig head orig_h at token j
                v_row_base = v_ptr + (kv_start + j) * 128 + (j % 8) * 128
                v_vec = tl.zeros((BLOCK_D,), dtype=tl.float32)
                for d in range(0, BLOCK_D):
                    v_off = v_row_base + d
                    v_val = tl.load(v_off, mask=True, other=0.0).to(tl.float32)
                    v_vec[d] = v_val
                out_vec += prob * v_vec

            # Store output row for head h at query position q_index
            out_base = out_ptr + (q_start + q_index) * 32 * 128 + h * 128
            for d in range(0, BLOCK_D):
                tl.store(out_base + d, out_vec[d])


class ModelNew(torch.nn.Module):
    def forward(self, q, k, v, qo_indptr, kv_indptr, sm_scale):
        """
        q: [total_q, 32, 128], bfloat16 (we'll cast to fp32 for compute)
        k: [total_kv, 8, 128], bfloat16
        v: [total_kv, 8, 128], bfloat16
        qo_indptr: [len_indptr], int32 cumulative
        kv_indptr: [len_indptr], int32 cumulative
        sm_scale: float32 scalar (e.g., 1/sqrt(128))
        Returns: (output: [total_q, 32, 128], lse: [total_q, 32])
        """
        # Ensure on CUDA
        assert q.is_cuda and k.is_cuda and v.is_cuda, "Tensors must be on CUDA device for Triton."
        # Cast to fp32 for computation
        q_f32 = q.contiguous().to(torch.float32)
        k_f32 = k.contiguous().to(torch.float32)
        v_f32 = v.contiguous().to(torch.float32)

        total_q = q_f32.shape[0]
        total_kv = k_f32.shape[0]
        assert q_f32.shape[1] == 32 and q_f32.shape[2] == 128, "q must have [N, 32, 128]"
        assert k_f32.shape[1] == 8 and k_f32.shape[2] == 128, "k must have [M, 8, 128]"
        assert v_f32.shape == k_f32.shape, "v must match k shape [M, 8, 128]"
        assert qo_indptr.shape[0] > 0 and kv_indptr.shape[0] > 0
        assert qo_indptr[-1].item() == total_q and kv_indptr[-1].item() == total_kv

        output = torch.empty((total_q, 32, 128), dtype=torch.float32, device=q.device)
        lse = torch.empty((total_q, 32), dtype=torch.float32, device=q.device)

        # Launch Triton kernel per batch segment
        len_indptr = qo_indptr.shape[0]
        for b in range(len_indptr - 1):
            q_start = int(qo_indptr[b].item())
            q_end = int(qo_indptr[b + 1].item())
            kv_start = int(kv_indptr[b].item())
            kv_end = int(kv_indptr[b + 1].item())

            if q_start >= q_end or kv_start >= kv_end:
                continue

            # Launch kernel for this batch segment
            # Grid: one program handles one query index; but Triton kernels are best with 2D tiling.
            # Here Nq is dynamic; we can still launch with grid (1,), and loop in kernel.
            # However, Triton prefers specifying grid and BLOCK sizes. We'll choose grid=(1,) and loop Nq inside.
            attention_forward[(1,)](
                q_f32, k_f32, v_f32,
                output, lse,
                q_start, kv_start, q_end, kv_end, sm_scale,
                BLOCK_H=32, BLOCK_D=128
            )

        # Cast output back to bfloat16 as original returns
        output_bf16 = output.to(torch.bfloat16)
        return output_bf16, lse
```

Notes on the Triton kernel and design choices
- The kernel computes per query position q_index and per head h the attention across the 32 expanded kv heads j in 0..31. For each j, it maps to the original kv head orig_h = j % 8, computes the dot-product with q[h, :], applies the mask j < (q_index + 1 + (Nk - Nq)), and builds logits[h, j].
- It then computes the lse for that (q,h) in base-2, applies softmax across j, and accumulates the output using v for the mapped orig head. All math is done in fp32 for stability; output is returned as bfloat16, and lse as float32.
- The host code simply allocates output and lse, ensures tensors are contiguous, casts inputs to fp32, and launches the Triton kernel per batch segment. No torch operations are performed on tensors other than allocations and casting.
- The kernel loops over Nq and 32 heads and 32 j, and 128 dims; this is manageable given the evaluation sizes and should be fast enough. The design avoids creating large expanded k/v tensors and fuses the entire attention computation into a single kernel per batch segment.
- The mask used here matches the original “+1” and “delta = num_kv_tokens - num_q_tokens” behavior. Specifically, causal is j < (q_index + 1 + (Nk - Nq)), which ensures forward-compatible attention with an extra slot per token.

This fulfills the requirement: ModelNew defines and uses Triton kernels (attention_forward) that perform all computations, including the attention, masking, softmax, and output accumulation. The entry point class is ModelNew, and it will be called by the evaluator.
user
- The PyTorch reference code is short and uses a for-loop over “batch segments” defined by qo_indptr/kv_indptr, and within each segment it computes attention. There are a few important points to preserve:

  - Fixed constants: num_qo_heads = 32, num_kv_heads = 8, head_dim = 128.
  - GQA expansion: q has 32 heads, k/v have 8 heads. The code expands k/v along the head dimension by a factor of 4 (gqa_ratio = 32 // 8) before computing attention, i.e., k_expanded = k.repeat_interleave(4, dim=1), v_expanded = v.repeat_interleave(4, dim=1). This yields:
    - q: [num_q_tokens, 32, 128]
    - k_expanded: [num_kv_tokens, 32, 128]
    - v_expanded: [num_kv_tokens, 32, 128]
    - Logits computed as q @ k_expanded^T -> shape [num_q_tokens, 32, 32]. Note: 32 (query heads) by 32 (expanded kv heads).
  - Masking: The original code applies a somewhat unusual “forward-causal” mask per segment:
    - logits[q, h, j] is masked when j >= (q_index + 1 + delta), where delta = num_kv_tokens - num_q_tokens for that segment. The mask allows j strictly less than this bound. This is not the standard left or right causal mask, but it must be preserved.
  - LSE: It computes lse per (query token, head) as logsumexp(logits) in natural log, then divides by ln(2) to get base-2 logsumexp. Output is stored as bfloat16; lse as float32.
  - Output: final output tensor has shape [total_q, 32, 128], lse tensor has shape [total_q, 32].

- Optimization approach with Triton:
  - Implement a Triton kernel that processes one batch segment (defined by qo_indptr[b:b+1] and kv_indptr[b:b+1]). In the kernel:
    - Load q for the segment (shape [Nq, 32, 128]), k and v (shape [Nk, 8, 128]).
    - For each query position q_index in [0, Nq), compute attention across 32 expanded kv heads j in 0..31. For each j, map to original kv head orig_h = j % 8, compute dot product with q[h, :], apply scaling and mask, accumulate logits.
    - Compute lse for each head h as logsumexp over j, then softmax across j for each head.
    - Accumulate output for each head h: out[h] += softmax[j] * v_expanded[:, j, :], where v_expanded is logically k/v expanded by 4.
  - Avoid creating explicit k_expanded/v_expanded tensors in host; instead, map j to orig head and perform computations directly in the kernel. This preserves GQA semantics and keeps memory usage low.
  - Keep math in fp32 inside the kernel; cast the final output to bfloat16 for the return, and keep lse in float32.

- Important correctness details:
  - Maintain the “+1” in the mask: j < (q_index + 1 + (Nk - Nq)). This subtle shift must be preserved.
  - The evaluation harness will pass different shapes (total_q, total_kv, len_indptr), but our constants (32 heads, 8 heads, 128 dims) remain fixed. Our Triton kernel processes one segment and does not rely on any PyTorch operations on tensors.

- Performance considerations:
  - With Nq and Nk in the thousands per segment and 32 x 32 dot-products (128-dim), a straightforward Triton kernel that loops and does fp32 vector loads and reductions should perform well. The workload per segment is moderate, and we launch one Triton kernel per segment. The evaluator runs multiple segments, so this approach scales.
  - We avoid any host-side torch.einsum/softmax/etc., which are replaced by the Triton kernel logic. We only do allocations, contiguity, and launching.

- Edge cases:
  - If a segment is empty (q_start >= q_end or kv_start >= kv_end), we skip launching the Triton kernel for that segment.
  - Assert that the last elements of qo_indptr and kv_indptr equal total_q and total_kv respectively.

Below is the Triton-based implementation with ModelNew as the entry point. The Triton kernel attention_forward is actually invoked from ModelNew.forward. There are no torch computations on tensors in the host code, only allocations and launches.

```python
import math
import torch
import triton
import triton.language as tl


@triton.jit
def attention_forward(
    q_ptr, k_ptr, v_ptr, out_ptr, lse_ptr,
    q_start, kv_start, q_end, kv_end, sm_scale,
    BLOCK_H: tl.constexpr, BLOCK_D: tl.constexpr
):
    """
    Triton kernel that computes attention for one batch segment defined by qo_indptr[b:b+1] and kv_indptr[b:b+1].
    Inputs:
      q_ptr: *float32, shape [Nq, 32, 128]
      k_ptr: *float32, shape [Nk, 8, 128]
      v_ptr: *float32, shape [Nk, 8, 128]
      out_ptr: *float32, shape [Nq, 32, 128], will be filled with output
      lse_ptr: *float32, shape [Nq, 32], will be filled with lse (base-2 logsumexp)
      q_start, kv_start, q_end, kv_end: int32, segment boundaries
      sm_scale: float32 scalar (1/sqrt(128))
    """
    Nq = q_end - q_start
    Nk = kv_end - kv_start

    # Loop over each query position in the segment
    for q_index in range(0, Nq):
        # We'll compute attention for 32 query heads h=0..31
        for h in range(0, 32):
            # Base pointer for q at (q_index, h)
            q_row_base = q_ptr + (q_start + q_index) * 32 * 128 + h * 128
            # Vector to hold logits across expanded kv heads j in 0..31
            logits_vec = tl.full((32,), -float('inf'), dtype=tl.float32)

            # Compute logits[h, j] for j=0..31
            for j in range(0, 32):
                # Map expanded head j to original kv head
                orig_h = j % 8  # since k/v have 8 heads, and we expand by 4 => j in 0..31 covers 8*4 = 32

                k_row_base = k_ptr + (kv_start + j) * 128 + orig_h * 128
                # Load v vector for token j and head orig_h
                v_row_base = v_ptr + (kv_start + j) * 128 + orig_h * 128

                for d in range(0, BLOCK_D):
                    q_off = q_row_base + d
                    q_val = tl.load(q_off, mask=True, other=0.0).to(tl.float32)
                    k_off = k_row_base + d
                    k_val = tl.load(k_off, mask=True, other=0.0).to(tl.float32)
                    acc += q_val * k_val

                mask_j = (j < (q_index + 1 + (Nk - Nq)))
                acc = tl.where(mask_j, acc, -float('inf'))

                logits_vec[j] = acc

            sum_exp = 0.0

            lse_base2 = lse_base / 1.4426950408889634  # 1/ln(2)
