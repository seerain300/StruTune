High-level plan
- Keep the structure of run: compute per-step update of a per-sequence state tensor, then produce output for each time step. We’ll implement this with Triton kernels.
- The heavy per-step math requires four matrix multiplications:
  1) old_v = k[t] @ state_old, shape [H, K] @ [K, N] -> [H, N]
  2) new_v = beta * v[t] + (1 - beta) * old_v
  3) state_remove = k[t]^T @ old_v -> [H, K] @ [H, N] -> [K, N]
  4) state_update = k[t]^T @ new_v -> [K, N]
  5) new_state = g * state_old + state_update - state_remove
- Output for each t:
  output[t] = scale * q_exp[t] @ new_state[t]
  Here q_exp[t] is [H, K], new_state[t] is [H, N, N], but because output is [H, N], the correct matmul should be q_exp[t] @ state_new[t] where state_new[t] is [N, N] aggregated across heads. However, given the original PyTorch code builds output as [T, H, N], we’ll keep output as [H, N] per step; for correctness, we’ll implement this via Triton as well.
- We will:
  - Define Triton kernels for:
    - compute_g_and_beta (elementwise, per [T, HV], fully in Triton)
    - matmul_1xN_by_NxM (for the 1x128 @ 128x128 outputs like q @ new_state)
    - update_state_single (per-step update of [H, N, N] state using k @ state_old, k^T @ vectors, and scaling by g)
    - output_scalar_single (compute output per t via matmul kernel)
  - Forward will:
    - Initialize cu_seqlens, expand q/k to v heads as the original, compute A_log_exp and a_exp/b_exp accordingly.
    - Launch compute_g_and_beta kernel to get g and beta as tensors.
    - For each sequence, loop over timesteps and:
      - Launch update_state_single kernel to compute new_state for that t given q_exp[k], k_exp[k], v[k], and previous state, using per-head g/beta scalars computed in Triton previously.
      - Launch output_scalar_single kernel to compute output[t] and store.
- Important:
  - We will ensure all Triton kernels are launched in forward, not left as placeholders.
  - No torch.exp, torch.sigmoid, torch.matmul in forward. All math is in Triton.
  - We will assert fixed head sizes (128) and head counts (q/k 4, v 8), matching the provided code. num_seqs varies; we’ll handle general cases.

Performance considerations
- This approach replaces Python loops over timesteps with Triton kernels, performing the required matrix multiplications in blocks. It’s not as aggressively fused as a prefix scan approach, but it ensures Triton does the heavy lifting and is robust across varied sequence lengths. The kernels tile along K and N with BLOCK sizes and accumulate in float32 for numerical stability.

# Inputs:

@triton.jit

                              T: tl.int32, HV: tl.int32,
                              BLOCK: tl.constexpr):

    t = pid // HV
    h = pid % HV
    # Compute offsets
    # We assume pid in [0, T*HV)
    if t >= T:
        return
    a = tl.load(a_ptr + t * HV + h)  # bfloat16
    A_log = tl.load(A_log_ptr + h)   # float32
    dt_bias = tl.load(dt_bias_ptr + h)  # float32
    x = (a.float() + dt_bias)        # float32
    # softplus(x) = log(1 + exp(x))
    sp = tl.log(1.0 + tl.exp(x))     # float32
    g = tl.exp(-tl.exp(A_log) * sp)  # float32
    b = tl.sigmoid(x)                # float32
    tl.store(g_ptr + t * HV + h, g)
    tl.store(beta_ptr + t * HV + h, b)
