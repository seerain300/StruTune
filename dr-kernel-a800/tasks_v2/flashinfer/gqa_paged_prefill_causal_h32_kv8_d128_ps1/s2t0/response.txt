Understanding the original PyTorch code and its computational pattern
- Inputs:
  - q: [total_q, num_qo_heads, head_dim] = [T, H, D] = [total queries, 32, 128]
  - k_cache: [num_pages, 1, num_kv_heads, head_dim] = [N, 1, 8, D]
  - v_cache: same shape as k_cache
  - qo_indptr: [len_indptr] with cumsum of sequence lengths (i.e., segment starts/ends for queries across batches)
  - kv_indptr: [len_indptr] with cumsum of sequence lengths (i.e., segment starts/ends for keys/values across batches)
  - kv_indices: [num_kv_indices] with per-token selected cached K/V page ids
  - sm_scale: float32 scalar, here 1/sqrt(128)
- Assumptions:
  - num_qo_heads == 32, num_kv_heads == 8, head_dim == 128, assert total_q == qo_indptr[-1].item()
  - Flatten k_cache and v_cache along the “1” dimension: k_cache_flat = k_cache.squeeze(1) -> [N, 8, D], similarly v_cache_flat
- Operation per batch b:
  - q_start = qo_indptr[b], q_end = qo_indptr[b+1], and similarly kv_start, kv_end
  - If q_start >= q_end or kv_start >= kv_end, skip
  - Find all cached K/V segments for that batch: kv_indices[kv_start:kv_end] -> [M] page_ids, M = number of KV tokens for this batch
  - For each query token q_idx in [0..num_q_tokens-1]:
    - q_pos = q[q_start+q_idx] -> [H, D]
    - For each qo head h in [0..H-1]:
      - kv_head = h // (H//num_kv_heads) = h // 4 (GQA mapping)
      - q_head = q_pos[h] -> [D]
      - k_head = k_cache_flat[page_ids[:max_kv_idx], kv_head] -> [max_kv_idx, D], where max_kv_idx = min(q_idx + 1 + (M - num_q_tokens), M)
        The +1 and delta are intended for causal/length-aware masking, effectively limiting attention to the first min(q_idx+1 + (M - num_q_tokens), M) tokens of the segment (so queries can’t see future tokens after their own position plus segment gap).
      - v_head = v_cache_flat[...] -> [max_kv_idx, D]
      - logits = q_head @ k_head.T -> [max_kv_idx]
      - logits_scaled = logits * sm_scale
      - lse[h] += logsumexp(logits_scaled) / ln(2) (accumulate per head)
      - attn = softmax(logits_scaled)
      - out_head = attn @ v_head -> [D]
      - Store output[global_q_idx, h] = out_head (bfloat16)
  - Notes:
    - The code asserts num_qo_heads == 32 and num_kv_heads == 8 and head_dim == 128. GQA_ratio = 4, i.e., 4 KV heads share attention across 4 Q heads.
    - For each iteration over q_idx, the code reconstructs small slices of K/V from the full cache. In the provided get_inputs(), num_pages is relatively small, but in some workloads it can be large (hundreds of thousands), and M can be large, making repeated slicing costly.

Performance bottlenecks and optimization opportunities
- The original loop design:
  - For each batch b and each query token q_idx and each head h, it:
    - Constructs k_batch = k_cache_flat[page_ids[:max_kv_idx], kv_head], v_batch = v_cache_flat[...]
    - Computes a dense matmul q_head @ k_head.T (size D x max_kv_idx), applies softmax, then dense matmul attn @ v_head (max_kv_idx x D).
    - This repeats the K/V slicing for each q_idx/h, causing redundant memory loads and heavy per-iteration indexing overhead.
- Observations:
  - For fixed (b, M = kv_end - kv_start), the set of used k_cache_flat rows is always the same set of M cached rows: those indexed by kv_indices[kv_start:kv_end]. So we can load these rows once per batch and reuse across all q_idx and all heads. That’s a substantial improvement: instead of loading K/V for each query separately, load once per batch segment and keep in registers or fast memory. This reduces global memory traffic drastically when M is large.
  - The attention math for each head:
    - With head_dim = 128, D is moderate. Triton can compute logsumexp and softmax in fp32 and then write bfloat16. We can also compute matmuls using Triton, though the repeated small matmuls (D x K then K x D) may be fine with PyTorch as fallback. To maximize performance and keep everything Triton, we can implement the full forward per head and per q_idx as a Triton kernel, but it’s important to note that per-iteration matmul in Triton may not outperform PyTorch for small K unless we carefully tile; however, the dominant cost here is K/V loading. By loading K/V once per batch segment, the biggest win comes.

Design of Triton implementation
- Host (ModelNew.forward) responsibilities:
  - Compute shapes and allocate outputs. Ensure all inputs are contiguous and on CUDA device.
  - Precompute per-batch segment K and V from k_cache_flat and v_cache_flat:
    - For each b in [0..len_indptr-2]:
      - seg_len_q = qo_indptr[b+1] - qo_indptr[b]
      - seg_len_kv = kv_indptr[b+1] - kv_indptr[b]
      - if seg_len_q > 0 and seg_len_kv > 0:
        - k_segment = k_cache_flat[kv_indices[kv_indptr[b]:kv_indptr[b+1]]] -> [seg_len_kv, 8, 128]
          However, Triton kernel expects 2D [K, D] and the kernel will slice kv_head; we can pass k_segment reshaped as [K, 8*128] and use a third dimension of size 8, but simpler is to keep it as [K, 8, D] and slice. Given Triton kernels operate on 2D tensors, we can load per kv_head directly. So better approach: build k_segment_list[8] = k_cache_flat[:, kv_head, :] for each kv_head.
        - Similarly v_segment_list[8]
        - Then launch a Triton kernel that takes q, k_segment_list[h], v_segment_list[h], outputs per (q_idx, h).
  - Launch Triton kernels:
    - Grid dimension:
      - We can structure the grid as (num_batches, num_q_tokens, num_qo_heads). Each kernel instance handles one (b, q_idx, h).
    - Inside each kernel:
      - Read q_pos[h] vector (length D) from q[global_q_idx, h].
      - Load k rows for the segment up to max_kv_idx for kv_head and compute logits vector length K by q_head @ k_row (which is equivalent to dot(q_head, k_row) for each row). This is D times K, vectorized. Triton’s tl.dot can compute this efficiently. We accumulate logits in fp32.
      - Compute softmax of logits_scaled (scaled by sm_scale), then output head = softmax @ v_rows. This is the final D-dimensional output vector for that head. Store as bfloat16.
      - Accumulate lse per (global_q_idx, h) as logsumexp(logits_scaled) / ln(2). Since the original code accumulates across q_idx (not per-batch), we need to ensure we keep global lse across batches. We can keep lse in host as a torch tensor and update with += lse_scalar from kernel (kernel returns per-(b,h) sum; we’ll do per query globally by mapping q_idx -> global_q_idx). To keep it simple and fast, we can write per-batch partial lse and host will sum across b for each (global_q_idx, h). Given len_indptr is small in most cases, this is fine. For large len_indptr, this adds a small overhead; we can mitigate by keeping lse as an atomic or aggregated variable, but simplicity is preferred here.
    - Triton kernels:
      - We will implement one Triton kernel that processes a single (b, q_idx, h) and writes out the D-length output vector and updates lse. We will pass all K and V rows for that kv_head for the segment, and the kernel will compute the attention for that head.
      - Each kernel instance:
        - Determine q_pos = q[b, q_idx, :] (we will pass q[b] flattened per program? Easier to pass pointers and slice. Triton program_id(0)=b, program_id(1)=q_idx, program_id(2)=h. Then we pass pointers and compute offsets accordingly. We can’t directly index q with [b,q_idx,h] from inside kernel, so we pass precomputed q[b] as a 2D [num_q_tokens, H] tensor or 1D per head; better, we compute global_q_idx = qo_indptr[b] + q_idx and pass q at host side. We will flatten q to [T, H, D] contiguous, then inside kernel load q[global_q_idx, h] as a vector. For efficiency, we will allocate q_flat and pass pointers. We will also pass k_segment[h] and v_segment[h] for the batch segment, which are 2D [K, D]. The kernel will compute max_kv_idx for causal masking.
      - This approach minimizes repeated K/V loads: K/V loaded once per batch segment, then used for all q_idx and all heads in that segment by launching a grid over (b, q_idx, h). It satisfies the “all computation in Triton” requirement, avoids any torch math on the host, and reduces memory traffic substantially.

Handling general dynamic sizes
- len_indptr, total_q, num_kv_indices, num_pages vary across workloads. Our Triton kernel will operate per (b, q_idx, h) and will:
  - Read qo_indptr[b], qo_indptr[b+1], kv_indptr[b], kv_indptr[b+1]
  - Compute num_q_tokens = qo_indptr[b+1] - qo_indptr[b], num_kv_tokens = kv_indptr[b+1] - kv_indptr[b]
  - delta = num_kv_tokens - num_q_tokens
  - Determine max_kv_idx = min(q_idx + 1 + delta, num_kv_tokens) per (q_idx, b)
  - Loop over all kv positions k in [0..max_kv_idx-1]:
    - Read k_row from k_segment[h, k, :] and v_row from v_segment[h, k, :]
    - Compute logits[k] = dot(q_head, k_row)
    - Maintain running max and sum for logsumexp
  - Finally compute lse = (logsumexp(logits_scaled) / ln(2))
  - Compute attn = softmax(logits_scaled)
  - Compute out = attn @ v_rows (sum over k rows)
  - Store output and update lse.
- This kernel will be launched with grid = (len_indptr-1, max(num_q_tokens across b), 32). We will compute max(num_q_tokens) on host and set grid accordingly. In practice, Triton kernels support dynamic grid lambdas, but we’ll choose a conservative approach: host computes max q_len and uses that for the grid’s third dimension; it’s fine since len_indptr-1 is small relative to T and H. We will create output and lse tensors with shape (total_q, 32) and per-launch compute global_q_idx and h. This keeps host simple.

Precision and dtype:
- The reference code casts q to float32. We’ll keep q, k, v in float32 for the Triton computations, then store output as bfloat16, and lse as float32. Triton can load bfloat16 and cast to float32 internally; here we’ll ensure input to kernels are float32.

Edge cases and correctness:
- If q_start >= q_end or kv_start >= kv_end, we skip the batch segment. We’ll add a host-side check and not launch the kernel for that b.
- For causal: max_kv_idx is computed as per original. When q_idx is 0 and delta negative (fewer KV than Q), max_kv_idx = 1. This preserves the idea of starting to see at least one KV. In typical setups, num_q_tokens == num_kv_tokens (both segments equal), so delta = 0, max_kv_idx = q_idx + 1. This matches a common causal pattern. We must preserve this logic exactly to match outputs.
- We need to match the accumulation of lse across all q_idx. The original lse is computed per (global_q_idx, h) across all b. Our approach computes per-batch lse and the host will sum across b for each (global_q_idx, h). Given the typical len_indptr is small, this is acceptable. If len_indptr is very large, we could also make lse an atomic accumulation, but per-batch partial sums are simpler and faster.

Plan summary
- Implement ModelNew.forward:
  - Compute qo_indptr, kv_indptr sums; allocate output and lse.
  - Flatten q to [T, H, D] and cast to float32.
  - Precompute k_segments and v_segments per batch:
    - For each b: k_segment[h] = k_cache_flat[:, h, :] indexed by kv_indices in that segment; similarly v.
    - Shapes: k_segment[h] -> [K, D], v_segment[h] -> [K, D], where K = kv_end - kv_start.
  - Launch Triton kernel per (b, q_idx, h):
    - Grid = (len_indptr-1, max_q_tokens, 32)
    - Each instance loads q[global_q_idx, h], k_segment[h], v_segment[h], computes attention, stores output, and atomically adds its lse contribution to lse[global_q_idx, h] divided by ln(2). We will output lse in float32.
- Provide Triton kernel: attention_single_q_idx_h_kernel
  - Accepts pointers to q_flat, k_segment[h], v_segment[h], lse_out[global_q_idx, h], sm_scale.
  - Computes num_q_tokens, num_kv_tokens, delta, max_kv_idx.
  - Iterates over k in [0..max_kv_idx-1], accumulates logits vector, computes logsumexp, softmax, then computes output vector via attn @ v_rows.
  - Stores output as bfloat16 (cast from float32) and atomically adds lse to lse_out.

This design:
- Fuses all computational logic into Triton kernels: no PyTorch math is used in the host code (except for simple shape, allocation, and casts).
- Reduces K/V loads: loaded once per batch segment, reused across all q_idx and all heads in that segment.
- Handles dynamic sizes and varies len_indptr, total_q, num_kv_indices, num_pages across workloads.
- Preserves correctness (modulo small differences in lse accumulation strategy; typically len_indptr is small so per-batch sums are fine).

Now the code for ModelNew with Triton kernels.

```python
import math
import torch
import triton
import triton.language as tl


@triton.jit
def attention_single_q_idx_h_kernel(
    q_ptr,          # *fp32, shape [total_q, H, D] flattened
    k_ptr,          # *fp32, shape [K, D], one per kv_head for the batch segment
    v_ptr,          # *fp32, shape [K, D], one per kv_head for the batch segment
    qo_indptr_ptr,  # *int32, shape [len_indptr]
    kv_indptr_ptr,  # *int32, shape [len_indptr]
    lse_ptr,        # *fp32, shape [total_q, H]
    sm_scale,       # fp32 scalar
    B: tl.constexpr,  # number of batches (len_indptr - 1)
    H: tl.constexpr,  # number of qo heads (e.g., 32)
    D: tl.constexpr,  # head dim (128)
    BLOCK_K: tl.constexpr,  # block size for K loop (e.g., 128)
):
    # Grid: (B, num_q_tokens_max, H)
    b = tl.program_id(0)
    q_idx = tl.program_id(1)
    h = tl.program_id(2)

    # Determine segment bounds
    qo_start = tl.load(qo_indptr_ptr + b)
    qo_end = tl.load(qo_indptr_ptr + b + 1)
    kv_start = tl.load(kv_indptr_ptr + b)
    kv_end = tl.load(kv_indptr_ptr + b + 1)

    num_q_tokens = qo_end - qo_start
    num_kv_tokens = kv_end - kv_start

    # If invalid segment, exit
    if (num_q_tokens <= 0) or (num_kv_tokens <= 0):
        return

    # Global query index
    global_q_idx = qo_start + q_idx

    # Compute causal-like mask parameter: max number of KV tokens this query can see
    # delta = num_kv_tokens - num_q_tokens (same as original)
    delta = num_kv_tokens - num_q_tokens
    # max_kv_idx = min(q_idx + 1 + delta, num_kv_tokens)
    max_kv_idx = tl.minimum(q_idx + 1 + delta, num_kv_tokens)

    # Load q[h, :] vector of length D (fp32)
    q_base = global_q_idx * H * D
    q_offset = q_base + h * D
    q_vec = tl.load(q_ptr + q_offset + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0)

    # Compute logits and logsumexp in fp32
    logits = tl.zeros((BLOCK_K,), dtype=tl.float32)  # will be masked later
    # Running max and sum for logsumexp
    m = -float('inf')
    s = 0.0

    # Loop over k in [0, max_kv_idx)
    for k_start in range(0, max_kv_idx * BLOCK_K, BLOCK_K):
        k_idx = k_start // BLOCK_K  # we want the scalar k in [0..max_kv_idx-1]
        # Build mask for valid k
        valid_k = (k_idx + tl.arange(0, BLOCK_K)) < max_kv_idx
        # Compute K matrix indices: k_idx + arange(0, BLOCK_K) but only up to max_kv_idx
        # Load k_rows: k_ptr is [K, D], we index by k_idx
        k_rows = tl.load(k_ptr + (k_idx + tl.arange(0, BLOCK_K)) * D + tl.arange(0, D),
                         mask=valid_k & (tl.arange(0, D) < D),
                         other=0.0)  # [BLOCK_K, D]
        # Accumulate logits: q_vec @ k_rows.T => sum over D
        logits_block = tl.sum(q_vec[:, None] * k_rows[None, :], axis=1)  # [BLOCK_K]
        # Apply mask to invalid positions by setting to -inf so they don't contribute
        logits_block = tl.where(valid_k, logits_block, -float('inf'))
        # Update running max and sum
        block_max = tl.max(logits_block, axis=0)
        m_new = tl.maximum(m, block_max)
        # s = s * exp(m - m_new) + sum(exp(logits_block - m_new))
        s = s * tl.exp(m - m_new) + tl.sum(tl.exp(logits_block - m_new), axis=0)
        m = m_new

    # Compute logsumexp
    lse_val = m + tl.log(s)  # base e
    # Original divides by ln(2). Convert to base-2
    lse_val = lse_val * (1.0 / 0.6931471805599453)  # 1 / ln(2)

    # Accumulate into lse[global_q_idx, h] (host will aggregate across b)
    lse_offset = global_q_idx * H + h
    tl.atomic_add(lse_ptr + lse_offset, lse_val)

    # Compute attention weights (softmax of scaled logits)
    # Recompute logits for each k to get attn; alternatively we can compute softmax from logits using m and s.
    # We need attn for each k to do out = sum_k attn_k * v_k. To avoid recomputing q@k for every k, we
    # instead compute out by iterating k and accumulating. This is acceptable for D=128.
    out_vec = tl.zeros((D,), dtype=tl.float32)
    # Iterate k again and accumulate
    for k_start in range(0, max_kv_idx * BLOCK_K, BLOCK_K):
        k_idx = k_start // BLOCK_K
        valid_k = (k_idx + tl.arange(0, BLOCK_K)) < max_kv_idx
        k_rows = tl.load(k_ptr + (k_idx + tl.arange(0, BLOCK_K)) * D + tl.arange(0, D),
                         mask=valid_k & (tl.arange(0, D) < D),
                         other=0.0)
        # Compute logits block
        logits_block = tl.sum(q_vec[:, None] * k_rows[None, :], axis=1)
        logits_block = tl.where(valid_k, logits_block, -float('inf'))
        # Compute softmax in base-e (PyTorch uses base-e)
        exp_block = tl.exp(logits_block - m)  # base-e
        sum_block = tl.sum(exp_block, axis=0)
        attn_block = exp_block / sum_block
        # Scale attention by sm_scale (same as original)
        attn_block = attn_block * sm_scale
        # Load v_rows
        v_rows = tl.load(v_ptr + (k_idx + tl.arange(0, BLOCK_K)) * D + tl.arange(0, D),
                         mask=valid_k & (tl.arange(0, D) < D),
                         other=0.0)
        # Accumulate out = sum_k attn_k * v_k
        out_vec += tl.sum(attn_block[:, None] * v_rows[None, :], axis=0)

    # Store output as bfloat16
    # Cast to bfloat16 and store at [global_q_idx, h, :]
    out_base = global_q_idx * H * D
    out_offset = out_base + h * D
    tl.store(q_ptr + out_offset + tl.arange(0, D), out_vec.to(tl.bfloat16), mask=tl.arange(0, D) < D)


class ModelNew(torch.nn.Module):
    def forward(self, q, k_cache, v_cache, qo_indptr, kv_indptr, kv_indices, sm_scale):
        # Ensure device is CUDA
        assert q.is_cuda and k_cache.is_cuda and v_cache.is_cuda, "Triton requires CUDA tensors"
        device = q.device
        total_q = q.shape[0]
        num_qo_heads = q.shape[1]
        head_dim = q.shape[2]
        num_pages, _, num_kv_heads, _ = k_cache.shape
        len_indptr = qo_indptr.shape[0]

        # Allocate outputs
        output = torch.empty((total_q, num_qo_heads, head_dim), dtype=torch.bfloat16, device=device)
        lse = torch.zeros((total_q, num_qo_heads), dtype=torch.float32, device=device)

        # Flatten q to [T, H, D] and cast to fp32 for kernel math
        q_flat = q.contiguous().view(-1, num_qo_heads, head_dim).to(torch.float32)

        # Precompute k_segments and v_segments per batch b
        k_cache_flat = k_cache.squeeze(1).contiguous()  # [num_pages, num_kv_heads, head_dim] -> [N, 8, D]
        v_cache_flat = v_cache.squeeze(1).contiguous()
        k_segments_list = []
        v_segments_list = []
        # We build k_segments[h] and v_segments[h] for each batch segment b. However, to minimize host work,
        # we will launch the kernel with k_ptr, v_ptr pointing to appropriate slices. To do that, we need to
        # prepare per-batch pointers. We'll allocate per-batch arrays and then pass them to the kernel via grid
        # and recompute indices inside the kernel. To reduce complexity, we'll precompute k_segments_list and
        # v_segments_list on host, each of length B, where each element is [K, D] per kv_head.

        # Compute segments per batch: for each b, get kv_indices slice, gather k/v
        B = len_indptr - 1
        for b in range(B):
            qo_start = int(qo_indptr[b].item())
            qo_end = int(qo_indptr[b + 1].item())
            kv_start = int(kv_indptr[b].item())
            kv_end = int(kv_indptr[b + 1].item())
            num_q_tokens = qo_end - qo_start
            num_kv_tokens = kv_end - kv_start
            if num_q_tokens <= 0 or num_kv_tokens <= 0:
                continue
            # Gather cached indices for this batch segment
            selected = kv_indices[kv_start:kv_end]  # [num_kv_tokens]
            # Build k_segments[h] and v_segments[h] per kv_head
            k_segments_per_b = []
            v_segments_per_b = []
            for kv_head in range(num_kv_heads):
                # k_cache_flat[selected, kv_head, :] -> [num_kv_tokens, D]
                k_seg = k_cache_flat[selected, kv_head, :]  # [num_kv_tokens, D]
                v_seg = v_cache_flat[selected, kv_head, :]  # [num_kv_tokens, D]
                # We will pass k_seg and v_seg directly to the kernel. To make them contiguous and in fp32:
                k_seg = k_seg.to(torch.float32).contiguous()  # [num_kv_tokens, D]
                v_seg = v_seg.to(torch.float32).contiguous()
                k_segments_per_b.append(k_seg)
                v_segments_per_b.append(v_seg)
            k_segments_list.append(k_segments_per_b)
            v_segments_list.append(v_segments_per_b)

        # Now we need to launch the kernel. Grid dims: (B, max_q_tokens, H).
        # We need to know max_q_tokens across all b. Compute it.
        max_q_tokens = 0
        for b in range(B):
            qo_start = int(qo_indptr[b].item())
            qo_end = int(qo_indptr[b + 1].item())
            max_q_tokens = max(max_q_tokens, qo_end - qo_start)

        # Prepare grid
        grid = (B, max_q_tokens, num_qo_heads)

        # We need to pass pointers for k_ptr and v_ptr per (b, h) to the kernel. Triton supports per-program
        # pointers; here we can emulate by launching with k_segments_list[b][h] and v_segments_list[b][h]
        # But Triton requires actual tensors, not python lists. We can create per-(b,h) tensors and launch
        # by selecting the correct tensor inside kernel via b and h. To do this, we'll build a 3D grid with
        # a meta-parameter H and iterate; better is to use a 2D grid and decode (b, q_idx, h) using program_id.
        # We'll do a 3D grid with axis2 = h. Triton supports 3D grids. We'll pass pointers as per b/h.

        # Launch the kernel
        # We'll create a wrapper to pass k_ptr and v_ptr for each (b, h) selected. Triton will bind these
        # from the launch. We'll compute b, q_idx, h from program ids, then select k_segments_list[b][h]
        # and v_segments_list[b][h], and pass them as tensors. To keep code compact, we directly use:
        attention_single_q_idx_h_kernel[grid](
            q_flat,                  # q_ptr
            k_segments_list[b][h],   # k_ptr (note: we must pass per-launch tensor; Triton binds based on grid)
            v_segments_list[b][h],   # v_ptr
            qo_indptr,               # qo_indptr_ptr
            kv_indptr,               # kv_indptr_ptr
            lse.view(-1, num_qo_heads),  # lse_ptr
            sm_scale,                # sm_scale
            B=B, H=num_qo_heads, D=head_dim, BLOCK_K=128
        )

        # After the kernel returns, lse has been accumulated. Now store outputs.
        # Note: The kernel above only processed one (b, q_idx, h) and used q_segments from host. In practice,
        # we need to pass the correct k_ptr/v_ptr for each launch. Triton doesn't allow passing a tensor that
