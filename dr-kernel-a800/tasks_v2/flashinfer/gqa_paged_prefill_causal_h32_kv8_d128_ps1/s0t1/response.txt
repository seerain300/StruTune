Root-cause analysis of the previous Triton implementation and fixes

What went wrong:
- The previous Triton kernel attempted to implement the entire attention per batch element with loops and dynamic vector sizes. While the logic is theoretically correct, it led to two critical issues that caused compilation/runtime failure:
  1) Dynamic control flow and vector shapes that depend on runtime values (e.g., max_kv_idx, num_q_tokens, num_kv_tokens) are not supported well by Triton’s static JIT. Triton requires loop bounds to be compile-time constants and vector shapes to be determined at compile-time. The code used Python “for i in range(0, max_kv_idx)” where max_kv_idx is computed inside the kernel; Triton cannot unroll such loops with runtime-dependent bounds. Similarly, building vectors with shapes based on runtime values is not allowed.
  2) Another subtle issue: Triton kernels cannot directly return tensors mutated from device memory (like lse). While I tried to update lse in the kernel, mutating global memory from within the Triton kernel can lead to undefined behavior and is error-prone. The better approach is to compute the result per batch in the kernel and return the outputs to host, where we can merge/accumulate across batches and also manage lse.

Performance and generality:
- The original PyTorch implementation uses Python-side loops per batch, token, and head. That’s easy but not performant for large sizes and many batches. Triton is excellent for batched matmuls and reductions, but this problem is a bit unusual because it compiles queries and KV per batch using kv_indices and performs per-token 1D dot products and softmax. Still, we can leverage Triton to:
  - Compute output vectors per (batch b, token q_idx, head h). This keeps the computation in Triton and avoids torch ops in the host code. We can still use Python to loop over b and q_idx, which is fine for many batches, and Triton will execute the kernel quickly for each case.
  - For lse accumulation, since the original code updates lse in-place across batches (it recomputes per call and uses preallocated tensors), we can compute lse per batch in Triton and then (host-side) add it to the lse returned from the previous batch calls. This preserves the side-effect behavior of the original model.

Plan to fix and optimize:
- Write a simple Triton kernel that, for a given batch b:
  - Reads q_batch, k_batch, v_batch selected by kv_indices for that batch.
  - For each token q_idx in q_batch:
    - Compute max_kv_idx using causal logic: max_kv_idx = min(q_idx + 1 + (num_kv_tokens - num_q_tokens), num_kv_tokens).
    - For each head h:
      - Compute q_vec[h] = q_batch[q_idx, h], k_vec = k_batch[:max_kv_idx, kv_head], v_vec = v_batch[:max_kv_idx, kv_head].
      - Compute logits_i = dot(q_vec, k_row[i]) for each i in 0..max_kv_idx-1 (this is a scalar per i; we loop i).
      - Compute running max and sum for logsumexp across i, then lse_value = (max + log(sum)) / ln(2).
      - Compute attention attn_i = exp(logits_i - max) and output vector out_vec = sum_i attn_i * v_row[i].
      - Store out_vec to output[global_q_idx, h] in bfloat16.
      - Compute and return lse_value / ln(2) for that (global_q_idx, h). Host will accumulate lse across batches by adding each batch’s contribution.

- Host code:
  - _run_triton_b returns (output_chunk, lse_chunk) for one batch b. It launches the kernel once per batch b. We keep output_chunk as a list of vectors and finally stack them into a torch tensor.
  - ModelNew.forward calls _run_triton_b for each b in range(len_indptr - 1), accumulates lse per (global_q_idx, head) by adding the returned chunk, and finally concatenates output chunks to produce the final output tensor of shape [total_q, num_qo_heads, head_dim]. We return (output, lse).

- Dtype:
  - The original code uses bfloat16 for q/k/v and computes with float32 internally, returning bfloat16 output and float32 lse. Our Triton kernel will load bfloat16 q/k/v, compute in float32, and store output as bfloat16. For lse we’ll compute float32 values.

Why this avoids Triton pitfalls:
- Loops and vector operations in the kernel have compile-time known bounds:
  - The kernel loops over head_dim (128) and gqa_ratio (4). These are constants.
  - We use static unrolled loops for the dot product (e.g., over 16 chunks).
  - The only runtime-dependent loop is over idx in 0..max_kv_idx-1 for computing logsumexp. Triton supports “while” loops; however, we can restructure by computing the number of idx steps as an int scalar and unroll the loop in Triton using static control. To keep things robust, we’ll structure the kernel so that the loop over idx uses a while loop with scalar bounds; Triton allows while loops with runtime conditions, and since idx changes each iteration, the JIT handles it.

import torch

# It operates on:
#   q: [total_q, num_qo_heads, head_dim] bfloat16
#   k_flat: [num_pages * num_kv_heads * head_dim] bfloat16 (we pass k_cache.squeeze(1))
#   v_flat: [num_pages * num_kv_heads * head_dim] bfloat16
#   qo_indptr: [len_indptr] int32
#   kv_indptr: [len_indptr] int32
#   kv_indices: [num_kv_indices] int32
# It returns:
#   output_chunk: list of float32 vectors (per (global_q_idx, head))
#   lse_chunk: list of float32 scalars (per (global_q_idx, head))
if TRITON_AVAILABLE:
    @triton.jit
    def _compute_batch_output_kernel(
        q_ptr, k_ptr, v_ptr,
        qo_indptr_ptr, kv_indptr_ptr, kv_indices_ptr,
        # outputs as device buffers (we'll allocate and read back in host):
        out_chunk_ptr, lse_chunk_ptr,
        sm_scale: tl.float32,
        total_q: tl.int32,
        num_qo_heads: tl.int32,
        head_dim: tl.int32,
        gqa_ratio: tl.int32,
        b: tl.int32,  # which batch (0-based), in range [0, len_indptr-2]
        len_indptr: tl.int32,
    ):
        # Load qo_indptr[b] and qo_indptr[b+1]
        q_start = tl.load(qo_indptr_ptr + b)
        q_end = tl.load(qo_indptr_ptr + b + 1)
        kv_start = tl.load(kv_indptr_ptr + b)
        kv_end = tl.load(kv_indptr_ptr + b)

        num_q_tokens = q_end - q_start
        num_kv_tokens = kv_end - kv_start

        # If nothing to do, return early
        if (num_q_tokens <= 0) or (num_kv_tokens <= 0) or (b >= len_indptr - 1):
            return

        # Load kv_indices slice for this batch: [kv_start, kv_end)
        # We need a local vector idx_vec of length num_kv_tokens
        # Triton supports building vectors with constexpr sizes; here num_kv_tokens is runtime.
        # We'll emulate by scalar loop: create idx_vec via a while loop.
        idx_vec = []  # dynamic list of int
        i = 0
        while i < num_kv_tokens:
            idx_val = tl.load(kv_indices_ptr + kv_start + i)  # int32
            idx_vec.append(idx_val)
            i += 1

        # For each token q_idx in this batch
        q_idx = 0
        while q_idx < num_q_tokens:
            global_q_idx = q_start + q_idx

            # Compute max_kv_idx for causal masking
            # delta = num_kv_tokens - num_q_tokens
            delta = num_kv_tokens - num_q_tokens
            max_kv_idx = num_kv_tokens  # initialize
            # compute q_idx + 1 + delta, then clamp to num_kv_tokens
            tmp = q_idx + 1 + delta
            # Triton lacks min helper, implement as: if tmp < num_kv_tokens: max_kv_idx = tmp else: max_kv_idx = num_kv_tokens
            if tmp < num_kv_tokens:
                max_kv_idx = tmp
            else:
                max_kv_idx = num_kv_tokens

            # For each head h
            h = 0
            while h < num_qo_heads:
                kv_head = h // gqa_ratio  # GQA mapping: 32 -> 8 heads, ratio 4

                # Load q_vec[h] for this token: q[global_q_idx, h]
                # q layout: [total_q, num_qo_heads, head_dim] contiguous
                q_off = global_q_idx * (num_qo_heads * head_dim) + h * head_dim
                q_vec = tl.load(q_ptr + q_off + tl.arange(0, head_dim))  # [head_dim], bfloat16
                q_vec = q_vec.to(tl.float32)

                # Initialize logsumexp accumulators for this head
                running_max = tl.full((), -float("inf"), dtype=tl.float32)
                lse_sum = tl.full((), 0.0, dtype=tl.float32)

                # Loop over idx in 0..max_kv_idx-1 to compute logsumexp
                i = 0
                while i < max_kv_idx:
                    idx = idx_vec[i]
                    # k_ptr layout: [num_pages, num_kv_heads, head_dim] flattened = [num_pages * num_kv_heads * head_dim]
                    # Given idx selects a "page" for KV, and kv_head selects the KV head.
                    # Compute linear offset for k_row and v_row
                    k_off = idx * (num_kv_heads * head_dim) + kv_head * head_dim
                    k_row = tl.load(k_ptr + k_off + tl.arange(0, head_dim))  # [head_dim], bfloat16
                    k_row = k_row.to(tl.float32)

                    # Dot product q_vec @ k_row
                    dot_val = 0.0
                    # Unrolled over head_dim in 16 chunks
                    for d in range(0, 128, 16):
                        q_chunk = q_vec[d : d + 16]
                        k_chunk = k_row[d : d + 16]
                        dot_val += tl.sum(q_chunk * k_chunk, axis=0)

                    logits_i = dot_val * sm_scale
                    new_max = tl.maximum(running_max, logits_i)
                    sum_term = lse_sum * tl.exp(running_max - logits_i) + tl.exp(new_max - logits_i)
                    running_max = new_max
                    lse_sum = sum_term

                    i += 1

                lse_value = (running_max + tl.log(lse_sum)) * (1.0 / math.log(2.0))  # float32

                # Now compute output vector: out_vec = sum_i attn_i * v_row[i]
                out_vec = tl.zeros((head_dim,), dtype=tl.float32)
                i = 0
                while i < max_kv_idx:
                    idx = idx_vec[i]
                    k_off = idx * (num_kv_heads * head_dim) + kv_head * head_dim
                    k_row = tl.load(k_ptr + k_off + tl.arange(0, head_dim))  # [head_dim]
                    k_row = k_row.to(tl.float32)
                    dot_val = 0.0
                    for d in range(0, 128, 16):
                        q_chunk = q_vec[d : d + 16]
                        k_chunk = k_row[d : d + 16]
                        dot_val += tl.sum(q_chunk * k_chunk, axis=0)
                    logits_i = dot_val * sm_scale
                    attn_i = tl.exp(logits_i - running_max)
                    v_off = idx * (num_kv_heads * head_dim) + kv_head * head_dim
                    v_row = tl.load(v_ptr + v_off + tl.arange(0, head_dim))  # [head_dim]
                    v_row = v_row.to(tl.float32)
                    out_vec += attn_i * v_row
                    i += 1

                # Store output vector to out_chunk: out_chunk[global_q_idx * num_qo_heads + h]
                out_idx = global_q_idx * num_qo_heads + h
                # out_chunk_ptr is a 1D buffer of float32, length = total_q * num_qo_heads
                tl.store(out_chunk_ptr + out_idx, out_vec)

                # Store lse_value to lse_chunk[global_q_idx * num_qo_heads + h]
                lse_idx = global_q_idx * num_qo_heads + h
                tl.store(lse_chunk_ptr + lse_idx, lse_value)

                h += 1

            q_idx += 1


def _run_triton_b(q, k_cache, v_cache, qo_indptr, kv_indptr, kv_indices, sm_scale, b):
    """
    Compute output for a single batch b using Triton, return (output_chunk, lse_chunk).
    output_chunk: list of float32 vectors of length head_dim, indexed by (global_q_idx, head).
    lse_chunk: list of float32 scalars, indexed by (global_q_idx, head).
    """
    assert TRITON_AVAILABLE, "Triton is not available"
    assert q.is_cuda and k_cache.is_cuda and v_cache.is_cuda, "All tensors must be on CUDA"
    assert q.dtype == torch.bfloat16 and k_cache.dtype == torch.bfloat16 and v_cache.dtype == torch.bfloat16

    total_q, num_qo_heads, head_dim = q.shape
    num_pages, _, num_kv_heads, _ = k_cache.shape
    assert num_qo_heads == 32 and num_kv_heads == 8 and head_dim == 128, "Shape assertions must hold"
    gqa_ratio = num_qo_heads // num_kv_heads  # 4

    # Make inputs contiguous
    q = q.contiguous()
    k_flat = k_cache.squeeze(1).contiguous()  # [num_pages, num_kv_heads, head_dim]
    v_flat = v_cache.squeeze(1).contiguous()  # [num_pages, num_kv_heads, head_dim]

    # Prepare output buffers for this batch in host (lists), we'll allocate device tensors
    out_shape = (total_q, num_qo_heads, head_dim)
    # We allocate device buffers to store per-(q_idx, head) outputs and lse. Use float32 for numerical stability.
    out_chunk = torch.empty(total_q * num_qo_heads * head_dim, dtype=torch.float32, device=q.device)
    lse_chunk = torch.empty(total_q * num_qo_heads, dtype=torch.float32, device=q.device)

    # Launch kernel: one program per b
    grid = (1,)
    _compute_batch_output_kernel[grid](
        q, k_flat, v_flat,
        qo_indptr, kv_indptr, kv_indices,
        out_chunk, lse_chunk,
        sm_scale,
        total_q, num_qo_heads, head_dim, gqa_ratio,
        b, qo_indptr.shape[0],
        num_warps=4, num_stages=2
    )

    # Convert out_chunk to 3D tensor [total_q, num_qo_heads, head_dim]
    # We built out_chunk as a flat buffer; reconstruct
    # Note: out_chunk_ptr + out_idx wrote vectors of length head_dim; we need to separate them by head.
    # Instead, we can directly reconstruct by iterating: out_chunk is dense in q-major, then h-major.
    # The kernel wrote out_chunk[global_q_idx * (num_qo_heads * head_dim) + h * head_dim :] = vector
    # So we can copy into a 3D tensor:
    out_3d = torch.empty(out_shape, dtype=torch.float32, device=q.device)
    # Fill out_3d: for each (q_idx, h), the vector is contiguous in out_chunk starting at out_idx
    # out_idx = q_idx * (num_qo_heads * head_dim) + h * head_dim
    # For simplicity, we copy using the same indexing:
    # For each (q_idx, h), the vector out_vec is out_chunk[q_idx * (num_qo_heads * head_dim) + h].
    # But since out_chunk is flat, we need to reconstruct. Easiest: we will recompute per (q_idx,h) from out_chunk using slicing,
    # but that would re-run computation. Safer approach: the kernel already wrote out_chunk as [q,h]-separate vectors; we can read them back.
    # To do that, we need to know the exact structure: out_chunk[base + offset], base = q_idx * (num_qo_heads * head_dim)
    # So we can populate out_3d by slicing:
    for q_idx in range(total_q):
        base_q = q_idx * (num_qo_heads * head_dim)
        for h in range(num_qo_heads):
            out_vec_flat = out_chunk[base_q + h * head_dim : base_q + (h + 1) * head_dim]
            out_3d[q_idx, h] = out_vec_flat

    # lse_chunk is [total_q * num_qo_heads]; we'll convert to [total_q, num_qo_heads] and add later.
    lse_2d = lse_chunk.view(total_q, num_qo_heads)

    return out_3d, lse_2d

            # Active mask for q: q_idx < num_q_tokens
            q_active = q_idx_vec < num_q_tokens
            # Convert to global q indices

            h = 0

                kv_head = h // gqa_ratio  # GQA mapping: 32 heads -> 8 kv_heads, ratio=4

                # q layout: [total_q, num_qo_heads, head_dim] contiguous

                q_off_vec = global_q_idx_vec * (num_qo_heads * head_dim) + h * head_dim
                q_vec = tl.load(q_ptr + q_off_vec + tl.arange(0, head_dim),

                lse_sum = tl.full((), 0.0, dtype=tl.float32)

                    # Load k_row as vector [head_dim]; masked by active_i
                    k_row = tl.load(k_ptr + k_off + tl.arange(0, head_dim),
                                    mask=active_i, other=0.0)
                    k_row = k_row.to(tl.float32)

                    # Compute dot product q_vec[:, j] @ k_row[j] across j
                    dot_vals = tl.zeros((BLOCK_T,), dtype=tl.float32)

                        k_chunk = k_row[d : d + 16]

                    causal_mask = (q_idx_vec >= (i + 1))  # i == q_idx implies equal to i+1? We need i > q_idx -> q_idx < i
