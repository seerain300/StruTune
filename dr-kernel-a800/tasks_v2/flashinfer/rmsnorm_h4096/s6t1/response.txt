Detailed analysis and optimization plan

What the original code does
- Inputs:
  - hidden_states: shape [batch_size, hidden_size], dtype typically bfloat16, cast to float32 for compute.
  - weight: shape [hidden_size], dtype typically bfloat16, cast to float32 for compute.
- Compute in float32:
  1) Compute row-wise mean of squares: mean = sum(x^2) / hidden_size.
  2) inv_rms = 1 / sqrt(mean + EPS).
  3) Scale: y = x * inv_rms * weight (elementwise multiply, weight broadcast across batch).
  4) Cast back to original dtype (hidden_states.dtype) and return.

Opportunities to optimize
- The original PyTorch sequence uses multiple kernels and creates intermediate tensors (x^2, inv_rms). Even though PyTorch can be efficient, a fused Triton kernel can reduce kernel launches and memory traffic.
- Our initial Triton kernel made two passes over each row:
  - Pass 1: accumulate sum of squares (reads x once).
  - Pass 2: read x again and weight, compute y, and write out.
  This doubles the read of x. For bandwidth-bound operations, cutting reads can significantly improve performance.
- We can redesign the Triton kernel to read each element of x only once, keep it in registers, immediately multiply by weight and inv_rms, and write out. This is possible because inv_rms is a scalar per row and can be computed from the reduction results.
- Implementation detail: Triton doesn’t provide a built-in vector reduction to a scalar across a 1D vector; you need a loop to reduce. So, we will do the first loop over columns to compute the sum of squares (accumulate in float32). Then we compute inv_rms. Then a second loop that recomputes x and weight and writes y. This still improves over the baseline because we avoid materializing x^2 and inv_rms tensors and operate in a single Triton kernel. While we still read x twice, we avoid extra intermediate allocations and PyTorch elementwise kernels, and we keep data in registers for the weight load.

Performance tuning choices
- Grid: one Triton program per row (grid = (batch_size,)). This keeps the kernel simple and scales well for typical batch sizes.
- BLOCK_SIZE: choose 256 for columns. With hidden_size=4096, that’s 16 iterations per row, which is manageable. 256 offers a good balance between parallelism and register usage. We can mask the tail.
- num_warps: set to 8 to improve throughput on modern GPUs for a 256-wide vectorized load/store.
- num_stages: 3 is a reasonable default for pipelining. You can tune 2–4; we’ll start with 3.
- Dtype handling: compute in float32; store in the output dtype (fp32, fp16, bf16) to match original behavior. We’ll pass an out_dtype_code to the kernel to select the cast.

Plan
1) Triton kernel _rms_scale_kernel:
   - One program per row (row_id = tl.program_id(0)).
   - First loop over columns: load x in chunks of BLOCK_SIZE, accumulate sum of squares in a float32 scalar.
   - Compute mean and inv_rms.
   - Second loop over columns: re-load x, load weight, compute y = x * inv_rms * weight (float32), store to out_ptr with appropriate cast (fp32/fp16/bf16) via out_dtype_code.
   - Ensure masking for the last partial block.

2) ModelNew.forward:
   - Ensure inputs are on CUDA and contiguous.
   - Assert hidden_size == 4096 to match original (optional, but helps catch misuse).
   - Cast hidden_states and weight to float32 for compute.
   - Allocate output tensor with same shape and dtype as hidden_states.
   - Launch kernel with grid=(batch_size,), BLOCK_SIZE=256, num_warps=8, num_stages=3.
   - Return output.

3) Optional: You can benchmark different BLOCK_SIZE (128, 256) and num_warps (4, 8). The previous run used 128/4, and achieved ~1.27x. Switching to 256/8 can increase throughput for 4096 columns.

```python
import torch
import triton
import triton.language as tl

# Triton kernel: per-row RMS scaling with weight, optimized to keep computation in one kernel
# and perform minimal tensor allocations. We read x twice (once for reduction, once for output),
# but avoid materializing x^2 or inv_rms tensors and avoid multiple PyTorch elementwise kernels.
@triton.jit
def _rms_scale_kernel(
    hidden_ptr,        # *float32, pointer to hidden_states (cast to float32)
    weight_ptr,        # *float32, pointer to weight (cast to float32)
    out_ptr,           # *T_out, pointer to output (will store casted result)
    batch_size,        # int32
    hidden_size,       # int32
    eps,               # float32
    out_dtype_code: tl.constexpr,  # 0: fp32, 1: fp16, 2: bf16
    BLOCK_SIZE: tl.constexpr        # e.g., 256
):
    row_id = tl.program_id(0)  # one program per row
    if row_id >= batch_size:
        return

    row_base = hidden_ptr + row_id * hidden_size

    # First pass: accumulate sum of squares across columns in chunks
    sumsq = 0.0
    for col_start in range(0, hidden_size, BLOCK_SIZE):
        cols = col_start + tl.arange(0, BLOCK_SIZE)
        mask = cols < hidden_size
        x = tl.load(row_base + cols, mask=mask, other=0.0)  # float32
        sumsq += tl.sum(x * x, axis=0)

    # Compute inv_rms = 1 / sqrt(mean + eps), mean = sumsq / hidden_size
    mean = sumsq / hidden_size
    inv_rms = 1.0 / tl.sqrt(mean + eps)  # float32 scalar

    # Second pass: compute output and store
    for col_start in range(0, hidden_size, BLOCK_SIZE):
        cols = col_start + tl.arange(0, BLOCK_SIZE)
        mask = cols < hidden_size
        x = tl.load(row_base + cols, mask=mask, other=0.0)  # float32
        w = tl.load(weight_ptr + cols, mask=mask, other=0.0)  # float32
        y = x * inv_rms * w  # float32
        # Cast to desired output dtype
        # 0: fp32, 1: fp16, 2: bf16
        if out_dtype_code == 0:
            out_val = y
        elif out_dtype_code == 1:
            out_val = y.to(tl.float16)
        elif out_dtype_code == 2:
            out_val = y.to(tl.bfloat16)
        else:
            out_val = y  # default fp32
        tl.store(out_ptr + row_id * hidden_size + cols, out_val, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, weight):
        # Ensure CUDA tensors and contiguity
        assert hidden_states.is_cuda and weight.is_cuda, "Tensors must be on CUDA for Triton kernel."
        hidden = hidden_states.contiguous()
        w = weight.contiguous()

        # Match original assertion: hidden_size must be 4096
        assert hidden.shape[1] == 4096, "hidden_size must be 4096."

        # Cast to float32 for compute
        x = hidden.to(torch.float32)
        w = w.to(torch.float32)

        batch_size = x.shape[0]
        hidden_size = x.shape[1]

        # Prepare output tensor in original dtype
        out = torch.empty_like(hidden, dtype=hidden.dtype, device=hidden.device)

        # Determine output dtype code for kernel
        if out.dtype == torch.float32:
            out_dtype_code = 0
        elif out.dtype == torch.float16:
            out_dtype_code = 1
        elif out.dtype == torch.bfloat16:
            out_dtype_code = 2
        else:
            # Fallback: store in fp32 if unexpected dtype
            out = torch.empty_like(hidden, dtype=torch.float32, device=hidden.device)
            out_dtype_code = 0

        # Launch Triton kernel: one program per row
        grid = (batch_size,)
        # Tuning parameters: 256-wide blocks, 8 warps, 3 stages
        BLOCK_SIZE = 256
        num_warps = 8
        num_stages = 3

        _rms_scale_kernel[grid](
            x, w, out,
            batch_size, hidden_size,
            1e-5,
            out_dtype_code=out_dtype_code,
            BLOCK_SIZE=BLOCK_SIZE,
            num_warps=num_warps,
            num_stages=num_stages,
        )

        return out
```

import torch
import triton
import triton.language as tl

# Triton kernel: per-row RMS scaling with weight.
# One program per row. We read x twice: once to compute sum of squares, once to write output.
@triton.jit
def _rms_scale_kernel(
    hidden_ptr,        # *float32, pointer to hidden_states (cast to float32)
    weight_ptr,        # *float32, pointer to weight (cast to float32)
    out_ptr,           # *T_out, pointer to output (will store casted result)
    batch_size,        # int32
    hidden_size,       # int32
    eps,               # float32
    out_dtype_code: tl.constexpr,  # 0: fp32, 1: fp16, 2: bf16
    BLOCK_SIZE: tl.constexpr        # e.g., 1024 or 256 or 128
):
    row_id = tl.program_id(0)  # one program per row
    if row_id >= batch_size:
        return

    row_base = hidden_ptr + row_id * hidden_size

    # First pass: accumulate sum of squares across columns in chunks
    sumsq = 0.0
    for col_start in range(0, hidden_size, BLOCK_SIZE):
        cols = col_start + tl.arange(0, BLOCK_SIZE)
        mask = cols < hidden_size
        x = tl.load(row_base + cols, mask=mask, other=0.0)  # float32
        sumsq += tl.sum(x * x, axis=0)

    # Compute inv_rms = 1 / sqrt(mean + eps), mean = sumsq / hidden_size
    mean = sumsq / hidden_size
    inv_rms = 1.0 / tl.sqrt(mean + eps)  # float32 scalar

    # Second pass: compute output and store
    for col_start in range(0, hidden_size, BLOCK_SIZE):
        cols = col_start + tl.arange(0, BLOCK_SIZE)
        mask = cols < hidden_size
        x = tl.load(row_base + cols, mask=mask, other=0.0)  # float32
        w = tl.load(weight_ptr + cols, mask=mask, other=0.0)  # float32
        y = x * inv_rms * w  # float32

        # Cast to desired output dtype
        if out_dtype_code == 0:
            out_val = y
        elif out_dtype_code == 1:
            out_val = y.to(tl.float16)
        elif out_dtype_code == 2:
            out_val = y.to(tl.bfloat16)
        else:
            out_val = y  # default fp32
        tl.store(out_ptr + row_id * hidden_size + cols, out_val, mask=mask)
