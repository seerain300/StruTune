Thank you for the detailed feedback. The previous Triton implementation attempted to load and process one token at a time inside a single program, which is error-prone and not performant. It also had a few issues that could cause compilation/runtime errors and correctness failures:

- Mismatch between tl.load index/vector shape: using tl.load with a scalar pointer plus tl.arange(0, D) requires care; better to use vectorized loads for a block of tokens and reduce over that block to avoid per-token loops.
- Using a scalar loop for tokens can lead to Triton control flow issues, and the previous code assumed K=8, which is fine, but we should ensure robustness and performance.
- Triton kernels prefer vectorized operations and BLOCKed reductions. We can do two-pass lse using block-wise reductions, which is numerically stable and efficient.

Plan to fix and optimize:

1) Keep the Triton kernel simple and robust: one program per (b, h). This ensures we can correctly map tensors and do per-head computation.

2) Remove per-token scalar loops. Instead, process tokens in blocks. For each block:
   - Compute all dot products for that block: dots_block = q_vec @ K_block, where K_block is [BLOCK_T, D], yielding [BLOCK_T] vector of logits for that block.
   - Compute block_max = max(dots_block), sum_exp_block = sum(exp((dots_block - block_max) * sm_scale)).
   - Accumulate global sum_exp += sum_exp_block to compute lse. We will use a stable logsumexp: lse = log(sum_exp) / ln(2).
   - After finishing all blocks, we have lse for this (b, h).

3) Second pass: loop over tokens again in blocks. For each token index in the block, compute dot, compute attn = exp((dot - lse) * sm_scale), and accumulate out_vec += attn * V_row for that token. This ensures we have the correct lse before computing attention weights.

4) Use masked vector loads for token blocks to handle non-multiple-of-block lengths. Dtypes: load as bf16, convert to fp32 for math, store output as bfloat16. sm_scale is fp32.

5) Ensure inputs are contiguous and CUDA, assert expected constants, and return outputs matching the original shape and dtype.

6) Performance: Although the two-pass approach recomputes some dot products, it leverages Triton’s vectorized reductions and avoids Python overhead. With B up to 64, H=32, D=128, K=8, and num_tokens up to tens of thousands, this should be competitive. It also avoids atomics and inter-thread reductions.

def fused_gqa_row_blocks_kernel(
    q_ptr,          # *bf16, [B, H, D]
    k_ptr,          # *bf16, [Np, 1, K, D]
    v_ptr,          # *bf16, [Np, 1, K, D]
    indptr_ptr,     # *int32, [B+1]
    indices_ptr,    # *int32, [num_tokens]
    out_ptr,        # *bf16, [B, H, D]
    lse_ptr,        # *fp32,  [B, H]
    sm_scale,       # fp32
    B: tl.constexpr,  # batch size
    H: tl.constexpr,  # num_qo_heads = 32
    D: tl.constexpr,  # head_dim = 128
    BLOCK_T: tl.constexpr,  # number of tokens per block (e.g., 128 or 256)
):
    pid_b = tl.program_id(0)
    pid_h = tl.program_id(1)

    kv_head = pid_h // (H // 8)  # GQA ratio is 4, so 32//8 = 4
    gqa_ratio = H // 8

    # Load q vector for this (b, h)
    q_offset = pid_b * H * D + pid_h * D
    q_vec = tl.load(q_ptr + q_offset).to(tl.float32)  # [D], fp32

    # Load indptr[start, end]
    start = tl.load(indptr_ptr + pid_b).to(tl.int32)
    end = tl.load(indptr_ptr + pid_b + 1).to(tl.int32)
    num_tokens = end - start

    # Pass 1: compute lse using block-wise max and sum-exp over all tokens
    sum_exp = 0.0
    t = 0
    while t < num_tokens:
        # token indices for this block
        t_offsets = t + tl.arange(0, BLOCK_T)
        mask_t = t_offsets < num_tokens
        idxs = tl.load(indices_ptr + start + t_offsets, mask=mask_t, other=0).to(tl.int32)  # [BLOCK_T]

        # Build K_block [BLOCK_T, D] and compute dots [BLOCK_T]
        K_block = tl.zeros((BLOCK_T, D), dtype=tl.float32)
        for i in range(BLOCK_T):
            # pointer to k row for this token index
            k_row_ptr = k_ptr + idxs[i] * (8 * D) + kv_head * D
            k_row = tl.load(k_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)  # [D]
            K_block[i, :] = k_row

        # dot products: q_vec @ K_block => [BLOCK_T]
        dots_block = tl.sum(q_vec[:, None] * K_block, axis=0)  # [BLOCK_T]
        # block max for numerical stability
        block_max = tl.max(dots_block, axis=0)
        # sum exp after scaling
        sum_exp += tl.sum(tl.exp((dots_block - block_max) * sm_scale), axis=0)

        t += BLOCK_T

    lse_acc = tl.log(sum_exp) * (1.4426950408889634)  # log2(sum_exp) = log(sum_exp) / ln(2)

    # Pass 2: compute output vector out[b, h, :] in fp32, then cast to bf16
    out_vec = tl.zeros((D,), dtype=tl.float32)
    t = 0
    while t < num_tokens:
        t_offsets = t + tl.arange(0, BLOCK_T)
        mask_t = t_offsets < num_tokens
        idxs = tl.load(indices_ptr + start + t_offsets, mask=mask_t, other=0).to(tl.int32)  # [BLOCK_T]

        # For each token in the block, compute attn and accumulate
        for i in range(BLOCK_T):

        t += BLOCK_T

    # Store output as bfloat16

- Avoid any mixing of Python ints with Triton tensors in pointer expressions. Do not write k_ptr + idx * (K * D) + .... Instead, compute base offsets using only Triton tensors.
- Simplify: process tokens in blocks. For each block:
  - Load idxs = kv_indices[start + t_offsets] as a Triton tensor (mask for bounds).
  - For each token i in the block, compute k_row = k_ptr + idxs[i] * (K*D) + kv_head * D, where idxs[i] and (K*D), kv_head* D are Triton tensors. Triton will handle scalar broadcasting of idxs[i] with the pointer type.
  - Compute dot = sum(q_vec * k_row), accumulate to sum_exp using a stable logsumexp.
- After the first pass, we have lse. In the second pass, loop tokens again in blocks, compute dot and attn, and accumulate out_vec += attn * v_row for each token i in the block. This avoids storing huge K-blocks and ensures stable lse.

This two-pass approach remains correct. The compile error should be resolved by avoiding Python-int in pointer arithmetic and keeping all indexing arithmetic in Triton tensors.

):

    pid_h = tl.program_id(1)

    kv_head = pid_h // gqa_ratio  # 0..7

    q_offset = pid_b * H * D + pid_h * D
