- What the original code does
  - It’s a GQA (Grouped Query Attention) forward for a batch of sequences.
  - Inputs:
    - q: [batch_size, num_qo_heads, head_dim] with head_dim=128
    - k_cache, v_cache: [num_pages, 1, num_kv_heads, head_dim], with num_kv_heads=8 and num_qo_heads=32, so GQA ratio is num_qo_heads // num_kv_heads = 4
    - kv_indptr: [batch_size + 1], i.e., per-batch start/end offsets in tokens
    - kv_indices: [num_tokens_total], mapping token index to a cached “page” (an integer within [0, num_pages))
    - sm_scale: scalar for scaling logits
  - For each batch b:
    - Determine the valid token range: start=kv_indptr[b], end=kv_indptr[b+1]
      - num_tokens = end - start (assumes no empty batches in provided inputs)
    - Gather K and V for those tokens based on kv_indices[page_start:page_end]. These are [num_tokens, num_kv_heads, head_dim]
    - For each query head h in 0..num_qo_heads-1:
      - kv_head = h // GQA_RATIO (in this setup GQA_RATIO=4)
      - q_head = q[b, h]  # [head_dim]
      - k_head = K gathered at that kv_head  # [num_tokens, head_dim]
      - v_head = V gathered at that kv_head  # [num_tokens, head_dim]
      - Compute logits = q_head @ k_head.T  → shape [num_tokens]
      - Scale: logits_scaled = logits * sm_scale
      - Compute lse[b, h] = logsumexp(logits_scaled) / log(2), which is equivalent to logsumexp base-2
      - Compute attn = softmax(logits_scaled, dim=0)  → [num_tokens]
      - Output[b, h] = attn @ v_head  → [head_dim], then cast to bfloat16 and store

  - The code asserts constants: num_qo_heads==32, num_kv_heads==8, head_dim==128, and uses a GQA ratio of 4.
  - The PyTorch-only loop is simple but involves Python-level for-loops, repeated matmuls, and reductions. For large batch_size and large num_tokens, this is not optimal and can be optimized.

- Where the time goes
  - For each (b, h), it does:
    - Gather K,V for one kv-head over many tokens
    - Matmul q @ k^T → O(num_tokens * head_dim)
    - Reduction for logsumexp → O(num_tokens)
    - Matmul attn @ v → O(num_tokens * head_dim)
  - It repeats this for all heads. With batch_size potentially large, num_tokens potentially large, and many heads, this is memory-bound and compute-bound depending on the GPU and sizes. The gather from kv_indices introduces strided access into the cache, which isn’t ideal for coalescing, but that’s dictated by the data structure. We can still optimize the math-heavy parts.

- Optimization strategy with Triton
  - Triton is excellent at fusing small kernels, reducing framework overhead, and optimizing simple elementwise/row-wise operations. The core work here per (b,h) is essentially:
    - Compute logits = q[h] · k[t] for all t in [0..num_tokens-1] (dot product of a vector over the token K rows).
    - Reduce logsumexp on logits_scaled over t.
    - Weighted sum: out = sum_t attn[t] * v[t].
  - We can implement a Triton kernel that computes the output for one (b,h) row over all tokens:
    - It will loop over tokens in blocks (BLOCK_T). For each block, load the K row block (k_block) and compute a block of logits. Reduce to find the block max, then loop again to accumulate sum(exp(logits_scaled - block_max)) for that block to get the block’s contribution to lse; then loop again to compute attn and accumulate out = sum(attn * v_block) into a vector accumulator. Finally, store out to output[b, h, :] and write lse[b, h].
    - This structure allows us to do:
      - One kernel per (b,h) (simplest and robust) with a grid size of (batch_size, num_qo_heads). It’s a sequential loop over tokens inside the kernel, which is fine for head_dim=128 and moderate num_tokens. The provided inputs show num_tokens up to tens of thousands; even a loop over tokens per kernel should be acceptable, especially if we choose BLOCK_T = 128 or 256 to vectorize the inner operations.
    - We can specialize the kernel to head_dim=128, which is the asserted constant here. That lets us simplify index math and achieve better codegen. We can use a while loop in Triton to iterate tokens without knowing num_tokens at compile time.

- Considerations
  - Device handling: The original code uses torch.no_grad(). Triton kernels run on CUDA. We should ensure inputs are on CUDA, or provide a CPU fallback. For this task, we can assume CUDA inputs. If not on CUDA, we can fallback to the PyTorch implementation (but the evaluation will supply CUDA tensors).
  - Dtypes: q, k, v are bfloat16 in the provided get_inputs. We’ll load in bfloat16, convert to float32 for math (logsumexp, softmax, matmuls), and write outputs in bfloat16. The scalar sm_scale is float32.
  - Correctness: We must exactly replicate the reference behavior:
    - lse per (b,h) as base-2 logsumexp of logits_scaled
    - softmax over tokens for each query head h
    - Gather K,V per kv-head, not per q-head
    - GQA ratio is 4, so kv_head = h // 4
    - Output shape [batch_size, num_qo_heads, head_dim], bfloat16

- Triton kernel design
  - One kernel handles one (b,h) pair. It reads q[h], lse[b,h], and output[b,h] pointers; then it loops over tokens in chunks of BLOCK_T=128:
    - First pass: compute max block-wise for numerical stability; also compute sum_exp over the block using a second pass. For simplicity, we can do a single pass trick by recomputing logits and summing exp directly (we need the max anyway), or compute max first and then sum. We’ll do:
      - Loop t from 0 to num_tokens, stepping by BLOCK_T:
        - t_offsets = t + arange(BLOCK_T)
        - mask = t_offsets < num_tokens
        - k_block = load k_cache[page indices, kv_head, t_offsets] as bf16 -> fp32
        - logits_block = q_vec @ k_block  (vector over head_dim dot with each k row)
        - block_max = max(logits_block)
        - sum_exp += sum(exp((logits_block - block_max) * sm_scale))
      - After finishing, compute lse_part = log(sum_exp) / ln(2), then update running lse_acc += lse_part. Initialize lse_acc = -inf.
      - Second loop to compute attn and accumulate out:
        - For each t:
          - Compute logits_t = q_vec @ k_t
          - attn_t = exp((logits_t - lse_acc) * sm_scale)
          - out += attn_t * v_t
        - Store out as bfloat16 into output[b,h,:].
      - Write lse_acc / ln(2) to lse[b,h].
  - This approach keeps everything in a single kernel per (b,h) with straightforward math. It avoids atomics and cross-thread reductions. It’s acceptable because head_dim is small (128), and we are doing vectorized computations for each token block.

- Expected performance
  - For the given workloads, batch_size up to 64, num_tokens up to tens of thousands, this Triton kernel will:
    - Reduce Python overhead and separate-kernel launches compared to pure PyTorch formatmul+softmax combinations.
    - Use vectorized inner operations over head_dim.
    - Keep all math in fp32 for stability, cast outputs to bf16 at the end.
  - The gather from kv_indices is still the same pattern (strided), and Triton cannot change that without changing data layout. But optimizing the compute per token with Triton should give clear gains compared to calling torch operations per head.

- Edge cases and robustness
  - Asserts: We keep the same asserts on shapes and constants. The evaluation inputs are generated to match the asserts.
  - If inputs are not CUDA tensors, we fallback to the PyTorch implementation. However, the evaluation harness will provide CUDA tensors, so the Triton path is used.
  - We ensure contiguity: k_cache, v_cache, q are made contiguous where needed. We can rely on the provided tensors being contiguous; if not, we can call .contiguous() before launching the kernel.

```python
import math
import torch

try:
    import triton
    import triton.language as tl
    TRITON_AVAILABLE = True
except Exception:
    TRITON_AVAILABLE = False


# Triton kernel: one program handles one (batch, query-head) pair.
# It loops over all tokens in the batch's segment to compute the output vector for that head.
@triton.jit
def fused_gqa_row_kernel(
    q_ptr,          # *bf16, shape [B, H, D]
    k_ptr,          # *bf16, shape [Np, 1, K, D]
    v_ptr,          # *bf16, shape [Np, 1, K, D]
    indptr_ptr,     # *int32, shape [B+1]
    indices_ptr,    # *int32, shape [num_tokens]
    out_ptr,        # *bf16, shape [B, H, D]
    lse_ptr,        # *fp32,  shape [B, H]
    sm_scale,       # fp32 scalar
    B,              # int
    Np,             # int (num_pages, not used directly but kept for clarity)
    H,              # int (num_qo_heads)
    D,              # int (head_dim)
    K,              # int (num_kv_heads)
    gqa_ratio,      # int (H // K), but we pass H//K explicitly
    BLOCK_T: tl.constexpr,  # token chunk size
):
    # Each program handles one (b, h) pair
    pid_b = tl.program_id(0)
    pid_h = tl.program_id(1)

    # Compute kv_head corresponding to query head h under GQA grouping
    kv_head = pid_h // gqa_ratio  # scalar int

    # Load q vector for this head (assume D == 128)
    # q_ptr layout: [B, H, D] contiguous. Address: q_ptr + pid_b * H * D + pid_h * D
    q_offset = pid_b * H * D + pid_h * D
    q_vec = tl.load(q_ptr + q_offset)  # shape (D,) in fp16; we will convert to fp32
    q_vec = q_vec.to(tl.float32)  # ensure fp32 for math

    # Compute [start, end] for this batch in indptr
    start = tl.load(indptr_ptr + pid_b).to(tl.int32)
    end = tl.load(indptr_ptr + pid_b + 1).to(tl.int32)
    num_tokens = end - start

    # Accumulate logsumexp over tokens
    # We'll do two passes: first to compute max (via block-wise max), then compute sum of exp(logit_scaled - max)
    # and store lse; second pass to compute attn and accumulate output.

    # Prepare accumulators
    lse_acc = -float("inf")  # fp32 scalar

    # First pass: compute sum_exp = sum_t exp((q·k_t - lse_acc) * sm_scale)
    # We'll iterate over tokens in blocks of BLOCK_T.
    # Note: Triton allows Python-level loops; num_tokens is runtime scalar.
    t = 0
    while t < num_tokens:
        t_offsets = t + tl.arange(0, BLOCK_T)
        mask = t_offsets < num_tokens

        # Load token indices for this block
        idxs = tl.load(indices_ptr + t_offsets, mask=mask, other=0).to(tl.int32)

        # For each token in the block, load k row for kv_head and accumulate sum_exp for the block.
        # We'll compute logits per token and update sum_exp. Since BLOCK_T is a vector, we need to iterate t.
        # To do that, we perform a per-token loop within the block. This is acceptable given D=128 and typical sizes.
        # Sum-exp for the block
        block_sum_exp = 0.0
        for t_i in range(BLOCK_T):
            if mask[t_i]:
                idx = idxs[t_i]
                # Compute address for k[idx, kv_head, :] and v[idx, kv_head, :]
                # k_ptr layout: [Np, 1, K, D] => linear index for (idx, kv_head, d) is idx * (1*K*D) + kv_head * D + d
                # Since the second dim is 1, we can use idx * (K * D) + kv_head * D + d
                # We only need the row for this idx and kv_head across D dims.
                k_row_ptr = k_ptr + idx * (K * D) + kv_head * D
                v_row_ptr = v_ptr + idx * (K * D) + kv_head * D

                # Load k_row as vector (D=128)
                k_row = tl.load(k_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0)
                k_row = k_row.to(tl.float32)
                # Load v_row as vector
                v_row = tl.load(v_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0)
                v_row = v_row.to(tl.float32)

                # Compute dot product: q_vec · k_row
                # q_vec: (D,), k_row: (D,) => sum(q * k)
                dot = tl.sum(q_vec * k_row, axis=0)  # scalar fp32
                logits = dot
                # Update block_sum_exp += exp((logits - lse_acc) * sm_scale)
                # Note: we are accumulating the block's contribution regardless of final lse_acc.
                # We will recompute with final lse_acc during the second pass. Here, we compute a local block_max.
                # Instead, we compute per-token contribution in the second pass. For now, we initialize.
                # To compute block_max for this pass, we would need previous t_i's as well. Simpler: do block-wise max in a separate loop.
                # We'll recompute block-wise max by scanning tokens again after computing lse_acc.
                pass
        # Since we can't reuse dot without recompute, we avoid storing per-token dots. We'll instead:
        # Recompute max over tokens in a separate loop after we have lse_acc. For this, we need to store q_vec? Not necessary.
        # To simplify, we will do a second approach: compute max over tokens in a separate loop using a scalar max var.
        # But since we need sum_exp, we compute per-token contributions in the second pass, but that will recompute dots.
        # Therefore, we'll do a safer approach: compute max per token and update block_max. But Triton doesn't allow dynamic global state across loops cleanly here.
        # As a practical workaround: we will recompute per token in the second pass to get attn. This is acceptable for D=128 and moderate N.
        t += BLOCK_T

    # We need lse_acc to compute attn in the second pass. Since we cannot easily pass back to second pass,
    # we'll compute lse_acc by recomputing the max using a scalar running maximum.
    # Let's recompute max using a scalar approach. For simplicity and correctness, we'll recompute the max in a loop.
    max_val = -float("inf")
    t = 0
    while t < num_tokens:
        idx = tl.load(indices_ptr + t).to(tl.int32)
        k_row_ptr = k_ptr + idx * (K * D) + kv_head * D
        k_row = tl.load(k_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)
        dot = tl.sum(q_vec * k_row, axis=0)
        max_val = tl.maximum(max_val, dot)
        t += 1
    # Now compute sum_exp with sm_scale using the same loop:
    sum_exp = 0.0
    t = 0
    while t < num_tokens:
        idx = tl.load(indices_ptr + t).to(tl.int32)
        k_row_ptr = k_ptr + idx * (K * D) + kv_head * D
        k_row = tl.load(k_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)
        dot = tl.sum(q_vec * k_row, axis=0)
        sum_exp += tl.exp((dot - max_val) * sm_scale)
        t += 1
    lse_acc = tl.log(sum_exp) * (1.4426950408889634)  # log2(sum_exp) = log(sum_exp) / ln(2)

    # Second pass: compute output vector by weighted sum of v_rows with softmax(logits_scaled)
    out_vec = tl.zeros((D,), dtype=tl.float32)
    t = 0
    while t < num_tokens:
        idx = tl.load(indices_ptr + t).to(tl.int32)
        k_row_ptr = k_ptr + idx * (K * D) + kv_head * D
        v_row_ptr = v_ptr + idx * (K * D) + kv_head * D

        k_row = tl.load(k_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)
        v_row = tl.load(v_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)

        dot = tl.sum(q_vec * k_row, axis=0)  # scalar
        # attn = softmax((dot - lse_acc) * sm_scale)
        attn = tl.exp((dot - lse_acc) * sm_scale)
        out_vec += attn * v_row
        t += 1

    # Store output
    out_offset = pid_b * H * D + pid_h * D
    tl.store(out_ptr + out_offset, out_vec.to(tl.bfloat16))

    # Store lse (base-2)
    lse_offset = pid_b * H + pid_h
    tl.store(lse_ptr + lse_offset, (lse_acc * 1.4426950408889634))  # lse in base-2


class ModelNew(torch.nn.Module):
    def forward(self, q, k_cache, v_cache, kv_indptr, kv_indices, sm_scale):
        # Ensure CUDA and contiguity
        assert TRITON_AVAILABLE, "Triton is not available"
        device = q.device
        assert device.type == "cuda", "Inputs must be on CUDA device"
        # Shapes
        B, H, D = q.shape
        _, _, K, _ = k_cache.shape
        assert D == 128 and H == 32 and K == 8, "This Triton implementation expects D=128, H=32, K=8"
        assert k_cache.shape[1] == 1 and v_cache.shape[1] == 1, "num_pages dimension must be 1"
        Np = k_cache.shape[0]
        assert kv_indptr.shape[0] == B + 1, "kv_indptr shape must be [B+1]"
        assert kv_indices.shape[0] == (kv_indptr[-1].item() - kv_indptr[0].item()), "kv_indices size must match indptr"

        # Ensure contiguity
        q = q.contiguous()
        k_cache = k_cache.contiguous()
        v_cache = v_cache.contiguous()
        kv_indptr = kv_indptr.contiguous()
        kv_indices = kv_indices.contiguous()

        # Output and lse buffers
        out = torch.empty((B, H, D), dtype=torch.bfloat16, device=device)
        lse = torch.empty((B, H), dtype=torch.float32, device=device)

        # Launch Triton kernel: one program per (b, h)
        grid = (B, H)
        # We pass sm_scale as fp32
        fused_gqa_row_kernel[grid](
            q, k_cache, v_cache, kv_indptr, kv_indices, out, lse, sm_scale,
            B, Np, H, D, K, H // K,
            BLOCK_T=128,
        )
        return out, lse
```

Notes on the kernel and design:
- The kernel operates per (batch, query-head) pair, which matches the original Python loop structure. It avoids inter-thread reductions and complex atomics.
- It uses a two-phase approach:
  - First, compute per-token dot products q·k_t to find the maximum for numerical stability, and accumulate the sum of exp(adjusted logits). Because Triton doesn’t allow returning scalars across loops cleanly, we compute the max in a separate loop and then the sum_exp in another loop. That’s two passes over K. For D=128, this is acceptable and simple.
  - Second, loop again to compute attn = softmax(logit_scaled) per token and accumulate out = sum_t attn_t * v_t. We do this entirely inside the kernel.
- The output is stored as bfloat16, and lse is stored in base-2 logsumexp to match the original run function’s behavior.
- The get_inputs function in the original code produces CUDA tensors by default, so ModelNew.forward will run the Triton kernel. If the inputs were on CPU, you could add a fallback to the original PyTorch run, but the evaluation harness will supply CUDA tensors.

This Triton implementation focuses on the heavy computation per head, fusing the matmul and softmax logic into a single kernel per (b,h), which should outperform the Python-level loop and reduce framework overhead, especially across large batch sizes and many tokens.

```python
import math
import torch

try:
    import triton
    import triton.language as tl
    TRITON_AVAILABLE = True
except Exception:
    TRITON_AVAILABLE = False


@triton.jit
def fused_gqa_row_kernel(
    q_ptr,          # *bf16, [B, H, D]
    k_ptr,          # *bf16, [Np, 1, K, D]
    v_ptr,          # *bf16, [Np, 1, K, D]
    indptr_ptr,     # *int32, [B+1]
    indices_ptr,    # *int32, [num_tokens]
    out_ptr,        # *bf16, [B, H, D]
    lse_ptr,        # *fp32,  [B, H]
    sm_scale,       # fp32
    B: tl.constexpr,  # not used, but kept for signature clarity
    H: tl.constexpr,  # num_qo_heads = 32
    D: tl.constexpr,  # head_dim = 128
    K: tl.constexpr,  # num_kv_heads = 8
    gqa_ratio: tl.constexpr,  # H // K = 4
):
    pid_b = tl.program_id(0)
    pid_h = tl.program_id(1)

    kv_head = pid_h // gqa_ratio  # 0..7

    # Load q vector for this (b, h)
    q_offset = pid_b * H * D + pid_h * D
    q_vec = tl.load(q_ptr + q_offset).to(tl.float32)  # [D], fp32

    # Load indptr[start, end]
    start = tl.load(indptr_ptr + pid_b).to(tl.int32)
    end = tl.load(indptr_ptr + pid_b + 1).to(tl.int32)
    num_tokens = end - start

    # Pass 1: compute max and sum_exp for lse
    max_val = -float("inf")
    sum_exp = 0.0
    t = 0
    while t < num_tokens:
        idx = tl.load(indices_ptr + start + t).to(tl.int32)
        # k row and v row pointers for kv_head
        k_row_ptr = k_ptr + idx * (K * D) + kv_head * D  # [D]
        v_row_ptr = v_ptr + idx * (K * D) + kv_head * D  # [D]

        k_row = tl.load(k_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)
        v_row = tl.load(v_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)

        dot = tl.sum(q_vec * k_row, axis=0)  # scalar fp32
        max_val = tl.maximum(max_val, dot)
        sum_exp += tl.exp((dot - max_val) * sm_scale)
        t += 1

    lse_acc = tl.log(sum_exp) * (1.4426950408889634)  # log2(sum_exp) = log(sum_exp) / ln(2)

    # Pass 2: compute output vector
    out_vec = tl.zeros((D,), dtype=tl.float32)
    t = 0
    while t < num_tokens:
        idx = tl.load(indices_ptr + start + t).to(tl.int32)
        k_row_ptr = k_ptr + idx * (K * D) + kv_head * D
        v_row_ptr = v_ptr + idx * (K * D) + kv_head * D

        k_row = tl.load(k_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)
        v_row = tl.load(v_row_ptr + tl.arange(0, D), mask=tl.arange(0, D) < D, other=0.0).to(tl.float32)

        dot = tl.sum(q_vec * k_row, axis=0)
        attn = tl.exp((dot - lse_acc) * sm_scale)
        out_vec += attn * v_row
        t += 1

    # Store output as bfloat16
    out_offset = pid_b * H * D + pid_h * D
    tl.store(out_ptr + out_offset, out_vec.to(tl.bfloat16))

    # Store lse (base-2)
    lse_offset = pid_b * H + pid_h
    tl.store(lse_ptr + lse_offset, (lse_acc * 1.4426950408889634))

        k_cache = k_cache.contiguous()
        v_cache = v_cache.contiguous()
        kv_indptr = kv_indptr.contiguous()
```
