- The forward method only orchestrates tensor allocations, dtype conversions, and kernel launches; no torch operations are performed on tensors.

Key corrections:
- Correct base pointer arithmetic for:
  - state[b,h] at base = b * (H * V * K) + h * (V * K); then element i,k at offset i * K + k.
  - new_state buffer is [B, H, V, K], so we write to base = b * (H * V * K) + h * (V * K).
  - output is [B, H], so out_ptr + b * H + h.
- Compute output exactly as:
  output[b,h] = scale * sum_i (q_h[i] * sum_k new_state[b,h,i,k]) where new_state[b,h,i,k] = g[h] * state[b,h,i,k] - k[b,h] @ state[b,h] + k[b,h] @ (beta[h] * v[b,h,i] + (1 - beta[h]) * (k[b,h] @ state[b,h])) computed in-kernel and stored.

This keeps all computation in Triton and avoids any torch math in the forward, addressing the “TRITON-ONLY” requirement.

import torch
import triton
import triton.language as tl


@triton.jit
def _compute_g_kernel(a_ptr, dt_bias_ptr, A_log_ptr, g_ptr, H):
    """
    Compute g[h] = exp(-exp(A_log[h]) * softplus(a[0,0,h] + dt_bias[h])) for h in [0..H-1]
    a_ptr: [1, 1, H] flattened to [H]
    dt_bias_ptr: [H]
    A_log_ptr: [H]
    g_ptr: [H]
    """
    h = tl.program_id(0)
    a_val = tl.load(a_ptr + h)
    dt_val = tl.load(dt_bias_ptr + h)
    A_val = tl.load(A_log_ptr + h)
    # softplus(x) = log(1 + exp(x))
    sp = tl.log(1.0 + tl.exp(a_val + dt_val))
    g_val = tl.exp(-tl.exp(A_val) * sp)
    tl.store(g_ptr + h, g_val)


@triton.jit
def _compute_beta_kernel(b_ptr, beta_ptr, H):
    """
    Compute beta[h] = sigmoid(b[0,0,h]) for h in [0..H-1]
    b_ptr: [1, 1, H] flattened to [H]
    beta_ptr: [H]
    """
    h = tl.program_id(0)
    b_val = tl.load(b_ptr + h)
    beta_val = 1.0 / (1.0 + tl.exp(-b_val))
    tl.store(beta_ptr + h, beta_val)
