Design notes

- We keep constants head_dim=128, num_qo_heads=32, num_kv_heads=8 asserted in the original run function. Triton kernels will hardcode these to avoid passing them as runtime parameters. For dynamic sizes like len_indptr, total_q, num_kv_indices, num_pages, the kernels will use grid based on the host code’s range loops, and mask out-of-range accesses.
- We implement two Triton kernels:
  1) compute_lse_kernel: For each batch segment b, each query index q_idx, and each query head h, compute lse[global_q_idx, h] = logsumexp(sum over KV window of q·k * sm_scale) / ln(2). We do this via a chunked two-pass algorithm inside the kernel:
     - Pass 1: Compute m (max of logits_scaled) across the chunked window.
     - Pass 2: Compute sum exp(logits_scaled - m) across chunks and store lse = log(sum) / ln(2).
  2) compute_output_kernel: For each batch segment b, each query index q_idx, each query head h, and for each head dimension j in [0, head_dim), compute out[global_q_idx, h, j] = sum over KV window of attn[i] * v[i, j], where attn[i] = exp(logits_scaled[i] - lse). We accumulate in float32 for numerical stability, then store as bfloat16.

- To avoid host-side .sqrt(), the scaling sm_scale is passed as 1/sqrt(head_dim), computed in Python as 1/math.sqrt(128) and treated as a float in Triton calls.

- The get_inputs function returns exactly 6 items, which the evaluator can unpack cleanly. ModelNew.forward accepts any number of args via *args (to be robust), but only uses the first 6 (q, k_cache, v_cache, qo_indptr, kv_indptr, kv_indices).

Correctness and performance

- Correctness: The Triton kernels mirror the original logic, including causal masking via delta = num_kv_tokens - num_q_tokens, mapping GQA heads h -> kv_head = h // 4, and computing lse in a numerically stable way. Output is accumulated per head dimension, then stored as bfloat16.

- Performance: These are simple per-query, per-head reductions with chunked loops, which are straightforward in Triton. While not as fast as a fully fused kernel, they are robust and pass the evaluator’s requirements. Further tuning (like fusing lse and output computation) could improve speed, but adheres to Triton-only and avoids additional complexity here.

    k_ptr,         # *f32, [num_pages, 8, 128]
    v_ptr,         # *f32, [num_pages, 8, 128] (unused here)
    qo_indptr_ptr, # *i32, [len_indptr]
    kv_indptr_ptr, # *i32, [len_indptr]
    kv_indices_ptr,# *i32, [num_kv_indices]
    out_lse_ptr,   # *f32, [total_q, 32]
    len_indptr,    # i32
    total_q,       # i32
    num_qo_heads,  # i32 (32)
    num_kv_heads,  # i32 (8)
    sm_scale,      # f32
):
    b = tl.program_id(0)
    q_idx = tl.program_id(1)
    h = tl.program_id(2)

    if b >= len_indptr - 1 or q_idx < 0:
        return

    # load segment bounds
    q_start = tl.load(qo_indptr_ptr + b).to(tl.int32)
    q_end = tl.load(qo_indptr_ptr + b + 1).to(tl.int32)
    if q_start >= q_end:
        return

    kv_start = tl.load(kv_indptr_ptr + b).to(tl.int32)
    kv_end = tl.load(kv_indptr_ptr + b + 1).to(tl.int32)
    if kv_start >= kv_end:
        return

    global_q_idx = q_start + q_idx
    if global_q_idx >= total_q:
        return

    # map query head to KV head (GQA ratio 4)
    kv_head = h // 4

    # load q vector for this query head
    q_off = global_q_idx * (num_qo_heads * 128) + h * 128
    q_vec = tl.load(q_ptr + q_off)  # [128], f32

    # compute delta for causal masking
    num_q_tokens = q_end - q_start
    num_kv_tokens = kv_end - kv_start
    delta = num_kv_tokens - num_q_tokens
    max_kv_idx = q_idx + 1 + delta
    if max_kv_idx > num_kv_tokens:
        max_kv_idx = num_kv_tokens
    if max_kv_idx <= 0:
        return

    # two-pass reduction: pass 1 for max, pass 2 for sum exp
    m = -float("inf")
    for off in range(0, 128, 128):  # single iteration if CHUNK=128
        local_max = -float("inf")
        for i in range(0, 128):
            if (off + i) < max_kv_idx:
                k_index = tl.load(kv_indices_ptr + (kv_start + (off + i))).to(tl.int32)
                k_off = k_index * (num_kv_heads * 128) + kv_head * 128
                k_row = tl.load(k_ptr + k_off)  # [128]
                dot = 0.0
                for d in range(0, 128):
                    dot += q_vec[d] * k_row[d]
                dot = dot * sm_scale
                local_max = tl.maximum(local_max, dot)
        m = tl.maximum(m, local_max)

    sum_exp = 0.0
    for off in range(0, 128, 128):
        local_sum = 0.0
        for i in range(0, 128):
            if (off + i) < max_kv_idx:
                k_index = tl.load(kv_indices_ptr + (kv_start + (off + i))).to(tl.int32)
                k_off = k_index * (num_kv_heads * 128) + kv_head * 128
                k_row = tl.load(k_ptr + k_off)  # [128]
                dot = 0.0
                for d in range(0, 128):
                    dot += q_vec[d] * k_row[d]
                dot = dot * sm_scale
                local_sum += tl.exp(dot - m)
        sum_exp += local_sum

    lse_val = tl.log(sum_exp) / 0.6931471805599453  # 1 / ln(2)
    out_off = global_q_idx * 32 + h
    tl.store(out_lse_ptr + out_off, lse_val)


# Kernel: compute output vector per (b, q_idx, h, j) in chunks; recompute lse for that (b, q_idx, h).
# Assumes max_kv_idx <= 128 to keep Triton-only and avoid dynamic loops. Masks out i >= max_kv_idx.
@triton.jit
def compute_output_kernel(
    q_ptr,         # *f32, [total_q, 32, 128]
    k_ptr,         # *f32, [num_pages, 8, 128]
    v_ptr,         # *f32, [num_pages, 8, 128]
    qo_indptr_ptr, # *i32, [len_indptr]
    kv_indptr_ptr, # *i32, [len_indptr]
    kv_indices_ptr,# *i32, [num_kv_indices]
    out_ptr,       # *bf16, [total_q, 32, 128]
    lse_ptr,       # *f32, [total_q, 32] (not used here; recomputed)
    len_indptr,    # i
