  2) For a given batch interval b and query index q_idx, determine num_q_tokens = q_end - q_start and num_kv_tokens = kv_end - kv_start. Compute causal “max_kv_idx” without using continue: max_kv_idx = min(q_idx + 1 + (num_kv_tokens - num_q_tokens), num_kv_tokens). If max_kv_idx <= 0, we will just skip inner computation via if, not continue.
  3) For each head h, map kv_head = h // 4 (since 32/8 = 4).
  4) Loop over t from 0 to KNUM (runtime KNUM determined on host), where KNUM is the number of valid KV rows for this q position and batch, i.e., KNUM = min(max_kv_idx, num_kv_tokens). We will pass KNUM as a tl.constexpr to the Triton kernel so it can use a while loop. This avoids dynamic while loops which Triton doesn’t support.
  5) For each t, gather k_row = k_cache[kv_indices[qo_indptr[b] + t], kv_head, :] and v_row = v_cache[...] into contiguous [128] buffers. Compute q_vec · k_row = logits[t] using a Triton dot kernel with HEAD_DIM as tl.constexpr.
  6) Store logits into a buffer logits_scaled[KNUM], scale by sm_scale, and compute lse = logsumexp(logits_scaled) / ln(2) in Triton using max trick. We will implement logsumexp in Triton (no torch).
  7) Compute softmax = exp(logits_scaled - lse) in Triton (no torch). Then compute output = softmax * v_row (matvec) and store to output[q_start + q_idx, h, :]. We can do this elementwise: for d in 0..HEAD_DIM-1, out[d] += softmax * v_row[d]. We loop over d with tl.constexpr HEAD_DIM.
- This design ensures:
  - We do not use continue, only if and while loops.
  - We avoid Python min/max in Triton by computing max_kv_idx with arithmetic and tl.where is avoided; we use scalar comparisons in if.
  - We do not call any torch operations in forward. We only launch Triton kernels and allocate outputs. Shapes/strides computed on host; tensors made contiguous; we read inputs and write outputs using Triton.
- Limitation: We must pass KNUM and HEAD_DIM as tl.constexpr to Triton kernels, which means the kernels specialize per (b, q_idx, h). That’s acceptable because Triton can compile multiple variants. However, our implementation still needs to be correct for all workloads. Triton cannot loop over runtime KNUM; so we pass KNUM. The attention logic per (b, q_idx, h) is correct and will be computed for each such triplet, covering all query positions and heads.
- For kv_indices range, we compute kv_start = kv_indptr[b], kv_end = kv_indptr[b+1], num_kv_tokens = kv_end - kv_start, max_kv_idx = min(q_idx + 1 + (num_kv_tokens - num_q_tokens), num_kv_tokens), then KNUM = min(max_kv_idx, num_kv_tokens). That implements the original causal logic without using continue.

# Triton kernel: gather q[b, q_idx, h] into q_vec[h, :] (row-major of length HEAD_DIM)
# q_ptr: *f32, shape [BQ, NUM_QO_HEADS, HEAD_DIM], contiguous
# qo_indptr_ptr: *i32, len = len_indptr
# q_vec_ptr: *f32, shape [NUM_QO_HEADS, HEAD_DIM], contiguous
@triton.jit
def _gather_q_vec_kernel(
    q_ptr, qo_indptr_ptr, q_vec_ptr,
    BQ, NUM_QO_HEADS, HEAD_DIM,
    b, q_idx, h,
    stride_q_b, stride_q_h, stride_q_d,
    out_stride_h, out_stride_d,
    size: tl.constexpr,
):
    q_start = tl.load(qo_indptr_ptr + b)
    q_end = tl.load(qo_indptr_ptr + b + 1)
    num_q_tokens = q_end - q_start
    global_q_idx = q_start + q_idx
    if q_idx >= num_q_tokens:
        return
    base = global_q_idx * stride_q_b + h * stride_q_h
    # q_vec[h, :] stored as contiguous vector
    row_start = h * HEAD_DIM
    d = 0
    while d < HEAD_DIM:
        val = tl.load(q_ptr + base + d * stride_q_d)
        tl.store(q_vec_ptr + row_start + d, val)
        d += 1

# Triton kernel: compute dot product q_vec · k_row -> scalar logits[t]
# q_vec_ptr: *f32, shape [NUM_QO_HEADS, HEAD_DIM], but we only use row h: linear offset h*HEAD_DIM
# k_row_ptr: *f32, shape [HEAD_DIM], contiguous
@triton.jit
def _q_k_dot_scalar_kernel(
    q_vec_ptr, k_row_ptr, logits_ptr,
    HEAD_DIM,
    q_vec_stride_h, q_vec_stride_d,
    k_row_stride_d,
    size: tl.constexpr,
):
    # We assume q_vec is laid out as row-major over heads: row h starts at offset h*HEAD_DIM
    # Here we only use row 0 (since per-(b, q_idx, h) attention uses one head at a time).
    sum_val = 0.0
    d = 0
    while d < HEAD_DIM:
        q_val = tl.load(q_vec_ptr + 0 * HEAD_DIM + d * q_vec_stride_d)
        k_val = tl.load(k_row_ptr + d * k_row_stride_d)
        sum_val += q_val * k_val
        d += 1
    tl.store(logits_ptr, sum_val)
