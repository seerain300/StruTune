Fixing the issues and optimization plan

- The previous submission failed with a KeyError on sm_scale because the Triton kernel did not accept the sm_scale argument. I will fix the kernel signatures to include sm_scale and pass it as a runtime float.

- The evaluator also flagged usage of torch.log and .log. To comply with the “Triton-only computation” rule, I will remove any torch math from ModelNew.forward and implement the final normalization (logsumexp) in a Triton kernel as well. This ensures no torch compute is used anywhere.

- Triton compilation robustness: The previous kernels used vectorized tl.arange indexing for multi-dimensional loads. To make Triton reliably compile across the evaluator’s dynamic sizes, I will structure the kernels using scalar loops over head_dim and kv_tokens and perform elementwise loads/stores. This is slower than a full matmul kernel but keeps compilation simple and avoids pointer math pitfalls.

- Performance: Even though this approach is not as fast as a matmul-optimized implementation, it should still be faster than the original Python loop (especially for large batches). The biggest win is removing Python-side per-token loops in the kernel, and doing everything in Triton. Once correctness is established, a future step could optimize with Triton matmul-like kernels and a final normalization kernel, but for now we ensure correctness and Triton-only execution.

What is computed
- Inputs:
  - q: [total_q, num_qo_heads, head_dim], bfloat16.
  - k_cache, v_cache: [num_pages, 1, num_kv_heads, head_dim], bfloat16.
  - qo_indptr, kv_indptr, kv_indices as in the original.
  - sm_scale: float32.

- Fixed constraints from original (treated as constants):
  - num_qo_heads = 32
  - num_kv_heads = 8
  - head_dim = 128
  - gqa_ratio = num_qo_heads // num_kv_heads = 4
  - k_cache, v_cache are “page_size=1” so we flatten to [num_pages, num_kv_heads, head_dim].

- Output:
  - output: [total_q, 32, 128], bfloat16.
  - lse: [total_q, 32], float32 (computed via Triton kernel).

Design of Triton kernels

1) attention_batch_kernel
- Grid: (num_batches,)
- Each program handles one batch element. We loop over tokens in that batch and query heads:
  - For each token t and each query head h:
    - kv_head = h // gqa_ratio
    - Compute num_kv_tokens = kv_end - kv_start (scalar for the batch). Determine max_kv_idx as min(t+1+delta, num_kv_tokens) where delta = num_kv_tokens - t. If max_kv_idx <= 0, skip.
    - q_vec = q_batch[t, :, :]  (float32)
    - k_base = k_batch_ptr with shape [max_kv_idx, num_kv_heads, head_dim]
    - v_base = v_batch_ptr with shape [max_kv_idx, num_kv_heads, head_dim]
    - Initialize acc_vec = 0.0 [128], sum_softmax = 0.0 (float32), lse_vec = -inf [128] (float32).
    - For k_idx in 0..max_kv_idx-1:
      - k_vec = k_base[k_idx, kv_head, :] (float32), v_vec = v_base[k_idx, kv_head, :]
      - dot = sum_{d=0..127} q_vec[h, d] * k_vec[d] scaled by sm_scale (float32)
      - sum_softmax += exp(dot)
      - lse_vec += exp(dot / ln2) * dot  (we'll divide by ln2 in a Triton normalize kernel)
    - Store sum_softmax and lse_vec to device buffers.
- Note: q_batch, k_batch, v_batch are made contiguous float32 on the host side.

2) normalize_logsumexp_kernel
- Grid: (num_batches, 32)
- For each (batch, head):
  - Reads sum_softmax scalar and lse_vec (128) produced by attention_batch_kernel.
  - Computes lse_final = log(sum_softmax) / ln2 + max(lse_vec). Writes to lse output tensor (float32).

This design ensures:
- No torch math in forward except for data movement and dtype conversions.
- No Python-side loops over queries/keys per token; everything is handled in Triton (either scalar-loops over dims or vectorized over head_dim which we implement via explicit loops for robustness).
- The sm_scale argument is declared in kernel signatures and passed at launch, eliminating the KeyError.

Trade-offs
- Performance: This is not the fastest possible GQA implementation (no matmul fusion). However, the original Python code used torch per-token loops as well. The Triton version eliminates Python overhead and should be at least competitive, and it satisfies the “Triton-only” requirement strictly.

    lse_vec_ptr,        # [num_q_tokens, num_qo_heads, head_dim], float32

    sm_scale,           # float32
):

    b_id = tl.program_id(0)

    # We'll loop over each token in this batch and each query head
    for t in range(0, q_num_tokens):

            max_kv_idx = tl.minimum(t + 1 + delta, num_kv_tokens)
            if max_kv_idx <= 0:

                q_vec[d] = q_val

            sum_softmax = tl.zeros((), dtype=tl.float32)
            lse_vec = tl.zeros([HEAD_DIM], dtype=tl.float32) - float("inf")

            # Accumulate logsumexp over keys
            for k in range(0, max_kv_idx):
                k_ptr = k_base_ptr + k * (num_kv_heads * HEAD_DIM) + kv_head * HEAD_DIM

                v_vec = tl.zeros([HEAD_DIM], dtype=tl.float32)
