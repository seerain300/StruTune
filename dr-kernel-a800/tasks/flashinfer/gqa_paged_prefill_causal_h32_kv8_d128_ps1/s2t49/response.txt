Here is a complete Triton-based implementation that defines ModelNew, launches Triton kernels from forward, and performs the core attention computation in Triton without any PyTorch tensor operations. The forward computes:
- output: [total_q, 32, 128] as bfloat16
- lse: [total_q, 32] as float32, using base-2 logsumexp

Plan recap:
- We map Triton program instances over (segment b, query index q_idx, head h). Each kernel computes:
  - q_vec = q[b, h, :]
  - K = max_kv_idx = min(q_idx + 1 + (num_kv_tokens - num_q_tokens), num_kv_tokens)
  - For k in 0..127, we load k_rows from k_cache and v_rows from v_cache per query head mapping (kv_head = h // 4), compute logits q·k_row, accumulate lse (max, sumexp) and output vector out_vec += softmax * v_row.
  - Write out_vec to output[b * num_q_tokens + q_idx, h, :] as bfloat16, write lse to lse[b * num_q_tokens + q_idx, h].
- We avoid torch.matmul, .max, .matmul, .min, torch.logsumexp, torch.softmax in the forward; everything is done in Triton.
- We do not pass any dynamic constexpr; MAX_K is a literal 128 (matching head_dim). We mask out elements k >= max_kv_idx.
