Analysis and plan

- Original behavior:
  - hidden_states: [B, H], H=4096, dtype bfloat16 (from get_inputs).
  - weight: [H], dtype bfloat16.
  - Steps:
    1) x = hidden_states.float()
    2) inv_rms = rsqrt(mean(x^2) + 1e-5) per row
    3) scaled = x * inv_rms
    4) y = scaled * weight.float()
    5) return y.to(hidden_states.dtype)

- Triton strategy:
  - Implement a single Triton kernel that processes one row per program (grid = (B,)).
  - Use vectorized operations with a single pass over the row:
    - Create column offsets offs = tl.arange(0, H) (H is a compile-time constant 4096).
    - Load the row: x = tl.load(hidden_ptr + row * stride_hs + offs, mask=offs<H, other=0.0).
    - Compute sum of squares in FP32: x32 = x.to(tl.float32); x32 = tl.where(mask, x32, 0.0); sumsq = tl.sum(x32 * x32).
    - Compute inv_rms = rsqrt(sumsq / H + EPS).
    - Load weight vector (FP32): w = tl.load(weight_ptr + offs, mask=offs<H, other=0.0).to(tl.float32).
    - Compute y = x32 * inv_rms * w (FP32).
    - Store y to out_ptr + row * stride_out + offs with mask=offs<H.
  - Host forward:
    - Ensure inputs are CUDA and contiguous.
    - Allocate out_fp32 with shape (B, H).
    - Launch Triton kernel with grid=(B,), num_warps=4, num_stages=2.
    - Cast output to hidden_states.dtype before returning.

Final code

```python
import torch
import triton
import triton.language as tl

HIDDEN_SIZE = 4096
EPS = 1e-5

@triton.jit
def normalize_and_scale_row(hidden_ptr, weight_ptr, out_ptr,
                            stride_hs, stride_out):
    # One program per row
    row = tl.program_id(0)
    base_hs = hidden_ptr + row * stride_hs
    base_out = out_ptr + row * stride_out

    # Vectorized column offsets (compile-time constant 4096)
    offs = tl.arange(0, HIDDEN_SIZE)
    mask = offs < HIDDEN_SIZE

    # Load row (masked), cast to float32
    x = tl.load(base_hs + offs, mask=mask, other=0.0)
    x32 = x.to(tl.float32)

    # Ensure masked lanes do not contribute to the sum
    x32 = tl.where(mask, x32, 0.0)

    # Compute sum of squares in FP32
    sumsq = tl.sum(x32 * x32)

    # Compute inverse RMS per row: rsqrt(mean + EPS)
    mean = sumsq / HIDDEN_SIZE
    inv_rms = tl.rsqrt(mean + EPS)

    # Load weight vector (masked), cast to float32
    w = tl.load(weight_ptr + offs, mask=mask, other=0.0).to(tl.float32)

    # Compute output: y = x * inv_rms * w
    y32 = x32 * inv_rms * w

    # Store FP32 output (masked)
    tl.store(base_out + offs, y32, mask=mask)

class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, weight):
        # Ensure CUDA and contiguous
        assert hidden_states.is_cuda and weight.is_cuda, "Inputs must be on CUDA for Triton."
        hidden_states = hidden_states.contiguous()
        weight = weight.contiguous()

        B, H = hidden_states.shape
        assert H == HIDDEN_SIZE, f"Expected hidden size 4096, got {H}"
        assert weight.numel() == H, "Weight must have length equal to hidden size."

        # Allocate output in FP32 for computation
        out = torch.empty((B, H), dtype=torch.float32, device=hidden_states.device)

        # Launch Triton kernel: one program per row
        grid = (B,)
        normalize_and_scale_row[grid](
            hidden_states, weight, out,
            hidden_states.stride(0), out.stride(0),
            num_warps=4, num_stages=2
        )

        # Match original behavior: cast to hidden_states.dtype
        return out.to(hidden_states.dtype)
```

Notes
- The kernel uses vectorized loads/stores with a mask and a compile-time HIDDEN_SIZE to avoid dynamic for-loops and ensure correctness.
- All computation is done inside Triton; ModelNew.forward ensures inputs are CUDA, contiguous, and returns the correctly cast output.
- If you need to support other hidden sizes, you can parameterize H and adjust the kernel accordingly, but for the provided workload H=4096, this specialization is efficient and avoids Triton’s dynamic-loop pitfalls.
