This is memory-bound, requiring two reads and one write per row. Our earlier correct versions used a single Triton program per row with two passes and achieved ~1.7x speedups.

- The new regression likely stems from shape handling and masking:
  - We previously asserted hidden_size == 4096, which is consistent with the provided inputs. The evaluation now includes other shapes (e.g., batch_size varying), and the latest kernel’s masking logic might have caused partial rows or masked values to leak into the accumulation (e.g., sum of squares computed on masked vectors), leading to incorrect inv_rms and hence incorrect outputs. A common pitfall is relying on masked loads without ensuring the accumulator for reductions is properly zeroed before each iteration or inadvertently mixing masked lanes into the reduction. If the reduction isn’t carefully masked, masked lanes can contribute 0 or other unintended values.

- Another potential issue is output dtype handling. Although the math was correct in earlier runs, if we start using broader dtype codes or incorrect casting, it can cause output mismatches. We should keep the output cast explicit and minimal.

Plan to fix correctness
- Keep the fused per-row kernel (two passes: first to compute sum of squares, second to scale and store).
- Remove the hidden_size assertion and robustly handle arbitrary batch sizes. The kernel already uses grid=(batch_size,), so that’s fine. The hidden dimension should match the weight length; we’ll assert hidden_states.shape[1] == weight.shape[0], but we won’t assert a specific value.
- Strengthen masking:
  - In the first pass (sum of squares), ensure we only reduce over valid lanes. We’ll compute acc_sq as a scalar and guard each BLOCK_SIZE chunk with mask to avoid any possibility of masked lanes contributing.
  - In the second pass (write), ensure we only store for valid lanes. We’ll use tl.load with mask and other=0.0 for partial tiles, and tl.store with mask. This avoids any chance of writing out-of-bounds.

Optimization considerations
- The operation is memory-bound; writing intermediates to global memory would only add bandwidth. The two-pass approach is optimal: first pass to compute scalar inv_rms, second pass to scale and store.
- Using BLOCK_SIZE=1024 and 8 warps keeps iterations low (4 for 4096) and provides good occupancy. We won’t over-tune, but we’ll ensure the kernel compiles and runs correctly for arbitrary sizes while keeping performance solid.

```python
import torch
import triton
import triton.language as tl

# Triton kernel: per-row RMS scaling with weight.
# One program per row. Two passes: first to compute sum of squares, second to scale and store.
@triton.jit
def _rms_scale_kernel(
    hidden_ptr,        # *float32, pointer to hidden_states (cast to float32)
    weight_ptr,        # *float32, pointer to weight (cast to float32)
    out_ptr,           # *T_out, pointer to output (will store casted result)
    batch_size,        # int32
    hidden_size,       # int32
    eps,               # float32
    out_dtype_code: tl.constexpr,  # 0: fp32, 1: fp16, 2: bf16
    BLOCK_SIZE: tl.constexpr        # e.g., 1024
):
    row_id = tl.program_id(0)  # one program per row

    # First pass: accumulate sum of squares for this row (scalar in float32)
    acc_sq = 0.0
    for col in range(0, hidden_size, BLOCK_SIZE):
        offs = col + tl.arange(0, BLOCK_SIZE)
        mask = offs < hidden_size
        # Load x for this row; masked lanes get 0.0 so they don't contribute to sum
        x = tl.load(hidden_ptr + row_id * hidden_size + offs, mask=mask, other=0.0)
        # Sum of squares across this chunk (reduction over vector -> scalar)
        chunk_sq = tl.sum(x * x, axis=0)
        acc_sq += chunk_sq

    mean_sq = acc_sq / hidden_size
    inv_rms = 1.0 / tl.sqrt(mean_sq + eps)

    # Second pass: scale and store
    for col in range(0, hidden_size, BLOCK_SIZE):
        offs = col + tl.arange(0, BLOCK_SIZE)
        mask = offs < hidden_size
        # Load x and weight; masked lanes get 0.0
        x = tl.load(hidden_ptr + row_id * hidden_size + offs, mask=mask, other=0.0)
        w = tl.load(weight_ptr + offs, mask=mask, other=0.0)
        y = x * inv_rms * w  # all math in fp32

        # Cast based on out_dtype_code and store
        if out_dtype_code == 0:
            tl.store(out_ptr + row_id * hidden_size + offs, y, mask=mask)
        elif out_dtype_code == 1:
            tl.store(out_ptr + row_id * hidden_size + offs, y.to(tl.float16), mask=mask)
        else:
            tl.store(out_ptr + row_id * hidden_size + offs, y.to(tl.bfloat16), mask=mask)

# Host-side wrapper for ModelNew
class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, weight):
        # Ensure device and contiguity
        assert hidden_states.is_cuda and weight.is_cuda, "Inputs must be on CUDA tensors for Triton."
        hidden = hidden_states.contiguous()
        w = weight.contiguous()

        batch_size, hidden_size = hidden.shape
        assert w.shape[0] == hidden_size, "weight must have the same length as the last dimension of hidden_states"

        # Compute in float32 for stability
        hidden_f32 = hidden.to(torch.float32)
        w_f32 = w.to(torch.float32)

        # Allocate output in the original dtype
        out = torch.empty_like(hidden)

        # Determine dtype code for casting at store
        out_dtype_code = 0
        if hidden.dtype == torch.float16:
            out_dtype_code = 1
        elif hidden.dtype == torch.bfloat16:
            out_dtype_code = 2
        # default to fp32 if none of the above
        # BLOCK_SIZE tuned for hidden_size around 4096; for other sizes, mask handles tails.
        BLOCK_SIZE = 1024
        grid = (batch_size,)

        _rms_scale_kernel[grid](
            hidden_f32, w_f32, out,
            batch_size, hidden_size, 1e-5,
            out_dtype_code=out_dtype_code,
            BLOCK_SIZE=BLOCK_SIZE,
            num_warps=8, num_stages=3
        )
        return out
```
