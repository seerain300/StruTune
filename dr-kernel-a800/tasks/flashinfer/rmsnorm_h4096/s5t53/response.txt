Root cause analysis
- The previous “KeyError: 'Keyword argument BLOCK_SIZE was specified but unrecognised'” occurs because the Triton kernel signature didn’t declare BLOCK_SIZE as a tl.constexpr, and the launcher passed BLOCK_SIZE=4096 as a meta-parameter. Triton requires that any meta-parameter used in tl.arange or as tl.constexpr be declared in the kernel signature.
- The compilation errors around “tl.sum(x * x, axis=0)” indicate that the kernel relied on non-constexpr vectorization and masking. With H=4096, we can use a single vectorized pass if we set BLOCK_SIZE to H as a constexpr and use offs = tl.arange(0, BLOCK_SIZE). Since we ensure H == BLOCK_SIZE, mask can be all True; Triton still requires mask to be a boolean vector, but with equality, it’s unnecessary, yet keeping it avoids edge issues.

Plan
- Implement a Triton kernel normalize_scale_row that processes one row per program (grid = (B,)).
- Use BLOCK_SIZE: tl.constexpr with BLOCK_SIZE = 4096, so tl.arange(0, BLOCK_SIZE) is valid.
- Steps inside the kernel:
  1) Load the entire row from hidden_ptr, cast to float32.
  2) Compute sumsq = tl.sum(x32 * x32) across the vector (scalar).
  3) Compute inv_rms = rsqrt(sumsq / H + EPS).
  4) Load weight vector from weight_ptr (cast to float32), broadcast inv_rms, compute y32 = x32 * inv_rms * w32, and store to out_ptr.
- Host code:
  - Ensure inputs are on CUDA and contiguous.

  - Return out_fp32 cast to hidden_states.dtype to match original behavior.

Final code

```python
import torch
import triton
import triton.language as tl

HIDDEN_SIZE = 4096
EPS = 1e-5

@triton.jit
def normalize_scale_row(hidden_ptr, weight_ptr, out_ptr,
                        B, H, stride_hs, stride_out,
                        BLOCK_SIZE: tl.constexpr):
    # One program per row
    row = tl.program_id(0)

    # Vector of column offsets (constexpr)
    offs = tl.arange(0, BLOCK_SIZE)
    mask = offs < H  # H == BLOCK_SIZE, but keep mask for safety

    # Base pointers for this row
    hidden_row_ptr = hidden_ptr + row * stride_hs
    out_row_ptr = out_ptr + row * stride_out

    # Load the entire row (hidden_states), cast to float32
    x = tl.load(hidden_row_ptr + offs, mask=mask, other=0.0).to(tl.float32)

    # Compute sum of squares across the row (scalar)
    sumsq = tl.sum(x * x, axis=0)
    mean_sq = sumsq / H
    inv_rms = tl.rsqrt(mean_sq + EPS)

    # Load weight vector, cast to float32
    w = tl.load(weight_ptr + offs, mask=mask, other=0.0).to(tl.float32)

    # Compute scaled output
    y32 = x * inv_rms * w

    # Store result (float32; host will cast to desired dtype)
    tl.store(out_row_ptr + offs, y32, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, hidden_states: torch.Tensor, weight: torch.Tensor) -> torch.Tensor:
        # Ensure inputs are on CUDA and contiguous
        assert hidden_states.is_cuda and weight.is_cuda, "Inputs must be on CUDA device."
        hidden = hidden_states.contiguous()
        weight = weight.contiguous()

        B, H = hidden.shape
        assert H == HIDDEN_SIZE, "hidden_states must have 4096 columns."

        # Allocate output as float32 for computation precision
        out = torch.empty((B, H), device=hidden.device, dtype=torch.float32)

        # Launch Triton kernel: one program per row
        grid = (B,)
        normalize_scale_row[grid](
            hidden, weight, out,
            B, H, hidden.stride(0), out.stride(0),
            BLOCK_SIZE=HIDDEN_SIZE,
            num_warps=8,  # good occupancy for 4096-wide vector
            num_stages=1
        )

        # Match original behavior: return in original hidden_states dtype
        return out.to(hidden_states.dtype)
```
