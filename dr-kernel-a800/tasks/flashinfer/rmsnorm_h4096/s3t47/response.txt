Observations and analysis
- Original computation:
  - inv_rms[i] = 1 / sqrt(mean_j(x[i, j]^2) + EPS), per row.
  - y[i, j] = x[i, j] * inv_rms[i] * weight[j].
- Previous fused Triton kernel did two passes over the row: one to compute sum of squares and another to produce outputs. This is good but we can do better for the common case H=4096.

Optimization strategy
- Introduce a “fullrow” specialized Triton kernel that:
  - Loads the entire row x[row, :] into a BLOCK_SIZE vector (BLOCK_SIZE=4096) in one shot.
  - Computes sum of squares, then inv_rms, then immediately computes y = x * inv * w for the entire row and stores it.
  - This is a single pass: load x, compute, load w, compute, store. It avoids the second read of x entirely.
- Keep a general “tiled” Triton kernel for arbitrary H that handles rows in tiles and uses two passes (sum then output) to maintain correctness and generality.
- In forward, if H <= 4096 and H is a multiple of a reasonable block size (4096), use the fullrow kernel; otherwise use the tiled kernel.

Why this improves performance
- For H=4096 (all test cases), each row fits into one vector of size 4096. The fullrow kernel:
  - Reads x once, computes sumsq and inv_rms, computes y, and writes output — all in one kernel. It eliminates the second read of x and the intermediate per-row data handling.
- This reduces memory traffic and kernel work, which should further increase speed while preserving exact correctness.

Implementation details
- Triton kernels:
  - fullrow_scale_kernel: one program per row, BLOCK_SIZE=4096, num_warps=8, num_stages=2.
  - tiled_scale_kernel: one program per row, iterate over columns in tiles (BLOCK_SIZE=256), two-pass logic (sum then output), num_warps=4, num_stages=2.
- Forward:
  - Ensure inputs are float32, contiguous, on CUDA.
  - Allocate output as float32 [B, H].
  - Choose kernel: if H <= 4096 and divisible by 4096, use fullrow; else use tiled.
  - Launch chosen kernel with grid=(B,).
  - Return output cast to hidden_states.dtype.

import torch

try:
    import triton
    import triton.language as tl
    TRITON_AVAILABLE = True
except Exception:
    TRITON_AVAILABLE = False


# Full-row fused kernel: assumes H <= BLOCK_SIZE and BLOCK_SIZE is a multiple of 128 for good perf.
# One program per row. Loads entire row x[row, :], computes sumsq, inv_rms, then y = x * inv * w, and stores.
@triton.jit
def fullrow_scale_kernel(x_ptr, w_ptr, out_ptr,
                          B, H,
                          EPS: tl.constexpr,
                          BLOCK_SIZE: tl.constexpr):
    row_id = tl.program_id(0)
    # Row base pointers
    x_row = x_ptr + row_id * H
    out_row = out_ptr + row_id * H

    # Vector of column offsets
    offs = tl.arange(0, BLOCK_SIZE)
    mask = offs < H

    # Load row and weight vector
    x = tl.load(x_row + offs, mask=mask, other=0.0)
    w = tl.load(w_ptr + offs, mask=mask, other=0.0)

    # Compute sum of squares for this row
    x2 = x * x
    sumsq = tl.sum(x2, axis=0)

    # Compute inv_rms = 1 / sqrt(mean + EPS)
    mean = sumsq / H
    inv = 1.0 / tl.sqrt(mean + EPS)

    # Scale and store
    y = x * inv * w
    tl.store(out_row + offs, y, mask=mask)


# General tiled kernel: works for any H. Two-pass approach (sum then output).
@triton.jit
def tiled_scale_kernel(x_ptr, w_ptr, out_ptr,
                        B, H,
                        EPS: tl.constexpr,
                        BLOCK_SIZE: tl.constexpr):
    row_id = tl.program_id(0)
    x_row = x_ptr + row_id * H
    out_row = out_ptr + row_id * H

    # Pass 1: compute sum of squares per row
    sumsq = 0.0
    for col_start in range(0, H, BLOCK_SIZE):
        offs = col_start + tl.arange(0, BLOCK_SIZE)
        mask = offs < H
        x = tl.load(x_row + offs, mask=mask, other=0.0)
        x2 = x * x
        sumsq += tl.sum(x2, axis=0)

    # Compute inv_rms
    mean = sumsq / H
    inv = 1.0 / tl.sqrt(mean + EPS)

    # Pass 2: compute y = x * inv * w and store
    for col_start in range(0, H, BLOCK_SIZE):
        offs = col_start + tl.arange(0, BLOCK_SIZE)
        mask = offs < H
        x = tl.load(x_row + offs, mask=mask, other=0.0)
        w = tl.load(w_ptr + offs, mask=mask, other=0.0)
        y = x * inv * w
        tl.store(out_row + offs, y, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, hidden_states: torch.Tensor, weight: torch.Tensor):
        # Ensure CUDA and float32 for computation
        device = hidden_states.device
        B, H = hidden_states.shape
        assert weight.shape == (H,), f"weight must have shape [{H}], got {tuple(weight.shape)}"
        # Cast inputs to float32 for numerical stability; keep original dtype for final output
        hidden_f32 = hidden_states.to(torch.float32).contiguous()
        weight_f32 = weight.to(torch.float32).contiguous()

        # Allocate output tensor in float32
        out = torch.empty((B, H), dtype=torch.float32, device=device)

        # Choose kernel: fullrow for H <= 4096 and divisible by 4096, else tiled
        use_fullrow = (H <= 4096) and (H % 4096 == 0)

        if use_fullrow:
            grid = (B,)
            fullrow_scale_kernel[grid](
                hidden_f32, weight_f32, out,
                B, H,
                EPS=1e-5,
                BLOCK_SIZE=4096,
                num_warps=8,  # more warps for 4096-wide vector
                num_stages=2,
            )
        else:
            grid = (B,)
            tiled_scale_kernel[grid](
                hidden_f32, weight_f32, out,
                B, H,
                EPS=1e-5,
                BLOCK_SIZE=256,
                num_warps=4,
                num_stages=2,
            )

        # Cast back to original hidden_states dtype before returning
        out = out.to(hidden_states.dtype)
        return out
