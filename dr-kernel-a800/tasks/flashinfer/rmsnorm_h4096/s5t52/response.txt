Root causes and fixes
- KeyError: 'Keyword argument BLOCK_SIZE was specified but unrecognised’:
  - The Triton kernel signature must declare BLOCK_SIZE as a tl.constexpr meta-parameter. The launcher passes BLOCK_SIZE=4096, and Triton requires it to be in the signature as BLOCK_SIZE: tl.constexpr. This was missing in prior submissions, causing the KeyError.
- Triton compilation errors:
  - Using tl.arange with non-constexpr or mismatched arguments leads to compilation errors. We must use offs = tl.arange(0, BLOCK_SIZE) with BLOCK_SIZE: tl.constexpr, and ensure H == BLOCK_SIZE so mask is trivially all True and safe.
  - Avoid dynamic while/for loops. Use a single vectorized pass for the entire row.
  - Ensure masking and types are consistent. Casting should be done on the loaded tensor, and reduction should be performed over the vector.

Optimization strategy
- One Triton kernel that processes one row per program (grid = (B,)).
- Single vectorized pass for H=4096:
  - offs = tl.arange(0, BLOCK_SIZE) with BLOCK_SIZE=4096.
  - Load the row from hidden_ptr, cast to float32.
  - Compute sumsq = sum(x^2) for normalization.
  - Compute inv_rms = rsqrt(sumsq/H + EPS).
  - Load weight vector, cast to float32.
  - Compute y = x * inv_rms * w and store to out_ptr.
- Host forward:
  - Ensure inputs are CUDA and contiguous.
  - Allocate out_fp32 with shape (B, H).
  - Launch Triton kernel with grid=(B,) and meta-parameter BLOCK_SIZE=4096.
  - Return out_fp32 cast to hidden_states.dtype to match original behavior.

Final code

```python
import torch
import triton
import triton.language as tl

HIDDEN_SIZE = 4096
EPS = 1e-5

@triton.jit
def normalize_scale_row(hidden_ptr, weight_ptr, out_ptr,
                        B, H, stride_hs, stride_out,
                        BLOCK_SIZE: tl.constexpr):
    # One program per row
    row = tl.program_id(0)

    # Vector of column offsets (constexpr for Triton)
    offs = tl.arange(0, BLOCK_SIZE)
    mask = offs < H  # H == BLOCK_SIZE, so all lanes are valid; mask kept for safety

    # Base pointers for this row
    hidden_row_ptr = hidden_ptr + row * stride_hs
    out_row_ptr = out_ptr + row * stride_out

    # Load the entire row (hidden_states), cast to float32
    x = tl.load(hidden_row_ptr + offs, mask=mask, other=0.0)
    x = x.to(tl.float32)

    # Compute sum of squares across the row
    sumsq = tl.sum(x * x, axis=0)           # scalar
    mean_sq = sumsq / H                      # scalar
    inv_rms = tl.rsqrt(mean_sq + EPS)       # scalar

    # Load weight vector, cast to float32
    w = tl.load(weight_ptr + offs, mask=mask, other=0.0)
    w = w.to(tl.float32)

    # Compute output: y = x * inv_rms * w
    y = x * inv_rms * w

    # Store output (float32)
    tl.store(out_row_ptr + offs, y, mask=mask)

class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, weight):
        # Ensure CUDA and contiguous
        assert hidden_states.is_cuda and weight.is_cuda, "Inputs must be CUDA tensors."
        hidden = hidden_states.contiguous()
        weight = weight.contiguous()

        B, H = hidden.shape
        assert H == HIDDEN_SIZE, f"Expected hidden_size == {HIDDEN_SIZE}, got {H}"

        # Output buffer in float32 for computation stability
        out = torch.empty((B, H), device=hidden.device, dtype=torch.float32)

        # Launch Triton kernel: one program per row, BLOCK_SIZE=H
        grid = (B,)
        normalize_scale_row[grid](
            hidden, weight, out,
            B, H, hidden.stride(0), out.stride(0),
            BLOCK_SIZE=HIDDEN_SIZE,
            num_warps=8,  # good occupancy for a 4096-wide vector
            num_stages=1
        )

        # Cast back to the original hidden_states dtype to match original behavior
        return out.to(hidden_states.dtype)
```

Notes
- The kernel signature now includes BLOCK_SIZE: tl.constexpr, resolving the “unrecognised” keyword error.
- The kernel uses a single vectorized pass and performs both normalization and scaling in one launch, minimizing memory traffic.
- We preserve the original behavior by returning the output cast to hidden_states.dtype. The computation is done in float32 for numerical stability, as in the original code.
