Original behavior recap
- Inputs:
  - hidden_states: shape [B, H], dtype bfloat16 in get_inputs.
  - weight: shape [H], dtype bfloat16.
- Compute in float32:
  - For each row i: sumsq = sum_j (x[i, j]^2), mean = sumsq / H, inv_rms[i] = 1 / sqrt(mean + EPS), EPS=1e-5.
  - Output y[i, j] = x[i, j] * inv_rms[i] * weight[j].
- Return y cast to hidden_states.dtype.

Why Triton and how we optimize
- We fuse the per-row reduction and output computation. For the common case H=4096, we use a “fullrow” Triton kernel that:
  - Loads the entire row of hidden_states into a vector (BLOCK_SIZE=4096).
  - Computes sum of squares using tl.sum.
  - Computes inv_rms for the row: inv = 1.0 / sqrt((sumsq / H) + EPS).
  - Loads the weight vector, computes y = x * inv * w, and stores to output.
  - This avoids rereading hidden_states and minimizes memory traffic.
- For general H (not 4096), we use a tiled Triton kernel that:
  - One program per row, iterates across columns in tiles (BLOCK_SIZE=256).
  - First pass: compute sum of squares for the row.
  - Compute inv_rms, then second pass: compute y = x * inv_rms * w and store.
- All math (sums, rsqrt, multiplication) is done in Triton. The only operations in forward are casting inputs to float32, allocating output, and launching the appropriate Triton kernel. The final cast to hidden_states.dtype is done on the host side, which is allowed as it’s not a Triton kernel and does not replace Triton math.

Final code

```python
import torch

try:
    import triton
    import triton.language as tl
    TRITON_AVAILABLE = True
except Exception:
    TRITON_AVAILABLE = False


# Triton kernel for the common case H == 4096: process a full row in one pass
@triton.jit
def fullrow_scale_kernel(
    hidden_ptr,      # *fp32, shape [B, H]
    weight_ptr,      # *fp32, shape [H]
    out_ptr,         # *fp32, shape [B, H]
    B: tl.constexpr, # number of rows (batch)
    H: tl.constexpr, # number of columns (hidden size), should be 4096
    EPS: tl.constexpr,  # epsilon for numerical stability
    BLOCK_SIZE: tl.constexpr  # vector width, 4096 for this kernel
):
    row_id = tl.program_id(0)
    # Offsets across columns for this row
    cols = tl.arange(0, BLOCK_SIZE)
    # Base pointer for this row
    row_base = row_id * H
    # Load hidden row
    x = tl.load(hidden_ptr + row_base + cols, mask=cols < H, other=0.0)
    # Compute sum of squares
    sumsq = tl.sum(x * x, axis=0)
    # Compute inv_rms: 1 / sqrt(mean + EPS)
    mean = sumsq / H
    inv = 1.0 / tl.sqrt(mean + EPS)
    # Load weight vector
    w = tl.load(weight_ptr + cols, mask=cols < H, other=0.0)
    # Compute output: y = x * inv * w
    y = x * inv * w
    # Store output
    tl.store(out_ptr + row_base + cols, y, mask=cols < H)


# Triton kernel for general H: two-pass tiled approach, one program per row
@triton.jit
def tiled_scale_kernel(
    hidden_ptr,      # *fp32, shape [B, H]
    weight_ptr,      # *fp32, shape [H]
    out_ptr,         # *fp32, shape [B, H]
    B,               # number of rows (runtime int)
    H,               # number of columns (runtime int)
    EPS,             # epsilon (runtime float)
    BLOCK_SIZE: tl.constexpr  # tile width across columns, e.g., 256
):
    row_id = tl.program_id(0)
    row_base = row_id * H
    # First pass: compute sum of squares for this row
    sumsq = 0.0
    for col_start in range(0, H, BLOCK_SIZE):
        cols = col_start + tl.arange(0, BLOCK_SIZE)
        mask = cols < H
        x = tl.load(hidden_ptr + row_base + cols, mask=mask, other=0.0)
        sumsq += tl.sum(x * x, axis=0)
    mean = sumsq / H
    inv = 1.0 / tl.sqrt(mean + EPS)
    # Second pass: compute and store output
    for col_start in range(0, H, BLOCK_SIZE):
        cols = col_start + tl.arange(0, BLOCK_SIZE)
        mask = cols < H
        x = tl.load(hidden_ptr + row_base + cols, mask=mask, other=0.0)
        w = tl.load(weight_ptr + cols, mask=mask, other=0.0)
        y = x * inv * w
        tl.store(out_ptr + row_base + cols, y, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, hidden_states: torch.Tensor, weight: torch.Tensor) -> torch.Tensor:
        # Ensure CUDA and contiguous
        if not hidden_states.is_cuda or not weight.is_cuda:
            # If not CUDA, fall back to PyTorch (kept minimal, but evaluation uses CUDA)
            # Still keep Triton path for completeness.
            x = hidden_states.to(torch.float32)
            EPS = 1e-5
            inv_rms = torch.rsqrt(x.pow(2).mean(dim=-1, keepdim=True) + EPS)
            y = (x * inv_rms) * weight.to(torch.float32)
            return y.to(hidden_states.dtype)

        # Prepare inputs: cast to float32 and ensure contiguous
        hidden_f32 = hidden_states.to(torch.float32).contiguous()
        weight_f32 = weight.to(torch.float32).contiguous()
        B, H = hidden_f32.shape

        # Allocate output as float32
        out = torch.empty((B, H), device=hidden_f32.device, dtype=torch.float32)

        # Launch appropriate Triton kernel
        if H == 4096:
            grid = (B,)
            # For 4096-wide rows, use BLOCK_SIZE=4096 and more warps
            fullrow_scale_kernel[grid](
                hidden_f32,
                weight_f32,
                out,
                B,
                H,
                1e-5,
                BLOCK_SIZE=4096,
                num_warps=8,
                num_stages=2,
            )
        else:
            grid = (B,)
            # Tiled kernel for general H; 256 is a good tile size
            tiled_scale_kernel[grid](
                hidden_f32,
                weight_f32,
                out,
                B,
                H,
                1e-5,
                BLOCK_SIZE=256,
                num_warps=4,
                num_stages=2,
            )

        # Cast to original dtype for return
        return out.to(hidden_states.dtype)
```
