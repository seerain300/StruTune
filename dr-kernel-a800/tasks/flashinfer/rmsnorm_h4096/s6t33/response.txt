Thanks for the latest results. We’re consistently correct and seeing good speedups. Since the operation is memory-bound (each row must be read twice and written once), the best approach is to keep a single fused Triton kernel with one program per row and two passes. The remaining gains come from tuning tile sizes and execution parameters.

Recap
- Per row:
  - Compute inv_rms = 1 / sqrt(mean(x^2) + eps), with mean over the 4096 elements.
  - Output y = (x * inv_rms) * weight.
- Memory traffic is unavoidable: two reads per row and one write. Writing intermediates would only add bandwidth.

Plan
- Keep a single Triton kernel with one program per row, two passes:
  - First pass: accumulate sum of squares to derive inv_rms.
  - Second pass: re-read x, multiply by inv_rms and weight, and store output.
- Autotune:
  - Provide multiple configurations with different BLOCK_SIZE, num_warps, and num_stages. Triton’s autotune will pick the best-performing configuration for hidden_size=4096. This can squeeze out extra throughput across different GPUs.
  - Candidate configurations:
    - BLOCK_SIZE=1024, num_warps=8, num_stages=3
    - BLOCK_SIZE=2048, num_warps=8, num_stages=4
    - BLOCK_SIZE=4096, num_warps=8, num_stages=4
    - BLOCK_SIZE=2048, num_warps=4, num_stages=3
    - BLOCK_SIZE=512,  num_warps=4, num_stages=3
- Compute precision: Do math in float32 inside the kernel and cast at store to match the original behavior (fp32/fp16/bf16). Masked loads/stores ensure correctness for any size; we assert hidden_size == 4096 in ModelNew.

Final code

```python
import torch
import triton
import triton.language as tl

# Triton kernel: per-row RMS scaling with weight.
# One program per row. We read x twice: once to compute sum of squares, once to write output.
@triton.autotune(
    configs=[
        triton.Config({"BLOCK_SIZE": 1024}, num_warps=8, num_stages=3),
        triton.Config({"BLOCK_SIZE": 2048}, num_warps=8, num_stages=4),
        triton.Config({"BLOCK_SIZE": 4096}, num_warps=8, num_stages=4),
        triton.Config({"BLOCK_SIZE": 2048}, num_warps=4, num_stages=3),
        triton.Config({"BLOCK_SIZE": 512},  num_warps=4, num_stages=3),
    ],
    key=["hidden_size"],
)
@triton.jit
def _rms_scale_kernel(
    hidden_ptr,        # *float32, pointer to hidden_states (cast to float32)
    weight_ptr,        # *float32, pointer to weight (cast to float32)
    out_ptr,           # *T_out, pointer to output (will store casted result)
    batch_size,        # int32
    hidden_size,       # int32
    eps,               # float32
    out_dtype_code: tl.constexpr,  # 0: fp32, 1: fp16, 2: bf16
    BLOCK_SIZE: tl.constexpr        # e.g., 1024
):
    row_id = tl.program_id(0)  # one program per row

    # First pass: accumulate sum of squares over the row.
    sum_sq = 0.0
    num_tiles = (hidden_size + BLOCK_SIZE - 1) // BLOCK_SIZE
    for tile in range(0, num_tiles):
        offs = tile * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
        mask = offs < hidden_size
        x = tl.load(hidden_ptr + row_id * hidden_size + offs, mask=mask, other=0.0)
        sum_sq += tl.sum(x * x)

    # Compute inv_rms = 1 / sqrt(mean(x^2) + eps) where mean = sum_sq / hidden_size
    mean = sum_sq / hidden_size
    inv_rms = 1.0 / tl.sqrt(mean + eps)

    # Second pass: scale and write output
    for tile in range(0, num_tiles):
        offs = tile * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
        mask = offs < hidden_size
        x = tl.load(hidden_ptr + row_id * hidden_size + offs, mask=mask, other=0.0)
        w = tl.load(weight_ptr + offs, mask=mask, other=0.0)
        y = x * inv_rms * w

        # Cast to desired output dtype before store
        if out_dtype_code == 0:
            y_cast = y
        elif out_dtype_code == 1:
            y_cast = tl.cast(y, tl.float16)
        else:
            y_cast = tl.cast(y, tl.bfloat16)

        tl.store(out_ptr + row_id * hidden_size + offs, y_cast, mask=mask)

class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, weight):
        # Ensure inputs are on CUDA and contiguous
        assert hidden_states.is_cuda and weight.is_cuda, "Inputs must be CUDA tensors"
        hidden = hidden_states.contiguous()
        wt = weight.contiguous()

        # Cast to float32 for compute; keep original dtype for output casting
        hidden_f32 = hidden.to(torch.float32)
        wt_f32 = wt.to(torch.float32)

        batch_size = hidden_f32.shape[0]
        hidden_size = hidden_f32.shape[1]
        assert hidden_size == 4096, "This implementation assumes hidden_size == 4096"

        # Output tensor in the same dtype as input hidden_states
        out = torch.empty_like(hidden, dtype=hidden.dtype)

        # Determine output dtype code for kernel (0: fp32, 1: fp16, 2: bf16)
        out_dtype_code = 0
        if hidden.dtype == torch.float16:
            out_dtype_code = 1
        elif hidden.dtype == torch.bfloat16:
            out_dtype_code = 2
        else:
            out_dtype_code = 0  # default fp32

        # Launch Triton kernel: one program per row
        grid = (batch_size,)
        _rms_scale_kernel[grid](
            hidden_f32, wt_f32, out, batch_size, hidden_size, 1e-5,
            out_dtype_code=out_dtype_code,
        )
        return out
```

Notes
- All computation is done inside Triton kernels. No PyTorch tensor methods (.rsqrt, .mean, .pow, etc.) are used on device tensors in host code.
- The kernel performs two passes per row: first to compute inv_rms and second to scale and write. This minimizes global memory writes (one per element) while ensuring correctness.
- Autotune provides multiple configurations for BLOCK_SIZE, num_warps, and num_stages, letting Triton pick the best-performing setup for hidden_size=4096 on the target GPU.

数学描述
- 对于每一行向量 x ∈ R^4096：
  - sum_sq = Σ_i x_i^2
  - mean = sum_sq / 4096
  - inv_rms = 1 / sqrt(mean + eps)
  - y_j = x_j * inv_rms * weight_j, j in 0..4095
- eps = 1e-5
- hidden_states 可以是 bfloat16/fp16/fp32，在代码中强制转换为 float32 进行计算

- 每行需要读取两次 hidden_states (一次计算 sum of squares，一次用于 scale and write)，并写一次结果
- 无法只读一次就完成，因为 inv_rms 需要知道整行的均值
- 如果试图将 inv_rms 写入全局再读取，又会增加一次全局读写，反而更慢
- 因此，最佳策略是：一个 Triton kernel 一行，两个 pass，在 kernel 内部完成 sum 和 scale，不依赖 PyTorch op

- 保持数值与 PyTorch 版本相同，允许 autotune 选择 BLOCK_SIZE 和执行参数

优化计划
- 单一 kernel，一个 program per row
- 两个 pass：
  1) 遍历所有 tile，累加 sum of squares
  2) 遍历所有 tile，重新读取 x，计算 y = x * inv_rms * weight，并写入输出
- Triton autotune：提供几个配置，让 Triton 选择最佳 BLOCK_SIZE/num_warps/num_stages
  - BLOCK_SIZE 为 512, 1024, 2048, 4096
  - num_warps 4 or 8
  - num_stages 3 or 4
- 计算使用 float32，存储时根据 hidden_states.dtype 进行 cast (fp32/fp16/bf16)
