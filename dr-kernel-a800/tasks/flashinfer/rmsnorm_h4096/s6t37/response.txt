Since the operation is memory-bound (each row must be read twice and written once), the most effective approach is to keep a single fused Triton kernel without intermediate global memory writes, and tune execution parameters to hide latency and minimize loop iterations.

Operation recap
- Per row:
  - Compute inv_rms = 1 / sqrt(mean(x^2) + eps), where mean is across 4096 elements.
  - Output y = (x * inv_rms) * weight.
- Memory traffic: two reads (first pass to accumulate sum of squares, second pass to scale and write) and one write per row. Writing intermediates to global memory would only add bandwidth and slow things down.

Plan
- Keep one Triton program per row, two passes:
  - First pass: accumulate sum of squares to derive inv_rms.
  - Second pass: re-read x, multiply by inv_rms and weight, and store output.
- Tiling and execution parameters:
  - Use BLOCK_SIZE=1024 with num_warps=8 and num_stages=3. This yields 4 loop iterations for hidden_size=4096, balancing register pressure and loop count. The prior configuration achieved ~1.74x, and we’ll keep it.
  - Compute in float32 and cast only at store to match original behavior. Masked loads/stores ensure correctness.
- Ensure inputs are contiguous and on CUDA. No host-side PyTorch computation beyond necessary dtype conversion and allocation.

```python
import torch
import triton
import triton.language as tl

# Triton kernel: per-row RMS scaling with weight.
# One program per row. We read x twice: once to compute sum of squares, once to write output.
@triton.jit
def _rms_scale_kernel(
    hidden_ptr,        # *float32, pointer to hidden_states (cast to float32)
    weight_ptr,        # *float32, pointer to weight (cast to float32)
    out_ptr,           # *T_out, pointer to output (will store casted result)
    batch_size,        # int32
    hidden_size,       # int32
    eps,               # float32
    out_dtype_code: tl.constexpr,  # 0: fp32, 1: fp16, 2: bf16
    BLOCK_SIZE: tl.constexpr        # e.g., 1024
):
    row_id = tl.program_id(0)  # one program per row

    # First pass: accumulate sum of squares across the row
    sumsq = 0.0  # scalar float32
    # Loop over the row in chunks of BLOCK_SIZE
    for col_start in range(0, hidden_size, BLOCK_SIZE):
        col_offsets = col_start + tl.arange(0, BLOCK_SIZE)
        mask = col_offsets < hidden_size
        x = tl.load(hidden_ptr + row_id * hidden_size + col_offsets, mask=mask, other=0.0)
        sumsq += tl.sum(x * x, axis=0)

    mean = sumsq / hidden_size
    inv_rms = tl.rsqrt(mean + eps)  # 1.0 / sqrt(mean + eps)

    # Second pass: read x again, scale, and write output
    for col_start in range(0, hidden_size, BLOCK_SIZE):
        col_offsets = col_start + tl.arange(0, BLOCK_SIZE)
        mask = col_offsets < hidden_size
        x = tl.load(hidden_ptr + row_id * hidden_size + col_offsets, mask=mask, other=0.0)
        w = tl.load(weight_ptr + col_offsets, mask=mask, other=0.0)
        y = x * inv_rms * w  # compute in float32

        # Cast to target dtype at store
        if out_dtype_code == 0:
            y_cast = y
        elif out_dtype_code == 1:
            y_cast = tl.cast(y, tl.float16)
        else:
            y_cast = tl.cast(y, tl.bfloat16)
        tl.store(out_ptr + row_id * hidden_size + col_offsets, y_cast, mask=mask)

class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, weight):
        # Ensure CUDA and contiguous float32 compute
        assert hidden_states.is_cuda and weight.is_cuda, "Inputs must be CUDA tensors"
        batch_size, hidden_size = hidden_states.shape
        assert hidden_size == 4096, "hidden_size must be 4096"

        # Cast inputs to float32 for compute
        hidden = hidden_states.contiguous().to(torch.float32)
        weight = weight.contiguous().to(torch.float32)

        # Prepare output with target dtype
        out = torch.empty_like(hidden_states, device=hidden_states.device)

        # Encode output dtype for kernel
        dtype_code = 0  # fp32
        if out.dtype == torch.float16:
            dtype_code = 1
        elif out.dtype == torch.bfloat16:
            dtype_code = 2
        else:
            # default to fp32 if some other dtype appears
            dtype_code = 0

        # Launch Triton kernel
        grid = (batch_size,)
        _rms_scale_kernel[grid](
            hidden, weight, out,
            batch_size, hidden_size, 1e-5,
            dtype_code,
            BLOCK_SIZE=1024,
            num_warps=8,
            num_stages=3,
        )
        return out
```

- 计算流程：
  - 将 hidden_states 转为 float32。
  - 计算每行的 RMS 逆：inv_rms = rsqrt(mean(x^2) + EPS)，其中 EPS=1e-5，mean 是对 4096 元素的均值，keepdim=True 保持形状 [batch_size, 1]。
  - 与 weight (转为 float32) 相乘：y = (x * inv_rms) * weight。
  - 返回 y，转换回 hidden_states 的原始 dtype (题目中 get_inputs 返回 bfloat16)。

内存/计算特性
- 每行必须读取两次 hidden_states：
  - 第一次为了计算 sum of squares (得到 inv_rms)。
  - 第二次为了应用 inv_rms 和 weight 生成输出。
- 每行写入一次输出。
- 因此操作本质上是内存带宽受限的，任何额外的全局内存写入 (例如 x^2 或 inv_rms) 都会减慢速度。

- 保持单个 Triton kernel，并且：
  - 一个程序处理一行 (per-row kernel)。

- 避免任何主机侧的 PyTorch 计算 (除了必要的 dtype 转换/分配)，确保所有的数值计算都在 Triton kernel 中完成。
- 选择合适的 tiling/warps/stages 来隐藏内存延迟并减少 loop 迭代次数：
  - hidden_size=4096 时，BLOCK_SIZE=1024 → 4 次迭代，num_warps=8，num_stages=3 是一个不错的平衡。
- 计算时使用 float32，仅在 store 时 cast 到目标 dtype (fp32/fp16/bf16)。

详细实现步骤
1. Triton kernel 结构
   - 一个程序对应一个 batch 行 (grid=(batch_size,))。
   - 第一遍 loop (0..hidden_size step BLOCK_SIZE)：
     - 计算 x^2 并 tl.sum 得到 sumsq。
   - 计算 inv_rms = rsqrt(sumsq / hidden_size + EPS)。
   - 第二遍 loop (0..hidden_size step BLOCK_SIZE)：
     - 重新 load x 和 weight 的相应 chunk
     - y = x * inv_rms * weight (float32)
     - 根据输出 dtype_code (0: fp32, 1: fp16, 2: bf16) cast 后 tl.store。

2. Host 侧的 ModelNew.forward
   - 检查 CUDA 设备和 hidden_size == 4096。
   - hidden_states 和 weight 转为 float32 (contiguous) 以进行计算。
   - 输出分配为 empty_like(original hidden_states shape and dtype) —— 这是为了匹配原 PyTorch forward 的返回 dtype，在 kernel 中进行 cast store。
   - 编码输出 dtype_code 为 0/1/2，并 launch kernel。

3. 保持严格限制
   - 不使用 torch 的 elementwise reduction (如 torch.sum, torch.mean, torch.rsqrt) 来做主计算，全部放在 Triton kernel 内部完成。
   - 不使用任何 @torch.no_grad() 以外的 PyTorch autograd 逻辑；但为了兼容测试环境，我们可以在 forward 里不显式开启/关闭 autograd（实际上评估可能不需要反向，且原 code 也没有使用 autograd）。

4. 性能考量
   - 两个 pass 是不可避免的，因为没有全局行均值的快速共享机制。
   - BLOCK_SIZE=1024 已经表现良好 (~1.74x)，我们保持此设置，并确保 num_warps=8, num_stages=3 来最大化吞吐。
   - 保持计算在 float32，只在最后 cast，可以最小化数值误差并保持正确性。

5. 安全性和鲁棒性
   - 使用 masked loads/stores 来支持隐藏层大小变化 (尽管题目中 hidden_size=4096)。
   - assert hidden_size==4096 以防不测。

        x = tl.load(hidden_ptr + row_id * hidden_size + col_offsets, mask=mask, other=0.0)
        sumsq += tl.sum(x * x, axis=0)

    mean = sumsq / hidden_size
    inv_rms = tl.rsqrt(mean + eps)  # 1.0 / sqrt(mean + eps)

    # Second pass: read x again, scale, and write output
    for col_start in range(0, hidden_size, BLOCK_SIZE):
        col_offsets = col_start + tl.arange(0, BLOCK_SIZE)
        mask = col_offsets < hidden_size
        x = tl.load(hidden_ptr + row_id * hidden_size + col_offsets, mask=mask, other=0.0)
        w = tl.load(weight_ptr + col_offsets, mask=mask, other=0.0)
        y = x * inv_rms * w  # compute in float32

        # Cast to target dtype at store
        if out_dtype_code == 0:
            y_cast = y
        elif out_dtype_code == 1:
            y_cast = tl.cast(y, tl.float16)
        else:
            y_cast = tl.cast(y, tl.bfloat16)
        tl.store(out_ptr + row_id * hidden_size + col_offsets, y_cast, mask=mask)

class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, weight):
        # Ensure CUDA and contiguous float32 compute
        assert hidden_states.is_cuda and weight.is_cuda, "Inputs must be CUDA tensors"
        batch_size, hidden_size = hidden_states.shape
        assert hidden_size == 4096, "hidden_size must be 4096"

        # Cast inputs to float32 for compute (contiguous)
        hidden = hidden_states.contiguous().to(torch.float32)
        weight = weight.contiguous().to(torch.float32)

        # Prepare output with target dtype (match hidden_states dtype)
        out = torch.empty_like(hidden_states, device=hidden_states.device)

        # Encode output dtype for kernel
        dtype_code = 0  # fp32 default
        if out.dtype == torch.float16:
            dtype_code = 1
        elif out.dtype == torch.bfloat16:
            dtype_code = 2
        else:
            # default to fp32 if some other dtype appears
            dtype_code = 0

        # Launch Triton kernel: one program per row
        grid = (batch_size,)
        _rms_scale_kernel[grid](
            hidden, weight, out,
            batch_size, hidden_size, 1e-5,
            dtype_code,
            BLOCK_SIZE=1024,
            num_warps=8,
            num_stages=3,
        )
        return out

- 性能: 采用 per-row kernel 两遍读取隐藏层数据的方式避免了额外的全局内存写入，结合 BLOCK_SIZE=1024, num_warps=8, num_stages=3，在之前的评估中获得了 ~1.74x 以上的 speedup，并且保持 14/14 正确性。
