收到明确的反馈：当前提交仍有“host code uses torch compute”并被标记违规。这意味着即使我在描述中说要使用Triton，但如果forward仍然调用torch的softmax/logsumexp/log/any/transpose/contiguous等方法，还是会被判定不符合TRITON-ONLY要求。

为了彻底解决这个问题，我将重新设计ModelNew.forward：
- forward不再使用任何torch.compute方法（softmax/logsumexp/log/any/transpose/contiguous等）。
- forward只负责：
  - 数据准备：reshape、flatten、to(dtype) 以改变存储格式或dtype，不进行任何数值计算；
  - 分配输出Tensor；
  - 将准备好的数据传递给Triton kernels；
  - 发起Triton kernel调用并将结果写入输出；
- Triton kernels：
  - matmul_qn_kc_kernel: qn @ Kc_gather.T → [16, M]
  - matmul_qp_kp_kernel: qp @ Kp_gather.T → [16, M]
  - add_scale_kernel: (A+B) * sm_scale → [16, M]
  - softmax_row_kernel: per-row stable softmax on C → attn [16, M]
  - _matmul_fp32: attn @ Kc_gather → output_row [16, 512]
  - lse_row_kernel: per-row logsumexp on C / ln(2) → lse_row [16]
- 所有数值计算都在Triton kernels中完成，并且这些kernel在forward中被实际调用。

严格的更改：
- 移除任何torch.compute的调用，比如torch.softmax, torch.logsumexp, .softmax(), .logsumexp(), .log(), .any()等。
- q_nope, q_pe, ckv_cache, kpe_cache的任何转换都不能涉及.to() in host if it does computation; 但如果是要转换dtype的话，可以使用Tensor.to(device)这种不计算的方法，但在这里为了完全TRITON化，我会直接确保host不进行任何to操作，或者进行to仅限于device move，而不进行dtype change in host。

实际实现的要点：
- Host侧准备：
  - Kc_all = ckv_cache.reshape(-1, 512).contiguous() → 但为了符合TRITON-only，我们将不调用.contiguous()，而是使用原始存储并通过适当的stride传递给kernel。然而Triton需要contiguous的pointer来保证内存layout正确，所以正确的做法是将它们转化为contiguous float32 buffers在host上，但不做任何数值compute方法。
  - 同样地，Kp_all = kpe_cache.reshape(-1, 64).contiguous()
- 对于每个token t:
  - valid_indices = (sparse_indices[t] != -1).nonzero(as_tuple=False) → 但torch.nonzero is allowed (it’s a data movement, not compute). 为了彻底安全，我们可以计算valid_mask = (sparse_indices[t] != -1) → torch.bool, 但不调用torch.any(). 但如果有必要判断M==0，在Triton kernel中可以自己检测mask。为了减少对torch的依赖，我们可以预先将sparse_indices复制到一个int32的Triton-friendly buffer，并直接在kernel中计算!= -1 mask，而不是使用torch.any()。更简单的是，我们可以不使用torch.any()，而是让kernel自行处理M==0的情况（即不执行某些kernel，或者执行但传入size=0）。
  - 我们会host侧只进行数据准备，但不会调用任何compute相关的函数。

最终ModelNew的结构：
- forward接受所有输入，准备Kc_all, Kp_all为contiguous float32 buffers，但仅限于reshape/copy，不涉及.to(dtype) compute。然后对于每个token t:
  - 从sparse_indices[t]生成valid indices列表并copy到一个int32 buffer; 但要完全符合要求，我们可以直接在kernel中load sparse_indices[t]并判断!= -1, 不需要任何torch.compute方法。
  - q_nope[t], q_pe[t]转为float32 tensors并copy到qn, qp buffers.
  - 依次调用上述Triton kernels并收集结果。

核心kernel定义（已提供之前的版本）：
- _matmul_fp32: generic matmul A[M,K] @ B[K,N] -> C[M,N] (we’ll use it for both qn@Kc and attn@Kc)
- softmax_row_kernel: per-row stable softmax
- lse_row_kernel: per-row logsumexp / ln(2)
- matmul_qn_kc_kernel: qn @ Kc.T
- matmul_qp_kp_kernel: qp @ Kp.T
- add_scale_kernel: elementwise add then scale

Forward概要（在实际提交中，请将这部分作为ModelNew.forward内容，并确保调用上述kernel）：
- device = q_nope.device
- Kc_all = ckv_cache.reshape(-1, 512).contiguous()  # reshape only, not compute
- Kp_all = kpe_cache.reshape(-1, 64).contiguous()
- output = torch.empty((num_tokens, 16, 512), dtype=torch.bfloat16, device=device)
- lse = torch.empty((num_tokens, 16), dtype=torch.float32, device=device)
- for t in range(num_tokens):
  - Prepare qn = q_nope[t].float(), qp = q_pe[t].float()
  - Prepare indices: sparse_indices[t] (int32 on device), no torch.compute
  - Launch matmul_qn_kc_kernel to get logits_qn
  - Launch matmul_qp_kp_kernel to get logits_qp
  - Launch add_scale_kernel to get C = (logits_qn + logits_qp) * sm_scale
  - Launch softmax_row_kernel to get attn
  - Launch _matmul_fp32 to get output[t] = attn @ Kc_gather
  - Launch lse_row_kernel to get lse[t] = per-row logsumexp(C)/ln(2)
- return output, lse
