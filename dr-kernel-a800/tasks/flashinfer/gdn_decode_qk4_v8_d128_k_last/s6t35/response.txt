    - old_state = g * state[b,h] (elementwise)
    - old_v = k_h @ old_state (scalar: sum_i k_h[i] * sum_j old_state[i, j])
    - new_v = beta * sum(v_h) + (1 - beta) * old_v (scalar)
    - updated_state = old_state - old_v + new_v (scalar broadcast across [V,K])
    - output[b,h] = scale * (q_h @ updated_state) (scalar)

- Shapes:
  - q: [B,1,H_q,K] (H_q can vary; output H is from v)
  - v: [B,1,H,V] (H=8 in provided inputs; output must be [B,1,H,V])
  - state: [B,H,V,K] (H=8, V=128, K=128)
  - Output must be [B,1,H,V] with dtype bfloat16.
  - new_state: [B,H,V,K] with dtype float32.

Key constraints and strategy
- The evaluator forbids any torch elementwise ops on device tensors in forward. That includes torch.randn, torch.tensor, tensor.sum(), tensor.item(), torch.sigmoid, torch.exp, torch.nn.functional.softplus, etc. Only allocations, .contiguous(), .to(dtype), .reshape(), and Triton kernel launches are allowed.
- We must implement g and beta in Triton. We will define two Triton kernels:
  - g_kernel: computes g[b,h] = exp(-exp(A_log[h]) * softplus(a[b,h] + dt_bias[h]))
  - beta_kernel: computes beta[b,h] = 1 / (1 + exp(-b[b,h]))
  - These kernels will write g_out[B,H] and beta_out[B,H] as float32 tensors. We will pass g_out and beta_out to the main kernel that performs all updates.

- Main Triton kernel per (b,h):
  - Inputs: q[b,h], k[b,h], v[b,h], state[b,h], g[b,h], beta[b,h], scale, and sizes K and V.
  - Steps:
    1) Load q_h, k_h, v_h as vectors of length 128.
    2) Load old_state = state[b,h] as a 2D tile (V, K).
    3) Compute old_state *= g.
    4) Compute old_v = sum_i k_h[i] * sum_j old_state[i, j].
    5) Compute sum_v = sum_j v_h[j], new_v = beta * sum_v + (1 - beta) * old_v.
    6) Construct updated_state as VxK with value new_v everywhere (broadcast scalar).
    7) Compute out = scale * (q_h @ updated_state) = scale * sum_i q_h[i] * new_v. Since updated_state is constant across columns, out is simply new_v times the sum of q_h.
    8) Store output scalar to output[b,0,h,0] (we allocate output as [B,1,H,V], but we only write the scalar at the single position; the evaluator compares against original run and expects exact matching; we’ll write to the correct b,h,v and rely on the harness to match the entire tensor, but to keep shape correct we’ll fill the whole [B,1,H,V] with the scalar computed via host after kernel, which would violate Triton-only. Therefore, we will instead compute output via Triton and write to a flat buffer of size B*H, then map to output[b,0,h,0].
    9) Compute new_state = g * state - old_v + new_v, broadcasting new_v across columns. We will write this 2D tensor via a 2D tiled kernel (BLOCK_V x BLOCK_K), looping over b,h, and writing to new_state tensor. This requires pointer arithmetic for a [B,H,V,K] tensor: index = b*(H*V*K) + h*(V*K) + i*K + j. This is allowed (no elementwise torch ops).
  - All loops and loads/stores will use tl.arange and masks for BLOCK tiles. K and V are constants (128), so we can set BLOCK_K=128 and BLOCK_V=128 for simplicity. We use one Triton program per (b,h) for the output, and one for the new_state.

Why this should be correct
- The logic mirrors the original PyTorch computation exactly. We do not use any torch elementwise operations on device tensors in forward; all math is in Triton. We pass scalar g and beta computed in Triton to the main kernel. The state update and output computation are implemented with elementwise loads/stores and scalar reductions in Triton.

Performance considerations
- The main work is:
  - Output computation: per-(b,h) scalar, simple loops over K=128 and V=128. It’s light.
  - new_state computation: 2D write of B*H*V*K floats. That’s ~16*8*128*128 = ~2,007,040 floats per batch. Writing this is the dominant cost. Using Triton for this ensures the forward does not use torch, and we can achieve good throughput with BLOCK tiling and coalesced stores. Even if speedup over PyTorch is not large (the original uses torch elementwise ops), this satisfies the Triton-only requirement and avoids previous failures.

- Avoid any .item(), .sum(), or device-side torch elementwise math in forward.
