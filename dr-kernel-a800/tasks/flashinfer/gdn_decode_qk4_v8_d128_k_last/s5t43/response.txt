The “RuntimeError: shape '[1, 1, 8]' is invalid for input of size 1024” indicates a Triton kernel attempted to load a 1D pointer with an index derived from a shape of [1,1,8], but the input tensor was actually [1,1,8], and the pointer arithmetic expected a flat vector of size 1024. The most likely culprit is that we passed b, a, or A_log with a 3D shape while the kernel expected a 1D contiguous vector. Another source of mismatches can be non-contiguous views or incorrect flattening.

To fix and prevent recurrence:
- Ensure we pass 1D vectors of correct length to Triton kernels and avoid 3D-shaped loads.
- Cast all parameter tensors (A_log, a, b, dt_bias) to float32 before launching Triton, because tl.exp requires floating-point.
- Use simple 1D Triton kernels that do not depend on complex indexing; keep shapes explicit.
- Always launch kernels from forward and avoid returning None. The forward method now invokes two kernels and returns both outputs.

Design recap and correctness
- Inputs after squeeze:
  - q: [B, 4, K], k: [B, 4, K], v: [B, 8, V], state_in: [B, 8, V, K]
  - A_log: [8], a: [B, 1, 8], dt_bias: [8], b: [B, 1, 8], scale: float
- Per batch b and head h (H=num_v_heads=8):
  - g[h] = exp(-exp(A_log[h]) * softplus(a[b,1,h] + dt_bias[h]))
  - beta[h] = sigmoid(b[b,1,h])
  - old_v = sum over k of k_h[k] * state[b,h,k] (reduce over K=128)
  - new_v = beta * v_h + (1 - beta) * old_v
  - old_state = g * state[b,h]
  - state_remove = sum over k of k_h[k] * old_state[k] (reduce over K)
  - state_update = sum over k of k_h[k] * new_v[k] (reduce over K)
  - new_state[b,h] = old_state - state_remove[:, None] + state_update[:, None]
  - output[b,h] = scale * dot(q[b,h], new_state[b,h]) (reduce over V=128)

Implementation details
- Triton kernels:
  1) _compute_g_beta_kernel: one program per h in [0..H-1]. Loads A_log[h], a_vec[b,h], dt_bias[h] (as floats), computes g and beta, stores to g_vec[h] and beta_vec[h].
  2) _update_single_bh_kernel: one program per (b,h). Loops over V and K (K=128, V=128) to perform the state update and write output[b,h] and the new_state[b,h,:] slice. We also write all K values per V to the new_state buffer to produce the [B,H,V,K] tensor.
- Forward:
  - Cast a, b, A_log, dt_bias to float32.
  - Launch _compute_g_beta_kernel to compute g_vec and beta_vec.
  - Launch _update_single_bh_kernel to compute output and new_state.
  - Return output [B,H,V] cast to bfloat16 and new_state [B,H,V,K] as float32.

import math
import torch
import triton
import triton.language as tl


@triton.jit
def _compute_g_beta_kernel(a_ptr, b_ptr, A_log_ptr, dt_bias_ptr, g_ptr, beta_ptr, H):
    """
    Compute g[h] = exp(-exp(A_log[h]) * softplus(a[b,1,h] + dt_bias[h])) and
    beta[h] = sigmoid(b[b,1,h]) for h in [0..H-1].
    a_ptr: [B, H] float32
    b_ptr: [B, H] float32
    A_log_ptr: [H] float32
    dt_bias_ptr: [H] float32
    g_ptr: [H] float32 output
    beta_ptr: [H] float32 output
    """
    h = tl.program_id(0)  # one program per head
    # Load parameters as scalars
    a_val = tl.load(a_ptr + h)  # a[b,h]
    b_val = tl.load(b_ptr + h)  # b[b,h]
    A_log_val = tl.load(A_log_ptr + h)  # A_log[h]
    dt_bias_val = tl.load(dt_bias_ptr + h)  # dt_bias[h]

    # softplus(x) = log(1 + exp(x)), implemented robustly
    x = a_val + dt_bias_val
    # softplus = tl.log(1.0 + tl.exp(x))  # Triton supports these
    softplus_x = tl.log(1.0 + tl.exp(x))

    # g = exp(-exp(A_log) * softplus(a + dt_bias))
    g = tl.exp(-tl.exp(A_log_val) * softplus_x)
    # beta = sigmoid(b) = 1 / (1 + exp(-b))
    beta = 1.0 / (1.0 + tl.exp(-b_val))

    tl.store(g_ptr + h, g)
    tl.store(beta_ptr + h, beta)


@triton.jit
def _update_single_bh_kernel(
    q_ptr, k_ptr, v_ptr, state_in_ptr,
    g_ptr, beta_ptr,
    out_ptr, new_state_ptr,
    B: tl.constexpr, H: tl.constexpr, V: tl.constexpr, K: tl.constexpr, scale: tl.float32
):
    """
    One program per (b,h). Compute output[b,h] and fill new_state[b,h,:] over K.
    q_ptr: [B, H, K]
    k_ptr: [B, H, K]
    v_ptr: [B, H, V]
    state_in_ptr: [B, H, V, K]
    g_ptr: [H] float32
    beta_ptr: [H] float32
    out_ptr: [B*H] float32
    new_state_ptr: [B*H*V*K] float32
    """
    b = tl.program_id(0)  # batch index
    h = tl.program_id(1)  # head index

    # Load g and beta
    g = tl.load(g_ptr + h)
    beta = tl.load(beta_ptr + h)

    # Compute old_v = sum_k k_h[k] * state_in[b,h,k]
    old_v = 0.0
    for k_idx in range(0, K):
        k_elem = tl.load(k_ptr + b * H * K + h * K + k_idx)  # scalar
        state_elem = tl.load(state_in_ptr + b * H * V * K + h * V * K + k_idx * V)  # [V] contiguous
        # sum over V implicitly via scalar broadcasting: state_elem is length V vector
        # Here state_elem is V elements: we need sum_k(state_in[b,h,k_idx, :])
        # Better: compute per k_idx sum across V dimension; but state_in is [B,H,V,K]; we need to read vector across V for fixed k_idx.
        # Use linear indexing: for each i in 0..V-1, read state_in[b,h,i,k_idx]
        old_v += k_elem * tl.sum([tl.load(state_in_ptr + b * H * V * K + h * V * K + k_idx * V + i) for i in range(0, V)])

    # Compute new_v = beta * v[b,h,:] + (1 - beta) * old_v
    new_v = tl.zeros(V, dtype=tl.float32)
    for i in range(0, V):
        v_elem = tl.load(v_ptr + b * H * V + h * V + i)
        new_v[i] = beta * v_elem + (1.0 - beta) * old_v

    # old_state = g * state_in[b,h,:]
    old_state = tl.zeros([V, K], dtype=tl.float32)
    for i in range(0, V):
        for k_idx in range(0, K):
            old_state[i, k_idx] = g * tl.load(state_in_ptr + b * H * V * K + h * V * K + k_idx * V + i)

    # state_remove = sum_k k_h[k] * old_state[k]
    state_remove = tl.zeros(V, dtype=tl.float32)
    for k_idx in range(0, K):
        k_elem = tl.load(k_ptr + b * H * K + h * K + k_idx)
        state_remove += k_elem * tl.sum([old_state[i, k_idx] for i in range(0, V)])

    # state_update = sum_k k_h[k] * new_v[k]
    state_update = tl.zeros(V, dtype=tl.float32)
    for k_idx in range(0, K):
        k_elem = tl.load(k_ptr + b * H * K + h * K + k_idx)
        # new_v is vector of length V; access new_v[k_idx] for each k_idx? We need to map k_idx -> element of new_v.
        # Instead, compute state_update = sum_k k_elem * new_v[k] by iterating over V and matching k.
        # We can compute directly: new_v has indices i; but we need scalar new_v value for each k_idx iteration.
        # Since new_v is known per k, we must map each k to the corresponding new_v element. Compute new_v values once and then:
        pass  # Triton JIT requires structured loops; we'll fill using beta and v logic below.

    # Compute output[b,h] = scale * dot(q[b,h,:], new_state_vector)
    # We need new_state_vector for all (i,k). For simplicity, we'll compute output using a known formula:
    # Let's recompute new_state[b,h,:] vector as new_state = old_state - state_remove[:,None] + state_update[:,None]
    # But we don't have state_update V-vector yet. We need to compute it properly.

    # Correct approach: compute new_state per (i,k) as new_state[i,k] = old_state[i,k] - state_remove[i] + state_update[i]
    # We need state_update per i. Compute:
    state_update_vec = tl.zeros(V, dtype=tl.float32)
    for k_idx in range(0, K):
        k_elem = tl.load(k_ptr + b * H * K + h * K + k_idx)
        # state_update_vec += k_elem * (beta * v_elem + (1-beta) * old_v) where v_elem is v[b,h,:]
        # We need v[b,h,:]. Load and compute:
        for i in range(0, V):
            v_elem_i = tl.load(v_ptr + b * H * V + h * V + i)
            state_update_vec[i] += k_elem * (beta * v_elem_i + (1.0 - beta) * old_v)

    # Now compute output: new_state_vector = old_state - state_remove[:,None] + state_update_vec[:,None]
    # We need to write all V rows. We'll compute new_state[i,k] in two steps: first fill rows, then output dot.
    # However, we still need output: output = scale * sum_i q[b,h,i] * new_state[i] where new_state[i] is scalar sum over k.
    # That's not correct. Instead, we can compute new_state[i,k] and then compute output via dot with q[b,h,:].
    # Let's do it:

    # Prepare q vector: q[b,h,:] length V
    q_vec = tl.zeros(V, dtype=tl.float32)
    for i in range(0, V):
        q_elem = tl.load(q_ptr + b * H * V + h * V + i)
        q_vec[i] = q_elem

    # Compute output[b,h] = scale * sum_i q[i] * (old_state[i] - state_remove[i] + state_update_vec[i])
    # old_state[i] is scalar sum over K; we don't need to compute it; we'll recompute via state_in.
    # Simplify: since we already have state_update_vec and state_remove, compute new_state_scalar[i] = old_state[i] - state_remove[i] + state_update_vec[i] equals:
    # We need to determine old_state[i]. It's g * state_in[b,h,i,0..K-1]. That's sum over K. We can compute it:
    new_state_scalar = tl.zeros(V, dtype=tl.float32)
    for i in range(0, V):
        sum_state_i = 0.0
        for k_idx in range(0, K):
            sum_state_i += tl.load(state_in_ptr + b * H * V * K + h * V * K + k_idx * V + i)
        sum_state_i *= g
        new_state_scalar[i] = sum_state_i - state_remove[i] + state_update_vec[i]

    output_val = 0.0
    for i in range(0, V):
        output_val += q_vec[i] * new_state_scalar[i]
    output_val *= scale
    out_offset = b * H
    tl.store(out_ptr + out_offset + h, output_val)

    # Fill new_state[b,h,:] over K: new_state[i,k] = new_state_scalar[i] - state_remove[i] + state_update_vec[i]
    # But state_update_vec affects all k equally since it was computed as sum over k? No, state_update_vec was computed per i including k contributions.
    # Clarification: state_update_vec[i] = sum_k k_elem * (beta*v[i] + (1-beta)*old_v). That is per i and independent of k. Therefore:
    # new_state[i,k] = (g * state_in[i]) - state_remove[i] + state_update_vec[i] equals: old_state[i] - state_remove[i] + state_update_vec[i]
    # We already have new_state_scalar[i] as above. So new_state[i,k] = new_state_scalar[i] for all k? That would imply no k dependency, which is incorrect.

    # Therefore, we must recompute per (i,k): new_state[i,k] = g * state_in[b,h,i,k] - (k_elem * old_state[i])? No, state_remove is per i scalar.
    # Actually, state_remove[i] = sum_k k_elem * old_state[i,k]. But old_state[i,k] depends on k. So new_state[i,k] = g*state_in[i,k] - state_remove[i] + state_update_vec[i] is wrong because state_remove[i] is scalar, not per-k.
    # This indicates a design mistake: we cannot recover per-(i,k) new_state without storing it in the kernel. The simplest is to compute per (i,k) using state_in and write to new_state_ptr.

    # Fix: compute and write new_state per (i,k). Recompute old_state[i,k] and apply the formula: new_state[i,k] = g*state_in[i,k] - state_remove[i] + state_update_vec[i]
    # state_update_vec[i] is per i; state_remove[i] is per i scalar. But state_remove[i] is sum over k of k_elem * old_state[i,k]. We can compute it by accumulating for each i across K.
    # Let's redefine state_remove as per-(i) scalar: create state_remove_vec[V].
    # We already computed state_remove as a scalar; that was incorrect because it treated all i equally. Fix: compute per i.

    # Compute per-i state_remove[i] = sum_k k_elem * g * state_in[b,h,i,k]
    state_remove_vec = tl.zeros(V, dtype=tl.float32)
    for i in range(0, V):
        sum_i = 0.0
        for k_idx in range(0, K):
            s_elem = tl.load(state_in_ptr + b * H * V * K + h * V * K + k_idx * V + i)
            k_elem = tl.load(k_ptr + b * H * K + h * K + k_idx)
            sum_i += k_elem * g * s_elem
        state_remove_vec[i] = sum_i

    # state_update_vec per i is independent of k: state_update_vec[i] = sum_k k_elem * (beta*v[i] + (1-beta)*old_v)
    state_update_vec = tl.zeros(V, dtype=tl.float32)
    for i in range(0, V):
        v_elem_i = tl.load(v_ptr + b * H * V + h * V + i)
        state_update_vec[i] = beta * v_elem_i + (1.0 - beta) * old_v
        # Accumulate across k of k_elem contributions:
        for k_idx in range(0, K):
            k_elem = tl.load(k_ptr + b * H * K + h * K + k_idx)
            state_update_vec[i] += k_elem * (beta * v_elem_i + (1.0 - beta) * old_v)
        # Correction: the above double counts beta*v_elem_i + (1-beta)*old_v for each k. It should be computed once:
        # So set it back to the non-k dependent value:
        # We'll compute state_update_vec[i] = beta*v_elem_i + (1-beta)*old_v without k contributions. The k contribution is irrelevant for state_update_vec since new_v does not depend on k per i; it depends on the entire vector via beta and old_v. The previous attempt to include k was incorrect. Let's set it correctly:

    # Therefore, to keep correctness, we'll compute new_state[i,k] directly using the original formula without trying to precompute state_update_vec. This will involve iterating over i and k, but Triton allows loops up to 128. We will recompute each element.

    # Compute per-(i,k) new_state and store in linear new_state_ptr[b*H*V*K + (h*V+K)*i + k]
    for i in range(0, V):
        # old_state_scalar_i = g * sum_k state_in[b,h,i,k]
        sum_state_i = 0.0
        for k_idx in range(0, K):
            sum_state_i += tl.load(state_in_ptr + b * H * V * K + h * V * K + k_idx * V + i)
        old_state_scalar_i = g * sum_state_i

        state_remove_i = 0.0
        state_update_i = 0.0
