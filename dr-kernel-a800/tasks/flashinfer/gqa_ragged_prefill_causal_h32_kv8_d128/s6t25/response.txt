Root cause and plan

- The previous Triton implementation hit “illegal memory access” on CUDA. The most likely cause is mismatched or incorrect pointer arithmetic in Triton kernels when using element strides for 3D tensors. Specifically:
  - I computed pointer offsets using stride_b = head_dim * num_heads and stride_h = head_dim, which is incorrect for a 3D tensor with strides [C, H, D]. The correct element stride for the batch dimension should be head_dim * num_qo_heads, not head_dim * num_qo_heads. Misaligned pointers lead to out-of-range writes and illegal accesses.
  - In the softmax accumulation kernel, I incorrectly indexed v_expanded as j * (num_qo_heads * head_dim) + h * head_dim. That’s wrong: v_expanded has shape [N, num_qo_heads, head_dim] contiguous. The correct contiguous index for v_expanded[j, h, :] is j * (num_qo_heads * head_dim) + h * head_dim. Although both N and num_qo_heads are 32 in the given code, relying on this accidental equality is fragile and can break in general.
- Another potential source of errors is using tensor offsets that don’t match the actual memory layout. Triton requires element strides derived from tensor strides via multiplication, not via arbitrary formulas. Using .stride() from PyTorch and computing element strides as stride_in_elements = torch_stride * element_size_of_dtype can be brittle; better to use simple, well-defined contiguous layouts and derive strides accordingly.
- I also compute lse as logsumexp(logits[i, h, :]) and then divide by log(2). To match the original code, I will compute lse = logsumexp(logits) and then multiply by inv_log2 = log(2) rather than divide by log(2).

Fix strategy
- Restructure kernels to use simpler, well-defined memory layouts:
  - After computing logits in Triton, materialize a [num_q_tokens, num_qo_heads, num_kv_tokens] float32 tensor for logits. Compute lse per (i, h) via Triton reduction. Compute output accumulation via Triton kernel that reads logits, lse, and v_expanded, and writes the accumulated output.
- Eliminate any risk of illegal memory access:
  - Compute element strides consistently and correctly. For example:
    - logits is [B, H, J] where B=num_q_tokens, H=num_qo_heads, J=num_kv_tokens. Its element strides: sB = H*J, sH=J, sJ=1. We pass these directly.
    - v_expanded is [J, H, D] where D=head_dim. Its element strides: sJ=H*D, sH=D, sD=1. We pass these directly.
  - Avoid complex tensor pointer arithmetic. Use simple base pointers and derived offsets.

Performance considerations
- Triton kernels:
  - Kernel 1: compute logits with causal masking (one program per (i, h), loop over j).
  - Kernel 2: reduction for lse (one program per (i, h), two passes over j: max then sum).
  - Kernel 3: output accumulation (one program per (i, h), loop over j, accumulate with exp(score - m) * v[j, h, :] and apply causal mask).
- This avoids Python control flow in Triton, uses tl.where for masking, and ensures contiguous element indexing. While PyTorch’s attention is highly optimized, the evaluation requires Triton-only, and this implementation should be correct and compilable.

        tl.store(logits_ptr + logits_offset, score)


@triton.jit
def _lse_row_kernel(
    logits_ptr, lse_ptr,
    num_q_tokens, num_kv_tokens, num_qo_heads,
    lse_stride_b, lse_stride_h,  # strides for lse [B, H]
):
    pid = tl.program_id(axis=0)
    i = pid // num_qo_heads
    h = pid % num_qo_heads
    if i >= num_q_tokens:
        return

    # Compute lse[i, h] = logsumexp(logits[i, h, :]) / log(2) using max-shift trick:
    # m = max(score), s = sum(exp(score - m)), lse = (m + log(s)) / log(2)
    m = -float("inf")
    for j in range(0, num_kv_tokens):
        offset = i * lse_stride_b + h * lse_stride_h + j * lse_stride_h  # here: j is dummy, lse_stride_h is 1
        # We need j-th element of logits[i, h, :], advance by + logits_stride_J per j
        score = tl.load(logits_ptr + (i * lse_stride_b + h * logits_stride_H) + j * logits_stride_J)
        m = tl.maximum(m, score)

    s = 0.0
    for j in range(0, num_kv_tokens):
        score = tl.load(logits_ptr + (i * lse_stride_b + h * logits_stride_H) + j * logits_stride_J)
        y = tl.exp(score - m)
        s += y

    lse_val = (tl.log(s) + m) * (1.0 / math.log(2.0))  # divide logsumexp by ln(2) as original does
    lse_offset = i * lse_stride_b + h * lse_stride_h
    tl.store(lse_ptr + lse_offset, lse_val)


@triton.jit
def _softmax_accum_output_kernel(
    logits_ptr, lse_ptr, v_ptr, out_ptr,
    num_q_tokens, num_kv_tokens, num_qo_heads, head_dim,
    out_stride_B, out_stride_H, out_stride_D,     # strides for out [B, H, D]
    lse_stride_b, lse_stride_h,                   # strides for lse [B, H]
    v_stride_J, v_stride_H, v_stride_D,          # strides for v_expanded [J, H, D]
):
    pid = tl.program_id(axis=0)
    i = pid // num_qo_heads
    h = pid % num_qo_heads
    if i >= num_q_tokens:
        return

    # Load lse[i, h]
    lse_offset = i * lse_stride_b + h * lse_stride_h
    lse_val = tl.load(lse_ptr + lse_offset)  # already (logsumexp / log(2))

    # Accumulate output[i, h, :] = sum_j exp(logits[i, h, j] - lse_val) * v_expanded[j, h, :]
    out_base = i * out_stride_B + h * out_stride_H
    d = tl.arange(0, head_dim)
    out_ptr_vec = out_ptr + out_base + d

    # We need to zero out out_ptr_vec before accumulation. Triton kernels can't memset, but host can. Since we launch this kernel after computing logits and lse, we should have initialized out to zeros. However, we can implement zeroing here:
    for d0 in range(0, head_dim):
        tl.store(out_ptr + out_base + d0, 0.0)

    for j in range(0, num_kv_tokens):
        # score = logits[i, h, j]
        score = tl.load(logits_ptr + (i * lse_stride_b + h * logits_stride_H) + j * logits_stride_J)
        w = tl.exp(score - lse_val)  # softmax weight for this j

        # v_expanded[j, h, :] base offset: j*v_stride_J + h*v_stride_H
        v_base = j * v_stride_J + h * v_stride_H
        v_ptr_vec = v_ptr + v_base + d

        v_vals = tl.load(v_ptr_vec)
        out_vals = tl.load(out_ptr_vec)
        out_vals = out_vals + w * v_vals
        tl.store(out_ptr_vec, out_vals)
