- The original code computes a multi-head attention with GQA:
  - q: [total_q, 32, 128]
  - k: [total_kv, 8, 128]
  - v: [total_kv, 8, 128]
  - num_qo_heads = 32, num_kv_heads = 8, head_dim = 128
  - GQA ratio = 32 // 8 = 4. For each batch b, K and V are repeated along head_dim by factor 4 to align with 32 heads.

- Per batch b:
  - num_q_tokens = q_end - q_start, num_kv_tokens = kv_end - kv_start.
  - Expand k and v along head dimension by factor 4 to get [num_kv_tokens, 32, 128].
  - Compute logits per head h: Qh @ Kh^T where Qh is [num_q_tokens, 128], Kh is [num_kv_tokens, 128], producing logits [num_q_tokens, num_kv_tokens].
  - Scale logits by sm_scale = 1/sqrt(128).
  - Apply causal mask: query i can attend KV position j if j < (i + 1 + delta), with delta = num_kv_tokens - num_q_tokens. If delta <= 0, mask is all False.
  - Compute lse per (query, head): logsumexp(logits) in base 2 (divide by log(2)). The original code returns lse, but the main output is the attention output. We’ll compute and return both to match the signature.

- Triton implementation strategy:
  - We’ll implement two Triton kernels:
    1) compute_logits_masked_and_lse: computes the scaled logits for all heads, applies causal mask, stores logits, and computes lse per (query, head).
       - We’ll launch one Triton program per (batch, head) pair. Each program computes a matrix of size [num_q_tokens, num_kv_tokens], tiled over q and kv positions. This avoids constructing expanded k and v explicitly and performs K/V expansion implicitly by computing Qh @ Kh^T using the original 8-head K/V and repeating along head tiles inside the kernel (i.e., mapping each head h to the corresponding 8 head by h % 8).
       - We’ll also compute row-wise maxima for LSE while filling the logits tile (no need to materialize the entire logits matrix).
    2) compute_output_and_lse_from_logits: compute softmax along KV tokens for each (query, head), multiply by V_expanded, and write output. Also compute and write lse in base 2. This kernel also launches per (batch, head) and performs the matvec per row.

- Correctness considerations:
  - We must ensure qo_indptr and kv_indptr indexing is correct: each batch b uses tokens from q[qo_indptr[b]:qo_indptr[b+1]], k[kv_indptr[b]:kv_indptr[b+1]], v[kv_indptr[b]:kv_indptr[b+1]]. We’ll pass pointers to the sliced tensors in forward, but Triton kernels will still index them using local start indices. This avoids host-side slicing and keeps everything in Triton.
  - Causal mask: We’ll construct mask on host as int8 [num_q_tokens, num_kv_tokens] and pass it to Triton. The condition j < (i + 1 + delta) is implemented exactly.
  - LSE in base 2: We compute lse per row and divide by log(2.0). To improve numerical stability, we compute softmax on scaled logits (multiply by 1/log(2)) and LSE accordingly, then scale the output back to the original base. This keeps consistency.
  - Dtypes: The original uses bfloat16 for q, k, v. We’ll operate in float32 in kernels for numerical stability and write outputs as float32 (then convert to bfloat16 to match the original output type). LSE can be float32. This matches typical practice and avoids precision issues.

  - Fuse mask application and LSE computation during logits computation, and fuse softmax and matvec during output computation. While Triton doesn’t support autograd, these fused operations reduce host-side overhead.
