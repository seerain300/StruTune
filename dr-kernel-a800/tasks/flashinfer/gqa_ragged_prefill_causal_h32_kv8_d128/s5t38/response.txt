Design overview:
- We define a Triton kernel that processes one block (determined by qo_indptr and kv_indptr slices). For each block:
  - Load q, k, v as float32.
  - Compute attention logits Q @ K^T for each query head across all key/value heads, with scaling SM_SCALE.
  - Apply the causal mask j < q_idx + 1 + delta.
  - Compute lse per (q, head) = logsumexp(logits) / log(2).
  - Compute softmax over K dimension and multiply by V to produce output.
  - Store output (bfloat16) and lse (float32) into their respective tensors.
- Host code (ModelNew.forward):
  - Cast q, k, v to float32 and ensure contiguity.
  - Allocate output (bfloat16) and lse (float32).
  - Loop over blocks b from 0 to len_indptr - 2, derive q_start, q_end, kv_start, kv_end by reading qo_indptr[b:b+2] and kv_indptr[b:b+2] as device int32 tensors. Set M = q_end - q_start, N = kv_end - kv_start. If M or N <= 0, skip. Otherwise, launch Triton kernel with M, N, G, GH, D as constexpr and sm_scale as runtime scalar.
  - Return (output, lse). No torch math in forward.
