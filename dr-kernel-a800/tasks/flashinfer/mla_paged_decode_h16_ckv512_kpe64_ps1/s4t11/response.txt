- Kc = Kc_all[tokens] → [M, 512], Kp = Kp_all[tokens] → [M, 64]

- attn[i] = exp(logits_scaled[i]) / sum_j exp(logits_scaled[j]) across tokens
- out[h, :] = sum_i attn[i] * Kc[i, :] = attn @ Kc → [512], cast to bfloat16

Key optimization ideas:
- The heavy parts are GEMVs: qn @ Kc.T and out = attn @ Kc. These should be Triton kernels.
- We can avoid computing Kp @ qp for each token by leveraging linearity: logsumexp over tokens of (a[i] + b[i]) equals logsumexp(a) + logsumexp(b). However, a[i] depends on qn and Kc, b[i] depends on qp and Kp. While a[i] is the same for all heads, b[i] varies per head, so this trick does not universally reduce compute across heads. Instead, we implement the two GEMVs in Triton.
- For softmax and lse, Triton’s tl.arange requires constexpr. To avoid torch ops, I implement a Triton reduction kernel that:
  - Loads the logits_scaled vector in chunks (constexpr BLOCK_M).
  - Reduces to compute max and sum(exp) per chunk using vector operations.
  - Iteratively combines chunk maxima and sums to produce global max and sum. This avoids tl.arange(0, M) entirely.
  - Computes lse = log(sum) / ln(2) and writes attn vector.
- Triton matvec kernel details:
  - Input A is a row vector of length K (qn or a chunk), B is [M, K], output C is [1, M].
  - Use tl.static_range to loop over K in tiles (BLOCK_K), load chunks, and accumulate into a vector acc[M].
  - This avoids dynamic loops and compiles robustly.
