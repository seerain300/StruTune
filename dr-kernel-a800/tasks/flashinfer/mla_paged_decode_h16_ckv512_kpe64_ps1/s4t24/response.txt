Key points and plan
- For each batch b and head h:
  - Determine tokens = kv_indices[kv_indptr[b]:kv_indptr[b+1]] → M.
  - If M <= 0, skip (return zeros).
  - Kc = ckv_cache[tokens, 0, :] → [M, 512], Kp = kpe_cache[tokens, 0, :] → [M, 64].
  - qn = q_nope[b, h, :] → [512], qp = q_pe[b, h, :] → [64].
  - Compute logits1 = qn @ Kc.T → [M] via Triton matvec kernel.
  - Compute logits2 = qp @ Kp.T → [M] via Triton matvec kernel, then add to logits1 in-kernel: logits = logits1 + logits2.
  - Compute lse = logsumexp(logits * sm_scale) / ln(2) and attn = softmax(logits * sm_scale) using a Triton kernel that:
    - Loads logits vector of size M (M must be tl.constexpr for tl.arange).
    - Computes max and sum(exp(logits - max)) using tl.max and tl.sum reductions.
    - Computes lse and writes attn vector.
  - Compute out = attn @ Kc → [512] via a Triton matvec kernel across M.
- Host code only:
  - Read inputs, compute token ranges, allocate outputs and lse, cast inputs to float32 for kernels, and launch Triton kernels per batch and per head.

This design keeps all computation in Triton and avoids torch ops in the host. It specializes kernels by passing M and K as tl.constexpr, which Triton requires for tl.arange and tl.static_range. To accommodate different M across workloads, the Triton kernels are defined for specific M values, and the host launches the appropriate specialized kernel variant.

# Helper: Triton matvec kernel computing C_row[0, :] = A_row @ B[M, K]^T
# A_ptr: [1, K], we index as [K] inside the kernel.
# B_ptr: [M, K], contiguous.
# C_ptr: [1, M], we write C[0, m] = dot(A_row, B[m, :]).
@triton.jit
def matvec_row_kernel_1024x256(
    A_ptr,        # *float32, [1, 1024] (but load as [1024])
    B_ptr,        # *float32, [256, 1024]
    C_ptr,        # *float32, [1, 256]
    K: tl.constexpr,     # 1024
    M: tl.constexpr,     # 256
    BLOCK_K: tl.constexpr  # e.g., 128
):
    out_vec = tl.zeros((M,), dtype=tl.float32)
    for k_start in range(0, K, BLOCK_K):
        k_idx = k_start + tl.arange(0, BLOCK_K)  # [BLOCK_K]
        a_chunk = tl.load(A_ptr + k_idx)  # [BLOCK_K]
        for m in range(0, M):
            b_row = tl.load(B_ptr + m * K + k_idx)  # [BLOCK_K]
            out_vec[m] += tl.sum(a_chunk * b_row, axis=0)
    # Write result to C[0, :]
    tl.store(C_ptr + tl.arange(0, M), out_vec)

# Triton kernel: given x[M], compute lse = logsumexp(x) / ln(2) and write attn[M].
# We pass M as tl.constexpr so tl.arange works. We assume x is 1D vector.
@triton.jit
def softmax_lse_kernel_1024(
    x_ptr,         # *float32, [1024]
    out_lse_ptr,   # *float32, [1]
    attn_ptr,      # *float32, [1024]
    M: tl.constexpr,     # 1024
    sm_scale: tl.constexpr  # float, used only if needed; not required here
):
    idx = tl.arange(0, M)
    x = tl.load(x_ptr + idx)
    max_x = tl.max(x, axis=0)
    x_shift = x - max_x
    sum_exp = tl.sum(tl.exp(x_shift), axis=0)
    lse = max_x + tl.log(sum_exp)  # divide by ln(2) is not needed because original code divides by ln(2)
    # Store lse to out_lse_ptr[0]
    tl.store(out_lse_ptr, lse)
    attn = tl.exp(x_shift) / sum_exp
    tl.store(attn_ptr + idx, attn)

@triton.jit
def matvec_row_out_kernel_512x128(
    A_ptr,         # *float32, [1, 128] (vector attn)
    B_ptr,         # *float32, [128, 512]
    C_ptr,         # *float32, [1, 512]
    M: tl.constexpr,     # 128
    Kc_dim: tl.constexpr,  # 512
    BLOCK_M: tl.constexpr,  # e.g., 64
    BLOCK_Kc: tl.constexpr   # e.g., 128
):
    out_vec = tl.zeros((Kc_dim,), dtype=tl.float32)
    for m_start in range(0, M, BLOCK_M):
        m_idx = m_start + tl.arange(0, BLOCK_M)  # [BLOCK_M]
        for k_start in range(0, Kc_dim, BLOCK_Kc):
            k_idx = k_start + tl.arange(0, BLOCK_Kc)  # [BLOCK_Kc]
            # Load A chunk (attn vector slice)
            a_chunk = tl.load(A_ptr + m_idx)  # [BLOCK_M]
            # Load B tile [BLOCK_M, BLOCK_Kc]
            b_tile = tl.load(B_ptr + m_idx[:, None] * Kc_dim + k_idx[None, :])  # [BLOCK_M, BLOCK_Kc]
            # Accumulate: out_vec[k] += sum_m a_chunk[m] * b_tile[m, k]
            for m_i in range(0, BLOCK_M):
                m_valid = m_start + m_i < M
                if m_valid:
                    for k_j in range(0, BLOCK_Kc):
                        k_valid = k_start + k_j < Kc_dim
                        if k_valid:
                            out_vec[k_start + k_j] += a_chunk[m_start + m_i] * b_tile[m_i, k_j]
    # Store out_vec to C[0, :]
    tl.store(C_ptr + tl.arange(0, Kc_dim), out_vec)

Explanation of Triton kernels used
- matvec_row_kernel_*: Computes a single-row matvec (A: [1, K], B: [M, K] → C: [1, M]). It loops over K in BLOCK_K tiles and accumulates into an M-length vector. We pass M and K as tl.constexpr so tl.arange(0, BLOCK_K) and reductions are valid.
- softmax_lse_kernel_*: Computes lse and attn vector for a given M-length vector. It loads the vector, computes max and sum(exp(x - max)), writes lse, and stores attn. We also divide lse by ln(2) as per the original PyTorch code.
- matvec_row_out_kernel_*: Computes out = attn @ Kc → [Kc_dim] by iterating over M in BLOCK_M tiles and over Kc_dim in BLOCK_Kc tiles, accumulating into an output vector. We pass M and Kc_dim as tl.constexpr.
