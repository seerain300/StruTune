import math
import torch
import triton
import triton.language as tl


@triton.jit
def compute_logits_scaled_per_batch_kernel(
    qn_ptr,         # *fp32, shape [H, D], contiguous
    qp_ptr,         # *fp32, shape [H, Dp], contiguous
    Kc_ptr,         # *fp32, shape [L_tokens, D], contiguous
    Kp_ptr,         # *fp32, shape [L_tokens, Dp], contiguous
    logits_ptr,     # *fp32, shape [H, L_tokens], contiguous (flattened)
    H,              # int32
    D: tl.constexpr,         # compile-time constant: 512
    Dp: tl.constexpr,        # compile-time constant: 64
    L_tokens,       # int32 runtime
):
    # One program per head h
    h = tl.program_id(0)
    # Initialize logits row for this head
    for t in range(0, L_tokens):
        acc1 = 0.0
        # Dot qn[h, :] with Kc[t, :]
        for k in range(0, D):
            q = tl.load(qn_ptr + h * D + k)    # qn[h, k]
            kc = tl.load(Kc_ptr + t * D + k)   # Kc[t, k]
            acc1 += q * kc
        acc2 = 0.0
        # Dot qp[h, :] with Kp[t, :]
        for k in range(0, Dp):
            q = tl.load(qp_ptr + h * Dp + k)   # qp[h, k]
            kp = tl.load(Kp_ptr + t * Dp + k)  # Kp[t, k]
            acc2 += q * kp
        logit = (acc1 + acc2)
        # Store logits[h, t]
        tl.store(logits_ptr + h * L_tokens + t, logit)


@triton.jit
def compute_lse_and_output_per_batch_kernel(
    Kc_ptr,         # *fp32, shape [L_tokens, D], contiguous
    logits_ptr,     # *fp32, shape [H, L_tokens], contiguous
    output_ptr,     # *fp32, shape [H, D], contiguous
    lse_ptr,        # *fp32, shape [H], contiguous
    H,              # int32
    D: tl.constexpr,         # 512
    L_tokens,       # int32
):
    h = tl.program_id(0)

    # Compute max for numerical stability
    m = -float("inf")
    for t in range(0, L_tokens):
        logit = tl.load(logits_ptr + h * L_tokens + t)
        if logit > m:
            m = logit
    # Compute sum exp(logits - m) / ln(2)
    ln2 = 1.4426950408889634  # math.log(2)
    sum_exp = 0.0
    for t in range(0, L_tokens):
        logit = tl.load(logits_ptr + h * L_tokens + t)
        exp_t = tl.exp(logit - m)
        sum_exp += exp_t
    lse = tl.log(sum_exp) / ln2
    tl.store(lse_ptr + h, lse)

    # Compute output[h, :] = softmax(logits) @ Kc
    for t in range(0, L_tokens):
        logit = tl.load(logits_ptr + h * L_tokens + t)
        attn = tl.exp(logit - lse)
        # Kc[t, :]
        for k in range(0, D):
            kc = tl.load(Kc_ptr + t * D + k)
            # output[h, k] += attn * Kc[t, k]
            tl.atomic_add(output_ptr + h * D + k, attn * kc)

        H = q_nope.shape[1]
        D = q_nope.shape[2]  # 512
        Dp = q_pe.shape[2]   # 64

        # Output tensors
        output = torch.zeros((batch_size, H, D), dtype=torch.float32, device=device)  # compute in fp32
        lse = torch.full((batch_size, H), -float("inf"), dtype=torch.float32, device=device)

                lse[b] = torch.full((H,), -float("inf"), dtype=torch.float32, device=device)
                continue

            Kc = Kc_all[tok_idx].contiguous()  # [L_tokens, D]
            Kp = Kp_all[tok_idx].contiguous()  # [L_tokens, Dp]

            qn = q_nope[b].to(torch.float32).contiguous()  # [H, D]
            qp = q_pe[b].to(torch.float32).contiguous()    # [H, Dp]

            # Allocate per-batch buffers

            grid = (H,)

- Important detail: The original code computes lse per head as logsumexp(logits_scaled) divided by log(2). We must implement that exactly: lse = log(sum(exp(logits_scaled)) / ln(2)). Earlier submissions may have omitted the division by ln(2), causing large discrepancies. I’ve added this division explicitly.

- Batch slicing must match exactly: For each batch b, L_tokens = kv_indptr[b+1] - kv_indptr[b], and tok_idx = kv_indices[kv_indptr[b]:kv_indptr[b+1]]. Our implementation does this. To further avoid mismatches, we iterate over the batch in the host and launch Triton kernels per batch; this guarantees correct slicing and per-batch logic.

3) Triton vectorization constraints:
- Triton’s tl.arange requires compile-time tl.constexpr for axes. We will keep inner loops over D=512 and Dp=64 using tl.arange (constexpr), and iterate over L_tokens and H in runtime scalar loops. Triton handles scalar loops with runtime bounds.
- Avoid tl.program_id over tokens; keep one program per head (grid=(H,)) and loop over tokens. This reduces complexity and avoids dynamic grid shape issues.

Plan to ensure correctness first
- ModelNew.forward will:
  - Ensure all tensors are on CUDA and contiguous.
  - Cast ckv_cache and kpe_cache to float32 and squeeze the size-1 dimension to [num_pages, D] and [num_pages, Dp].
  - For each batch b:
    - Compute L_tokens and tok_idx using kv_indptr[b:b+1] and kv_indices slices.
    - Kc = Kc_all[tok_idx], Kp = Kp_all[tok_idx], qn = q_nope[b], qp = q_pe[b], all cast to float32.
    - Launch Triton kernel compute_logits_scaled_per_batch_kernel to compute logits_scaled[h, t] for each head h and token t.
    - Launch Triton kernel compute_lse_and_output_per_batch_kernel to compute lse[h] and output[h, :] for each head h.
  - Return output in bfloat16 and lse in float32.

Performance considerations
- The current kernels use scalar loops for outer dimensions; they are correct but not highly optimized. Once correctness is confirmed, we can:
  - Fuse the two kernels into one kernel per batch to reduce intermediate buffers.
  - Vectorize inner loops using tl.arange for D and Dp when appropriate.
  - Parallelize across H and possibly tokens using 2D grids. This can improve throughput, but we must ensure dynamic sizes are handled carefully.
