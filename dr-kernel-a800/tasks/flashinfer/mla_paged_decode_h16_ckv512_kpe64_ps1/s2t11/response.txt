The persistent CompilationError with “for h in range(0, H)” and the earlier “TypeError: dynamic_func() missing 3 required positional arguments” indicate that Triton kernels used Python for-loops with runtime-bound variables (H is tl.int32). Triton requires loops to be static, i.e., use tl.static_range with constexpr bounds. Additionally, earlier attempts used 2D broadcasted address expressions in tl.load, which can also trigger compilation failures.

To fix and ensure correctness:
- Remove any runtime-dependent for-loops in Triton kernels. Use one Triton program per (batch, head) pair, i.e., grid=(B, H). This way, H is a known constant per launch, and Triton can compile loops that depend on H.
- Avoid 2D broadcasted tl.load. Use 1D vectorized loads with masks. We can compute addresses as base + offset, where offset is derived from tl.arange and scalar indices.
- Keep heavy computation in Triton. Host code will prepare inputs (make tensors contiguous, flatten q_nope and q_pe to [B*H, D1] and [B*H, D2]), launch kernels, and assemble outputs. No torch matmul/softmax in the host code.

Design recap and plan
- Original PyTorch per batch b, head h:
  - L_tokens = kv_indptr[b+1] - kv_indptr[b].
  - For t in 0..L_tokens-1:
    - idx = kv_indices[page_beg + t], with page_beg = kv_indptr[b].
    - Kc_row = ckv_cache[idx, :] ∈ R^{D1=512}, Kp_row = kpe_cache[idx, :] ∈ R^{D2=64}.
    - logits_scalar = (sum(qn[h, :] * Kc_row) + sum(qp[h, :] * Kp_row)) * sm_scale.
    - softmax across t: attn_t = exp(logits_scaled[t] - max_t) / sum_t exp(.).
    - out[h, :] += attn_t * Kc_row.
    - lse[h] = logsumexp(logits_scaled) / ln(2).
- Triton approach:
  - Kernel 1 (_lse_kernel): grid = (B, H). Each program computes lse for one (b, h). It loops over tokens in tiles (constexpr BLOCK_T) and for each token t within the tile:
    - Load Kc_row and Kp_row as 1D vectors with masks to avoid OOB.
    - Compute scalar logits_scaled and update per-column token_max_vec and token_sum_vec. At the end, write lse[b, h] = token_max_vec + log(token_sum_vec) / ln(2).
  - Kernel 2 (_output_kernel): grid = (B, H). Each program computes output[h, :] for that (b, h). It first computes token_max_vec and token_sum_vec as in _lse_kernel, then loops over tokens in tiles, computes attn_t for each token, and accumulates output[h, :] += attn_t * Kc_row.
  - Host code:
    - Ensure q_nope and q_pe are contiguous, flatten to [B*H, D1] and [B*H, D2].
    - Ensure ckv_cache and kpe_cache subviews (Kc_sub and Kp_sub, shaped [L_tokens, D1] and [L_tokens, D2]) are contiguous.
    - Launch kernels with B and H as meta-parameters (tl.constexpr) and L_tokens, sm_scale as runtime scalars. Use BLOCK_T as constexpr (e.g., 128) and tl.static_range to iterate tiles.

This design eliminates runtime-dependent loops in Triton kernels, uses safe 1D loads with masks, and ensures kernels are actually launched. It should compile and run across the provided workloads. Output is returned as in the original: output in bfloat16 and lse in float32.

import math
import torch
import triton
import triton.language as tl


@triton.jit
def _lse_kernel(
    q_nope_ptr,          # *f32, shape [B*H, D1], contiguous
    q_pe_ptr,            # *f32, shape [B*H, D2], contiguous
    Kc_sub_ptr,          # *f32, shape [L_tokens, D1], contiguous
    Kp_sub_ptr,          # *f32, shape [D2], contiguous
    lse_out_ptr,         # *f32, shape [B, H], contiguous
    B: tl.constexpr,     # batch size (meta)
    H: tl.constexpr,     # number of heads (meta)
    D1: tl.constexpr,    # head_dim_ckv (meta), e.g., 512
    D2: tl.constexpr,    # head_dim_kpe (meta), e.g., 64
    L_tokens: tl.int32,  # runtime scalar
    sm_scale: tl.float32,
    BLOCK_T: tl.constexpr,
):
    # One Triton program per (b, h)
    b = tl.program_id(axis=0)
    h = tl.program_id(axis=1)

    # Load q vectors for head h (q_nope[b, h, :] and q_pe[b, h, :])
    qn = tl.load(q_nope_ptr + b * H * D1 + h * D1 + tl.arange(0, D1)).to(tl.float32)  # [D1]
    qp = tl.load(q_pe_ptr + b * H * D2 + h * D2 + tl.arange(0, D2)).to(tl.float32)   # [D2]

    # Initialize per-column max and sum across tokens
    token_max_vec = tl.full((D1,), -float("inf"), dtype=tl.float32)
    token_sum_vec = tl.zeros((D1,), dtype=tl.float32)

    # Tile over tokens; static unroll over BLOCK_T
    for tile in tl.static_range(0, (L_tokens + BLOCK_T - 1) // BLOCK_T):
        t0 = tile * BLOCK_T
        for tt in tl.static_range(0, BLOCK_T):
            t = t0 + tt
            valid = t < L_tokens
            # Load Kc_row and Kp_row as 1D vectors
            Kc_row = tl.load(Kc_sub_ptr + t * D1 + tl.arange(0, D1), mask=valid, other=0.0).to(tl.float32)  # [D1]
            Kp_row = tl.load(Kp_sub_ptr + t * D2 + tl.arange(0, D2), mask=valid, other=0.0).to(tl.float32)  # [D2]

            # Compute scalar logits for this token
            dot1 = tl.sum(qn * Kc_row, axis=0)  # scalar
            dot2 = tl.sum(qp * Kp_row, axis=0)  # scalar
            logits_scalar = (dot1 + dot2) * sm_scale  # scalar

            # Update per-column max and sum (masked by valid)
            token_max_vec = tl.maximum(token_max_vec, logits_scalar)
            token_sum_vec += tl.where(valid, tl.exp(logits_scalar - token_max_vec), 0.0)

    # Write lse[b, h] = max + log(sum) / ln(2)
    lse_val = token_max_vec + tl.log(token_sum_vec) / 1.4426950408889634  # ln(2)
    tl.store(lse_out_ptr + b * H + h, lse_val)


@triton.jit
def _output_kernel(
    q_nope_ptr,          # *f32, shape [B*H, D1], contiguous
    q_pe_ptr,            # *f32, shape [B*H, D2], contiguous
    Kc_sub_ptr,          # *f32, shape [L_tokens, D1], contiguous
    Kp_sub_ptr,          # *f32, shape [L_tokens, D2], contiguous

    D2: tl.constexpr,    # head_dim_kpe (meta)
    L_tokens: tl.int32,  # runtime scalar
    sm_scale: tl.float32,
    BLOCK_T: tl.constexpr,
):
    # One Triton program per (b, h)
    b = tl.program_id(axis=0)
    h = tl.program_id(axis=1)

    # Load q vectors for head h
    qn = tl.load(q_nope_ptr + b * H * D1 + h * D1 + tl.arange(0, D1)).to(tl.float32)  # [D1]
    qp = tl.load(q_pe_ptr + b * H * D2 + h * D2 + tl.arange(0, D2)).to(tl.float32)   # [D2]

    # Initialize per-column max and sum across tokens
    token_max_vec = tl.full((D1,), -float("inf"), dtype=tl.float32)
    token_sum_vec = tl.zeros((D1,), dtype=tl.float32)

    # Tile over tokens; static unroll over BLOCK_T
    for tile in tl.static_range(0, (L_tokens + BLOCK_T - 1) // BLOCK_T):
        t0 = tile * BLOCK_T
        for tt in tl.static_range(0, BLOCK_T):
            t = t0 + tt
            valid = t < L_tokens
            Kc_row = tl.load(Kc_sub_ptr + t * D1 + tl.arange(0, D1), mask=valid, other=0.0).to(tl.float32)  # [D1]
            Kp_row = tl.load(Kp_sub_ptr + t * D2 + tl.arange(0, D2), mask=valid, other=0.0).to(tl.float32)  # [D2]

            dot1 = tl.sum(qn * Kc_row, axis=0)
            dot2 = tl.sum(qp * Kp_row, axis=0)
            logits_scalar = (dot1 + dot2) * sm_scale
            token_max_vec = tl.maximum(token_max_vec, logits_scalar)
            token_sum_vec += tl.where(valid, tl.exp(logits_scalar - token_max_vec), 0.0)

    # Second pass: compute attn and accumulate output
    for tile in tl.static_range(0, (L_tokens + BLOCK_T - 1) // BLOCK_T):
        t0 = tile * BLOCK_T
        for tt in tl.static_range(0, BLOCK_T):
            t = t0 + tt
            valid = t < L_tokens
            Kc_row = tl.load(Kc_sub_ptr + t * D1 + tl.arange(0, D1), mask=valid, other=0.0).to(tl.float32)  # [D1]
            Kp_row = tl.load(Kp_sub_ptr + t * D2 + tl.arange(0, D2), mask=valid, other=0.0).to(tl.float32)  # [D2]

            dot1 = tl.sum(qn * Kc_row, axis=0)
            dot2 = tl.sum(qp * Kp_row, axis=0)
            logits_scalar = (dot1 + dot2) * sm_scale
            attn = tl.where(valid, tl.exp(logits_scalar - token_max_vec) / token_sum_vec, 0.0)  # scalar
            out_vec = tl.load(out_ptr + (b * H + h) * D1 + tl.arange(0, D1))
            out_vec += attn * Kc_row
            tl.store(out_ptr + (b * H + h) * D1 + tl.arange(0, D1), out_vec)

- We also attempted 2D broadcasted tl.load in some forms, which Triton can be finicky with. Using 1D vectorized loads with masks is safer.

To fix these, I redesigned the Triton approach so that:
- We launch one Triton program per (batch, head) pair, i.e., grid=(B, H). This avoids runtime-dependent loops inside the kernel: the h index becomes a compile-time constant for each program.
- We tile over tokens with a constexpr BLOCK_T and use tl.static_range for the tile loop. Each program computes both the lse and output for its (b, h). This avoids recomputing entirely and avoids host-side PyTorch computation for the heavy parts.
- We use only 1D vectorized loads with masks. We construct Kc_sub and Kp_sub per batch b using PyTorch on device (which is acceptable). Triton performs the scalar and vector math.

Plan
- For each batch b:
  - Compute L_tokens = kv_indptr[b+1] - kv_indptr[b].
  - Build Kc_sub[b] and Kp_sub[b] as contiguous tensors of shape [L_tokens, D1] and [L_tokens, D2] by gathering from Kc_all and Kp_all using kv_indices mapped per b. In the provided get_inputs, kv_indptr length is batch_size + 1 and kv_indices length equals total tokens across batches. We slice kv_indices for each b using offsets derived from kv_indptr. We then copy the corresponding rows from Kc_all and Kp_all into Kc_sub[b] and Kp_sub[b] using PyTorch (on device), so Triton kernels get per-b contiguous data and can operate safely.
- Triton kernels:
  - _compute_bhead_kernel: grid=(B, H). Each program:
    - Loads qn[h] and qp[h] as 1D vectors.
    - Initializes token_max_vec and token_sum_vec (per column).
    - Iterates over tokens in tiles of size BLOCK_T (static). For each token in the tile:
      - Loads Kc_row and Kp_row as 1D vectors with masks.
      - Computes scalar logits = (sum(qn*Kc_row) + sum(qp*Kp_row)) * sm_scale.
      - Updates token_max_vec and token_sum_vec.
    - After the loop, computes lse = token_max_vec + log(token_sum_vec) / ln(2) and stores to lse[b, h].
    - Re-iterates tokens (static) and accumulates out[h, :] += exp(logits - token_max_vec) / token_sum_vec * Kc_row.

This design avoids runtime-dependent loops and problematic tl.load broadcasting. Triton does all heavy computation. Host code prepares per-b data and launches kernels.

import triton.language as tl

    BLOCK_T: tl.constexpr,
):
