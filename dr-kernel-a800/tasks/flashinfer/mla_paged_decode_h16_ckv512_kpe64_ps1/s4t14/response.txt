- Launches Triton kernels from ModelNew.forward
- Performs all heavy numeric work inside Triton (matvec, logsumexp, exp, log)
- Avoids any torch matmul/softmax/exp/sum/max in the host code

Analysis, failure diagnosis, and plan

What the original code computes per batch b and head h:
- tokens = kv_indices[kv_indptr[b]:kv_indptr[b+1]] → M tokens. If M <= 0, skip.
- Kc = Kc_all[tokens] → [M, 512], Kp = Kp_all[tokens] → [M, 64]
- qn = q_nope[b, h, :] → [512], qp = q_pe[b, h, :] → [64]
- logits[i] = sum_k qn[k] * Kc[i, k] + sum_k qp[k] * Kp[i, k] → [M]
- lse[h] = logsumexp(logits * sm_scale) / ln(2)
- attn[i] = exp(logits_scaled[i]) / sum_j exp(logits_scaled[j]) → [M]
- out[h, :] = attn @ Kc → [512], cast to bfloat16

Previous failures:
- Triton compilation errors due to tl.arange requiring tl.constexpr; using tl.arange(0, M) with runtime M caused compilation failure.
- Using torch operations (e.g., torch.sum, torch.log, torch.tensor) in host code was flagged.

Plan to fix:
- Implement matvec in Triton using a “columns-block” kernel:
  - For qn @ Kc.T: We pass A = qn as [1, K], B = Kc as [M, K], and we design the kernel to produce a block of output rows C of size BLOCK_M per program. Each program handles a range of output row indices. We accumulate across K in constexpr tiles (BLOCK_K) and write out a vector of size BLOCK_M for that block. This avoids tl.arange over runtime M.
  - We launch grid along the output row dimension (ceil_div(M, BLOCK_M)) and let each program compute a block of rows. The kernel uses tl.static_range over K tiles, which compiles reliably.
  - We will use this matvec_col_kernel for:
    - qn @ Kc.T → logits vector
    - out = attn @ Kc → final output vector per head
- Implement logsumexp entirely in Triton without tl.arange:
  - Two-pass reduction over M in chunks of BLOCK_M (constexpr).
    - Pass 1: compute per-chunk max and sum of exp(logits - chunk_max). Merge chunks into global gmax and gsum stably:
      - gmax = max(gmax, chunk_max)
      - gsum = gsum * exp(gmax - prev_gmax) + chunk_sum * exp(chunk_max - gmax)
    - Pass 2: compute final lse = log(gsum) / ln(2). We do the log in Triton via tl.log. We also compute attn vector = exp(logits - gmax) / gsum per element in chunks and write it to a device tensor.
  - This avoids tl.arange and torch reductions.

Performance:
- The matvec_col_kernel reduces the heavy GEMV work in Triton. While we loop in tiles over K and blocks over M, this is a scalable approach and compiles. It avoids dynamic tl.arange and provides a robust Triton solution.
- The final out = attn @ Kc is computed via Triton using the same matvec_col_kernel by passing A = attn per head and B = Kc. This preserves Triton-only computation.

import math
import torch
import triton
import triton.language as tl


@triton.jit
def matvec_col_kernel(
    A_ptr,       # *float32, shape [1, K] (row vector A)
    B_ptr,       # *float32, shape [M, K] (rows of K, columns of K)
    C_ptr,       # *float32, shape [BLOCK_M, 1] (block of output rows)
    M,           # int32, number of rows in B
    K: tl.constexpr,              # constexpr, e.g., 512
    BLOCK_K: tl.constexpr,        # constexpr, e.g., 64
    BLOCK_M: tl.constexpr         # constexpr, e.g., 128 or 256
):
    # Each program handles a block of output rows of size BLOCK_M
    pid = tl.program_id(axis=0)
    out_row_start = pid * BLOCK_M

    # Columns indices for accumulation over K
    k_range = tl.arange(0, BLOCK_K)  # constexpr vector for tiling over K

    # Initialize accumulator for BLOCK_M output rows
    acc = tl.zeros((BLOCK_M,), dtype=tl.float32)

    # Loop over K dimension in tiles
    for k in tl.static_range(0, K, BLOCK_K):
        # Load A[k:k+BLOCK_K] as a vector
        a_vec = tl.load(A_ptr + k + k_range)  # A is [1, K]; pointer arithmetic gives row 0
        # Load corresponding block of B rows: [BLOCK_M, BLOCK_K]
        # Rows: out_row_start + arange(0, BLOCK_M)
        b_rows = out_row_start + tl.arange(0, BLOCK_M)  # shape (BLOCK_M,)
        mask_rows = b_rows < M
        # We need to build a [BLOCK_M, BLOCK_K] block for B
        b_ptrs = B_ptr + b_rows[:, None] * K + (k + k_range)[None, :]
        b_block = tl.load(b_ptrs, mask=mask_rows[:, None], other=0.0)
        # Accumulate: acc[b_row] += sum_k a_vec[k] * b_block[b_row, k]
        # Implement as dot: acc += sum over axis=1 of (a_vec[:, None] * b_block)
        acc += tl.sum(a_vec[:, None] * b_block, axis=1)

    # Store results to C: shape [BLOCK_M, 1], contiguous column
    out_cols = tl.arange(0, 1)  # constexpr vector for the single column
    c_ptrs = C_ptr + b_rows[:, None] * 1 + out_cols[None, :] * 1
    tl.store(c_ptrs, acc[:, None], mask=mask_rows[:, None])


@triton.jit
def lse_and_attn_kernel(
    x_ptr,               # *float32, [M] logits_scaled
    out_lse_ptr,         # *float32, [1] lse per head
    attn_ptr,            # *float32, [M] attn vector per head
    M,                   # int32
    sm_scale,            # float32
    BLOCK_M: tl.constexpr,  # e.g., 256
):
    # First pass: compute global max and sum(exp(x - max))
    gmax = -float('inf')
    gsum = 0.0

    for start in tl.static_range(0, M, BLOCK_M):
        idx = start + tl.arange(0, BLOCK_M)
        mask = idx < M
        x = tl.load(x_ptr + idx, mask=mask, other=-float('inf'))
        chunk_max = tl.max(x, axis=0)
        # sum of exp(x - chunk_max) over masked positions
        sum_exp = tl.sum(tl.exp(x - chunk_max), axis=0)

        # Merge with global
        new_gmax = tl.maximum(gmax, chunk_max)
        # scale previous sum and current chunk sum to new_gmax
        gsum = gsum * tl.exp(gmax - new_gmax) + sum_exp * tl.exp(chunk_max - new_gmax)
        gmax = new_gmax

    # Compute lse = log(gsum) / ln(2)
    lse = tl.log(gsum) / 0.6931471805599453  # 1 / ln(2)
    tl.store(out_lse_ptr, lse)

    # Second pass: write attn = exp(x - gmax) / gsum
    inv_gsum = 1.0 / gsum
    for start in tl.static_range(0, M, BLOCK_M):
        idx = start + tl.arange(0, BLOCK_M)
        mask = idx < M
        x = tl.load(x_ptr + idx, mask=mask, other=0.0)
        attn = tl.exp(x - gmax) * inv_gsum
        tl.store(attn_ptr + idx, attn, mask=mask)

# - matvec_row_kernel: computes a single output vector logits of size M given A=[1,K], B=[M,K]

@triton.jit
def matvec_row_kernel(
    A_ptr,          # *float32, [1, K]
    B_ptr,          # *float32, [M, K]
    C_ptr,          # *float32, [M]
    M,              # int32
    K: tl.constexpr,              # e.g., 512
    BLOCK_K: tl.constexpr         # e.g., 64
):
    # This kernel computes C = A @ B^T, where A is a row vector of length K, B has M rows.
    # Output C is a vector of length M. We implement as a row-wise dot product across K tiles.
    acc = tl.zeros((M,), dtype=tl.float32)
    # Loop over K in tiles
    for k in tl.static_range(0, K, BLOCK_K):
        a_vec = tl.load(A_ptr + k + tl.arange(0, BLOCK_K))  # [BLOCK_K]
        # For each row i, compute dot with B[i, k:k+BLOCK_K]
        # We'll iterate rows in a loop; Triton supports Python loops for runtime M.
        for i in range(0, M):
            b_row = tl.load(B_ptr + i * K + k + tl.arange(0, BLOCK_K))
            acc[i] += tl.sum(a_vec * b_row, axis=0)
    # Store acc
    tl.store(C_ptr + tl.arange(0, M), acc)


@triton.jit
def lse_and_attn_kernel(
    x_ptr,               # *float32, [M] logits_scaled
    out_lse_ptr,         # *float32, [1] lse per head
    attn_ptr,            # *float32, [M] attn vector per head
    M,                   # int32
    sm_scale,            # float32 (not used directly here)
    BLOCK_M: tl.constexpr  # e.g., 256
):
