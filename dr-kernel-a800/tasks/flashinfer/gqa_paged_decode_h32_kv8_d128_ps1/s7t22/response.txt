Root cause analysis and plan

- The error “k_cache and v_cache must be [Np, Nkv, D] after squeeze” is an assertion failure in the original run function. In the provided get_inputs(), k_cache and v_cache are created as [num_pages, 1, num_kv_heads, head_dim], then the reference code squeezes the middle 1 to [num_pages, num_kv_heads, head_dim]. To match the original behavior exactly, our ModelNew.forward should perform the same operation and then feed these tensors into the Triton kernels. The previous attempts didn’t explicitly reproduce this exact structure, which triggered the assertion.

- Additionally, prior “too many values to unpack (expected 3)” errors came from host-side shape unpacking. We should avoid unpacking tensor.shape unless we are sure about its dimensionality. In this submission, we won’t rely on unpacking q.shape, k_cache.shape, etc. Instead, we’ll derive Nq, Nkv, D, and B from the final squeezed k_cache and from q, and pass them as compile-time constants to Triton.

- Triton compute:
  - Two kernels:
    1) lse_kernel: one program per (b, h). Loop over tokens in the window [start, end). For each token i, compute attn_i = dot(q[b, h], k_cache[indices[start+i], kv_head]), scaled by sm_scale, track m = max(scaled), sum_exp = sum(exp(scaled - m)). Store lse[b, h] = log(sum_exp) + m divided by log(2).
    2) output_kernel: one program per (b, h). Recompute m and sum_exp. Compute softmax, then out[b, h, :] = sum_i softmax[i] * v_cache[indices[start+i], kv_head][:].
  - All numeric work inside Triton; no torch ops in host code.
  - Dtypes: q is bfloat16, k/v are bfloat16 converted to float32 for compute; outputs stored as bfloat16, lse as float32.

Performance considerations

- Parallelism is across (b, h). For typical B in {1, 16, 64} and Nq=32, that’s B*32 programs, which is reasonable. We use num_warps=4, num_stages=2. For large T, this loop-based approach is correct; further speedups could be explored with chunked vectorized reductions, but correctness is the priority.

import math
import torch
import triton
import triton.language as tl


@triton.jit
def lse_kernel(
    q_ptr,          # *bf16, [B, Nq, D]
    k_ptr,          # *bf16, [Np, Nkv, D] (after squeeze)
    indptr_ptr,     # *i32,  [B+1]
    indices_ptr,    # *i32,  [T_total]
    sm_scale,       # f32
    lse_ptr,        # *f32,  [B, Nq]
    B: tl.constexpr,          # batch size
    Nq: tl.constexpr,         # num_qo_heads
    Nkv: tl.constexpr,        # num_kv_heads
    D: tl.constexpr,          # head_dim
    gqa_ratio: tl.constexpr,  # Nq // Nkv (e.g., 4)
    stride_q_b, stride_q_h, stride_q_d,
    stride_k_p, stride_k_h, stride_k_d,
):
    pid = tl.program_id(0)  # one program per (b, h)
    b = pid // Nq
    h = pid % Nq
    kv_head = h // gqa_ratio

    # Load q[b, h] vector of length D
    q_base = q_ptr + b * stride_q_b + h * stride_q_h
    q_vec = tl.load(q_base + tl.arange(0, D) * stride_q_d).to(tl.float32)  # [D], f32

    # Token window [start, end)
    start = tl.load(indptr_ptr + b)         # int32
    end = tl.load(indptr_ptr + b + 1)      # int32
    T = end - start

    # Accumulate m and sum_exp
    m = tl.full((), -float("inf"), dtype=tl.float32)
    sum_exp = tl.zeros((), dtype=tl.float32)

    i = 0
    while i < T:
        idx = tl.load(indices_ptr + start + i).to(tl.int32)
        k_base = k_ptr + idx * (Nkv * D) + kv_head * D
        k_i = tl.load(k_base + tl.arange(0, D) * 1).to(tl.float32)  # [D]
        attn = tl.sum(q_vec * k_i, axis=0)  # scalar
        scaled = attn * sm_scale
        m = tl.maximum(m, scaled)
        exp_term = tl.exp(scaled - m)
        sum_exp += exp_term
        i += 1

    # lse = log(sum_exp) + m; divide by log(2) to match original
    log2 = 0.6931471805599453
    lse_val = tl.log(sum_exp) + m
    tl.store(lse_ptr + b * Nq + h, lse_val / log2)


@triton.jit
def output_kernel(
    q_ptr,          # *bf16, [B, Nq, D]
    k_ptr,          # *bf16, [Np, Nkv, D] (after squeeze)
    v_ptr,          # *bf16, [Np, Nkv, D] (after squeeze)
    indptr_ptr,     # *i32,  [B+1]

    Nq: tl.constexpr,         # num_qo_heads
    Nkv: tl.constexpr,        # num_kv_heads

    gqa_ratio: tl.constexpr,  # Nq // Nkv (e.g., 4)
    stride_q_b, stride_q_h, stride_q_d,
    stride_k_p, stride_k_h, stride_k_d,
    stride_v_p, stride_v_h, stride_v_d,
    stride_out_b, stride_out_h, stride_out_d,

    b = pid // Nq
    h = pid % Nq

    # Token window [start, end)

    end = tl.load(indptr_ptr + b + 1)      # int32
    T = end - start

    # Recompute m and sum_exp for softmax
    m = tl.full((), -float("inf"), dtype=tl.float32)

    i = 0

        scaled = attn * sm_scale
        m = tl.maximum(m, scaled)
        exp_term = tl.exp(scaled - m)
        sum_exp += exp_term
        i += 1

    # Output vector: out[b, h, :] = sum_i (exp(scaled[i]-m)/sum_exp) * v_selected[i]
    out_row_base = out_ptr + b * stride_out_b + h * stride_out_h

        i = 0

            v_base = v_ptr + idx * (Nkv * D) + kv_head * D

            # We need prob = exp(scaled[i] - m) / sum_exp. We can recompute scaled[i] - m and divide.
            # However, we don't have attn[i] here; we recompute it in a second pass.
            # So we reconstruct prob via recomputation:
            k_base = k_ptr + idx * (Nkv * D) + kv_head * D
            k_i = tl.load(k_base + tl.arange(0, D) * 1).to(tl.float32)
            attn_i = tl.sum(q_vec * k_i, axis=0)
            scaled_i = attn_i * sm_scale
            prob = tl.exp(scaled_i - m) / sum_exp
            acc += prob * v_i
            i += 1
        tl.store(out_row_base + j * stride_out_d, acc.to(tl.bfloat16))
        j += 1

  - Implement two Triton kernels:
    1) lse_kernel: one program per (b, h), loops over tokens in that batch’s window, computes attn = q[b,h] · k_cache[token, kv_head], scales by sm_scale, accumulates m = max(scaled) and sum_exp = sum(exp(scaled - m)). Then lse[b,h] = log(sum_exp) + m, divided by log(2).
    2) output_kernel: one program per (b, h). Recomputes m and sum_exp. Computes softmax and produces output[b,h,:] = sum_i softmax[i] * v_cache[token, kv_head] by looping tokens. Store output as bfloat16, lse as float32.
  - All numeric work inside Triton; host code only allocates tensors, makes inputs contiguous, squeezes, and launches kernels.

- Host-side fixes:
  - Avoid unpacking tensor.shape. Use .size(0), .size(1), etc., and pass sizes as arguments to Triton kernels (B, Nq, Np, Nkv, D). Do not assert fixed values; just ensure squeezed k_cache and v_cache have [Np, Nkv, D].
  - Ensure q, k_cache, v_cache, kv_indptr, kv_indices are on CUDA and contiguous.
