        out_vec = tl.zeros((HEAD_DIM,), dtype=tl.float32)
        lse = tl.full((), -float("inf"), dtype=tl.float32)

            k_t = k_t.to(tl.float32)
            v_t = v_t.to(tl.float32)

            # q_vec: [HEAD_DIM], k_t: [HEAD_DIM]
            dot = 0.0
            for d in range(HEAD_DIM):

            # Scale logits

            # Update LSE stably: in base e, then divide by ln(2) to match original "logsumexp base 2"

            attn = tl.exp(scaled - lse)

            # Accumulate output
            out_vec += attn * v_t

Summary of the original computation and optimization strategy
- The original PyTorch forward implements Grouped Query Attention (GQA):
  - Inputs:
    - q: [B, num_qo_heads, HEAD_DIM] with num_qo_heads = 32, HEAD_DIM = 128.
    - k_cache: [num_pages, 1, num_kv_heads, HEAD_DIM] with num_kv_heads = 8.
    - v_cache: [num_pages, 1, num_kv_heads, HEAD_DIM].
    - kv_indptr: [B+1] int32, defining token ranges per batch element: tokens[b] = kv_indptr[b+1] - kv_indptr[b].
    - kv_indices: not used in the reference; kv_indptr[b]..kv_indptr[b+1] defines the indices.
    - sm_scale: float32 scaling factor (1/sqrt(HEAD_DIM) in the example).
  - For each (b, h):
    - Compute num_tokens = kv_indptr[b+1] - kv_indptr[b].
    - Use GQA mapping kv_head = h // (num_qo_heads // num_kv_heads) = h // 4.
    - For t in 0..num_tokens-1:
      - idx = kv_indptr[b] + t. Gather k_t = k_cache[idx, 0, kv_head, :], v_t = v_cache[idx, 0, kv_head, :].
      - Compute dot = q[b, h] · k_t, scaled = dot * sm_scale.
      - Compute LSE (logsumexp in base 2): lse = logsumexp(logits_scaled) / ln(2).
      - attn = softmax(logits_scaled). We can compute attention as exp(scaled - lse).
      - out_vec[h] += attn * v_t.
    - Store out_vec (cast to bfloat16) to output[b, h], and store lse / ln(2) to lse[b, h].

- Triton kernel design:
  - One Triton program per (b, h). Grid size = (B * num_qo_heads,).
  - Inside the program:
    - Compute num_tokens = kv_end - kv_start, where kv_start = kv_indptr[b], kv_end = kv_indptr[b+1].
    - Load q_vec = q[b, h] as float32.
    - Initialize out_vec (float32) and lse (float32) = -inf.
    - Loop t from 0 to num_tokens-1:
      - idx = kv_start + t.
      - Compute kv_head = h // 4.
      - Load k_t and v_t from k_cache/v_cache using idx and kv_head, cast to float32.
      - dot = sum(q_vec * k_t).
      - scaled = dot * sm_scale.
      - Update LSE stably: if lse == -inf, lse = scaled; else new_lse = max(lse, scaled) + log(1 + exp(-abs(lse - scaled))).
      - attn = exp(scaled - lse).
      - out_vec += attn * v_t.
    - Store out_vec to output[b, h], store lse / ln(2) to lse[b, h].

- Why this approach:
  - It moves all math (dot product, scaling, LSE update, softmax via exp, and accumulation) into the Triton kernel.
  - It avoids any torch matmul/softmax/logsumexp on the host side, satisfying the strict Triton-only requirement.
  - It handles variable batch sizes and token counts as per the evaluation workloads.
