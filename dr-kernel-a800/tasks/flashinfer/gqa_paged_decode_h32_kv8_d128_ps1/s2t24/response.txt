Final diagnosis and plan

- The evaluation system requires that all numeric computation be performed inside Triton @triton.jit kernels, and that ModelNew.forward actually launch these kernels. Previous submissions either didn’t define Triton kernels or used torch operations, which led to compilation/runtime errors and non-evaluation.
- To fix this, we will implement a Triton kernel that:
  - Operates per (batch b, query head h) without Python-side loops in forward.
  - Loops over up to NUM_TOKS tokens using masks to guard accesses. This avoids dynamic control flow in Triton and prevents compilation issues.
  - For each token i:
    - Computes dot = q[b, h] · k_cached[token], scales by sm_scale, updates lse via a running max and sumexp, and in a second pass recomputes attention and accumulates output.
  - Stores output[b, h, :] as float32 (then we’ll cast to bfloat16 on the host) and lse[b, h] as float32.
- ModelNew.forward will:
  - Ensure inputs are on CUDA and contiguous.
  - Cast q, k_cache, v_cache to float32 for computation.
  - Allocate output and lse tensors, launch the Triton kernel with grid (batch_size, num_qo_heads), and cast output to bfloat16 before returning.

Key correctness notes
- GQA mapping: num_qo_heads = 32, num_kv_heads = 8, kv_ratio = 4, so kv_head = h // 4.
- lse is computed as logsumexp((q·k) * sm_scale) / ln(2). Since sm_scale > 0, logsumexp((q·k) * sm_scale) == logsumexp(q·k). We pass half_ln2_inv = 1 / ln(2) to the kernel to divide by ln(2).
- Masks handle cases where num_tokens_actual < NUM_TOKS.

```python
import math
import torch

try:
    import triton
    import triton.language as tl
    TRITON_AVAILABLE = True
except Exception:
    TRITON_AVAILABLE = False


if TRITON_AVAILABLE:
    @triton.jit
    def _attention_bh_kernel(
        q_ptr,            # *float32, shape [BATCH_SIZE, NUM_QO_HEADS, HEAD_DIM]
        k_ptr,            # *float32, shape [NUM_PAGES, NUM_KV_HEADS, HEAD_DIM]
        v_ptr,            # *float32, shape [NUM_PAGES, NUM_KV_HEADS, HEAD_DIM]
        kv_indptr_ptr,    # *int32, shape [BATCH_SIZE+1]
        kv_indices_ptr,   # *int32, shape [NUM_KV_INDICES]
        out_ptr,          # *float32, shape [BATCH_SIZE, NUM_QO_HEADS, HEAD_DIM]
        lse_ptr,          # *float32, shape [BATCH_SIZE, NUM_QO_HEADS]
        sm_scale,         # float32 scalar
        half_ln2_inv,     # float32 scalar: 1 / ln(2)
        BATCH_SIZE: tl.constexpr,
        NUM_QO_HEADS: tl.constexpr,
        NUM_KV_HEADS: tl.constexpr,
        HEAD_DIM: tl.constexpr,
        NUM_TOKS: tl.constexpr,
    ):
        b = tl.program_id(0)
        h = tl.program_id(1)

        # GQA mapping: kv_head = h // (32 // 8) = h // 4
        kv_ratio = NUM_QO_HEADS // NUM_KV_HEADS
        kv_head = h // kv_ratio

        # Base offsets
        q_base = b * NUM_QO_HEADS * HEAD_DIM + h * HEAD_DIM

        # First pass: compute max and sum(exp(s - max)) across tokens
        max_s = -1e20  # scalar
        sum_exp = 0.0  # scalar

        for i in range(NUM_TOKS):
            mask_i = i < (kv_indptr_ptr[b + 1] - kv_indptr_ptr[b])
            # start of this batch
            idx = tl.load(kv_indices_ptr + kv_indptr_ptr[b] + i, mask=mask_i, other=0)  # int32

            # Offsets for k and v rows for this (batch b, token i, kv_head)
            k_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM
            v_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM

            # Load q_vec [HEAD_DIM]
            q_vec = tl.load(q_ptr + q_base + tl.arange(0, HEAD_DIM), mask=True, other=0.0)
            # Load k_vec and v_vec [HEAD_DIM]
            k_vec = tl.load(k_ptr + k_off + tl.arange(0, HEAD_DIM), mask=mask_i, other=0.0)
            v_vec = tl.load(v_ptr + v_off + tl.arange(0, HEAD_DIM), mask=mask_i, other=0.0)

            # Dot product scalar
            dot_i = tl.sum(q_vec * k_vec, axis=0)  # scalar
            s_i = dot_i * sm_scale

            # Update max and sum-exp only if valid
            if mask_i:
                max_s = tl.maximum(max_s, s_i)
                sum_exp = sum_exp * tl.exp(sum_exp - s_i) + 1.0  # maintain sum(exp(s - max_s)) when s_i > max_s; this is a standard trick

        # lse = log(max_s) + log(sum_exp) * (1/ln(2))
        lse_val = tl.log(max_s) + tl.log(sum_exp) * half_ln2_inv
        # Write lse for this (b, h)
        lse_base = b * NUM_QO_HEADS + h
        tl.store(lse_ptr + lse_base, lse_val)

        # Second pass: recompute s, compute attn, and accumulate output
        out_vec = tl.zeros([HEAD_DIM], dtype=tl.float32)
        for i in range(NUM_TOKS):
            mask_i = i < (kv_indptr_ptr[b + 1] - kv_indptr_ptr[b])
            idx = tl.load(kv_indices_ptr + kv_indptr_ptr[b] + i, mask=mask_i, other=0)

            k_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM
            v_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM

            q_vec = tl.load(q_ptr + q_base + tl.arange(0, HEAD_DIM), mask=True, other=0.0)
            k_vec = tl.load(k_ptr + k_off + tl.arange(0, HEAD_DIM), mask=mask_i, other=0.0)
            v_vec = tl.load(v_ptr + v_off + tl.arange(0, HEAD_DIM), mask=mask_i, other=0.0)

            dot_i = tl.sum(q_vec * k_vec, axis=0)
            s_i = dot_i * sm_scale
            attn_i = tl.exp(s_i - lse_val)  # softmax with lse as logsumexp
            out_vec += attn_i * v_vec  # v_vec is [HEAD_DIM], attn_i is scalar

        # Store output for this (b, h)
        tl.store(out_ptr + q_base, out_vec)


class ModelNew(torch.nn.Module):
    def __init__(self):
        super().__init__()

    def forward(self, q, k_cache, v_cache, kv_indptr, kv_indices, sm_scale):
        # Ensure Triton availability
        if not TRITON_AVAILABLE:
            # Fallback: run original logic using PyTorch (not ideal, but ensures functional behavior)
            # Note: In evaluation, Triton is available; this branch is primarily for robustness.
            # Implementing a full PyTorch fallback here is cumbersome; we rely on Triton.
            raise RuntimeError("Triton is not available")

        # Move to CUDA and ensure contiguity
        device = q.device
        assert q.is_cuda and k_cache.is_cuda and v_cache.is_cuda and kv_indptr.is_cuda and kv_indices.is_cuda, "All inputs must be CUDA tensors"
        q = q.contiguous()
        k_cache = k_cache.contiguous()
        v_cache = v_cache.contiguous()
        kv_indptr = kv_indptr.contiguous()
        kv_indices = kv_indices.contiguous()

        # Cast to float32 for computation
        q = q.to(torch.float32)
        k_cache = k_cache.to(torch.float32)
        v_cache = v_cache.to(torch.float32)

        batch_size, num_qo_heads, head_dim = q.shape
        _, num_pages, num_kv_heads, _ = k_cache.shape
        len_indptr = kv_indptr.shape[0]
        num_kv_indices = kv_indices.shape[0]

        # Output and lse tensors
        output = torch.empty((batch_size, num_qo_heads, head_dim), dtype=torch.float32, device=device)
        lse = torch.empty((batch_size, num_qo_heads), dtype=torch.float32, device=device)

        # Grid: one program per (b, h)
        grid = (batch_size, num_qo_heads)

        # Launch Triton kernel
        _attention_bh_kernel[grid](
            q, k_cache, v_cache, kv_indptr, kv_indices,
            output, lse,
            float(sm_scale), float(1.0 / math.log(2.0)),
            BATCH_SIZE=batch_size,
            NUM_QO_HEADS=num_qo_heads,
            NUM_KV_HEADS=num_kv_heads,
            HEAD_DIM=head_dim,
            NUM_TOKS=1024,  # large bound; masked by num_tokens_actual
            num_warps=4,
            num_stages=2,
        )

        # Return output as bfloat16 (to match original) and lse as float32
        return output.to(torch.bfloat16), lse
```

Notes
- The Triton kernel is invoked by ModelNew.forward; no torch ops are used for computation in forward. All math is done in Triton, with masked loops over tokens to avoid dynamic control flow.
- Output is returned as bfloat16 to match the original, and lse as float32.
- If Triton is unavailable, a RuntimeError is raised. In the evaluation environment, Triton should be available, so this won’t trigger. If you need a PyTorch fallback, you can replace the forward body with the original run function, but that would violate the TRITON-ONLY requirement.

Final analysis, root cause, and plan

- The original PyTorch code performs, for each batch b and query head h:
  - Determine cached token indices using kv_indptr and kv_indices.
  - For each token i, compute dot = q[b, h] · k_cache[token, kv_head], where kv_head = h // (32 // 8) = h // 4 (GQA).
  - Scale dot by sm_scale (1/sqrt(128)) and compute lse = logsumexp(dot * sm_scale) / ln(2).
  - Compute attn = softmax(dot * sm_scale) and output[b, h, :] = sum_i attn_i * v_cache[token, kv_head].
- The evaluation system requires all numeric work to be done in Triton @triton.jit kernels and that ModelNew.forward invokes those kernels. Previous submissions either didn’t define Triton kernels, used torch ops, or had compilation issues due to dynamic control flow and host-side masks.

Fix strategy
- Implement a single Triton kernel that operates per (b, h) program:
  - No Python-side loops in forward; Triton kernel iterates up to NUM_TOKS with masks to guard iterations. This avoids dynamic control flow and prevents Triton compilation errors.
  - First pass: loop over i in range(NUM_TOKS), compute dot_i and s_i = dot_i * sm_scale, update running max_s and sum_exp = sum(exp(s_i - max_s)) (this is equivalent to logsumexp(s)). Handle invalid iterations with masks.
  - Compute lse = log(max_s) + log(sum_exp) * (1/ln(2)).
  - Second pass: recompute s_i, compute attn_i = exp(s_i - lse), and accumulate out_vec += attn_i * v_cache[token, kv_head] along the vector dimension. Store out_vec to output[b, h, :]. Store lse to lse[b, h].
- ModelNew.forward:
  - Ensure inputs are CUDA and contiguous.
  - Cast q, k_cache, v_cache to float32 for computation.
  - Allocate output (float32) and lse (float32), launch the Triton kernel with grid (batch_size, num_qo_heads), then cast output to bfloat16 before returning.
