Understanding the problem and root cause

- The original PyTorch “run” function computes a grouped-attention output per batch element and query head, using k_cache/v_cache indexed by kv_indptr and kv_indices. It asserts fixed shapes (num_qo_heads=32, num_kv_heads=8, head_dim=128). However, the evaluation environment runs multiple workloads with dynamic shapes. In such cases, any host-side assumptions or shape unpacking can fail.

- The evaluation repeatedly reports “too many values to unpack (expected 3)” errors. This happens when Python tries to unpack a tensor’s .shape (e.g., q.shape) into exactly three variables (batch, heads, dim). If q has more than 3 dimensions (e.g., due to non-standard views or additional leading dims), .shape returns a tuple with more than 3 elements, causing the ValueError. This is purely a host-side issue, not a Triton kernel compile/runtime error.

- Additionally, some workloads also trigger “head_dim mismatch” assertions. This confirms that input shapes vary and we must avoid hard assertions on fixed head/num_heads.

Fix strategy

- Remove all host-side assertions that depend on fixed shapes. Do not rely on unpacking q.shape, k_cache.shape, v_cache.shape into exactly three values. Instead, derive dimensions from the explicitly provided tensors using .size() and only assume the expected rank.

- Ensure that all tensors passed to Triton are contiguous and on CUDA, and that we pass shapes as compile-time constants to Triton kernels. This avoids shape-related unpacking entirely.

- Implement two Triton kernels:
  1) lse_kernel: one program per (b, h), loops over tokens, computes scaled attention scores, accumulates m and sum_exp for logsumexp, stores lse[b, h] = log(sum_exp) + m, then divides by log(2).
  2) output_kernel: one program per (b, h), recomputes m and sum_exp, computes softmax, and produces out[b, h, :] = softmax @ v_selected by looping over tokens and accumulating soft_i * v_i[j]. Store as bfloat16.

- Avoid torch matmul/softmax on tensors in host code; all computation is done inside Triton kernels.

Performance considerations

- The per-program loops are dynamic (T varies by workload). Triton supports while loops, which we use. For very large T, further optimization can be done (e.g., chunked vectorized reductions and possibly fusing kernels). This implementation prioritizes correctness and robustness. Once correctness is confirmed, we can add chunking and potential fusion.

import math
import torch
import triton
import triton.language as tl


@triton.jit
def lse_kernel(
    q_ptr,          # *bf16, [B, Nq, D]
    k_ptr,          # *bf16, [Np, Nkv, D]
    indptr_ptr,     # *i32,  [B+1]
    indices_ptr,    # *i32,  [T_total]
    sm_scale,       # f32
    lse_ptr,        # *f32,  [B, Nq]
    B: tl.constexpr,          # batch size
    Nq: tl.constexpr,         # num_qo_heads
    Nkv: tl.constexpr,        # num_kv_heads
    D: tl.constexpr,          # head_dim
    gqa_ratio: tl.constexpr,  # Nq // Nkv
    stride_q_b, stride_q_h, stride_q_d,  # strides for q
):
    pid = tl.program_id(0)  # one program per (b, h)
    b = pid // Nq
    h = pid % Nq
    kv_head = h // gqa_ratio  # GQA mapping

    # Load q[b, h] vector of length D
    q_base = q_ptr + b * stride_q_b + h * stride_q_h
    q_vec = tl.load(q_base + tl.arange(0, D) * stride_q_d).to(tl.float32)  # [D], f32

    # Token window [start, end)
    start = tl.load(indptr_ptr + b)         # int32
    end = tl.load(indptr_ptr + b + 1)       # int32
    T = end - start

    # Accumulate max and sum_exp for logsumexp
    m = tl.full((), -float("inf"), dtype=tl.float32)
    sum_exp = tl.zeros((), dtype=tl.float32)

    i = 0
    while i < T:
        idx = tl.load(indices_ptr + start + i).to(tl.int32)  # token index
        # k_i = k_cache[idx, kv_head, :]
        k_base = k_ptr + idx * (Nkv * D) + kv_head * D
        k_i = tl.load(k_base + tl.arange(0, D) * 1).to(tl.float32)  # [D]
        attn = tl.sum(q_vec * k_i, axis=0)  # scalar
        scaled = attn * sm_scale
        m = tl.maximum(m, scaled)
        exp_term = tl.exp(scaled - m)
        sum_exp += exp_term
        i += 1

    # lse = log(sum_exp) + m; divide by log(2) to match original
    log2 = 0.6931471805599453
    lse_val = tl.log(sum_exp) + m
    tl.store(lse_ptr + b * Nq + h, lse_val / log2)


@triton.jit
def output_kernel(
    q_ptr,          # *bf16, [B, Nq, D]
    k_ptr,          # *bf16, [Np, Nkv, D]
    v_ptr,          # *bf16, [Np, Nkv, D]
    indptr_ptr,     # *i32,  [B+1]
    indices_ptr,    # *i32,  [T_total]
    sm_scale,       # f32
    lse_ptr,        # *f32,  [B, Nq]
    out_ptr,        # *bf16, [B, Nq, D]
    B: tl.constexpr,          # batch size
    Nq: tl.constexpr,         # num_qo_heads
    Nkv: tl.constexpr,        # num_kv_heads
    D: tl.constexpr,          # head_dim
    gqa_ratio: tl.constexpr,  # Nq // Nkv
    stride_q_b, stride_q_h, stride_q_d,
    stride_k_p, stride_k_h, stride_k_d,
    stride_v_p, stride_v_h, stride_v_d,
    stride_out_b, stride_out_h, stride_out_d,
):
    pid = tl.program_id(0)  # one program per (b, h)
    b = pid // Nq
    h = pid % Nq
    kv_head = h // gqa_ratio  # GQA mapping

    # Load q[b, h] vector of length D
    q_base = q_ptr + b * stride_q_b + h * stride_q_h
    q_vec = tl.load(q_base + tl.arange(0, D) * stride_q_d).to(tl.float32)  # [D], f32

    # Token window [start, end)
    start = tl.load(indptr_ptr + b)         # int32
    end = tl.load(indptr_ptr + b + 1)       # int32
    T = end - start

    # Recompute m and sum_exp for softmax
    m = tl.full((), -float("inf"), dtype=tl.float32)
    sum_exp = tl.zeros((), dtype=tl.float32)

    i = 0
    while i < T:
        idx = tl.load(indices_ptr + start + i).to(tl.int32)  # token index
        k_base = k_ptr + idx * (Nkv * D) + kv_head * D
        k_i = tl.load(k_base + tl.arange(0, D) * 1).to(tl.float32)  # [D]
        attn = tl.sum(q_vec * k_i, axis=0)  # scalar
        scaled = attn * sm_scale
        m = tl.maximum(m, scaled)
        exp_term = tl.exp(scaled - m)
        sum_exp += exp_term
        i += 1

    # Prepare output vector
    out_base = out_ptr + b * stride_out_b + h * stride_out_h
    # Initialize output to zeros
    tl.store(out_base + 0 * stride_out_d + tl.arange(0, D) * stride_out_d,
             tl.zeros((D,), dtype=tl.bfloat16))

    # Accumulate out[b, h, :] = sum_i softmax_i * v_i
    i = 0
    while i < T:
        idx = tl.load(indices_ptr + start + i).to(tl.int32)  # token index
        v_base = v_ptr + idx * (Nkv * D) + kv_head * D
        v_i = tl.load(v_base + tl.arange(0, D) * 1).to(tl.float32)  # [D]
        scaled = attn * sm_scale
        softmax_i = tl.exp(scaled - m) / sum_exp
        # out += softmax_i * v_i
        out_vec = tl.load(out_base + tl.arange(0, D) * stride_out_d).to(tl.float32)
        out_vec += softmax_i * v_i
        # store updated out
        tl.store(out_base + tl.arange(0, D) * stride_out_d, out_vec.to(tl.bfloat16))
        i += 1


class ModelNew(torch.nn.Module):
    def forward(self, q, k_cache, v_cache, kv_indptr, kv_indices, sm_scale):
        # Ensure all inputs are CUDA and contiguous
        device = q.device
        assert q.is_cuda and k_cache.is_cuda and v_cache.is_cuda and kv_indptr.is_cuda and kv_indices.is_cuda, "Inputs must be CUDA tensors."

        q = q.contiguous()
        k_cache = k_cache.contiguous()
        v_cache = v_cache.contiguous()
        kv_indptr = kv_indptr.contiguous()
        kv_indices = kv_indices.contiguous()

        # Shapes: we only use .size() to get dims, not .shape unpacking
        B = q.size(0)
        Nq = q.size(1)
        D = q.size(2)  # head_dim

        Np, _, Nkv, _ = k_cache.size()
        assert k_cache.size() == v_cache.size() == (Np, Nkv, D), "k_cache/v_cache must be of shape [Np, Nkv, D]."

        # Output and lse
        output = torch.empty((B, Nq, D), dtype=torch.bfloat16, device=device)
        lse = torch.empty((B, Nq), dtype=torch.float32, device=device)

        # Strides
        stride_q_b, stride_q_h, stride_q_d = q.stride()
        stride_k_p, stride_k_h, stride_k_d = k_cache.stride()
        stride_v_p, stride_v_h, stride_v_d = v_cache.stride()
        stride_out_b, stride_out_h, stride_out_d = output.stride()

        # Launch Triton kernels: one program per (b, h)
        grid = (B * Nq,)

        # For GQA, gqa_ratio = Nq // Nkv
        gqa_ratio = Nq // Nkv

        # Kernel 1: compute lse
        lse_kernel[grid](
            q, k_cache, kv_indptr, kv_indices, sm_scale, lse,
            B, Nq, Nkv, D, gqa_ratio,
            stride_q_b, stride_q_h, stride_q_d,
            num_warps=4, num_stages=2,
        )

        # Kernel 2: compute output
        output_kernel[grid](
            q, k_cache, v_cache, kv_indptr, kv_indices, sm_scale, lse, output,
            B, Nq, Nkv, D, gqa_ratio,
            stride_q_b, stride_q_h, stride_q_d,
            stride_k_p, stride_k_h, stride_k_d,
            stride_v_p, stride_v_h, stride_v_d,
            stride_out_b, stride_out_h, stride_out_d,
            num_warps=4, num_stages=2,
        )

        return output, lse

Design

- Input tensors:
  - q: [B, Nq, D] bfloat16
  - k_cache, v_cache: [Np, Nkv, D] bfloat16 (note: the original uses shape [Np, 1, Nkv, D] but squeezes middle dim; we’ll support [Np, Nkv, D] for generality). The evaluator’s workloads appear to use this format.
  - kv_indptr: [B+1] int32
  - kv_indices: [T_total] int32
  - sm_scale: float32 scalar

- Computation per (b, h):
  - kv_head = h // (Nq // Nkv) (GQA mapping).
  - Token window: start = kv_indptr[b], end = kv_indptr[b+1], T = end - start.
  - If T == 0, output zeros and skip.
  - Loop i in 0..T-1:
    - idx_i = kv_indices[start + i]
    - k_i = k_cache[idx_i, kv_head], v_i = v_cache[idx_i, kv_head], each length D.
    - attn_i = dot(q[b, h], k_i)
    - scaled_i = attn_i * sm_scale
    - Compute m = max(scaled_i), sum_exp = sum(exp(scaled_i - m)), lse = log(sum_exp) + m, divide by log(2) for base-2 LSE (match original).
    - softmax_i = exp(scaled_i - m) / sum_exp
    - out_vec[j] += softmax_i * v_i[j] (accumulate across tokens). Output stored as bfloat16. lse stored as float32.

- Implement two Triton kernels:
  1) lse_kernel: one program per (b, h), loop over T, compute m and sum_exp, store lse[b, h] divided by log(2).
  2) output_kernel: one program per (b, h), loop over T again, compute softmax per token, accumulate out_vec += softmax_i * v_i, store as bfloat16.

- Host forward:
  - Ensure tensors are CUDA and contiguous.
  - Derive B, Nq, Nkv, D from sizes using .size(), not .shape.
  - Allocate output and lse tensors.
  - Launch kernels with grid = (B * Nq,).
  - Return output, lse.

Performance considerations

- While loops over dynamic T are fine for correctness; they may not be the fastest for very large T. Once correctness is established, we can consider:
  - Chunked processing to vectorize reductions (compute chunk max and exp-sum, combine).
  - Fusing kernels to avoid recomputation of m/sum_exp (not straightforward because we need them for softmax and out; one kernel would need more complex control flow).
  - Using more warps and stages tuned for D=128.

- While-loop iteration over T is robust and correct but may not be the fastest for very large T. If performance needs to be improved:
  - Implement chunked processing: load BLOCK tokens per iteration, compute chunk-wise m and sum_exp, combine across chunks. This reduces loop overhead and can improve throughput.
  - Consider fusing kernels to avoid recomputation of m and sum_exp, although it requires careful control flow in Triton due to dynamic T.

- The current implementation prioritizes correctness and integration. Once it passes all evaluations, we can tune num_warps/num_stages and explore chunked vectorized reductions for speed.
