Rigorous analysis, failure diagnosis, and optimization plan

What the original code computes
- Input shapes:
  - q: [batch_size, num_qo_heads=32, head_dim=128]
  - k_cache, v_cache: [num_pages, 1, num_kv_heads=8, head_dim=128]
  - kv_indptr: [len_indptr], int32 with len_indptr == batch_size + 1, marking per-batch token ranges in k_cache
  - kv_indices: [num_kv_indices], int32 listing token indices into the first dimension of k_cache (i.e., “num_pages”)
- Per batch b and query head h:
  - tokens = kv_indices[kv_indptr[b]:kv_indptr[b+1]]
  - Use GQA mapping: kv_head = h // (32 // 8) = h // 4
  - For each token index i, gather k_i = k_cache_flat[i, kv_head], v_i = v_cache_flat[i, kv_head], both [128]
  - Compute logits = q[b, h] · k_i (GEMV), scale s = logits * sm_scale where sm_scale = 1/sqrt(128)
  - lse[b, h] = logsumexp(s) / log(2). The code uses an identity logsumexp(x) = log(max(y)) + log(sum(exp(x - max))) when x = 2^u, u = s. This is mathematically equivalent to logsumexp(s) / ln(2), but we’ll compute it as log(max_s) + log(sum_exp) * (1/ln(2)).
  - attn_i = softmax(s) and output[b, h] = sum_i attn_i * v_i

Key constraints from the prompt
- All computation must be done inside Triton @triton.jit kernels. No torch ops in host code (no torch.matmul, torch.softmax, .matmul, etc.).
- Avoid scalar control flow inside kernels. Use masked loops with fixed upper bound (NUM_TOKS) and masks to guard out-of-range iterations.

Why previous attempts failed and how we fix
- Prior versions had compilation errors or used torch operations, so the evaluator did not run them. We will ensure:
  - No torch ops in forward; everything is Triton kernels.
  - Triton kernels perform:
    - Loading q[h], iterating over tokens with masks.
    - Computing dot products (q · k_i) in-kernel.
    - First pass to compute max and sum(exp(s - max)), then lse = log(max) + log(sum_exp) * (1/ln(2)).
    - Second pass to compute attn_i and accumulate output.
  - Host code only: allocate outputs, launch kernel per (b, h), and return results in expected dtypes.

Performance considerations
- Each kernel handles one (b, h). It loops over up to NUM_TOKS with masks, which covers all provided workloads (maximum num_tokens observed ~129K in the batch list, but our NUM_TOKS will be set to 1<<20 to be safe). Using masks prevents out-of-bounds and avoids dynamic branching.
- Compute in float32 inside the kernel for numerical stability; return output as bfloat16 and lse as float32.

import math
import torch

try:
    import triton
    import triton.language as tl
    TRITON_AVAILABLE = True
except Exception:
    TRITON_AVAILABLE = False


if TRITON_AVAILABLE:
    @triton.jit
    def _attention_bh_kernel(
        q_ptr,                 # *float32, shape [NUM_QO_HEADS, HEAD_DIM]
        k_ptr,                 # *float32, shape [NUM_PAGES, NUM_KV_HEADS, HEAD_DIM]
        v_ptr,                 # *float32, shape [NUM_PAGES, NUM_KV_HEADS, HEAD_DIM]
        kv_indptr_ptr,         # *int32, shape [BATCH_SIZE + 1]
        kv_indices_ptr,        # *int32, shape [NUM_KV_INDICES]
        out_ptr,               # *float32, shape [BATCH_SIZE, NUM_QO_HEADS, HEAD_DIM]
        lse_ptr,               # *float32, shape [BATCH_SIZE, NUM_QO_HEADS]
        sm_scale,              # float32 scalar
        BATCH_SIZE: tl.constexpr,
        NUM_QO_HEADS: tl.constexpr,
        NUM_KV_HEADS: tl.constexpr,
        HEAD_DIM: tl.constexpr,
        NUM_TOKS: tl.constexpr,          # upper bound on tokens per batch (e.g., 1<<20)
        HALF_LN2_INV: tl.constexpr,      # 1 / ln(2) = 1.442695...
    ):
        # program ids: one program per (batch, query head)
        b = tl.program_id(0)  # int
        h = tl.program_id(1)  # int

        # GQA mapping: kv_head = h // (32 // 8) = h // 4
        kv_ratio = NUM_QO_HEADS // NUM_KV_HEADS
        kv_head = h // kv_ratio  # 0..7

        # Determine token range for this batch
        start = tl.load(kv_indptr_ptr + b)              # int32
        end = tl.load(kv_indptr_ptr + b + 1)           # int32
        num_tokens_actual = end - start                # int32

        # Load q[h] vector
        q_vec = tl.load(q_ptr + h * HEAD_DIM + tl.arange(0, HEAD_DIM))  # [HEAD_DIM], float32

        # Pass 1: compute max and sum(exp(s - max)) across tokens
        max_s = tl.full((), -1.0e20, tl.float32)  # scalar
        sum_exp = tl.zeros((), tl.float32)        # scalar
        for i in range(NUM_TOKS):
            mask_i = i < num_tokens_actual
            idx = tl.load(kv_indices_ptr + start + i, mask=mask_i, other=0)  # int32 token index

            # Offsets for k and v rows
            k_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM
            v_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM

            # Load k_vec and v_vec (masked)
            k_vec = tl.load(k_ptr + k_off, mask=mask_i, other=0.0)  # [HEAD_DIM], float32
            v_vec = tl.load(v_ptr + v_off, mask=mask_i, other=0.0)  # [HEAD_DIM], float32

            # Dot product: scalar logits
            logits = tl.sum(q_vec * k_vec, axis=0)  # scalar float32
            s = logits * sm_scale

            # Update max and sum-exp only if valid
            if mask_i:
                max_s = tl.maximum(max_s, s)
                # sum_exp = sum_exp * exp(max_s - s) + 1 for s_i > current max_s is not correct; we need to maintain
                # max_s as current max and sum_exp = sum(exp(s_j - max_s)) for all j. To do this robustly without
                # recomputing max for each element, we can compute:
                # If s > max_s: new_sum = exp(s - old_max) + old_sum_exp * exp(old_max - s)
                # Else: sum_exp += exp(s - max_s)
                # We keep a running sum_exp adjusted by rescaling when max increases.
                # Implementation: track inc by checking s > max_s and adjust sum_exp accordingly.
                # However Triton does not support branching with dynamic 'if' easily; better approach is to compute
                # everything unconditionally and maintain sum_exp as sum(exp(s - max_s)) using the standard trick.
                # That requires knowing max_s before the loop, which we don't have until the loop ends. Therefore,
                # we avoid computing sum_exp here and instead compute it in a second loop once max_s is known.
                # To satisfy Triton constraints, we will set max_s and sum_exp via two passes in this kernel.

        # We cannot know max_s before computing all s. Therefore, we will restructure: compute sum_exp in pass1 by
        # looping and keeping a running sum_exp updated by rescaling whenever s > max_s. Triton supports elementwise
        # operations but not dynamic re-scaling per-iteration cleanly. Instead, we will implement sum_exp accumulation
        # by initializing sum_exp = 0 and for each s_i: if s_i > max_s: sum_exp = exp(s_i - s_i) + sum_exp * exp(max_s - s_i) and max_s = s_i; else sum_exp += exp(s_i - max_s).
        # Triton does not have Python 'if' branching on runtime values; instead we use tl.where and elementwise masks.
        # But we only have scalar s. So we implement a per-iteration update:
        # sum_exp = where(s > max_s, 1.0 + sum_exp * exp(max_s - s), sum_exp + exp(s - max_s))
        # Note: this requires computing exp of differences; we store max_s and update sum_exp vectorially per iteration.
        # Triton allows scalar updates; we implement scalar logic via tl.where.
        # However, Triton scalar 'if' won't work as intended. Therefore, we switch to a simpler approach:
        # Compute max_s and then sum_exp in pass1 by scanning and maintaining scalar max and sum.
        # For Triton, we can do:
        # Pass1: max_s, sum_exp
        # Pass2: recompute s and compute output. We cannot compute sum_exp without knowing final max_s. The standard trick
        # is to compute max and sum_exp using a two-pass algorithm:
        # 1) First pass: compute global max m. Then sum_exp = sum(exp(s - m)).
        # Since we cannot have a global max without knowing max_s, we instead compute max_s via the largest s seen.
        # Then sum_exp via sum(exp(s - max_s)). We can do that in a second loop by recomputing dot products, which is
        # acceptable because the workload is small and we are doing Triton-only compute.
        # To avoid host-side torch ops, we will recompute s for each token in a second loop.

        # Reset max_s and recompute in pass2 with an initial guess. The most robust approach is to compute max_s in pass2.
        # However, Triton requires compile-time loops; we will not rely on dynamic loops. Instead, we will implement a
        # two-kernel design: one to compute max_s, then compute sum_exp, then another to compute output. But this exceeds
        # the requirement to use a single kernel.
        # Therefore, we instead compute max_s via the largest s observed in pass1 and then in pass2 recompute s to accumulate
        # sum_exp. This requires scanning tokens twice in-kernel. Triton supports for loops with runtime bounds and masks.

        # Fix: implement two phases using scalar accumulation in the same kernel:
        # Phase A: compute max_s (largest s across tokens).
        max_s = tl.full((), -1.0e20, tl.float32)
        for i in range(NUM_TOKS):
            mask_i = i < num_tokens_actual
            idx = tl.load(kv_indices_ptr + start + i, mask=mask_i, other=0)  # int32
            k_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM
            v_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM

            k_vec = tl.load(k_ptr + k_off, mask=mask_i, other=0.0)
            v_vec = tl.load(v_ptr + v_off, mask=mask_i, other=0.0)

            logits = tl.sum(q_vec * k_vec, axis=0)
            s = logits * sm_scale

            if mask_i:
                max_s = tl.maximum(max_s, s)

        # Phase B: compute sum_exp = sum(exp(s - max_s)) and lse
        sum_exp = tl.zeros((), tl.float32)
        for i in range(NUM_TOKS):
            mask_i = i < num_tokens_actual
            idx = tl.load(kv_indices_ptr + start + i, mask=mask_i, other=0)  # int32
            k_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM
            v_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM

            k_vec = tl.load(k_ptr + k_off, mask=mask_i, other=0.0)
            v_vec = tl.load(v_ptr + v_off, mask=mask_i, other=0.0)

            logits = tl.sum(q_vec * k_vec, axis=0)
            s = logits * sm_scale

            if mask_i:
                sum_exp += tl.exp(s - max_s)

        # lse = log(max_s) + log(sum_exp) * (1/ln(2))
        # Note: original lse = logsumexp(s) / ln(2) = log(max_s + sum_exp * exp(0)) * (1/ln(2)) is incorrect; we need:
        # lse = log(sum_exp) / ln(2) only if we sum exp(s). However, we have sum_exp = sum(exp(s - max_s)), so:
        # lse_correct = log(sum_exp) / ln(2). We previously wrote log(max_s) + log(sum_exp) * (1/ln(2)) which is incorrect.
        # Fix: lse = log(sum_exp) * HALF_LN2_INV.
        lse_val = tl.log(sum_exp) * HALF_LN2_INV

        # Store lse[b, h]
        tl.store(lse_ptr + b * NUM_QO_HEADS + h, lse_val)

        # Phase C: compute output vector out[b, h, :] = sum_i attn_i * v_i, where attn_i = exp(s - lse_val)
        out_vec = tl.zeros([HEAD_DIM], dtype=tl.float32)
        for i in range(NUM_TOKS):
            mask_i = i < num_tokens_actual
            idx = tl.load(kv_indices_ptr + start + i, mask=mask_i, other=0)  # int32
            k_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM
            v_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM

            k_vec = tl.load(k_ptr + k_off, mask=mask_i, other=0.0)
            v_vec = tl.load(v_ptr + v_off, mask=mask_i, other=0.0)

            logits = tl.sum(q_vec * k_vec, axis=0)
            s = logits * sm_scale

            if mask_i:
                attn = tl.exp(s - lse_val)
                out_vec += attn * v_vec

        # Store output[b, h, :]
        tl.store(out_ptr + b * NUM_QO_HEADS * HEAD_DIM + h * HEAD_DIM + tl.arange(0, HEAD_DIM), out_vec, mask=True)


class ModelNew(torch.nn.Module):
    def forward(self, q, k_cache, v_cache, kv_indptr, kv_indices, sm_scale):
        # Ensure Triton availability
        if not TRITON_AVAILABLE:
            # Fallback to PyTorch computation if Triton is not available
            # (This is for safety; the evaluator uses Triton environment.)
            # However, to meet the requirement strictly, we should not reach here.
            raise RuntimeError("Triton is not available")

        # Device and dtype handling
        device = q.device
        assert q.is_cuda and k_cache.is_cuda and v_cache.is_cuda and kv_indptr.is_cuda and kv_indices.is_cuda, \
            "All tensors must be CUDA tensors for Triton execution"
        assert q.dtype == torch.bfloat16 and k_cache.dtype == torch.bfloat16 and v_cache.dtype == torch.bfloat16, \
            "Inputs must be bfloat16 as per original code"
        assert kv_indptr.dtype == torch.int32 and kv_indices.dtype == torch.int32

        # Shapes
        batch_size = q.shape[0]
        num_qo_heads = q.shape[1]
        head_dim = q.shape[2]
        num_pages = k_cache.shape[0]
        num_kv_heads = k_cache.shape[2]

        # Constants
        NUM_QO_HEADS = num_qo_heads  # 32
        NUM_KV_HEADS = num_kv_heads  # 8
        HEAD_DIM = head_dim          # 128
        # Upper bound for tokens per batch: large to cover all workloads
        NUM_TOKS = 1 << 20           # 1,048,576
        HALF_LN2_INV = 1.4426950408889634  # 1 / ln(2)

        # Make inputs contiguous and cast to float32 for compute
        q32 = q.contiguous().to(torch.float32)
        k32 = k_cache.contiguous().to(torch.float32)
        v32 = v_cache.contiguous().to(torch.float32)
        kv_indptr = kv_indptr.contiguous()
        kv_indices = kv_indices.contiguous()

        # Allocate output and lse
        output = torch.empty((batch_size, num_qo_heads, head_dim), dtype=torch.float32, device=device)
        lse = torch.empty((batch_size, num_qo_heads), dtype=torch.float32, device=device)

        # Launch Triton kernel: one program per (b, h)
        grid = (batch_size, num_qo_heads)
        _attention_bh_kernel[grid](
            q32, k32, v32, kv_indptr, kv_indices, output, lse, sm_scale,
            batch_size, NUM_QO_HEADS, NUM_KV_HEADS, HEAD_DIM, NUM_TOKS, HALF_LN2_INV,
            num_warps=4, num_stages=2
        )

        # Return output in bfloat16 (to match original), and lse in float32
        return output.to(torch.bfloat16), lse

        k_ptr,                 # *float32, shape [NUM_PAGES, NUM_KV_HEADS, HEAD_DIM]

        NUM_QO_HEADS: tl.constexpr,
        NUM_KV_HEADS: tl.constexpr,
        HEAD_DIM: tl.constexpr,
        NUM_TOKS: tl.constexpr,          # upper bound on tokens per batch (e.g., 1<<20)
        HALF_LN2_INV: tl.constexpr,      # 1 / ln(2) = 1.442695...
    ):
        # program ids: one program per (batch, query head)
        b = tl.program_id(0)  # int
        h = tl.program_id(1)  # int

        # GQA mapping: kv_head = h // (32 // 8) = h // 4
        kv_ratio = NUM_QO_HEADS // NUM_KV_HEADS
        kv_head = h // kv_ratio  # 0..7

        # Determine token range for this batch
        start = tl.load(kv_indptr_ptr + b)              # int32
        end = tl.load(kv_indptr_ptr + b + 1)           # int32
        num_tokens_actual = end - start                # int32

        # Load q[h] vector
        q_vec = tl.load(q_ptr + h * HEAD_DIM + tl.arange(0, HEAD_DIM))  # [HEAD_DIM], float32

        # Pass 1: compute max and sum(exp(s - max)) across tokens
        max_s = tl.full((), -1.0e20, tl.float32)  # scalar
        sum_exp = tl.zeros((), tl.float32)        # scalar

            mask_i = i < num_tokens_actual
            idx = tl.load(kv_indices_ptr + start + i, mask=mask_i, other=0)  # int32 token index

            # Offsets for k and v rows

            v_off = idx * NUM_KV_HEADS * HEAD_DIM + kv_head * HEAD_DIM

            # Load k_vec and v_vec (masked)
            k_vec = tl.load(k_ptr + k_off, mask=mask_i, other=0.0)  # [HEAD_DIM], float32
            v_vec = tl.load(v_ptr + v_off, mask=mask_i, other=0.0)  # [HEAD_DIM], float32

            # Dot product: scalar logits
            logits = tl.sum(q_vec * k_vec, axis=0)  # scalar float32
            s = logits * sm_scale

                sum_exp += tl.exp(s - max_s)

        tl.store(lse_ptr + b * NUM_QO_HEADS + h, lse_val)
