Detailed diagnosis, root cause, and plan

- The repeated “too many values to unpack (expected 3)” error points to a host-side shape handling bug. In the original PyTorch code, run(...): the function body assumes the input q has shape (batch_size, num_qo_heads, head_dim) and asserts num_qo_heads == 32, num_kv_heads == 8, head_dim == 128. In many evaluation harnesses, these assumptions may not hold; if q is not a 3D tensor with exactly 3 dimensions, accessing q.shape and attempting to unpack it to three variables can fail.

- In the previous submission, even though we passed B, Nq, Nkv, D to Triton, the error persisted. This suggests that at least one of the tensor shapes used in forward was not 3D or was non-contiguous, causing q.shape or k_cache.shape to not yield a 3-tuple. The fix is to:
  - Ensure q, k_cache, v_cache, kv_indptr, kv_indices are explicitly made contiguous.
  - In forward, only unpack 3-tuples from tensors that are guaranteed to be 3D and contiguous, or use the explicitly passed shape constants. To be robust, we will remove all hard assertions and only rely on the passed shape constants for Triton kernels.

- Triton kernels:
  - We will keep two kernels:
    1) lse_kernel: one program per (b, h), iterates over tokens, computes scaled attention scores, accumulates m and sum_exp for logsumexp, stores lse[b, h] = log(sum_exp) + m, then divided by log(2) to match the original.
    2) output_kernel: one program per (b, h), recomputes m and sum_exp, computes softmax, then computes out[b, h, :] = softmax @ v_selected by looping over tokens and accumulating soft_i * v_i[j]. Output is stored as bfloat16.
  - We will use while loops (supported in Triton) to handle dynamic T. This avoids potential issues with tl.arange over runtime lengths. The GQA mapping kv_head = h // (Nq // Nkv) generalizes to any Nq and Nkv.

Performance considerations
- While loop-based kernels are simpler and correct; they may not be the fastest for very large T. However, given the diverse and sometimes large T values in the provided axes (up to ~50k), this approach aims for correctness first. After correctness is established, further speedups can be explored by:
  - Chunking tokens (BLOCK_T) and vectorizing reductions for m and sum_exp.
  - Fusing kernels to avoid recomputation.
  - Using tl.static_range and tl.multiple_of where applicable (though D is dynamic here).

import math
import torch
import triton
import triton.language as tl


@triton.jit
def lse_kernel(
    q_ptr,          # *bf16, [B, Nq, D]
    k_ptr,          # *bf16, [Np, Nkv, D]
    indptr_ptr,     # *i32,  [B+1]
    indices_ptr,    # *i32,  [T_total]
    sm_scale,       # f32
    lse_ptr,        # *f32,  [B, Nq]
    B: tl.constexpr,          # batch size
    Nq: tl.constexpr,         # num_qo_heads
    Nkv: tl.constexpr,        # num_kv_heads
    D: tl.constexpr,          # head_dim
    gqa_ratio: tl.constexpr,  # Nq // Nkv (e.g., 4)
    stride_q_b, stride_q_h, stride_q_d,
):
    # one program per (b, h)
    pid = tl.program_id(0)
    b = pid // Nq
    h = pid % Nq
    kv_head = h // gqa_ratio  # GQA mapping

    # compute start/end for this batch b
    start = tl.load(indptr_ptr + b)         # int32
    end = tl.load(indptr_ptr + b + 1)       # int32
    T = end - start

    # vector q[b, h, :]
    q_base = q_ptr + b * stride_q_b + h * stride_q_h
    q_vec = tl.load(q_base + tl.arange(0, D) * stride_q_d).to(tl.float32)  # [D], f32

    # accumulate max and sum_exp for logsumexp
    m = tl.full((), -float("inf"), dtype=tl.float32)
    sum_exp = tl.zeros((), dtype=tl.float32)

    i = 0
    while i < T:
        idx = tl.load(indices_ptr + start + i).to(tl.int32)  # token index in [0, Np)
        k_base = k_ptr + idx * (Nkv * D) + kv_head * D
        k_i = tl.load(k_base + tl.arange(0, D) * 1).to(tl.float32)  # [D], f32
        attn = tl.sum(q_vec * k_i, axis=0)  # scalar
        scaled = attn * sm_scale
        m = tl.maximum(m, scaled)
        exp_term = tl.exp(scaled - m)
        sum_exp += exp_term
        i += 1

    # lse = log(sum_exp) + m; divide by log(2) to match original
    log2 = 0.6931471805599453
    lse_val = tl.log(sum_exp) + m
    tl.store(lse_ptr + b * Nq + h, lse_val / log2)


@triton.jit
def output_kernel(

    k_ptr,          # *bf16, [Np, Nkv, D]

    indptr_ptr,     # *i32,  [B+1]

    sm_scale,       # f32

    out_ptr,        # *bf16, [B, Nq, D]
    B: tl.constexpr,          # batch size
    Nq: tl.constexpr,         # num_qo_heads
    Nkv: tl.constexpr,        # num_kv_heads
    D: tl.constexpr,          # head_dim
    gqa_ratio: tl.constexpr,  # Nq // Nkv
    stride_q_b, stride_q_h, stride_q_d,
    stride_k_p, stride_k_h, stride_k_d,
    stride_v_p, stride_v_h, stride_v_d,
    stride_out_b, stride_out_h, stride_out_d,
):

    pid = tl.program_id(0)
    b = pid // Nq
    h = pid % Nq

    # load q[b, h, :]
    q_base = q_ptr + b * stride_q_b + h * stride_q_h
    q_vec = tl.load(q_base + tl.arange(0, D) * stride_q_d).to(tl.float32)  # [D], f32

    end = tl.load(indptr_ptr + b + 1)       # int32
    T = end - start

    # load lse[b, h] and recompute m and sum_exp for softmax

        sum_exp += exp_term
        i += 1

    # Now compute output vector: out[b, h, :] = softmax @ v_selected

    i = 0
    while i < T:

        i += 1

    out_base = out_ptr + b * stride_out_b + h * stride_out_h

- The original Model.forward computes, for each batch b and each query head h:
  - Determine the set of token indices within the window kv_indices[kv_indptr[b]:kv_indptr[b+1]] with T = end - start.
  - For each token i in the window:
    - Use kv_head = h // (Nq // Nkv) (GQA mapping). With Nq=32, Nkv=8, kv_head = h // 4.
    - Compute attn_i = dot(q[b, h], k_cache[token_indices[start+i], kv_head]) where q, k_cache are bfloat16; we cast to float32 for compute.
    - Scale: scaled_i = attn_i * sm_scale. Note: sm_scale = 1/sqrt(128) in the provided get_inputs. The original code uses this scale; no extra normalization by D elsewhere.
  - Compute logsumexp in base 2: m = max(scaled), sum_exp = sum(exp(scaled - m)), lse = log(sum_exp) + m, then divide by log(2).

  - Compute output vector: out[b, h, :] = sum_i soft_i * v_cache[token_indices[start+i], kv_head].
  - Store output[b, h, :] as bfloat16; lse[b, h] as float32.
