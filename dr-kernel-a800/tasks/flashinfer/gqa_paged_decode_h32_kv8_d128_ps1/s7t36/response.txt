Key insights and constraints

- We can’t use torch ops (matmul, softmax, etc.) in host code; all numeric computation must be inside Triton kernels. However, we can perform host-side setup and tensor allocation.
- The original logic:
  - For each batch b and query head h, consider token indices in [start, end) where start = kv_indptr[b], end = kv_indptr[b+1].
  - Compute attn_i = dot(q[b, h], k_cache[token_indices[start+i], kv_head]) for each token i, scale by sm_scale, compute logsumexp (m = max, sum_exp = sum exp(scaled - m)), then lse = log(sum_exp) + m, divided by log(2).
  - Softmax = exp(scaled - m) / sum_exp, and output[b, h, :] = softmax @ v_cache[token_indices[start+i], kv_head].
- GQA mapping: kv_head = h // (Nq // Nkv). In the fixed version, Nq//Nkv = 4.

- Shape-unpacking errors: avoid accessing tensor.shape on non-3D or non-contiguous tensors. Make inputs contiguous and only then use .shape.

Optimization strategy

- Use Triton kernels:
  - lse_kernel: one program per (b, h), loop over tokens T dynamically using a while loop, compute m and sum_exp, store lse[b, h] = log(sum_exp) + m / log(2).
  - output_kernel: one program per (b, h), recompute m and sum_exp, compute softmax, and produce out[b, h, :] by looping tokens and accumulating soft_i * v_i[j]. We’ll write out in bfloat16.
- Ensure all computations are in float32, outputs in bfloat16. This matches the original output dtype and typical attention compute practice.

import math
import torch
import triton
import triton.language as tl


@triton.jit
def lse_kernel(
    q_ptr,          # *bf16, [B, Nq, D]
    k_ptr,          # *bf16, [Np, Nkv, D]
    indptr_ptr,     # *i32,  [B+1]
    indices_ptr,    # *i32,  [T_total]
    sm_scale,       # f32
    lse_ptr,        # *f32,  [B, Nq]
    B: tl.constexpr,          # batch size
    Nq: tl.constexpr,         # num_qo_heads
    Nkv: tl.constexpr,        # num_kv_heads
    D: tl.constexpr,          # head_dim
    gqa_ratio: tl.constexpr,  # Nq // Nkv (should be 4)
    stride_q_b, stride_q_h, stride_q_d,
):
    pid = tl.program_id(0)  # one program per (b, h)
    b = pid // Nq
    h = pid % Nq
    kv_head = h // gqa_ratio  # GQA mapping

    # Load q[b, h] vector of length D
    q_base = q_ptr + b * stride_q_b + h * stride_q_h
    q_vec = tl.load(q_base + tl.arange(0, D) * stride_q_d).to(tl.float32)  # [D], f32

    # Token window [start, end)
    start = tl.load(indptr_ptr + b)         # int32
    end = tl.load(indptr_ptr + b + 1)       # int32
    T = end - start

    # Accumulate m and sum_exp for logsumexp
    m = tl.full((), -float("inf"), dtype=tl.float32)
    sum_exp = tl.zeros((), dtype=tl.float32)

    i = 0
    while i < T:
        idx = tl.load(indices_ptr + start + i).to(tl.int32)
        # k_ptr is [Np, Nkv, D]; each row has stride Nkv*D in the p dimension
        k_base = k_ptr + idx * (Nkv * D) + kv_head * D
        k_i = tl.load(k_base + tl.arange(0, D) * 1).to(tl.float32)  # [D]
        attn = tl.sum(q_vec * k_i, axis=0)  # scalar
        scaled = attn * sm_scale
        m = tl.maximum(m, scaled)
        exp_term = tl.exp(scaled - m)
        sum_exp += exp_term
        i += 1

    # lse = log(sum_exp) + m; divide by log(2) to match original
    log2 = 0.6931471805599453
    lse_val = tl.log(sum_exp) + m
    tl.store(lse_ptr + b * Nq + h, lse_val / log2)

        B, Nq, D = q.shape
        Np, _, Nkv, _ = k_cache.shape  # middle 1 squeezed by user; we don't squeeze here

        # We need to infer kv_indptr consistency: last should be total tokens.

        grid = (B * Nq,)
        # Compute strides for q
        stride_q_b, stride_q_h, stride_q_d = q.stride()

        stride_k_p, stride_k_h, stride_k_d = k_cache.stride()

        stride_v_p, stride_v_h, stride_v_d = v_cache.stride()
        # Strides for out
        stride_out_b, stride_out_h, stride_out_d = output.stride()

        gqa_ratio = Nq // Nkv

            stride_v_p, stride_v_h, stride_v_d,
            stride_out_b, stride_out_h, stride_out_d,
            num_warps=4, num_stages=2,
        )

        return output, lse
