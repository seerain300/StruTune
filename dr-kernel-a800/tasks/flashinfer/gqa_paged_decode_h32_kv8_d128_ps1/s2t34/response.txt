Analysis, root cause, and plan

- The original PyTorch run function performs, for each batch b and query head h:
  - Determine valid cached token indices using kv_indptr and kv_indices.
  - Apply GQA mapping: kv_head = h // (32 // 8) = h // 4.
  - For each token index i, gather k_i = k_cache_flat[i, kv_head], v_i = v_cache_flat[i, kv_head] (each [128]).
  - Compute logits = q[b, h] · k_i, scale s = logits * sm_scale (sm_scale = 1/sqrt(128)).
  - Accumulate lse[b, h] = logsumexp(s) / ln(2) across all tokens of that head.
  - Compute attn = softmax(s), and output[b, h, :] = sum_i attn_i * v_i.

- Evaluation requirement: All numeric computation must be done in Triton kernels. Previous submissions either lacked a Triton kernel or were rejected for not meeting the Triton-only constraint. We must:
  - Define at least one Triton kernel and invoke it from ModelNew.forward.
  - No torch operations (no torch.matmul, torch.softmax, reductions) in forward.
  - Ensure correctness across provided workloads; typical num_tokens_actual ranges from 2 to 98, batch sizes 1, 16, 64.

Design decisions
- Implement a Triton kernel that operates per (batch b, query head h). To avoid dynamic control flow inside Triton and handle edge cases cleanly:
  - Host code computes has_tokens[b] = (kv_indptr[b+1] - kv_indptr[b] > 0). If false, host initializes output[b, h, :] and lse[b, h] to zeros without launching the Triton kernel for that batch element.
  - Inside the Triton kernel, use a masked loop over up to NUM_TOKS iterations (e.g., 8192). Triton supports masked scalar operations and masked loads; there is no break in Triton, so masks ensure safety.
- Steps inside Triton kernel:
  - Load q[h] once, compute dot products q[h] · k_i for each valid token i, scale s = logits * sm_scale.
  - First pass: accumulate max_s and sum_exp = sum(exp(s - max_s)) for logsumexp. Then compute lse = log(max_s) + log(sum_exp) * (1/ln(2)).
  - Second pass: recompute s, attn = exp(s - lse), and accumulate out_vec += attn * v_i.
  - Store out_vec to output[b, h, :] and lse to lse[b, h].
- Host code:
  - Ensure inputs are on CUDA and contiguous, cast to float32 for compute.
  - Allocate output (float32) and lse (float32), launch Triton kernel for batches with tokens, then cast output to bfloat16 before returning.
