Root causes in the previous submission:
- Using tl.constexpr parameters in kernels (q_len, L, H, head_dim_ckv, head_dim_kpe) caused Triton to treat them as compile-time constants; mixing them with runtime values and incorrect grid mapping led to compilation errors.
- I tried to do large per-program loops and reductions inside Triton. Triton prefers vectorized work along program_id axes; doing arbitrary dynamic reductions can be brittle. The safest approach is to:
  - Launch one program per (query position i, head h).
  - Use a second grid over token positions L for parts that need row-wise vectorization, if needed. In our case, we can compute everything per (i, h) with vectorized L in a single program, but Triton doesn’t support dynamic vector lengths that vary per launch; therefore, we’ll launch one program per (i, h) and loop over L and K dims inside the kernel. This avoids using tl.constexpr and ensures correctness.

Design recap (keeping original semantics):
- Given per-batch ranges:
  - qo_indptr[b:b+2] defines q_start..q_end (exclusive).
  - kv_indptr[b:b+2] defines token range [page_beg..page_end) and kv_indices gives per-token cache positions tok_idx in [0, num_pages).
- For each query i in [0, q_len), we:
  - Extract qn = q_nope[q_start + i, :, :] and qp = q_pe[q_start + i, :, :].
  - Form Kc = Kc_all[tok_idx] [L, 512], Kp = Kp_all[tok_idx] [L, 64].
  - Compute logits[h, l] = qn[h] @ Kc[l, :] + qp[h] @ Kp[l, :] for h in [0..H-1], l in [0..L-1].
  - Scale: logits_scaled[h, :] = logits[h, :] * sm_scale.
  - Causal mask: positions k > query_abs_pos are -inf, where query_abs_pos = (L - q_len) + i.
  - Compute lse[h] = logsumexp(logits_scaled[h, :]) / log(2.0).
  - attn[h, :] = softmax(logits_scaled[h, :]) along L.
  - out[i, h, :] = attn[h, :] @ Kc[:, :].T, then store into output[i, h, :].

   - Inside the program:

     - Store logits[i, h, l] = acc[l] to a 2D buffer logits_2d[q_len, H] where each element is a [L] vector. We’ll pass a flat pointer and index offset i*H + h. This avoids using tl.constexpr.

2) lse_and_attn_1d (fixed version):
   - Grid: (q_len, H). One program per (i, h).
   - Read logits_2d[i, h, :] vector of length L.
   - Scale by sm_scale.

   - Compute attn[h, :] = exp(logits_scaled - lse) / sum.

3) matmul_vec_by_mat:

def matmul_vec_by_mat(
    attn_ptr,            # *float32, [Q_seg, H, L] contiguous

):

    i = tl.program_id(0)  # query index
    h = tl.program_id(1)  # head index

    # Column range for this tile
    cols = tile * BLOCK_COL + tl.arange(0, BLOCK_COL)
    mask_cols = cols < head_dim_ckv

    # Initialize output vector for this (i, h)
    out_vec = tl.zeros([BLOCK_COL], dtype=tl.float32)

    # Loop over l in [0, L) and accumulate
    # Triton supports loops with runtime bounds
    for l in range(0, L):

    # Store results
    tl.store(out_ptr + i * (H * head_dim_ckv) + h * head_dim_ckv + cols, out_vec, mask=mask_cols)
