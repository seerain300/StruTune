Final analysis, root cause, and plan

- The evaluator flagged “decoy kernels” earlier because kernels were defined but not actually launched from ModelNew.forward. It also complained about torch ops that should be moved into Triton kernels. The primary requirement now: ModelNew.forward must invoke all Triton kernels and perform all heavy math in Triton. No torch operations should be used for elementwise or matmul-like operations.

- Original computation structure:
  - q: [L, 4, 128], k: [L, 4, 128], v: [L, 8, 128]
  - a: [L, 32], dt_bias: [8], b: [L, 32], A_log: [8]
  - Compute per (t, h where h in 0..7):
    - Expand q, k to [L, 8, 128] via repeat_interleave(2, dim=1) — we will implement this in Triton.
    - g[h] = exp(-exp(A_log[h]) * softplus(a_expanded[t, h] + dt_bias[h])) — implement softplus, sigmoid, and gate in Triton.
    - beta[h] = sigmoid(b[t, h]) — implement in Triton.
    - output[t, h, :] = scale * q_exp[t, h, :] @ state_new[h, :, :] — implement GEMV in Triton.
    - state_new[h, :, :] update: old_v = k_exp[t, h, :] @ state_old[h, :, :], new_v = beta[h] * v[t, h, :] + (1 - beta[h]) * old_v, then state_new[h, :, :] = g[h] * state_old[h, :, :] + k_exp[t, h, :]^T @ (new_v - old_v) — implement state update in Triton.

- We will define and launch the following Triton kernels from forward:
  - repeat_interleave_2: takes q/k [L, 4, 128] and writes q_exp/k_exp [L, 8, 128].
  - softplus_torch_like: computes softplus(a + dt_bias) with dt_bias[hh] broadcast across 2 heads — we need to compute softplus for h in 0..31, mapping h -> hh = h // 2.
  - sigmoid_torch_like: computes sigmoid(b) for b: [L, 32].
  - gate_exp_neg_exp: computes g[h] = exp(-exp(A_log[hh]) * softplus_out[h]) where hh = h // 2.
  - gemv_kernel: computes output[t, h, :] = scale * q_exp[t, h, :] @ state_new[h, :, :] over K=128.
  - state_update_kernel: updates state[h, :, :] using k_exp, v, beta, g, and current state.

- Forward function:
  - Ensure inputs are contiguous and on CUDA device.
  - Launch repeat_interleave_2 to produce q_exp and k_exp.
  - Launch softplus_torch_like and sigmoid_torch_like to produce softplus_out [L, 32] and beta [L, 32]; then launch gate_exp_neg_exp to produce g [L, 32]; map to 8 heads by storing hh = h // 2 for heads h in 0..7.
  - Launch gemv_kernel for each (t, h) to compute output [L, 8, 128].
  - Launch state_update_kernel for each (t, h) to update state.
  - Return output and new_state, in bfloat16 as in the original.

- Notes:
  - All elementwise and GEMV computations are done in Triton. Torch operations like .repeat_interleave are avoided in the host code; instead we implement repeats in Triton.
  - To satisfy the evaluator, we must actually invoke each kernel from forward. The previous rejections were due to not launching some kernels; we now ensure all listed kernels are launched.
  - The output shape matches the original: output [L, 8, 128] (bfloat16). We will allocate it as bfloat16, and inside kernels, compute in float32 and cast on store.

import triton
import triton.language as tl

# Triton kernel: repeat_interleave along dim=1 by factor 2
@triton.jit
def repeat_interleave_2(inp_ptr, out_ptr, L, C, K, FACTOR: tl.constexpr):
    # inp_ptr points to [L, C, K], out_ptr points to [L, C*FACTOR, K]
    pid = tl.program_id(0)  # flatten over L*C*FACTOR
    L_dim = C * FACTOR
    # decode indices
    h_orig = pid // (K * FACTOR)
    r = pid % (K * FACTOR)
    fact = r // K
    kk = r % K
    h = h_orig * FACTOR + fact
    src = inp_ptr + h_orig * (C * K) + kk
    dst = out_ptr + h * (C * K) + kk
    val = tl.load(src)
    tl.store(dst, val)


# Triton elementwise: softplus(x) = max(x, 0) + log(1 + exp(-|x|))
@triton.jit
def softplus_torch_like(x_ptr, out_ptr, N):
    offs = tl.arange(0, 1024)
    mask = offs < N
    x = tl.load(x_ptr + offs, mask=mask, other=0.0)
    absx = tl.abs(x)
    soft = tl.maximum(x, 0.0) + tl.log(1.0 + tl.exp(-absx))
    tl.store(out_ptr + offs, soft, mask=mask)


# Triton elementwise: sigmoid(x) = 1 / (1 + exp(-x))
@triton.jit
def sigmoid_torch_like(x_ptr, out_ptr, N):
    offs = tl.arange(0, 1024)
    mask = offs < N
    x = tl.load(x_ptr + offs, mask=mask, other=0.0)
    sig = 1.0 / (1.0 + tl.exp(-x))
    tl.store(out_ptr + offs, sig, mask=mask)


# Triton elementwise: compute g[h] = exp(-exp(A_log[hh]) * softplus_out[h]), hh = h // 2
@triton.jit
def gate_exp_neg_exp(g_ptr, soft_ptr, A_log_ptr, N):

    offs = tl.arange(0, 1024)
    mask = offs < N

    A = tl.load(A_log_ptr + hh, mask=mask, other=0.0)
    gate = tl.exp(-tl.exp(A) * soft)
    tl.store(g_ptr + offs, gate, mask=mask)


# Triton GEMV: out[h] = scale * q_exp[t, h, :] @ state[h, :, :] where q is [K], state is [V, K]
# We will call this kernel for each (t, h). We pass pointers to q_exp[t, h, :] and state_new[h, :, :] flattened.
@triton.jit
def gemv_kernel(q_ptr, state_ptr, out_ptr, K, V, scale):
    # Each program handles one (t, h)
    pid = tl.program_id(0)
    # q is [K], state is [V, K], out is [V]
    # We decode pid into (t, h) by caller providing grid=(L*8,)
    # However, here we keep it simple: one program per row; forward will launch grid over t and h separately.
    # Instead, we rely on forward to pass pointers; this kernel expects linear addressing:
    # q_ptr points to q_exp[t, h, :] vector; state_ptr points to state_new[h, :, :] as row.
    # Since we can't decode t,h here, we assume pid is over (t,h) as done in forward.
    # Implementation: load q vector, loop over V, and reduce over K.
    acc = tl.zeros([V], dtype=tl.float32)
    for j in range(0, V):
        # For each j, compute dot(q, state[j, :])
        dot = 0.0
        for k in range(0, K):
            qk = tl.load(q_ptr + k)
            state_jk = tl.load(state_ptr + j * K + k)
            dot += qk * state_jk
        acc[j] = dot * scale
    # Store acc
    for j in range(0, V):
        tl.store(out_ptr + j, acc[j])
