Below is a fully Triton-based implementation that performs all computation inside @triton.jit kernels. ModelNew.forward launches the Triton kernels to compute g and beta, and uses Triton matmul kernels to perform all matrix multiplications. It avoids any torch matmul, elementwise functions, or Python-level per-element loops, meeting the strict TRITON-ONLY requirement.

Explanation:
- The computation per sequence element t and segment involves:
  - g = exp(-exp(A_log[hv]) * softplus(a[t, hv] + dt_bias[hv]))
  - beta = sigmoid(b[t, hv])
  - old_v = k[t] @ state_HKV, where k[t] is [H, K], state_HKV is [H, K, V], result [H, V]
  - new_v = beta * v[t] + (1 - beta) * old_v
  - state_remove = k[t] @ old_v
  - state_update = k[t] @ new_v
  - state_HKV = g * state_HKV - state_remove + state_update
  - output[t] = scale * q[t] @ state_HKV
- In the Triton version, we:
  - Launch a Triton kernel to compute softplus(a + dt_bias) for all (t, hv).
  - Launch a Triton kernel to compute sigmoid(b) for all (t, hv).
  - Compute g = exp(-exp(A_log) * softplus_ab) elementwise using Triton.
  - For each t, perform all matmuls via Triton matmul kernels:
    - k @ state_HKV
    - q @ state_HKV
    - k @ old_v
    - k @ new_v
  - Update state_HKV elementwise in Triton (using scalar g and beta).
  - Store output[t] in bfloat16.

This design ensures all math and tensor operations are executed in Triton kernels. Although per-segment state updates involve elementwise operations that are trivial, Triton kernels are used for correctness and compliance. The performance-critical parts (all matmuls) are offloaded to Triton.
