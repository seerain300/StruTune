This is a challenging task because the original computation requires maintaining a per-segment 3D state tensor across many timesteps, updating it with multiple small GEMMs per t, and then producing an output. Triton kernels are great for elementwise math and matmul, but doing a fully dynamic, Python-level per-element loop with Triton to maintain a 3D tensor state in a single kernel is nontrivial because Triton kernels typically run as grids of programs and do not support arbitrary Python-side loops over device tensors inside the kernel. However, we can still provide a Triton-based implementation that uses Triton for heavy elementwise math and matmuls, and a carefully structured Triton kernel that processes one sequence segment entirely (looping over t inside the kernel) while maintaining the state as a device tensor. This satisfies the requirement that all computation happens in @triton.jit kernels launched by forward, and avoids any torch elementwise math or matmul in forward.

High-level plan:
- Define Triton kernels for:
  - softplus(x) = log(1 + exp(x)) per (t, hv)
  - sigmoid(z) = 1 / (1 + exp(-z)) per (t, hv)
  - g = exp(-exp(A_log[hv]) * softplus(a[t, hv] + dt_bias[hv])) per (t, hv)
  - matmul for small shapes: given A of shape [M,K], B of shape [K,N], produce C of shape [M,N] with tiling. We will use this to compute:
    - old_v = k[t] @ state_HKV
    - state_remove = k[t] @ old_v
    - state_update = k[t] @ new_v
    - output = scale * q[t] @ state_HKV
- In forward:
  - Launch Triton kernels to produce g and beta tensors on device (no torch elementwise).
  - For each segment defined by cu_seqlens (grid over segments), launch a Triton kernel that:
    - Loops over t from seq_start to seq_end (scalar loop inside the kernel), loads q[t], k[t], v[t], g[t], beta[t], reads/writes state_HKV using tl.load/tl.store, and performs all updates using Triton matmul kernels. This ensures that all computation inside the forward is done by Triton kernels. We avoid any torch matmul or elementwise math in forward.

- Shapes:
  - q: [T, H, K], k: [T, H, K], v: [T, H, V]
  - state_HKV: [H, K, V], output: [T, H, V]

  - For each t in [seq_start, seq_end):

        offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
        offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)
        acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)
        for k0 in range(0, K, BLOCK_K):
            offs_k = k0 + tl.arange(0, BLOCK_K)
            A_ptrs = A + offs_m[:, None] * stride_am + offs_k[None, :] * stride_ak
            B_ptrs = B + offs_k[:, None] * stride_bk + offs_n[None, :] * stride_bn
            A_mask = (offs_m[:, None] < M) & (offs_k[None, :] < K)
            B_mask = (offs_k[:, None] < K) & (offs_n[None, :] < N)
            A_tile = tl.load(A_ptrs, mask=A_mask, other=0.0)
            B_tile = tl.load(B_ptrs, mask=B_mask, other=0.0)
            acc += tl.dot(A_tile, B_tile)
        C_ptrs = C + offs_m[:, None] * stride_cm + offs_n[None, :] * stride_cn
        C_mask = (offs_m[:, None] < M) & (offs_n[None, :] < N)
        tl.store(C_ptrs, acc, mask=C_mask)
