Understanding the original PyTorch logic and the evaluation requirements

- The original Model.run function:
  - Given q: [L, 4, 128] (bfloat16), k: [L, 4, 128] (bfloat16), v: [L, 8, 128] (bfloat16), state: [S, 8, 128, 128] (float32), plus per-head parameters A_log: [8] (float32), a: [L, 8] (bfloat16), dt_bias: [8] (float32), b: [L, 8] (bfloat16), cu_seqlens: [S+1] (int64), scale: float.
  - It computes for each sequence segment and each time step t:
    - Gate g per head: g = exp(-exp(A_log) * softplus(a_expanded + dt_bias_expanded)) where a_expanded and dt_bias_expanded go across 32 columns (the code repeats_interleave to get 8 heads). The output uses only the first 8 expanded heads corresponding to original 4 heads.
    - beta = sigmoid(b_expanded).
    - q_exp and k_exp are made by repeating 4 heads to 8 via repeat_interleave(2) along dim=1, giving [L, 8, 128].
    - The code updates state per segment and produces output[t, h, :] = scale * q_exp[t, h, :] @ state_new[h, :, :].
  - Output shape: [L, H, V] with H=8, V=128 (bfloat16).
  - State updates are per segment and per head, using einsum-like operations, but the final output is produced by GEMV on q_exp and state_new.

- Evaluation requirement:
  - Provide ModelNew whose forward invokes Triton kernels. No torch ops should perform the actual math. Previously submitted kernels were defined but not launched, which caused rejections. We must actually call @triton.jit kernels from ModelNew.forward, including elementwise kernels and GEMV.

Key points for correctness and Triton usage

- We must replicate exactly the output tensor generation and per-segment state updates, but the most involved math should be done in Triton:
  - Elementwise: softplus on (a + dt_bias), sigmoid on b, exp on A_log. These must be computed via Triton kernels and results used thereafter.
  - GEMV: output[t, h, :] = scale * q_exp[t, h, :] @ state_new[h, :, :]. Implement as a Triton kernel that takes q_vec[K] and state[H, K] and produces out[H].
  - State update: For each (segment, t), given q_exp[t], k_exp[t], v[t], current state_old[h, :, :], compute:
    - old_v[h, :] = k_exp[t, h, :] @ state_old[h, :, :]
    - new_v[h, :] = beta[h] * v[t, h, :] + (1 - beta[h]) * old_v[h, :]

The reference uses einsum with repeated indices; however, since k @ state_old produces a [128] vector per head h, the operations reduce to elementwise and dot products. We’ll implement the clear parts: elementwise beta*v, elementwise addition, and the two dot products (k^T @ old_v and k^T @ new_v) using Triton reduction kernels.

- Dtypes:
  - q, k, v are bfloat16; A_log, dt_bias, a, b are float32; state is float32. We can compute g and beta in float32 for stability, then use them in Triton kernels. Triton can handle bf16, but for simplicity we’ll compute using float32 and let Triton do elementwise arithmetic; GEMV can operate on float32/float16, and we’ll cast appropriately.

- Performance:

For small H and K, this is acceptable, and it ensures Triton kernels are actually invoked.     # softplus(x) = max(x, 0) + log(1 + exp(-|x|))
    absx = tl.abs(x)
    soft = tl.maximum(x, 0.0) + tl.log(1.0 + tl.exp(-absx))
    tl.store(out_ptr + offs, soft, mask=mask)

@triton.jit
def sigmoid_torch_like(x_ptr, out_ptr, N):
    # Sigmoid: 1 / (1 + exp(-x))
    offs = tl.arange(0, 1024)
    mask = offs < N
    x = tl.load(x_ptr + offs, mask=mask, other=0.0)
    sig = 1.0 / (1.0 + tl.exp(-x))
    tl.store(out_ptr + offs, sig, mask=mask)

# GEMV: out[j] = sum_i q[i] * state[j, i], q: [K], state: [V, K], out: [V]
@triton.jit
def gemv_kernel(q_ptr, state_ptr, out_ptr, K, V, scale, BLOCK_K: tl.constexpr, BLOCK_OUT: tl.constexpr):
    # q_ptr: [K], state_ptr: [V*K] (row-major), out_ptr: [V]
    num_tiles = tl.cdiv(K, BLOCK_K)
    acc = tl.zeros((BLOCK_OUT,), dtype=tl.float32)
    for tile in range(0, num_tiles):
        k_offs = tile * BLOCK_K + tl.arange(0, BLOCK_K)
        mask_k = k_offs < K
        q_vals = tl.load(q_ptr + k_offs, mask=mask_k, other=0.0)
        for j in range(0, BLOCK_OUT):
            j_idx = j
            state_row_ptr = state_ptr + j_idx * K + k_offs
            state_vals = tl.load(state_row_ptr, mask=mask_k, other=0.0)
            acc[j] += tl.sum(q_vals * state_vals, axis=0)
    acc = acc * scale
    out_offs = tl.arange(0, BLOCK_OUT)
    mask_out = out_offs < V
    tl.store(out_ptr + out_offs, acc, mask=mask_out)
