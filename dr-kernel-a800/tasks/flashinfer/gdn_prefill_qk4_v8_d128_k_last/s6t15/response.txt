Explanation and plan
- Original run semantics:
  - For each sequence, iterate over timesteps t in [0, seq_len):
    - Compute per-head g and beta:
      g = exp(-exp(A_log) * softplus(a + dt_bias))
      beta = sigmoid(b)
    - Maintain state tensor per (head h, N, N) across t. In code, it’s stored as [H, N, K] but used as [H, K, N] via transposes.
    - Per t:
      - old_v = k[t] @ state_old, where k[t] is [H, K], state_old is [H, K, N], result old_v is [H, N]
      - new_v = beta * v[t] + (1 - beta) * old_v
      - state_remove = k[t]^T @ old_v -> [K, N]
      - state_update = k[t]^T @ new_v -> [K, N]
      - new_state = g * state_old + state_update - state_remove, shape [H, K, N]
    - Output per t:
      output[t] = scale * (q_exp[t] @ new_state), where q_exp[t] is [H, K], new_state is [H, K, N] -> output is [H, N]

- Triton kernels to implement:
  1) softplus_triton: elementwise softplus(x) = log(1 + exp(x))
  2) sigmoid_triton: elementwise sigmoid(x)
  3) compute_g_beta_kernel: elementwise compute g and beta for each (t, h)
  4) matmul_row_kernel: computes C[N] = A[K] @ B[N, N] for row vector A (q_exp[t, h, :]) times matrix B (new_state[h]), producing output per head.
  5) mm_k_state_kernel: computes per-head vector out[N] = k[t, h, :] @ state_old[h, :, :], for updating old_v.
  6) mm_kT_vec_kernel: computes per-kk scalar contrib = sum over n of k[t, kk, h] * old_v[h, n], for building state_remove.
  7) update_state_kernel: updates new_state[h, :, :] for all heads h by applying g * state_old + state_update - state_remove.

- Forward:
  - Ensure all math is in Triton:
    - Compute g and beta with compute_g_beta_kernel (uses softplus_triton and sigmoid_triton).
    - For each sequence and t:
      - Initialize state_old as provided or zeros.
      - Compute old_v via mm_k_state_kernel.
      - Compute new_v via torch elementwise (not allowed), but we can derive it from old_v and beta in Triton by precomputing beta per (t,h). However, v[t] is scalar per head; Triton elementwise kernel can apply beta * v to create new_v without torch. To keep pure Triton, we compute new_v by a Triton elementwise kernel with v_exp[:, h] broadcast.
      - Compute state_remove and state_update using mm_kT_vec_kernel (per kk) and accumulate into matrices for state_update and state_remove using Triton vectorized reductions or by constructing [K, N] via loop; Triton lacks clean per-kk dynamic vector writeback, so we instead compute final [H, K, N] update directly by applying g * state_old + (k^T @ new_v) - (k^T @ old_v). The simplest is to keep update in Triton per (h, kk) and construct final update tensor. Given Triton’s limitation of not returning large multi-dimensional arrays cleanly, we implement final state update by a Triton kernel that reads state_old and applies the closed-form: new_state[h, kk, n] = g[h] * state_old[h, kk, n] + sum_m new_v[h, m] * k[t, kk, h] - sum_m old_v[h, m] * k[t, kk, h].
      - Produce output per head via matmul_row_kernel using q_exp[t, h, :] @ new_state[h, :, :].

Note: Triton does not support returning multi-dimensional outputs easily from custom kernels, and mixing per-head indexing in Triton can be cumbersome. Therefore, the forward will orchestrate the sequence of Triton kernels:
- Use compute_g_beta_kernel to populate g and beta.
- For each t, do:
  - mm_k_state_kernel to get old_v (vector).
  - Elementwise Triton kernel to produce new_v per head (beta * v).
  - update_state_kernel to apply full state update per head.
  - matmul_row_kernel to produce output per head.
- Avoid any torch matmul or elementwise operations in the host.

# Triton kernels

@triton.jit
def softplus_triton(x_ptr, out_ptr, N: tl.int32):
    """
    Elementwise softplus(x) = log(1 + exp(x)).
    x_ptr: [N] float32
    out_ptr: [N] float32
    """
    pid = tl.program_id(0)
    x = tl.load(x_ptr + pid)
    y = tl.log(1.0 + tl.exp(x))
    tl.store(out_ptr + pid, y)


@triton.jit
def sigmoid_triton(x_ptr, out_ptr, N: tl.int32):
    """
    Elementwise sigmoid(x) = 1 / (1 + exp(-x)).
    x_ptr: [N] float32
    out_ptr: [N] float32
    """
    pid = tl.program_id(0)
    x = tl.load(x_ptr + pid)
    y = 1.0 / (1.0 + tl.exp(-x))
    tl.store(out_ptr + pid, y)


@triton.jit
def compute_g_beta_kernel(a_ptr, dt_bias_ptr, A_log_ptr, g_ptr, beta_ptr, T: tl.int32, H: tl.int32):

    Compute g and beta per (t, h):

      beta = sigmoid(b)
    a_ptr: [T*H] bfloat16 (flattened)
    dt_bias_ptr: [H] float32
    A_log_ptr: [H] float32
    g_ptr: [T*H] float32
    beta_ptr: [T*H] float32 (caller may prefill or we compute via sigmoid_triton)
    """
    pid = tl.program_id(0)
    t = pid // H
    h = pid % H
    if t >= T:
        return

@triton.jit
def matmul_row_kernel(A_ptr, B_ptr, C_ptr, K: tl.int32, N: tl.int32):
    """
    Compute C[N] = A[K] @ B[N, N], where:
      A_ptr: [K] float32 (row vector)
      B_ptr: [K, N] laid out row-major: base = ptr + kk*N + n
      C_ptr: [N] float32
    Note: This kernel expects A_ptr to be a row vector of length K, and B_ptr to be a 2D array [K, N] with contiguous layout.
    """
    pid = tl.program_id(0)  # n index
    n = pid
    if n >= N:
        return
    # acc
    acc = 0.0
    # Iterate over kk in [0, K)
    for kk in range(0, K):
        b_elem = tl.load(B_ptr + kk * N + n)
        a_elem = tl.load(A_ptr + kk)
        acc += a_elem * b_elem
    tl.store(C_ptr + n, acc)


@triton.jit
def mm_k_state_kernel(k_ptr, state_ptr, out_ptr, H: tl.int32, K: tl.int32, N: tl.int32):
    """
    Compute out[N] = k[H, K] @ state[H, K, N], per head h.
    k_ptr: flattened row [K], state_ptr: flattened [H*K*N], out_ptr: [N]
    We assume k is single row for a given h; the forward will iterate h and pass k[h, :] accordingly.
    """
    pid = tl.program_id(0)  # n index
    n = pid
    if n >= N:
        return
    acc = 0.0
    # We need to sum over kk in [0, K): k[kk] * state[h, kk, n]
    # k_ptr points to k[h, :]; state_ptr points to state[h, :, :]
    for kk in range(0, K):
        k_elem = tl.load(k_ptr + kk)
        # state[h, kk, n] element offset: h*(K*N) + kk*N + n
        state_elem = tl.load(state_ptr + h * (K * N) + kk * N + n)
        acc += k_elem * state_elem
    tl.store(out_ptr + n, acc)


@triton.jit
def mm_kT_vec_kernel(k_ptr, vec_ptr, contrib_ptr, H: tl.int32, K: tl.int32, N: tl.int32):
    """
    Compute contrib[K] = sum_n k[K, H] * vec[H, N] for each kk, i.e. k^T @ vec per kk.
    That is, for each kk, contrib[kk] = sum over h of k[kk, h] * vec[h].
    Here we compute a scalar contrib for each kk via per-kk loop in host; to keep Triton-only, we instead compute per-kk scalar via a small grid and store. In practice, Triton doesn't support returning vector easily, so we keep this as scalar contribution kernel.
    However, the forward will loop over kk and launch this kernel per kk and accumulate. For simplicity, we return scalar to host via reductions. To avoid host-side reduction, we can accumulate into a 1-element buffer using atomic_add, but Triton atomic_add requires pointers; we can use it if allowed. To stay pure Triton, we implement accumulators in torch in forward.
    """
    kk = tl.program_id(0)
    if kk >= K:
        return
    acc = 0.0
    for h in range(0, H):
        for n in range(0, N):
            k_elem = tl.load(k_ptr + kk * H + h)
            v_elem = tl.load(vec_ptr + h * N + n)
            acc += k_elem * v_elem
    # Store scalar contribution for kk
    tl.store(contrib_ptr + kk, acc)

@triton.jit
def update_state_elem_kernel(state_old_ptr, state_new_ptr, g_ptr, k_ptr, new_v_ptr, old_v_ptr,
                              H: tl.int32, K: tl.int32, N: tl.int32):
    """
    Elementwise update for state_new[h, kk, n] = g[h] * state_old[h, kk, n] + (sum_m new_v[h, m] * k[kk, h]) - (sum_m old_v[h, m] * k[kk, h]).
    We launch a 3D grid over (h, kk, n). H must be passed as constexpr for loop unrolling over H.
    """
    h = tl.program_id(0)
    kk = tl.program_id(1)
    n = tl.program_id(2)
    if (h >= H) or (kk >= K) or (n >= N):
        return
    # Load scalars and vectors
    g_h = tl.load(g_ptr + h)  # float32
    # state_old element at [h, kk, n]
    old_offset = h * (K * N) + kk * N + n
    state_old_val = tl.load(state_old_ptr + old_offset)
    # Compute contributions: sum over m of (new_v[h, m] * k[kk, h]) and (old_v[h, m] * k[kk, h])
    contrib_add = 0.0
    contrib_sub = 0.0
    # m in [0, N)
    for m in range(0, N):
        new_v_elem = tl.load(new_v_ptr + h * N + m)
        old_v_elem = tl.load(old_v_ptr + h * N + m)
        k_elem = tl.load(k_ptr + kk * H + h)  # k[kk, h]
        contrib_add += new_v_elem * k_elem
        contrib_sub += old_v_elem * k_elem
    new_state_val = state_old_val * g_h + contrib_add - contrib_sub
    tl.store(state_new_ptr + old_offset, new_state_val)

@triton.jit
def softplus_triton(x_ptr, out_ptr, N: tl.int32):
    """
    Elementwise softplus(x) = log(1 + exp(x)).
    x_ptr: [N] float32
    out_ptr: [N] float32
    """
    pid = tl.program_id(0)
    x = tl.load(x_ptr + pid)
    y = tl.log(1.0 + tl.exp(x))
    tl.store(out_ptr + pid, y)


@triton.jit
def sigmoid_triton(x_ptr, out_ptr, N: tl.int32):
    """
    Elementwise sigmoid(x) = 1 / (1 + exp(-x)).
    x_ptr: [N] float32
    out_ptr: [N] float32
    """
    pid = tl.program_id(0)
    x = tl.load(x_ptr + pid)
    y = 1.0 / (1.0 + tl.exp(-x))
    tl.store(out_ptr + pid, y)

def matmul_row_kernel(A_ptr, B_ptr, C_ptr, K: tl.int32, N: tl.int32):
    """
    Compute C[N] = A[K] @ B[N, N], where:
      A_ptr: [K] float32 (row vector)

        a_elem = tl.load(A_ptr + kk)
        acc += a_elem * b_elem
    tl.store(C_ptr + n, acc)
