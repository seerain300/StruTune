Careful analysis, root cause, and plan

- The evaluation environment asserts shapes for inputs:
  - q must be [L, 4, 128]
  - k must be [L, 4, 128]
  - v must be [L, 8, 128]
  The prior attempts showed runtime errors indicating the checker expected these exact shapes and rejected workloads where these checks failed. The most likely cause is that the test harness constructs inputs with these exact shapes, and any mismatch (e.g., due to get_inputs returning tensors of those shapes or the harness’ own expectations) will trigger the assertion. To prevent this, we must ensure that ModelNew.forward does not rely on get_inputs and instead uses the inputs passed directly to it, with robust shape handling.

- We must also ensure Triton kernels are actually invoked and that we perform the core computations with Triton:
  - softplus: s = softplus(a + dt_bias) where a has shape [L, 32], dt_bias has shape [8], yielding [L, 32]
  - sigmoid: beta = sigmoid(b) where b has shape [L, 32], yielding [L, 32]
  - gate g: g = exp(-exp(A_log) * s), with A_log shape [8], yielding [L, 32], and then mapping to 8 heads (0->0,1->0,2->1,3->1,4->2,5->2,6->3,7->3)
  - state update per (t, head h): old_v = k[t,h] @ state_old[h,:,:], new_v = beta[h] * v[t,h] + (1-beta[h]) * old_v, state_new[h,:,:] = g[h] * state_old[h,:,:] - k[t,h]^T @ old_v + k[t,h]^T @ new_v
  - output per (t, h): output[t,h,:] = scale * q[t,h] @ state_new[h,:,:]
  Here, q/k/v expand via repeat_interleave(2) from 4 heads to 8 heads: q_exp = q.repeat_interleave(2, dim=1), k_exp = k.repeat_interleave(2, dim=1). The original forward uses q_exp and k_exp to compute outputs; we will match this behavior.

- Triton kernel usage:
  - Implement three elementwise kernels for softplus, sigmoid, and gate g (compute exp(-exp(A_log) * s) and map to 8 heads).
  - Implement a GEMV kernel to compute q[t,h] @ state[h,:,:] for each (t,h). We use a 1D kernel that loops over K=128 and accumulates. Triton kernel grid will be (L*H,), and inside each program we decode t,h from program_id.
  - Implement a state update kernel for each (t,h): it updates state_new[h,:,:] in place. We will allocate state_new as float32 and perform the update. Triton kernel grid will be (L*H,), and inside we handle the 128x128 update via tiled loops over K and V.

- Important changes for correctness:
  - Do not call get_inputs in forward. Use the inputs passed to forward directly (q, k, v, state, A_log, a, dt_bias, b, cu_seqlens, scale). This avoids shape mismatches if the harness constructs different inputs.
  - Ensure all tensors are contiguous and on CUDA device. If not CUDA, we can still run, but the Triton kernels require CUDA. We will assert device compatibility and make tensors contiguous.
  - Launch all Triton kernels: softplus_torch_like for s, sigmoid_torch_like for beta, gate_kernel for g, and GEMV and state_update kernels for each (t,h).

- Performance notes:
  - Using a Triton GEMV kernel per (t,h) is acceptable here because H is small (8) and L is moderate; it demonstrates Triton usage. A more optimized approach could fuse multiple timesteps or use block matmul, but to keep code maintainable and robust, we will use GEMV per pair.
  - We will compute s and beta on host from Triton outputs (simple, robust), then use Triton to compute g, outputs, and state updates. This minimizes torch computation and ensures kernels are used.

# Triton elementwise kernels: must be launched from forward
@triton.jit
def softplus_torch_like(x_ptr, out_ptr, N):
    # x_ptr: 1D, out_ptr: 1D, N: number of elements
    BLOCK = 1024
    offs = tl.arange(0, BLOCK)
    mask = offs < N
    x = tl.load(x_ptr + offs, mask=mask, other=0.0)
    # numerically stable softplus: max(x, 0) + log(1 + exp(-|x|))
    absx = tl.abs(x)
    soft = tl.maximum(x, 0.0) + tl.log(1.0 + tl.exp(-absx))
    tl.store(out_ptr + offs, soft, mask=mask)

@triton.jit
def sigmoid_torch_like(x_ptr, out_ptr, N):
    # Sigmoid: 1 / (1 + exp(-x))
    BLOCK = 1024
    offs = tl.arange(0, BLOCK)
    mask = offs < N
    x = tl.load(x_ptr + offs, mask=mask, other=0.0)
    sig = 1.0 / (1.0 + tl.exp(-x))
    tl.store(out_ptr + offs, sig, mask=mask)

@triton.jit
def gate_kernel(a_expanded_ptr, dt_bias_ptr, A_log_ptr, g_ptr, L, C, num_heads, BLOCK: tl.constexpr):
    # a_expanded_ptr: [L*C], dt_bias_ptr: [C], A_log_ptr: [num_heads], g_ptr: [L*num_heads]
    # We assume num_heads == 8, C == 32. Each row of a_expanded is length C, and we map it to 8 heads.
    # For each row i in 0..L-1, and j in 0..C-1, head = j // 2.
    # Load a[i, j], dt_bias[j], A_log[head], compute gate value.
    # We'll launch with grid=(L,), and iterate j in tiles inside.
    for i in range(0, L):
        # base pointer for row i in a_expanded
        base = i * C
        for j in range(0, C, BLOCK):
            idx = j + tl.arange(0, BLOCK)
            mask = idx < C
            a_val = tl.load(a_expanded_ptr + base + idx, mask=mask, other=0.0)
            dt_val = tl.load(dt_bias_ptr + idx, mask=mask, other=0.0)
            # softplus of (a_val + dt_val)
            sp = tl.maximum(a_val + dt_val, 0.0) + tl.log(1.0 + tl.exp(-(a_val + dt_val)))
            head = idx // 2  # map 32 -> 8 heads (0->0,1->0,2->1,3->1,...)
            # load A_log for each head
            A = tl.load(A_log_ptr + head, mask=mask, other=0.0)
            # gate = exp(-exp(A) * softplus)
            gate_val = tl.exp(-tl.exp(A) * sp)
            # store gate per element (shape [L,32]), then we'll map to [L,8] on host
            tl.store(g_ptr + i * C + j + idx, gate_val, mask=mask)

功能逻辑回顾
- 原来的 run 函数做了以下工作：
  - 计算 g = exp(-exp(A_log) * softplus(a + dt_bias))，其中 a 的 shape 是 [L, 32]，dt_bias 的 shape 是 [8]。最终 g 的 shape 是 [L, 32]，然后通过 repeat_interleave(2) 映射到 8 个 heads：head 0 由列 0,1 得到相同的 g，head 1 由 2,3，head 2 由 4,5，head 3 由 6,7。

  - 对于每个序列的每个时间步 t，更新 state[h,:,:] (h in 0..7)：
    - old_v = k_exp[t,h,:] @ state_old[h,:,:]  (shape [128])
    - new_v = beta[h] * v[t,h,:] + (1 - beta[h]) * old_v
    - state_new[h,:,:] = g[h] * state_old[h,:,:] - k_exp[t,h,:]^T @ old_v + k_exp[t,h,:]^T @ new_v
  - 计算 output[t,h,:] = scale * q_exp[t,h,:] @ state_new[h,:,:]

- 最关键的是，forward 必须使用传入的 q,k,v, state, A_log, a, dt_bias, b, cu_seqlens, scale，并且不能创建不符合预期形状的张量，否则评估器会拒绝。同时，forward 必须调用 Triton 算子来完成所有 heavy computations。

解决方案
- 为了满足评估器的 strict requirement，我们需要：
  - 在 forward 中不调用 get_inputs，而是直接使用传入的参数，并且在 forward 中明确进行 shape 检查以防止失败。
  - 实现 Triton 算子来完成 softplus, sigmoid, gate g, GEMV, 和 state update：
    - softplus_torch_like: 用于计算 a + dt_bias 的 softplus -> [L,32]
    - sigmoid_torch_like: 用于计算 beta = sigmoid(b) -> [L,32]
    - gate_elementwise_kernel: 用于计算 per-element gate for [L,32]: g_el = exp(-exp(A_log[hh]) * softplus(a[t,j] + dt_bias[j])) mapped to [L,8] by averaging pairs, but since gate kernel is per-element, we compute per element and then map on host; to satisfy Triton usage, we implement a Triton gate kernel that writes [L,32], then we map to [L,8] in host.
    - gemv_torch_like: Triton GEMV kernel to compute q_vec @ state_row (q_vec: [K], state_row: [V,K]) for each (t,h). We will launch this for each (t,h).
    - state_update_kernel: Triton kernel to update state[h,:,:] per (t,h). This involves:
      - old_v = k_exp[t,h,:] @ state_old[h,:,:] via reduction over K tiles
      - new_v = beta[h] * v[t,h,:] + (1 - beta[h]) * old_v (elementwise)
      - update state_new[h,:,:] = g[h] * state_old[h,:,:] - k_exp[t,h,:]^T @ old_v + k_exp[t,h,:]^T @ new_v via reduction over K tiles
    - 这两个 Triton kernel都需要能够处理指针和多维数组的逻辑，我们将通过传递正确的 base pointers 和 strides 来实现。对于 state_new 的更新，我们将返回一个新 tensor state_out = state_new (不修改原 state) 以符合原函数的 output 返回结构。

- 性能考虑：
  - GEMV 每个 (t,h) 有 128x128 矩阵乘以 128 维向量，共 L*8 = 48 个 GEMV，在给定的例子中 L=6, H=8。使用 Triton GEMV kernel 进行计算是可以接受的，并且展示了 Triton 的使用。对于更大数据量，可以进一步融合计算以提高性能，但为了清晰性，我们使用 Triton GEMV 逐个计算。
  - state_update 也是 128x128 matmul-like operations; Triton kernel可以做 reduction over K tiles.

实施细节
- forward:
  - 检查 q, k, v 的 shape 符合 [L,4,128], [L,4,128], [L,8,128]。
  - 将 a, dt_bias, b 展平到 [L*32], [8], [L*32] 并计算 softplus 和 sigmoid 通过 Triton kernels，得到 s[L,32] 和 beta[L,32]。
  - 计算 g_el = exp(-exp(A_log) * s) 通过 Triton gate kernel，写入 g_el[L,32]，然后将每对列平均得到 g_mat[L,8] (head 0: avg col 0,1; head 1: avg 2,3; ...).
  - q_exp = q.repeat_interleave(2, dim=1), k_exp = k.repeat_interleave(2, dim=1) 生成 [L,8,128]。
  - state_out = torch.empty_like(state) 作为新的 state (不修改传入 state)。
  - 对于每个 t 和每个 h in 0..7:
    - 从 state_out 中提取 state_old[h,:,:] 为 [128,128] (float32)。
    - 从 q_exp, k_exp, v 中取出 q_vec = q_exp[t,h,:], k_vec = k_exp[t,h,:], v_vec = v[t,h,:] (128-dim).
    - 1) 计算 old_v = gemv(q_vec, state_old[h,:,:]) via Triton gemv kernel, produce [128] float32.
    - 2) 计算 new_v_vec = beta[h] * v_vec + (1 - beta[h]) * old_v via Triton elementwise kernel (write to float32 vector).
    - 3) 计算 update_vec = -k_vec^T @ old_v + k_vec^T @ new_v_vec via Triton reduction (128 sums) into a scalar (float32), then scale by g[h] from g_mat[t,h].
    - 4) state_new[h,:,:] = state_old[h,:,:] + scale * update_vec (float32).
    - 5) 计算 output_vec = scale * q_vec @ state_new[h,:,:] via Triton GEMV kernel, produce [128] float32, cast to bfloat16 and store in output[t,h,:].
  - 返回 output (L,8,128, bfloat16) 和 state_out (num_seqs,8,128,128, float32)。
  - 确保在 forward 中调用了所有 Triton kernels：softplus, sigmoid, gate, gemv, state update.

- Triton kernels:
  - softplus_torch_like: 1D grid over N = L*32, mask loads, compute softplus, store.
  - sigmoid_torch_like: 1D grid over N = L*32, mask, compute sigmoid, store.
  - gate_elementwise_kernel: 1D grid over N = L*32, compute per-element gate: sp = softplus(a+dt), g = exp(-exp(A_log[j//2]) * sp), store g to g_el buffer.
  - gemv_torch_like: grid = (L*8,), pid maps to (t,h), load q_vec from q_exp base, state row from state_out[h,:,:] base, loop over K=128 in blocks, accumulate into out vector, store.
  - state_update_kernel: grid = (L*8,), pid maps to (t,h). It:
    - Computes old_v via reduction over K tiles.
    - Computes new_v_vec elementwise in Triton.
    - Computes update scalar via reduction over K tiles: dot(k_vec, new_v_vec - old_v).
    - Applies update to state_out[h,:,:] in-place: state_out[h] += g[h] * scale * update.

- 重要的是，forward 不再调用 get_inputs；它只使用传入的参数并进行 shape 检查，然后调用 Triton kernels。

import torch
import triton
import triton.language as tl

# Triton elementwise kernels
@triton.jit
def softplus_torch_like(x_ptr, out_ptr, N):
    # x_ptr: [N], out_ptr: [N], compute softplus(x) = max(x, 0) + log(1 + exp(-|x|))
    BLOCK = 1024
    offs = tl.arange(0, BLOCK)
    mask = offs < N
    x = tl.load(x_ptr + offs, mask=mask, other=0.0)
    absx = tl.abs(x)
    soft = tl.maximum(x, 0.0) + tl.log(1.0 + tl.exp(-absx))
    tl.store(out_ptr + offs, soft, mask=mask)

@triton.jit
def sigmoid_torch_like(x_ptr, out_ptr, N):
    # Sigmoid: 1 / (1 + exp(-x))
    BLOCK = 1024
    offs = tl.arange(0, BLOCK)
    mask = offs < N
    x = tl.load(x_ptr + offs, mask=mask, other=0.0)
    sig = 1.0 / (1.0 + tl.exp(-x))
    tl.store(out_ptr + offs, sig, mask=mask)

@triton.jit
def gate_elementwise_kernel(a_ptr, dt_ptr, A_log_ptr, g_ptr, L, C, BLOCK: tl.constexpr):
    # Compute per-element gate for [L, 32] -> store to g_ptr [L*32]
    # a_ptr: [L*C], dt_ptr: [C], A_log_ptr: [8], g_ptr: [L*C]
    for i in range(0, L):
        base = i * C
        for j in range(0, C, BLOCK):
            idx = j + tl.arange(0, BLOCK)
            mask = idx < C
            a_val = tl.load(a_ptr + base + idx, mask=mask, other=0.0)
            dt_val = tl.load(dt_ptr + idx, mask=mask, other=0.0)
            sp = tl.maximum(a_val + dt_val, 0.0) + tl.log(1.0 + tl.exp(-(a_val + dt_val)))
            # head mapping: head = idx // 2 for the 32 -> 8 mapping
            head = idx // 2
            A = tl.load(A_log_ptr + head, mask=mask, other=0.0)
            gate = tl.exp(-tl.exp(A) * sp)
            tl.store(g_ptr + base + idx, gate, mask=mask)

@triton.jit
def gemv_torch_like(q_ptr, state_ptr, out_ptr, K, V, scale):
    # Compute out = scale * q @ state_row, where q: [K], state_row: [V,K] (row of [V,K] represented linearly)
    pid = tl.program_id(0)
    # We launch with grid=(L*8,), decode t,h:
    H = 8
    t = pid // H
    h = pid % H
    # q_vec base pointer
    q_base = q_ptr  # pointer to q_exp[t,h,:] as [K]
    # state row base pointer: state[h,:,:] as [V,K]
    state_base = state_ptr  # pointer to state_out[h,:,:] as [V*K]
    out_base = out_ptr  # [V]
    # Reduction over K
    acc = tl.zeros([V], dtype=tl.float32)
    # K is 128, V is 128; we use BLOCK=128 for simplicity
    for k_start in range(0, K, 128):
        k_offs = k_start + tl.arange(0, 128)
        q_vals = tl.load(q_base + k_offs, mask=k_offs < K, other=0.0)  # [128]
        # For each j in V, load state[j, k_offs] as [128], multiply, sum
        for j in range(0, V):
            state_addr = state_base + j * K + k_offs
            state_vals = tl.load(state_addr, mask=k_offs < K, other=0.0)  # [128]
            prod = q_vals * state_vals  # [128]
            acc[j] += tl.sum(prod, axis=0)
    acc = acc * scale
    # Store out
    for j in range(0, V):
        tl.store(out_base + j, acc[j])

@triton.jit
