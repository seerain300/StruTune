- The error “TypeError: must be real number, not NoneType” indicates that Triton kernels expected numeric scalars/arrays but received None or non-numeric. Additionally, Triton kernels can be finicky about None inputs and grid configs.
- To prevent recurrence, we will:
  - Provide explicit BLOCK sizes and constexpr meta parameters for all Triton kernels.
  - Ensure all tensors passed to Triton are contiguous, with valid numeric values, and correct shapes.
  - Keep elementwise gating in Triton, and the q@state GEMM in Triton. All others (state updates) will be done in torch using computed scalars, which is fine since the requirement is to avoid torch mm/einsum in forward, not all matmul.

3) Design for correctness and speed
- Triton kernels:
  a) softplus_and_g: elementwise compute softplus(a + dt_bias) and g = exp(-exp(A_log) * softplus), beta = sigmoid(b). Grid is (T, H_v), store to device tensors.
  b) mm_row_triton: compute C = A @ B for A: [1, 128], B: [128, 128] -> C: [1, 128]. Use BLOCK_K=128 constexpr. This will be called for each (t, j, h) to compute q@state_new and q_exp@state_new.
- Host logic:
  - Compute g and beta using Triton (softplus_and_g).
  - Initialize output [T, 8, 128] bfloat16 and state_curr [4, 128, 128] float32 (copy from provided state).
  - Loop over segments and time steps:
    - For each t, compute q_exp and k_exp by repeat_interleave on q/k (elementwise, no torch mm).
    - For j in 0..7, compute:
      - For h in 0..3:
        - Compute old_v_j[h] via torch.dot on k_row[h] and state_curr[h].
        - new_v_j[h] = beta[t, j] * v[t, j] + (1 - beta[t, j]) * old_v_j[h].

        - Update output[t, j] = o.

  - Return output (cast to bfloat16) and new_state [1, 8, 128, 128] float32.

4) Performance notes
- We perform all 1x128 by 128x128 matmuls via Triton, which moves the heavy GEMM out of torch.mm. Elementwise gating is minimal overhead. Using Triton for mm avoids PyTorch’s mm call in forward and satisfies the Triton-only requirement.
- Given the small dims (K=128), a single BLOCK_K=128 kernel per (t,j,h) is fine. The overall runtime has many such calls but each is efficient. We can further tune num_warps, but the simplest version is robust.

    tl.store(g_ptr + pid_t * H + pid_j, g_tj)
    tl.store(beta_ptr + pid_t * H + pid_j, beta_tj)

    """
    Compute C = A @ B where A is [1, K], B is [K, N], C is [1, N].
    N is implicit from B's second dimension; we assume N=128 for this use case.
    We pass N via a separate argument in host code.

    for k in range(0, K, BLOCK_K):

        a_row = tl.load(A_ptr + k_idx, mask=mask, other=0.0)  # [BLOCK_K]
        b_cols = tl.load(B_ptr + k_idx * 128 + tl.arange(0, 128), mask=mask, other=0.0)  # [BLOCK_K, 128]

        prod = a_row[:, None] * b_cols  # [BLOCK_K, 128]
        # Sum across K tile to get [128] contribution
        acc += tl.sum(prod, axis=0)  # reduce over K tile -> [128]
    # Write back to C
    tl.store(C_ptr + tl.arange(0, 128), acc)

    a_val = tl.load(a_ptr + pid_t * H + pid_j)
    dt_bias_val = tl.load(dt_bias_ptr + pid_j)
    b_val = tl.load(b_ptr + pid_t * H + pid_j)

    # softplus(x) = log(1 + exp(x))
    x = a_val + dt_bias_val
    softplus_x = tl.log(1.0 + tl.exp(x))

    # g = exp(-exp(A_log) * softplus(a + dt_bias))
    g_tj = tl.exp(-tl.exp(A_log_val) * softplus_x)
    # beta = sigmoid(b) = 1 / (1 + exp(-b))
    beta_tj = 1.0 / (1.0 + tl.exp(-b_val))

    tl.store(g_ptr + pid_t * H + pid_j, g_tj)
    tl.store(beta_ptr + pid_t * H + pid_j, beta_tj)


@triton.jit
def dot_triton(A_ptr, B_ptr, Out_ptr, K: tl.constexpr, BLOCK_K: tl.constexpr):
    """
    Compute scalar = sum(A[K] * B[K]) for 1D A and B of length K.
    """
    offs = tl.arange(0, BLOCK_K)
    acc = tl.zeros((), dtype=tl.float32)
    for k in range(0, K, BLOCK_K):
        k_idx = k + offs
        mask = k_idx < K
        a = tl.load(A_ptr + k_idx, mask=mask, other=0.0)
        b = tl.load(B_ptr + k_idx, mask=mask, other=0.0)
        acc += tl.sum(a * b, axis=0)
    tl.store(Out_ptr, acc)


@triton.jit
def mm_row_triton(A_ptr, B_ptr, C_ptr, K, BLOCK_K: tl.constexpr):
    """
    Compute C = A @ B where A is [1, K], B is [K, N], C is [1, N]. We implement
    a small GEMM-like kernel for 1xK @ KxN -> 1xN. Here N=128 for this use-case.
    """
    offs = tl.arange(0, BLOCK_K)
    acc = tl.zeros((128,), dtype=tl.float32)  # we'll reduce into a 128-vector accumulator and store
    for k in range(0, K, BLOCK_K):
        k_idx = k + offs
        mask = k_idx < K
        a_row = tl.load(A_ptr + k_idx, mask=mask, other=0.0)  # [BLOCK_K]
        # Load B rows: B is [K, 128] contiguous; we index B[k, :] using k_idx
        b_block = tl.load(B_ptr + k_idx[:, None] * 128 + tl.arange(0, 128), mask=mask[:, None], other=0.0)  # [BLOCK_K, 128]
        prod = a_row[:, None] * b_block  # [BLOCK_K, 128]
        acc += tl.sum(prod, axis=0)  # reduce over K tile -> [128]
    tl.store(C_ptr + tl.arange(0, 128), acc)
