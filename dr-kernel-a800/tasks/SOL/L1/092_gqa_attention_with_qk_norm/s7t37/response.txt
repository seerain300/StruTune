  - o_proj_weight: [H_out, K_out] — the original returns [B, S, 768], and in your setup, o_proj_weight has shape [96, 768]. This implies H_out=96 and K_out=768, i.e., output = linear(attn_output, o_proj_weight, None). However, the original code shows it returns [B, S, 768] without specifying attn_output. To ensure correctness for the given workloads, we will implement the full attention computation and then apply o_proj_weight to the computed attention output.
- Steps implemented in Triton:
  1) Linear projection for Q, K, V: compute dense F.linear-like results per (b, h, s). Grid over (B, H, S) and loop over K in tiles. This replaces F.linear for Q, K, V.
  2) RMSNorm for Q and K per row (b, h) over last dim S using q_norm_weight and k_norm_weight.
  3) Rotary Position Embedding (RoPE) for Q and K: split head_dim 128 into 64+64 and apply q_out = q*cos + [-q2, q1]*sin, similarly for K.
  4) Grouped-Query Attention (GQA) handling: we recompute K and V for all 96 heads in the attention kernel by mapping KVH to H via groups=12 (since 96 // 8 = 12). The attention kernel loops over KVH and groups to reconstruct K/V per target head.
  5) Attention computation:
     - For each (b, h) and tile of i (query positions), compute Q vector.
     - For each tile of j (key positions), reconstruct K and V vectors, compute scores = Q @ K^T * scaling, apply causal mask (upper triangle: i < j), softmax over j, accumulate output = softmax * V.
     - Store partial outputs into an out tensor of shape [B, S, H] (H=96).
  6) Output projection: out = linear(out[B, S, H], o_proj_weight[B, S, H_out=96] to [B, S, K_out=768]). Implemented in Triton with grid (B, H, S) looping over K_out=768 in tiles and accumulating.

This design ensures:
- Triton kernels are launched in forward.
- All computations are inside Triton (no torch ops).
- Dynamic handling of seq_len and batch_size via masked loads/stores and grids.
