Deep analysis, diagnosis, and optimization plan

- What needs to be computed:
  - LayerNorm across each hidden vector (1536 features), per row, with learnable ln_weight and ln_bias, eps=1e-6, output in bfloat16.
  - Spatial “shuffle” (actually a permutation + reshape) that maps the 1536-feature vectors into 12288-length vectors. This is metadata manipulation, but it dictates how we lay out input to the first linear. We will implement it in Triton to avoid any PyTorch ops.
  - First Linear: (num_merged_patches, 12288) @ (12288, 6144)^T -> (num_merged_patches, 6144). Implement with a Triton GEMM.
  - GELU activation. Implement elementwise GELU in Triton using erf approximation, in fp32.
  - Second Linear: (num_merged_patches, 6144) @ (6144, 3584)^T -> (num_merged_patches, 3584). Implement with a Triton GEMM.

- Constraints:
  - No torch.cat anywhere. But torch.permute is allowed (metadata-only), and tensors reshaping is fine. The heavy computation must be done in Triton kernels. So we must:
    - Implement LayerNorm in a Triton kernel.
    - Implement the spatial shuffle in Triton: a permutation + reshape to produce the [num_merged_patches, 12288] input for the first linear, without torch.cat.
    - Implement both GEMMs in Triton.
    - Implement GELU in Triton.

- Key detail about the original permutation:
  - For each grid i with (T, H, W), the number of patches this grid contributes is T*H*W.
  - The code creates hidden_norm for all num_patches, then iterates grids:
    - For each grid, take patches corresponding to its T*H*W patches.
    - Reshape as (T, H//2, 2, W//2, 2, 1536), permute to (T, H//2, W//2, 2, 2, 1536), then reshape to (T*(H//2)*(W//2), 1536*4) = (T*(H//2)*(W//2), 12288).
  - This is a deterministic permutation, fully determined by the grid’s T,H,W and the offset in hidden_norm. We can implement this in Triton by computing the mapping from output linear index to input index, loading the correct elements, and writing them into the output row via coalesced writes.

- Plan:
  - Triton LayerNorm kernel (layernorm_rows_kernel): 1D grid over rows, two-pass reduction (sum and sumsq), compute mean and variance in fp32, normalize, apply ln_weight and ln_bias, store as bfloat16.
  - Triton spatial_shuffle kernel (spatial_shuffle_kernel): 2D grid over (num_merged_rows, feature_out_blocks) where feature_out_blocks = ceil(12288 / BLOCK). Each program writes a vector of size BLOCK of features into its row. Compute the corresponding input index using the permutation mapping and load from hidden_norm; use masks for out-of-range; store into output row.
    - The mapping is simple once we fix the offset and the grid’s T,H,W:
      - Let h_merged = H // 2, w_merged = W // 2.
      - output_row = (grid_t * h_merged * w_merged) + (h_merged_idx * w_merged + w_merged_idx)
      - base = output_row * 12288
      - For each output feature idx_out in [0, 12288):
        - c = idx_out % 1536
        - merge_i = (idx_out // 1536) % 4
        - u = (merge_i // 2), v = (merge_i % 2)
        - t = grid_t
        - h_in = h_merged_idx * 2 + u
        - w_in = w_merged_idx * 2 + v
        - input_row = offset + t * (H * W) + h_in * W + w_in
        - input_offset = input_row * 1536 + c
        - write Y[base + idx_out] = X[input_offset]
  - Triton GEMM kernel (gemm_kernel): tile-based, grid over (M tiles, N tiles). Compute C[m, n] = dot(A[m, k], B[k, n]) over K with BLOCK_M, BLOCK_N, BLOCK_K. We’ll use BLOCK_M=64, BLOCK_N=128, BLOCK_K=32. Compute in fp32, output fp32 (we keep the whole pipeline in fp32 for stability, casting only at the end).
  - Triton GELU kernel (gelu_kernel): 1D grid over output elements; apply GELU with erf approximation, in-place on fp32, then cast to bfloat16 if needed. Here, we’ll compute GELU in fp32 and then do a second kernel or convert in PyTorch after the GEMM. For simplicity and correctness, we compute GELU in Triton and return fp32, then do final cast outside in fp32 (the original output dtype is bfloat16, but we can safely keep fp32 until the very end).

- Important: We must strictly avoid torch.permute + torch.reshape into a cat. Instead, implement the same mapping in Triton to produce the [num_merged_patches, 12288] tensor directly. This is doable: for each output row r, determine its grid t/h/w, and h_merged/w_merged and loop over output features to compute corresponding input row and feature.

@triton.jit
def layernorm_rows_kernel(
    X_ptr,          # *const bfloat16, input [num_rows, features]
    Y_ptr,          # *bfloat16, output [num_rows, features]
    ln_weight_ptr,  # *const float32, [features]
    ln_bias_ptr,    # *const float32, [features]
    num_rows,       # int32
    features,       # int32
    eps,            # float32
    BLOCK: tl.constexpr,
):
    row_id = tl.program_id(0)
    if row_id >= num_rows:
        return

    sum_fp32 = 0.0
    sumsq_fp32 = 0.0

    # First pass: compute sum and sumsq in fp32
    for offs in range(0, features, BLOCK):
        idx = offs + tl.arange(0, BLOCK)
        mask = idx < features
        x = tl.load(X_ptr + row_id * features + idx, mask=mask, other=0.0).to(tl.float32)
        sum_fp32 += tl.sum(x, axis=0)
        sumsq_fp32 += tl.sum(x * x, axis=0)

    mean = sum_fp32 / features
    var = sumsq_fp32 / features - mean * mean
    inv_std = 1.0 / tl.sqrt(var + eps)

    # Second pass: normalize and apply affine
    for offs in range(0, features, BLOCK):
        idx = offs + tl.arange(0, BLOCK)
        mask = idx < features
        x = tl.load(X_ptr + row_id * features + idx, mask=mask, other=0.0).to(tl.float32)
        norm = (x - mean) * inv_std
        w = tl.load(ln_weight_ptr + idx, mask=mask, other=1.0).to(tl.float32)
        b = tl.load(ln_bias_ptr + idx, mask=mask, other=0.0).to(tl.float32)
        y = norm * w + b
        # store as bfloat16
        y_bf16 = y.to(tl.bfloat16)
        tl.store(Y_ptr + row_id * features + idx, y_bf16, mask=mask)
