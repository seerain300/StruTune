Design overview:
- Triton conv3x3 (stride=1, padding=1):
  - Kernel processes a single output row for one (n, co) at a time, iterating over all input channels C and the 3x3 neighborhood. It accumulates into a vector acc[BLOCK] and stores results. We pass H and W as constexpr to allow static loops and mask only for out-of-bounds (though with padding=1 and H/W constexpr, accesses are safe).
  - Launch grid: (B, C_OUT, H). Each program computes one row output for a given batch n and output channel co. We choose BLOCK=64 or 128 for W to keep vectorization reasonable. This approach avoids dynamic H/W loops and reduces the chance of Triton compilation/runtime errors.

- Triton GroupNorm + SiLU:
  - groupnorm_sums_kernel: per (n, group), compute sum and sum of squares across all channels in the group and all H*W elements for that sample, using static loops over H, W, and C_PER_GROUP. Store sums and sumsq in global buffers.
  - groupnorm_invstd_kernel: compute invstd = 1/sqrt(var + eps) per (n, group).
  - groupnorm_silu_apply_kernel: normalize each x value with per-channel scale and bias (norm_weight, norm_bias), then apply SiLU: silu(x) = x * sigmoid(x). Use static loops for H, W, and C_PER_GROUP.

- Ensure num_groups divides C and tensors are contiguous. Use float32 compute for stability. Launch all kernels from ModelNew.forward.

This ensures Triton is doing the heavy lifting and all kernels are actually used, avoiding the “decoy” issue. Note: While this Triton conv is simpler and robust, it may not be as fast as cuDNN. Once correctness is confirmed, we can further tune BLOCK and tiling.
