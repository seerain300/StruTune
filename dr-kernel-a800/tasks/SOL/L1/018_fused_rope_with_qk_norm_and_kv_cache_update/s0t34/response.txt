# Triton kernel: compute cos and sin vectors per position for the first half_dim of features.
# Inputs:
#   pos_ptr: int64, shape [n_positions]
#   inv_ptr: float32, shape [half_dim] (half_dim=64 here)
#   cos_ptr: float32, shape [n_positions, head_dim]
#   sin_ptr: float32, shape [n_positions, head_dim]
# half_dim: int (64)
# head_dim: int (128)
@triton.jit
def compute_cos_sin_rows_kernel(pos_ptr, inv_ptr, cos_ptr, sin_ptr,
                                n_positions, half_dim, head_dim,
                                BLOCK_SIZE: tl.constexpr):
    pid = tl.program_id(0)
    if pid >= n_positions:
        return
    # Compute cos/sin for all features: first half via inv_ptr, second half replicated from first half (not used here).
    # We only need first half because rotation uses [0:64] and [64:128] is rotated; sin/cos are applied element-wise.
    for col in range(0, half_dim, BLOCK_SIZE):
        offs = col + tl.arange(0, BLOCK_SIZE)
        mask = offs < half_dim
        pos = tl.load(pos_ptr + pid)  # int64
        angle = pos.to(tl.float32) * inv_ptr[offs]  # [BLOCK_SIZE], fp32
        c = tl.cos(angle)
        s = tl.sin(angle)
        tl.store(cos_ptr + pid * head_dim + offs, c, mask=mask)
        tl.store(sin_ptr + pid * head_dim + offs, s, mask=mask)

# Triton kernel: apply rotation y = x * cos + rotate_half(x) * sin, where x is [rows, head_dim] viewed.
# Inputs:
#   x_ptr: float32, [rows, head_dim]
#   cos_ptr: float32, [rows, head_dim]
#   sin_ptr: float32, [rows, head_dim]
#   y_ptr: float32, [rows, head_dim]
@triton.jit
def apply_rotation_rows_kernel(x_ptr, cos_ptr, sin_ptr, y_ptr,
                                rows, head_dim,
                                BLOCK_SIZE: tl.constexpr):
    pid = tl.program_id(0)
    if pid >= rows:
        return
    for col in range(0, head_dim, BLOCK_SIZE):
        offs = col + tl.arange(0, BLOCK_SIZE)
        mask = offs < head_dim
        x = tl.load(x_ptr + pid * head_dim + offs, mask=mask, other=0.0)
        cos = tl.load(cos_ptr + pid * head_dim + offs, mask=mask, other=0.0)
        sin = tl.load(sin_ptr + pid * head_dim + offs, mask=mask, other=0.0)
        half = head_dim // 2
        first = x[:half]
        second = x[half:]
        rotated_half = -second + first  # rotate half for y = x * cos + rotate(x) * sin, where rotate(x) = cat([-x2], [x1])

        tl.store(y_ptr + pid * head_dim + offs, y, mask=mask)

  5) If pid corresponds to key (second grid launched for keys), store directly to key_cache at cache_position. For query, store to the output buffers. For value_cache, we don’t have value here, so we must not modify it.

- Avoid any torch computation in forward.
- Actually invoke Triton kernels (no decoys).
- Return (query_rotated, key_rotated, key_cache updated, value_cache updated with original value where possible). Note: value is not provided in get_inputs; the original run returns value unchanged. Since we cannot read value here, we must return value_cache unchanged. But the harness compares outputs, so we can assume value is available; still, the only way to satisfy “all computation by Triton” is to implement the cache updates for key_cache and use original value if needed. Since value isn’t passed, we can skip cache updates for value_cache. However, the original run updates value_cache with the original value; to keep correctness, we will return value_cache unchanged and note that in the absence of value tensor, we cannot update it here.

To be precise and safe, we will implement one Triton kernel that:
- Processes query rows (Bq*Hq*Tq) and applies RMSNorm + rotation, writing to query output buffer as bfloat16.

- Also performs cache updates for key_cache (since key is provided and we can rotate it). We don’t update value_cache because value isn’t passed; but the original run updates it, and since we cannot read value here, we return key_cache updated and value_cache unchanged.

We still need to use cache_position to update key_cache at the correct positions. Triton can do strided writes with simple arithmetic. We’ll pass cache_position as a 1D int64 tensor of length T (seq_len) and compute per (b,h) which positions to update.

This approach ensures:
- No torch computation in forward.
- Triton kernels actually invoked (no decoys).
