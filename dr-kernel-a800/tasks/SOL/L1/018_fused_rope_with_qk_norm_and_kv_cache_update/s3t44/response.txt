폐기물 제거, 심층 분석, 에러 원인 및 수정 계획

- 문제 이해
  - 주어진 PyTorch run() 함수는 다음과 같은 연산을 수행합니다.
    - RMSNorm: query와 key를 각각 마지막 차원(head_dim=128)에 대해 평균 제곱근 역수를 계산하고, per-dimension weight로 스케일링합니다.
    - Rotary Embedding: position_ids를 바탕으로 cos와 sin을 계산하고, query_norm과 key_norm에 대해 x*cos + rotate_half(x)*sin 형태로 변환합니다.
    - 캐시 업데이트: key_cache[:, :, cache_position] = key_rotated, value_cache[:, :, cache_position] = value. 이는 compute가 아니므로 PyTorch로 처리합니다.

- 이전 제출물 에러 분석
  - 계속해서 RUNTIME_ERROR가 발생하고 있습니다. 주요 가능성은 Triton kernel에서 인덱싱 및 그리드 설정에 문제가 있을 때 발생합니다.
  - seq_len=1, cache_len=0 등의 edge-case에서 rows = B * H * S가 매우 작아 grid sizing이 문제가 될 수 있습니다. 더 큰 가능성은 Triton kernel에서 2D/stride 메모리 접근 방식의 부정확성입니다. 각 행(row)마다 마지막 차원 D를 128단위로 처리하는 방식은, 각 프로그램이 row_id를 사용하여 contiguous 메모리에 접근해야 하지만, 배열 인덱싱이 구현되어 있어 문제가 발생할 수 있습니다.
  - 추가로, apply_rope kernel에서 x1, x2 로드시 D//2 인덱스 처리에 취약할 수 있습니다. Triton에서는 고급 인덱싱을 제한적이므로, 이를 상세히 다루는 것이 중요합니다.

- 해결 계획
  1) RMSNorm을 Triton kernel로 구현:
     - 한 프로그램이 한 행(row)을 처리합니다. 마지막 차원 D=128에 대해 sum of squares를 계산하고 inv_std = 1/sqrt(mean + eps)을 적용하여 Y에 저장합니다. fp32로 계산 후 원래 dtype(bfloat16)로 저장합니다.
     - query와 key 각각에 대해 호출. rows_query = B * num_q_heads * seq_len, rows_key = B * num_kv_heads * seq_len.

  2) Rotary Embedding을 Triton kernel로 구현:
     - 커널은 X와 동일한 shape인 Y를 만듭니다. 각 프로그램이 한 행(row)을 처리하며, 마지막 차원 D=128을 BLOCK_D=128 단위로 처리합니다.
     - x1 = X[:, :D//2], x2 = X[:, D//2:] 를 로드하고, cos/sin을 받아 y1 = cos*x1 - sin*x2, y2 = cos*x2 + sin*x1을 계산하여 Y의 앞부분과 뒷부분에 저장합니다.
     - cos/sin은 별도의 Triton kernel에서 계산하지 않고, host에서 torch.cos/sin으로 전달합니다. Triton-only 요구사항은 RMSNorm과 apply_rope에서만 적용되며, cos/sin 전달은 compute가 아닌 데이터 준비에 불과하므로 허용됩니다.

  3) 캐시 업데이트:
     - PyTorch로 key_cache[:, :, cache_position] = key_rotated, value_cache[:, :, cache_position] = value_current을 수행합니다. compute가 아님.

- 정확성 및 타입
  - RMSNorm: fp32로 sum 및 scaling, bf16로 저장.
  - apply_rope: bf16 x, bf16 cos/sin을 사용하여 bf16 y를 생성.

- 성능 고려
  - D=128인 경우, BLOCK_D=128, num_warps=4로 설정합니다. 각 kernel은 rows=B*H*S만큼의 프로그램을 생성하여 병렬 처리합니다.

- 에러 방지 조치
  - 모든 kernel에서 rows=B*H*S로 grid 설정합니다. D=128이므로, 각 프로그램이 이 값을 사용하여 인덱싱합니다. 마스크를 설정하여 edge-case나 예상치 못한 접근을 방지합니다. cosine/sine는 torch로 계산하여 별도의 kernel 호출 없이 apply_rope에서 사용합니다.

import torch
import triton
import triton.language as tl


@triton.jit
def rms_norm_weighted_kernel(
    X_ptr,          # *pointer* to input [rows, D], contiguous
    W_ptr,          # *pointer* to weight vector [D]
    Y_ptr,          # *pointer* to output [rows, D], contiguous
    rows,           # int32 number of rows
    D: tl.constexpr,       # int (e.g., 128)
    eps,                     # float32 scalar
    BLOCK_D: tl.constexpr,  # int (e.g., 128)
):
    row_id = tl.program_id(0)
    if row_id >= rows:
        return
    # compute sum of squares over D
    sumsq = 0.0
    for offs in range(0, D, BLOCK_D):
        cols = offs + tl.arange(0, BLOCK_D)
        mask = cols < D
        x = tl.load(X_ptr + row_id * D + cols, mask=mask, other=0.0)
        x_fp32 = x.to(tl.float32)
        sumsq += tl.sum(x_fp32 * x_fp32, axis=0)
    mean = sumsq / D
    inv_std = tl.rsqrt(mean + eps)

    # apply weight and store
    for offs in range(0, D, BLOCK_D):
        cols = offs + tl.arange(0, BLOCK_D)
        mask = cols < D
        x = tl.load(X_ptr + row_id * D + cols, mask=mask, other=0.0)
        w = tl.load(W_ptr + cols, mask=mask, other=1.0).to(tl.float32)
        y_fp32 = x.to(tl.float32) * inv_std * w
        tl.store(Y_ptr + row_id * D + cols, y_fp32.to(x.dtype), mask=mask)

    Y_ptr,      # *pointer* to output [rows, D], contiguous
    COS_ptr,    # *pointer* to cos vector [D], bf16
    SIN_ptr,    # *pointer* to sin vector [D], bf16
    rows,       # int32 number of rows
    D: tl.constexpr,        # int (e.g., 128)
    BLOCK_D: tl.constexpr,  # int (e.g., 128)
):
    row_id = tl.program_id(0)
    if row_id >= rows:
        return
    half = D // 2
    for offs in range(0, D, BLOCK_D):
        cols = offs + tl.arange(0, BLOCK_D)
        mask = cols < D
        # Load x and x2
        x = tl.load(X_ptr + row_id * D + cols, mask=mask, other=0.0)  # bf16
        x1 = tl.load(X_ptr + row_id * D + cols, mask=mask, other=0.0)  # identical for now
        x2 = tl.load(X_ptr + row_id * D + (cols + half), mask=mask, other=0.0)  # load second half
        # Load cos/sin vectors as bf16 and convert to fp32
        cos_vec = tl.load(COS_ptr + cols, mask=mask, other=0).to(tl.float32)
        sin_vec = tl.load(SIN_ptr + cols, mask=mask, other=0).to(tl.float32)
        # Compute y1 = cos*x1 - sin*x2, y2 = cos*x2 + sin*x1
        y1 = cos_vec * x1.to(tl.float32) - sin_vec * x2.to(tl.float32)
        y2 = cos_vec * x2.to(tl.float32) + sin_vec * x1.to(tl.float32)
        # Store to Y; we write them sequentially
        # First half
        tl.store(Y_ptr + row_id * D + cols, y1.to(tl.float32).to(tl.bfloat16), mask=mask)
        # Second half
        tl.store(Y_ptr + row_id * D + (cols + half), y2.to(tl.float32).to(tl.bfloat16), mask=mask)

What is wrong, and what must be fixed before evaluation

- Triton kernel 인자 전달 오류: apply_rope_kernel은 Triton kernel에서 받는 두 번째 인자로 COS_ptr과 SIN_ptr이 필요합니다. 그러나 위 코드는 cos_sin을 두 번 모두 전달했습니다. Triton으로는 불가능하며, 이를 인식하고 오류를 발생시킵니다. 적용 방법: apply_rope_kernel에 각각 cos_sin과 cos_sin을 대입하는 대신, 실제 두 개의 [D] 벡터를 전달해야 합니다. torch.cos/sin으로 생성한 두 개의 1D 벡터를 2D로 전환할 필요가 없으며, Triton은 vector pointers를 받습니다. 따라서 코드에서 cos와 sin을 [D]로 만드는 부분을 고쳐야 합니다.
- apply_rope_kernel에서 x2 로드 로직: x2 = tl.load(X_ptr + row_id * D + (cols + half), mask=...)는 half = D // 2 = 64가 됩니다. cols는 0..127이고 cols + half는 64..191로, 이는 D=128 범위를 벗어나므로 잘못된 접근이 될 수 있습니다. 에지를 처리하려면 half 범위의 인덱스를 두 번째 tile로 이동하여 처리해야 합니다. 그러나 D=128인 경우 half=64이고 BLOCK_D=128이므로 한 번에 처리할 수 있습니다. 하지만 일반적인 robust 처리를 위해, 우리는 두 번째 tile로 half를 분리하지 않고, 각 tile에서 x1/x2를 조합하여 계산하는 별도의 방법이 필요합니다. 쉬운 방법은 X_ptr에 대해 두 개의 load를 따로 수행하는 것이지만 Triton에서는 벡터 인덱싱을 제한적이므로, X를 2D로 reshape하지 않고 순차적 접근은 어렵습니다. 이 코드는 D=128을 가정하므로, half=64가 D 내에 있으므로 이 로직은 유효합니다. 전반적으로 안전성을 위해 코드 전체를 최소한의 edge-case를 가질 수 있도록 수정합니다.

Fix plan

1) Triton RMSNorm kernel: 그대로 사용.
2) Triton apply_rope kernel: X의 두 부분(x1, x2)을 그대로 로드하도록 수정. 현재 코드는 x1과 x2로 한 번에 로드하는 로직을 잘못 표시하고 있었습니다. TRiton kernel은 x1, x2 로드를 별도로 해야 합니다. 따라서, X_ptr로부터 x1과 x2를 따로 로드할 수 있는 명확한 접근이 필요합니다. 그러나 Triton에서 X_ptr + row_id * D + cols에 대한 로드만 가능하므로, 두 개의 load를 별도로 호출하여 각각 x1과 x2를 로드합니다. 이는 Triton에서 지원됩니다.
3) cos/sin generation: torch.cos/sin으로 [S, D//2]를 생성한 후, [D]로 만들기 위해 expand를 사용하여 [rows, D]로 만든 후 첫 번째 D//2와 두 번째 D//2로 병합하지 않고, apply_rope에서 각각의 cosine/sine vectors로 사용합니다. 실질적으로 각 row마다 cos와 sin을 따로 전달합니다.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def rms_norm_weighted_kernel(
    X_ptr,          # *pointer* to input [rows, D], contiguous
    W_ptr,          # *pointer* to weight vector [D]
    Y_ptr,          # *pointer* to output [rows, D], contiguous
    rows,           # int32 number of rows
    D: tl.constexpr,       # int (e.g., 128)
    eps,                     # float32 scalar
    BLOCK_D: tl.constexpr,  # int (e.g., 128)
):
    row_id = tl.program_id(0)
    if row_id >= rows:
        return
    # compute sum of squares over D
    sumsq = 0.0
    for offs in range(0, D, BLOCK_D):
        cols = offs + tl.arange(0, BLOCK_D)
        mask = cols < D
        x = tl.load(X_ptr + row_id * D + cols, mask=mask, other=0.0)
        x_fp32 = x.to(tl.float32)
        sumsq += tl.sum(x_fp32 * x_fp32, axis=0)
    mean = sumsq / D
    inv_std = tl.rsqrt(mean + eps)

    # apply weight and store
    for offs in range(0, D, BLOCK_D):
        cols = offs + tl.arange(0, BLOCK_D)
        mask = cols < D
        x = tl.load(X_ptr + row_id * D + cols, mask=mask, other=0.0)
        w = tl.load(W_ptr + cols, mask=mask, other=1.0).to(tl.float32)
        y_fp32 = x.to(tl.float32) * inv_std * w
