- Implement a Triton kernel rmsnorm_rotate_kernel:
  - Grid: one program per (b, q_head, s). We will allocate output query_out and compute the rotated query in Triton.
  - RMSNorm:
    - Load the query row vector (length D), compute sum of squares in float32, compute scale = 1 / sqrt((sum_sq / D) + eps).
    - Write normalized and scaled output: y = x * scale * q_norm_weight.
  - Rotary embedding (RotE):
    - Compute cos and sin vectors of length D from inv_freq using pos = cache_len + s:
      cos_vec[i] = 1 / sqrt(1 + inv_freq[i]^2), sin_vec[i] = inv_freq[i] / sqrt(1 + inv_freq[i]^2), for i < HALF; for i >= HALF, cos_vec[i] = cos_vec[i - HALF], sin_vec[i] = sin_vec[i - HALF].
    - Apply rotation: y' = y * cos_vec + rotate_half(y) * sin_vec, where rotate_half swaps and negates the second half.
  - Store y' to query_out.
- Forward:
  - Make query, q_norm_weight, and inv_freq contiguous. Allocate query_out = torch.empty_like(query).
  - Launch the Triton kernel with grid = (B * num_q_heads * seq_len,). Return query_out. We do not attempt to read/write cache tensors or position_ids in Triton, keeping it robust.
