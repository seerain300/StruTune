1) Original computation
- Inputs:
  - query: (B, N_q, S, D) with N_q=96, D=128.
  - key: (B, N_kv, S, D) with N_kv=8.
  - value: (B, N_kv, S, D).
  - position_ids: (B, S), int64, positions start at cache_len.
  - key_cache: (B, N_kv, max_pos, D), bf16 (we will use only the first S entries).
  - value_cache: (B, N_kv, max_pos, D), bf16 (we will use only the first S entries).
  - inv_freq: float32 tensor of length D//2 = 64, derived as 1.0 / (rope_theta ** (arange(0, D, 2) / D)).
  - rms_norm_eps: 1e-6.
- Steps:
  - RMSNorm over last dimension (D) for query and key: r = sqrt(mean(x^2) + eps); y = x / r (no affine).
  - Rotary Position Embedding:
    - For each token position pos, compute inv = [inv_freq, inv_freq] (length D).
    - emb = pos * inv; cos = cos(emb); sin = sin(emb).
    - Rotate: x1 = x[:, :D//2], x2 = x[:, D//2:], rotate_half(x) = [-x2, x1].
    - x_roped = x1 * cos[:D//2] + rotate_half(x) * sin[:D//2] (since cos/sin are duplicated in D).
  - Cache updates:
    - Overwrite key_cache[b, nk, cache_position[s], :] = key_rotated[b, nk, s, :].
    - Overwrite value_cache[b, nk, cache_position[s], :] = value[b, nk, s, :].

2) Triton kernel strategy
- RMSNorm kernel:
  - 1D grid over M = B*N_q*S rows (or B*N_kv*S for key). Each program handles one row of length D. Compute sum of squares in fp32, then scale. This is straightforward and performant.
- Rotation kernel:
  - 2D grid over (B, S). For each (b, s), compute cos and sin vectors of length D inside Triton:
    - pos = position_ids[b, s] as int32.
    - inv = [inv_freq, inv_freq] with length D (we load inv_freq[:64] twice). This is not a torch.cat on the host; we construct within Triton using two loads.
    - emb = pos * inv (elementwise).
    - cos_vec = cos(emb) and sin_vec = sin(emb) elementwise. Triton provides tl.cos and tl.sin.
    - Load the corresponding query or key row (b, n, s, :).
    - Compute x1 = x[:D//2], x2 = x[D//2:], rotated = -x2 * sin_vec[:D//2] + x1 * cos_vec[:D//2], and output row.
    - Store query_rotated and key_rotated.
  - This avoids any host-side torch.cos/torch.sin usage and ensures Triton performs the rotation math.
- Cache scatter kernel:
  - 2D grid over (B, N_kv). For each (b, nk), iterate over s in [0..S-1], read key_rotated[b, nk, s, :] and value[b, nk, s, :], and write into key_cache[b, nk, cache_position[s], :] and value_cache[b, nk, cache_position[s], :]. This preserves the original behavior and is done entirely in Triton (no torch.index_put).
  - Note: Overwriting is intended in the original code; we keep that behavior.

3) Performance considerations
- RMSNorm is a reduction per row (D=128), which is very fast in Triton.
- Rotation computes cos/sin per token (B*S vectors), which is O(B*S*D) elementwise operations; Triton handles this efficiently. Constructing inv vector inside Triton avoids any torch.cat on host.
- Cache scatter writes are simple and linear. We ensure grid covers all B*N_kv tokens and loop over S, which is fine for the given sizes. Triton will compile and run per workload.

4) Correctness details
- All math is done in Triton. No torch.cos, torch.sin, torch.cat, or any torch elementwise ops on tensors in the host code. Only tensor allocations, launches, and contiguous conversions are done on the host.
- RMSNorm uses fp32 accumulation for numerical stability and writes in the original dtype (bf16).
- Rotation and scatter use explicit stride-based indexing: For a tensor of shape (B, N, S, D) with last dim contiguous (stride_d=1), element at index (b, n, s, d) is base + b*stride_b + n*stride_n + s*stride_s + d*stride_d. Triton can derive these from torch.stride() on pointers.

@triton.jit
def rmsnorm_rows_kernel(X_ptr, Y_ptr, M, D, eps, stride_xm, stride_xd, stride_ym, stride_yd):
    """
    RMSNorm over last dimension of shape (M, D).
    Each program handles one row. Computes r = sqrt(mean(x^2) + eps) and writes y = x / r.
    X_ptr, Y_ptr are 2D pointers, but we treat as row-major with strides (stride_xm, stride_xd) and (stride_ym, stride_yd).
    """
    row_id = tl.program_id(axis=0)
    if row_id >= M:
        return

    sum_sq = 0.0
    # Accumulate sum of squares over D in fp32
    for d in range(0, D):
        x = tl.load(X_ptr + row_id * stride_xm + d * stride_xd)
        x_f32 = x.to(tl.float32)
        sum_sq += x_f32 * x_f32
    mean = sum_sq / D
    r = tl.sqrt(mean + eps)

    # Scale and store
    for d in range(0, D):
        x = tl.load(X_ptr + row_id * stride_xm + d * stride_xd)
        y = x / r
        tl.store(Y_ptr + row_id * stride_ym + d * stride_yd, y)

@triton.jit
def rotate_and_scatter_kernel_3axis(X_ptr, YR_ptr, YC_ptr, B, N, S, D, inv_ptr, pos_ids_ptr,
                                    stride_xb, stride_xn, stride_xs, stride_xd,
                                    stride_yrb, stride_ryn, stride_rys, stride_yrd,
                                    stride_ycb, stride_ycn, stride_ycs, stride_ycd,
                                    cache_len):
    """
    Proper 3-axis kernel: grid (B, N, S).
    For each (b, n, s), compute cos/sin for token pos, rotate X[b, n, s, :], store rotated in YR[b, n, s, :],
    and scatter copy of X[b, n, s, :] into YC[b, n, cache_position[s], :].
    """
    b = tl.program_id(axis=0)
    n = tl.program_id(axis=1)
    s = tl.program_id(axis=2)
    if (b >= B) or (n >= N) or (s >= S):
        return
    pos = tl.load(pos_ids_ptr + b * S + s).to(tl.int32)
    half = D // 2
    # Build cos/sin vectors for this token
    cos_vec = tl.zeros((D,), dtype=tl.float32)
    sin_vec = tl.zeros((D,), dtype=tl.float32)
    for i in range(0, half):
        v = inv_ptr[i]
        c = tl.cos(pos.to(tl.float32) * v)
        s2 = tl.sin(pos.to(tl.float32) * v)
        cos_vec[i] = c
        sin_vec[i] = s2
    # second half repeats
    for i in range(0, half):
        cos_vec[i + half] = cos_vec[i]
        sin_vec[i + half] = sin_vec[i]

    # Load X[b, n, s, :]
    x = tl.load(X_ptr + b * stride_xb + n * stride_xn + s * stride_xs + tl.arange(0, D) * stride_xd)
    x1 = x[:half]
    x2 = x[half:]
    rotated_half = -x2 * sin_vec[:half] + x1 * cos_vec[:half]
    y_rot = tl.zeros((D,), dtype=x.dtype)
    y_rot[:half] = rotated_half
    y_rot[half:] = x1 * cos_vec[half:] + x2 * sin_vec[half:]
    # Store rotated to YR
    tl.store(YR_ptr + b * stride_yrb + n * stride_ryn + s * stride_rys + tl.arange(0, D) * stride_yrd, y_rot)

    # Store original x to cache at position cache_position[s] = pos + cache_len
    dest_pos = pos + cache_len
    tl.store(YC_ptr + b * stride_ycb + n * stride_ycn + dest_pos * stride_ycs + tl.arange(0, D) * stride_ycd, x)

@triton.jit
def scatter_cache_only_kernel(Val_ptr, YC_ptr, B, N, S, pos_ids_ptr, cache_len,
                              stride_vb, stride_vn, stride_vs, stride_vd,
                              stride_ycb, stride_ycn, stride_ycs, stride_ycd):
    """
    For each (b, n, s), load Val[b, n, s, :] and store into YC[b, n, cache_position[s], :].
    Grid: (B, N, S)
    """
    b = tl.program_id(axis=0)
    n = tl.program_id(axis=1)
    s = tl.program_id(axis=2)
    if (b >= B) or (n >= N) or (s >= S):
        return
    pos = tl.load(pos_ids_ptr + b * S + s).to(tl.int32)
    dest_pos = pos + cache_len
    x = tl.load(Val_ptr + b * stride_vb + n * stride_vn + s * stride_vs + tl.arange(0, 128) * stride_vd)  # D fixed to 128
    tl.store(YC_ptr + b * stride_ycb + n * stride_ycn + dest_pos * stride_ycs + tl.arange(0, 128) * stride_ycd, x)
