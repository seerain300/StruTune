Thorough diagnosis, root cause, and robust plan

Summary of the PyTorch reference
- Inputs:
  - query: [B, num_q_heads=96, S, D=128]
  - key, value: [B, num_kv_heads=8, S, D]
  - position_ids: [B, S] int64
  - key_cache, value_cache: [B, num_kv_heads, L=262144, D]
  - cache_position: [S] int64
  - q_norm_weight, k_norm_weight: [D], initialized to ones
  - inv_freq: [D//2=64] float32
- Steps:
  1) RMSNorm on query and key along last dim D:
     - For each [b, h, s] row: rms = sqrt(mean(x^2) + eps), normalize x by 1/rms, then multiply by learned weight vector (q_norm_weight for query, k_norm_weight for key).
     - Compute in fp32 for numerical stability, output in original dtype (bf16).
  2) Rotation:
     - For each position s, pos = position_ids[b, s]:
       - angle = pos * inv_freq, inv_freq length D//2=64.
       - Build cos_all = cos(angle) concatenated with itself to length D, sin_all = sin(angle) concatenated with itself.
       - For query: y = x * cos_all - rotate_half(x) * sin_all, where rotate_half(x) = [-x[..., D//2:], x[..., :D//2]].
       - For key: y = x * sin_all - rotate_half(x) * cos_all.
  3) Cache update:
     - key_cache[:, :, cache_position] = rotated_key
     - value_cache[:, :, cache_position] = value (not rotated).

Why the previous Triton attempts failed (0/13 correct, RUNTIME_ERROR)
- The evaluation feedback repeatedly flagged usage of torch.cos/torch.sin/torch.stack/torch.cat in ModelNew.forward, and previously reported mismatches and runtime errors. To be safe, the forward must not perform any torch elementwise math or tensor construction; all such computations must be in Triton kernels. Also, our kernels must handle the correct number of query heads (H_q=96) and kv heads (H_kv=8) consistently across all workloads, and we must not rely on hidden host-side operations.
- Triton compilation/runtime errors usually come from:
  - Inconsistent launch grid vs tensor shapes (e.g., using H_kv=8 while num_q_heads=96).
  - Complex per-element dynamic indexing that Triton doesn’t like (e.g., constructing cos_all/sin_all with torch.cat and then using it in Triton).
  - Using torch ops on the host to build cos/sin/cat vectors and then passing them to Triton, which violates the TRITON-ONLY requirement and caused evaluation rejections.

Robust plan to satisfy TRITON-ONLY and correctness
- Implement RMSNorm in Triton:
  - Kernel rms_norm_kernel runs one program per (b, h, s) row and reduces across D=128 using a simple loop and a BLOCK_SIZE (e.g., 128). This avoids dynamic shapes and is robust. It computes inv_rms in fp32, scales, and multiplies by weight in fp32, then stores back in bf16.
  - Ensure we launch with H_q=96 for query and H_kv=8 for key/value, and use masks on S if needed. Given eval workloads have S≥1, this is fine.
- Implement rotation for query and key in Triton:
  - For query rotation: compute per-position cos_all and sin_all inside the Triton kernel by iterating over D//2 and forming the concatenation y = cos(angle) cat cos(angle) for cos_all, and similarly for sin_all. Then perform y = x * cos_all - rotate_half(x) * sin_all.
  - For key rotation: similarly compute sin_all and cos_all and perform y = x * sin_all - rotate_half(x) * cos_all.
  - Important: Do not use torch.cos/torch.sin/torch.cat on the host. The position index and angles are computed in-kernel; we don’t need to build cos_all/sin_all as separate tensors— we generate them per row using Triton’s elementwise operations.
- Implement cache scatter update in Triton:
  - scatter_update_cache_kernel copies rotated keys (and values) into key_cache[:, :, cache_position] and value_cache[:, :, cache_position] using a simple launch grid (B, H, S) and a BLOCK_SIZE loop over D. We pass positions as int32 and compute the destination index via cache_position[b, s].
- Forward:
  - Only:
    - Launch Triton kernels to compute query_norm, key_norm, query_rot, key_rot.
    - Launch scatter kernel to update caches.
  - No torch elementwise operations or tensor constructions (cos/sin/cat/stack) in forward. Only tensor metadata (shape, strides) and dtype conversions.

Performance considerations
- RMSNorm kernels are straightforward reductions across D; with D=128 and one program per row, they are efficient and simple. Using BLOCK_SIZE=128 keeps the code compact and avoids dynamic loops.
- Rotation kernels build cos_all/sin_all inside-kernel using simple loops over D//2; this avoids host-side torch ops and keeps all math on-device. Although forming cos_all/sin_all per position is O(D) per row, D is small (128), and each kernel instance is limited to S=seq_len in a batch. Given seq_len in provided workloads is modest (1–512), this is acceptable and satisfies TRITON-ONLY.
- Scatter update kernel is simple: one program per (b,h,s), loop over D, load from src, store to cache at position cache_position[b, s]. This avoids complex indexing and is robust.

import torch
import triton
import triton.language as tl


@triton.jit
def rms_norm_kernel(
    X_ptr, Out_ptr, Weight_ptr,
    B, H, S, D,
    x_stride_b, x_stride_h, x_stride_s, x_stride_d,
    out_stride_b, out_stride_h, out_stride_s, out_stride_d,
    eps,
    BLOCK_SIZE: tl.constexpr,
):
    # Each program handles one (b, h, s) row
    b = tl.program_id(0)
    h = tl.program_id(1)
    s = tl.program_id(2)

    x_row_ptr = X_ptr + b * x_stride_b + h * x_stride_h + s * x_stride_s
    out_row_ptr = Out_ptr + b * out_stride_b + h * out_stride_h + s * out_stride_s

    # Accumulate sum of squares across D
    sum_sq = 0.0
    for offs in range(0, D, BLOCK_SIZE):
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        x = tl.load(x_row_ptr + idx * x_stride_d, mask=mask, other=0.0).to(tl.float32)
        sum_sq += tl.sum(x * x)

    mean = sum_sq / D
    inv_rms = 1.0 / tl.sqrt(mean + eps)

    # Scale and multiply by weight, store in original dtype (bf16 expected)
    for offs in range(0, D, BLOCK_SIZE):
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        x = tl.load(x_row_ptr + idx * x_stride_d, mask=mask, other=0.0).to(tl.float32)
        w = tl.load(Weight_ptr + idx, mask=mask, other=1.0).to(tl.float32)
        y = x * inv_rms * w
        # Store as fp32; Out tensor dtype is typically fp32; if bf16 is desired, convert after kernel.
        # Here, we assume Out is fp32 for rotation (then cast later).
        tl.store(out_row_ptr + idx * out_stride_d, y, mask=mask)


# Triton kernel: rotate query (cos-based rotation). Computes cos_all and sin_all inside-kernel.
@triton.jit
def rotate_query_kernel(
    X_ptr, Out_ptr, Positions_ptr, InvFreq_ptr,
    B, H, S, D, HALF_D,
    x_stride_b, x_stride_h, x_stride_s, x_stride_d,
    out_stride_b, out_stride_h, out_stride_s, out_stride_d,
    BLOCK_SIZE: tl.constexpr,
):
    b = tl.program_id(0)
    h = tl.program_id(1)
    s = tl.program_id(2)

    pos = tl.load(Positions_ptr + b * S + s).to(tl.float32)  # position as float32 for angle
    x_row_ptr = X_ptr + b * x_stride_b + h * x_stride_h + s * x_stride_s
    out_row_ptr = Out_ptr + b * out_stride_b + h * out_stride_h + s * out_stride_s

    # Build cos_all: [D] = cos(angle) cat cos(angle), where angle = pos * inv_freq[:HALF_D]
    cos_all = tl.zeros([D], dtype=tl.float32)
    for j in range(0, HALF_D):
        angle_j = pos * tl.load(InvFreq_ptr + j)  # scalar
        cos_j = tl.cos(angle_j)
        # Place into even indices
        for i in range(0, D, 2):
            cos_all = tl.where((tl.arange(0, D) == i), cos_all + cos_j, cos_all)

    # Build sin_all similarly
    sin_all = tl.zeros([D], dtype=tl.float32)
    for j in range(0, HALF_D):
        angle_j = pos * tl.load(InvFreq_ptr + j)
        sin_j = tl.sin(angle_j)
        for i in range(0, D, 2):
            sin_all = tl.where((tl.arange(0, D) == i), sin_all + sin_j, sin_all)

    # Compute rotate_half(x): [-x[D//2:], x[:D//2]]
    for offs in range(0, D, BLOCK_SIZE):
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        x = tl.load(x_row_ptr + idx * x_stride_d, mask=mask, other=0.0).to(tl.float32)
        half = D // 2
        x_half = x[half:]
        x_first = x[:half]
        x_rot = tl.concatenate([-x_half, x_first], axis=0)  # shape [D]
        # y = x * cos_all - x_rot * sin_all
        cos_chunk = cos_all[offs : offs + BLOCK_SIZE]
        sin_chunk = sin_all[offs : offs + BLOCK_SIZE]
        y = x * cos_chunk - x_rot * sin_chunk
        tl.store(out_row_ptr + idx * out_stride_d, y, mask=mask)

    out_row_ptr = Out_ptr + b * out_stride_b + h * out_stride_h + s * out_stride_s

    # Build sin_all: [D] = sin(angle) cat sin(angle)

        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        x = tl.load(x_row_ptr + idx * x_stride_d, mask=mask, other=0.0).to(tl.float32)
        half = D // 2
        x_half = x[half:]
        x_first = x[:half]
        x_rot = tl.concatenate([-x_half, x_first], axis=0)  # shape [D]
        # y = x * sin_all - x_rot * cos_all
        sin_chunk = sin_all[offs : offs + BLOCK_SIZE]
        cos_chunk = cos_all[offs : offs + BLOCK_SIZE]

# Updates: Out[b, h, cache_position[b, s], :] = Src[b, h, s, :]
@triton.jit
def scatter_update_cache_kernel(
    Src_ptr, Out_ptr,
    B, H, S, D,
    src_stride_b, src_stride_h, src_stride_s, src_stride_d,
    out_stride_b, out_stride_h, out_stride_l, out_stride_d,

    BLOCK_SIZE: tl.constexpr,
):

    h = tl.program_id(1)
    s = tl.program_id(2)

    src_row_ptr = Src_ptr + b * src_stride_b + h * src_stride_h + s * src_stride_s
    out_row_ptr = Out_ptr + b * out_stride_b + h * out_stride_h + pos * out_stride_l

    for offs in range(0, D, BLOCK_SIZE):
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        src_val = tl.load(src_row_ptr + idx * src_stride_d, mask=mask, other=0.0).to(tl.float32)
        tl.store(out_row_ptr + idx * out_stride_d, src_val, mask=mask)

        sin_j = tl.sin(angle_j)
        for i in range(0, D, 2):
            idx = i + tl.arange(0, 1)
            sin_all = tl.where(idx == i, sin_all + sin_j, sin_all)

    # Compute rotate_half(x): [-x[D//2:], x[:D//2]]
    half = D // 2
    for offs in range(0, D, BLOCK_SIZE):
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        x = tl.load(x_row_ptr + idx * x_stride_d, mask=mask, other=0.0).to(tl.float32)
        x_half = x[half:]
        x_first = x[:half]
        x_rot = tl.concatenate([-x_half, x_first], axis=0)  # shape [D]
        cos_chunk = cos_all[offs : offs + BLOCK_SIZE]
        sin_chunk = sin_all[offs : offs + BLOCK_SIZE]
        y = x * cos_chunk - x_rot * sin_chunk
        tl.store(out_row_ptr + idx * out_stride_d, y, mask=mask)


# Triton kernel: rotate key (sin-based rotation). Computes sin_all and cos_all inside-kernel.
@triton.jit
def rotate_key_kernel(
    X_ptr, Out_ptr, Positions_ptr, InvFreq_ptr,
    B, H, S, D, HALF_D,
    x_stride_b, x_stride_h, x_stride_s, x_stride_d,
    out_stride_b, out_stride_h, out_stride_s, out_stride_d,
    BLOCK_SIZE: tl.constexpr,
):
    b = tl.program_id(0)
    h = tl.program_id(1)
    s = tl.program_id(2)

    pos = tl.load(Positions_ptr + b * S + s).to(tl.float32)
    x_row_ptr = X_ptr + b * x_stride_b + h * x_stride_h + s * x_stride_s
    out_row_ptr = Out_ptr + b * out_stride_b + h * out_stride_h + s * out_stride_s

    # Build sin_all: [D] = sin(angle) cat sin(angle)
    sin_all = tl.zeros([D], dtype=tl.float32)
    for j in range(0, HALF_D):
        angle_j = pos * tl.load(InvFreq_ptr + j)
        sin_j = tl.sin(angle_j)
        for i in range(0, D, 2):
            idx = i + tl.arange(0, 1)
            sin_all = tl.where(idx == i, sin_all + sin_j, sin_all)

    # Build cos_all similarly
    cos_all = tl.zeros([D], dtype=tl.float32)
    for j in range(0, HALF_D):
        angle_j = pos * tl.load(InvFreq_ptr + j)
        cos_j = tl.cos(angle_j)
        for i in range(0, D, 2):
            idx = i + tl.arange(0, 1)
            cos_all = tl.where(idx == i, cos_all + cos_j, cos_all)

    # Compute rotate_half(x): [-x[D//2:], x[:D//2]]
    half = D // 2
    for offs in range(0, D, BLOCK_SIZE):
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        x = tl.load(x_row_ptr + idx * x_stride_d, mask=mask, other=0.0).to(tl.float32)
        x_half = x[half:]
        x_first = x[:half]
        x_rot = tl.concatenate([-x_half, x_first], axis=0)  # shape [D]
        sin_chunk = sin_all[offs : offs + BLOCK_SIZE]
        cos_chunk = cos_all[offs : offs + BLOCK_SIZE]
        y = x * sin_chunk - x_rot * cos_chunk
        tl.store(out_row_ptr + idx * out_stride_d, y, mask=mask)


# Triton kernel: scatter update cache for keys and values.
# Updates: Out[b, h, cache_position[b, s], :] = Src[b, h, s, :]
@triton.jit
def scatter_update_cache_kernel(
    Src_ptr, Out_ptr,
    B, H, S, D,
    src_stride_b, src_stride_h, src_stride_s, src_stride_d,
    out_stride_b, out_stride_h, out_stride_l, out_stride_d,
    positions_ptr,  # int32 positions [B, S]
    BLOCK_SIZE: tl.constexpr,
):
    b = tl.program_id(0)
    h = tl.program_id(1)
    s = tl.program_id(2)

    pos = tl.load(positions_ptr + b * S + s)  # int32
    src_row_ptr = Src_ptr + b * src_stride_b + h * src_stride_h + s * src_stride_s
    out_row_ptr = Out_ptr + b * out_stride_b + h * out_stride_h + pos * out_stride_l

    for offs in range(0, D, BLOCK_SIZE):
        idx = offs + tl.arange(0, BLOCK_SIZE)
        mask = idx < D
        src_val = tl.load(src_row_ptr + idx * src_stride_d, mask=mask, other=0.0).to(tl.float32)
        tl.store(out_row_ptr + idx * out_stride_d, src_val, mask=mask)
