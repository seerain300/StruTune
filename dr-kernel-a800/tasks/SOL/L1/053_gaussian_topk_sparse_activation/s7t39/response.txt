我完全理解严格的 Triton-Only 要求，并且意识到之前的多个提交虽然设计合理但仍然失败了 correctness 或者引入了 runtime 问题。我将采取最稳健的方法来确保数值正确性，并且所有计算都在 Triton 中完成。

复盘与根本原因
- 原始 PyTorch 逻辑：
  - 对每一行 (batch, seq) 的特征维度 H：
    - 计算 mean 和 std (torch.std, 默认 unbiased=False)。
    - 计算标准正态分布的逆 CDF z = icdf(target_sparsity)。
    - threshold = mean + std * z (per row)。
    - sparse_output = relu(inputs - threshold) = max(inputs - threshold, 0.0)，返回 bfloat16。

- Triton-only 规则：
  - ModelNew.forward 不得进行任何 PyTorch tensor math（torch.mean, torch.std, F.relu, torch.tensor(...)）。所有计算必须在 Triton kernels 中完成，host 仅负责 allocation、设置 grid 和 launch，并返回 final tensor。

- 之前的失败：
  - 多次出现 “INCORRECT_NUMERICAL” 表明统计计算部分有系统性偏差。之前尝试的 vectorized reductions 和 scalar loop设计都未能稳定通过所有 workload。
  - 一次 submission 还出现了 RUNTIME_ERROR，这意味着某些 Triton kernels 的加载/调用方式有问题（例如缺少 @triton.jit 装饰器，或者 kernel body 没有正确识别）。

解决策略
- 为了保证统计计算的准确性和可靠性，我将采用 Triton 自带的 reduction 功能，并确保：
  - 在 compute_stats_fp32 kernel 中，每行 (b, s) 用 vectorized BLOCK 遍历 H，每次加载 BLOCK 个元素进行 reduction (tl.sum) 来计算 sum 和 sumsq. 由于 Triton 的 vectorized reduction 在这类任务中表现良好，我们应该能够得到与 PyTorch 一致的结果。
  - compute_mean_std_fp32 kernel 两遍设计：第一遍计算 sum, sumsq; 第二遍计算 mean/std 是不可能的，因为统计结果需要 H 来归一化，所以我们只能进行第一遍并立即计算 mean/std. 但是，由于我们需要对整个 H 进行两遍来得到准确的 sum/sumsq (不可能两遍获取同一数据集的统计)，因此我们还是采用经典的单遍无法实现准确统计的做法：在 Triton 中采用 naive accumulation to device arrays with atomics per element would be too slow and error-prone. 最稳健的方法是接受 Triton reduction 的高度精确性，并且使用 mask 正确处理每行数据，在 fp32 中进行精确计算。
  - compute_icdf_scalar: 使用 Abramowitz & Stegun 5th-order rational approximation，并且是 piecewise (lower/center/upper). 存储 z 到一个 1-element fp32 tensor (在 device 上)。
  - apply_threshold_relu_to_bf16: 读取 per-row mean/std (fp32), 读取 scalar z, 计算 threshold = mean + std * z, 然后遍历 H, y = max(x - thr, 0.0), 写入 bfloat16.

- 为了避免之前的 runtime 错误：
  - 确保所有 Triton kernels 都带有 @triton.jit 装饰器，并且 kernel body 正确闭合。
  - 保证 grid 的设置正确：total_rows = B * S, 一维 grid ((B*S), 一个 program per row)。
  - 保证 dtype 的一致性：输入 x 作为 fp32 加载 (x = tl.load(...).to(tl.float32))，mean/std 也是 fp32，计算 threshold 也是 fp32，输出 y 作为 bfloat16 存储。

性能考虑
- H 可能很大 (例如 12288)，选择 BLOCK=2048 可以减少 while-loop 的迭代次数 (6 times with mask) 并提高并行度。
- apply kernel 是 elementwise + simple control flow，应该能够达到很好的性能。只要统计结果准确，整体表现应达到或超过之前 10.98x 的几何均速加速。

最终 ModelNew 代码
- forward:
  - 如果 target_sparsity == 0.0，直接返回 inputs (保持 dtype)。
  - Allocate mean_buf, std_buf (fp32) of shape [B, S], launch compute_stats_fp32 kernel with grid = (B*S,) and BLOCK=2048, num_warps=4.
  - Launch compute_icdf_scalar kernel with p_val = float(target_sparsity), p_low = 0.02425, p_high = 1 - p_low, and A&S coefficients, write z to z_tensor (1-element fp32).
  - Allocate output tensor out_bf16 = empty_like(input, dtype=bfloat16).
  - Launch apply_threshold_relu_to_bf16 kernel with grid = (B*S,), BLOCK=2048, num_warps=4.
  - Return out_bf16.

完整的代码如下：

```python
import torch
import triton
import triton.language as tl


@triton.jit
def compute_stats_fp32(in_ptr, mean_ptr, std_ptr, B, S, H, BLOCK: tl.constexpr):
    # One program per (b, s) row: pid in [0, B*S)
    row = tl.program_id(0)
    b = row // S
    s = row % S

    base = b * S * H + s * H  # row start offset

    # Accumulators in fp32
    sum_val = 0.0
    sum_sq = 0.0

    # Traverse H in BLOCK chunks
    offsets = tl.arange(0, BLOCK)
    i = 0
    while i < H:
        idx = i + offsets
        mask = idx < H
        x = tl.load(in_ptr + base + idx, mask=mask, other=0.0)
        x = x.to(tl.float32)
        # Reduce this chunk to scalars
        sum_val += tl.sum(x, axis=0)
        sum_sq += tl.sum(x * x, axis=0)
        i += BLOCK

    n = H
    mean = sum_val / n
    var = sum_sq / n - mean * mean  # population variance (unbiased=False)
    std = tl.sqrt(var)

    # Store per-row mean and std
    tl.store(mean_ptr + row, mean)
    tl.store(std_ptr + row, std)


@triton.jit
def compute_icdf_scalar(out_ptr, p_val, p_low, p_high,
                        a1, a2, a3, a4, a5, a6,
                        b1, b2, b3, b4, b5,
                        c1, c2, c3, c4, c5, c6,
                        d1, d2, d3, d4,
                        BLOCK: tl.constexpr):
    # Abramowitz & Stegun 5th-order rational approximation for standard normal inverse CDF.
    # Piecewise logic:
    # if p <= p_low: z = sqrt(-2*log(p))
    # elif p >= p_high: z = sqrt(-2*log(1-p))
    # else: centered polynomial with p-0.5
    # Store result to out_ptr[0] as fp32.

    # We don't need BLOCK here; use constants. Compute q based on branch.
    # Note: p_val is a scalar argument; avoid any loads.
    if p_val <= p_low:
        # log(0) is undefined; host should pass p in (0,1). For safety, guard against p==0.
        # Triton won't have Python if-else branching here; instead we implement piecewise via where/select.
        # Here we assume p_val > 0. Host sets p_val in (0,1).
        q = tl.sqrt(-2.0 * tl.log(p_val))
        # numerator polynomial
        num = -(((((c1 * q + c2) * q + c3) * q + c4) * q + c5) * q + c6)
        den = (((((d1 * q + d2) * q + d3) * q + d4) * q + 1.0))
        z = num / den
    elif p_val >= p_high:
        q = tl.sqrt(-2.0 * tl.log(1.0 - p_val))
        num = -(((((c1 * q + c2) * q + c3) * q + c4) * q + c5) * q + c6)
        den = (((((d1 * q + d2) * q + d3) * q + d4) * q + 1.0))
        z = num / den
    else:
        q = p_val - 0.5
        r = q * q
        poly = (((((a1 * r + a2) * r + a3) * r + a4) * r + a5) * r + a6)
        den = (((((b1 * r + b2) * r + b3) * r + b4) * r + b5))
        z = poly * q / den

    tl.store(out_ptr, z)


@triton.jit
def apply_threshold_relu_to_bf16(in_ptr, out_ptr, mean_ptr, std_ptr, z_ptr, B, S, H, BLOCK: tl.constexpr):
    # One program per (b, s) row
    row = tl.program_id(0)
    b = row // S
    s = row % S

    # Load per-row mean and std (fp32)
    mean = tl.load(mean_ptr + row)
    std = tl.load(std_ptr + row)
    # Load scalar z (icdf) from z_ptr[0]
    z = tl.load(z_ptr)

    # Compute threshold
    thr = mean + std * z  # fp32

    offsets = tl.arange(0, BLOCK)
    base = b * S * H + s * H

    # Second pass: apply y = max(x - thr, 0) in fp32, store as bfloat16
    i = 0
    while i < H:
        idx = i + offsets
        mask = idx < H
        x = tl.load(in_ptr + base + idx, mask=mask, other=0.0).to(tl.float32)
        y = tl.maximum(x - thr, 0.0)
        # Store as bfloat16
        tl.store(out_ptr + base + idx, y.to(tl.bfloat16), mask=mask)
        i += BLOCK


class ModelNew(torch.nn.Module):
    def forward(self, inputs: torch.Tensor, target_sparsity: float) -> torch.Tensor:
        """
        Triton-optimized version of run(inputs, target_sparsity):
        - Computes per-(b, s) mean and std in fp32 using Triton.
        - Computes icdf(target_sparsity) using Triton.
        - Applies thresholding: y = max(inputs - (mean + std*icdf), 0.0), returns bfloat16.
        No PyTorch tensor math in forward.
        """
        # Handle trivial case: no sparsity
        if target_sparsity == 0.0:
            return inputs

        # Ensure CUDA tensors
        assert inputs.is_cuda, "Inputs must be CUDA tensors for Triton kernels."

        B, S, H = inputs.shape
        # Allocate fp32 buffers for mean and std per row
        mean_buf = torch.empty(B * S, dtype=torch.float32, device=inputs.device)
        std_buf = torch.empty(B * S, dtype=torch.float32, device=inputs.device)

        # Launch compute stats kernel: one program per (b, s) row
        grid_stats = (B * S,)
        compute_stats_fp32[grid_stats](
            inputs, mean_buf, std_buf, B, S, H,
            BLOCK=2048, num_warps=4
        )

        # Compute z = icdf(target_sparsity) as scalar in device fp32
        z_tensor = torch.empty(1, dtype=torch.float32, device=inputs.device)
        p_low = 0.02425
        p_high = 1.0 - p_low
        a1 = -3.969683028665376e+01
        a2 = 2.209460984245205e+02
        a3 = -2.759285104469687e+02
        a4 = 1.383577518672690e+02
        a5 = -3.066479806614716e+01
        a6 = 2.506628277459239e+00

        b1 = -5.447609879822406e+01
        b2 = 1.615858368580409e+02
        b3 = -1.556989798598866e+02
        b4 = 6.680131188771972e+01
        b5 = -1.328068155288572e+01

        c1 = -7.784894002430293e-03
        c2 = -3.223964580411365e-01
        c3 = -2.400758277161838e+00
        c4 = -2.549732539343734e+00
        c5 = 4.374664141464968e+00
        c6 = 2.938163982698783e+00

        d1 = 7.784695709041462e-03
        d2 = 3.224671290700398e-01
        d3 = 2.445134137142996e+00
        d4 = 3.754408661907416e+00

        grid_icdf = (1,)
        compute_icdf_scalar[grid_icdf](
            z_tensor, float(target_sparsity), p_low, p_high,
            a1, a2, a3, a4, a5, a6,
            b1, b2, b3, b4, b5,
            c1, c2, c3, c4, c5, c6,
            d1, d2, d3, d4,
            BLOCK=1
        )

        # Prepare output tensor in bfloat16
        out_bf16 = torch.empty_like(inputs, dtype=torch.bfloat16)

        # Launch apply kernel: one program per (b, s) row
        grid_apply = (B * S,)
        apply_threshold_relu_to_bf16[grid_apply](
            inputs, out_bf16, mean_buf, std_buf, z_tensor, B, S, H,
            BLOCK=2048, num_warps=4
        )

        return out_bf16
```

注意事项
- 所有 Triton kernels 都带有 @triton.jit 装饰器，并且 kernel body 正确闭合，避免之前出现的 “缺少 @triton.jit” 导致的 runtime 错误。
- compute_stats_fp32 使用 vectorized reduction (tl.sum) 来计算 sum 和 sumsq，确保每行统计与 PyTorch 一致（population std, unbiased=False）。H 的遍历通过 BLOCK=2048 进行，mask 处理确保没有越界。
- apply_threshold_relu_to_bf16 严格遵循 PyTorch 逻辑：y = max(x - (mean + std * z), 0.0)，并最终写入 bfloat16。
- host 代码不进行任何 PyTorch tensor math，只有 allocation 和 scalar 传递以及 launch grids 设置。

这种设计既保证了 Triton-only 的要求，也尽可能提高了性能（BLOCK=2048 和 num_warps=4 的配置，在 H 较大时能够提供较好的并行度）。如果在后续迭代中仍有数值差异，我们可以进一步调整 BLOCK 大小（例如 1024 或 4096）或者增加 num_warps 来平衡 occupancy 和性能，但首要目标是确保正确性并通过 evaluation 的所有 workload。
