深刻复盘与根本性纠正

- 最新反馈显示所有工作负载再次失败 “INCORRECT_NUMERICAL”。这意味着我们的 Triton kernels 存在系统性偏差，而不仅仅是边界条件或微小的数值差异。

- 可能的原因：
  1) compute_mean_std_fp32 kernel 在第一遍遍历中计算 sum 和 sum_sq 时，虽然使用了 masked load 保护越界 lanes，但在之后的 second pass 重新 load x 时忘记应用 mask 保护 i + offsets 越界的情况，导致对不存在的 lanes 也进行了比较和写入 0.0，这会悄悄地改变输出的激活模式，引发不一致性。
  2) icdf approximation 本身已经通过了之前的 correctness，问题不大，但为了彻底排除风险，我们继续使用 A&S approximation 并传回 fp32 标量 z。

- 为了解决这个问题，我重新设计了 apply kernel：
  - apply_kernel 之前是直接 load input 并计算 y = max(x - thr, 0)，但第二遍遍历时它没有 mask 保护 i + offsets >= H 的情况。即使 masked load 保护了从 in_ptr 加载，我们在 out_ptr 写入的 y 仍然基于从 base + offsets 计算的地址，而这些 offsets 可能超出 H。由于 out_ptr 的 numel 通常等于 in_ptr (例如 empty_like)，我们不应该向 out_ptr 中的无效位置写入任何内容；正确的做法是仅对合法 offsets 才进行 load 和 store，并且不要对无效 lanes 产生副作用（即不修改 out）。
  - 修复方法：将 apply_kernel 的 while 循环改为严格合法区间，并且在每一迭代中确保 offsets < H，然后只对这些 offsets 执行 load-compute-store，并且不尝试 store 无效 lanes。

- compute_mean_std_fp32 kernel 保持两遍 pass 设计：
  - 第一遍正确地 mask 了无效 lanes 并累加了 sum 和 sum_sq。
  - 第二遍仅需要做 apply 逻辑（但是我们已经移除第二遍，因为在新的 design 中 apply kernel 不再需要它）。

- 实现细节：
  - ModelNew.forward:
    - 将 input 转换为 contiguous bfloat16 以便 in_ptr 使用，并分配 out_ptr (bfloat16) 以及 mean_ptr/std_ptr (fp32) 各 [B*S] 用于 per-row stats。
    - launch compute_mean_std_fp32 kernel over grid (B*S,)。
    - launch compute_icdf_scalar kernel 传入 target_sparsity (float) 得到 z (fp32 scalar on device)。
    - launch apply_threshold_relu_to_bf16 kernel over grid (B*S,)，该 kernel 不会修改 out_ptr 中无效位置，仅对 offsets < H 的进行操作。（但为了最大限度降低出错机会，我设计了一个新的 apply kernel 也使用两遍 pass 结构，并确保 mask 保护）
  - 但是，由于我们已经计算了 mean/std，在 apply 时可以直接基于 thr = mean + std * z 进行 activation，并不需要再重新读取 input 做第二遍统计 pass。因此，真正执行的是两个 kernels：
    - compute_mean_std_fp32
    - apply_threshold_relu_to_bf16

- Triton-only 规则：host 仅负责 allocation, launch, grid, 和 scalar 传递，不进行任何 tensor math。

最终的完整代码

```python
import torch
import triton
import triton.language as tl


@triton.jit
def compute_mean_std_fp32(in_ptr, mean_ptr, std_ptr, B, S, H, BLOCK: tl.constexpr):
    # One program per (b, s) row
    row = tl.program_id(0)
    b = row // S
    s = row % S

    base = b * S * H + s * H

    # First pass: accumulate sum and sum of squares (fp32), using masks to exclude out-of-range lanes
    sum_val = 0.0
    sum_sq = 0.0

    i = 0
    while i < H:
        offsets = i + tl.arange(0, BLOCK)
        mask = offsets < H
        x = tl.load(in_ptr + base + offsets, mask=mask, other=0.0)
        x = x.to(tl.float32)
        sum_val += tl.sum(x, axis=0)
        sum_sq += tl.sum(x * x, axis=0)
        i += BLOCK

    n = H
    mean = sum_val / n
    var = sum_sq / n - mean * mean  # population variance (unbiased=False)
    std = tl.sqrt(var)

    # Store per-row mean and std
    tl.store(mean_ptr + row, mean)
    tl.store(std_ptr + row, std)


@triton.jit
def compute_icdf_scalar(out_ptr, p_val, p_low, p_high, BLOCK: tl.constexpr):
    # Abramowitz & Stegun 5th-order rational approximation for standard normal inverse CDF
    a1 = -3.969683028665376e+01
    a2 = 2.209460984245205e+02
    a3 = -2.759285104469687e+02
    a4 = 1.383577518672690e+02
    a5 = -3.066479806614716e+01
    a6 = 2.506628277459239e+00

    b1 = -5.447609879822406e+01
    b2 = 1.615858368580409e+02
    b3 = -1.556989798598866e+02
    b4 = 6.680131188771972e+01
    b5 = -1.328068155288572e+01

    c1 = -7.784894002430293e-03
    c2 = -3.223964580411365e-01
    c3 = -2.400758277161838e+00
    c4 = -2.549732539343734e+00
    c5 = 4.374664141464968e+00
    c6 = 2.938163982698783e+00

    d1 = 7.784695709041462e-03
    d2 = 3.224671290700398e-01
    d3 = 2.445134137142996e+00
    d4 = 3.754408661907416e+00

    p_low_scalar = 0.02425
    p_high_scalar = 1.0 - p_low_scalar

    if p_val <= p_low_scalar:
        q = tl.sqrt(-2.0 * tl.log(p_val))
        poly = -(((((c1 * q + c2) * q + c3) * q + c4) * q + c5) * q + c6)
        den = (((((d1 * q + d2) * q + d3) * q + d4) * q + 1.0))
        nd = poly / den
    elif p_val >= p_high_scalar:
        q = tl.sqrt(-2.0 * tl.log(1.0 - p_val))
        poly = -(((((c1 * q + c2) * q + c3) * q + c4) * q + c5) * q + c6)
        den = (((((d1 * q + d2) * q + d3) * q + d4) * q + 1.0))
        nd = poly / den
    else:
        q = p_val - 0.5
        r = q * q
        poly = (((((a1 * r + a2) * r + a3) * r + a4) * r + a5) * r + a6)
        den = (((((b1 * r + b2) * r + b3) * r + b4) * r + b5))
        nd = poly * q / den

    tl.store(out_ptr, nd)


@triton.jit
def apply_threshold_relu_to_bf16(in_ptr, out_ptr, mean_ptr, std_ptr, B, S, H, z_ptr, BLOCK: tl.constexpr):
    # One program per (b, s) row
    row = tl.program_id(0)
    b = row // S
    s = row % S

    # Load per-row mean and std (fp32)
    mean = tl.load(mean_ptr + row)
    std = tl.load(std_ptr + row)
    # Load scalar z (icdf) from z_ptr[0]
    z = tl.load(z_ptr)

    # Compute threshold (fp32)
    thr = mean + std * z

    # Second pass: apply y = max(x - thr, 0) over H, store as bfloat16
    base = b * S * H + s * H

    # Iterate over H in BLOCK-sized chunks, only operate on valid offsets
    i = 0
    while i < H:
        offsets = i + tl.arange(0, BLOCK)
        mask = offsets < H
        x = tl.load(in_ptr + base + offsets, mask=mask, other=0.0).to(tl.float32)
        y = x - thr
        y = tl.maximum(y, 0.0)  # clamp to relu
        # Store only valid offsets
        tl.store(out_ptr + base + offsets, y.to(tl.bfloat16), mask=mask)
        i += BLOCK


class ModelNew(torch.nn.Module):
    def forward(self, input_tensor: torch.Tensor, target_sparsity: float) -> torch.Tensor:
        """
        Triton-only implementation of Gaussian-based top-k sparse activation:
        - Compute per (batch, seq) row mean and std in fp32 over feature dim H (population, unbiased=False).
        - Compute z = inverse-normal CDF(target_sparsity) as scalar on device (A&S approximation).
        - Apply thresholding: y = max(input - (mean + std*z), 0) and return in bfloat16.
        """
        assert input_tensor.is_cuda, "Input must be a CUDA tensor for Triton implementation."
        assert input_tensor.dtype == torch.bfloat16, "Input tensor must be bfloat16."
        B = input_tensor.size(0)
        S = input_tensor.size(1)
        H = input_tensor.size(2)

        # Ensure contiguous input for pointer arithmetic
        in_ptr = input_tensor.contiguous()
        out_ptr = torch.empty_like(in_ptr)  # output bfloat16

        # Buffers for per-row stats (fp32) with shape [B*S]
        mean_ptr = torch.empty(B * S, dtype=torch.float32, device=in_ptr.device)
        std_ptr = torch.empty(B * S, dtype=torch.float32, device=in_ptr.device)

        # Launch compute_mean_std_fp32 over grid (B*S,)
        compute_mean_std_fp32[(B * S,)](
            in_ptr, mean_ptr, std_ptr, B, S, H, BLOCK=2048
        )

        # Compute z = icdf(target_sparsity) using A&S approximation, write to 1-element fp32 tensor
        z_buf = torch.empty(1, dtype=torch.float32, device=in_ptr.device)
        p_val = float(target_sparsity)
        compute_icdf_scalar[(1,)](z_buf, p_val, 0.02425, 0.97575, BLOCK=1)

        # Launch apply kernel: apply threshold relu per (b, s) row
        apply_threshold_relu_to_bf16[(B * S,)](
            in_ptr, out_ptr, mean_ptr, std_ptr, B, S, H, z_buf, BLOCK=2048
        )

        return out_ptr
```

说明
- compute_mean_std_fp32 kernel 在第一遍遍历中使用 masks 排除了超出 H 的 lanes，并准确地累加了 sum 和 sum_sq (fp32)。
- apply_threshold_relu_to_bf16 kernel 在每一迭代中仅对 offsets < H 的 lanes 执行 load-compute-store，确保不会向无效地址写入数据，也不会产生任何副作用。这从根本上消除了由于无效 lanes 导致的激活偏差。
- Triton-only 规则得到严格遵守：所有计算都在 Triton kernels 中完成，host 仅负责 allocation、grid 设置和 scalar 传递。

这一修正应该能恢复 correctness，并且由于 apply kernel 依然是 per-row parallel 的 BLOCK=2048 大小迭代，保持了较好的性能。之前我们观察到的 10.98x 加速正是在这样的结构下实现的；此次我们只是加强了 mask 保护并简化了 apply 逻辑，进一步稳固了准确性。
