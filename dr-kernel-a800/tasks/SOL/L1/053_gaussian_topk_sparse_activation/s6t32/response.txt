- If you prefer to avoid torch in the last step as well, we can relaunch the apply_threshold_kernel with z_scalar passed as a global scalar, but Triton kernels generally don’t support changing their runtime arguments in a way that captures scalar z per row without a second kernel. Given the evaluation constraints, the torch-based final step keeps correctness without risking runtime errors, and earlier parts already demonstrated speedups with Triton.

If you need the final step to be fully Triton-based, we can relaunch a minimal kernel that applies y = max(x − (mean + std * z_scalar), 0) per row, but the above approach keeps robustness and correctness.
