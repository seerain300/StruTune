Deep analysis and plan

Understanding the original computation
- Input x has shape [B, S, L] = [batch_size, seq_len, intermediate_size].
- It computes per-feature statistics along the last dimension L:
  - For each feature f in 0..L-1, compute mean_f and std_f over all rows across B*S elements: mean_f = sum(x[..., f]) / (B*S), std_f = sqrt(sum(x^2[..., f])/(B*S) − mean_f^2).
- target_sparsity is a scalar in (0, 1). It computes q = ndtri(target_sparsity), the inverse standard normal CDF.
- It forms a per-feature threshold: threshold_f = mean_f + std_f * q.
- It applies elementwise sparse ReLU with this per-feature threshold broadcast across rows:
  - y[b, s, f] = max(x[b, s, f] − threshold_f, 0).
- Returns y as bfloat16.

Constraints from the evaluation environment
- Forward must not perform any torch operations on tensors. This includes no torch.mean, torch.std, no sqrt, no tensor() calls, no elementwise clamp, no dtype conversions using torch in forward. The only allowed work is @triton.jit kernels, allocations, and view/reshape for metadata.
- A Triton kernel that is defined but not launched is considered a decoy. We must actually launch it. In particular, forward must invoke cast_bf16_kernel[...] to cast from FP32 to BF16.

Root cause of previous failures and fixes
- The prior version computed q with torch.tensor(), which violated the “no torch ops in forward” constraint. We must move that into a Triton kernel.
- The core robust pattern is to avoid atomics. We’ll compute per-feature reductions by iterating across rows in chunks per feature, accumulating sum and sumsq in FP32. Then compute mean and std per feature in Triton. Finally, apply the elementwise ReLU with per-feature threshold broadcast.

Design
- Kernel 1: sum_per_feature_kernel
  - Grid: (L,) — one program per feature f.
  - Loop across rows in chunks of BLOCK_ROWS, compute linear index idx = row * L + f, load x[idx], accumulate sum for feature f.
  - Store sum[f] to a device buffer.
- Kernel 2: sumsq_per_feature_kernel
  - Same grid and loop; accumulate sum of squares into sumsq[f].
  - Store to a device buffer.
- Kernel 3: compute_mean_std_per_feature_kernel
  - Grid: (L,) — one program per feature f.
  - Load sum[f], sumsq[f], and rows = B*S; compute mean[f] = sum[f] / rows, var[f] = sumsq[f] / rows − mean[f]^2, std[f] = sqrt(var[f]).
  - Compute q = ndtri(target_sparsity) via a Triton function (Abramowitz-Stegun approximation). This q must be computed inside Triton without any torch tensor creation in forward. We pass target_sparsity as a scalar (float) to the kernel and compute q inside the kernel, then use it to form threshold[f] = mean[f] + std[f] * q.
  - Store threshold[f].
- Kernel 4: sparse_relu_per_feature_kernel
  - 2D grid: (B*S, L). For each (row, feature), compute x[row, f] and threshold[f], apply y = max(x − threshold, 0). Store to output FP32 buffer. This avoids elementwise broadcasting complexities and keeps indexing simple.
- Kernel 5: cast_bf16_kernel
  - Launch this unconditionally in forward to cast the FP32 output to BF16, writing to the final output tensor. This ensures we actually invoke the cast kernel and not leave it as a decoy.

Complexity and performance
- The reduction kernels iterate over B*S rows for each feature. For typical sizes (e.g., B*S up to hundreds of thousands and L up to 12288), using BLOCK_ROWS = 256 or 1024 is fine. These loops are straightforward and avoid atomics. Computing q per feature kernel is negligible since L is small compared to B*S.
- The elementwise kernel is simple 2D mapping with contiguous access along the last dimension. Triton can handle this.

import math
import torch
import triton
import triton.language as tl


# Triton kernel: compute sum per feature across all rows (B*S)
@triton.jit
def sum_per_feature_kernel(x_ptr, sum_ptr,
                            B, S, L,
                            BLOCK_ROWS: tl.constexpr):
    f = tl.program_id(0)
    rows = B * S
    total_sum = 0.0
    for row_start in range(0, rows, BLOCK_ROWS):
        row_offsets = row_start + tl.arange(0, BLOCK_ROWS)
        mask_rows = row_offsets < rows
        # linear index for x[b, s, f] across all rows: idx = row_offsets * L + f
        idx = row_offsets * L + f
        # load values (cast to fp32); mask invalid rows to 0
        vals = tl.load(x_ptr + idx, mask=mask_rows, other=0.0)
        # accumulate sum
        total_sum += tl.sum(vals, axis=0)
    tl.store(sum_ptr + f, total_sum)


# Triton kernel: compute sum of squares per feature across all rows (B*S)
@triton.jit
def sumsq_per_feature_kernel(x_ptr, sumsq_ptr,
                              B, S, L,
                              BLOCK_ROWS: tl.constexpr):
    f = tl.program_id(0)
    rows = B * S
    total_sumsq = 0.0
    for row_start in range(0, rows, BLOCK_ROWS):
        row_offsets = row_start + tl.arange(0, BLOCK_ROWS)
        mask_rows = row_offsets < rows
        idx = row_offsets * L + f
        vals = tl.load(x_ptr + idx, mask=mask_rows, other=0.0)
        total_sumsq += tl.sum(vals * vals, axis=0)
    tl.store(sumsq_ptr + f, total_sumsq)


# Triton kernel: compute mean, std, and per-feature threshold = mean + std * ndtri(target_sparsity)
@triton.jit
def compute_mean_std_per_feature_kernel(sum_ptr, sumsq_ptr, threshold_ptr,
                                        B, S, L, target_sparsity):
    # Compute q = ndtri(target_sparsity) using Abramowitz-Stegun approximation
    # We implement the "best" approximation for the lower and upper tails and central region.
    # This is a scalar per program (feature), computed without any torch ops.

    # Constants for the approximation
    a1 = -3.969683028665376e+01
    a2 = 2.209460984245205e+02
    a3 = -2.759285104469687e+02
    a4 = 1.383577518672690e+02
    a5 = -3.066479806614716e+01
    a6 = 2.506628277459239e+00

    b1 = -5.447609879822406e+01
    b2 = 1.615858368580409e+02
    b3 = -1.556989798598866e+02
    b4 = 6.680131188771972e+01
    b5 = -1.328068155288572e+01

    c1 = -7.784894002430293e-03
    c2 = -3.223964580411365e-01
    c3 = -2.400758277161838e+00
    c4 = -2.549732539343734e+00
    c5 = 4.374664141464968e+00
    c6 = 2.938163982698783e+00

    d1 = 7.784695709041462e-03
    d2 = 3.224671290700398e-01
    d3 = 2.445134137142996e+00
    d4 = 3.754408661907416e+00

    p_low = 0.02425

    f = tl.program_id(0)
    sum_f = tl.load(sum_ptr + f)
    sumsq_f = tl.load(sumsq_ptr + f)

    rows = B * S
    mean = sum_f / rows
    var = sumsq_f / rows - mean * mean
    var = tl.maximum(var, 0.0)  # guard against tiny negative due to rounding
    std = tl.sqrt(var)

    # Compute q = ndtri(target_sparsity) using A&S approximation.
    # We'll implement piecewise approximation; note that for target_sparsity ~0.5, q≈0.
    # For simplicity and correctness, use a branchless or masked form with t = 1 - p.
    # Use central region when t in (p_low, 1 - p_low).
    p = target_sparsity  # scalar argument passed to kernel
    t = 1.0 - p
    # Piecewise computation for q (Abramowitz-Stegun 7.1.26)
    # Lower region
    # q = (c1*t + c2)*t + c3  /  (d1*t + d2)*t + d3
    q_low = (((c1 * t + c2) * t + c3) / (((d1 * t + d2) * t + d3)))
    # Upper region
    q_up = -(((((c1 * t + c2) * t + c3) * t + c4) * t + c5) * t + c6) / (((((d1 * t + d2) * t + d3) * t + d4) * t + 1.0))

    # Central region
    # u = sqrt(-2*log(p)) - 1
    # q = (((((a1*u + a2)*u + a3)*u + a4)*u + a5)*u + a6) * u / (((((b1*u + b2)*u + b3)*u + b4)*u + b5)*u + 1.0)
    u = tl.sqrt(-2.0 * tl.log(p)) - 1.0
    q_mid = (((((a1 * u + a2) * u + a3) * u + a4) * u + a5) * u + a6) * u / (((((b1 * u + b2) * u + b3) * u + b4) * u + b5) * u + 1.0)

    # Combine piecewise (use logical masks)
    mask_low = t > p_low
    mask_high = t < 1.0 - p_low
    # When neither low nor high: use central region
    mask_mid = ~(mask_low | mask_high)

    q = tl.where(mask_low, q_low, tl.where(mask_high, q_up, q_mid))

    thr = mean + std * q
    tl.store(threshold_ptr + f, thr)


# Triton kernel: elementwise sparse ReLU with per-feature threshold broadcast
@triton.jit
def sparse_relu_per_feature_kernel(x_ptr, threshold_ptr,
                                    out_ptr,
                                    B, S, L):
    pid_row = tl.program_id(0)  # over rows
    pid_f = tl.program_id(1)    # over features
    rows = B * S
    mask = (pid_row < rows) & (pid_f < L)
    idx = pid_row * L + pid_f
    x_val = tl.load(x_ptr + idx, mask=mask, other=0.0)
    thr = tl.load(threshold_ptr + pid_f)
    y = x_val - thr
    y = tl.maximum(y, 0.0)
    tl.store(out_ptr + idx, y, mask=mask)


# Triton kernel: cast FP32 to BF16 elementwise
@triton.jit
def cast_bf16_kernel(in_ptr, out_ptr, N, BLOCK: tl.constexpr):
    for start in range(0, N, BLOCK):
        offs = start + tl.arange(0, BLOCK)
        mask = offs < N
        vals = tl.load(in_ptr + offs, mask=mask, other=0.0)
        # Triton provides fp32->bf16 cast implicitly on store if out_ptr is bf16.
        tl.store(out_ptr + offs, vals, mask=mask)  # cast happens on store


class ModelNew(torch.nn.Module):
    def __init__(self, target_sparsity: float = 0.0):
        super().__init__()
        # store target_sparsity as Python float; we will pass it to Triton kernels
        self.target_sparsity = float(target_sparsity)

    def forward(self, inputs: torch.Tensor) -> torch.Tensor:
        # Ensure input is contiguous
        assert inputs.dim() == 3, "inputs must be 3D: [B, S, L]"
        B, S, L = inputs.shape

        # We must perform all heavy computation in Triton; avoid any torch ops in forward.
        # Compute FP32 view for math (no tensor creation via torch in forward).
        # Note: inputs may be any floating dtype; we load as is and do FP32 math.
        # Allocate per-feature buffers for sums and thresholds (FP32)
        sum_f = torch.empty(L, dtype=torch.float32, device=inputs.device)
        sumsq_f = torch.empty(L, dtype=torch.float32, device=inputs.device)
        threshold_f = torch.empty(L, dtype=torch.float32, device=inputs.device)

        # 1) Reduce sum and sumsq per feature across all rows
        BLOCK_ROWS = 1024
        grid_sum = (L,)
        sum_per_feature_kernel[grid_sum](
            inputs, sum_f,
            B, S, L,
            BLOCK_ROWS=BLOCK_ROWS,
            num_warps=4
        )

        sumsq_per_feature_kernel[grid_sum](
            inputs, sumsq_f,
            B, S, L,
            BLOCK_ROWS=BLOCK_ROWS,
            num_warps=4
        )

        # 2) Compute mean, std, and per-feature threshold using Triton (compute q inside kernel)
        compute_mean_std_per_feature_kernel[(L,)](
            sum_f, sumsq_f, threshold_f,
            B, S, L, self.target_sparsity,
            num_warps=1
        )

        # 3) Elementwise sparse ReLU: broadcast threshold per feature
        out_fp32 = torch.empty(B * S * L, dtype=torch.float32, device=inputs.device)
        grid_relu = (B * S, L)
        sparse_relu_per_feature_kernel[grid_relu](
            inputs, threshold_f,
            out_fp32,
            B, S, L,
            num_warps=4
        )

        # 4) Cast to bfloat16 via Triton kernel (forward MUST invoke this)
        out_bf16 = torch.empty(B * S * L, dtype=torch.bfloat16, device=inputs.device)
        BLOCK_CAST = 4096
        grid_cast = (triton.cdiv(B * S * L, BLOCK_CAST),)
        cast_bf16_kernel[grid_cast](
            out_fp32, out_bf16, B * S * L,
            BLOCK=BLOCK_CAST, num_warps=4
        )

        # Reshape to [B, S, L] and return
        return out_bf16.view(B, S, L)

- The elementwise kernel uses a 2D grid across rows and features, ensuring simple and robust indexing without atomics. The reduction kernels loop across rows in chunks, which is safe for large B*S.
