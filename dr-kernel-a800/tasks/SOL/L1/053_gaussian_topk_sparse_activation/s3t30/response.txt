Diagnosis and plan

The original PyTorch forward computes:
- Inputs x of shape [B, S, L].
- Per-feature mean and std along the last dimension (L) for each (B, S):
  - m[b, s, f] = mean(x[b, s, :], reduce over L)
  - s[b, s, f] = std(x[b, s, :], reduce over L, unbiased=False)
- Adaptive threshold per feature: thr[f] = m[:, :, f] + s[:, :, f] * ndtri(target_sparsity).
- Sparse activation per element: y[b, s, f] = max(x[b, s, f] - thr[f], 0).
- Return y as bfloat16.

Key semantic point: The threshold is broadcast along the last dimension, meaning it’s applied per feature across all (b, s) rows. In other words:
- Build m_sum[b, s, f] = mean of x over L for that specific (b, s, f), and similarly s_sum. This implies summing over the L dimension for each (b, s) row, independently for each f. Equivalently, mean_std is computed per feature across all rows: mean[f] = sum over rows of x[b, s, f] divided by (B*S).

Previous failures likely stemmed from:
- Inconsistent broadcasting semantics or insufficient robustness in Triton kernels (grid sizing, masking, atomics, dtype handling).
- Runtime errors on large L (up to 12288) and large B*S, where simple 1D reductions or atomics can be fragile. A more robust approach is to compute per-feature reductions by looping over rows and features in Triton without atomics.

New approach to ensure correctness and avoid torch ops:
- Implement two Triton kernels that compute per-feature sum and sum of squares across all rows:
  1) sum_per_feature_kernel: Each program handles one feature f and loops over rows (B*S) in chunks, accumulates sum in fp32, stores to a [L] array.
  2) sumsq_per_feature_kernel: Same as above, accumulating x^2.
- Triton kernel compute_mean_std_kernel reads sum and sumsq and writes mean and std per feature in fp32.
- Triton kernel broadcast_threshold_kernel computes thr per feature: thr[f] = mean[f] + std[f] * std_multiplier (std_multiplier is a device scalar; no torch operations in forward).
- Triton kernel sparse_relu_kernel applies per-element activation: out[b, s, f] = max(x[b, s, f] - thr[f], 0) in fp32.
- Triton kernel cast_bf16_kernel casts the fp32 output to bfloat16 and stores into final output (forward must invoke this kernel; no torch .to in forward).
- No torch reductions, means, std, sqrt, or tensor creations in forward. Only Triton kernels and allocations.

This design matches the original semantics exactly and is robust for large shapes. It avoids atomics, handles variable sizes with masking, and keeps all math in Triton.

def sum_per_feature_kernel(inp, sum_out, N_ROWS, L, BLOCK_ROWS: tl.constexpr):
    # Each program handles one feature f
    f = tl.program_id(axis=0)
    # Initialize accumulator
    acc = tl.zeros((), dtype=tl.float32)
    # Loop over rows in chunks
    for start in range(0, N_ROWS, BLOCK_ROWS):
        row_idx = start + tl.arange(0, BLOCK_ROWS)
        mask = row_idx < N_ROWS
        # Linear index for inp[row, f]: row * L + f
        idx = row_idx * L + f
        vals = tl.load(inp + idx, mask=mask, other=0.0)
        acc += tl.sum(vals, axis=0)
