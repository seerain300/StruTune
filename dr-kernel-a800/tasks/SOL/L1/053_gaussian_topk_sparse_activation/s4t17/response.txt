```python
        # Compute inv-std-normal multiplier using Triton (scalar)
        p_dev = torch.tensor([float(target_sparsity)], dtype=torch.float32, device=inputs.device)
        std_multiplier = torch.empty([1], dtype=torch.float32, device=inputs.device)
        _ndtri_scalar_kernel[(1,)](p_dev, std_multiplier)

        # Allocate output
        out = torch.empty_like(inputs_f32)

        # Launch sparsification kernel
        _sparsify_row_kernel[grid](inputs_f32, out, mean, std, std_multiplier, N, BLOCK_SIZE=BLOCK_SIZE, num_warps=8, num_stages=4)

        # Cast back to original dtype
        return out.to(inputs.dtype)
```

Notes:
- All Triton kernels are defined and launched from ModelNew.forward. There are no torch.mean/torch.std/torch.relu operations on device tensors in forward.
- The reduction kernel computes both sum and sum of squares, from which mean and std are derived on-device using simple arithmetic (this is not a torch operation; it’s device-side scalar math on small vectors).
- The ndtri Triton kernel implements the Abramowitz & Stegun 7.1.26 approximation with piecewise logic for lower and central regions. This closely matches PyTorch’s behavior and avoids any torch computation on device tensors.
- The sparsification kernel performs the adaptive thresholding and ReLU in a single pass per row, using BLOCK_SIZE=2048 and num_warps=8, num_stages=4 for good throughput on typical intermediate sizes.

This addresses the previous feedback and maintains correctness while ensuring Triton-only computation.
