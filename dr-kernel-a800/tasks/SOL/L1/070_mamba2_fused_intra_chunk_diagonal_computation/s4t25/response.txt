High-level design and plan

- Inputs:
  - hidden_states: [N, T, L_hs, H, D]
  - A_cumsum: [N, H, T, L_hs]
  - B: [N, T, L_hs, G, K]
  - C: [N, T, L_hs, G, K]
  where N=batch_size, T=num_chunks, L_hs=chunk_size, H=num_heads, D=head_dim, G=N_GROUPS=8, K=32 (asserted in original). We will not assume fixed sizes; we’ll make the kernels dynamic.

- Computation steps:
  1) Build L (lower-triangular exponential mask) in Triton:
     - For each (n, h, t), construct a 2D matrix M_segment of shape [L_hs, L_hs]:
       M_segment[i, j] = sum_{m=0..j} A_cumsum[n, h, t, i] for i <= j, else 0.
     - L[i, j] = exp(M_segment[i, j]) when i <= j, else 0. We implement this with 2D tile in Triton: grid=(1, 1, 1) per (n, h, t) and broadcast results. This avoids tril/cumsum and is O(L^2), which is fine and simpler for correctness on small L. The kernel will:
       - Compute i_offsets and j_offsets via tl.arange, with masks i<L and j<L.
       - For each i (outer loop), accumulate m from 0 to L-1: mask m <= j and i <= j to load A_cumsum[n, h, t, i] and accumulate. This avoids out-of-bounds and handles any L.
       - Store exp(acc) to L_out[n, h, t, i, j] where i<=j; else 0.

  2) Contract B @ C^T to G in Triton:
     - Compute G[n, t, i, j] = sum over groups g in [0..7] and K in [0..31] of C[n, t, i, g, k] * B[n, t, j, g, k].
     - Triton kernel _contract_bc_to_g: grid over (N, T, L_hs, L_hs) and loop over G and K. Pass BLOCK_K meta-parameter and loop k from 0..K-1; K is runtime. This avoids expand/permute and handles arbitrary L_hs.

  3) Apply lower-triangular mask to G:
     - Triton kernel _apply_mask_and_store_M: M = G * L; compute lower-triangular condition inside-kernel via i >= j; store masked output.

  4) Compute Y_diag (diagonal matvec) in Triton:
     - For each (n, t, i, h), output Y[n, t, i, h, d] = sum over j of M[n, t, i, j, h] * hidden_states[n, t, j, h, d].
     - Triton kernel _diag_matvec_sum: grid over (N, T, H), loop j over [0..L_hs-1], accumulate. This computes the result directly; we do not precompute G*M on host.

- Returns:
  - Return Y in bfloat16 to match original behavior.

This design ensures Triton kernels are actually invoked and handle dynamic sizes robustly. It also eliminates the need for torch tril/cumsum on the host and avoids Python-side permutations, which was a source of failure on small workloads.
