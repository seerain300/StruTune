Design: Triton-only frequency domain extraction using rfftfreq
- Rather than manually computing sin/cos for arbitrary n, which is error-prone and inconsistent with PyTorch for different seqlen, we will:
  - Compute k_indices = rfftfreq(2*seqlen, 1/(2*seqlen)) in PyTorch (this is a small vector of length seqlen+1). This gives the exact frequency indices for rfft.
  - For each (batch, channel) slice, construct an exponent base per k = 0..seqlen: base = -2*pi * k * k_indices.
  - Then, compute y_real and y_imag by taking the dot product of x[:L] with cos(base[:L]) and sin(base[:L]) respectively, and scale by 1/(2*seqlen). This matches rfft’s result for real inputs.
- Implementation details:

    batch: tl.int32,       # B

    pad_stride_c: tl.int32,# stride for channel in padded
    pad_stride_l: tl.int32,# stride for last dim in padded
    BLOCK_L: tl.constexpr   # tile size for L
):

    b = pid // channels
    c = pid % channels

    x_base = b * x_stride_b + c * x_stride_c
    pad_base = b * pad_stride_b + c * pad_stride_c

    # Copy first half: j = 0..L-1
    j = 0

        j_vec = j + tl.arange(0, BLOCK_L)
        mask = j_vec < L
        vals = tl.load(x_ptr + x_base + j_vec * x_stride_l, mask=mask, other=0.0)
        tl.store(x_padded_ptr + pad_base + j_vec * pad_stride_l, vals, mask=mask)
        j += BLOCK_L
