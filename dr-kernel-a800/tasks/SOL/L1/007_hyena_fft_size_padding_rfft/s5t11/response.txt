import torch
import triton
import triton.language as tl


@triton.jit
def cosine_sum_kernel(x_ptr, out_ptr, j, N, stride_row, L):
    """
    Compute real_rfft[j] for j in [0, L-1], where L=seqlen+1 and N=2*seqlen.
    real_out[j] = (1/N) * sum_{k=0..N-1} x[k] * cos(2*pi*j*k/N)
    out_ptr is per-(b,c) row flattened to length L. We store at index j.
    """
    acc = 0.0
    # Sum over padded length N: x_ptr is length N, with zeros in the second half.
    # Triton cannot iterate over runtime N directly in a range; use a while loop.
    k = 0
    while k < N:
        xk = tl.load(x_ptr + k)
        angle = 2.0 * 3.141592653589793 * j * k / N
        acc += xk * tl.cos(angle)
        k += 1
    # Normalize by N (original code divides by 2*seqlen; here N == 2*seqlen)
    acc *= 1.0 / N
    # Store result at out_ptr[j]
    tl.store(out_ptr + j, acc)

    Compute imag_rfft[j] for j in [1, L-2], where L=seqlen+1 and N=2*seqlen.

Deep analysis and plan

Understanding the original behavior
- Input x has shape (batch, channels, seqlen).
- torch.fft.rfft(x, n=2*seqlen) computes the real-input FFT for each (batch, channel) row, padding to length 2*seqlen with zeros, and returns a complex output of length (2*seqlen)//2 + 1 = seqlen + 1 bins.
- The outputs are normalized by 2*seqlen (not by seqlen+1), and the function returns the real and imaginary parts separately.

Why the previous attempts failed
- The earlier submissions either didn’t launch Triton kernels (decoy) or used Triton loops in a way that could cause runtime issues. The evaluator requires that Triton kernels are actually called from forward, and correctness must be maintained for all provided workloads.

Triton approach without torch.fft
We can compute the rfft bins directly for real inputs without using torch.fft by leveraging the identity for real-valued DFT:

For a real vector x of length N_in (here N_in = seqlen), the rfft output of length M_out = N_in + 1 when padding to N = 2*N_in has:
- real_out[j] = (1/N) * sum_{k=0..2N-1} x[k] * cos(2*pi*j*k/(2N)) for j=0..M_out-1
- imag_out[j] = (1/N) * sum_{k=0..2N-1} x[k] * sin(2*pi*j*k/(2N)) for j=1..M_out-2
  imag_out[0] = 0, imag_out[M_out-1] = 0 (since sin terms at zero and Nyquist are zero for real input).

Implementation strategy
- For each (batch, channel) row, create a padded input x_row_padded of length N = 2*seqlen, with x[b, c, :] in the first half and zeros in the second half (implicit zero-padding).
- Compute the cosine sums for real_out:
  - Launch a Triton kernel that computes real_out[j] for j in 0..seqlen. It loops over k from 0 to N-1, accumulates x[k] * cos(2*pi*j*k/N), normalizes by N, and writes to an output buffer for that (b, c) row.
- Compute the sine sums for imag_out:
  - Launch a Triton kernel that computes imag_out[j] for j in 1..seqlen-1. It loops over k from 0 to N-1, accumulates x[k] * sin(2*pi*j*k/N), normalizes by N, and writes to an output buffer for that (b, c) row. We set imag_out[0] and imag_out[seqlen] to zero explicitly.

Integration into ModelNew.forward
- In forward, we:
  - Ensure input is float32 and contiguous.
  - Allocate output buffers: real_out and imag_out with shape (batch, channels, seqlen+1), float32.
  - Flatten each (b, c) row into a 1D buffer of length L = seqlen+1 and launch cosine_sum_kernel for j in 0..seqlen. We’ll call this kernel once per j; Triton will compile a version specialized for that j, which is fine here.
  - Similarly, launch sine_sum_kernel for j in 1..seqlen-1.
  - Return real_out and imag_out.

This guarantees Triton kernels are invoked and perform the computation, while preserving exact behavior of the original code.
