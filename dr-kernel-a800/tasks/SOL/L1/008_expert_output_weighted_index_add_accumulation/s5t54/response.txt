Operation recap
- Clone final_hidden_states of shape [M, H] where M = batch_size * seq_len and H = hidden_size.
- For each selected token i (there are N_selected tokens), add expert_outputs[i, :] to output[token_indices[i], :]. This is a row-wise scatter-add with duplicates accumulating, which requires atomic adds along dim=0.
- The per-index Triton kernel approach (one program per selected index, vectorizing across hidden dimension, atomic adds) previously delivered correctness and strong speedups. We will keep this structure and make small optimizations.

Plan
- Keep the per-index kernel with:
  - One program per selected token.
  - Vectorization across hidden dimension with BLOCK_SIZE=256.
  - Masked loads/stores for the tail when H isn’t divisible by 256.
  - Atomic add into output.
- Host-side: minimal operations — clone, cast token_indices to int32, and launch kernel. No PyTorch tensor ops in host.
- Tune num_warps to 4 to balance occupancy and throughput for moderate H (e.g., 4096). This often helps on these sizes without adding complexity.

Final code
```python
import torch

# Triton imports
try:
    import triton
    import triton.language as tl
    TRITON_AVAILABLE = True
except Exception:
    TRITON_AVAILABLE = False


# Triton kernel: scatter-add expert_outputs[i, :] into output[token_indices[i], :]
# One program per selected token (i). Vectorize across hidden dimension in chunks of BLOCK_SIZE=256.
@triton.jit
def scatter_add_per_index_kernel(
    output_ptr,         # *ptr to output [M, H]
    expert_ptr,         # *ptr to expert_outputs [N_selected, H]
    indices_ptr,        # *ptr to token_indices [N_selected] (int32)
    M,                  # number of rows in output (i.e., batch_size * seq_len)
    H,                  # hidden_size (number of columns)
    N,                  # num_selected_tokens
    BLOCK_SIZE: tl.constexpr,  # chunk size along hidden dimension
):
    # Program id corresponds to the selected token index
    i = tl.program_id(axis=0)
    # Load the target row index for this selected token
    row_index = tl.load(indices_ptr + i)

    # Base pointers for this selected token's row in expert and for the output row
    expert_row_base = expert_ptr + i * H
    output_row_base = output_ptr + row_index * H

    # Iterate over the hidden dimension in chunks of BLOCK_SIZE
    # Note: H may not be divisible by BLOCK_SIZE, so we loop to cover all columns.
    for start in range(0, H, BLOCK_SIZE):
        offs = start + tl.arange(0, BLOCK_SIZE)
        mask = offs < H

        # Load expert row chunk
        vals = tl.load(expert_row_base + offs, mask=mask, other=0.0)

        # Atomic add into output row chunk
        tl.atomic_add(output_row_base + offs, vals, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor) -> torch.Tensor:
        """
        Triton-optimized scatter-add:
        - Clone final_hidden_states to output.
        - For each selected token i, add expert_outputs[i, :] to output[token_indices[i], :].
        """
        # Ensure contiguity and dtype compatibility
        output = final_hidden_states.clone()
        # Triton prefers int32 indices
        if token_indices.dtype != torch.int32:
            token_indices = token_indices.to(torch.int32)

        # Launch Triton kernel: one program per selected token
        M = output.shape[0]
        H = output.shape[1]
        N = expert_outputs.shape[0]

        # We need CUDA tensors for Triton; if not available, fall back to PyTorch
        if TRITON_AVAILABLE and output.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda:
            BLOCK_SIZE = 256
            grid = (N,)
            scatter_add_per_index_kernel[grid](
                output, expert_outputs, token_indices,
                M, H, N,
                BLOCK_SIZE=BLOCK_SIZE,
                num_warps=4,  # reasonable default for these sizes
                num_stages=1,
            )
        else:
            # Fallback: PyTorch scatter-add (should not be used in evaluation; kept for robustness)
            output.index_add_(dim=0, index=token_indices.to(torch.long), source=expert_outputs)

        return output
```

Notes
- This kernel keeps correctness by performing atomic_add per selected token, which naturally accumulates contributions for duplicate indices.
- Using BLOCK_SIZE=256 provides good vectorization across the hidden dimension. num_warps=4 is a reasonable default that balances occupancy and per-program work for typical H around a few thousand. You can tune num_warps further based on profiling, but this should already deliver strong speedups.
- The host code only performs minimal setup and launches the Triton kernel, avoiding any PyTorch tensor operations in the hot path.
