Analysis and optimization plan
- Current kernel characteristics:
  - One Triton program handles T updates (T is a compile-time constant like 4).
  - For each update lane, it iterates over hidden dimension in chunks of BLOCK_H and performs a single atomic_add per chunk.
  - This reduces atomics from H per update to ceil(H / BLOCK_H), which is good, but we can do even better when hidden_size is a common multiple (e.g., 1024) by writing the entire row in one atomic add.
- Key optimization:
  - Introduce a “full-row” kernel variant for the case H <= BLOCK_H (we’ll choose BLOCK_H = 1024). In this variant, each program handles up to T updates and performs a single atomic_add for the entire row per update (no loop). This minimizes atomic operations: T * atomic adds per program instead of T * ceil(H / BLOCK_H).
  - Keep the existing multi-chunk kernel for larger H. It still reduces atomics by a factor of BLOCK_H and preserves correctness.
- Heuristics:
  - If H <= 1024: use full-row kernel with BLOCK_H = 1024, num_warps = 8, T = 4.
  - Else: use multi-chunk kernel:
    - If H >= 2048: BLOCK_H = 1024, num_warps = 8.
    - If H >= 1024: BLOCK_H = 512, num_warps = 4.
    - Else: BLOCK_H = 256, num_warps = 2.
    - T = 4 for both to balance per-program work and register pressure.
- Host-side:
  - Ensure tensors are on CUDA device and contiguous.
  - Create output accumulator in float32 (final_hidden_states converted to float32). Triton does not support bfloat16 atomic adds; float32 is fine. Cast back to bfloat16 after the kernel.

Rationale
- Correctness: Atomic adds in float32 are supported and duplicates are handled properly. We clone final_hidden_states to produce a fresh output buffer, and return the casted result to bfloat16 to match the original interface.
- Performance: The full-row path eliminates the inner loop for H <= 1024, reducing atomic operations further. Processing multiple updates per program reduces launch overhead and improves utilization. Chunked vector loads/stores improve memory coalescing.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_full_row_kernel(
    out_ptr,            # *float32 [B, H]
    indices_ptr,        # *int32 [N]
    vals_ptr,           # *float32 [N, H]
    N,                  # int32: number of updates
    H: tl.constexpr,    # hidden size (constexpr for specialization)
    T: tl.constexpr,    # updates per program
    BLOCK_H: tl.constexpr,  # block size (== H in this kernel)
):
    pid = tl.program_id(axis=0)
    start = pid * T
    # Vector of lanes within a program
    lanes = tl.arange(0, T)
    # Compute positions handled by this program (masked for tail)
    pos = start + lanes
    mask_pos = pos < N

    # Load token indices for these positions
    idx = tl.load(indices_ptr + pos, mask=mask_pos, other=0).to(tl.int32)

    # Compute row offsets (each row is contiguous in memory)
    row_offsets = idx * H  # shape [T], int32

    # Process each update lane: atomic add entire row of vals_ptr[pos, :]
    # For each lane, do a single atomic add of the full row
    # We use a compile-time loop over T (small).
    for k in range(T):
        if not (pos[k] < N):
            continue
        # Load val_row[k, :] as float32
        offs = row_offsets[k] + tl.arange(0, H)  # [H] contiguous
        v = tl.load(vals_ptr + pos[k] * H + tl.arange(0, H), mask=mask_pos[k], other=0.0).to(tl.float32)  # mask_pos scalar, broadcast ok
        # Atomic add into output row
        out_row_ptr = out_ptr + row_offsets[k] + tl.arange(0, H)
        tl.atomic_add(out_row_ptr, v)


@triton.jit
def scatter_add_chunked_kernel(
    out_ptr,             # *float32 [B, H]
    indices_ptr,         # *int32 [N]
    vals_ptr,            # *float32 [N, H]
    N,                   # int32: number of updates
    H,                   # int32: hidden size (runtime)
    T: tl.constexpr,     # updates per program
    BLOCK_H: tl.constexpr,
):
    pid = tl.program_id(axis=0)
    start = pid * T
    lanes = tl.arange(0, T)
    pos = start + lanes
    mask_pos = pos < N

    # Load indices
    idx = tl.load(indices_ptr + pos, mask=mask_pos, other=0).to(tl.int32)

    # Iterate over hidden dimension in blocks
    num_blocks = (H + BLOCK_H - 1) // BLOCK_H
    for b in range(0, num_blocks):
        h_start = b * BLOCK_H
        h_offsets = h_start + tl.arange(0, BLOCK_H)
        mask_h = h_offsets < H

        # Build per-lane pointers for vals: vals_ptr[pos[k], h_offsets]
        # Pointer for each lane is base + pos[k]*H + h_offsets
        for k in range(T):
            if (pos[k] < N):
                base = pos[k] * H
                v = tl.load(vals_ptr + base + h_offsets, mask=mask_pos[k] & mask_h, other=0.0).to(tl.float32)
                out_ptrs = out_ptr + idx[k] * H + h_offsets
                tl.atomic_add(out_ptrs, v)


def _select_config(H: int):
    # Choose BLOCK_H and num_warps based on H
    if H <= 1024:
        BLOCK_H = 1024
        num_warps = 8
    elif H <= 2048:
        BLOCK_H = 1024
        num_warps = 8
    elif H <= 4096:
        BLOCK_H = 512
        num_warps = 4
    else:
        BLOCK_H = 256
        num_warps = 2
    return BLOCK_H, num_warps


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Ensure CUDA and contiguity
        device = final_hidden_states.device
        assert device.type == "cuda", "Triton kernels require CUDA tensors"
        final_hidden_states = final_hidden_states.contiguous()
        expert_outputs = expert_outputs.contiguous()
        token_indices = token_indices.contiguous()

        # Compute shapes
        B, H = final_hidden_states.shape
        N = expert_outputs.shape[0]
        assert token_indices.shape[0] == N, "token_indices length must match num_selected_tokens"

        # Prepare fp32 output buffer for accumulation (bfloat16 atomics not supported)
        out_fp32 = final_hidden_states.to(torch.float32).clone()

        # Cast expert_outputs to float32 for accumulation
        vals_fp32 = expert_outputs.to(torch.float32)

        # Triton prefers int32 indices for pointer arithmetic
        indices_i32 = token_indices.to(torch.int32)

        # Select kernel config
        BLOCK_H, num_warps = _select_config(H)
        T = 4  # number of updates per program

        # Grid size: number of programs; each handles T updates
        if H <= BLOCK_H:
            # Full-row path: one atomic add per update (no inner loop)
            grid = (triton.cdiv(N, T),)
            scatter_add_full_row_kernel[grid](
                out_fp32, indices_i32, vals_fp32, N, H, T, BLOCK_H,
                num_warps=num_warps, num_stages=2,
            )
        else:
            # Chunked path: iterate hidden dimension in blocks
            grid = (triton.cdiv(N, T),)
            scatter_add_chunked_kernel[grid](
                out_fp32, indices_i32, vals_fp32, N, H, T, BLOCK_H,
                num_warps=num_warps, num_stages=2,
            )

        # Cast back to bfloat16 to match original API
        return out_fp32.to(torch.bfloat16)

    pid = tl.program_id(axis=0)
    start = pid * T
    lanes = tl.arange(0, T)
    pos = start + lanes
    mask_pos = pos < N

    # Load indices
    idx = tl.load(indices_ptr + pos, mask=mask_pos, other=0).to(tl.int32)

    # Iterate over hidden dimension in blocks
    num_blocks = (H + BLOCK_H - 1) // BLOCK_H
    for b in range(0, num_blocks):
        h_start = b * BLOCK_H
        h_offsets = h_start + tl.arange(0, BLOCK_H)
        mask_h = h_offsets < H

        for k in range(T):
            if pos[k] < N:
                base = pos[k] * H
                v = tl.load(vals_ptr + base + h_offsets).to(tl.float32)
                out_ptrs = out_ptr + idx[k] * H + h_offsets
                tl.atomic_add(out_ptrs, v)


def _select_config(H: int):
    # Choose BLOCK_H, num_warps, and T based on H
    if H >= 4096:
        BLOCK_H = 1024
        num_warps = 8
        T = 8
    elif H >= 2048:
        BLOCK_H = 1024
        num_warps = 8
        T = 8
    elif H >= 1024:
        BLOCK_H = 512
        num_warps = 4
        T = 8
    elif H >= 512:
        BLOCK_H = 512
        num_warps = 4
        T = 8
    elif H >= 256:
        BLOCK_H = 256
        num_warps = 2
        T = 8
    elif H >= 128:
        BLOCK_H = 128
        num_warps = 2
        T = 4
    else:
        BLOCK_H = 64
        num_warps = 1
        T = 4
    return BLOCK_H, num_warps, T


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Ensure CUDA tensors and contiguity
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "All tensors must be on CUDA"
        final_hidden_states = final_hidden_states.contiguous()
        expert_outputs = expert_outputs.contiguous()
        token_indices = token_indices.contiguous()

        # Shapes
        B, H = final_hidden_states.shape
        N = expert_outputs.shape[0]
        assert token_indices.shape[0] == N, "token_indices length must match num_selected_tokens"

        # Accumulator in float32 (bfloat16 atomic_add not supported)
        out_fp32 = final_hidden_states.to(torch.float32).clone()

        # Cast expert outputs to float32 for accumulation
        vals_fp32 = expert_outputs.to(torch.float32)

        # Triton prefers int32 indices
        indices_i32 = token_indices.to(torch.int32)

        # Kernel config
        BLOCK_H, num_warps, T = _select_config(H)

        # Grid: each program handles T updates
        grid = (triton.cdiv(N, T),)

        if H <= BLOCK_H:
            # Full-row path: minimal atomics, one add per update (vectorized full row)
            scatter_add_full_row_kernel[grid](
                out_fp32, indices_i32, vals_fp32, N, H, T,
                num_warps=num_warps, num_stages=2,
            )
        else:
            # Chunked path for larger H
            scatter_add_chunked_kernel[grid](
                out_fp32, indices_i32, vals_fp32, N, H, T, BLOCK_H,
                num_warps=num_warps, num_stages=2,
            )

        # Cast back to bfloat16 to match original API
        return out_fp32.to(torch.bfloat16)
```

为什么这样有效
- full-row kernel：每update一次atomic_add，原子次数降到最低，对于H <= 1024的工作负载非常高效。
- chunked kernel：合理选择BLOCK_H和T，减少块数量和程序数量，同时保持较好的并行度和内存访问效率。
- 所有计算都在Triton中完成，没有使用PyTorch的计算来生成结果，严格遵守了“Triton-only”要求。
- 正确性：atomic_add在float32上处理duplicate indices是安全的，最后转换回bfloat16以匹配接口。

如果有任何工作负载表现不佳或需要进一步调整，我们可以考虑：
- 对于非常大的N，尝试增加T到16，但要注意寄存器压力和潜在的性能下降；或者对于某些特定H/N比，略微降低T以提高稳定性。
- 在某些极端情况下，如果N非常大而H很小，可以考虑将T设置为H的倍数来最大化一次程序内的工作量，但通常T固定为4或8已经足够。
