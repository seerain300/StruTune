Detailed analysis and plan

- Original PyTorch behavior:
  - final_hidden_states: tensor of shape (M, H) where M = batch_size * seq_len, H = hidden_size, dtype bfloat16.
  - expert_outputs: tensor of shape (N, H), dtype bfloat16, where N = batch_size * seq_len * num_experts_per_tok.
  - token_indices: tensor of shape (N,), dtype long, values in [0, M).
  - The run function clones final_hidden_states and then performs output.index_add_(dim=0, index=token_indices, source=expert_outputs).
    This is equivalent to: for i in range(N): output[token_indices[i]] += expert_outputs[i], using atomic adds for duplicates.

- What went wrong in previous attempts:
  - First submission failed to invoke a Triton kernel, so it relied on PyTorch index_add (invalid for this task).
  - Second submission defined and launched a Triton kernel, but some configurations showed numerical mismatches. The evaluator reports “INCORRECT_NUMERICAL” for several workloads, which means the Triton scatter-add isn’t exactly reproducing PyTorch’s index_add behavior in all shapes/dtypes/index patterns. This is a robustness issue on Triton’s atomic_add semantics for bfloat16 scatter along a non-identity index.

- Strategy to ensure correctness:
  - We must use a Triton kernel and perform the actual scatter-add (no PyTorch index_add), while keeping behavior identical to the original. To maximize correctness, implement a simple, robust per-row per-element atomic add:
    - One Triton program handles one source row i, iterates over the hidden dimension H in a loop, loads expert_outputs[i, j], and performs tl.atomic_add(output[token_indices[i], j], expert_outputs[i, j]).
    - This avoids complex tiling and masking that can introduce off-by-one or out-of-bounds behavior. While it’s less performant than vectorized tiles, it is reliable and matches torch.index_add semantics (duplicate indices are summed via atomics).

- Performance considerations:
  - The per-element loop does H atomics per row, which can be heavy for large N and H. However, correctness is paramount. Once correctness is guaranteed across all configurations, we can revisit a vectorized tile-based approach (BLOCK_H) and map multiple tiles per row across a second grid dimension to improve throughput, while retaining correctness checks.
  - For now, prioritize correctness and robustness. We still launch a Triton kernel from ModelNew.forward, as required.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_rows_atomic_kernel(
    output_ptr,          # *bfloat16, shape [M, H]
    source_ptr,          # *bfloat16, shape [N, H]
    index_ptr,           # *int32,    shape [N]
    M: tl.constexpr,     # int: number of rows in output
    N: tl.constexpr,     # int: number of source rows
    H: tl.constexpr      # int: hidden size
):
    # Each program handles one source row i
    pid = tl.program_id(axis=0)
    if pid >= N:
        return

    # Load the destination row index for this source row
    dest = tl.load(index_ptr + pid)  # int32
    # Loop over hidden dimension and perform atomic add per element
    for j in range(0, H):
        # Load source value as bfloat16
        src_val = tl.load(source_ptr + pid * H + j)  # bfloat16
        # Atomic add into output at (dest, j)
        tl.atomic_add(output_ptr + dest * H + j, src_val)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        """
        Triton-optimized version of the original run() function.
        Performs atomic accumulation: output[token_indices[i]] += expert_outputs[i] for all i.
        Returns the updated output tensor (clone of final_hidden_states, then accumulation).
        """
        # Ensure CUDA device and contiguity
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, \
            "All tensors must be on CUDA device for Triton kernels."
        # Preserve original final_hidden_states by cloning
        output = final_hidden_states.clone()
        output = output.contiguous()
        expert_outputs = expert_outputs.contiguous()
        token_indices = token_indices.contiguous()

        # Shapes
        M = output.shape[0]  # batch_seq_len
        H = output.shape[1]  # hidden_size
        N = expert_outputs.shape[0]  # num_selected_tokens

        # Triton grid: one program per source row
        grid = (N,)

        # Cast indices to int32 for Triton
        index_i32 = token_indices.to(torch.int32)

        # Launch Triton kernel
        scatter_add_rows_atomic_kernel[grid](
            output,            # output_ptr
            expert_outputs,    # source_ptr
            index_i32,         # index_ptr
            M,                 # M
            N,                 # N
            H                  # H
        )

        return output
```
