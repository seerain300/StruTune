Great, we have correctness across all 16 workloads and a geomean speedup of ~1.19x. The operation is a scatter-add along rows: output[token_indices[i]] += expert_outputs[i, :]. To further improve performance without risking correctness, we should:

- Minimize the number of atomic operations while preserving the parallelization across updates. Our previous vectorized approach already reduces atomics from H per update to H / BLOCK_H per update. We can take this a step further by processing multiple updates per Triton program (T updates), so each program performs only a small number of atomic adds (T * number_of_blocks). This reduces kernel launch overhead and can improve throughput.

Plan
- Implement a Triton kernel that:
  - Uses a 1D grid where each program handles T updates (T is a small compile-time constant like 4 or 8).
  - For each program, compute a base index start = pid * T and process updates at positions pos = start + k for k in [0, T), using a mask for the last program that may have fewer updates.
  - For each update lane, load the index idx = token_indices[pos], and process the hidden dimension in blocks of BLOCK_H:
    - Load v_chunk = expert_outputs[pos, h:h+BLOCK_H] as float32.
    - Perform a single atomic_add of v_chunk into out_fp32[idx, h:h+BLOCK_H].
  - This keeps atomics per update to around H / BLOCK_H and reduces the number of programs by factor T. It maintains correct accumulation for duplicate indices via atomic adds.
- Host-side:
  - Ensure tensors are on CUDA, contiguous.
  - Clone final_hidden_states and cast it to float32 for accumulation (bfloat16 atomic adds aren’t supported). Perform the Triton kernel on that fp32 buffer.
  - After kernel, cast the accumulated output back to bfloat16 to match the original interface.

Heuristics
- BLOCK_H: choose based on hidden_size:
  - If H >= 1024, BLOCK_H = 1024, num_warps = 8.
  - Else if H >= 512, BLOCK_H = 512, num_warps = 4.
  - Else, BLOCK_H = 256, num_warps = 2.
- T (updates per program): 4 is a good balance; try 8 for very large H/N. For the provided workloads, 4 is sufficient.

Code (Triton kernel with T=4)

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_rows_multi_update_kernel(
    out_ptr,            # *float32, shape [M, H] (M=batch_seq_len)
    token_indices_ptr,  # *int32, shape [N]
    expert_outputs_ptr, # *float32, shape [N, H]
    N,                  # int32, total number of updates
    H,                  # int32, hidden size
    T: tl.constexpr,    # number of updates per program (compile-time constant)
    BLOCK_H: tl.constexpr,  # block size along hidden dimension
):
    # One program handles T updates
    pid = tl.program_id(axis=0)
    start = pid * T

    # Vectorized lanes for the T updates
    k = tl.arange(0, T)  # vector [0..T-1]
    pos = start + k
    mask_k = pos < N  # mask for valid lanes

    # Load token indices for each of the T lanes
    idx = tl.load(token_indices_ptr + pos, mask=mask_k, other=0)  # int32

    # Loop over hidden dimension in chunks of BLOCK_H
    for h in range(0, H, BLOCK_H):
        offs = h + tl.arange(0, BLOCK_H)  # vector of column offsets
        mask_offs = offs < H

        # Build 2D mask for valid lanes and valid columns
        mask = mask_k[:, None] & mask_offs[None, :]

        # Load v_chunk for each lane: shape [T, BLOCK_H]
        # Each lane loads expert_outputs[pos, offs]
        v = tl.load(
            expert_outputs_ptr + pos[:, None] * H + offs[None, :],
            mask=mask,
            other=0.0,
        )  # float32

        # Atomic add v into out[idx, offs] for each lane
        # out is float32; indices are int32
        tl.atomic_add(out_ptr + idx[:, None] * H + offs[None, :], v, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Fallback to PyTorch if not on CUDA (rare in evaluation, but safe)
        if not final_hidden_states.is_cuda or not expert_outputs.is_cuda or not token_indices.is_cuda:
            output = final_hidden_states.clone()
            output.index_add_(0, token_indices, expert_outputs.to(output.dtype))
            return output

        # Ensure contiguity and dtypes
        M = final_hidden_states.shape[0]
        H = final_hidden_states.shape[1]
        N = expert_outputs.shape[0]

        # Prepare output buffer in float32 for atomic accumulation
        out_fp32 = final_hidden_states.clone().to(torch.float32)

        # Ensure inputs are contiguous
        token_indices_i32 = token_indices.to(torch.int32).contiguous()
        expert_outputs_fp32 = expert_outputs.contiguous().to(torch.float32)

        # Heuristics for BLOCK_H and T
        if H >= 1024:
            BLOCK_H = 1024
            num_warps = 8
        elif H >= 512:
            BLOCK_H = 512
            num_warps = 4
        else:
            BLOCK_H = 256
            num_warps = 2

        # Process multiple updates per program
        T = 4

        # Grid size: number of programs
        grid = (triton.cdiv(N, T),)

        scatter_add_rows_multi_update_kernel[grid](
            out_fp32,
            token_indices_i32,
            expert_outputs_fp32,
            N,
            H,
            T=T,
            BLOCK_H=BLOCK_H,
            num_warps=num_warps,
            num_stages=2,
        )

        # Cast back to bfloat16 to match original API
        return out_fp32.to(torch.bfloat16)
```

- BLOCK_H and num_warps are chosen heuristically based on H; you can refine these based on profiling in your environment.

    idx = tl.load(token_indices_ptr + pos, mask=mask_k, other=0)  # int32

    # Iterate over hidden dimension in chunks
    for h in range(0, H, BLOCK_H):
        offs = h + tl.arange(0, BLOCK_H)      # column offsets
        mask_offs = offs < H                   # mask for last block

        # 2D mask for valid lanes and valid columns
        mask = mask_k[:, None] & mask_offs[None, :]

        # Load v_chunk for each lane: shape [T, BLOCK_H]
        v = tl.load(
            expert_outputs_ptr + pos[:, None] * H + offs[None, :],
            mask=mask,
            other=0.0,
        )  # float32

        # Atomic add into output
        tl.atomic_add(out_ptr + idx[:, None] * H + offs[None, :], v, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Fallback to PyTorch if not on CUDA (safety)
        if (not final_hidden_states.is_cuda) or (not expert_outputs.is_cuda) or (not token_indices.is_cuda):

            output.index_add_(0, token_indices, expert_outputs.to(output.dtype))

        # Shapes
        M = final_hidden_states.shape[0]
        H = final_hidden_states.shape[1]
        N = expert_outputs.shape[0]

        # Output buffer in float32 for atomic accumulation
        out_fp32 = final_hidden_states.clone().to(torch.float32)

        # Ensure inputs are contiguous and dtype correct
        token_indices_i32 = token_indices.to(torch.int32).contiguous()
        expert_outputs_fp32 = expert_outputs.contiguous().to(torch.float32)

        # Heuristics for BLOCK_H and num_warps based on H
        if H >= 2048:
            BLOCK_H = 1024
            num_warps = 8
        elif H >= 1024:
            BLOCK_H = 1024
            num_warps = 8
        elif H >= 512:
            BLOCK_H = 512
            num_warps = 4
        elif H >= 256:
            BLOCK_H = 256
            num_warps = 2
        elif H >= 128:

            num_warps = 2
        elif H >= 64:

        elif H >= 32:

            num_warps = 1
        elif H >= 16:

            num_warps = 1
        elif H >= 8:

            num_warps = 1
        elif H >= 4:

        # Process multiple updates per program: T=4 is a good balance
        T = 4

        grid = (triton.cdiv(N, T),)

Razones de diseño y justificación
- Correctitud: tl.atomic_add en float32 es soportado, y duplicados son correctos ya que Triton fusionará atomics en la misma posición. La clonación de final_hidden_states y conversión a float32 garantiza un estado inicial correcto, y el cast final a bfloat16 responde a la API original.
- Performance: Vectorizando a través de H en bloques reduce atomics desde H por update a ceil(H / BLOCK_H). Procesar T updates per program reduce el número de programas y overhead. BLOCK_H y num_warps se eligen dinámicamente según H. T=4 es un equilibrio robusto.
- Portabilidad: Uso estándar de Triton (tl.arange, masks, program_id) y se mantienen conversiones y contiguity en host, que son accionables.
