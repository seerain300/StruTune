Deep analysis and optimization plan

Operation recap
- We need to perform per-row scatter-add: for each i, output[token_indices[i]] += expert_outputs[i].
- output has shape [M, H] where M = batch_size * seq_len and H = hidden_size. token_indices[i] in [0, M). expert_outputs[i] has shape [H].
- In PyTorch, index_add handles duplicates correctly and is highly optimized. Our Triton approach must mimic this.

Why performance is lagging
- The previous Triton kernel used one program per update (N = num_selected_tokens) and either per-element atomic_add or masked vectorized atomic_add. This introduces many small atomic operations and can underutilize the GPU, leading to slower performance.
- On GPUs, row-wise writes are best handled with row-tiling: each program handles multiple rows at once, vectorized across the hidden dimension. This reduces atomic contention and improves memory coalescing.

Optimization strategy
- Use a row-tiling Triton kernel:
  - Grid: 2D, (N_tiles, M_tiles), where:
    - N_tiles = ceil_div(N, BLOCK_N), number of tiles along the updates dimension.
    - M_tiles = ceil_div(M, BLOCK_M), number of tiles along the row dimension.
  - Each program processes BLOCK_M rows (a tile of rows) and BLOCK_N updates (a tile of updates). For each row in its tile and for each update in its tile:
    - Load idx = token_indices[i] and the corresponding v = expert_outputs[i, :] as float32.
    - Atomic add v into out_fp32[row, :], for all rows in the tile. This reduces the number of atomic operations and performs batched atomics for multiple rows.
- Accumulate in float32 to avoid bfloat16 atomic limitations. Finally, cast the accumulated output back to bfloat16 to match the original.
- Keep tensors contiguous and ensure dtype conversions are correct.

Correctness considerations
- Duplicate indices are handled by atomic_add; each update adds its row regardless of prior updates, matching index_add semantics.
- We avoid per-element loops inside the kernel by using vectorized loads/stores and broadcasting. This approach should be robust across Triton versions, as it avoids intricate masked vector atomic patterns that previously caused intermittent failures.

Kernel details
- Parameters: out_fp32 (M, H), expert_outputs (N, H), token_indices (N), N, M, H.
- Use tl.atomic_add for float32. No need for masks on row tile if we set grid to cover all rows; masks can be used for safety if needed.
- Choose BLOCK_M = 128 and BLOCK_N = 64 as reasonable defaults. These values provide good parallelism and coalescing on typical GPUs. They can be adjusted, but 128/64 are safe and effective for a wide range of hidden sizes.

Host-side setup
- Convert final_hidden_states to float32 and clone to out_fp32 (M, H).
- Convert expert_outputs to float32 (N, H).
- Convert token_indices to int32 (N).
- Launch the Triton kernel with grid = (ceil_div(N, BLOCK_N), ceil_div(M, BLOCK_M)).
- After the kernel finishes, cast out_fp32 to bfloat16 and return.

This design significantly reduces the number of atomic operations and should improve performance while maintaining correctness.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_rows_kernel(
    out_ptr,          # *float32, shape [M, H]
    expert_ptr,       # *float32, shape [N, H]
    idx_ptr,          # *int32,   shape [N]
    N,                # int32
    M,                # int32
    H,                # int32
    BLOCK_M: tl.constexpr,  # tile size along rows
    BLOCK_N: tl.constexpr,  # tile size along updates
):
    # 2D launch grid: (tiles along updates, tiles along rows)
    pid_n = tl.program_id(0)
    pid_m = tl.program_id(1)

    # Rows and updates this program handles
    row_start = pid_m * BLOCK_M
    update_start = pid_n * BLOCK_N

    rows = row_start + tl.arange(0, BLOCK_M)  # [BLOCK_M]
    updates = update_start + tl.arange(0, BLOCK_N)  # [BLOCK_N]

    # Masks for in-bounds
    rows_mask = rows < M
    updates_mask = updates < N

    # For each update in the tile, add its vector to the corresponding row
    # Note: atomic_add accumulates across duplicates correctly.
    for k in range(BLOCK_N):
        i = updates[k]
        row_mask_k = updates_mask[k]  # scalar boolean
        # If this update is out of range, skip
        if row_mask_k:
            # Load index
            idx = tl.load(idx_ptr + i)  # int32
            # Load expert vector for this update (shape [H])
            v = tl.load(expert_ptr + i * H + tl.arange(0, H), mask=True, other=0.0)  # [H]
            # Atomic add v into out[row, :] for each row in the tile
            # rows is [BLOCK_M], v is [H]; broadcasting across rows
            for j in range(BLOCK_M):
                row = rows[j]
                valid_row = rows_mask[j]
                # If this row is out of bounds, skip
                if valid_row:
                    # Compute base pointer for this row
                    base = row * H
                    # Atomic add v into out[row, :]
                    # Triton supports atomic_add on fp32
                    tl.atomic_add(out_ptr + base + tl.arange(0, H), v)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor,
                expert_outputs: torch.Tensor,
                token_indices: torch.Tensor):
        """
        Triton implementation of:
          output = final_hidden_states.clone()
          output.index_add_(dim=0, index=token_indices, source=expert_outputs)
        where final_hidden_states: [batch_seq_len, hidden_size], bfloat16
              expert_outputs: [num_selected_tokens, hidden_size], bfloat16
              token_indices: [num_selected_tokens], long
        Returns output in bfloat16, with duplicates summed.
        """
        # Ensure inputs are on the same device and contiguous
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "All tensors must be on CUDA"
        # Shapes
        M = final_hidden_states.shape[0]
        N = expert_outputs.shape[0]
        H = expert_outputs.shape[1]

        # Accumulate in float32 for correctness
        out_fp32 = final_hidden_states.to(torch.float32).clone()  # [M, H], float32

        # Prepare inputs for Triton
        expert_fp32 = expert_outputs.to(torch.float32)  # [N, H], float32
        # Ensure contiguity
        out_fp32 = out_fp32.contiguous()
        expert_fp32 = expert_fp32.contiguous()
        token_int = token_indices.to(torch.int32)  # [N], int32
        token_int = token_int.contiguous()

        # Kernel launch configuration
        BLOCK_M = 128  # tile size along rows
        BLOCK_N = 64   # tile size along updates
        grid = (triton.cdiv(N, BLOCK_N), triton.cdiv(M, BLOCK_M))

        # Launch Triton kernel
        scatter_add_rows_kernel[grid](
            out_fp32, expert_fp32, token_int,
            N, M, H,
            BLOCK_M=BLOCK_M, BLOCK_N=BLOCK_N,
            num_warps=4,  # reasonable default; can be tuned
        )

        # Cast back to bfloat16 to match original
        result = out_fp32.to(torch.bfloat16)
        return result
```

The choice of BLOCK_M=128 and BLOCK_N=64 is a balanced default; for very large H, you might increase BLOCK_N to 128, and for very large M, BLOCK_M to 256, depending on GPU and typical workload sizes. Optimization plan
- Use a more aggressive vectorized approach, but keep it simple and robust:
  - Assign each Triton program to one update i (grid = (N,)). This avoids complex cross-row vectorization and reduces code complexity.
  - Inside the kernel, load the entire vector v = expert_outputs[i, :] in a single chunk (BLOCK_H >= H). Since H is dynamic per workload, we select BLOCK_H as the next power-of-two >= H, capped to 1024. This ensures we handle any hidden size with a single masked load/store, avoiding per-element loops.
  - Perform a single atomic_add of the loaded vector into the destination row. This reduces the number of atomic operations drastically compared to per-element atomic_adds, and should improve throughput.
- Continue accumulating in float32 and cast back to bfloat16 for the final output to match PyTorch’s original dtype.

Why this should be faster
- Instead of performing many atomics per update (one per element), we perform one atomic operation per update by loading and adding the whole row at once. This reduces atomic contention and kernel overhead, improving performance.
- Using BLOCK_H = next power-of-two >= H minimizes wasted threads and masked operations. For typical hidden sizes (128–1024), this matches Triton’s vectorization preferences and avoids per-element loops.

Correctness considerations
- The kernel uses float32 atomic_add, which is supported and reliable. Duplicates are handled correctly by atomic semantics.
- Masking is used only for the tail when BLOCK_H > H, which is safe; with BLOCK_H chosen as next power-of-two >= H, there is no tail and mask is not needed. Still, we’ll include mask handling for generality.
- We ensure all tensors are contiguous and properly cast on the host side.

```python
import torch
import triton
import triton.language as tl


def _next_power_of_two(x: int) -> int:
    # Returns the next power-of-two >= x, capped at 1024
    if x <= 1:
        return 1
    p = 1
    while p < x and p < 1024:
        p <<= 1
    return p


@triton.jit
def scatter_add_single_update_kernel(
    out_ptr,          # *float32, shape [M, H]
    expert_ptr,       # *float32, shape [N, H]
    idx_ptr,          # *int32,   shape [N]
    N: tl.constexpr,  # int
    M: tl.constexpr,  # int
    H: tl.constexpr,  # int
    BLOCK_H: tl.constexpr,  # int, vector width >= H
):
    # One program per update
    pid = tl.program_id(0)
    # If pid >= N, nothing to do
    if pid >= N:
        return

    # Load destination row index
    idx = tl.load(idx_ptr + pid)  # int32
    if idx < 0 or idx >= M:
        return  # defensive, though token_indices are valid in provided inputs

    # Compute base pointers for this update and destination row
    # expert_ptr is row-major: row i has offset i * H
    base_expert = pid * H
    base_out = idx * H

    # Load the entire vector v = expert_outputs[pid, :] as float32
    offs = tl.arange(0, BLOCK_H)  # [BLOCK_H]
    mask = offs < H
    v = tl.load(expert_ptr + base_expert + offs, mask=mask, other=0.0)  # [BLOCK_H], float32

    # Atomic add v into out[base_out + offs]
    # out_ptr is row-major: out[row, :] base at row * H
    tl.atomic_add(out_ptr + base_out + offs, v, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor,
                expert_outputs: torch.Tensor,
                token_indices: torch.Tensor):
        """
        Triton implementation of:
          output = final_hidden_states.clone()
          output.index_add_(dim=0, index=token_indices, source=expert_outputs)
        where final_hidden_states: [batch_seq_len, hidden_size], bfloat16
              expert_outputs: [num_selected_tokens, hidden_size], bfloat16
              token_indices: [num_selected_tokens], long
        Returns output in bfloat16, with duplicates summed.
        """
        # Ensure all tensors are on CUDA
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "All tensors must be on CUDA"

        # Shapes
        M = final_hidden_states.shape[0]
        N = expert_outputs.shape[0]
        H = expert_outputs.shape[1]

        # Accumulate in float32 for correctness and performance
        out_fp32 = final_hidden_states.to(torch.float32).clone()  # [M, H], float32

        # Prepare inputs for Triton
        expert_fp32 = expert_outputs.to(torch.float32)  # [N, H], float32
        token_int = token_indices.to(torch.int32)      # [N], int32

        # Ensure contiguity
        out_fp32 = out_fp32.contiguous()
        expert_fp32 = expert_fp32.contiguous()
        token_int = token_int.contiguous()

        # Select BLOCK_H as next power-of-two >= H, capped at 1024
        BLOCK_H = _next_power_of_two(H)

        # Launch Triton kernel: one program per update
        grid = (N,)

        # Choose num_warps based on BLOCK_H; 4 or 8 are good defaults
        num_warps = 4 if BLOCK_H <= 256 else 8

        scatter_add_single_update_kernel[grid](
            out_fp32, expert_fp32, token_int,
            N, M, H,
            BLOCK_H=BLOCK_H,
            num_warps=num_warps,
        )

        # Cast back to bfloat16 to match original
        result = out_fp32.to(torch.bfloat16)
        return result
```
