Performance analysis
- Operation: output[token_indices[i]] += expert_outputs[i] for i in [0..N), where output is (M, H), expert_outputs is (N, H), and token_indices length N. This is a scatter-add along dim=0.
- Characteristics:
  - Scatter-add introduces atomic contention when multiple indices target the same output row. We can only mitigate it by increasing per-program work or by a more sophisticated two-phase reduction per row. The latter adds complexity and risks correctness regressions.
  - A 1D grid over N with each program handling an entire H dimension (or large chunks) performs well because it vectorizes over H and reduces kernel launch overhead. It keeps atomics per element, but the simplicity and vectorization typically beat more complex designs that suffer from atomics.

Plan to improve
- Keep the one-program-per-source-row design.
- Increase per-program work by using larger BLOCK_H for larger H to reduce loop iterations and improve memory throughput. Previously, BLOCK_H=256/128/64 worked well. We can slightly adjust to ensure good occupancy without excessive register pressure:
  - If H >= 2048: BLOCK_H=256, num_warps=8, num_stages=3
  - If H >= 512: BLOCK_H=128, num_warps=4, num_stages=2
  - Else: BLOCK_H=64, num_warps=2, num_stages=2
- Keep the while loop over H with runtime termination to handle arbitrary H. This avoids Triton compile-time constraints and makes the kernel robust across varied shapes.
- Ensure inputs are contiguous and token_indices is int32 for efficient address arithmetic.

This should help performance for larger hidden sizes while keeping robustness for smaller ones.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_row_kernel(
    output_ptr,            # *bf16 or *fp16 pointer, shape [M, H]
    expert_ptr,            # *bf16 or *fp16 pointer, shape [N, H]
    index_ptr,             # *int32 pointer, shape [N]
    M, H, N,               # int32 scalars
    BLOCK_H: tl.constexpr  # tile size along H
):
    # Each program handles one source row (n in [0, N))
    n = tl.program_id(0)
    # Guard in case grid > N (not needed if grid == N, but safe)
    if n >= N:
        return

    # Precompute base offsets for this row n
    # We'll process H in chunks of BLOCK_H
    h = 0
    # Loop over H dimension in chunks
    while h < H:
        h_offsets = h + tl.arange(0, BLOCK_H)
        mask = h_offsets < H

        # Load token index for this row
        # index_ptr is int32; token can be any value in [0, M)
        idx = tl.load(index_ptr + n, mask=True)  # scalar, no mask needed
        idx = idx.to(tl.int32)

        # Compute output row pointer: output is row-major, row stride is H
        out_row_ptr = output_ptr + idx * H

        # Load expert output chunk: expert is row-major, row stride is H
        exp_row_ptr = expert_ptr + n * H
        exp_chunk = tl.load(exp_row_ptr + h_offsets, mask=mask, other=0.0)

        # Compute destination pointers and atomic add
        dest_ptr = out_row_ptr + h_offsets
        # Perform atomic add for valid elements
        tl.atomic_add(dest_ptr, exp_chunk, mask=mask)

        # Advance to next chunk
        h += BLOCK_H


def _select_launch_params(H: int):
    # Heuristic tuning based on H
    if H >= 2048:
        return 256, 8, 3  # BLOCK_H, num_warps, num_stages
    elif H >= 512:
        return 128, 4, 2
    else:
        return 64, 2, 2


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        """
        Triton-accelerated scatter-add:
            output[token_indices[i]] += expert_outputs[i]
        where output = final_hidden_states (shape [M, H])
              expert_outputs = shape [N, H]
              token_indices = shape [N], dtype long or int32
        """
        # Ensure device is CUDA for Triton
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "Triton requires CUDA tensors"
        # Ensure contiguous and proper dtypes
        output = final_hidden_states.contiguous()
        expert_outputs = expert_outputs.contiguous()
        # Triton prefers int32 indices for address arithmetic
        if token_indices.dtype != torch.int32:
            # Safe because M and H in provided workloads are within int32 range
            token_indices = token_indices.to(torch.int32)
        token_indices = token_indices.contiguous()

        M, H = output.shape
        N = expert_outputs.shape[0]

        # Choose launch parameters
        BLOCK_H, num_warps, num_stages = _select_launch_params(H)

        # Launch grid: one program per source row
        grid = (N,)

        scatter_add_row_kernel[grid](
            output, expert_outputs, token_indices,
            M, H, N,
            BLOCK_H=BLOCK_H,
            num_warps=num_warps,
            num_stages=num_stages,
        )
        return output
```
