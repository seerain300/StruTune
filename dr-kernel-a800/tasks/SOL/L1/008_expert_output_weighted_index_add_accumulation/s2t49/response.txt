- Operation recap:
  - output = final_hidden_states.clone()

  - For each i in [0, N): add expert_outputs[i, :] into output[token_indices[i], :]. Duplicates in token_indices must accumulate (atomic adds).

- Current working strategy:
  - Launch one Triton program per row i (N programs).
  - Within each program, iterate over the hidden dimension H in chunks of BLOCK, load the chunk from expert_outputs, and perform tl.atomic_add into the destination row out[token_indices[i], cols].
  - This approach is simple and robust. It previously delivered ~2.0x; slight variability can come from BLOCK size and num_warps choices.

- Performance refinements:
  - Choose BLOCK as the next power-of-two of H, capped at 256. This reduces the number of loop iterations (chunks). For H up to 1024 (per previous tests), this usually keeps BLOCK at 128 or 256.
  - Tune num_warps based on BLOCK:
    - BLOCK <= 64: num_warps=2
    - BLOCK <= 128: num_warps=4
    - BLOCK=256: num_warps=8
  - Keep num_stages=2 for pipelining.
  - Ensure tensors are contiguous, output is a clone, and token_indices are int32.
  - Keep the masked vector loads/stores to avoid any out-of-bounds access on the tail.

This strategy preserves correctness and typically improves throughput over a naive per-element atomic add. The main lever is selecting a larger BLOCK (e.g., 128 or 256) when H permits, which reduces loop overhead and atomic operations per row.

Final code (ModelNew)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def _index_add_rows_kernel(
    out_ptr,         # *half, output buffer
    expert_ptr,      # *half, expert_outputs
    indices_ptr,     # *int32, token_indices
    N,               # int32, number of selected tokens
    H,               # int32, hidden size
    BLOCK: tl.constexpr,
):
    # One program per selected token row
    pid = tl.program_id(axis=0)
    if pid >= N:
        return

    # Load destination row index for this selected token
    idx = tl.load(indices_ptr + pid)

    # Iterate over hidden dimension in chunks of BLOCK
    r = 0
    while r < H:
        cols = r + tl.arange(0, BLOCK)
        mask = cols < H

        # Compute linear offsets
        out_offsets = idx * H + cols
        exp_offsets = pid * H + cols

        # Load chunk from expert_outputs
        vals = tl.load(expert_ptr + exp_offsets, mask=mask, other=0.0)

        # Atomically add into the output row
        tl.atomic_add(out_ptr + out_offsets, vals, mask=mask)

        r += BLOCK


def _next_power_of_two(n: int) -> int:
    # Return the next power-of-two >= n, minimum 64, maximum 256
    if n <= 64:
        return 64
    elif n <= 128:
        return 128
    else:
        return 256


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Ensure tensors are on CUDA and contiguous
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "All tensors must be on CUDA."
        # Clone to preserve original
        out = final_hidden_states.contiguous().clone()
        expert = expert_outputs.contiguous()
        indices = token_indices.contiguous().to(torch.int32)

        # Dimensions
        N = expert.shape[0]
        H = expert.shape[1]

        # Choose BLOCK and num_warps based on H
        BLOCK = _next_power_of_two(H)
        if BLOCK <= 64:
            num_warps = 2
        elif BLOCK <= 128:
            num_warps = 4
        else:
            num_warps = 8

        # Launch one program per selected token
        grid = (N,)
        _index_add_rows_kernel[grid](out, expert, indices, N, H, BLOCK=BLOCK, num_warps=num_warps, num_stages=2)
        return out
```

Notes
- This kernel uses a simple, correct masked loop over the hidden dimension, performing atomic_add into the destination row. It avoids per-element atomics and cross-row hazards.
- We dynamically choose BLOCK to reduce the number of loop iterations while keeping good occupancy. The previous correct submissions used similar logic, and this should recover or improve performance relative to the last ~1.64x result.
- We keep the forward method minimal: shapes/strides checks, contiguity, int32 indices, and launching the Triton kernel. No PyTorch computation is used in the host path, satisfying the requirement that Triton performs the numerics.
