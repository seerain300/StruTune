Deep analysis, root-cause investigation, and plan

- What the model computes:
  - final_hidden_states has shape (M, H), where M = batch_size * seq_len.
  - expert_outputs has shape (N, H), where N = M * num_experts_per_tok.
  - token_indices has shape (N), values in [0, M).
  - The reference implementation clones final_hidden_states and then does:
    output[token_indices[i]] += expert_outputs[i] for each i, which is exactly torch.index_add(dim=0, index=token_indices, source=expert_outputs). Duplicates in token_indices are correctly handled by atomic adds.

- Why the last submissions failed:
  - The evaluation environment reported “INCORRECT_NUMERICAL” for several workloads. This typically indicates subtle issues such as:
    - Using wrong pointer/stride assumptions (e.g., treating row-major memory as strided incorrectly).
    - Incorrect masking or out-of-bounds writes.
    - Incorrect grid/tiling for the first dimension (M) or hidden dimension (H).
    - Mismatched dtypes or pointer types (e.g., using int64 indices with Triton expecting int32).
  - While the kernel logic (vectorize over H, masked atomic_add) seemed sound, the numerical mismatch suggests the kernel wasn’t correctly indexing the output rows (M) or the hidden dimension (H) in all cases, or the grid did not match the intended semantics. The “INCORRECT_NUMERICAL” also implies the output vector wasn’t the (M, H) vector we expect, but rather something like (N, H) (i.e., appending or misplacing the scatter contributions), which would happen if the kernel launched against the wrong output tensor or misinterpreted program_id(0).

- Strategy to fix correctness robustly:
  - Map one Triton program to one source row i (grid = N). That program:
    - Loads the token index idx = token_indices[i] (int32).
    - Iterates over the hidden dimension H in tiles of BLOCK_H = 256 (single pass for typical H ≤ 1024).
    - Loads the corresponding expert_outputs[i, offs] vector and atomically adds to out[idx, offs].
  - Ensure:
    - final_hidden_states is cloned and used as the output tensor, shape (M, H), contiguous.
    - expert_outputs and out are bfloat16 (torch.randn(...) is bfloat16 in the provided get_inputs).
    - token_indices are int32.
    - Masking for offs < H is correct.
    - Use tl.atomic_add to handle duplicates.
    - Keep tensors contiguous; avoid any ambiguous stride assumptions.

- Performance considerations:
  - The previously working version with BLOCK_H=256, num_warps=4, num_stages=2 showed ~2.0x speedup and correctness. We’ll revert to that configuration. Dynamically changing BLOCK_H and warps introduced instability and caused the recent failures. We’ll keep it fixed for robustness and predictable performance.

- Preventing recurrence:
  - Keep the kernel simple: one row per program, vectorize across H only. No 2D tiling across M. Ensure types are correct and masking is tight. Avoid heuristic changes that could break correctness in edge cases.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_rows_kernel(
    out_ptr,          # *const bfloat16, shape [M, H], used as output
    src_ptr,          # *const bfloat16, shape [N, H]
    indices_ptr,      # *const int32,    shape [N]
    M: tl.constexpr,  # total rows in out_ptr/src_ptr (M = batch_size * seq_len)
    H: tl.constexpr,  # hidden size
    N: tl.constexpr,  # number of source rows to scatter (N = M * num_experts_per_tok)
    BLOCK_H: tl.constexpr,  # tile size for H (e.g., 256)
):
    # One program per source row
    row = tl.program_id(0)  # row in [0, N)
    if row >= N:
        return

    # Load the destination row index for this source row
    idx = tl.load(indices_ptr + row)
    if idx < 0 or idx >= M:
        # Defensive check; mask will prevent OOB stores if we rely on grid=N and valid indices.
        return

    # Iterate over the hidden dimension in tiles of BLOCK_H
    # For typical H <= 1024, this is a single iteration with BLOCK_H=256.
    for start in range(0, H, BLOCK_H):
        offs = start + tl.arange(0, BLOCK_H)
        mask = offs < H

        # Compute base offsets for out and src rows
        out_base = idx * H + offs
        src_base = row * H + offs

        # Load the source vector (masked for tail)
        src_vals = tl.load(src_ptr + src_base, mask=mask, other=0.0)

        # Atomically add into the output row vector
        tl.atomic_add(out_ptr + out_base, src_vals, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor) -> torch.Tensor:
        # Ensure devices and dtypes
        assert final_hidden_states.is_cuda, "final_hidden_states must be on CUDA"
        assert expert_outputs.is_cuda, "expert_outputs must be on CUDA"
        assert token_indices.is_cuda, "token_indices must be on CUDA"

        # Clone to create the output buffer
        output = final_hidden_states.clone()

        # Shapes
        M = final_hidden_states.shape[0]
        H = final_hidden_states.shape[1]
        N = expert_outputs.shape[0]
        assert expert_outputs.shape[1] == H, "expert_outputs second dimension must match hidden size"
        assert token_indices.shape[0] == N, "token_indices length must equal N"

        # Ensure contiguous tensors
        output = output.contiguous()
        expert_outputs = expert_outputs.contiguous()
        token_indices = token_indices.to(torch.int32).contiguous()

        # Grid: one program per source row
        grid = (N,)

        # Launch kernel with a proven configuration
        scatter_add_rows_kernel[grid](
            output, expert_outputs, token_indices,
            M=M, H=H, N=N,
            BLOCK_H=256,
            num_warps=4,
            num_stages=2,
        )

        return output
```

Notes:
- The kernel maps one Triton program to each source row and vectorizes across H in tiles of size 256, using masked tl.atomic_add to handle duplicates safely. This matches the semantics of torch.index_add(dim=0, ...).
- We explicitly clone final_hidden_states and use that as output. The grid is (N,), which is the number of source rows. This avoids any ambiguity about which tensor is being modified.
- We enforce token_indices dtype to int32 for Triton and ensure all tensors are contiguous.
- This configuration previously delivered correct results and strong speedups; reverting to it removes the dynamic heuristics that led to the recent numerical mismatches.
