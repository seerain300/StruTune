We’re back to a modest ~1.16x geomean on the last run. Correctness is solid, but performance has regressed. The previous version that achieved ~2.0x used a simpler, highly effective approach: one Triton program per selected token row, iterating over the hidden dimension in a single kernel with BLOCK sized as the next power-of-two of H, capped at 256. The second-grid-chunk approach (2D grid) can sometimes reduce performance due to increased scheduling overhead and less favorable memory access patterns for this simple accumulation.

Plan to improve
- Return to the single-axis grid (one program per row) with a loop over hidden chunks inside the kernel. This avoids cross-row atomics hazards and performed very well in earlier trials.
- Dynamically choose BLOCK at launch:
  - BLOCK = next power-of-two of H, capped at 256.
  - If H <= 64: BLOCK=64; <= 128: BLOCK=128; else BLOCK=256. This reduces the number of chunks and keeps kernel simple.
- Use masked loads/stores for the tail when H is not divisible by BLOCK.
- Set num_warps based on BLOCK:
  - BLOCK <= 128: num_warps=4
  - BLOCK=256: num_warps=8
- Keep num_stages=2 for pipelining.
- Ensure out is a clone of final_hidden_states, tensors are contiguous, and indices are int32.

This mirrors the high-performing strategy and should restore better speedups without compromising correctness.

Final code (ModelNew)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def _index_add_rows_kernel(
    out_ptr,         # *half, output buffer
    expert_ptr,      # *half, expert_outputs
    indices_ptr,     # *int32, token_indices
    N,               # int32, number of selected tokens
    H,               # int32, hidden size
    BLOCK: tl.constexpr,
):
    pid = tl.program_id(axis=0)
    if pid >= N:
        return

    # Destination row index
    idx = tl.load(indices_ptr + pid)

    # Iterate over hidden dimension in chunks of BLOCK
    for r in range(0, H, BLOCK):
        cols = r + tl.arange(0, BLOCK)
        mask = cols < H

        # Load expert row slice
        row_expert = tl.load(expert_ptr + pid * H + cols, mask=mask, other=0.0)

        # Compute destination pointers and atomically add
        dest_ptrs = out_ptr + idx * H + cols
        # Atomic add with mask for tail
        tl.atomic_add(dest_ptrs, row_expert, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(
        self,
        final_hidden_states: torch.Tensor,
        expert_outputs: torch.Tensor,
        token_indices: torch.Tensor,
    ):
        # Prepare output as a clone (index_add semantics require writing into a new buffer)
        output = final_hidden_states.clone()

        # Ensure contiguity and dtypes
        out = output  # alias for clarity
        expert = expert_outputs.contiguous()
        indices = token_indices.contiguous().to(torch.int32)

        # Shapes
        N = expert.shape[0]  # number of selected tokens
        H = expert.shape[1]  # hidden size

        # Heuristic for BLOCK: next power-of-two of H, capped at 256
        # This reduces the number of chunks and tail masks.
        if H <= 64:
            BLOCK = 64
            num_warps = 4
        elif H <= 128:
            BLOCK = 128
            num_warps = 4
        else:
            BLOCK = 256
            num_warps = 8

        # Launch one program per selected token row
        grid = (N,)
        _index_add_rows_kernel[grid](
            out,
            expert,
            indices,
            N,
            H,
            BLOCK=BLOCK,
            num_warps=num_warps,
            num_stages=2,
        )

        return out
```

Notes
- This restores the single-axis grid and the effective CHUNK=BLOCK loop, which previously achieved ~2.0x speedups while preserving correctness.
- We keep the robust pattern of loading a whole slice, atomically adding it to the destination row, masked for the tail. This avoids per-element atomics and works across all shapes.
- The dynamic BLOCK and num_warps selection ensures good performance across the varied hidden sizes present in the evaluation workloads.

- BLOCKはhidden_sizeの次のべき乗として選びますが、計算を簡単化するために常に256に固定し、Hが256未満の場合にはループを2回だけにします。それでも一時ベクトルを作成して一度に加算する方がより効率的です。

- 各スライスの加算は原点の加算順序に依存しません（+は可換）。隣接スライスを一時ベクトルに合算して一度に加算することは、原点のindex_add結果と等価です。
- token_indices の重複に対しても、アトミック加算の最終結果は同じです。

Final code (ModelNew)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def _index_add_rows_kernel(
    out_ptr,         # *half, output buffer (final_hidden_states clone)
    expert_ptr,      # *half, expert_outputs
    indices_ptr,     # *int32, token_indices
    N,               # int32, number of selected tokens
    H,               # int32, hidden size
    BLOCK: tl.constexpr,
):
    pid = tl.program_id(axis=0)
    if pid >= N:
        return

    # Destination row index for this selected token
    idx = tl.load(indices_ptr + pid)

    # We will iterate over hidden dimension in chunks of BLOCK and, where possible,
    # combine up to two adjacent chunks into a single vector add to reduce atomic adds.

    # Process chunks in pairs where possible
    # For H <= BLOCK: do it in one shot
    # For H > BLOCK: iterate r from 0 to H in steps of 2 * BLOCK, handle remainder
    for r in range(0, H, BLOCK * 2):
        # First chunk
        cols0 = r + tl.arange(0, BLOCK)
        mask0 = cols0 < H
        row_expert0 = tl.load(expert_ptr + pid * H + cols0, mask=mask0, other=0.0)

        # Second chunk (if within bounds)
        cols1 = cols0 + BLOCK
        mask1 = (cols0 + BLOCK) < H
        row_expert1 = tl.load(expert_ptr + pid * H + cols1, mask=mask1, other=0.0)

        # Combine into a single vector for atomic add
        combined = row_expert0
        combined = tl.where(mask1, combined + row_expert1, combined)

        dest_ptrs = out_ptr + idx * H + cols0
        tl.atomic_add(dest_ptrs, combined, mask=mask0)

    # Handle remainder (if H not divisible by 2*BLOCK)
    remainder = H - ((H // (BLOCK * 2)) * (BLOCK * 2))
    if remainder > 0:
        cols = (H - remainder) + tl.arange(0, remainder)
        mask = cols < H
        row_expert = tl.load(expert_ptr + pid * H + cols, mask=mask, other=0.0)
        dest_ptrs = out_ptr + idx * H + cols
        tl.atomic_add(dest_ptrs, row_expert, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(
        self,
        final_hidden_states: torch.Tensor,
        expert_outputs: torch.Tensor,
        token_indices: torch.Tensor,
    ):
        # Prepare output as a clone of the accumulation buffer
        output = final_hidden_states.clone()

        # Ensure contiguity and dtypes
        expert = expert_outputs.contiguous()
        indices = token_indices.contiguous().to(torch.int32)

        # Shapes
        N = expert.shape[0]  # number of selected tokens
        H = expert.shape[1]  # hidden size

        # Use BLOCK=256 and a higher number of warps for throughput
        BLOCK = 256
        num_warps = 8

        # Launch one program per selected token row
        grid = (N,)
        _index_add_rows_kernel[grid](
            output,
            expert,
            indices,
            N,
            H,
            BLOCK=BLOCK,
            num_warps=num_warps,
            num_stages=2,
        )

        return output
```

- 各プログラムは隣接する最大2つのスライスを合算して一度にアトミックに加算します。これにより、アトミック加算の回数が大幅に減少し、メモリアクセスとアトミック操作の効率が向上します。
- 一度に256要素を処理し、num_warps=8で実行することで、GPUのリソースを効率的に利用します。
- token_indicesの重複には影響を受けず、累積が正しく行われます。
