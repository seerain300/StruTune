Thanks for the detailed feedback. We’re consistently correct and achieving ~1.16–1.22x speedup. The operation is a row-wise scatter-add: for each i, output[token_indices[i]] += expert_outputs[i, :]. The dominant cost is atomic accumulation. Our prior kernels reduced atomics by vectorizing across the hidden dimension and, in one variant, by processing multiple updates per program. Let’s push further with a design that:

- Minimizes atomics per update by writing full rows when hidden_size fits into a single vector.
- Amortizes kernel overhead by processing multiple updates per Triton program.
- Chooses vector width (BLOCK_H) and warps based on hidden_size to balance occupancy and register pressure.

Diagnosis
- Baseline approach (one program per update, scalar loop over H): ~H atomics per update. Very slow.
- Vectorized per-update (one program per update, chunking H): ~H / BLOCK_H atomics per update. Much faster.
- Multi-update per program (each program handles T updates and loops over H in chunks): reduces number of programs but still does many atomic adds per update lane; performance okay but not consistently best.

Bottleneck
- Atomic operations are the bottleneck. We should reduce the number of atomics and ensure coalesced accesses. A full-row vectorized atomic_add when H <= BLOCK_H (e.g., 1024) reduces per-update atomics to 1. When H > BLOCK_H, we need chunked loops.

Optimization plan
1) Full-row kernel (for H <= BLOCK_H):
   - One Triton program processes up to T updates. For each update lane k:
     - idx = token_indices[pos + k], with masks for tail.
     - Load v = expert_outputs[pos + k, :] (float32), shape (BLOCK_H).
     - Perform a single tl.atomic_add of v into out_fp32[idx, :].
   - This does exactly one atomic add per update, minimizing contention.

2) Chunked kernel (for H > BLOCK_H):
   - One Triton program processes up to T updates.
   - For each update lane k:
     - idx = token_indices[pos + k], with masks for tail.
     - Iterate over hidden dimension in blocks of BLOCK_H:
       - h = base + arange(BLOCK_H)
       - v_chunk = expert_outputs[pos + k, h]
       - tl.atomic_add(out_fp32[idx, h], v_chunk)
     - This keeps atomics to H / BLOCK_H per update.

3) Host-side:
   - Ensure all tensors are on the same CUDA device, contiguous, and dtype float32 for accumulation.
   - Allocate output_fp32 = final_hidden_states.clone().to(torch.float32).
   - After kernel, cast to bfloat16 to match original API.

4) Heuristics:
   - Choose BLOCK_H = 1024 if H <= 1024; else 512 if H <= 2048; else 256.
   - Choose T = 4 (process 4 updates per program) to reduce grid size while keeping register usage reasonable.
   - num_warps = 8 for 1024, 4 for 512, 2 for 256.

Why this should help
- For the common hidden_size (1024 in many models), the full-row kernel uses one atomic add per update and one program per group of T updates. This reduces atomic contention and kernel scheduling overhead versus per-update programs. Combined with coalesced row loads, it should improve throughput.
- For larger hidden sizes, chunked kernel keeps atomics low (e.g., 8 atomics at BLOCK_H=1024, 16 at 512, etc.) while preserving parallelism.

Final code (ModelNew.forward with Triton kernels)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_full_row_kernel(
    out_ptr,                # *fp32, shape [B, H]
    token_indices_ptr,      # *i32, shape [N]
    expert_outputs_ptr,     # *fp32, shape [N, H]
    N,                      # int
    H,                      # int
    BLOCK_H: tl.constexpr,  # int (e.g., 1024)
    T: tl.constexpr,        # number of updates per program
):
    pid = tl.program_id(0)  # one program handles up to T updates
    base = pid * T
    # vector of update offsets [0, 1, 2, ..., T-1]
    offs = tl.arange(0, T)  # shape (T,)
    pos = base + offs        # positions in [0, N)
    # mask: only consider valid positions (pos < N)
    mask_pos = pos < N

    # Load indices for each update lane
    idx = tl.load(token_indices_ptr + pos, mask=mask_pos, other=0)  # int32
    idx = idx.to(tl.int32)

    # Base pointers for each update lane
    # out_ptr is [B, H], row-major
    # expert_outputs_ptr is [N, H], row-major
    # We'll compute pointers as out_ptr + idx * H + h and expert_outputs_ptr + pos * H + h
    h = tl.arange(0, BLOCK_H)  # full row vector
    mask_h = h < H  # since BLOCK_H >= H, mask_h is all True, but keep for safety

    # For each valid lane, do a full-row atomic add
    # Note: We can't vectorize across lanes easily in Triton, so we do per-lane loop.
    # Triton supports python 'for' with scalar conditions; we loop over offs and handle masking.
    for k in range(T):
        p = pos[k]
        m_k = mask_pos[k]
        # If this lane is invalid, skip
        if m_k:
            v = tl.load(expert_outputs_ptr + p * H + h, mask=mask_h, other=0.0).to(tl.float32)
            out_row_ptr = out_ptr + idx[k] * H + h
            tl.atomic_add(out_row_ptr, v, mask=mask_h)


@triton.jit
def scatter_add_chunked_kernel(
    out_ptr,                # *fp32, shape [B, H]
    token_indices_ptr,      # *i32, shape [N]
    expert_outputs_ptr,     # *fp32, shape [N, H]
    N,                      # int
    H,                      # int
    BLOCK_H: tl.constexpr,  # int (e.g., 512 or 256)
    T: tl.constexpr,        # number of updates per program
):
    pid = tl.program_id(0)  # one program handles up to T updates
    base = pid * T
    offs = tl.arange(0, T)  # vector of T lanes
    pos = base + offs
    mask_pos = pos < N

    # Load indices for each update lane
    idx = tl.load(token_indices_ptr + pos, mask=mask_pos, other=0).to(tl.int32)

    # Iterate over hidden dimension in chunks
    num_chunks = (H + BLOCK_H - 1) // BLOCK_H
    for c in range(0, num_chunks):
        h = c * BLOCK_H + tl.arange(0, BLOCK_H)
        mask_h = h < H
        for k in range(T):
            p = pos[k]
            m_k = mask_pos[k]
            if m_k:
                v = tl.load(expert_outputs_ptr + p * H + h, mask=mask_h, other=0.0).to(tl.float32)
                out_row_ptr = out_ptr + idx[k] * H + h
                tl.atomic_add(out_row_ptr, v, mask=mask_h)


class ModelNew(torch.nn.Module):
    def __init__(self):
        super().__init__()

    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Ensure tensors are on same device and contiguous
        assert final_hidden_states.device.type == "cuda" and expert_outputs.device.type == "cuda" and token_indices.device.type == "cuda", "All inputs must be on CUDA"
        B = final_hidden_states.shape[0]
        H = final_hidden_states.shape[1]
        N = expert_outputs.shape[0]
        # Accumulate in float32 for atomic_add support
        out_fp32 = final_hidden_states.clone().to(torch.float32)
        token_indices_i32 = token_indices.to(torch.int32).contiguous()
        expert_outputs_fp32 = expert_outputs.contiguous().to(torch.float32)

        # Heuristics for BLOCK_H and num_warps
        if H <= 1024:
            BLOCK_H = 1024
            num_warps = 8
            use_full_row = True
        elif H <= 2048:
            BLOCK_H = 512
            num_warps = 4
            use_full_row = False
        else:
            BLOCK_H = 256
            num_warps = 2
            use_full_row = False

        # Process multiple updates per program to reduce grid size
        T = 4

        if use_full_row:
            grid = (triton.cdiv(N, T),)
            scatter_add_full_row_kernel[grid](
                out_fp32,
                token_indices_i32,
                expert_outputs_fp32,
                N,
                H,
                BLOCK_H=BLOCK_H,
                T=T,
                num_warps=num_warps,
                num_stages=2,
            )
        else:
            grid = (triton.cdiv(N, T),)
            scatter_add_chunked_kernel[grid](
                out_fp32,
                token_indices_i32,
                expert_outputs_fp32,
                N,
                H,
                BLOCK_H=BLOCK_H,
                T=T,
                num_warps=num_warps,
                num_stages=2,
            )

        # Cast back to bfloat16 to match original API
        return out_fp32.to(torch.bfloat16)
```

Notes
- Correctness: Atomic adds in float32 handle duplicates properly. We clone and cast the final buffer, then return bfloat16. Shapes and strides are standard row-major: pointer + idx * H + h.
- Performance: The full-row kernel cuts atomics per update to 1 for H <= 1024 and reduces program count by factor T. The chunked kernel maintains low atomics for larger H. Heuristics for BLOCK_H and num_warps aim to balance occupancy and register pressure.
- This preserves Triton-only computation: all heavy work is in Triton kernels; no torch ops are used for the core scatter-add.

import triton
import triton.language as tl

def scatter_add_chunked_kernel(

- Correctitud: Atomic adds en float32 suman correctamente y respetan duplicados en token_indices. El resultado se convierte a bfloat16 al final, como en el modelo original.
- Performance: El kernel vectoriza a lo largo de H en bloques, minimizando atomics a H/BLOCK_H per update. Un programa por update evita complejidad en per-lane control flow y mantuvo el geomean ~1.22x. Aumentar num_stages a 4 puede ayudar ligeramente en kernels más costosos; no empeora en configuraciones más pequeñas. No hardcodeamos tamaños, y el kernel funciona con cualquier H,N,B.
- Simplicidad: Host solo asegura device, contiguity, dtype, y lanza el kernel. No usamos PyTorch ops en el núcleo, cumpliendo con el requisito Triton-único.
