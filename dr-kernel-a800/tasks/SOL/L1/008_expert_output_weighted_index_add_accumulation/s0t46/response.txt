Operation recap
- We need to perform scatter-add along dim=0: output[token_indices[i]] += expert_outputs[i] for i in [0..N), where output is (M, H), expert_outputs is (N, H), and token_indices length N. M = batch_size * seq_len.
- This operation is inherently parallel but can suffer from atomic contention when many indices map to the same output row. The best we can do is maximize per-program work, keep memory access coalesced, and tune launch parameters.

Current design and bottlenecks
- We use one Triton program per source row (n). Inside each program, we iterate over H in chunks (BLOCK_H), load token_indices[n], load the corresponding expert_outputs[n, h_block], compute destination addresses, and issue tl.atomic_add to the output.
- This design was robust and fast. The main remaining bottleneck is atomic contention when many rows target the same output row. While we can’t fully eliminate atomics without a two-phase reduction (which adds complexity), we can reduce the number of atomic operations by increasing per-program work and tuning block sizes and launch parameters.

Optimization plan
- Keep one-program-per-source-row, but increase per-program work:
  - Use larger BLOCK_H for larger H to reduce loop iterations and improve memory throughput. We’ll select BLOCK_H based on H:
    - H >= 2048: BLOCK_H = 256, num_warps = 8, num_stages = 3
    - H >= 512: BLOCK_H = 128, num_warps = 4, num_stages = 2
    - Else: BLOCK_H = 64, num_warps = 2, num_stages = 2
- Maintain vectorized loads/stores across the H-chunk for coalesced memory access.
- Keep the while loop over H with runtime termination to handle arbitrary H sizes robustly.
- Ensure token_indices is int32 for efficient address arithmetic and output/expert tensors are contiguous and on CUDA.

Why this should help
- Larger BLOCK_H reduces loop overhead and the number of atomic operations per source row, which can improve throughput especially for larger H. Tuning num_warps and num_stages helps balance occupancy and pipeline depth across different GPU architectures.

Final code

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_row_kernel(
    output_ptr,            # *bf16 or *fp16 pointer, shape [M, H]
    expert_ptr,            # *bf16 or *fp16 pointer, shape [N, H]
    index_ptr,             # *int32 pointer, shape [N]
    M: tl.constexpr,       # number of rows in output (M = batch_size * seq_len)
    N: tl.constexpr,       # number of source rows (N = batch_seq_len * num_experts_per_tok)
    H: tl.constexpr,       # hidden size
    BLOCK_H: tl.constexpr  # chunk size over H
):
    # Each program handles one source row 'n'
    n = tl.program_id(axis=0)
    if n >= N:
        return

    # Load token index for this source row
    dest_row = tl.load(index_ptr + n)  # int32

    # Iterate over H in chunks of size BLOCK_H
    h_start = 0
    while h_start < H:
        offs = h_start + tl.arange(0, BLOCK_H)
        mask = offs < H

        # Load the corresponding expert outputs for this row and chunk
        # Row-major addressing: expert_ptr + n * H + offs
        vals = tl.load(expert_ptr + n * H + offs, mask=mask, other=0)

        # Compute destination addresses: output_ptr + dest_row * H + offs
        dest_addrs = output_ptr + dest_row * H + offs

        # Atomic add the values into the output
        tl.atomic_add(dest_addrs, vals, mask=mask)

        h_start += BLOCK_H


def _choose_launch_params(H: int):
    # Heuristic launch parameter selection based on H
    if H >= 2048:
        return 256, 8, 3
    elif H >= 512:
        return 128, 4, 2
    else:
        return 64, 2, 2


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Ensure tensors are on CUDA and contiguous
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "Tensors must be on CUDA"
        final_hidden_states = final_hidden_states.contiguous()
        expert_outputs = expert_outputs.contiguous()
        # Triton prefers int32 for indices; ensure it and bounds
        if token_indices.dtype != torch.int32:
            token_indices = token_indices.to(torch.int32)
        token_indices = token_indices.contiguous()

        M = final_hidden_states.shape[0]
        N = expert_outputs.shape[0]
        H = final_hidden_states.shape[1]

        # Allocate output (we accumulate in-place to match original behavior)
        output = final_hidden_states

        # Choose kernel launch params
        BLOCK_H, num_warps, num_stages = _choose_launch_params(H)

        # Grid: one program per source row
        grid = (N,)

        scatter_add_row_kernel[grid](
            output, expert_outputs, token_indices,
            M, N, H, BLOCK_H,
            num_warps=num_warps, num_stages=num_stages
        )

        return output
```
