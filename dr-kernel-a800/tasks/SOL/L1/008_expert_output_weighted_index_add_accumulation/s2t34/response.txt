We’re at 16/16 correctness with a solid speedup. To push performance further while keeping correctness rock-solid, we should maintain the previously validated approach and choose deterministic, shape-aware kernel parameters. The earlier 1.7–2.0x speedups came from:
- One Triton program per selected token row (N programs). This avoids cross-row atomics hazards and keeps the kernel simple and deterministic.
- Vectorized chunked atomic_add across hidden dimension H in chunks of BLOCK with tight masks.

We’ll keep this structure and refine launch-time configuration:
- Choose BLOCK deterministically based on H to minimize the number of atomic_add chunks:
  - BLOCK = next power-of-two of H, capped at 256. This keeps the number of chunks small for H up to 1024 (often 1 or 2 chunks).
- Set num_warps based on BLOCK to balance occupancy and throughput:
  - num_warps=4 for BLOCK <= 128.
  - num_warps=8 for BLOCK=256.
- Use num_stages=2 to enable pipelining of loads/stores.

This avoids autotune risk and keeps the code path simple, masking the tail properly. It previously produced strong speedups and should restore or slightly improve performance compared to the last submission.

Final code (ModelNew)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def _index_add_rows_kernel(
    out_ptr,         # *half (final_hidden_states clone, we write into it)
    expert_ptr,      # *half (expert_outputs)
    indices_ptr,     # *int32 (token_indices)
    N,               # int32: number of selected tokens
    H,               # int32: hidden size
    BLOCK: tl.constexpr,
):
    # One program per selected token row
    pid = tl.program_id(axis=0)
    if pid >= N:
        return

    # Load destination row index for this selected token
    idx = tl.load(indices_ptr + pid)
    # idx is expected to be in [0, N); we assume token_indices are valid

    # Process the hidden vector in chunks of BLOCK, with a mask for the tail
    # For r in [0, ceil(H / BLOCK)):
    #   cols = r*BLOCK + [0..BLOCK-1], mask = cols < H
    #   out[idx, cols] += expert[pid, cols]
    # We implement this via pointer arithmetic and tl.atomic_add
    # Note: We don't have a direct per-row pointer in Triton; we compute addresses with base + offsets.

    # Create a vector of column offsets for this chunk
    # Triton requires compile-time constants for arange, so we loop r explicitly
    # We'll iterate in Python-like fashion using while loop pattern:
    r = 0
    cols = tl.arange(0, BLOCK)
    while r * BLOCK < H:
        offs = r * BLOCK + cols
        mask = offs < H

        # Load current values from out at destination row 'idx' for offs
        # Pointer offset for out row idx is idx * H + offs
        out_base = idx * H + offs
        out_vals = tl.load(out_ptr + out_base, mask=mask, other=0.0)

        # Load expert row slice
        expert_base = pid * H + offs
        expert_vals = tl.load(expert_ptr + expert_base, mask=mask, other=0.0)

        # Atomic add into output
        tl.atomic_add(out_ptr + out_base, expert_vals, mask=mask)

        r += 1
```

Usage in ModelNew.forward
```python
class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor,
                expert_outputs: torch.Tensor,
                token_indices: torch.Tensor):
        """
        Triton-optimized index_add along dim=0:
          output = final_hidden_states.clone()
          output.index_add_(dim=0, index=token_indices, source=expert_outputs)
        """
        # Ensure tensors are contiguous and dtypes are as expected
        out = final_hidden_states.clone().contiguous()
        expert = expert_outputs.contiguous()
        indices = token_indices.to(torch.int32).contiguous()

        N = expert.shape[0]
        H = expert.shape[1]

        # Choose BLOCK deterministically based on H to minimize chunks
        if H <= 64:
            BLOCK = 64
            num_warps = 4
        elif H <= 128:
            BLOCK = 128
            num_warps = 4
        else:
            BLOCK = 256
            num_warps = 8

        # Launch one program per selected token row
        grid = (N,)
        _index_add_rows_kernel[grid](out, expert, indices, N, H, BLOCK=BLOCK, num_warps=num_warps, num_stages=2)
        return out
```

Notes
- This kernel preserves PyTorch’s index_add semantics with accumulation exactly: for each selected token row i, it adds the corresponding expert_outputs[i, :] into output[token_indices[i], :], handling duplicates correctly.
- We use masked loads/stores and masked atomic_add to handle the tail when H is not a multiple of BLOCK.
- We avoid Triton autotune to prevent any configuration-induced failures, and instead select BLOCK and num_warps deterministically based on H.
- The approach has already been validated for 16 workloads and delivered >1.7x speedups. The refined launch-time configuration should restore or slightly improve performance while keeping correctness
