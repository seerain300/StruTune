import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_dim0_kernel(
    output_ptr,         # *bf16, shape [M, H]
    indices_ptr,        # *int32, shape [N]
    inputs_ptr,         # *bf16, shape [N, H]
    N,                  # int32, number of expert outputs rows
    stride_out_row,     # int64, elements between rows of output
    stride_out_col,     # int64, elements between cols of output (typically 1)
    stride_in_row,      # int64, elements between rows of inputs (typically H)
    stride_in_col,      # int64, elements between cols of inputs (typically 1)
    H: tl.constexpr,    # hidden_size, compile-time for vectorization
    BLOCK: tl.constexpr # number of columns processed per program, should be >= H
):
    # Each program handles one row i
    i = tl.program_id(axis=0)
    if i >= N:
        return

    # Load target row index (int32)
    idx = tl.load(indices_ptr + i)  # scalar int32

    # Prepare column offsets
    cols = tl.arange(0, H)
    mask = cols < H  # always true since H is constexpr and we use BLOCK >= H, but keep mask for safety

    # Load expert vector for row i across H columns
    in_ptrs = inputs_ptr + i * stride_in_row + cols * stride_in_col
    vals = tl.load(in_ptrs, mask=mask, other=0.0)  # shape (H,) bf16

    # Compute output pointers for row idx and atomic add vals across columns
    out_ptrs = output_ptr + idx * stride_out_row + cols * stride_out_col
    tl.atomic_add(out_ptrs, vals, mask=mask)

  - output = final_hidden_states.clone()
  - output.index_add_(dim=0, index=token_indices, source=expert_outputs)
  - This means: for each i in [0, N), output[token_indices[i]] += expert_outputs[i, :] across all hidden dimensions. Duplicates in token_indices are accumulated.
- Triton approach:
  - Launch one Triton program per row i (i.e., per expert output). Grid = (N,).
  - Each program:
    - Loads idx = token_indices[i] (int32).
    - Loads the expert vector vals = expert_outputs[i, :] as a vector across H columns.
    - Computes output pointers for row idx and performs tl.atomic_add to add vals into that row.
  - This directly mirrors index_add along dim=0 and handles duplicates via atomics.
- Robustness:
  - We ensure all tensors are contiguous, cast token_indices to int32, and use strides (in elements) for pointer arithmetic.
  - No CPU fallback on GPU; Triton kernel is always invoked when tensors are on CUDA.
- Performance:
  - O(N*H) atomic adds. While not the fastest possible, it is a simple and correct approach for this pattern, and the evaluation prioritizes correctness. We set BLOCK to cover H and use a modest num_warps.

Final code

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_dim0_row_kernel(
    output_ptr,       # *bf16, shape [M, H]
    indices_ptr,      # *int32, shape [N]
    inputs_ptr,       # *bf16, shape [N, H]
    N,                # int32
    stride_out_row,   # int64 (elements between rows of output)
    stride_out_col,   # int64 (elements between cols of output, typically 1)
    stride_in_row,    # int64 (elements between rows of inputs, typically H)
    stride_in_col,    # int64 (elements between cols of inputs, typically 1)
    H: tl.constexpr,  # hidden_size (compile-time for vectorization)
    BLOCK: tl.constexpr,  # number of columns processed per program (>= H)
):
    # One program per row i
    i = tl.program_id(axis=0)
    if i >= N:
        return

    # Load target row index (int32)
    idx = tl.load(indices_ptr + i)  # scalar int32

    # Column offsets and mask
    cols = tl.arange(0, BLOCK)
    mask = cols < H  # ensure we only process valid hidden dims

    # Load expert vector for row i across H columns
    in_ptrs = inputs_ptr + i * stride_in_row + cols * stride_in_col
    vals = tl.load(in_ptrs, mask=mask, other=0.0)  # shape (BLOCK,), bf16

    # Compute output pointers for row idx and atomic add vals across columns
    out_ptrs = output_ptr + idx * stride_out_row + cols * stride_out_col
    tl.atomic_add(out_ptrs, vals, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Ensure we run the Triton kernel on GPU. No CPU fallback on CUDA tensors.
        # If tensors are not on CUDA, raise to avoid silent incorrectness.
        if (not final_hidden_states.is_cuda) or (not expert_outputs.is_cuda) or (not token_indices.is_cuda):
            raise RuntimeError("ModelNew.forward requires CUDA tensors for Triton execution.")

        # Clone the accumulator to preserve original random initialization
        output = final_hidden_states.clone().contiguous()

        # Shapes and assertions
        M, H = output.shape
        N = expert_outputs.shape[0]
        assert expert_outputs.shape == (N, H), "expert_outputs must have shape (num_selected_tokens, hidden_size)"
        assert token_indices.shape[0] == N, "token_indices length must match expert_outputs rows"

        # Ensure inputs are contiguous
        expert_outputs = expert_outputs.contiguous()
        # Cast indices to int32 for pointer arithmetic
        token_indices = token_indices.to(torch.int32).contiguous()

        # Strides in elements
        stride_out_row = output.stride(0)
        stride_out_col = output.stride(1)
        stride_in_row = expert_outputs.stride(0)  # typically H
        stride_in_col = expert_outputs.stride(1)  # typically 1

        # Launch Triton kernel: one program per row i
        grid = (N,)

        # Choose BLOCK as the next power of two >= H, capped to 1024 for safety.
        # Since H is usually 128 or 256 in the provided configs, BLOCK=256 is sufficient.
        BLOCK = 256 if H <= 256 else 1024

        scatter_add_dim0_row_kernel[grid](
            output, token_indices, expert_outputs,
            N,
            stride_out_row, stride_out_col,
            stride_in_row, stride_in_col,
            H=H, BLOCK=BLOCK,
            num_warps=4,   # tuneable: 4 or 8 are typical
            num_stages=2   # tuneable
        )

        return output
```

Why this should fix correctness and runtime issues
- The Triton kernel is simple and avoids complex 2D grids or dynamic loops that previously caused runtime errors. It assigns one program per row i, loads the expert vector for that row, and atomically adds it into the correct output row. This exactly matches the original index_add along dim=0, including handling duplicates.
- We preserve the original random initialization by cloning final_hidden_states before accumulation.
- We ensure contiguous tensors and correct stride usage for pointer arithmetic, minimizing the risk of illegal memory access.
- The kernel is always invoked when tensors are on CUDA, satisfying the requirement to use Triton rather than falling back to PyTorch. If tensors are not on CUDA, we raise an error
