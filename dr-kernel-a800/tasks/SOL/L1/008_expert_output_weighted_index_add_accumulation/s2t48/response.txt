Root cause assessment
- The operation we must implement is an index_add along the batch (row) dimension:
  - output = final_hidden_states.clone()
  - output.index_add_(dim=0, index=token_indices, source=expert_outputs)
  - That is, for each selected token i: output[token_indices[i], :] += expert_outputs[i, :]. Duplicates in token_indices must accumulate, hence atomic adds are needed.
- A reliable, correct Triton strategy that previously passed 16/16:
  - One Triton program per selected token row (N programs).
  - Within each program, loop across the hidden dimension H with a chunked masked vector using tl.arange and a mask for cols < H.
  - Load the chunk from expert_outputs and perform tl.atomic_add into output[token_indices[pid], cols].
- We must ensure:
  - output is a clone (not in-place).
  - token_indices are int32.
  - tensors are contiguous.
  - no out-of-bounds accesses; masks properly handle the tail.
- The reported runtime errors likely stem from a buggy loop or improper use of dynamic ranges in Triton. To prevent recurrence, we will implement the loop using a while loop with compile-time-unrolled masking via tl.arange and tl.minimum for bounds. This is the approach that previously worked across all provided workloads.

Performance considerations
- The one-program-per-row design keeps the kernel simple and avoids cross-row atomics hazards.
- We’ll choose BLOCK based on H:
  - BLOCK=64 if H <= 64, 128 if H <= 128, else 256.
  - Use num_warps=2 for BLOCK=64, 4 for 128, 8 for 256. This provides good occupancy and throughput.
- Although this design uses per-chunk atomics, it’s robust and previously delivered ~2.0x speedups on the same harness. We’ll keep it and avoid risky 2D grid strategies that caused a performance regression earlier.

Final code (ModelNew) with a corrected, robust Triton kernel
```python
import torch
import triton
import triton.language as tl


@triton.jit
def _index_add_rows_kernel(
    out_ptr,         # *fp16 or *bf16 (final_hidden_states clone)
    expert_ptr,      # *fp16 or *bf16 (expert_outputs)
    indices_ptr,     # *int32 (token_indices)
    N,               # int32: number of selected tokens (rows in expert_outputs)
    H,               # int32: hidden size (columns)
    BLOCK: tl.constexpr,
):
    pid = tl.program_id(axis=0)
    if pid >= N:
        return

    # Destination row index for this selected token
    idx = tl.load(indices_ptr + pid)

    # Loop over hidden dimension in chunks of BLOCK
    r = 0
    while r < H:
        cols = r + tl.arange(0, BLOCK)
        # Mask for valid columns (handle tail)
        col_mask = cols < H

        # Compute linear offsets
        out_offsets = idx * H + cols
        exp_offsets = pid * H + cols

        # Masked load of expert chunk
        exp_vals = tl.load(expert_ptr + exp_offsets, mask=col_mask, other=0.0)

        # Atomically add into output row at idx
        tl.atomic_add(out_ptr + out_offsets, exp_vals, mask=col_mask)

        r += BLOCK


def _choose_block_and_warps(H: int):
    # Choose a BLOCK size as a power-of-two up to 256
    if H <= 64:
        block = 64
        warps = 2
    elif H <= 128:
        block = 128
        warps = 4
    else:
        block = 256
        warps = 8
    return block, warps


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Ensure device is CUDA for Triton; fallback not implemented in this environment
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "Tensors must be on CUDA for Triton."
        # Clone output buffer to avoid in-place modifications
        output = final_hidden_states.clone()

        # Ensure tensors are contiguous
        output = output.contiguous()
        expert_outputs = expert_outputs.contiguous()
        token_indices = token_indices.contiguous()

        # Triton expects int32 indices
        if token_indices.dtype != torch.int32:
            token_indices = token_indices.to(torch.int32)

        N = expert_outputs.shape[0]
        H = expert_outputs.shape[1]

        # Launch configuration
        BLOCK, num_warps = _choose_block_and_warps(H)
        grid = (N,)  # one program per selected token row

        # Launch kernel
        _index_add_rows_kernel[grid](
            output,
            expert_outputs,
            token_indices,
            N,
            H,
            BLOCK=BLOCK,
            num_warps=num_warps,
            num_stages=2,
        )

        return output
```

Notes
- The kernel uses a while loop over H with a vectorized chunk of size BLOCK, and a mask to handle the tail when H is not divisible by BLOCK. This pattern was previously validated and avoided out-of-bounds accesses.
- We ensure output is a clone of the input final_hidden_states, indices are int32, tensors are contiguous, and we set the grid to one program per row.
- BLOCK and num_warps are chosen deterministically based on H to balance performance and correctness.
