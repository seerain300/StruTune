The primary reason is that the previous kernel performed scalar loads/stores per column, which underutilizes memory bandwidth and adds substantial overhead.

Goal
- Preserve correctness: exactly match PyTorch’s index_add along dim=0 (row-wise scatter-add), including duplicate indices.
- Improve performance: vectorize the load/add/store across the hidden dimension to perform a single chunked operation per row, leveraging Triton’s vectorization and minimizing memory passes.

Analysis and plan
- Original behavior:
  - output = final_hidden_states.clone()  (random init)
  - output.index_add_(dim=0, index=token_indices, source=expert_outputs)
  - This adds the entire row expert_outputs[i] into output[token_indices[i]] for each i. Duplicates accumulate.

- Previous Triton implementation (correct but slow):
  - One program per i; scalar loop over H performing atomic_add per element. This is simple but very slow due to per-element atomic and scalar access.

- Optimized Triton approach:
  - Still one program per i (row), but:
    - Load the entire expert vector for row i in a vectorized manner: vals = tl.load(in_ptrs, mask=...)
    - Compute the destination row index idx = token_indices[i].
    - Add the vector vals to output[idx, :] using vectorized atomic_add across a chunk of columns.
      - Iterate over the hidden dimension H in blocks of BLOCK (e.g., 128), mask the tail, and atomic_add the vector slice into output.
  - This reduces the number of atomic operations from H per row to ceil(H/BLOCK) per row and performs vectorized loads/stores, significantly improving throughput while preserving correctness.

- Safety and robustness:
  - Ensure tensors are contiguous and dtypes are correct.
  - Cast token_indices to int32 for pointer arithmetic.
  - Use strides from PyTorch tensors (elements) to construct pointers; no out-of-bounds when idx in [0, M).
  - Keep a fallback to PyTorch on CPU, but on CUDA we always use the Triton kernel to satisfy the requirement.

Final code (ModelNew with optimized Triton kernel)

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_dim0_chunked_kernel(
    output_ptr,       # *bf16, shape [M, H], contiguous
    indices_ptr,      # *int32, shape [N]
    inputs_ptr,       # *bf16, shape [N, H], contiguous
    N,                # int32
    M,                # int32 (batch_size * seq_len)
    H,                # int32 (hidden_size)
    stride_out_row,   # int64
    stride_out_col,   # int64
    stride_in_row,    # int64
    stride_in_col,    # int64
    BLOCK: tl.constexpr,  # block size along hidden dimension
):
    # One program per row i
    i = tl.program_id(axis=0)
    if i >= N:
        return

    # Load destination row index
    idx = tl.load(indices_ptr + i)  # int32

    # Compute base pointers for this input row i
    in_base = inputs_ptr + i * stride_in_row
    # Load the entire expert vector in chunks of BLOCK
    for h_start in range(0, H, BLOCK):
        col = h_start + tl.arange(0, BLOCK)  # vector of column offsets
        mask = col < H
        vals = tl.load(in_base + col * stride_in_col, mask=mask, other=0.0)  # shape (BLOCK,), bfloat16

        # Compute output pointers for row idx and add vals
        out_base = output_ptr + idx * stride_out_row
        out_ptrs = out_base + col * stride_out_col
        # Perform vectorized atomic add across columns
        tl.atomic_add(out_ptrs, vals, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Preserve original semantics: clone the accumulator (random init)
        output = final_hidden_states.clone()

        # If not on CUDA, fallback to PyTorch to ensure correctness
        if (not output.is_cuda) or (not expert_outputs.is_cuda) or (not token_indices.is_cuda):
            output.index_add_(dim=0, index=token_indices, source=expert_outputs)
            return output

        # Ensure inputs are contiguous
        output = output.contiguous()
        expert_outputs = expert_outputs.contiguous()
        token_indices = token_indices.to(torch.int32).contiguous()

        # Shapes
        M, H = output.shape  # batch_seq_len, hidden_size
        N = expert_outputs.shape[0]
        assert expert_outputs.shape[1] == H, "expert_outputs second dimension must match hidden_size"
        assert token_indices.shape[0] == N, "token_indices length must match expert_outputs rows"

        # Strides in elements
        stride_out_row = output.stride(0)
        stride_out_col = output.stride(1)
        stride_in_row = expert_outputs.stride(0)
        stride_in_col = expert_outputs.stride(1)

        # Launch Triton: one program per row
        BLOCK = 128  # tuneable: 128 or 256 are good choices; 128 reduces risk for large H
        grid = (N,)

        scatter_add_dim0_chunked_kernel[grid](
            output, token_indices, expert_outputs,
            N, M, H,
            stride_out_row, stride_out_col,
            stride_in_row, stride_in_col,
            BLOCK=BLOCK,
            num_warps=4,   # tuneable
            num_stages=2   # tuneable
        )

        return output
```

Why this improves performance while keeping correctness
- It performs vectorized loads/stores and vectorized atomic adds across chunks of the hidden dimension, instead of per-element scalar operations. This drastically reduces the number of atomic operations and leverages Triton’s efficient memory access.
- It exactly implements the index_add along dim=0 semantics: for each row i, it adds the entire vector expert_outputs[i] into output[token_indices[i], :], accumulating duplicates.
- It preserves the original random initialization by cloning final_hidden_states before accumulation.
- It uses strides from PyTorch tensors to construct pointers, avoiding illegal memory access. We cast token_indices to int32 and ensure all tensors are contiguous.

Further optimization ideas (if needed)
- Increase BLOCK to 256 for larger hidden_size to reduce loop iterations; ensure the GPU has sufficient register and L2 capacity.
- Adjust num_warps based on hidden_size (e.g., 8 for larger blocks) to improve occupancy.
- If M and N are very large, consider splitting work across additional axes or using a 2D grid while carefully handling atomics; but the current 1D grid per row is simple and effective for this pattern.

This version keeps full correctness and should provide a clear performance improvement over the previous scalar implementation.
