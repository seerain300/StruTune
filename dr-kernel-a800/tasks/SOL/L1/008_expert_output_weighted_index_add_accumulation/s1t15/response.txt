Analysis and plan

- Behavior to implement:
  - Start with output = final_hidden_states.clone() where final_hidden_states has shape (M, H) and M = batch_size * seq_len.
  - For each i in [0, N), where N = M * num_experts_per_tok, add expert_outputs[i] to output[token_indices[i]] with atomic adds if token_indices[i] is repeated. This is equivalent to torch.index_add(dim=0, index=token_indices, source=expert_outputs).

- Current status:
  - The last submission used a vectorized Triton kernel processing H in tiles (BLOCK_H=512), with one program per source row (grid = N) and num_warps=8. It remains correct but achieved a lower speedup (~1.28x). The earlier version with BLOCK_H=256 and num_warps=4 had better speedup (~1.64x). So performance is sensitive to tile size and launch configuration.

- Optimization strategy:
  - Reduce the number of iterations per program while keeping register pressure reasonable. BLOCK_H=256 is a balanced choice for typical H ≤ 1024, often resulting in a single loop iteration and good throughput.
  - Use num_warps=4, which previously performed better on these workloads, and set num_stages=2 to improve pipelining slightly without increasing complexity.
  - Keep tensors contiguous, indices as int32, and bfloat16 for output and source. Ensure proper masking for tails when H is not divisible by BLOCK_H.
  - Maintain the simple one-row-per-program mapping to avoid correctness pitfalls with 2D tiling (which earlier caused numerical mismatches).

- Why this should help:
  - BLOCK_H=256 with 4 warps delivered better speedup earlier. Adjusting num_stages can help hide memory latency. Keeping the per-row vectorized atomic adds minimizes the number of atomic operations and leverages GPU parallelism. This approach preserves correctness while improving performance consistency.

Final code

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_rows_kernel(
    out_ptr,          # *const bfloat16, shape [M, H]
    src_ptr,          # *const bfloat16, shape [N, H]
    indices_ptr,      # *const int32,     shape [N]
    N,                # total source rows
    H,                # hidden size
    BLOCK_H: tl.constexpr,  # tile size over H
):
    # One program per source row
    row = tl.program_id(0)  # 0 .. N-1
    # Load destination row index and source vector for this row
    # Destination row index may be out of range if N > M, but here N = M * num_experts_per_tok, so it is valid.
    dest_row = tl.load(indices_ptr + row)  # int32
    # We will iterate over H in tiles
    for j in range(0, H, BLOCK_H):
        offs = j + tl.arange(0, BLOCK_H)
        mask = offs < H
        # Compute pointers
        src_row_ptr = src_ptr + row * H + offs
        out_row_ptr = out_ptr + dest_row * H + offs
        # Load source values (bf16)
        val = tl.load(src_row_ptr, mask=mask, other=0.0)
        # Atomic add into output
        tl.atomic_add(out_row_ptr, val, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        """
        Triton-accelerated scatter-add equivalent to:
            output = final_hidden_states.clone()
            output.index_add_(0, token_indices, expert_outputs)
        Returns the updated output.
        """
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "Inputs must be CUDA tensors"
        # Ensure contiguous tensors and dtypes
        out = final_hidden_states.clone()  # this performs the initial clone
        # Make inputs contiguous and cast indices to int32
        src = expert_outputs.contiguous()
        idx = token_indices.contiguous()
        if idx.dtype != torch.int32:
            idx = idx.to(torch.int32)

        M = out.shape[0]
        H = out.shape[1]
        N = src.shape[0]
        # Launch kernel: one program per source row
        grid = (N,)
        # Use BLOCK_H=256, num_warps=4, num_stages=2 for good balance on common H<=1024
        scatter_add_rows_kernel[grid](
            out, src, idx,
            N, H,
            BLOCK_H=256,
            num_warps=4,
            num_stages=2,
        )
        return out
```

Notes:
- This Triton kernel performs masked vectorized atomic adds across the hidden dimension for each source row, preserving correctness for duplicate token indices.
- We keep the host-side code minimal: allocate output as a clone of final_hidden_states, ensure contiguity and dtypes, and launch the kernel with a 1D grid over N (the number of source rows).
- BLOCK_H=256 and num_warps=4 previously delivered better speedup; num_stages=2 can help hide memory latency. If you want to explore further, you can try BLOCK_H=128 or 512 depending on the typical H in your workloads, but 256 is a safe, performant default here.
