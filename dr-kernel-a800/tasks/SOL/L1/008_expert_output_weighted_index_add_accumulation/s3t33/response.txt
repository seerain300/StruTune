Duplicates must be handled via atomic adds, and Triton only supports atomic_add in float32, so we accumulate in fp32 and cast back to bfloat16 at the end.

Further optimization considerations
- The kernel is memory-bound and dominated by atomic adds. Performance improvements come from:
  - Minimizing the number of atomic operations per update (vectorizing across the hidden dimension H).
  - Amortizing scheduling overhead and keeping good occupancy.
- A robust pattern that delivered the best speed so far:
  - One Triton program per update (grid = N). This keeps the kernel simple and avoids 2D loops and their potential register pressure.
  - Vectorize across H in BLOCK_H chunks, performing a single atomic_add per chunk. Choose BLOCK_H based on H to reduce atomics while balancing register usage:
    - H >= 1024: BLOCK_H = 1024, num_warps = 8. For H=1024, this is exactly one atomic add per update.
    - H >= 512: BLOCK_H = 512, num_warps = 4.
    - Otherwise: BLOCK_H = 256, num_warps = 2.
  - Keep num_stages=2 to balance latency hiding for memory ops.
- Alternative multi-update pattern (processing T updates per program) sometimes regressed due to increased register pressure. The simple per-update vectorization approach is currently the most stable and fastest across diverse workloads.

Plan
- Implement a single Triton kernel with:
  - One program per update (pid = program_id(0)).
  - Load idx = token_indices[pid] and v = expert_outputs[pid, :] as float32.
  - Iterate H in chunks of BLOCK_H, perform a single atomic_add of v_chunk into out_fp32[idx, h:h+BLOCK_H].
- Host-side:
  - Ensure inputs are contiguous and on the same CUDA device.
  - Cast final_hidden_states to float32 for accumulation; allocate out_fp32 contiguous buffer.
  - After Triton kernel, cast out_fp32 back to bfloat16 to match the original API.

Final code (ModelNew)
```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_rows_kernel(
    out_ptr,                # *fp32, shape [batch_seq_len, H]
    token_indices_ptr,      # *i32, shape [N]
    expert_outputs_ptr,     # *fp32, shape [N, H]
    N: tl.constexpr,        # number of updates (batch_seq_len * num_experts_per_tok)
    H: tl.constexpr,        # hidden size
    BLOCK_H: tl.constexpr,  # chunk size along H
):
    pid = tl.program_id(0)
    # Each program handles one update
    if pid >= N:
        return

    # Load token index (original position)
    idx = tl.load(token_indices_ptr + pid)
    # Load expert output vector for this update as float32
    # We will loop over H in chunks of BLOCK_H and do one atomic add per chunk
    # This keeps atomics minimal: one per chunk per update.
    h = 0
    while h < H:
        offs = h + tl.arange(0, BLOCK_H)
        mask = offs < H
        v = tl.load(expert_outputs_ptr + pid * H + offs, mask=mask, other=0.0)
        # Atomic add into the output row
        out_row_ptr = out_ptr + idx * H + offs
        tl.atomic_add(out_row_ptr, v, mask=mask)
        h += BLOCK_H


def _choose_block_h_and_warps(H: int):
    # Heuristics for chunk size and num_warps based on H
    if H >= 1024:
        return 1024, 8
    elif H >= 512:
        return 512, 4
    else:
        return 256, 2


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        """
        Triton-optimized scatter-add:
            output[token_indices[i]] += expert_outputs[i, :]
        Accumulates in float32 (Triton atomic_add supports fp32), returns bfloat16 like the original.
        """
        # Ensure device and contiguity
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "Inputs must be on CUDA"
        H = final_hidden_states.shape[1]
        N = token_indices.shape[0]

        # Clone input and cast to fp32 for accumulation
        out_fp32 = final_hidden_states.clone().to(torch.float32)
        expert_outputs_fp32 = expert_outputs.to(torch.float32)
        token_indices_i32 = token_indices.to(torch.int32)

        # Grid: one program per update
        grid = (N,)

        # Choose BLOCK_H and num_warps
        BLOCK_H, num_warps = _choose_block_h_and_warps(H)

        # Launch Triton kernel
        scatter_add_rows_kernel[grid](
            out_fp32,
            token_indices_i32,
            expert_outputs_fp32,
            N=N,
            H=H,
            BLOCK_H=BLOCK_H,
            num_warps=num_warps,
            num_stages=2,
        )

        # Cast back to bfloat16 to match original API
        return out_fp32.to(torch.bfloat16)
```

Notes
- This kernel uses the proven pattern that delivered the best speed: one program per update, vectorizing across H with a compile-time BLOCK_H and performing a single atomic_add per chunk. It preserves correctness for duplicate indices via atomic adds and avoids any PyTorch scatter operations in the host code.
- The heuristics for BLOCK_H and num_warps are chosen to balance atomics and register pressure across typical hidden sizes. You can further tune num_stages (e.g., 1 for very small H) if needed, but this configuration is robust and fast across the provided workloads.
