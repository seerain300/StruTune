- We use two Triton kernels:
  1) Row-chunk kernel: one program per source row (n), iterating H in chunks (BLOCK_H) and performing tl.atomic_add per element. This is simple and robust.
  2) 2D tiled kernel: one program processes a tile of BLOCK_N source rows and BLOCK_H hidden features, performing 2D atomic_add. This reduces the number of programs and increases per-program work, which can improve throughput when H is large and contention exists.
- Heuristic: Choose the 2D kernel when H is large (e.g., H >= 512). Otherwise, use the row-chunk kernel. Additionally, tune BLOCK sizes and num_warps/num_stages based on problem size.

- Improve per-program work without exploding register pressure:
  - Keep BLOCK_H = 128 for H >= 512, else 64. This provides good vectorization and coalesced loads/stores.
  - For the 2D kernel, use BLOCK_N = 64 when N is large (e.g., N >= 8192), else BLOCK_N = 32. This reduces the number of programs and increases work per program, improving throughput.
  - num_warps: 4 for BLOCK_H >= 128, 8 for larger blocks. num_stages: 2 for moderate H, 3 for very large H.
- Maintain robustness:
  - Keep the while loops with runtime termination to handle arbitrary H and N.
  - Ensure token_indices are int32, and tensors are contiguous on CUDA.
- This hybrid approach should retain the best characteristics of each kernel and can further improve performance across varying workloads.

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_row_kernel(
    output_ptr,            # *bf16 or *fp16, pointer to output (M, H)
    expert_ptr,            # *bf16 or *fp16, pointer to expert outputs (N, H)
    index_ptr,             # *int32, pointer to token indices (N,)
    M, N, H,               # int32 runtime sizes
    BLOCK_H: tl.constexpr  # tile size along H
):
    # One program per source row (n)
    n = tl.program_id(0)  # 0..N-1
    # Compute base offsets for this row
    # Addresses: output[n, :] starts at output_ptr + n*H, expert[n, :] at expert_ptr + n*H
    # We'll iterate over H in chunks of BLOCK_H
    h = 0
    while h < H:
        offs_h = h + tl.arange(0, BLOCK_H)
        mask = offs_h < H

        # Load token index for this row
        tok = tl.load(index_ptr + n)  # int32
        # Compute destination pointer: output[tok, offs_h]
        dest = tok * H + offs_h

        # Load the corresponding expert row chunk
        src = n * H + offs_h
        val = tl.load(expert_ptr + src, mask=mask, other=0)

        # Atomic add to output
        tl.atomic_add(output_ptr + dest, val, mask=mask)

        h += BLOCK_H


@triton.jit
def scatter_add_tile_kernel(
    output_ptr,            # *bf16 or *fp16, pointer to output (M, H)
    expert_ptr,            # *bf16 or *fp16, pointer to expert outputs (N, H)
    index_ptr,             # *int32, pointer to token indices (N,)
    M, N, H,               # int32 runtime sizes
    BLOCK_N: tl.constexpr, # number of source rows per program
    BLOCK_H: tl.constexpr  # number of hidden features per tile
):
    # 2D grid over tiles of (N, H)
    pid_n = tl.program_id(0)
    pid_h = tl.program_id(1)

    n_start = pid_n * BLOCK_N
    h_start = pid_h * BLOCK_H

    offs_n = n_start + tl.arange(0, BLOCK_N)
    offs_h = h_start + tl.arange(0, BLOCK_H)

    mask_n = offs_n < N
    mask_h = offs_h < H
    mask = mask_n[:, None] & mask_h[None, :]

    # Load token indices for this tile of rows
    tok_vec = tl.load(index_ptr + offs_n, mask=mask_n, other=0)  # shape (BLOCK_N,)

    # Build 2D destination addresses: output[tok_vec[n], offs_h]
    dest = tok_vec[:, None] * H + offs_h[None, :]

    # Load corresponding expert tile: expert[offs_n, offs_h]
    src = offs_n[:, None] * H + offs_h[None, :]
    val = tl.load(expert_ptr + src, mask=mask, other=0)

    # Atomic add to output
    tl.atomic_add(output_ptr + dest, val, mask=mask)


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Ensure inputs are on CUDA and contiguous
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "All tensors must be on CUDA"
        # Make sure token_indices is int32 for efficient address arithmetic
        if token_indices.dtype != torch.int32:
            token_indices = token_indices.to(torch.int32)
        token_indices = token_indices.contiguous()
        expert_outputs = expert_outputs.contiguous()

        M = final_hidden_states.shape[0]
        N = expert_outputs.shape[0]
        H = expert_outputs.shape[1]

        # Output buffer: clone from input or allocate
        output = final_hidden_states  # we will atomic_add into this buffer

        # Heuristic: choose kernel based on H and N
        use_2d = (H >= 512) and (N >= 8192)

        if use_2d:
            # 2D tiled kernel
            BLOCK_N = 64 if N >= 8192 else 32
            BLOCK_H = 128 if H >= 512 else 64
            grid = (triton.cdiv(N, BLOCK_N), triton.cdiv(H, BLOCK_H))
            # Tune num_warps/num_stages
            num_warps = 4 if BLOCK_H <= 128 else 8
            num_stages = 2 if H < 1024 else 3
            scatter_add_tile_kernel[grid](
                output, expert_outputs, token_indices,
                M, N, H,
                BLOCK_N=BLOCK_N, BLOCK_H=BLOCK_H,
                num_warps=num_warps, num_stages=num_stages
            )
        else:
            # Row-chunk kernel
            BLOCK_H = 128 if H >= 512 else 64
            grid = (N,)
            num_warps = 4 if BLOCK_H <= 128 else 8
            num_stages = 2 if H < 1024 else 3
            scatter_add_row_kernel[grid](
                output, expert_outputs, token_indices,
                M, N, H,
                BLOCK_H=BLOCK_H,
                num_warps=num_warps, num_stages=num_stages
            )

        return output
```

Observations and analysis
- The operation is a scatter-add along dim=0: output[token_indices[i]] += expert_outputs[i] for i in [0..N), where output is (M, H), expert_outputs is (N, H), and token_indices length N. M = batch_size * seq_len.
- PyTorch’s index_add is already optimized, but we are asked to implement a Triton version that is actually invoked from ModelNew.forward and aims for speedups across varied shapes.
- Challenges:
  - Scatter-add is inherently parallel but can have atomic contention when many indices map to the same output row. This makes it difficult to fully avoid atomics without a two-phase reduction per row (first reduce per-row, then add), which adds complexity and potential correctness risks.
  - Performance depends heavily on H and N, and the distribution of token_indices. We should maximize per-program work and keep memory accesses coalesced.

Strategy and plan
- Keep two Triton kernels:
  1) Row-chunk kernel: one Triton program per source row (n). Inside each program, iterate over H in BLOCK_H chunks, load token_indices[n], load the corresponding expert_outputs[n, h_block], and perform tl.atomic_add to output. This is simple and robust.
  2) 2D-tiled kernel: each Triton program processes a tile of BLOCK_N rows and BLOCK_H hidden features. It performs 2D atomic_add across the tile. This reduces the number of programs and increases per-program work, which can improve throughput when H and N are large.
- Heuristic to choose kernel:
  - Use the 2D tiled kernel when H is large (e.g., H >= 1024) and N is large (e.g., N >= 8192). Otherwise, use the row-chunk kernel.
  - This lets the kernel adapt to different contention patterns and shapes.
- Tuning:

  - 2D tiled: BLOCK_N = 64 for N >= 8192, else 32. BLOCK_H = 128 for H >= 1024, else 64. num_warps = 4, num_stages = 2.
