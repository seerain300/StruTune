Analysis and plan
- Semantics: output = final_hidden_states.clone(); then index_add along dim=0 with token_indices and expert_outputs. That means for each row i: output[token_indices[i], :] += expert_outputs[i, :]. Duplicates accumulate. Our Triton approach must match this exactly.

- Current status: We implemented a robust kernel that assigns one program per row i, loads the entire expert row vector, and performs vectorized atomic_add across chunks of the hidden dimension. This reduced atomic count and improved performance to about 1.29x on average.

- Bottleneck and opportunities:
  - Each program handles one row and processes all hidden columns in chunks, using atomic_add. This is good, but:
    - We can improve throughput by tuning block size and the number of warps to better saturate memory bandwidth on various GPUs and hidden sizes.
    - Ensure contiguous and proper dtype handling to avoid unnecessary copies or type conversions.
    - Keep code simple to avoid correctness regressions; more complex multi-program scatter-add patterns risk subtle issues (as we learned earlier).

- Strategy for further optimization:
  1) Keep one-program-per-row to avoid cross-program races and ensure deterministic accumulation.
  2) Use Triton’s autotune to select an optimal BLOCK size and num_warps based on the hidden dimension H. Provide a small set of configs (e.g., BLOCK 64/128/256 with num_warps 1/2/4), letting Triton pick the best for the given H at runtime.
  3) Maintain vectorized loads/stores within each chunk and use atomic_add for each chunk. This keeps the number of atomics modest (ceil(H/BLOCK)) and leverages Triton’s vectorization.
  4) Keep tensors contiguous and ensure token_indices is int32 for pointer arithmetic. Use strides from PyTorch tensors to compute element offsets.

Why not multi-program scatter-add to reduce atomic pressure per row?
- While it can reduce per-row atomics, it introduces cross-program write conflicts unless we use per-row atomics (which defeats the purpose) or a global grid that serializes work. Implementing safe, performant, and race-free scatter-add across the entire grid for every row is complex and easy to get wrong. The one-program-per-row approach is simpler and has already proven correct and reasonably fast. Autotuning should help close the performance gap further.

```python
import torch
import triton
import triton.language as tl


@triton.autotune(
    configs=[
        triton.Config({'BLOCK': 64}, num_warps=1, num_stages=2),
        triton.Config({'BLOCK': 128}, num_warps=2, num_stages=2),
        triton.Config({'BLOCK': 256}, num_warps=4, num_stages=2),
    ],
    key=['H'],
)
@triton.jit
def scatter_add_rows_kernel(
    output_ptr,           # *const half (final_hidden_states, cloned)
    expert_ptr,           # *const half (expert_outputs)
    indices_ptr,          # *const int32 (token_indices)
    N,                    # int32: number of rows in expert_outputs (len(token_indices))
    H,                    # int32: hidden size (number of columns)
    stride_out_row: tl.constexpr,  # int32: stride for output rows (in elements)
    stride_out_col: tl.constexpr,  # int32: stride for output cols (in elements), typically 1
    stride_in_row: tl.constexpr,   # int32: stride for expert rows
    stride_in_col: tl.constexpr,   # int32: stride for expert cols, typically 1
    BLOCK: tl.constexpr,           # chunk size across columns
):
    # One program per row i
    i = tl.program_id(axis=0)
    # If grid > N, guard (usually not needed since grid=N, but keep safety)
    if i >= N:
        return

    # Load destination row index for this row
    idx = tl.load(indices_ptr + i)  # int32

    # Iterate over hidden dimension in chunks of BLOCK
    # Note: we can't rely on a Python for-loop with runtime limits here, so we use a while loop.
    start = 0
    while start < H:
        cols = start + tl.arange(0, BLOCK)
        mask = cols < H

        # Compute pointers for the input row slice and output row slice
        in_ptrs = expert_ptr + i * stride_in_row + cols * stride_in_col
        out_ptrs = output_ptr + idx * stride_out_row + cols * stride_out_col

        # Load the expert values for this chunk (bf16)
        vals = tl.load(in_ptrs, mask=mask, other=0.0)

        # Atomically add to the output row
        tl.atomic_add(out_ptrs, vals, mask=mask)

        start += BLOCK


def _scatter_add_rows_triton(output: torch.Tensor, expert: torch.Tensor, indices: torch.Tensor):
    """
    output: (M, H), cloned final_hidden_states
    expert: (N, H)
    indices: (N,) int64 or int32, positions in [0, M)
    """
    assert output.is_cuda and expert.is_cuda and indices.is_cuda, "Triton kernel requires CUDA tensors."
    assert output.dtype == torch.bfloat16 and expert.dtype == torch.bfloat16, "Expect bfloat16 tensors."
    assert indices.dtype in (torch.int64, torch.int32), "indices must be int64 or int32."

    # Ensure contiguous for simpler stride handling
    output = output.contiguous()
    expert = expert.contiguous()
    # Triton prefers int32 for indices arithmetic; cast if necessary
    if indices.dtype != torch.int32:
        indices = indices.to(torch.int32)

    M, H = output.shape
    N = expert.shape[0]
    # Triton grid: one program per row
    grid = (N,)

    # Launch kernel
    scatter_add_rows_kernel[grid](
        output, expert, indices,
        N, H,
        output.stride(0), output.stride(1),
        expert.stride(0), expert.stride(1),
        H=H,  # key for autotune
    )
    return output


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        """
        Triton-based implementation of:
          output = final_hidden_states.clone()
          output.index_add_(dim=0, index=token_indices, source=expert_outputs)
        """
        # Ensure device and dtype
        assert final_hidden_states.dtype == torch.bfloat16 and expert_outputs.dtype == torch.bfloat16
        assert token_indices.device == final_hidden_states.device == expert_outputs.device, "All tensors must be on same device."
        # Clone to preserve original semantics
        output = final_hidden_states.clone()

        # Run Triton kernel
        _scatter_add_rows_triton(output, expert_outputs, token_indices)
        return output
```
