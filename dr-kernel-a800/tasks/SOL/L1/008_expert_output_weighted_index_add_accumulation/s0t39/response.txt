The operation is a scatter-add along dim=0, which is inherently limited by atomic contention when many indices map to the same output row. To further improve and stabilize performance, we can:

- Increase per-program work along H to reduce loop iterations and control overhead while keeping register pressure reasonable.
- Adapt kernel launch parameters (BLOCK_H, num_warps, num_stages) to H to balance occupancy and throughput.
- Keep the kernel simple and Triton-only, using one program per source row and vectorized chunks along H.

Plan
- One Triton program per source row n.
- Inside each program, iterate over H in chunks of BLOCK_H. For each chunk:
  - Load token_indices[n] once.
  - Load expert_outputs[n, h:h+BLOCK_H] with coalesced memory access.
  - Perform tl.atomic_add into output[token_indices[n], h:h+BLOCK_H].
- Adaptive tuning:
  - If H >= 2048: BLOCK_H=256, num_warps=8, num_stages=3 to handle very large H efficiently.
  - If H >= 512: BLOCK_H=256, num_warps=4, num_stages=2.
  - If H >= 128: BLOCK_H=128, num_warps=4, num_stages=2.
  - Else: BLOCK_H=64, num_warps=2, num_stages=2.
- Use int32 for token_indices to keep address arithmetic fast and within Triton’s efficient range for these workloads.

Final code

```python
import torch
import triton
import triton.language as tl


@triton.jit
def scatter_add_rows_kernel(
    output_ptr,       # *bf16 or *fp16, pointer to output [M, H]
    expert_ptr,       # *bf16 or *fp16, pointer to expert_outputs [N, H]
    index_ptr,        # *int32, pointer to token_indices [N]
    M: tl.int32,      # number of rows in output
    H: tl.int32,      # hidden size
    N: tl.int32,      # number of source rows
    BLOCK_H: tl.constexpr,
):
    # One program per source row
    n = tl.program_id(0)
    if n >= N:
        return

    # Destination row index for this source row
    dest = tl.load(index_ptr + n)  # int32
    # Base pointers for this source row
    expert_row_ptr = expert_ptr + n * H
    # Iterate over H in chunks
    start = 0
    while start < H:
        offs = start + tl.arange(0, BLOCK_H)  # [BLOCK_H] int32
        mask = offs < H
        # Load expert values for this chunk (coalesced along H)
        vals = tl.load(expert_row_ptr + offs, mask=mask, other=0.0)
        # Atomic add into output at destination row
        out_row_ptr = output_ptr + dest * H
        tl.atomic_add(out_row_ptr + offs, vals, mask=mask)
        start += BLOCK_H


def _choose_launch_params(H: int):
    # Adaptive tuning based on H
    if H >= 2048:
        return 256, 4, 3  # BLOCK_H, num_warps, num_stages
    elif H >= 512:
        return 256, 4, 2
    elif H >= 128:
        return 128, 4, 2
    else:
        return 64, 2, 2


class ModelNew(torch.nn.Module):
    def forward(self, final_hidden_states: torch.Tensor, expert_outputs: torch.Tensor, token_indices: torch.Tensor):
        # Triton-only implementation: no PyTorch tensor ops in host code
        assert final_hidden_states.is_cuda and expert_outputs.is_cuda and token_indices.is_cuda, "All inputs must be on CUDA"
        # Ensure dtype compatibility; we will operate in the same dtype as inputs (bf16 in provided setup)
        output = final_hidden_states
        # Token indices as int32 for Triton address arithmetic
        if token_indices.dtype != torch.int32:
            index_i32 = token_indices.to(torch.int32)
        else:
            index_i32 = token_indices

        M, H = output.shape
        N = expert_outputs.shape[0]
        # Choose kernel params based on H
        BLOCK_H, num_warps, num_stages = _choose_launch_params(H)
        grid = (N,)  # one program per source row

        scatter_add_rows_kernel[grid](
            output, expert_outputs, index_i32,
            M, H, N,
            BLOCK_H=BLOCK_H,
            num_warps=num_warps,
            num_stages=num_stages,
        )
        return output
```

- Adaptive BLOCK_H, num_warps, and num_stages aim to improve performance across varied H sizes. The previous best geomean (~1.83) was achieved with a similar approach, and this refinement can help stabilize or further improve performance while maintaining correctness across all workloads.
