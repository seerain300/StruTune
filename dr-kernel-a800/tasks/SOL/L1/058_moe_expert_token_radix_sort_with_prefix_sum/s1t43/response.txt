Design for Triton kernels:
1) compute_out_pos_triton:
   - Inputs: flat_ptr (int32), out_ptr (int32), N (int32), num_experts (int32).
   - One Triton program (grid=(1,)) loops over i in [0, N-1]:
     - Load v = flat[i] (int32).
     - Compute its position pos = le_counts[v] - (1 if there are duplicates of v and i is not the first occurrence else 0).
     - Set out[v] = i.
     - le_counts[v] += 1 (this models tie-breaking by making subsequent duplicates get position le_counts-1).
     Ties are ordered by original index due to sequential processing and the le_counts update order.
   - This produces out such that out[i] = index of i-th element in stable sorted order. We’ll return out.

2) cumsum_inclusive_triton:
   - Inputs: counts_ptr (int32), out_ptr (int32), length (constexpr, here 256).
   - Single Triton program does a sequential loop: out[i] = sum of counts[0..i], with out[0] = counts[0]. This builds expert_offsets with offsets[0]=0 at host by prepending.

3) histogram_kernel (simple host-side, but acceptable for correctness since we only use counts in Triton cumsum). However, the evaluation requires Triton usage; thus we can omit this step and directly build counts in compute_out_pos_triton as needed, but for clarity and consistency, we include a Triton histogram to match behavior. But to minimize risk, we will compute counts inside compute_out_pos_triton to avoid atomic complexity; counts_ptr will be length num_experts, initialized to zeros. However, we need counts for offsets; so we’ll maintain a global counts tensor and compute le_counts in Triton for offsets.

Implementation notes:
- Keep all tensors on the same device as flat; Triton kernels operate on device memory.
- Ensure all loads/stores use proper masks and dtypes.

import triton
import triton.language as tl


@triton.jit
def compute_out_pos_triton(flat_ptr, out_ptr, counts_ptr, le_ptr, N, num_experts: tl.constexpr):
    """
    Compute stable argsort permutation for flat_ptr[0:N] into out_ptr[0:N].
    Also compute per-expert counts into counts_ptr[0:num_experts] and inclusive prefix le into le_ptr[0:num_experts].
    For each element i with id = flat[i], we:
      - compute le_counts[id], update counts_ptr[id] += 1 and le_ptr[k] = sum_{k'=0..k} counts_ptr[k']
      - set out[id] = i
      - stable ordering is ensured by the sequential tie-breaking: subsequent duplicates get position le_counts - 1
    """
    # Initialize counts to 0 and le to 0 (we will build them in the loop)
    # counts_ptr and le_ptr are int32, length num_experts
    # We'll compute counts_ptr and le_ptr by side-effect per iteration.
    # For each i in 0..N-1:
    for i in range(0, N):
        # Load value at position i
        v = tl.load(flat_ptr + i)  # v is int32
        # Update counts_ptr[v] += 1
        old = tl.load(counts_ptr + v)
        new = old + 1
        tl.store(counts_ptr + v, new)
        # Compute inclusive prefix sum up to v to get le_counts[v]
        total = 0
        for k in range(0, num_experts):
            c = tl.load(counts_ptr + k)
            total += c
            tl.store(le_ptr + k, total)
        # Assign position i to out[v] (stable because we iterate sequentially)
        tl.store(out_ptr + v, i)


@triton.jit
def cumsum_inclusive_triton(counts_ptr, out_ptr, length: tl.constexpr):
    """
    Inclusive cumsum of counts_ptr[0:length] into out_ptr[0:length].
    out[0] = counts[0]; out[i] = sum_{j=0..i} counts[j].
    Single-program sequential loop.
    """
    total = tl.load(counts_ptr + 0)
    tl.store(out_ptr + 0, total)
    for i in range(1, length):
        val = tl.load(counts_ptr + i)
        total += val
        tl.store(out_ptr + i, total)


def run(topk_idx: torch.Tensor):
    """
    Triton-only implementation of the original run function:
    Returns sorted_token_indices (stable argsort permutation of flattened topk_idx) and expert_offsets.
    """
    # Flatten to int32 and ensure contiguous
    flat = topk_idx.reshape(-1).to(torch.int32).contiguous()
    N = flat.numel()
    device = flat.device

    num_experts = 256
    # Output permutation and counts buffers
    out = torch.empty(N, dtype=torch.int32, device=device)
    counts = torch.zeros(num_experts, dtype=torch.int32, device=device)
    le_counts = torch.empty(num_experts, dtype=torch.int32, device=device)

    # Launch Triton kernel to compute stable argsort permutation and counts+le
    # We pass N and num_experts as constexpr-like via arguments; Triton expects Python ints.
    compute_out_pos_triton[(1,)](flat, out, counts, le_counts, N, num_experts=num_experts)

    # sorted_token_indices is the permutation that would sort flat in stable order.
    # out[i] = index of i-th element in sorted order, so we return out directly as int32.
    sorted_token_indices = out

    # expert_offsets: inclusive prefix sums of counts per expert, length num_experts+1, with offsets[0]=0.
    # We will compute offsets using Triton cumsum on counts.
    offsets_counts = torch.empty(num_experts + 1, dtype=torch.int32, device=device)

    # We need offsets[0] = 0
    offsets_counts[0] = 0

    return sorted_token_indices, offsets_counts

  - Maintain per-expert counts in a small vector,
  - Compute inclusive prefix sums for le_counts,
  - Assign position to each element id and write a stable permutation out. We’ll return out as sorted_token_indices.

Key correctness details:
- Stable argsort tie-breaking: torch.argsort(flat, stable=True) sorts by value and, for ties, by original index (ascending). In Triton, we implement this by:
  - Iterating over i from 0 to N-1. For each i, compute le_counts[id] and set position pos = le_counts[id] - (1 if there are duplicates of id and i is not the first occurrence else 0). We maintain counts[id] and update le_counts sequentially, ensuring earlier i values get position le_counts before duplicates increase it.
  - We then set out[id] = i. This yields the permutation of indices [0..N-1] that places the i-th original element at position out[i] in the stable sorted order.
- expert_offsets: length num_experts+1. We can build counts in the Triton kernel and then perform an inclusive cumsum on counts with a simple Triton loop (no torch.cumsum).

Performance considerations:
- The stable permutation kernel uses a single Triton program with a sequential loop. This is acceptable for the sizes in the provided workloads (N up to 2048 and beyond but we benchmark small to medium sizes). A more advanced parallel counting-sort could be faster but is complex to ensure correctness without torch ops; this sequential approach is robust and Triton-only.

import triton
import triton.language as tl


@triton.jit
def compute_out_pos_triton(flat_ptr, out_ptr, counts_ptr, le_ptr, N, num_experts: tl.constexpr):
    """
    Compute stable argsort permutation for flat_ptr[0:N] into out_ptr[0:N].
    Also compute per-expert counts into counts_ptr[0:num_experts] and inclusive prefix le into le_ptr[0:num_experts].
    For each element i with id = flat[i], we:
      - compute le_counts[id] (inclusive sum of counts up to id)
      - update counts_ptr[id] += 1
      - set out[id] = i
    Stable ordering is ensured by iterating sequentially, so earlier i values get lower positions.
    """
    # Loop over all elements to assign positions
    for i in range(0, N):
        v = tl.load(flat_ptr + i)  # v is int32
        # Update counts and le_counts
        old = tl.load(counts_ptr + v)
        new = old + 1
        tl.store(counts_ptr + v, new)
        total = 0
        for k in range(0, num_experts):
            c = tl.load(counts_ptr + k)
            total += c
            tl.store(le_ptr + k, total)
        # Assign stable position: out[v] = i
        tl.store(out_ptr + v, i)


@triton.jit
def cumsum_inclusive_triton(counts_ptr, out_ptr, length: tl.constexpr):
    """
    Inclusive cumsum of counts_ptr[0:length] into out_ptr[0:length].
    out[0] = counts[0]; out[i] = sum_{j=0..i} counts[j].
    Single-program sequential loop.
    """
    total = tl.load(counts_ptr + 0)
    tl.store(out_ptr + 0, total)
    for i in range(1, length):
        val = tl.load(counts_ptr + i)
        total += val
        tl.store(out_ptr + i, total)


def run(topk_idx: torch.Tensor):
    """
    Triton-only implementation:
    Returns (sorted_token_indices, expert_offsets).
    - sorted_token_indices: permutation of [0..N-1] that would sort the flattened topk_idx stably (int32)
    - expert_offsets: inclusive prefix sums of counts per expert ID, length num_experts+1 (int32)
    """
    # Flatten and ensure int32 contiguous
    flat = topk_idx.reshape(-1).to(torch.int32).contiguous()
    N = flat.numel()
    device = flat.device

    num_experts = 256
    out = torch.empty(N, dtype=torch.int32, device=device)
    counts = torch.zeros(num_experts, dtype=torch.int32, device=device)
    le_counts = torch.empty(num_experts, dtype=torch.int32, device=device)

    # Launch Triton kernel to compute stable argsort permutation and counts+le
    compute_out_pos_triton[(1,)](flat, out, counts, le_counts, N, num_experts=num_experts)

    # sorted_token_indices is the permutation: out[i] = index of i-th element in stable sorted order.
    sorted_token_indices = out

    # expert_offsets: inclusive prefix sums of counts per expert, length num_experts+1, with offsets[0]=0
    offsets = torch.empty(num_experts + 1, dtype=torch.int32, device=device)
    # cumsum counts[1:] and place first element at 0
    cumsum_inclusive_triton[(1,)](counts, offsets[1:], length=num_experts)
    offsets[0] = 0

    return sorted_token_indices, offsets
