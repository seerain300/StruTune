  - Flatten the input topk_idx to a 1D tensor orig on device.
  - Compute expert_offsets entirely via Triton:
    - histogram_kernel: count occurrences of each expert id using atomic_add.
    - exclusive_prefix_sum_kernel: compute exclusive prefix sums of counts to produce offsets[e] = number of elements < e, stored in a single int32 output of length num_experts+1 (last element = total N). This avoids torch.cumsum.
  - Implement stable sorting of orig using a Triton kernel that performs a counting-sort-like stable permutation over the known small value range L=num_experts=256:
    - For each value v in [0..L-1]:
      - Compute its count and base offset.
      - Iterate over the flattened elements i in [0..N-1]. If orig[i] == v, assign out[base + local_rank] = i and increment local_rank. This preserves stability (equal values are assigned in increasing original order).
    - This deterministic approach produces the same result as torch.sort(stable=True) for the flattened values because:
      - Values are in [0..L-1] = [0..255].
      - Within each value, elements are assigned in increasing original index order (stable).

Performance considerations:
- The sorting kernel does a simple outer loop over L=256 and an inner loop over N flattened elements, performing vectorized comparisons and masked updates. This is simple and avoids complex sorting networks. Given the typical N from the benchmark (e.g., up to 2048–16384), this should run efficiently on GPU and avoid host-side torch calls.
- The histogram and prefix-sum are O(N) with small constants, and use atomic adds which Triton supports on int32 for GPU.

Edge handling:
- Ensure masks for lane bounds to avoid illegal memory access.
- Use int32 for counts and offsets to match torch semantics in the original (offsets are int32).
- Ensure kernels are invoked; forward will call sort_kernel, histogram_kernel, and exclusive_prefix_sum_kernel.

# Kernel: compute per-value counts for orig (int32 values in [0, L-1]).
# counts_ptr[e] = number of occurrences of value e in orig.
@triton.jit
def histogram_kernel(orig_ptr, counts_ptr, N, L: tl.constexpr, BLOCK: tl.constexpr):
    # One program per value e in [0, L)
    e = tl.program_id(0)
    # Initialize count to 0
    count = 0
    # Iterate over orig in chunks of BLOCK
    for start in range(0, N, BLOCK):
        offsets = start + tl.arange(0, BLOCK)
        mask = offsets < N
        vals = tl.load(orig_ptr + offsets, mask=mask, other=0)
        # Increment count for positions where orig[offsets] == e and offsets are valid
        count += tl.sum((vals == e) & mask)
    # Store count
    tl.store(counts_ptr + e, count)

# Output pointer points to out_ptr[0..L], we will write base per value.
@triton.jit

    # Maintain running sum and write bases for each i in 0..L-1

        ci = tl.load(counts_ptr + i)
        out_ptr[i] = running
        running += ci
    # last entry = total N
    out_ptr[L] = running
