    flat_ptr: int32* pointer to flattened topk_idx of length N
    counts_ptr: int32* pointer to counts array of length num_experts
    N: int32, number of elements in flat_ptr
    BLOCK_HIST: tile size for processing elements

    tl.atomic_add(counts_ptr + vals, 1, mask=mask)

    """
    Single-program inclusive scan of counts_ptr[0..M-1] into out_ptr[0..M-1].
    We assume M is small (e.g., 256), so one program is fine.
    out_ptr[M] will contain the final carry (not used here).

import triton
import triton.language as tl

# Fixed number of experts as in the original code
NUM_EXPERTS = 256


@triton.jit
def count_experts_kernel(flat_ptr, counts_ptr, N: tl.int32, BLOCK_COUNT: tl.constexpr):
    """
    Compute counts of each expert id in flat_ptr[0..N-1] into counts_ptr[0..NUM_EXPERTS-1].
    No atomics used. One program iterates over tiles of size BLOCK_COUNT.
    """
    i = 0
    while i < N:
        offs = i + tl.arange(0, BLOCK_COUNT)
        mask = offs < N
        vals = tl.load(flat_ptr + offs, mask=mask, other=0)  # int32
        # Accumulate counts per expert: for each value v in vals (masked), increment counts[v]
        # Since we don't have atomics, we loop over the BLOCK_COUNT and increment counts[v] if valid.
        # Note: Triton supports scalar while loops; we loop over the vector elements via a loop in Python
        # by expanding the vector into scalar increments.
        # However, Triton requires vectorized ops; instead, we use a segmented approach: for each element,
        # compute its index in the vector and update. A clean way is to process scalar by scalar:
        # We'll do it by expanding the vector elements one by one using a Python range loop.
        # This is acceptable for BLOCK_COUNT-sized operations and avoids atomics.
        # For each j in 0..BLOCK_COUNT-1:
        for j in range(BLOCK_COUNT):
            v = vals[j]
            m = (i + j) < N  # mask for this scalar element
            # v is int32; we must ensure counts_ptr[v] exists. Since vals are in [0, NUM_EXPERTS-1],
            # and get_inputs ensures that, we can safely increment.
            # But Triton does not support pointer arithmetic with runtime indices in this way directly.
            # Therefore, we rely on the fact that we will only index within [0, NUM_EXPERTS-1] and use
            # tl.load/tl.store on scalar with computed addresses. Triton supports scalar indexing.
            # Compute address and increment if m is True.
            if m:
                # Increment counts_ptr[v] by 1. Triton will handle the pointer arithmetic.
                tl.store(counts_ptr + v, tl.load(counts_ptr + v) + 1)
        i += BLOCK_COUNT


@triton.jit
def prefix_sum_kernel(counts_ptr, out_ptr, M: tl.int32):
    """
    Inclusive prefix sum of counts_ptr[0..M-1] into out_ptr[0..M-1].
    Single-program sequential scan. M is the number of experts (NUM_EXPERTS).
    """
    carry = tl.zeros((), dtype=tl.int32)
    # Sequential loop: Triton supports scalar loops
    for i in range(M):
        val = tl.load(counts_ptr + i)
        carry += val
        tl.store(out_ptr + i, carry)


@triton.jit
def compute_out_pos_real(flat_ptr, le_counts_ptr, lt_counts_ptr, out_ptr, N: tl.int32, BLOCK_OUT: tl.constexpr):

    Compute stable argsort permutation: out[i] = position of flat[i] in stable order.
    Uses le_counts_ptr and lt_counts_ptr which have length NUM_EXPERTS.
    N: number of elements in flat_ptr/out_ptr
    BLOCK_OUT: tile size for processing indices
    """

    while i < N:
        offs = i + tl.arange(0, BLOCK_OUT)
        mask = offs < N
        ids = tl.load(flat_ptr + offs, mask=mask, other=0)  # expert ids
        # For each element in the tile, compute its stable position
        # pos = le_counts[ids] - (1 if lt_counts[ids] > 0 else 0)
        for j in range(BLOCK_OUT):
            idx = i + j
            m = idx < N
            if m:
                idv = tl.load(flat_ptr + idx)  # scalar id
                lev = tl.load(le_counts_ptr + idv)  # scalar int32
                ltv = tl.load(lt_counts_ptr + idv)  # scalar int32
                duplicates = 1 if (ltv > 0) else 0  # scalar 0/1
                pos = lev - duplicates
                tl.store(out_ptr + idx, pos)
        i += BLOCK_OUT

Key insight for performance and correctness:
- torch.argsort(flat, stable=True) on this data distribution is equivalent to a counting-based stable sort:
  1) counts[k] = number of elements equal to k.
  2) le_counts[k] = inclusive prefix sum up to k: le_counts[i] = sum_{j<=i} counts[j].
  3) lt_counts[k] = le_counts[k] - counts[k] = number of elements strictly less than k.
  4) For each element i with id=k, its stable position is pos = le_counts[k] - (1 if lt_counts[k] > 0 else 0). This enforces stable tie-breaking by original index.
- torch.bincount(flat).cumsum(0) gives per-expert offsets. We can compute offsets via an inclusive prefix sum of counts. Since num_experts is small (256), a simple Python loop to accumulate is acceptable and avoids torch.cumsum (which is disallowed).

Plan:
1) count_experts_kernel: one Triton program loops over the flattened array in tiles, loads values, and increments counts_ptr[id] for each valid element. No atomics, only masked loads and scalar increments.
2) prefix_sum_kernel: single-program sequential inclusive scan of counts to produce le_counts (length NUM_EXPERTS). Then lt_counts = le_counts - counts.
3) compute_out_pos_real: one Triton program loops over the flattened array in tiles, loads ids, computes pos using le_counts and lt_counts, and writes to out.

    """
    Compute counts of each expert id in flat_ptr[0..N-1] into counts_ptr[0..NUM_EXPERTS-1].
    No atomics used. One program iterates over tiles of size BLOCK_COUNT and increments counts_ptr[id] for each element.
    """

    while i < N:
        # Process BLOCK_COUNT elements at a time
        for j in range(BLOCK_COUNT):
            idx = i + j

                tl.store(counts_ptr + idv, curr + 1)
        i += BLOCK_COUNT

        val = tl.load(counts_ptr + i)
        carry += val
