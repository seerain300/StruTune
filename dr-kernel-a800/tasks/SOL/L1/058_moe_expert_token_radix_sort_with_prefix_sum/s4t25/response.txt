Detailed analysis
- Original PyTorch logic:
  - Flattens topk_idx, computes a stable sort to get sorted_token_indices (the permutation that sorts by value).
  - Computes expert_offsets as the inclusive prefix sum of counts = torch.bincount(flat.long(), minlength=num_experts). This partitions tokens among experts.
- Our Triton approach:
  - Kernel 1: Histogram kernel that counts occurrences of each expert id per block, then atomically accumulates counts per bin. This avoids one atomic per element and reduces contention.
  - Kernel 2: Inclusive prefix-sum kernel to produce expert_offsets from counts. This ensures all computation is in Triton and avoids using .cumsum on the host.

Design of the Triton histogram kernel
- Inputs: flat (1D tensor of length N, int32), N, num_experts (constexpr), counts_ptr (int32).
- Launch: grid = (ceil_div(N, BLOCK),) where BLOCK is a tunable tile (e.g., 1024).
- For each program (block of BLOCK elements):
  - Load a vector of BLOCK indices.
  - For each expert id e in [0, num_experts), compute matches = (indices == e), sum them into an int32 count, and perform tl.atomic_add(counts[e], count). This yields counts[e] = number of occurrences of expert id e across all elements.
- This design reduces atomics to BLOCK * num_experts per launch, which is efficient and avoids per-element atomics.

Design of the Triton prefix-sum kernel (inclusive)
- Inputs: counts (int32 of length num_experts), out_ptr (int32 of length num_experts+1).
- Launch: grid = (1,) since num_experts is small (256), and the array is tiny.
- Compute inclusive scan:
  - For i from 0 to num_experts:
    - if i == 0: out[0] = 0
    - else: out[i] = out[i-1] + counts[i-1]
  - This is a simple single-pass loop inside the kernel, storing the cumulative sum at out[i+1] for i >= 0. Triton supports such loops over constexpr bounds.

import torch
import triton
import triton.language as tl


# Triton kernel: histogram of expert ids across a 1D flat array
@triton.jit
def _histogram_experts_kernel(
    flat_ptr,              # *int32, flattened indices
    N,                     # int32, number of elements
    counts_ptr,            # *int32, output counts per expert (length = num_experts)
    num_experts: tl.constexpr,  # compile-time constant for loop unrolling
    BLOCK: tl.constexpr,        # tile size (e.g., 1024)
):
    pid = tl.program_id(0)
    block_start = pid * BLOCK
    offsets = block_start + tl.arange(0, BLOCK)
    mask = offsets < N

    # Load a block of indices; masked loads use 0 for out-of-range, but mask avoids out-of-bounds access
    idx = tl.load(flat_ptr + offsets, mask=mask, other=0)

    # For each expert bin, count matches and atomically accumulate into counts_ptr[e]
    for e in range(0, num_experts):
        matches = (idx == e)
        # Convert boolean vector to int32, then reduce to a scalar
        matches_i32 = tl.where(matches, 1, 0)
        count = tl.sum(matches_i32, axis=0)  # reduce vector to scalar
        # Accumulate into global counts for this bin
        tl.atomic_add(counts_ptr + e, count)


# Triton kernel: inclusive prefix sum to produce expert_offsets
@triton.jit
def _inclusive_prefix_sum_kernel(
    counts_ptr,      # *int32, input counts (length = num_experts)
    out_ptr,         # *int32, output offsets (length = num_experts + 1)
    num_experts: tl.constexpr,
):
    # Single program computes the inclusive prefix sum
    running = 0
    # out[i+1] = sum of counts[0..i]
    for i in range(0, num_experts):
        running += tl.load(counts_ptr + i)
        tl.store(out_ptr + (i + 1), running)
    # out[0] should be 0 (implicit since we start running at 0)

        topk_idx = args[0]

        topk_idx = topk_idx.contiguous()

性能優化與 Triton 設計
- torch.bincount 非常高效，但我們用 Triton 實現 histogram 以減少 CPU/GPU 數據傳輸和內核調用的開銷：
  - Histogram kernel: grid = (ceil_div(N, BLOCK),)。每個 program 处理 BLOCK 大小的向量，計算每個專家 bin 的匹配數，並執行一次 atomic_add 到全局 counts[e]。這樣只需要 BLOCK * num_experts 個原子操作，而非 N 個，顯著減少競爭並提高性能。
- Prefix sum: 用一個單程序 Triton kernel 計算 inclusive prefix sum 生成 expert_offsets。num_experts=256
