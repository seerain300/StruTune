Rationale, diagnosis, and plan

What the original PyTorch code computes:
- Input: topk_idx with shape (batch_size, seq_len, num_experts_per_tok), dtype int32, values in [0, num_experts-1] and num_experts=256 in the harness.
- Forward:
  - Flatten flat = topk_idx.reshape(-1) into a 1D int32 vector of length M.
  - sorted_token_indices = torch.sort(flat, stable=True).values: a stable permutation of [0..M-1] ordered by the values in flat (for ties, original order is preserved).
  - expert_offsets = torch.bincount(flat).cumsum(0) + 1: inclusive prefix counts per expert id across tokens, plus 1 at the end, resulting in a tensor of length num_experts + 1.

Why previous attempts failed:
- “decoy kernel” and “host code uses tensor compute” warnings indicate that not all Triton kernels were actually doing useful work (either not launched or not used), and torch.sort or torch.bincount/cumsum were used in forward (host side). The evaluation expects ModelNew.forward to launch Triton kernels and perform all computations on the device, not on the host.
- “INCORRECT_NUMERICAL” means our computed results didn’t match the PyTorch reference. The likely culprits:
  - Misinterpreting what to sort. We must sort by the flattened int values, not by indices or other metadata.
  - Incorrect handling of stable ties (equal values) by original index. We must ensure tie_count is computed correctly and base_excl uses inclusive prefix sums correctly.

Fix strategy:
- Implement all heavy computations in Triton kernels and launch them from ModelNew.forward:
  1) counts_and_bases_kernel:
     - For each key k in [0..NUM_EXPERTS), compute count_k = number of occurrences of k in flat. Then write inclusive prefix sums offsets_incl[k] = sum(counts[0..k]) for k in 0..NUM_EXPERTS-1.
     - Also write total_count to a device scalar total_count_ptr so we can finalize expert_offsets.
     - This kernel must be launched and used to compute base_excl for the stable permutation.
  2) stable_permutation_kernel:
     - Produce sorted_token_indices via a stable ranking:
       - For each j in [0..M), load val_j = flat[j].
       - base_excl = offsets_incl[val_j - 1] if val_j > 0 else 0.
       - tie_count = number of previous indices t < j with same key and flat[t] < flat[j]. This ensures stable tie-breaking by original index.
       - rank = base_excl + tie_count. Write sorted_token_indices[j] = rank.
     - This kernel must be launched and do the actual sorting (stable), replacing torch.sort on the host.
  3) finalize_offsets_kernel:
     - Read offsets_incl and total_count and produce expert_offsets of length NUM_EXPERTS + 1:
       - offsets[:NUM_EXPERTS] = offsets_incl[:]
       - offsets[NUM_EXPERTS] = total_count + 1
     - This replaces torch.bincount + cumsum on the host.

Important considerations:
- Triton kernels must avoid dynamic for-loops over runtime sizes; instead, tile with vectors and use reduction (tl.sum). The permutation kernel computes tie_count by scanning flat in chunks and performing a vectorized comparison between each j and all earlier elements in chunks. This is a standard stable sort technique for small integer keys.
- Ensure dtypes are int32 throughout (flat is int32). We return torch.int32 tensors for sorted_token_indices and expert_offsets (matching the original). sorted_token_indices must be a permutation of [0..M-1] in increasing order by flat values (stable).
- Launch all kernels: counts_and_bases_kernel, stable_permutation_kernel, finalize_offsets_kernel. No torch.sort or torch.bincount on the host. Only allocations and Triton launches are allowed.

@triton.jit
def finalize_offsets_kernel(
    offsets_incl_ptr,         # *int32, length NUM_EXPERTS (counts per key)
    total_count_ptr,          # *int32, scalar total count
    offsets_ptr,              # *int32, output length NUM_EXPERTS + 1

):
    # Compute inclusive prefix sums for offsets_incl and write to offsets_ptr[0:NUM_EXPERTS]
    # We also write total_count + 1 at the end.
    running = tl.zeros((), dtype=tl.int32)
    for i in range(0, NUM_EXPERTS):
        cnt = tl.load(offsets_incl_ptr + i)
        running += cnt
        tl.store(offsets_ptr + i, running)
    total = tl.load(total_count_ptr)
    tl.store(offsets_ptr + NUM_EXPERTS, total + 1)
