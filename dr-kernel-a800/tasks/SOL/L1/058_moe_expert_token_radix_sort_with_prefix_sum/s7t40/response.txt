For each original[i], compute the number of elements less than v, then place i at position number_of_less + number of equal elements before i, using a deterministic tie-break (original position). This reproduces torch.sort(stable=True).indices without torch.sort.

- Key details:
  - Flatten topk_idx to original_flat, ensure int32 and contiguous.
  - histogram_kernel: Each program processes a single element (no vectors), loads original[i], and atomically increments counts[original[i]]. This avoids any vectorized atomics or reductions.
  - assign_stable_positions_kernel: Two nested loops. Outer loop over v in [0..255] (constexpr), inner loop over i from M-1 down to 0 in chunks of BLOCK (scalar idx per lane). We compute number_of_less by summing counts[k] for k < v. Then for each lane, if original[i] == v, place i at pos = number_of_less + number_of_equal_before_i, where number_of_equal_before_i is the number of elements before i with original[j] == v. We track used positions via a per-lane mask to avoid duplicate writes within the block.

- This design minimizes Triton runtime complexity: scalar loads, scalar atomics, and simple integer arithmetic. It should be compatible with Triton in the evaluation environment and produce the same outputs as the original PyTorch code.
