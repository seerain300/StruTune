任务回顾
- Input: topk_idx shape (batch_size, seq_len, num_experts_per_tok), dtype int32, values in [0, num_experts). In provided workloads, num_experts = 256.
- Original run:
  - Flatten flat = topk_idx.reshape(-1), length N = batch_size*seq_len*num_experts_per_tok.
  - sorted_token_indices = torch.sort(flat, stable=True).indices (length N), stable ordering by value; ties broken by original index.
  - expert_offsets = [0] + cumsum(bincount(flat)) (length num_experts + 1), prefix sums per expert.

挑战
- Triton 不提供内置的 stable sort 和 cumsum. 但是专家数量固定为 256 (compile-time constexpr), 我们可以设计核函数来实现所需的数据操作.

方案
- 我们需要生成两个输出：
  1) sorted_token_indices (N-length tensor): 这需要全局稳定排序算法。我们可以将 stable 排序分解为 ranks[i] = number of j with flat[j] < flat[i] + number of j with flat[j] == flat[i] and j < i. 这样对于相等的值会按原始索引递增排序，满足 stable=True. 接着使用 iterative selection (repeatedly choosing min rank with tie-breaking by smallest index) 来生成 sorted indices.
  2) expert_offsets (num_experts+1-length tensor): 专家计数 bincount 以及全局 prefix sum 可以在 Triton 中实现.

具体步骤
1) Triton kernel: count_experts_kernel
   - 对 vals_ptr[0..N-1] 进行全局 bincount，对于每个 token i, 如果 vals[i] == e, counts[e] += 1. 由于 num_experts=256, 循环实现 atomic_add 是可行的。

2) Triton kernel: less_counts_kernel
   - 计算 less[i] = sum over v < vals[i] of counts[v]. 由于 num_experts=256, 我们可以循环 v in [0..255] and accumulate counts[v] into an int32 less[i].

3) Triton kernel: tie_counts_kernel
   - 计算 tie[i] = counts[vals[i]]. Loop over e in [0..255] and accumulate 1 when e == vals[i]. This produces tie per token.

4) Triton kernel: stable_sort_and_write_kernel
   - Iteratively select tokens by scanning ranks. In each iteration:
     - Compute minimal rank across all tokens.
     - Among tokens with this minimal rank, choose the smallest index (stable tie-breaker).
     - Mark the selected token as used (set its rank to N+1) and store its original index to the output array.
     - Repeat N times.
   - This kernel must be launched from forward and use less_ptr and tie_ptr (both Triton-computed) to determine ranks.

5) Triton kernel: scan_prefix_sum_inclusive_kernel
   - Compute inclusive prefix sum of counts across all elements. We need global prefix sum, so we use a two-pass scan approach. However, in our case, we only need global prefix sum of the 256-element counts array, which is small. A simple vector-based scan is acceptable. If needed, we can implement a block-based inclusive scan and then combine with carry; but given num_experts=256, a straightforward vector inclusive scan suffices. The current kernel reads counts_ptr and writes prefix sums into offsets_ptr.

6) Triton kernel: write_expert_offsets_kernel
   - Write offsets[0] = 0 and offsets[1..num_experts] = inclusive_scan(counts). We use scan_prefix_sum_inclusive_kernel to fill offsets[1:], leaving offsets[0] as zero. Then we return offsets.

- Allocate counts = torch.zeros(256, dtype=torch.int32, device=vals.device).

- Launch less_counts_kernel(vals_ptr, counts_ptr, less_ptr, N, 256).
