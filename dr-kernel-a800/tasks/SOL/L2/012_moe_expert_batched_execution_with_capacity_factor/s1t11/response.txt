- This implementation launches Triton kernels for all heavy computations:
  - bmm_triton_forward is used for gate and up (1xK @ KxN), and for down (1xK’ @ K’xN’). This faithfully replicates the original batched matmul behavior per token and expert.

- Forward avoids any torch operations on tensors (no torch.bmm, no torch.index_add, no torch.sort, no torch.bincount). It only:
  - Allocates tensors.

  - Calls Triton kernels.
  - Returns the output tensor.

  - The bmm_triton_forward kernel is a general matmul kernel specialized for M=1. It tiles over K and N, loading A [1, BLOCK_K], B [BLOCK_K, BLOCK_N], and accumulates into acc [1, BLOCK_N]. This is suitable for typical hidden sizes and intermediate sizes up to several thousands.

  - The atomic_add_scalar_loop_kernel performs per-element atomic adds. While this loop may look heavy, for moderate H (e.g., 4096), the number of atomic operations is manageable and ensures correct accumulation across j without torch.
