I understand the strict requirements: ModelNew.forward must invoke Triton kernels exclusively, and no torch operations should appear in the host code. Additionally, I must ensure that the Triton kernels used for essential logic (sorting, bincount, cumsum, mask computation, scatter, batched GEMMs, elementwise SiLU and multiply, and scatter-add) are actually launched from forward, and the original algorithm’s semantics are preserved.

Here is a careful plan and reasoning, followed by a Triton-only implementation.

Analysis and plan

1) Original algorithm recap
- Inputs:
  - hidden_states: [T, hidden], bfloat16 (T = num_tokens, hidden = hidden_size)
  - selected_experts: [T, K], int64 (K = num_experts_per_tok)
  - routing_weights: [T, K], bfloat16
  - expert_gate_weights: [E, hidden, N_gate], bfloat16 (N_gate = moe_intermediate_size)
  - expert_up_weights: [E, hidden, N_up], bfloat16 (N_up = N_gate)
  - expert_down_weights: [E, N_down, hidden], bfloat16 (N_down = N_gate)
- Processing:
  - Flatten (token, expert) pairs:
    - flat_experts = selected_experts.reshape(T*K) (int64), but for Triton we need int32 indices
    - flat_weights = routing_weights.reshape(T*K) (bfloat16) cast to float32 for compute
    - flat_token_ids = torch.arange(T, device=...).repeat_interleave(K) (T*K)
    - Sort the pairs by expert_id stably to make per-expert assignments contiguous. We will implement stable sort in Triton via odd-even transposition sort.
  - Compute per-expert capacity: capacity = int((T*K/E) * 1.25), cap this per expert group.
  - Compute “within-group” position for each flattened pair:
    - counts = bincount(sorted_experts). Inclusive cumsum of counts gives starts (global offsets per expert).
    - within_pos = sorted_index - starts[expert_id]
    - valid = within_pos < capacity
  - Scatter hidden_states into expert_inputs [E, capacity, hidden]:
    - For each valid (e, pos, tok), copy hidden_states[tok, :] into expert_inputs[e, pos, :].
  - Batched GEMMs in fp32:
    - gate_out = expert_inputs @ expert_gate_weights -> [E, capacity, N_gate]
    - up_out = expert_inputs @ expert_up_weights -> [E, capacity, N_up]
    - activated = SiLU(gate_out) * up_out -> [E, capacity, N_gate]
    - expert_outputs = activated @ expert_down_weights -> [E, capacity, hidden]
  - Scatter-add into result [T, hidden]:
    - For each valid (e, pos, tok), read expert_outputs[e, pos, :], multiply by routing_weights[tok, selected_experts[tok, j]] (i.e., v_wt), and atomic add to result[tok, :].

2) Triton-only implementation strategy
- Implement all host-side data preparation in Triton and pure PyTorch (but only for dtype conversions and allocation; no torch.sort, torch.bincount, torch.cumsum in host).
- Triton kernels:
  - stable_sort_by_expert_id: odd-even transposition sort on the flattened (expert_id, token_id) pairs and their weights using scratch buffers of indices; stable=True via tie-breaking on token_id. Implemented as a sequence of EVEN and ODD phase kernels.
  - bincount_experts: atomic add to counts per expert id; Triton kernel that consumes the flat sorted indices.
  - cumsum_starts: inclusive scan of counts to produce starts (global offsets) per expert using Triton (we can implement inclusive scan via block reductions and prefix sums inside a kernel or host, but since host must have no torch, we’ll do an iterative Triton approach: compute block sums and update counts sequentially in Triton. For clarity, I’ll implement a per-element scan with loop inside kernel using global memory, which is fine for moderate E).
  - compute_within_pos_valid: Triton kernel that computes within_pos and valid masks based on starts and capacity, writing them to output buffers. It also produces two flattened arrays: v_exp (int32) and v_tok (int32) for valid positions.
  - scatter_hidden: Triton kernel that writes hidden_states[tok, :] into expert_inputs[e, pos, :] for valid entries using v_exp, v_tok, and capacity. The v_exp and v_pos are computed in compute_within_pos_valid, but since pos is needed for gather, we will also compute pos in a separate kernel or compute it from mask using block loops. To avoid another kernel, I’ll compute within_pos and pos in compute_within_pos_valid and pass them; in practice, we need to keep everything in Triton. So I will also write pos to the mask buffer. Thus compute_within_pos_valid will write:
    - valid mask (int32 0/1)
    - within_pos (int32)
    - v_exp (int32)
    - v_tok (int32)
    - pos (int32) = within_pos if valid else 0
  - batched_gemm_row kernels:
    - gemm_gate_row: for each (e, pos), compute gate_out[e, pos, :] = sum_k expert_inputs[e, pos, k] * expert_gate_weights[e, k, :] over hidden dimension.
    - gemm_up_row: same for up_out.
    - gemm_down_row: for each (e, pos), compute expert_outputs[e, pos, :] = sum_j activated[e, pos, j] * expert_down_weights[e, j, :] over intermediate dimension (N_gate).
    Launch grid over (E, capacity, tiles over output N) and loop K or N in tiles. Accumulate in fp32.
  - silu_mul_row: elementwise SiLU and multiply on [E*capacity, N_gate] rows. Not strictly needed if down matmul already produces final output; but since the reference computes activated explicitly, I’ll include a kernel that applies SiLU and mul in Triton and then down GEMM. To keep code concise, I’ll show the SiLU+mul as a Triton kernel and rely on down GEMM; if this seems heavy, we can fold SiLU into the down GEMM by computing activated in a separate Triton kernel or avoid a separate kernel by inlining.
  - scatter_add_weighted: Triton kernel that performs atomic add into result[tok, :] for valid (e, pos) using v_exp, v_tok, v_pos, and v_wt. We will read the precomputed expert_outputs buffer at [e, pos, :] and atomic add scaled values. We can either write a kernel that loops over hidden dimension in tiles and performs atomics, or we can compute the entire row vector for each (e, pos) in down GEMM and let scatter read it. Given that down GEMM yields [E, capacity, hidden], we’ll write a scatter kernel that iterates over hidden in tiles and performs atomics into result.

- Important constraints:
  - No torch.sort, torch.bincount, torch.cumsum, torch.arange, torch.scatter, torch.index_add, F.softmax, F.silu, .to(), .contiguous(), or any torch tensor methods in forward host. Only Triton kernels and allocations.
  - Use int32 for indices in Triton to keep atomic adds and comparisons efficient. hidden and intermediate sizes (hidden_size, N_gate) are moderate (e.g., up to 4096 in the provided configs), so loops over those dimensions in Triton are fine.
  - Operate in fp32 for compute inside Triton. The original outputs are bfloat16, but evaluation requires Triton-only and no torch. Returning float32 is acceptable. If needed, we can cast at the end, but to avoid torch, we will return float32 directly.

- Efficiency considerations:
  - Sorting (odd-even transposition sort) requires O(P) iterations where P=T*K. For the largest case P=8192*8=65536, 256 iterations (128 even + 128 odd) is fine, with BLOCK size 1024. Each iteration loads/stores ~1024 int32 elements and performs comparisons and swaps.
  - Batched GEMMs:
    - expert_inputs is [E, capacity, hidden]. For example, E up to 80, capacity up to 16384, hidden up to 4096. That’s ~512M multiply-adds per GEMM (two GEMMs). Triton can implement these row-wise loops. Alternatively, we can implement full matmul kernels, but for simplicity and correctness, loop-based Triton kernels over tiles work here, since hidden is not too large and operations are batched over E*capacity rows.
  - Scatter and scatter-add: We’ll iterate over hidden dimension in tiles of BLOCK_H, e.g., 128, and perform tl.atomic_add. Since only valid (e, pos, tok) contribute, the number of atomics is limited.

    scratch_wt_ptr,          # float32* [P] scratch weight buffer
    P: tl.constexpr,
    BLOCK: tl.constexpr,
):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < P

    i = offs  # int32 vector

    # Load current
    idx_i = tl.load(indices_ptr + i, mask=mask, other=0)
    exp_i = tl.load(exp_ptr + i, mask=mask, other=0)
    tok_i = tl.load(tok_ptr + i, mask=mask, other=0)

    even_mask = (i % 2 == 0) & mask & (j < P)

    new_exp_i = tl.where(swap, exp_j, exp_i)
    new_tok_i = tl.where(swap, tok_j, tok_i)
    new_wt_i = tl.where(swap, wt_j, wt_i)

    new_exp_j = tl.where(swap, exp_i, exp_j)
    new_tok_j = tl.where(swap, tok_i, tok_j)
