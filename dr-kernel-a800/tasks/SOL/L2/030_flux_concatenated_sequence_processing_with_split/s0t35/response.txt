Analysis and plan

Recap of the original computation
- Inputs:
  - hidden_states: shape [B, L_img, D]
  - encoder_hidden_states: shape [B, L_txt, D]
  - process_weight: shape [D, D]
- Operations:
  1) Concatenate along the sequence dimension:
     concatenated = [encoder_hidden_states, hidden_states] → [B, M, D], M = L_txt + L_img.
  2) Linear projection: processed = concatenated @ process_weight.T → [B, M, D].
  3) Split outputs: processed_encoder = processed[:, :L_txt, :], processed_hidden = processed[:, L_txt:, :].

Status so far
- Implementing the GEMM (matmul) in Triton has been fragile across all tested configurations, leading to “INCORRECT_NUMERICAL” and “RUNTIME_ERROR.” Specifically, 2 workloads out of 16 failed despite 14 passing earlier.
- Using torch.matmul for matmul was correct for 14/16, but the evaluator requires that all numeric computation be done by Triton kernels in ModelNew.forward. We still need to ensure all operations are Triton-invoked.

Strategy to ensure correctness and satisfy Triton-only requirement
- We will implement the matmul in Triton using a robust 1D program-per-row approach:
  - Treat each output element c[b, m, n] = sum_k a_concat[b, m, k] * W[k, n], with a_concat = [encoder_hidden_states, hidden_states].
  - Launch one Triton program per output row (flattened over b and m). Each program loops over n and k, accumulates into a float32 accumulator, and writes the result to output. This avoids tricky 2D tiling and makes indexing simple and robust.
  - We will pre-permute process_weight to [D, M] and treat it as a 1D vector per n, since we iterate n linearly. Although the typical GEMM formulation uses W[k, n], with our iteration order we can load W as contiguous per n and loop k. This keeps pointer arithmetic simple.
  - We will handle dtype: compute in float32 for numerical stability, then cast back to the original dtype at the end. This is acceptable as it is performed by Triton math (scalar ops) and not host-side tensor math.
- Implement Triton kernels for:
  - Concatenation: dst[b, t, :] = src1[b, t, :] if t < L_txt else src2[b, t - L_txt, :].
  - Splitting: copy processed[:, :L_txt, :] to processed_encoder and processed[:, L_txt:, :] to processed_hidden.

Performance considerations
- The matmul is the dominant cost; a naive 1D per-row kernel won’t beat torch.matmul in general, but it ensures correctness and avoids further Triton matmul pitfalls. Once correctness is solid, we can consider tiling improvements if needed.
- Concatenation and splitting are simple, so Triton kernels for them are lightweight.

Edge cases and safety
- We allocate output tensors explicitly with the correct shape and dtype before launching kernels.
- We use stride-based pointer arithmetic and masks where needed to avoid illegal memory access, especially since some dimensions might not be multiples of block sizes.
- We ensure the output dtype matches the input dtypes (the original uses default float32; we’ll keep float32 for simplicity and correctness).

    # Triton only supports 1D/2D grid; 3D not possible. We'll implement a per-(b, m, n) kernel with while loops.

    # We'll use a conservative approach: one program per (b, m) and loop over n in blocks. But Triton grid is fixed.
    # The robust approach is to have one program per (b, m, n) by using grid=(B, 1, 1) and computing m,n via math.
    # However, Triton doesn't expose m,n from grid; we'll set grid=(B, M, N) by passing them as tl.constexpr.
    # Since Triton kernels require compile-time shapes for grid, we can't do that. Therefore, we'll implement
    # a per-(b, m) program that loops over n and accumulates.

    # Let's set up program ids for b and m; Triton supports up to 3D grid. We'll use (B, M, 1) and decode:
    pid_b = tl.program_id(0)
    pid_m = tl.program_id(1)
    # n we will iterate in a constexpr loop with BLOCK_N; since Triton needs static loops, we choose BLOCK_N=128.
    BLOCK_N = 128
    # We'll iterate over n in chunks of BLOCK_N and accumulate.

    # Prepare accumulators for a block of N
    n_start = 0
    while n_start < D:
        n_offsets = n_start + tl.arange(0, BLOCK_N)
        # Mask for valid n
        mask_n = n_offsets < D

        # Initialize accumulator for this block
        acc = tl.zeros((BLOCK_N,), dtype=tl.float32)

        # Loop over K (D) in chunks
        K_BLOCK = 32  # constexpr block for k
        k_start = 0
        while k_start < D:
            k_offsets = k_start + tl.arange(0, K_BLOCK)
            mask_k = k_offsets < D

            # Load a_k: A[b, m, k_offsets]
            a_ptrs = srcA_ptr + pid_b * srcA_stride_b + pid_m * srcA_stride_s + k_offsets * srcA_stride_d

# Triton GEMM for concatenated A @ W.T into C
@triton.jit
def cat_gemm_kernel(
    A_ptr, W_ptr, C_ptr,
    B, L_txt, L_img, D, M,
    A_stride_b, A_stride_s, A_stride_d,
    W_stride_k, W_stride_n,
    C_stride_b, C_stride_s, C_stride_d,
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
):
    # Use a 3D grid: (B, tiles over M, tiles over N)
    pid_b = tl.program_id(0)
    pid_m = tl.program_id(1)
    pid_n = tl.program_id(2)

    m_start = pid_m * BLOCK_M
    n_start = pid_n * BLOCK_N

    m_offsets = m_start + tl.arange(0, BLOCK_M)
    n_offsets = n_start + tl.arange(0, BLOCK_N)

    # Accumulator
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    k = 0
    while k < D:
        k_offsets = k + tl.arange(0, BLOCK_K)
        mask_k = k_offsets < D

        # Load A[b, m, k] -> shape (BLOCK_M, BLOCK_K)
        a_ptrs = A_ptr + pid_b * A_stride_b + m_offsets[:, None] * A_stride_s + k_offsets[None, :] * A_stride_d
        a = tl.load(a_ptrs, mask=(m_offsets[:, None] < (L_txt + L_img)) & mask_k[None, :], other=0.0)

        # Load W[k, n] -> shape (BLOCK_K, BLOCK_N)
        w_ptrs = W_ptr + k_offsets[:, None] * W_stride_k + n_offsets[None, :] * W_stride_n
        w = tl.load(w_ptrs, mask=mask_k[:, None] & (n_offsets[None, :] < D), other=0.0)

        # Accumulate
        acc += tl.dot(a, w)

        k += BLOCK_K

    # Store C[b, m, n]
    c_ptrs = C_ptr + pid_b * C_stride_b + m_offsets[:, None] * C_stride_s + n_offsets[None, :] * C_stride_d
    mask_m = m_offsets[:, None] < (L_txt + L_img)
    mask_n = n_offsets[None, :] < D
    tl.store(c_ptrs, acc, mask=mask_m & mask_n)

class ModelNew(torch.nn.Module):
    def forward(self, hidden_states, encoder_hidden_states, process_weight):
        """
        hidden_states: [B, L_img, D]
        encoder_hidden_states: [B, L_txt, D]
        process_weight: [D, D]
        returns: (processed_encoder: [B, L_txt, D], processed_hidden: [B, L_img, D])
        """
        assert hidden_states.is_cuda and encoder_hidden_states.is_cuda and process_weight.is_cuda, "All inputs must be CUDA tensors"
        B = hidden_states.shape[0]
        L_img = hidden_states.shape[1]
        L_txt = encoder_hidden_states.shape[1]
        D = hidden_states.shape[2]
        M = L_txt + L_img

        # 1) Concatenate along sequence into A_cat: [B, M, D]
        A_cat = torch.empty((B, M, D), device=hidden_states.device, dtype=hidden_states.dtype)
        # Launch Triton concat kernel: grid=(B, M)
        grid_concat = (B, M)
        concat_cat_kernel[grid_concat](
            encoder_hidden_states, hidden_states, A_cat,
            B, L_txt, L_img, D,
            encoder_hidden_states.stride(0), encoder_hidden_states.stride(1), encoder_hidden_states.stride(2),
            hidden_states.stride(0), hidden_states.stride(1), hidden_states.stride(2),
            A_cat.stride(0), A_cat.stride(1), A_cat.stride(2),
            num_warps=1, num_stages=2
        )

        # 2) Linear projection: C = A_cat @ process_weight.T
        # Triton GEMM with tiling: choose blocks
        BLOCK_M = 64
        BLOCK_N = 64
        BLOCK_K = 32
        C = torch.empty((B, M, D), device=hidden_states.device, dtype=hidden_states.dtype)
        grid_gemm = (B, triton.cdiv(M, BLOCK_M), triton.cdiv(D, BLOCK_N))
        cat_gemm_kernel[grid_gemm](
            A_cat, process_weight, C,
            B, L_txt, L_img, D, M,
            A_cat.stride(0), A_cat.stride(1), A_cat.stride(2),
            process_weight.stride(0), process_weight.stride(1),
            C.stride(0), C.stride(1), C.stride(2),
            BLOCK_M=BLOCK_M, BLOCK_N=BLOCK_N, BLOCK_K=BLOCK_K,
            num_warps=4, num_stages=2
        )

        # 3) Split into encoder and hidden parts
        processed_encoder = torch.empty((B, L_txt, D), device=hidden_states.device, dtype=hidden_states.dtype)
        processed_hidden = torch.empty((B, L_img, D), device=hidden_states.device, dtype=hidden_states.dtype)

        # Launch Triton split kernels
        # For encoder: copy C[:, :L_txt, :]
        grid_encoder = (B, L_txt)
        copy_encoder_part_kernel[grid_encoder](
            C, processed_encoder,
            B, L_txt, D,
            C.stride(0), C.stride(1), C.stride(2),
            processed_encoder.stride(0), processed_encoder.stride(1), processed_encoder.stride(2),
            num_warps=1, num_stages=1
        )

        # For hidden: copy C[:, L_txt:, :]
        grid_hidden = (B, L_img)
        copy_hidden_part_kernel[grid_hidden](
            C, processed_hidden,
            B, L_img, D,

            processed_hidden.stride(0), processed_hidden.stride(1), processed_hidden.stride(2),
            num_warps=1, num_stages=1
        )

        return processed_encoder, processed_hidden
