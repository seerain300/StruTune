Careful analysis, diagnosis, and plan

1) Original PyTorch behavior
- Inputs:
  - encoder_hidden_states: [B, T, H]
  - hidden_states: [B, I, H]
  - process_weight: [H, H], no bias
- Steps:
  - Concatenate along sequence dimension: A_cat = torch.cat([encoder_hidden_states, hidden_states], dim=1) -> [B, L, H], with L = T + I
  - Linear projection: processed = A_cat @ process_weight.T -> [B, L, H]
  - Split: processed_encoder = processed[:, :T, :], processed_hidden = processed[:, T:, :]

2) Why earlier submissions failed
- The evaluation reports showed “INCORRECT_SHAPE” for three workloads. That points to tensor shape mismatches at output (e.g., wrong output tensor sizes), not numerical differences. It’s unlikely that the heavy matmul would fail consistently with shape mismatch, but it can happen if:
  - The Triton kernels wrote into buffers of incorrect shape (e.g., output allocated as [B, T, H] instead of [B, L, H]).
  - The grid or tiling logic didn’t cover the entire output space, leaving some dimensions incorrect.
- We must ensure:
  - Concatenation output has exact shape [B, L, H].
  - Matmul output has exact shape [B, L, H].
  - The split returns [B, T, H] for processed_encoder and [B, I, H] for processed_hidden. This is easy: split is correct if the matmul result is [B, L, H].

3) Optimization and correctness strategy
- Implement both steps in Triton to satisfy the “TRITON-ONLY” requirement:
  - Triton kernel to perform concatenation directly into an output tensor out_cat of shape [B, L, H], writing from encoder for the first T rows and hidden for the remaining I rows.
  - Triton batched GEMM kernel computing C[b, m, n] = sum_k out_cat[b, m, k] * process_weight.T[k, n], with W_T shape [H, H].
- Make the Triton GEMM robust:
  - 3D grid over (batch, sequence tiles, output tiles), iterate reduction dimension K in blocks (BLOCK_K).
  - Use masks to handle non-multiples and ensure no out-of-bounds loads/stores.
  - Pass strides from tensors to kernels so we can operate on any contiguous layout. Ensure inputs are contiguous before launching Triton.

4) Performance considerations
- The GEMM is the heavy work. The concat is a data movement step, but we still perform it in Triton to avoid torch.cat. Performance-wise, concat is cheap compared to GEMM, but ensuring the Triton GEMM is correct and robust is key.
- We can try different tile sizes (BLOCK_M/BLOCK_N/BLOCK_K) and num_warps/num_stages; however, correctness is priority. Once we have correctness, we can tune for speed.

import torch
import triton
import triton.language as tl


@triton.jit
def concat_seq_kernel(
    encoder_ptr, hidden_ptr, out_ptr,
    B: tl.constexpr, T: tl.constexpr, I: tl.constexpr, H: tl.constexpr,
    stride_e_b, stride_e_t, stride_e_h,
    stride_h_b, stride_h_i, stride_h_h,
    stride_o_b, stride_o_l, stride_o_h,
    BLOCK_H: tl.constexpr,
):
    # Grid: (B, L, ceil(H/BLOCK_H))
    b = tl.program_id(0)
    l = tl.program_id(1)
    tile_k = tl.program_id(2)

    k_offsets = tile_k * BLOCK_H + tl.arange(0, BLOCK_H)
    mask_k = k_offsets < H

    # Choose source based on l < T
    is_encoder = l < T

    # Compute pointers
    if is_encoder:
        src_ptr = encoder_ptr + b * stride_e_b + l * stride_e_t + k_offsets * stride_e_h
    else:
        m = l - T  # index in hidden
        src_ptr = hidden_ptr + b * stride_h_b + m * stride_h_i + k_offsets * stride_h_h

    # Output pointers
    out_ptr_k = out_ptr + b * stride_o_b + l * stride_o_l + k_offsets * stride_o_h

    # Load and store
    vals = tl.load(src_ptr, mask=mask_k, other=0.0)
    tl.store(out_ptr_k, vals, mask=mask_k)


@triton.jit
def batched_matmul_kernel(
    A_ptr, B_ptr, C_ptr,
    B, M, N, K,
    stride_A_b, stride_A_m, stride_A_k,
    stride_B_k, stride_B_n,
    stride_C_b, stride_C_m, stride_C_n,
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
):
    # Grid: (B, ceil(M/BLOCK_M), ceil(N/BLOCK_N))
    b = tl.program_id(0)
    pid_m = tl.program_id(1)
    pid_n = tl.program_id(2)

    m_offsets = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    n_offsets = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)

    # Accumulator
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # Reduction over K
    for k0 in range(0, K, BLOCK_K):
        k_offsets = k0 + tl.arange(0, BLOCK_K)

        # A[b, m, k]
        A_ptrs = A_ptr + b * stride_A_b + m_offsets[:, None] * stride_A_m + k_offsets[None, :] * stride_A_k
        A_mask = (m_offsets[:, None] < M) & (k_offsets[None, :] < K)
        a = tl.load(A_ptrs, mask=A_mask, other=0.0)

        # B[k, n]
        B_ptrs = B_ptr + k_offsets[:, None] * stride_B_k + n_offsets[None, :] * stride_B_n
        B_mask = (k_offsets[:, None] < K) & (n_offsets[None, :] < N)
        bmat = tl.load(B_ptrs, mask=B_mask, other=0.0)

        # acc += A_chunk @ B_chunk
        acc += tl.dot(a, bmat)

    # Store result
    C_ptrs = C_ptr + b * stride_C_b + m_offsets[:, None] * stride_C_m + n_offsets[None, :] * stride_C_n
    C_mask = (m_offsets[:, None] < M) & (n_offsets[None, :] < N)
    tl.store(C_ptrs, acc, mask=C_mask)


class ModelNew(torch.nn.Module):
    def forward(self, hidden_states: torch.Tensor, encoder_hidden_states: torch.Tensor, process_weight: torch.Tensor):
        """
        Triton-only implementation of:
          1) Concatenate encoder_hidden_states and hidden_states along sequence dimension
          2) Apply linear projection to the concatenated sequence
          3) Split back into separate encoder and image streams

        Returns:
          processed_encoder: [B, T, H]
          processed_hidden: [B, I, H]
        """
        assert hidden_states.dim() == 3 and encoder_hidden_states.dim() == 3, "Inputs must be 3D tensors [B, dim, H]"
        B, T, H = encoder_hidden_states.shape
        B2, I, H2 = hidden_states.shape
        assert B == B2 and H == H2, "Batch and hidden_dim must match across inputs"
        assert process_weight.shape == (H, H), "process_weight must be [H, H]"

        # Ensure contiguity
        encoder = encoder_hidden_states.contiguous()
        hidden = hidden_states.contiguous()
        weight = process_weight.contiguous()

        # 1) Concatenate into out_cat [B, L, H], L = T + I
        L = T + I
        out_cat = torch.empty((B, L, H), device=encoder.device, dtype=encoder.dtype)

        # Launch Triton concat kernel
        # Grid: (B, L, ceil(H/BLOCK_H))
        BLOCK_H = 128
        grid = (B, L, triton.cdiv(H, BLOCK_H))
        concat_seq_kernel[grid](
            encoder, hidden, out_cat,
            B, T, I, H,
            encoder.stride(0), encoder.stride(1), encoder.stride(2),
            hidden.stride(0), hidden.stride(1), hidden.stride(2),
            out_cat.stride(0), out_cat.stride(1), out_cat.stride(2),
            BLOCK_H=BLOCK_H,
            num_warps=4, num_stages=2,
        )

        # 2) Linear projection: C = out_cat @ process_weight.T  -> [B, L, H]
        WT = weight.t().contiguous()  # [H, H]
        C = torch.empty((B, L, H), device=out_cat.device, dtype=out_cat.dtype)

        # Triton batched matmul kernel
        # Grid: (B, ceil(L/BLOCK_M), ceil(H/BLOCK_N))
        BLOCK_M = 64
        BLOCK_N = 64
        BLOCK_K = 32
        grid_gemm = (B, triton.cdiv(L, BLOCK_M), triton.cdiv(H, BLOCK_N))
        batched_matmul_kernel[grid_gemm](
            out_cat, WT, C,
            B, L, H, H,  # M=L, N=H, K=H
            out_cat.stride(0), out_cat.stride(1), out_cat.stride(2),
            WT.stride(0), WT.stride(1),
            C.stride(0), C.stride(1), C.stride(2),
            BLOCK_M=BLOCK_M, BLOCK_N=BLOCK_N, BLOCK_K=BLOCK_K,
            num_warps=4, num_stages=2,
        )

        # 3) Split back into separate streams
        processed_encoder = C[:, :T, :]
        processed_hidden = C[:, T:, :]

        return processed_encoder, processed_hidden

Why this addresses the failures
- Shape mismatches: We explicitly allocate out_cat as [B, L, H] and the matmul output C as [B, L, H]. The concatenation kernel writes exactly into [B, L, H] without any ambiguity. The split uses [:T, :] and [T:, :], so the returned tensors have shapes [B, T, H] and [B, I, H], matching the original PyTorch function.
- Triton-only: All heavy computation (concat and matmul) is performed in Triton kernels. The forward does not use torch.cat or torch.matmul for the heavy work, satisfying the “TRITON-ONLY” requirement.
- Robustness: The concat kernel is straightforward and uses masks only for the last tile of H. The GEMM kernel uses 3D grid and masks for edge tiles in M, N, and K. Accumulation is in fp32 for stability; Triton will cast to the output dtype on store.

If correctness still shows issues on some workloads
- The prior “INCORRECT_NUMERICAL” cases likely stemmed from subtle dtype or reduction handling. We accumulated in fp32; Triton’s tl.dot should handle fp32 multiplication and addition. If the evaluator uses fp16 inputs and expects fp16 outputs, storing fp32 then casting on the host could introduce small differences. We currently store directly to C with out_cat’s dtype, which should match PyTorch’s dtype.
- If the environment uses bf16 or fp16, consider ensuring the kernels operate in that dtype by casting pointers accordingly. In Triton, we pass tensors of a specific dtype; the kernels will use that dtype for tl.load/tl.store. Accumulating in fp32 is typically acceptable, but if strict fp16-only is required, you can change acc initialization to tl.float16 and perform dot in that dtype. In practice, fp32 accumulation is safer numerically and typically acceptable in most environments.
