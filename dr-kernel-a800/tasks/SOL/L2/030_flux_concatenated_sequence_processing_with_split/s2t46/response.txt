What the original PyTorch code does
- Inputs:
  - encoder_hidden_states: [B, T, H]
  - hidden_states: [B, I, H]
  - process_weight: [H, H] (no bias)
- Steps:
  - Concatenate along sequence dimension: A_cat = torch.cat([encoder_hidden_states, hidden_states], dim=1) -> [B, L, H], with L = T + I
  - Linear projection: processed = A_cat @ process_weight.T -> [B, L, H]
  - Split: processed_encoder = processed[:, :T, :], processed_hidden = processed[:, T:, :]

Evaluator constraints
- “TRITON-ONLY COMPUTATION”: All numerical computation must be performed by custom @triton.jit kernels. The forward may:
  - compute shapes/strides,
  - allocate output tensors,
  - make tensors contiguous,
  - launch Triton kernels,
  - return the results.

Why our previous attempts failed
- We saw alternating failures: shape mismatches, runtime errors, and then numerical mismatches. The latest submission produced “RUNTIME_ERROR” for three workloads. Given the recent errors are runtime failures, the most likely causes are:
  - Triton kernel launch grid size mismatch (too few tiles), which can lead to missing parts of the computation. If grid is computed as (cdiv(M, BLOCK_M), cdiv(N, BLOCK_N)) but a config uses BLOCK_M or BLOCK_N not matching the grid’s assumption, some output won’t be computed, leading to incorrect or incomplete tensors. This often triggers runtime assertions or incorrect results.
  - Using Triton’s autotune with multiple BLOCK_M/N/K configs while the grid is computed against only one set of BLOCK sizes can cause under-coverage. The recommended approach is to define grid as a lambda that depends on the meta-parameters (BLOCK_M/BLOCK_N) of the selected config, ensuring the launch grid always covers all tiles for that config.
  - Dtype handling: ensure inputs to Triton are fp32 for accumulation and that stores match the expected dtype. We’ll cast inputs to float32 inside the kernel to accumulate in fp32.

Plan
- Implement both operations in Triton:
  1) Concatenation Triton kernel: produce out_cat of shape [B, L, H] by copying encoder and hidden into the first T and last I rows, respectively. This is a simple, robust 3D grid over (B, L, H).
  2) Triton batched GEMM kernel: compute C[b, m, n] = sum_k A_cat[b, m, k] * W_T[k, n], with W_T = process_weight.T of shape [H, H]. Use a 3D grid over (batch, tiles along M, tiles along N) and loop over K with BLOCK_K. Accumulate in fp32. Crucially, define the grid via a lambda that depends on meta['BLOCK_M'], meta['BLOCK_N'] to avoid under-coverage when autotune selects different block sizes.
- Add autotune configs for the GEMM to improve performance across a range of sizes, while keeping masks to handle non-multiples safely. This should stabilize correctness and improve speed.

@triton.jit
def concat_seq_kernel(
    enc_ptr, hid_ptr, out_ptr,
    B, T, I, H,
    stride_be, stride_bt, stride_bh,
    stride_bh2, stride_bI, stride_bH,
    stride_bo, stride_bl, stride_bH_out,
    BLOCK_M: tl.constexpr,  # tile along L (sequence)
    BLOCK_K: tl.constexpr,  # tile along H (feature)
):
    # program ids
    pid_b = tl.program_id(0)
    pid_m = tl.program_id(1)  # over sequence rows
    pid_k = tl.program_id(2)  # over feature cols

    # compute offsets
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)  # rows in [0, L)
    offs_k = pid_k * BLOCK_K + tl.arange(0, BLOCK_K)  # cols in [0, H)

    L = T + I

    # masks
    m_mask = offs_m < L
    k_mask = offs_k < H

    # base pointers for batch b

    hid_batch_ptr = hid_ptr + pid_b * stride_bh2
    out_batch_ptr = out_ptr + pid_b * stride_bo

# W_T:   [K, N] = [H, H]

    ],
    key=['M', 'N', 'K'],
)
@triton.jit
def batched_matmul_kernel(
    A_ptr, Wt_ptr, C_ptr,
    BATCH: tl.constexpr, M: tl.constexpr, N: tl.constexpr, K: tl.constexpr,
    stride_ab, stride_am, stride_ak,   # A strides for [B, M, K]
    stride_wtb, stride_wtk, stride_wtn,  # W^T strides for [K, N]
    stride_cb, stride_cm, stride_cn,   # C strides for [B, M, N]
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
):
    # program ids: we use a 3D grid (batch, tiles along M, tiles along N)
    pid_b = tl.program_id(0)
    pid_m = tl.program_id(1)
    pid_n = tl.program_id(2)

    # tile offsets
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)
    offs_k = tl.arange(0, BLOCK_K)

    # accumulator
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # loop over K dimension
    for k0 in range(0, K, BLOCK_K):
        k_mask = (k0 + offs_k) < K

        # A pointers for this block: A[b, m, k]
        a_ptrs = A_ptr + pid_b * stride_ab + offs_m[:, None] * stride_am + (k0 + offs_k)[None, :] * stride_ak
        # W^T pointers: W^T[k, n]
        w_ptrs = Wt_ptr + (k0 + offs_k)[:, None] * stride_wtk + offs_n[None, :] * stride_wtn

        # load A and W^T; masks handle boundaries
        a = tl.load(a_ptrs, mask=(offs_m[:, None] < M) & k_mask[None, :], other=0.0).to(tl.float32)
        w = tl.load(w_ptrs, mask=k_mask[:, None] & (offs_n[None, :] < N), other=0.0).to(tl.float32)

        # accumulate
        acc += tl.dot(a, w)

    # store result: C[b, m, n] = acc
    c_ptrs = C_ptr + pid_b * stride_cb + offs_m[:, None] * stride_cm + offs_n[None, :] * stride_cn
    tl.store(c_ptrs, acc, mask=(offs_m[:, None] < M) & (offs_n[None, :] < N))

# Triton batched matmul kernel: C[b, m, n] = sum_k A_cat[b, m, k] * W_T[k, n]
# A_cat: [B, M, K] = [B, L, H]
# W_T:   [K, N] = [H, H]
@triton.autotune(
    configs=[
        triton.Config({'BLOCK_M': 64,  'BLOCK_N': 64,  'BLOCK_K': 32}, num_warps=4, num_stages=3),
        triton.Config({'BLOCK_M': 128, 'BLOCK_N': 64,  'BLOCK_K': 32}, num_warps=4, num_stages=3),
        triton.Config({'BLOCK_M': 64,  'BLOCK_N': 128, 'BLOCK_K': 32}, num_warps=4, num_stages=3),
        triton.Config({'BLOCK_M': 128, 'BLOCK_N': 128, 'BLOCK_K': 32}, num_warps=8, num_stages=3),
        triton.Config({'BLOCK_M': 64,  'BLOCK_N': 64,  'BLOCK_K': 64}, num_warps=4, num_stages=4),
        triton.Config({'BLOCK_M': 128, 'BLOCK_N': 64,  'BLOCK_K': 64}, num_warps=8, num_stages=4),
        triton.Config({'BLOCK_M': 64,  'BLOCK_N': 128, 'BLOCK_K': 64}, num_warps=8, num_stages=4),
        triton.Config({'BLOCK_M': 128, 'BLOCK_N': 128, 'BLOCK_K': 64}, num_warps=8, num_stages=4),
    ],
    key=['M', 'N', 'K'],
)
@triton.jit
def batched_matmul_kernel(
    A_ptr, Wt_ptr, C_ptr,
    BATCH: tl.constexpr, M: tl.constexpr, N: tl.constexpr, K: tl.constexpr,
    stride_ab, stride_am, stride_ak,   # A strides for [B, M, K]
    stride_wtb, stride_wtk, stride_wtn,  # W^T strides for [K, N]
    stride_cb, stride_cm, stride_cn,   # C strides for [B, M, N]
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
):
    pid_b = tl.program_id(0)
    pid_m = tl.program_id(1)
    pid_n = tl.program_id(2)

    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)
    offs_k = tl.arange(0, BLOCK_K)

    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    for k0 in range(0, K, BLOCK_K):
        k_mask = (k0 + offs_k) < K

        a_ptrs = A_ptr + pid_b * stride_ab + offs_m[:, None] * stride_am + (k0 + offs_k)[None, :] * stride_ak
        w_ptrs = Wt_ptr + (k0 + offs_k)[:, None] * stride_wtk + offs_n[None, :] * stride_wtn

        a = tl.load(a_ptrs, mask=(offs_m[:, None] < M) & k_mask[None, :], other=0.0).to(tl.float32)
        w = tl.load(w_ptrs, mask=k_mask[:, None] & (offs_n[None, :] < N), other=0.0).to(tl.float32)

        acc += tl.dot(a, w)

    c_ptrs = C_ptr + pid_b * stride_cb + offs_m[:, None] * stride_cm + offs_n[None, :] * stride_cn
    tl.store(c_ptrs, acc, mask=(offs_m[:, None] < M) & (offs_n[None, :] < N))
