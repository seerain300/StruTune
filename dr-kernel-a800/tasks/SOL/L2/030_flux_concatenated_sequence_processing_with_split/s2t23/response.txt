Analysis, diagnosis, and plan

What the original PyTorch code does
- Inputs:
  - encoder_hidden_states: [B, T, H]
  - hidden_states: [B, I, H]
  - process_weight: [H, H], no bias
- Steps:
  - Concatenate along sequence dimension: A_cat = torch.cat([encoder_hidden_states, hidden_states], dim=1) -> [B, L, H], with L = T + I
  - Linear projection: processed = A_cat @ process_weight.T -> [B, L, H]
  - Split: processed_encoder = processed[:, :T, :], processed_hidden = processed[:, T:, :]

Evaluator requirements and failure modes
- The evaluator requires that “ALL numerical computation must be performed by custom @triton.jit kernels.” No torch.cat or torch.matmul should be used for the heavy work. The forward can:
  - compute shapes/strides,
  - allocate output tensors,
  - make tensors contiguous,
  - launch Triton kernels,
  - return the results.

We previously achieved 14/16 correct runs with a Triton batched GEMM. The remaining two workloads failed with “INCORRECT_NUMERICAL.” This suggests subtle numerical mismatches rather than out-of-bounds or runtime errors. The most likely causes are:
- Dtype handling: performing the matmul in fp32 while PyTorch uses fp16 can cause small numeric differences that evaluators flag as incorrect when inputs are fp16. In our previous kernels, we accumulated in fp32, which may deviate slightly from PyTorch’s fp16 matmul.
- Tiling and masking robustness for small dimensions (e.g., T=77, I=1024) can still be tricky. Ensuring BLOCK_M/BLOCK_N/BLOCK_K choices and masks properly handle all sizes is crucial.

Optimization and correctness plan
- Implement both steps in Triton to avoid any host-side torch computation:
  1) Triton concatenation kernel: straightforward 3D grid over (B, L, H). For each (b, m, k), write to out_cat[b, m, k]:
     - If m < T: take encoder[b, m, k]
     - Else: take hidden[b, m - T, k]
     This avoids complex batched indexing and is robust.
  2) Triton batched GEMM kernel: compute C[b, m, n] = sum_k A_cat[b, m, k] * W_T[k, n], with W_T = process_weight.T shape [H, H].
     - Use a 3D grid over (B, sequence tiles M, output tiles N).
     - Iterate reduction dimension K in blocks (BLOCK_K), using masks to handle edge cases when H is not divisible by BLOCK_K.
     - Accumulate in fp32 for stability, then store to output; Triton will cast to the output pointer dtype on store. This ensures the output tensor dtype matches A_cat (i.e., same as inputs).
     - Choose tile sizes that balance performance and robustness across diverse shapes. We’ll use:
       - BLOCK_M = 64, BLOCK_N = 64, BLOCK_K = 64
       - num_warps = 4, num_stages = 2
       These values are commonly stable and performant. We avoid overly aggressive tiles (e.g., 128x128) that can suffer from register pressure and partial coverage for some shapes.

Edge-case handling
- Ensure inputs are contiguous before launching kernels. Triton kernels will accept strides, but contiguous layouts simplify correctness and performance.
- The concatenation kernel uses masks based on m < T to correctly copy into the appropriate region without out-of-bounds.
- The GEMM kernel uses masks for M/N/K bounds to safely handle non-multiple sizes.

Final code implementing both Triton kernels

```python
import torch
import triton
import triton.language as tl


@triton.jit
def cat_seq_kernel(
    encoder_ptr, hidden_ptr, out_ptr,
    B, T, I, H,
    stride_e_b, stride_e_t, stride_e_h,
    stride_h_b, stride_h_i, stride_h_h,
    stride_o_b, stride_o_l, stride_o_h,
    BLOCK_H: tl.constexpr,
):
    # Grid: (B, L, ceil_div(H, BLOCK_H))
    b = tl.program_id(0)
    m = tl.program_id(1)
    h_block = tl.program_id(2)

    h_offsets = h_block * BLOCK_H + tl.arange(0, BLOCK_H)
    mask_h = h_offsets < H

    # Load appropriate source based on sequence index
    # Concatenation rule: if m < T -> encoder[b, m, h]; else -> hidden[b, m - T, h]
    is_encoder = m < T

    if is_encoder:
        src_ptr = encoder_ptr + b * stride_e_b + m * stride_e_t + h_offsets * stride_e_h
    else:
        src_idx = m - T
        src_ptr = hidden_ptr + b * stride_h_b + src_idx * stride_h_i + h_offsets * stride_h_h

    val = tl.load(src_ptr, mask=mask_h, other=0.0)
    out_ptr_m = out_ptr + b * stride_o_b + m * stride_o_l + h_offsets * stride_o_h
    tl.store(out_ptr_m, val, mask=mask_h)


@triton.jit
def batched_matmul_kernel(
    A_ptr, WT_ptr, C_ptr,
    B, M, N, K,
    stride_a_b, stride_a_m, stride_a_k,
    stride_w_k, stride_w_n,  # WT has shape [K, N], strides (k, n)
    stride_c_b, stride_c_m, stride_c_n,
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
):
    # Grid: (B, ceil_div(M, BLOCK_M), ceil_div(N, BLOCK_N))
    b = tl.program_id(0)
    m_block = tl.program_id(1)
    n_block = tl.program_id(2)

    m_offsets = m_block * BLOCK_M + tl.arange(0, BLOCK_M)
    n_offsets = n_block * BLOCK_N + tl.arange(0, BLOCK_N)

    # Accumulator in fp32 for numerical stability
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # Loop over K dimension in blocks
    for k_start in range(0, K, BLOCK_K):
        k_offsets = k_start + tl.arange(0, BLOCK_K)

        # Load A_tile: [BLOCK_M, BLOCK_K]
        a_ptrs = A_ptr + b * stride_a_b + m_offsets[:, None] * stride_a_m + k_offsets[None, :] * stride_a_k
        a_mask = (m_offsets[:, None] < M) & (k_offsets[None, :] < K)
        a_tile = tl.load(a_ptrs, mask=a_mask, other=0.0)

        # Load WT_tile: WT has shape [K, N], we want rows k_offsets, cols n_offsets -> [BLOCK_K, BLOCK_N]
        wt_ptrs = WT_ptr + k_offsets[:, None] * stride_w_k + n_offsets[None, :] * stride_w_n
        wt_mask = (k_offsets[:, None] < K) & (n_offsets[None, :] < N)
        wt_tile = tl.load(wt_ptrs, mask=wt_mask, other=0.0)

        # Accumulate: acc += a_tile @ wt_tile
        acc += tl.dot(a_tile.to(tl.float32), wt_tile.to(tl.float32))

    # Store results to C[b, m, n]
    c_ptrs = C_ptr + b * stride_c_b + m_offsets[:, None] * stride_c_m + n_offsets[None, :] * stride_c_n
    c_mask = (m_offsets[:, None] < M) & (n_offsets[None, :] < N)
    # Store as fp32; Triton will cast based on C_ptr dtype if needed. We keep fp32 for stability.
    tl.store(c_ptrs, acc, mask=c_mask)


class ModelNew(torch.nn.Module):
    def forward(self, encoder_hidden_states: torch.Tensor, hidden_states: torch.Tensor, process_weight: torch.Tensor):
        """
        Triton-optimized version of the original run function:
        1) Concatenate encoder_hidden_states and hidden_states along sequence dimension using Triton
        2) Apply linear projection using Triton batched matmul
        3) Split back into separate streams
        """
        # Ensure contiguous tensors
        encoder = encoder_hidden_states.contiguous()
        hidden = hidden_states.contiguous()
        weight = process_weight.contiguous()

        B, T, H = encoder.shape
        I = hidden.shape[1]
        L = T + I

        # 1) Concatenate along sequence dimension using Triton: out_cat [B, L, H]
        out_cat = torch.empty((B, L, H), device=encoder.device, dtype=encoder.dtype)

        BLOCK_H = 128  # tile along H for concatenation
        grid_cat = (B, L, triton.cdiv(H, BLOCK_H))
        cat_seq_kernel[grid_cat](
            encoder, hidden, out_cat,
            B, T, I, H,
            encoder.stride(0), encoder.stride(1), encoder.stride(2),
            hidden.stride(0), hidden.stride(1), hidden.stride(2),
            out_cat.stride(0), out_cat.stride(1), out_cat.stride(2),
            BLOCK_H=BLOCK_H,
            num_warps=1, num_stages=1,
        )

        # 2) Linear projection: processed = out_cat @ process_weight.T using Triton
        # Prepare WT = process_weight.T
        WT = weight.transpose(0, 1).contiguous()  # [H, H]
        processed = torch.empty((B, L, H), device=out_cat.device, dtype=out_cat.dtype)

        BLOCK_M = 64
        BLOCK_N = 64
        BLOCK_K = 64
        grid_gemm = (B, triton.cdiv(L, BLOCK_M), triton.cdiv(H, BLOCK_N))
        batched_matmul_kernel[grid_gemm](
            out_cat, WT, processed,
            B, L, H, H,  # M=L, N=H, K=H
            out_cat.stride(0), out_cat.stride(1), out_cat.stride(2),
            WT.stride(0), WT.stride(1),  # WT strides (k, n)
            processed.stride(0), processed.stride(1), processed.stride(2),
            BLOCK_M=BLOCK_M, BLOCK_N=BLOCK_N, BLOCK_K=BLOCK_K,
            num_warps=4, num_stages=2,
        )

        # 3) Split back into separate streams
        processed_encoder = processed[:, :T, :]
        processed_hidden = processed[:, T:, :]

        return processed_encoder, processed_hidden
```

Design of Triton GEMM (batched, per-batch 2D tiles)
- Inputs:
  - A_cat: [B, L, H], contiguous
  - WT: [H, H], contiguous (process_weight transposed)
  - Output C: [B, L, H]
- Kernel grid: (B, ceil_div(L, BLOCK_M), ceil_div(H, BLOCK_N))
- Each Triton program computes a [BLOCK_M x BLOCK_N] tile of C for a single batch index. It loops over K in BLOCK_K chunks, loading:
  - A_tile: [BLOCK_M, BLOCK_K] from A_cat[b, m:m+BLOCK_M, k:k+BLOCK_K]
  - WT_tile: [BLOCK_K, BLOCK_N] from WT[k:k+BLOCK_K, n:n+BLOCK_N]
  and accumulates acc += A_tile @ WT_tile. All math in fp32, final store casts to the output dtype.
- This approach avoids the complex 3D grid and reduces the chance of masking/grid errors. It’s simpler and more robust.

Edge cases and safeguards
- Ensure inputs are contiguous before launching kernels.
- Use masks for M/N/K bounds; BLOCK_* values should evenly divide typical sizes, but masks prevent OOB access when they don’t.
- Choose moderate tile sizes: BLOCK_M=64, BLOCK_N=64, BLOCK_K=64; num_warps=4, num_stages=2. These are balanced and performant across a range of sizes. You can adjust if needed, but this setup has shown stability.

```python
    A_ptr, WT_ptr, C_ptr,
    B, M, N, K,
    stride_a_b, stride_a_m, stride_a_k,

    stride_c_b, stride_c_m, stride_c_n,
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
):

    b = tl.program_id(0)
    m_block = tl.program_id(1)
    n_block = tl.program_id(2)

    n_offsets = n_block * BLOCK_N + tl.arange(0, BLOCK_N)

    for k_start in range(0, K, BLOCK_K):
        k_offsets = k_start + tl.arange(0, BLOCK_K)

        # Load A_tile: [BLOCK_M, BLOCK_K] from A[b, m, k]

        a_tile = tl.load(a_ptrs, mask=a_mask, other=0.0)

    c_mask = (m_offsets[:, None] < M) & (n_offsets[None, :] < N)
```
