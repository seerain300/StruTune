Deep analysis, diagnosis, and plan

- The original “run” function computes backward gradients for a layer that uses a shared expert and routing. The heavy math includes several dense matrix operations:
  - Per-token GEMVs:
    - grad_hidden_from_shared_up[token] = grad_shared_up_output[token] @ shared_expert_up_weight, shape [hidden_size]
    - grad_hidden_from_shared_gate[token] = grad_shared_gate_output[token] @ shared_expert_gate_weight, shape [hidden_size]
  - GEMMs (two large ones):
    - grad_shared_expert_down_weight = grad_shared_output.T @ shared_activated, shape [hidden_size, intermediate_size]
    - grad_router_weight = grad_router_logits.T @ hidden_states, shape [N_experts, hidden_size]
    - grad_shared_expert_up_weight = grad_shared_up_output.T @ hidden_states, shape [intermediate_size, hidden_size]
    - grad_shared_expert_gate_weight = grad_shared_gate_output.T @ hidden_states, shape [intermediate_size, hidden_size]

- The evaluator’s strict requirement: ModelNew.forward must invoke Triton kernels to perform all “computation.” No torch operations (no matmul, no .sum(), no .stack(), no .contiguous(), no .to() in host code). Data movement (e.g., ensuring contiguity) is acceptable as long as it’s not calling torch operations.

- Why the previous submissions failed:
  - Triton kernel indexing/grid/masking bugs led to runtime errors across different batch sizes. A 2D grid without correct pid_m/pid_n offset computation and masks can cause out-of-bounds accesses.
  - We must ensure every Triton kernel we launch is correct and robust across varying sizes (batch_seq_len can be 192, 384, 512, 8192, etc.).

Plan to fix correctness and keep Triton-only computation
- Implement a robust Triton GEMM (matrix multiply) kernel:
  - 2D tiling over M and N with explicit pid_m and pid_n, compute offsets for A (M,K), B (K,N), accumulate in fp32, store to C (M,N) with proper masks for both dimensions.
  - Use strides for A, B, C to correctly handle contiguity. We will ensure inputs are contiguous before launching Triton (data movement, not torch compute op).
  - Dtypes: compute in fp32 (for numerical stability), store as bf16 (matching get_inputs default).
- Implement a per-token GEMV Triton kernel:
  - One program per token (pid_m = token index), iterate over K in chunks (BLOCK_K), load x[token, :] and weight[:, :], accumulate y in fp32, store y (bf16).
  - This avoids 2D grid complexity and is robust for per-token vectors.

- Usage in forward:
  - Launch the 2D Triton matmul kernel for all GEMMs:
    - grad_shared_expert_down_weight = matmul(grad_shared_output.T, shared_activated)
    - grad_router_weight = matmul(grad_router_logits.T, hidden_states)
    - grad_shared_expert_up_weight = matmul(grad_shared_up_output.T, hidden_states)
    - grad_shared_expert_gate_weight = matmul(grad_shared_gate_output.T, hidden_states)
  - Launch the per-token GEMV Triton kernel for both GEMVs per token:
    - grad_hidden_from_shared_up = [gemv(grad_shared_up_output[t], shared_expert_up_weight) for t in tokens]
    - grad_hidden_from_shared_gate = [gemv(grad_shared_gate_output[t], shared_expert_gate_weight) for t in tokens]
  - Sum the per-token contributions to grad_hidden_states.

- Performance note:
  - The per-token GEMV kernel uses a 1D grid, which is fine since batch_seq_len is moderate to large. It avoids complex 2D tiling logic. The heavy GEMMs are computed by the 2D Triton kernel, which is more efficient and correct across shapes.

import torch
import triton
import triton.language as tl


@triton.jit
def matmul_bf16_fp32_kernel(
    A_ptr, B_ptr, C_ptr,
    M, N, K,
    stride_am, stride_ak,   # A strides: along M, along K
    stride_bk, stride_bn,   # B strides: along K, along N
    stride_cm, stride_cn,   # C strides: along M, along N
    BLOCK_M: tl.constexpr,  # tile size along M
    BLOCK_N: tl.constexpr,  # tile size along N
    BLOCK_K: tl.constexpr,  # tile size along K
):
    # 2D program ids
    pid_m = tl.program_id(0)  # along M
    pid_n = tl.program_id(1)  # along N

    # Compute offsets
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)
    offs_k = tl.arange(0, BLOCK_K)

    # Pointers to output C block
    c_ptrs = C_ptr + offs_m[:, None] * stride_cm + offs_n[None, :] * stride_cn

    # Accumulator in fp32
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # Loop over K
    for k in range(0, K, BLOCK_K):
        # Pointers to A block: [BLOCK_M, BLOCK_K]
        a_ptrs = A_ptr + offs_m[:, None] * stride_am + (k + offs_k)[None, :] * stride_ak
        # Pointers to B block: [BLOCK_K, BLOCK_N]
        b_ptrs = B_ptr + (k + offs_k)[:, None] * stride_bk + offs_n[None, :] * stride_bn

        # Masks for A and B loads
        a_mask = (offs_m[:, None] < M) & ((k + offs_k)[None, :] < K)
        b_mask = ((k + offs_k)[:, None] < K) & (offs_n[None, :] < N)

        # Load blocks, cast to fp32 for accumulation
        a = tl.load(a_ptrs, mask=a_mask, other=0.0).to(tl.float32)
        b = tl.load(b_ptrs, mask=b_mask, other=0.0).to(tl.float32)

        # FMA
        acc += tl.dot(a, b)

    # Store result to C (cast to bf16 as required)
    # We store acc as bf16 since the output tensor is bf16; Triton will cast on store if needed.
    c_mask = (offs_m[:, None] < M) & (offs_n[None, :] < N)
    tl.store(c_ptrs, acc, mask=c_mask)


@triton.jit
def gemv_bf16_fp32_kernel(
    x_ptr, w_ptr, y_ptr,
    M, K,
    stride_xm, stride_xk,   # x strides: along M, along K
    stride_wk, stride_wn,   # w strides: along K, along N
    stride_ym, stride_yk,   # y strides: along M (usually 1), along K (usually 1)
    BLOCK_K: tl.constexpr,
):
    # One program per row of x (per token)
    pid_m = tl.program_id(0)
    # Ensure pid_m is within M
    # We assume grid is set to (M,) so pid_m in [0, M)
    # Accumulator in fp32
    acc = tl.zeros((1,), dtype=tl.float32)

    # Iterate over K in chunks
    for k in range(0, K, BLOCK_K):
        offs_k = k + tl.arange(0, BLOCK_K)
        # Load x row chunk
        x_ptrs = x_ptr + pid_m * stride_xm + offs_k * stride_xk
        x_mask = offs_k < K
        x_chunk = tl.load(x_ptrs, mask=x_mask, other=0.0).to(tl.float32)  # [BLOCK_K]
        # Load w chunk (B block for GEMV)
        w_ptrs = w_ptr + offs_k[:, None] * stride_wk + tl.arange(0, 1) * stride_wn  # N=1 for GEMV
        # Note: N=1 so we just need one column, using stride_wn for the column (usually 0)
        # Here N is 1, so stride_wn doesn't matter; we just load [BLOCK_K, 1]
        w_mask = offs_k[:, None] < K  # second dim is 1
        w_chunk = tl.load(w_ptrs, mask=w_mask, other=0.0).to(tl.float32)  # [BLOCK_K, 1]
        # acc += sum(x_chunk * w_chunk)
        # w_chunk[:, 0] gives [BLOCK_K], broadcast across acc
        acc += tl.sum(x_chunk * tl.reshape(w_chunk[:, 0], (BLOCK_K,)), axis=0)

    # Store result y[pid_m] in bf16
    y_ptr_elem = y_ptr + pid_m * stride_ym
    # We store scalar acc as bf16
    tl.store(y_ptr_elem, acc.to(tl.bfloat16))

import torch
import triton
import triton.language as tl


@triton.jit
def matmul_bf16_fp32_kernel(
    A_ptr, B_ptr, C_ptr,
    M, N, K,
    stride_am, stride_ak,   # A strides: along M, along K
    stride_bk, stride_bn,   # B strides: along K, along N
    stride_cm, stride_cn,   # C strides: along M, along N
    BLOCK_M: tl.constexpr,  # tile size along M
    BLOCK_N: tl.constexpr,  # tile size along N
    BLOCK_K: tl.constexpr,  # tile size along K
):
    # 2D program ids
    pid_m = tl.program_id(0)  # along M
    pid_n = tl.program_id(1)  # along N

    # Compute tile offsets
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)
    offs_k = tl.arange(0, BLOCK_K)

    # Output pointers for current tile
    c_ptrs = C_ptr + offs_m[:, None] * stride_cm + offs_n[None, :] * stride_cn

    # Accumulator in fp32
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # Loop over K in chunks
    for k in range(0, K, BLOCK_K):
        # Pointers to A tile: [BLOCK_M, BLOCK_K]
        a_ptrs = A_ptr + offs_m[:, None] * stride_am + (k + offs_k)[None, :] * stride_ak
        # Pointers to B tile: [BLOCK_K, BLOCK_N]
        b_ptrs = B_ptr + (k + offs_k)[:, None] * stride_bk + offs_n[None, :] * stride_bn

        # Masks for loads
        a_mask = (offs_m[:, None] < M) & ((k + offs_k)[None, :] < K)
        b_mask = ((k + offs_k)[:, None] < K) & (offs_n[None, :] < N)

        # Load tiles, cast to fp32
        a = tl.load(a_ptrs, mask=a_mask, other=0.0).to(tl.float32)
        b = tl.load(b_ptrs, mask=b_mask, other=0.0).to(tl.float32)

        # Accumulate
        acc += tl.dot(a, b)

    # Store result tile (cast happens on store if C is bf16)
    c_mask = (offs_m[:, None] < M) & (offs_n[None, :] < N)
    tl.store(c_ptrs, acc, mask=c_mask)


@triton.jit
def gemv_bf16_fp32_kernel(
    x_ptr, w_ptr, y_ptr,
    M, K,
    stride_xm, stride_xk,   # x strides: along M, along K
    stride_wk, stride_wn,   # w strides: along K, along N
    stride_ym,              # y stride along M (scalar output)
    BLOCK_K: tl.constexpr,
):
    # One program per row (per token)
    pid_m = tl.program_id(0)
    acc = tl.zeros((1,), dtype=tl.float32)

    # Iterate over K in chunks
    for k in range(0, K, BLOCK_K):
        offs_k = k + tl.arange(0, BLOCK_K)
        # Load x row chunk: [BLOCK_K]
        x_ptrs = x_ptr + pid_m * stride_xm + offs_k * stride_xk
        x_mask = offs_k < K
        x_chunk = tl.load(x_ptrs, mask=x_mask, other=0.0).to(tl.float32)  # [BLOCK_K]

        # Load w chunk: [BLOCK_K, N] where N = w.shape[1]; we need w[:, 0] (first column)
        # We index the second dimension as 0; stride_wn is stride along N dimension.
        w_ptrs = w_ptr + offs_k[:, None] * stride_wk + 0 * stride_wn  # second dim is 1
        w_mask = offs_k[:, None] < K
        w_chunk = tl.load(w_ptrs, mask=w_mask, other=0.0).to(tl.float32)  # [BLOCK_K, 1]

        # Accumulate dot: sum(x_chunk * w_chunk[:, 0])
        acc += tl.sum(x_chunk * tl.reshape(w_chunk[:, 0], (BLOCK_K,)), axis=0)

    # Store scalar y[pid_m] as bf16
    y_ptr_elem = y_ptr + pid_m * stride_ym
    tl.store(y_ptr_elem, acc.to(tl.bfloat16))
