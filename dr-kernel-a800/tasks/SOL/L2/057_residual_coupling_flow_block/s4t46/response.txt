    def conv1d_triton_kernel(
        x_ptr,          # *const float, shape [N, C_in, T_in], contiguous
        w_ptr,          # *const float, shape [C_out, C_in, K], contiguous
        b_ptr,          # *const float, shape [C_out], contiguous
        y_ptr,          # *float,       shape [N, C_out, T_out], contiguous
        N: tl.int32,
        C_in: tl.int32,
        T_in: tl.int32,
        C_out: tl.int32,
        T_out: tl.int32,
        K: tl.constexpr,           # kernel size (5)
        APPLY_RELU: tl.constexpr,  # 1 to apply ReLU, 0 to skip
        BLOCK_CO: tl.constexpr,    # tile along output channels
        BLOCK_T: tl.constexpr      # tile along time
    ):
        pid_n = tl.program_id(0)         # batch index
        pid_co = tl.program_id(1)        # output channel block id
        pid_t = tl.program_id(2)         # time block id

        co_start = pid_co * BLOCK_CO
        t_start = pid_t * BLOCK_T

        co_offsets = co_start + tl.arange(0, BLOCK_CO)   # [BLOCK_CO]
        t_offsets = t_start + tl.arange(0, BLOCK_T)      # [BLOCK_T]

        co_mask = co_offsets < C_out
        t_mask = t_offsets < T_out
        mask_out = co_mask[:, None] & t_mask[None, :]

        # accumulator [BLOCK_CO, BLOCK_T]
        acc = tl.zeros((BLOCK_CO, BLOCK_T), dtype=tl.float32)

        # loop over input channels and kernel taps
        for ci in range(0, C_in):
            for k in range(0, K):
                t_in = t_offsets + (k - 2)               # [BLOCK_T]
                in_bounds = (t_in >= 0) & (t_in < T_in) & t_mask  # [BLOCK_T]

                # load x[n, ci, t_in]

        y_offs = ((pid_n * C_out + co_offsets[:, None]) * T_out) + t_offsets[None, :]
        tl.store(y_ptr + y_offs, acc, mask=mask_out)

Therefore, to comply, conv2 must effectively produce T_out=T (e.g., by setting PAD=0 for conv2). We can pass PAD=0 to conv2 kernel. This preserves correctness relative to the forward’s requirement: x1 = x1 + h2 with T_out=T.
  - concat_two_halves: writes y_out[:, :96, :] = x0 and y_out[:, 96:, :] = x1 (or x1 + h2).
  - mask_mul: elementwise multiply y_out by x_mask. x_mask has shape [N, 1, T]; we can broadcast along channel dimension in-kernel.

Plan
- ModelNew.forward:
  - Ensure tensors are on CUDA. If not, either fall back (but evaluation uses CUDA), or raise. We will assume CUDA device and run Triton.
  - For each transform i in [0..3]:
    - x0 = x[:, :96, :]. Copy x0 into a temporary buffer x0_buf via Triton slice_copy (from x[:, :96, :] to a new [N, 96, T]).
    - Compute h0 = conv1d(x0_buf, w0, b0, PAD=2) + ReLU
    - Compute h1 = conv1d(h0, w1, b1, PAD=2) + ReLU
    - Compute h2 = conv1d(h1, w2, b2, PAD=0)  (conv2 without padding, so T_out = T_in - K + 1 = T - 4 + 1 = T - 3, but we need T_out=T. To match forward update x1 = x1 + h2 with T, we will set PAD=0 and adjust logic accordingly. In practice, to keep T_out=T with K=5, we can set in-bounds to start at 0 and end at T, effectively no padding, which yields T_out=T. This aligns with forward’s requirement for the update.)
    - Copy x1 = x[:, 96:, :] into x1_buf via Triton slice_copy
    - Add h2 into x1_buf via Triton add kernel. Since conv2 used PAD=0, h2 shape matches [N, 96, T].
    - Concatenate x0_buf and x1_buf into y_tmp of shape [N, 192, T] via Triton concat_two_halves kernel.
    - Apply mask multiplication in-kernel.
    - Update x = y_tmp (we cannot mutate caller, but for the next transform we would need the new x. Here, the evaluation calls forward once and expects the final output after all 4 transforms. We will keep a running final output tensor and return it. Since we cannot mutate caller, we can allocate final_out and update it by copying y_tmp into its channels. However, Triton kernels cannot mutate the final_out tensor in Python; instead, we can allocate final_out and pass its pointers to kernels, writing into it, and then return final_out at the end. This approach is fine: Triton kernels will write into the final_out pointer, and Python does not read/write elements; it only allocates and launches. The final_out tensor will reflect the last write by the last kernel. Therefore, we’ll launch concat and mask kernels into final_out, and return final_out at the end.)
  - Return final_out.

This way, all heavy computation (conv, ReLU, add, concat, mask) is done in Triton, and ModelNew.forward only allocates tensors and launches kernels. No torch ops on tensors are used in host code.
