Final thinking, analysis, and plan

- The evaluator repeatedly flagged “decoy” kernels: Triton kernels were defined but not launched from ModelNew.forward. This is strictly forbidden. We must actually invoke each Triton kernel defined inside forward.
- Additionally, the evaluator prohibits torch.bmm (batched matmul) in ModelNew.forward. The original forward recomputation uses batched matmul to assemble predictions. We must implement that matmul in Triton.
- To match the original outputs across all workloads, we will reconstruct the forward recomputation path entirely using Triton kernels:
  1) Variance per (b, s): sum of squares across hidden dimension H. Implement with a Triton reduction kernel (sum_squares_reduce_kernel) that loops over H in tiles and uses atomic_add to accumulate per-(b, s) sums.
  2) rstd: Compute inv_std = 1/sqrt(var + eps) using rsqrt_kernel.
  3) Linear projection: routed vectors of length 9 via F.linear on length-9 inputs. Implement with GEMV (matvec_kernel) per (b, s), M=1, K=9, N=H.
  4) tanh of routed: Implement tanh_kernel to compute tanh for the routed vector.
  5) Linear coefficients: modalities and prediction/correction coefficients via GEMV using matvec_kernel.
  6) Final assembly of predictions: hidden[b, s, :] is [H] vector; all_coefs[b, s, :, :] is [9, 9]; predictions[b, s, :] = hidden @ all_coefs. Implement batched GEMM per (b, s): Out[H, 9] = X[H, 9] @ W[9, 9]. We will implement bmm_assemble_per_bs_kernel that computes Out[h, k] by looping over K (which is 9) in tiles and accumulating. This replaces torch.bmm and is launched from forward.

Key details:
- Use contiguous, float32 math for Triton kernels. Cast inputs to float32 before launching Triton, and produce outputs in float32. Return tensors cast appropriately.
- Launch grids:
  - sum_squares_reduce_kernel: grid = (B*S,)
  - rsqrt_kernel: grid = (B*S,)
  - tanh_kernel: grid = (B*S, 9)
  - matvec_kernel: grid = (B*S, 9) (compute each modalities vector)
  - bmm_assemble_per_bs_kernel: grid = (B*S, H, 9). This launches one program per (b, s, h, k) and accumulates Out[h, k] across K in tiles. With K=9, we can keep it simple and avoid excessive programs.

This approach ensures all heavy computation is done in Triton, avoids torch.bmm, and calls all defined kernels from forward to prevent “decoy” flags.

import torch
import triton
import triton.language as tl


# Triton kernels

@triton.jit
def sum_squares_reduce_kernel(x_ptr, out_ptr, H: tl.constexpr, BLOCK_H: tl.constexpr):
    """
    For each (b, s), reduce sum(x[b, s, :])^2 across H and write to out[b*S].
    We launch one program per (b, s) and accumulate into a scalar via atomic_add.
    x_ptr is laid out as [B*S, H] contiguous; each program processes its (b, s) row.
    """
    pid = tl.program_id(axis=0)  # index over (b, s)
    total = 0.0
    for h0 in range(0, H, BLOCK_H):
        offs = h0 + tl.arange(0, BLOCK_H)
        mask = offs < H
        x = tl.load(x_ptr + pid * H + offs, mask=mask, other=0.0)
        sq = x * x
        total += tl.sum(sq, axis=0)
    tl.atomic_add(out_ptr + pid, total)


@triton.jit
def rsqrt_kernel(inp_ptr, out_ptr, N, eps, BLOCK_SIZE: tl.constexpr):
    """
    Compute inv_std = 1/sqrt(inp + eps) for a vector of length N.
    """
    pid = tl.program_id(axis=0)
    offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = offsets < N
    x = tl.load(inp_ptr + offsets, mask=mask, other=0.0)
    inv_std = 1.0 / tl.sqrt(x + eps)
    tl.store(out_ptr + offsets, inv_std, mask=mask)


@triton.jit
def tanh_kernel(inp_ptr, out_ptr, N, BLOCK_SIZE: tl.constexpr):
    """
    Compute tanh for a vector of length N using exp:
    tanh(z) = (exp(2z) - 1) / (exp(2z) + 1)
    """
    pid = tl.program_id(axis=0)
    offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = offsets < N
    z = tl.load(inp_ptr + offsets, mask=mask, other=0.0)
    e2z = tl.exp(2.0 * z)
    y = (e2z - 1.0) / (e2z + 1.0)
    tl.store(out_ptr + offsets, y, mask=mask)


@triton.jit
def matvec_kernel(A_ptr, W_ptr, Out_ptr, M, N, K,
                  stride_a0, stride_a1, stride_w0, stride_w1,
                  BLOCK_N: tl.constexpr):
    """
    Implement GEMV: Out[M,K] = A[M,N] @ W[N,K]
    We call with M=1 for each (b,s) row; K is the output dim (e.g., 9).
    """
    pid_m = tl.program_id(axis=0)  # row index
    for pid_k in tl.static_range(0, tl.num_programs(axis=1)):
        acc = tl.zeros((), dtype=tl.float32)  # scalar accumulator per output feature
        for n0 in range(0, N, BLOCK_N):
            n_idx = n0 + tl.arange(0, BLOCK_N)
            mask_n = n_idx < N
            # Load A[pid_m, n_idx]
            a_row_ptr = A_ptr + pid_m * stride_a0 + n_idx * stride_a1
            a = tl.load(a_row_ptr, mask=mask_n, other=0.0)
            # Load W[n_idx, pid_k]
            w_col_ptr = W_ptr + n_idx * stride_w0 + pid_k * stride_w1
            w = tl.load(w_col_ptr, mask=mask_n, other=0.0)
            acc += tl.sum(a * w, axis=0)
        # Store to Out[pid_m, pid_k]
        out_index = pid_m * K + pid_k
        tl.store(Out_ptr + out_index, acc)


@triton.jit
def bmm_assemble_per_bs_kernel(H: tl.constexpr, K: tl.constexpr,
                                X_ptr, W_ptr, Out_ptr,
                                stride_x0, stride_x1, stride_w0, stride_w1,
                                stride_out0, stride_out1):
    """
    Batched GEMM per (b, s): Out[H, K] = X[H, K] @ W[K, K]
    This kernel computes Out[h, k] for a given (b, s) by looping over K (which is small: 9).
    We expect X_ptr to point to a slice for this (b, s); same for W and Out.
    Grid is (B*S, H, K); each program handles one (h, k).
    """
    pid_bs = tl.program_id(axis=0)  # combined batch-seq index
    h = tl.program_id(axis=1)
    k_out = tl.program_id(axis=2)
    acc = tl.zeros((), dtype=tl.float32)
    # Loop over K_small (K is 9 in this model). Since K is constexpr, we can iterate directly.
    for k_small in range(0, K):
        # Load X[h, k_small] and W[k_small, k_out]
        x_ptr = X_ptr + pid_bs * stride_x0 + h * stride_x1 + k_small * stride_x1
        w_ptr = W_ptr + k_small * stride_w0 + k_out * stride_w1
        x = tl.load(x_ptr)
        w = tl.load(w_ptr)
        acc += x * w
    # Store Out[h, k_out]
    out_ptr = Out_ptr + pid_bs * stride_out0 + h * stride_out1 + k_out * stride_out1
    tl.store(out_ptr, acc)
